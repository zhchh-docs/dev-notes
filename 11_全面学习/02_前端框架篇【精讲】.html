2基础层 · 入门必备

2.1 组件与模板的概念

组件是 Vue/React 应用的基本组成单元：把界面和逻辑封装成可复用、可组合的独立模块；模板是描述视图的声明式语法。

  • 组件 = 模板（结构）+ 逻辑（数据/行为）+ 样式，三者封装为独立单元
  • 模板是声明式的：描述"界面长什么样"，框架负责把它变成真实 DOM
  • 组件树：页面 = 根组件嵌套子组件，形成单向层级结构
  • SFC（单文件组件）：.vue 文件把 template / script / style 放在同一个文件里
<!-- App.vue：单文件组件 = 模板 + 逻辑 + 样式 -->
<template>
  <div class="card">
    <h2>{{ title }}</h2>
    <p>{{ content }}</p>
  </div>
</template>

<script setup>
import { ref } from 'vue'
const title = ref('卡片标题')
const content = ref('这是一段内容')
</script>

<style scoped>
.card { border: 1px solid #ddd; border-radius: 8px; padding: 16px; }
</style>

2.2 Vue 指令

指令是 Vue 模板中带 v- 前缀的特殊属性，用声明式语法完成条件渲染、列表渲染、双向绑定等常见操作，替代手动 DOM 操作。

  • v-if / v-else-if / v-else：条件渲染，按需创建或销毁节点；v-show 只切换 display，节点常驻
  • v-for：列表渲染，必须配合 :key 帮助 diff 复用节点
  • v-model：表单双向绑定，本质是 value 绑定 + input 事件的语法糖
  • v-bind（简写 :）：动态绑定属性；v-on（简写 @）：绑定事件
  • v-html：插入 HTML 字符串，内容来自用户时必须过滤，否则有 XSS 风险
<!-- 条件渲染 -->
<p v-if="isLogin">欢迎回来</p>
<p v-else>请先登录</p>

<!-- 列表渲染：key 帮助 diff 复用节点 -->
<ul>
  <li v-for="item in list" :key="item.id">{{ item.name }}</li>
</ul>

<!-- v-model 双向绑定 -->
<input v-model="keyword" placeholder="搜索">

<!-- v-on 绑定事件 -->
<button @click="search">搜索</button>

2.3 单向数据流

数据只能从父组件流向子组件（props），子组件不能直接修改 props，修改必须通过事件通知父组件——数据流向单一、可预测。

  • props 是父 → 子的唯一数据通道，子组件拿到的 props 是只读的
  • 子组件要改变数据：通过 emit 触发事件，由父组件修改自己的状态
  • 好处：状态来源清晰、便于排查问题、组件可独立复用
  • React 同样遵循单向数据流：props 只读，变更靠回调函数
<!-- 父组件：把 count 传给子组件，子组件要改时监听 add 事件 -->
<Child :count="count" @add="count++" />

<!-- 子组件：props 只读，改数据必须 emit -->
<script setup>
const props = defineProps({ count: Number })   // 只读，不要直接修改
const emit = defineEmits(['add'])
</script>

2.4 组件生命周期

组件从创建到销毁会经历多个阶段，框架在关键节点调用钩子函数，方便你挂载初始化逻辑、清理资源。

  • Vue2 选项式：beforeCreate → created → beforeMount → mounted → beforeUpdate → updated → beforeUnmount → unmounted
  • Vue3 组合式：onMounted / onUpdated / onUnmounted 等 setup 钩子
  • mounted：DOM 已挂载，适合发请求、操作 DOM、初始化图表
  • unmounted：清理定时器、取消订阅、移除事件监听，防止内存泄漏

组件生命周期钩子 流程图

import { onMounted, onUnmounted } from 'vue'

onMounted(() => {
  // DOM 已挂载：发请求、绑定事件、初始化图表
  fetchData()
})

onUnmounted(() => {
  // 组件销毁前：清理定时器、取消订阅
  clearInterval(timer)
})

3标准层 · 日常开发

3.1 Vue3 组合式 API

Vue3 推荐用 setup + ref / reactive / computed 组织逻辑，把同一功能的变量和函数聚在一起，比选项式 API 更易复用和阅读。

  • setup() 是组件逻辑入口；<script setup> 是编译期语法糖，更简洁
  • ref：包装基本类型为响应式（.value 访问）；reactive：包装对象
  • computed：派生状态，带缓存，依赖变化才重算
  • watch / watchEffect：监听数据变化执行副作用
  • 自定义组合函数 useXxx：把可复用逻辑抽成独立函数
import { ref, reactive, computed, watch } from 'vue'

const count = ref(0)                     // 基本类型用 ref
const form = reactive({ name: '' })      // 对象用 reactive

const double = computed(() => count.value * 2)  // 派生状态，带缓存

watch(count, (v, old) => {
  console.log(`count: ${old} → ${v}`)
})

3.2 组件通信

组件间的数据交互方式：props / emit 解决父子通信，provide / inject 跨层级注入，插槽做内容分发，复杂场景交给全局状态。

  • 父子通信：props 下发 + emit 上行，保持单向数据流
  • 跨层级：provide / inject，避免 props 逐层透传（prop drilling）
  • 内容分发：默认插槽 / 具名插槽 / 作用域插槽，让父组件控制渲染内容
  • 复杂场景：Pinia 全局状态（或 mitt 事件总线）
<!-- 父组件提供 -->
<script setup>
import { provide, ref } from 'vue'
const theme = ref('dark')
provide('theme', theme)          // 任意后代组件都可注入
</script>

<!-- 孙组件注入 -->
<script setup>
import { inject } from 'vue'
const theme = inject('theme')    // 拿到同一个 ref
</script>

3.3 状态管理 Pinia / Vuex

多个组件共享同一份数据（用户信息、购物车、主题）时，用集中式 Store 管理状态，避免 props 层层透传与状态分散。

  • Vuex（Vue2 官方方案）：state / getters / mutations / actions / modules 五要素
  • Pinia（Vue3 官方推荐）：state / getters / actions，天然支持组合式 API、类型友好、无 mutation
  • Store 是单一数据源：派生数据用 getters 计算，不重复存储
  • 何时用：跨组件共享、跨页面状态、需持久化缓存的数据
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', () => {
  const user = ref(null)
  const isLogin = computed(() => !!user.value)

  function login(data) { user.value = data }
  function logout() { user.value = null }

  return { user, isLogin, login, logout }
})

3.4 React Hooks

React 16.8 引入 Hooks，让函数组件拥有状态与副作用能力，取代类组件繁琐的 this 与生命周期写法。

  • useState：声明组件状态，返回 [值, 更新函数]
  • useEffect：副作用（请求 / 订阅 / 操作 DOM），依赖数组控制执行时机
  • useMemo / useCallback：缓存计算结果与函数引用，配合 memo 跳过渲染
  • useRef：保存可变值、访问 DOM 节点
  • 规则：只能在组件顶层调用 Hooks，不在循环 / 条件 / 嵌套函数中调用
function UserCard() {
  const [user, setUser] = useState(null)

  useEffect(() => {
    fetch('/api/user').then(r => r.json()).then(setUser)
  }, [])                    // 空依赖：仅挂载时执行一次

  const name = useMemo(() => user?.name ?? '游客', [user])

  return <div>{name}</div>
}

3.5 前端路由

SPA 用路由管理"URL 与视图"的映射：切换地址不刷新页面，视图随之变化。

  • hash 模式（#/xxx，无需服务端配置）与 history 模式（HTML5 History API，需服务端回退配置）
  • Vue Router：routes 表 + router-view；React Router：<Routes> / <Route>
  • 动态路由参数：/user/:id，组件内 useRoute().params 读取
  • 路由守卫：登录鉴权、权限控制（beforeEach）
  • 懒加载：路由级代码分割（() => import()），按需加载减小首屏体积
const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: Home },
    { path: '/user/:id', component: UserDetail, meta: { requiresAuth: true } }
  ]
})

// 路由守卫：未登录跳回登录页
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isLogin()) return '/login'
})

3.7 SSR / SSG（Nuxt）

SPA 首屏慢、SEO 差，SSR（服务端渲染）和 SSG（静态生成）解决这些问题；Nuxt 是 Vue 的全栈框架。

  • SSR：请求时服务端渲染 HTML 返回，SEO 好、首屏快；代价是服务器压力与 TTFB 略增
  • SSG：构建期生成静态 HTML，适合内容型站点，部署简单、速度最快
  • 水合（hydration）：服务端渲染 HTML 后，客户端 JS 接管交互
  • Nuxt 3：内置 SSR / SSG、文件路由、自动导入、服务端 API（Nitro）
// nuxt.config.ts：开启服务端渲染
export default defineNuxtConfig({
  ssr: true,
  app: { head: { title: '我的站点' } }
})

4深入层 · 原理进阶

4.1 响应式原理（Proxy / 依赖收集 / 派发更新）

Vue3 用 Proxy 代理对象的读写：get 时收集依赖（谁在用这个数据），set 时触发更新——数据一变，视图自动刷新。

  • Proxy 劫持 get / set / has / deleteProperty，支持数组索引与动态新增属性（Vue2 的 defineProperty 做不到）
  • 依赖收集：读取响应式数据时，把当前"副作用"（渲染函数 / effect）登记进依赖表
  • 派发更新：数据变化时，触发所有登记的副作用重新执行
  • effect 与 scheduler：scheduler 控制更新时机（异步批量、组件级调度）
// 迷你 reactive：get 收集依赖，set 触发更新
function reactive(obj) {
  return new Proxy(obj, {
    get(target, key) {
      track(target, key)        // 读取 → 收集当前副作用
      return target[key]
    },
    set(target, key, value) {
      target[key] = value
      trigger(target, key)      // 修改 → 通知副作用重新执行
      return true
    }
  })
}

4.2 虚拟 DOM 与 Diff 算法

框架不直接操作真实 DOM，而是用 JS 对象（虚拟节点 vnode）描述视图；数据变化后比较新旧 vnode 树（diff），找出最小变更再更新真实 DOM。

  • vnode = 描述节点的普通 JS 对象（tag / props / children）
  • 渲染流程：模板 → render 函数 → vnode → patch（diff + 更新 DOM）
  • Diff 策略：同层比较、key 复用（列表移动只做节点移动而非整块重建）
  • Vue3 双端 diff；React 用 Fiber 化的协调（可中断）
// vnode：用 JS 对象描述真实 DOM 结构
const vnode = {
  tag: 'div',
  props: { class: 'card' },
  children: [
    { tag: 'h2', props: {}, children: '标题' },
    { tag: 'p',  props: {}, children: '内容' }
  ]
}
// patch：比较新旧 vnode 树，最小化更新真实 DOM

4.3 渲染调度与更新机制

数据变化到 DOM 更新不是一步到位：框架把渲染任务批量、异步地调度，保证性能与数据一致性。

  • 组件级更新：数据变化只重新渲染依赖它的组件，不整棵树重渲
  • 异步批量：Vue 的 nextTick / 微任务队列把同一轮多次修改合并为一次渲染
  • React 的调度：Fiber 可中断渲染 + 优先级调度（concurrent 模式）
  • 手动优化本质都是减少"不必要的调度"：memo、key、稳定引用
// Vue 的更新是异步批量：多次改数据只渲染一次
state.count++     // 改第一次
state.name = 'x'  // 改第二次
// 同一轮微任务内合并为一次渲染

await nextTick()  // 此时 DOM 已更新（nextTick 返回 Promise）

4.4 React Fiber 架构简述

React 16 用 Fiber 重写协调器：把渲染拆成可中断、可恢复、带优先级的小任务，解决长列表 / 大应用阻塞主线程的问题。

  • 链表结构：fiber 节点记录 return / child / sibling，形成可遍历的树
  • 双缓冲：current 树（已渲染）与 workInProgress 树（构建中）
  • 渲染阶段可中断，提交阶段一次性不可中断地应用到 DOM
  • 优先级：Lane 模型；时间切片（time slicing）主动让出主线程
  • 收益：concurrent 渲染、Suspense、可中断更新
// fiber 节点：链表结构，可中断遍历
const fiber = {
  tag: 'FunctionComponent',   // 节点类型
  key: null,
  elementType: MyComponent,
  stateNode: null,            // 组件实例 / DOM
  return: parentFiber,        // 父节点
  child: childFiber,          // 第一个子节点
  sibling: nextFiber,         // 下一个兄弟节点
  lanes: 1                    // 优先级（Lane 模型）
}

4.5 微前端原理与 JS 沙箱隔离

微前端把巨石应用拆成多个可独立开发、独立部署的子应用，运行时统一由基座加载；核心难点是隔离子应用的 JS 与样式。

  • 架构：基座（主应用）管理路由与加载；子应用独立构建、独立部署
  • 加载方式：import-html-entry 拉取子应用 HTML/CSS/JS 并执行
  • JS 沙箱：Proxy 代理 window（快照 / 代理两种策略），防止全局变量污染
  • 样式隔离：shadow DOM 或 CSS 前缀（qiankun 内置方案）
  • 适用判断：团队 / 业务足够大、边界清晰才值得，小项目是过度设计
// qiankun：基座注册子应用
import { registerMicroApps, start } from 'qiankun'

registerMicroApps([
  { name: 'app-react', entry: '//localhost:3001', container: '#root', activeRule: '/react' },
  { name: 'app-vue',   entry: '//localhost:3002', container: '#root', activeRule: '/vue' }
])
start()

4.6 状态设计模式

状态管理不只是选库，更是一套设计约束：单向数据流、不可变更新、单一数据源、派生状态不重复存储。

  • 单向数据流：Action → State → View，状态变化路径唯一、可预测
  • 不可变更新：每次更新产生新对象（React 依赖引用比较决定是否渲染）
  • 单一数据源：同一数据只存一处，派生值用 computed / useMemo
  • 归一化：列表数据按 id 存索引，避免深层嵌套对象的拷贝开销
// 不可变更新：产生新对象，旧引用不变（React 靠引用比较跳过渲染）
setState(prev => ({ ...prev, count: prev.count + 1 }))

// 归一化存储：列表按 id 索引，避免嵌套对象拷贝
const state = { byId: { 1: { id: 1, name: 'a' } }, ids: [1] }

4.7 组件性能优化（memo / 懒加载）

性能优化的核心是"减少不必要的渲染 + 减小单次渲染成本"：memo 缓存组件、懒加载拆分代码、长列表虚拟化。

  • React.memo / useMemo / useCallback：props 未变时跳过重渲染（浅比较）
  • Vue：computed 缓存、v-once 静态标记、shallowRef、defineAsyncComponent 异步组件
  • 路由懒加载 + 组件异步加载：代码分割，减小首屏体积
  • 长列表虚拟化：只渲染可视区（vue-virtual-scroller / react-window）
  • 先量化再优化：用 React DevTools Profiler / Vue 性能面板定位真正瓶颈
// React.memo：props 不变时跳过渲染（浅比较）
const Row = memo(function Row({ item }) {
  return <li>{item.name}</li>
})

// useCallback：稳定回调引用，配合 memo 生效
const onClick = useCallback(() => doThing(item.id), [item.id])

// Vue 懒加载组件：按需加载，减小首屏体积
const Chart = defineAsyncComponent(() => import('./Chart.vue'))

6常见误区与实战要点

常见误区：
  • 把能放组件内部的状态都塞进全局 store，状态越积越多、难以追踪——先问"是否真的跨组件共享"
  • 子组件直接修改 props（如 props.count++），破坏了单向数据流，导致数据来源混乱
  • React useEffect 依赖数组写错：漏写依赖导致闭包过期，多写依赖导致无限循环
  • 组件通信层级太深，props 一层层透传（prop drilling），该用 provide / inject 或状态库时没换
  • v-for 不写 :key 或乱用 index 当 key，列表重排时出现渲染错乱、状态复用错误
  • 只要性能问题就上 memo / useMemo，没有先量化瓶颈，优化本身变成复杂度
  • 微前端没有业务规模就硬上，反而引入加载、通信、排查的多重复杂度
✅ 实战建议：先默认单向数据流 + 组件化拆分写业务；共享状态确定跨组件了再上 Pinia；性能优化先看 Profiler 再动手；路由懒加载与代码分割是低成本的默认收益。
