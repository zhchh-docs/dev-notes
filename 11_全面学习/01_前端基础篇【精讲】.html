1本篇概览与学习路径

本篇按照从易到难、从用到原理的顺序，把前端基础知识的 36 个知识点分成三个层级：

前端基础学习路径：三层递进

💡 学习建议：先把基础层全部搞懂，能写出静态页面；再练标准层，能独立完成业务需求；最后研究深入层，理解为什么这么写，遇到bug能定位。

2基础层 · 入门必备 基础

这一层是前端入门的最低要求，共 11 个知识点，看完就能写出第一个网页。

2.1 HTML 文档结构与基本标签 基础

HTML 是网页的骨架，浏览器从上到下解析标签，渲染出页面。

  • DOCTYPE：声明 HTML 版本，`<!DOCTYPE html>` 告诉浏览器用标准模式渲染
  • head：元信息，不显示在页面上（编码、标题、CSS、SEO）
  • body：页面所有可见内容都写在这里
  • 文本标签：h1~h6 标题、p 段落、a 超链接（href / target）、strong / em 强调、span 行内
  • 容器与列表：div 块级容器、ul>li 无序列表、ol>li 有序列表
  • 媒体标签：img（src / alt 必填，alt 描述图片）、video / audio、link 引入CSS、script 引入JS
  • 属性：id 全局唯一、class 可复用、data-* 自定义数据属性
  • 空标签：不需要闭合，如 img、br、hr、input、meta
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的第一个页面</title>
</head>
<body>
  <h1>Hello World</h1>
  <p>这是我的第一个网页，点我看看：</p>
  <a href="https://example.com" target="_blank">新窗口打开</a>
  <img src="logo.png" alt="站点Logo">
</body>
</html>

2.2 HTML 语义化标签 基础

用「有含义」的标签描述内容结构，而不是一摞 div 堆砌。

  • 好处：利于 SEO（搜索引擎读懂结构）、无障碍（读屏软件朗读）、代码可维护
  • 结构标签：header 页头、nav 导航、main 主体、section 区块、article 独立文章、aside 侧栏、footer 页脚
  • 内容标签：figure / figcaption 配图、time 时间、mark 标记、details / summary 折叠
  • 注意：一个页面建议只用一个 h1 主标题；div 依然用于纯样式容器
<header> 站点标题 </header>
<nav> 导航链接 </nav>
<main>
  <section>
    <h1>文章标题</h1>
    <article>正文内容</article>
  </section>
</main>
<aside> 侧边栏 </aside>
<footer> 版权信息 </footer>

2.3 HTML 表格与表单 基础

表格展示二维数据，表单收集用户输入，是业务页面的两大主力。

  • 表格结构：table > thead / tbody / tfoot，行 tr，单元格 th（表头）/ td
  • 合并单元格：rowspan 跨行、colspan 跨列
  • 表单提交：form 的 action 提交地址、method（GET 参数在 URL，POST 在请求体）
  • 常用控件：input（text / password / email / number / checkbox / radio / file / date）、select>option、textarea、button
  • 属性：required 必填、placeholder 占位提示、maxlength 长度限制、disabled 禁用、readonly 只读
  • label：for 指向控件 id，点击文字即可聚焦/选中
<table>
  <thead>
    <tr><th>姓名</th><th>年龄</th></tr>
  </thead>
  <tbody>
    <tr><td>张三</td><td>25</td></tr>
  </tbody>
</table>

<form action="/api/register" method="POST">
  <label for="username">用户名</label>
  <input id="username" name="username" type="text" required>
  <label for="pwd">密码</label>
  <input id="pwd" name="pwd" type="password" minlength="6">
  <button type="submit">注册</button>
</form>

2.4 CSS 选择器与优先级 基础

CSS 给 HTML 化妆：选择器找到元素，然后设置样式属性。

  • 基础选择器：标签 div { }、类 .box { }（最常用）、ID #header { }（全局唯一）、通配 *
  • 组合选择器：后代（空格）、子代 >、相邻兄弟 +、通用兄弟 ~
  • 属性选择器：[type="text"]、[href^="https"] 开头、[href$=".pdf"] 结尾、[class*="btn"] 包含
  • 伪类：:hover、:focus、:active、:first-child、:last-child、:nth-child(n)、:not(选择器)
  • 伪元素：::before / ::after 配合 content 插入装饰内容
  • 优先级（权重）：!important > 内联 style > ID > 类/属性/伪类 > 标签/伪元素 > 通配；同权重时后写的生效
/* 后代选择器：容器内的 p 变蓝色 */
.container p { color: #1d4ed8; }

/* 子代选择器：直接子元素 */
.list > li { margin: 8px 0; }

/* 伪类：悬停效果 */
.btn:hover { background: #1d4ed8; color: #fff; }

/* 伪元素：前缀装饰 */
.required::before { content: "*"; color: red; }

2.5 CSS 盒模型 基础

每个元素都是一个盒子：内容区 + 内边距 + 边框 + 外边距，理解它才能算对尺寸。

  • 四层结构：content 内容 → padding 内边距 → border 边框 → margin 外边距
  • box-sizing: content-box（默认）：width 只算内容区，总宽 = width + padding + border
  • box-sizing: border-box：width 包含 padding 和 border，布局更可控（全局推荐）
  • 外边距折叠（margin collapse）：垂直相邻的 margin 取较大值而非相加；父子间也会折叠
  • 解决折叠：给父元素加 overflow: hidden、padding、border，或改用 flex / grid 布局
  • BFC（块级格式化上下文）：overflow: hidden、display: flow-root 等可触发，用于清除浮动、隔离布局
/* 全局统一盒模型，推荐写法 */
* { box-sizing: border-box; }

.box {
  width: 200px;        /* border-box 下：总宽就是 200px */
  padding: 20px;
  border: 2px solid #1d4ed8;
  margin: 10px;
}

2.6 CSS 常用属性 基础

掌握高频属性，写页面时信手拈来。

  • 文本：color、font-size、font-family、font-weight、line-height 行高、text-align、text-decoration、letter-spacing 字间距、white-space
  • 背景：background-color、background-image、background-size（cover 铺满 / contain 完整包含）、background-position、background-repeat
  • 边框与圆角：border 简写、border-radius 圆角
  • 显示方式：display: block 块级 / inline 行内 / inline-block 行内块 / none 隐藏
  • 隐藏三兄弟的区别：display:none 不占位；visibility:hidden 占位不可见；opacity:0 占位且仍响应事件
  • 单位：px 固定像素、rem 相对根字号（推荐）、em 相对父字号、%、vw / vh 相对视口
.card {
  color: #1e293b;           /* 文字颜色 */
  font-size: 14px;          /* 字号 */
  line-height: 1.7;         /* 行高，建议 1.5~1.8 */
  font-weight: 600;         /* 字重 400 常规 / 700 粗体 */
  background: #f8fafc;
  border: 1px solid #e2e8f0;
  border-radius: 8px;       /* 圆角 */
  padding: 20px;
}

2.7 JavaScript 变量与数据类型 基础

JS 让网页动起来：存数据、做判断、处理交互。

  • 声明变量：let 可变变量、const 常量（推荐默认 const）、var 旧语法（函数级作用域，易出问题）
  • 基本类型（7 种）：number 数字、string 字符串、boolean 布尔、null、undefined、symbol 唯一值、bigint 大整数
  • 引用类型：object（含数组 Array、函数 Function）
  • typeof 的坑：typeof null === "object"（历史遗留 bug），判断 null 要用 === null
  • 字符串常用方法：length、indexOf、slice、split、replace、toUpperCase / toLowerCase、trim、includes、startsWith
  • 数字注意：NaN 表示非数字（NaN !== NaN）、Infinity 无穷大、浮点精度问题（0.1 + 0.2 !== 0.3）
const name = '张三';    // 字符串
let age = 25;            // 数字
const isStudent = true;  // 布尔

// 字符串方法
console.log(name.length);        // 2
console.log(name.includes('张')); // true
console.log(name.slice(0, 1));   // '张'

// 类型判断
console.log(typeof age);         // 'number'
console.log(null === null);      // true，判断 null 的正确方式

2.8 JS 运算符与类型转换 基础

运算符是计算的工具，理解隐式转换才能避开最常见的坑。

  • 算术：+ - * / %（取余）**（幂）；自增 ++ 自减 --
  • 比较：> < >= <=；== 宽松相等会做类型转换，=== 严格相等要求类型一致（推荐）
  • 逻辑：&& 与、|| 或、! 非；短路求值（a || b 中 a 为真就不看 b）
  • 空值合并 ??：只在左侧是 null / undefined 时取右侧，与 || 不同（|| 对 0 和空字符串也会兜底）
  • 三元：条件 ? 值A : 值B
  • 隐式转换："5" - 2 === 3（转数字）、"5" + 2 === "52"（+ 遇字符串拼接）、Boolean("") === false
  • 显式转换：Number("10")、String(10)、parseInt("10px") === 10
// 严格相等 vs 宽松相等
console.log(1 === '1');  // false，类型不同
console.log(1 == '1');   // true，会转换

// 空值合并
const a = 0;
console.log(a || '兜底');  // '兜底'，0 被当成 falsy
console.log(a ?? '兜底');  // 0，只有 null/undefined 才兜底

// 三元
const age = 20;
const type = age >= 18 ? '成年' : '未成年';

2.9 JS 流程控制 基础

分支与循环是程序的基本结构。

  • 分支：if / else if / else；switch（用严格相等比较，记得 break）
  • 循环：for（计数）、while（先判断）、do-while（至少执行一次）
  • for...of：遍历可迭代对象（数组、字符串、Map、Set），拿到值
  • for...in：遍历对象键名（也会遍历原型链属性，数组慎用）
  • 跳出：break 跳出整个循环、continue 跳过本次
// for 循环
for (let i = 0; i < 5; i++) {
  if (i === 2) continue; // 跳过 2
  if (i === 4) break;    // 到 4 停止
  console.log(i);        // 0 1 3
}

// for...of 遍历数组
const list = ['a', 'b', 'c'];
for (const item of list) {
  console.log(item);
}

// for...in 遍历对象
const user = { name: '张三', age: 25 };
for (const key in user) {
  console.log(key, user[key]);
}

2.10 JS 函数 基础

函数是复用逻辑的基本单元，三种写法各有用处。

  • 函数声明：function fn() {}，有提升，可在声明前调用
  • 函数表达式：const fn = function() {}，没有提升
  • 箭头函数：const fn = () => {}，写法简洁，但没有自己的 this 和 arguments（后文深入层讲）
  • 参数：默认参数 function fn(a = 1) {}；rest 参数 (...args) 收集剩余参数为数组
  • return：返回结果；不写 return 返回 undefined
  • IIFE 立即执行函数：(function() { ... })()，用于封装作用域、避免变量污染
// 函数声明
function add(a, b) {
  return a + b;
}

// 箭头函数（推荐用于简单逻辑）
const double = (n) => n * 2;

// 默认参数 + rest 参数
function greet(name = '朋友', ...tags) {
  return `你好，${name}，标签：${tags.join(',')}`;
}

// IIFE：立即执行，封装作用域
(function () {
  const secret = '外部访问不到';
})();

2.11 浏览器开发者工具（DevTools）基础

3标准层 · 日常开发 标准

这一层是实际工作中每天都要用的技能，共 12 个知识点，掌握后就能独立写业务页面。

3.1 Flexbox 弹性布局 标准

Flex 是一维布局方案，处理一行或一列的排列对齐，替代传统的 float hack。

  • 容器属性：display:flex 开启；flex-direction 主轴方向（row / column）；flex-wrap 换行；gap 子项间距
  • 主轴对齐 justify-content：flex-start 左对齐 / center 居中 / flex-end / space-between 两端对齐 / space-around / space-evenly
  • 交叉轴对齐 align-items：stretch 拉伸 / center 居中 / flex-start 顶对齐 / flex-end / baseline 基线
  • 项目属性：flex-grow 放大比例、flex-shrink 缩小比例、flex-basis 基础尺寸；flex:1 是 flex: 1 1 0% 的简写（平均占位）
  • align-self：单个项目独立对齐；order 调整顺序
  • 经典场景：水平垂直居中 = justify-content:center + align-items:center
.container {
  display: flex;
  justify-content: space-between; /* 两端对齐 */
  align-items: center;            /* 垂直居中 */
  gap: 16px;                      /* 子元素间距16px */
  flex-wrap: wrap;                /* 放不下换行 */
}

.item {
  flex: 1; /* 占剩余空间的比例，等宽分布 */
}

.center {
  display: flex;
  justify-content: center;
  align-items: center;
}

3.2 Grid 网格布局 标准

Grid 是二维布局方案，同时控制行和列，适合页面整体骨架与卡片墙。

  • 定义行列：grid-template-columns / grid-template-rows，单位支持 px、%、fr（份）、auto
  • repeat 简写：repeat(3, 1fr) 等宽三列；gap / row-gap / column-gap 间距
  • 显式与隐式网格：超出声明行列的内容进入隐式网格，用 grid-auto-rows 控制其高度
  • 项目定位：grid-column: 1 / 3（从第1线到第3线）或 grid-column: span 2（跨两列）；grid-row 同理
  • 区域简写：grid-area 可一次定义四线，也可配合 grid-template-areas 命名布局
  • 对齐：justify-items / align-items（单元格内）、justify-content / align-content（整个网格）
  • 选型：一维排列用 Flex，二维行列布局用 Grid
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 三等分 */
  gap: 16px;
}

.card:first-child {
  grid-column: span 2; /* 第一个卡片占两列 */
}

/* 页面骨架 */
.layout {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}

3.3 定位与层级 标准

position 控制元素「站在哪」，z-index 控制「谁盖住谁」。

  • static（默认）：正常文档流，偏移属性无效
  • relative：相对自身原位置偏移（top / right / bottom / left），原占位保留，常作为 absolute 的定位父级
  • absolute：脱离文档流，相对「最近的定位祖先」（relative / absolute / fixed）定位；没有就相对视口
  • fixed：脱离文档流，相对视口固定（滚动不动）——悬浮按钮、弹窗遮罩
  • sticky：相对滚动容器，滚动到阈值后「吸住」——吸顶导航
  • z-index：仅对定位元素生效，数值越大越靠上；只在同一层叠上下文内比较
.wrap {
  position: relative; /* 作为定位父级 */
}

.dropdown {
  position: absolute;
  top: 40px;    /* 相对 .wrap 向下 40px */
  left: 0;
  z-index: 10;
}

.nav-sticky {
  position: sticky;
  top: 0;       /* 滚过顶部后吸住 */
}

.modal-mask {
  position: fixed;
  inset: 0;     /* top/right/bottom/left 全 0 */
  z-index: 999;
}

3.4 响应式布局与媒体查询 标准

一套代码适配手机、平板、电脑：视口设置 + 媒体查询 + 弹性单位。

  • 视口 meta：<meta name="viewport" content="width=device-width, initial-scale=1.0">，不加则手机端按桌面宽度缩放
  • 媒体查询：@media (max-width: 768px) { } 屏幕宽度 ≤768px 时生效；可组合 (min-width) 与 (max-width)
  • 移动优先：先写移动端样式，再用 min-width 逐级增强，逻辑更简单
  • 弹性单位：rem 相对根字号（html），em 相对父字号，%、vw / vh 相对视口；clamp() 可做流式字号
  • 常见断点：768px（平板）、992px（桌面）、1200px（大屏）——Bootstrap 系约定，按项目自定
  • 图片适配：img { max-width:100%; height:auto; }；srcset 按屏幕密度换图
/* 基础样式（移动端优先） */
.container { padding: 12px; }

3.6 事件冒泡与事件委托 标准

事件会从目标元素向上传播（冒泡），利用这点把监听器统一挂到父级，就是事件委托。

  • 传播三阶段：捕获（外层→内层）→ 目标 → 冒泡（内层→外层），默认监听在冒泡阶段触发
  • stopPropagation()：阻止继续传播；stopImmediatePropagation() 还阻止同元素其他监听
  • preventDefault()：阻止默认行为（a 跳转、form 提交），不阻止传播
  • 事件委托：父元素统一监听，用 e.target 判断具体子元素；子元素动态增删也无需重新绑定
  • 优点：监听器数量少（性能）、支持动态列表、逻辑集中
// 委托：给 ul 绑一个监听，处理所有 li 点击
document.querySelector('#list').addEventListener('click', function (e) {
  const li = e.target.closest('li'); // 找到最近的 li
  if (!li) return;                   // 点击的不是 li 就忽略
  console.log('点击了：', li.textContent);
});

// 阻止冒泡场景：弹窗内点击不触发外层
popup.addEventListener('click', function (e) {
  e.stopPropagation();
});

3.7 Fetch 网络请求 标准

前端通过 HTTP 请求从后端拿数据，Fetch 是浏览器内置的请求 API。

  • HTTP 方法：GET 拿数据（参数在 URL）、POST 新增、PUT 全量更新、DELETE 删除、PATCH 部分更新

4.1 作用域与作用域链 深入

作用域决定变量「在哪里可见」；作用域链决定变量「按什么顺序查找」。

  • 三类作用域：全局、函数（function 声明内）、块级（let / const 在 { } 内）
  • var vs let/const：var 只有函数作用域且会提升（值为 undefined）；let / const 有块级作用域，且存在暂时性死区（TDZ，声明前访问报错）
  • 作用域链：函数定义时确定词法环境，查找变量时从内向外逐层找，直到全局；找不到报 ReferenceError
  • 执行上下文：调用函数时创建，包含变量对象、作用域链、this；调用栈记录调用顺序
  • 严格模式："use strict" 下未声明赋值直接报错，函数内 this 为 undefined（非严格下是全局对象）
let global = '全局';

function outer() {
  let outerVar = '外部';
  function inner() {
    let innerVar = '内部';
    // 查找顺序：innerVar → outerVar → global
    console.log(innerVar, outerVar, global);
  }
  inner();
}

outer();

// var 提升的坑
console.log(a); // undefined（已提升但未初始化）

// console.log(b); // 报错：TDZ，let 声明前不可访问
let b = 2;

4.2 闭包（Closure）深入

函数 + 它能访问的外部变量 = 闭包。内部函数记住了外部作用域，即使外部函数已经执行完。

  • 核心作用：创建私有变量、函数工厂、柯里化、实现防抖节流
  • 经典坑：循环中用 var 绑事件，所有回调拿到最后一个值——因为共享同一个变量；用 let 或 IIFE 解决
  • 内存：闭包持有变量引用使其不被回收；不要无必要地创建长生命周期闭包（可能内存泄漏）
  • 注意：每次调用外部函数都会创建新的闭包实例
// 闭包实现计数器：count 是私有变量
function createCounter() {
  let count = 0;
  return {
    increment: () => ++count,
    getCount: () => count
  };
}

const counter = createCounter();
counter.increment();
counter.increment();
console.log(counter.getCount()); // 2

// 经典坑：var + 循环
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // 3 3 3
}
// 修复：let（每次循环独立块级作用域）

  setTimeout(() => console.log(j), 100); // 0 1 2

4.3 this 指向与 call / apply / bind 深入

this 不是写代码时定死的，而是调用时根据「怎么调」决定指向谁。

  • 默认绑定：普通函数独立调用，非严格模式 this 是全局对象（浏览器 window），严格模式是 undefined
  • 隐式绑定：obj.fn() 调用，this 指向 obj（调用者）
  • 显式绑定：fn.call(thisArg, ...)、fn.apply(thisArg, argsArray) 立即调用；fn.bind(thisArg) 返回新函数（不立即执行）
  • new 绑定：new 构造函数时，this 指向新创建的对象
  • 箭头函数：没有自己的 this，继承定义时的外层 this；不能用作构造函数
  • 优先级：new > 显式绑定 > 隐式绑定 > 默认绑定
const user = {
  name: '张三',
  greet() {
    console.log('你好，' + this.name);
  }
};
user.greet(); // 隐式绑定 → 张三

const fn = user.greet;
// fn(); // 默认绑定 → this 是 undefined（严格模式）或 window

fn.call(user);    // 显式绑定 → 张三
fn.apply(user);
const bound = fn.bind(user); // 返回新函数
bound();                      // 张三

// 箭头函数继承外层 this
const counter = {
  count: 0,
  start() {
    setInterval(() => this.count++, 1000); // this 是 counter
  }
};

4.4 原型链与继承 深入

4.5 事件循环与异步原理 深入

JS 是单线程的，为什么能处理异步？靠事件循环：把异步任务放进队列，同步代码执行完再依次处理。

  • 同步任务：在调用栈上立刻执行；栈为空时进入「取任务」环节
  • 微任务：Promise.then / catch / finally、MutationObserver、queueMicrotask、await 之后的代码；优先级高，每轮清空
  • 宏任务：setTimeout、setInterval、I/O、事件回调；每轮只取一个，然后再次清空微任务
  • 执行顺序：同步 → 清空全部微任务 → 取一个宏任务 → 可能渲染 → 重复
  • Promise：pending → fulfilled / rejected，状态不可逆；Promise.all 全成功、race 最快、allSettled 全部结果、any 首个成功
  • async / await：语法糖；async 函数返回 Promise；await 让出线程，后续代码进微任务
console.log('1'); // 同步

setTimeout(() => console.log('2'), 0); // 宏任务

Promise.resolve().then(() => console.log('3')); // 微任务

console.log('4'); // 同步

// 输出顺序：1 → 4 → 3 → 2
// （先清空微任务 3，再执行宏任务 2）

// Promise.all：等全部成功
const [a, b] = await Promise.all([
  fetch('/api/a').then(r => r.json()),
  fetch('/api/b').then(r => r.json())

4.6 深拷贝与浅拷贝 深入

对象是引用类型：赋值只是复制引用。拷贝要区分「一层」还是「全部层」。

  • 引用赋值：const b = a 后改 b 会改 a（同一个对象）
  • 浅拷贝：展开 {...obj}、Object.assign、Array.slice()——只复制第一层，嵌套对象仍是共享引用
  • 深拷贝 JSON 法：JSON.parse(JSON.stringify(obj))——缺点：函数 / undefined / Symbol 丢失、Date 变字符串、NaN 变 null、循环引用报错
  • structuredClone：现代浏览器原生深拷贝，支持循环引用与 Date / Map / Set，但不支持函数
  • 手写深拷贝：递归 + WeakMap 记录已拷贝对象（解决循环引用）+ 按类型处理数组与对象
  • 场景：状态管理防篡改、表单回显备份、跨线程传数据
const original = { a: 1, list: [1, 2], user: { name: '张三' } };

// 浅拷贝：嵌套对象仍是引用
const shallow = { ...original };
shallow.user.name = '改到了'; // original 也被改了

// 深拷贝方案一：JSON（有局限）
const deep1 = JSON.parse(JSON.stringify(original));

// 深拷贝方案二：structuredClone（推荐）
const deep2 = structuredClone(original);

// 手写深拷贝核心
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (map.has(obj)) return map.get(obj); // 循环引用
  const copy = Array.isArray(obj) ? [] : {};
  map.set(obj, copy);
  for (const key of Object.keys(obj)) {
    copy[key] = deepClone(obj[key], map);
  }
  return copy;
}

4.7 防抖与节流 深入

高频事件（输入、滚动、拖拽）不能每次都执行重逻辑，用防抖 / 节流控制频率。

  • 防抖 debounce：停止触发后延迟执行——适合输入搜索、窗口 resize（等用户「消停」）
  • 节流 throttle：固定时间间隔内最多执行一次——适合滚动加载、拖拽移动（保证频率上限）
  • 区别一句话：防抖看「最后一次」，节流看「频率上限」
  • 实现要点：闭包保存定时器；组件卸载时清除定时器防止内存泄漏
// 防抖：停止输入 300ms 后才执行
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 节流：每 500ms 最多执行一次
function throttle(fn, interval = 500) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}

// 使用
const onSearch = debounce(async (kw) => {
  const res = await fetch('/api/search?q=' + kw);
  console.log(await res.json());
}, 300);

input.addEventListener('input', (e) => onSearch(e.target.value));

4.8 浏览器渲染原理 深入

从 HTML 到屏幕上的像素，浏览器经历了解析、样式计算、布局、绘制、合成五步。

  • 构建 DOM 与 CSSOM：解析 HTML 生成 DOM 树，解析 CSS 生成 CSSOM 树，两者合并成渲染树（只含可见节点）
  • 布局 Layout（回流 reflow）：计算每个元素的几何位置与尺寸——代价最高
  • 绘制 Paint（重绘 repaint）：填充像素（颜色、背景、边框）
  • 合成 Composite：分层合成到屏幕；transform / opacity 只走合成（GPU 加速），是最优路径
  • 触发回流：改尺寸 / 位置 / 增删 DOM、读写 offsetWidth 等布局属性（强制同步布局）
  • 触发重绘：改颜色 / 背景 / visibility；回流必伴随重绘
  • 优化：批量改 DOM（文档碎片）、样式集中改（classList）、读写分离、用 transform 做动画、防抖节流滚动
  • 关键渲染路径：script 加 defer / async 不阻塞解析；CSS 放 head 提前加载

4.9 浏览器缓存机制 深入

浏览器把静态资源存在本地，下次不用再下载，加快页面加载。

  • 强缓存：Cache-Control（max-age 秒数 / no-cache 每次询问 / no-store 不缓存）、Expires（HTTP/1.0，已过时）——命中直接用本地，不发请求
  • 协商缓存：ETag / If-None-Match（内容指纹）、Last-Modified / If-Modified-Since（最后修改时间）——问服务器，没变返回 304 用本地
  • 优先级：Cache-Control 优先于 Expires；ETag 优先于 Last-Modified
  • 最佳实践：带 hash 的 JS / CSS / 图片用强缓存（文件名变 = 内容变，天然失效）；HTML 用 no-cache 保证拿最新
  • 启发式缓存：没有显式缓存头时，浏览器可能按 Last-Modified 估算缓存时间

4.10 HTTP 协议与状态码 深入

HTTP 是浏览器与服务器的对话语言：方法表达意图，状态码表达结果。

  • 请求方法：GET 读（幂等安全）、POST 增、PUT 全量更新、PATCH 部分更新、DELETE 删、HEAD 只要响应头、OPTIONS 预检 / 探测
  • 2xx 成功：200 OK、201 Created、204 No Content
  • 3xx 重定向：301 永久移动（SEO 常用）、302 临时、304 Not Modified（协商缓存命中）、307 / 308 保留方法的重定向
  • 4xx 客户端错误：400 参数错误、401 未认证、403 无权限、404 不存在、405 方法不允许、409 冲突、422 校验失败、429 请求过频
  • 5xx 服务端错误：500 内部错误、502 网关错误、503 服务不可用、504 网关超时
  • 常见头：Content-Type、Content-Length、Authorization、Accept、Cache-Control、CORS 相关头
  • HTTP/1.1 vs HTTP/2：1.1 连接复用但队头阻塞；2.0 二进制分帧 + 多路复用 + 头部压缩，显著提速
  • HTTPS：在 HTTP 之上加 TLS；混合加密（非对称交换密钥 + 对称加密数据）；证书验证身份
// 一个完整请求的常见链路
// 浏览器输入 URL → DNS 解析 → TCP 连接 → TLS 握手（HTTPS）→ 发送 HTTP 请求 → 服务器响应 → 浏览器渲染

// 常见判断
fetch('/api/data').then(res => {
  if (res.status === 401) {
    // 未登录：跳转登录页
  } else if (res.status === 403) {
    // 无权限
  } else if (res.status === 404) {
    // 资源不存在
  }
});

4.11 同源策略与跨域 深入

浏览器默认禁止跨域读取数据（同源策略），跨域请求需要服务端配合放行（CORS）。

  • 同源定义：协议 + 域名 + 端口三者完全相同；如 https://a.com:443 与 https://a.com 同源
  • 为什么限制：防止恶意网站读取其他网站的 Cookie 与数据（安全边界）
  • CORS：由服务端返回响应头 Access-Control-Allow-Origin 放行指定来源
  • 简单请求：GET / POST / HEAD + 有限请求头，直接发；预检请求 preflight：非简单请求先发 OPTIONS 探询服务端允许
  • JSONP：利用 script 标签不受同源限制，服务端返回回调函数调用；仅支持 GET，且已不推荐（安全风险）
  • 开发环境解决：Vite / Webpack devServer proxy、Nginx 反向代理（同源转发）
  • ⚠️ 理解：跨域是浏览器的行为，不是后端拒绝；请求可能已到达后端，只是响应被浏览器拦下
// 服务端需要返回的响应头（后端配置）
// Access-Control-Allow-Origin: https://a.com
// Access-Control-Allow-Methods: GET, POST, PUT, DELETE
// Access-Control-Allow-Headers: Content-Type, Authorization
// Access-Control-Allow-Credentials: true（允许携带 Cookie）

// 前端带 Cookie 的跨域请求
fetch('https://api.b.com/data', {
  credentials: 'include'
});

4.12 前端安全：XSS 与 CSRF 深入

前端两大高危漏洞：XSS 偷数据、CSRF 替你发请求，开发时必须防御。

  • XSS（跨站脚本）：攻击者注入可执行脚本。三种：反射型（URL 参数）、存储型（存进数据库，如评论区）、DOM 型（前端 DOM 拼接）
  • XSS 防御：输出转义（框架默认转义）、不用 innerHTML 拼接用户内容、设置 CSP（内容安全策略）、HttpOnly Cookie、输入校验过滤
  • CSRF（跨站请求伪造）：诱导用户在已登录状态下向目标站点发请求（如转账、改密）；依赖浏览器自动携带 Cookie
  • CSRF 防御：Cookie 加 SameSite 属性、请求携带 CSRF Token 校验、校验 Origin / Referer、二次确认
  • 其他：点击劫持（X-Frame-Options: DENY）、敏感数据不落前端（密钥只放后端）
  • 安全编码：不 eval 用户输入、依赖保持更新（供应链漏洞）、Content-Security-Policy 白名单
// ❌ 危险：直接拼接用户输入（XSS）
// el.innerHTML = '<div>' + userInput + '</div>';

// ✅ 安全：textContent 转义输出
el.textContent = userInput;

// 或使用前端模板的自动转义（Vue/React 默认行为）

// CSRF Token 方案：请求头携带服务端下发的随机 token
fetch('/api/transfer', {
  method: 'POST',
  headers: { 'X-CSRF-Token': csrfToken },
  body: JSON.stringify({ to: 'xxx', amount: 100 })
});

4.13 Canvas 与 SVG 深入

浏览器里画图形的两条路线：SVG 矢量可交互，Canvas 位图高性能。

  • SVG：基于 XML 的矢量图，是 DOM 节点（可绑定事件、可 CSS 控制）；缩放不失真；适合图标、图形、数据可视化（数量少时）
  • Canvas：位图画布，JS 指令式绘制（getContext('2d')）；大量图形时性能更好；事件需自行做命中检测
  • 选型：数量少要交互用 SVG；数量大 / 动画密集用 Canvas；图表库 ECharts 默认 Canvas、可切 SVG 渲染
  • Canvas 基础：fillRect / strokeRect、beginPath + arc + fill / stroke、fillStyle / strokeStyle、渐变、fillText
  • 高清适配：canvas.width = 样式宽 × devicePixelRatio，否则高分屏模糊
  • 相关库：图表 ECharts / AntV、3D Three.js（WebGL，比 Canvas 2D 更底层）

const canvas = document.querySelector('#c');
const ctx = canvas.getContext('2d');
ctx.beginPath();
ctx.arc(100, 100, 50, 0, Math.PI * 2);
ctx.fillStyle = '#1d4ed8';
ctx.fill();

6常见误区与实战要点

新手常踩的坑：
  • CSS 优先级搞不清：以为后写的就一定覆盖，忽略了选择器权重（ID > 类 > 标签）
  • 闭包变量被共享：循环里用 var 声明变量，导致所有回调拿到的都是最后一个值（用 let 或 IIFE 解决）
  • 异步顺序搞反：以为 setTimeout(0) 会马上执行，其实它是宏任务，比 Promise（微任务）慢
  • 跨域不知道是谁的限制：不是后端拒绝，是浏览器的同源策略拦下了响应
  • localStorage 存对象不序列化：直接存对象，取出来是 "[object Object]"
  • fetch 不判断 res.ok：HTTP 404 / 500 不会进入 catch，必须自己判断状态码
  • 忘记 box-sizing：写了 width 又加 padding / border，实际宽度超出预期
  • 用 innerHTML 拼用户输入：直接导致 XSS，优先 textContent 或框架转义
  • sort 不传比较函数：[10, 2].sort() 得到 [10, 2]，因为默认按字符串排序
  • this 丢失：把 obj.method 单独取出来调用，this 不再是 obj，用 bind 或箭头函数固定
  • == 宽松相等：1 == '1' 为 true，容易隐藏类型 bug，一律用 ===
  • 深拷贝只用 JSON：遇到 undefined / Date / 循环引用就出错，大对象用 structuredClone
✅ 实战建议：基础层不用想太多，先照着写出来；标准层要练熟，形成肌肉记忆；深入层结合实际 bug 去理解，不要死背概念。调试时先开 DevTools 看 Console 与 Network，再动手改。
