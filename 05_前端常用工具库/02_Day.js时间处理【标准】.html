1简介与阅读指引

1.1 定位

Day.js 是一个 2KB 的轻量日期时间库：API 仿 Moment.js、核心不可变、插件按需加载。它解决的是"时间处理"这个前端经典泥潭——解析、格式化、加减、比较、时区。本篇按"为什么需要它 → 四个核心模型 → 分场景 API → 时间处理闭环"展开，重点标出日期库特有的坑（格式符大小写、diff 粒度、时区）。

1.2 痛点：原生 Date 为什么不够用

  • 月份从 0 开始：new Date(2026, 10, 15) 是 11 月 15 日——永远的坑源；
  • 可变性：d.setMonth(3) 直接改原对象，作为参数传递时被意外修改；
  • 格式化手写：getFullYear() + '-' + (getMonth()+1)... 每个项目写一遍；
  • 字符串解析不一致：new Date('2026-10-15') 与 new Date('2026/10/15') 在不同浏览器的时区解释不同；
  • 加减与比较：跨月加 30 天、"同一天吗"（到日还是到毫秒）都要自己绕。

1.3 适用 / 不适用场景

适合读本篇不适合（看别的）
项目在做时间展示/计算（表单、报表、倒计时）复杂时区业务（跨时区日历）→ 考虑 luxon/temporal，超出本篇
从 Moment.js 迁移或选型日期选择器组件用法 → 组件库文档

2核心模型

Day.js 的全部设计围绕四个模型：不可变、统一入口、插件体系、与 Moment 兼容的 API。

2.1 不可变（Immutable）：所有操作返回新实例

Day.js 的每个实例都不可变——dayjs().add(1, 'day') 返回新实例，原实例纹丝不动。两个推论：①必须接收返回值：d.add(1, 'day') 单独写一行是无效代码（新手第一大坑）；②可以安全传递：把实例当参数传给任何函数都不怕被改。这与原生 Date 的可变设计（setMonth 改自己）是根本分歧，也是"用库而不是裸用 Date"的最大理由之一。

2.2 统一入口：dayjs() 包装一切

无论输入是 Date 对象、ISO 字符串、时间戳还是无参（当前时间），都经 dayjs(x) 包装成 Dayjs 实例，之后统一用实例方法操作。判断"现在几点"用 dayjs()，校验合法用 dayjs(x).isValid()。约定：业务代码里不直接持有裸 Date，入口处立即包装，出口处再 format——把原生 Date 的坑挡在边界上。

2.3 插件体系：核心 2KB，能力按需加载

核心只保留最常用的解析/格式化/加减；utc、时区、相对时间、自定义解析、周数等能力全部以插件提供，用哪个 extend 哪个：

import dayjs from 'dayjs'
import relativeTime from 'dayjs/plugin/relativeTime'
dayjs.extend(relativeTime)          // 注册一次，全局生效

dayjs().fromNow()   // "3 天前"（未注册插件时此方法不存在）

坑预警：忘了注册插件 → 调用报 not a function（坑 5）。反过来这也是体积优势：不用时一个字节都不进包。

2.4 与 Moment 的关系：API 兼容的轻量替代

Day.js 的 API 刻意与 Moment.js 兼容（老项目迁移成本低），核心差异三点：①体积——核心 ~2KB vs Moment ~70KB；②不可变——Moment 实例可变（历史包袱）；③插件化——Moment 是大而全单体。结论：新项目直接 Day.js；Moment 已进入维护模式，存量项目渐进迁移。

3核心 API 精讲（按场景）

四个日常场景：解析与格式化、加减与差值、比较判断、相对时间与时区。

3.1 场景一：解析与格式化

import dayjs from 'dayjs'

// 解析：字符串/Date/时间戳统一入口
dayjs('2026-10-15 09:30:00')
dayjs(new Date())            // 从裸 Date 包装
dayjs(1760000000000)         // 毫秒时间戳

// 格式化：常用格式符
dayjs().format('YYYY-MM-DD HH:mm:ss')   // 2026-10-15 14:30:05
dayjs().format('YYYY年M月D日 dddd')      // 本地化星期（需配 locale）
dayjs().format('MM/DD HH:mm')           // 列表时间
// 常用格式符速记：YYYY 四位年 / MM 两位月 / DD 两位日 /
// HH 24时 / mm 分 / ss 秒 / dddd 星期全称 / A 上午下午

格式符大小写陷阱（高频坑，详见 7.2）：YYYY 是年、yyyy 在 Day.js 无效或含义不同；DD 是两位日、dd 是星期缩写——写错不报错，只是输出诡异。

3.2 场景二：加减与差值（add / subtract / diff）

// 加减：单位 'day'/'month'/'year'/'hour'/'minute'/'second'
dayjs('2026-10-15').add(1, 'month').format('YYYY-MM-DD')   // 2026-11-15（自动进位）
dayjs().subtract(7, 'day')                                  // 一周前

// 差值：diff 的粒度由单位参数决定
dayjs('2026-10-15').diff(dayjs('2026-09-30'), 'day')        // 15
dayjs('2026-10-15').diff(dayjs('2026-09-30'), 'month')      // 0（不满整月为 0）
// 倒计时：毫秒差自己换算
const ms = dayjs('2026-12-31').diff(dayjs())

diff 粒度陷阱（详见 7.3）：diff 按完整单位计数——10-15 与 9-30 差 15 天但差 0 个"整月"；要"月差"语义需自己按天换算或用 exactDate 相关选项。

3.3 场景三：比较判断（isBefore / isSame / isAfter）

const now = dayjs()
now.isBefore('2026-12-31')                    // 毫秒级比较
now.isSame(dayjs(), 'day')                    // ⚠️ 单位参数决定粒度
now.isSame('2026-10-15', 'date')              // "是同一天"必须给 'date'/'day'
// 区间：需要插件
import isBetween from 'dayjs/plugin/isBetween'
dayjs.extend(isBetween)
now.isBetween('2026-10-01', '2026-10-31', 'day', '[]')  // [] 含边界

核心认知：isSame(a) 不带单位是毫秒级相等（几乎永远 false）；"是不是同一天"必须传 'day'——这是 Day.js 使用频率最高的坑。

3.4 场景四：相对时间与时区

// 相对时间：评论区"3 小时前"
import relativeTime from 'dayjs/plugin/relativeTime'
import 'dayjs/locale/zh-cn'
dayjs.extend(relativeTime); dayjs.locale('zh-cn')
dayjs().subtract(3, 'hour').fromNow()        // 3 小时前

// UTC：跨时区展示（服务器时间用 UTC 存，前端转本地展示）
import utc from 'dayjs/plugin/utc'
dayjs.extend(utc)
dayjs.utc('2026-10-15T06:00:00Z').local().format('HH:mm')  // 转本地时间

4进阶知识点【进阶】

首次学习可整章跳过。前置：已熟练使用第 3 章 API。

4.1 customParseFormat：非标准格式解析

dayjs('15/10/2026', 'DD/MM/YYYY') 需要 customParseFormat 插件——没有它，Day.js 把无法识别的字符串直接判 invalid。后端给非 ISO 格式时必开此插件，并显式声明格式，杜绝浏览器解析歧义。

4.2 locale 国际化

两套机制：dayjs.locale('zh-cn') 全局切换；dayjs(x).locale('en') 单实例切换（报表多语言并排时用后者）。注意 locale 只影响文字输出（星期名、相对时间文案），不影响数值与计算；周的起始日由 locale 定义（中欧周一起始 vs 美式周日），影响 week() 相关计算。

4.3 时间的边界语义：startOf / endOf

dayjs().startOf('day')（当天 00:00:00.000）与 endOf('month')（月末 23:59:59.999）是区间查询的基石：查"今天的订单" = createdAt >= startOf('day') && <= endOf('day')。注意 endOf 的毫秒是 999——用 < 下一个 startOf 代替 <= endOf 是更稳的区间写法（避免毫秒精度歧义）。

4.4 性能与内存：实例复用与避免链式过长

Day.js 实例轻量，常规使用无性能问题。两个注意：①循环里重复 dayjs()（取当前时间）提到循环外；②超长链式（add 之后 subtract 再 add）优先用中间变量命名步骤——可读性与可调试性优于"一行流"。

6最小可运行 Demo

一个真实场景串起 API：活动倒计时 + 月度账单周期 + 评论区相对时间。安装 npm i dayjs 即跑。

6.1 完整代码

import dayjs from 'dayjs'
import relativeTime from 'dayjs/plugin/relativeTime'
import 'dayjs/locale/zh-cn'
dayjs.extend(relativeTime); dayjs.locale('zh-cn')

// —— 场景 1：活动倒计时（天/时/分/秒 换算）——
const deadline = dayjs('2026-12-31 23:59:59')
const ms = deadline.diff(dayjs())                  // 毫秒差
const days  = Math.floor(ms / 86400000)
const hours = Math.floor(ms % 86400000 / 3600000)
const mins  = Math.floor(ms % 3600000 / 60000)
console.log(`距结束还有 ${days} 天 ${hours} 小时 ${mins} 分钟`)

// —— 场景 2：月度账单周期（startOf/endOf 区间）——
const billMonth = dayjs('2026-10-15')
const from = billMonth.startOf('month')            // 10-01 00:00:00
const to   = billMonth.endOf('month')              // 10-31 23:59:59.999
console.log(from.format('YYYY-MM-DD HH:mm:ss'), '~', to.format('YYYY-MM-DD HH:mm:ss'))
console.log('上月同期:', billMonth.subtract(1, 'month').startOf('month').format('YYYY-MM-DD'))

// —— 场景 3：账单"是否本期"（isSame 带单位）——
const someOrderTime = dayjs('2026-10-20 08:00:00')
console.log('属于本期账单:', someOrderTime.isSame(billMonth, 'month'))  // true

// —— 场景 4：评论区相对时间 ——
console.log(dayjs().subtract(3, 'hour').fromNow())       // 3 小时前
console.log(dayjs('2026-10-01').fromNow())               // X 个月前

// —— 反例：不可变，光调用不接收 = 无效 ——
let d = dayjs('2026-10-15')
d.add(1, 'day')                                          // ⚠️ 无效调用
console.log(d.format('YYYY-MM-DD'))                      // 还是 2026-10-15
d = d.add(1, 'day')                                      // ✅ 接收返回值
console.log(d.format('YYYY-MM-DD'))                      // 2026-10-16

6.2 逐段解析

  • 倒计时：diff 取毫秒差后手动换算——不要用 diff(x, 'hour') 这类"整单位"语义做倒计时（不满整点直接为 0）；
  • 账单区间：startOf/endOf 定义区间边界，配合 isSame(单位) 做"归属判断"；
  • 相对时间：relativeTime 插件 + zh-cn locale，两行配置，评论区文案直接产出；
  • 反例段：刻意的无效调用示范——不可变库里最常见的"代码写了但没生效"。

6.3 生产改造扩展方向

  1. 倒计时封装为 Vue/React Hook（内部 setInterval + 卸载清理）；
  2. 账单周期抽成纯函数 getBillPeriod(date)，单测覆盖跨年 2 月；
  3. 后端时间统一 UTC ISO 字符串，前端入口处 dayjs.utc(x).local() 转本地（4.3 配套）。

7常见坑 & Debug

按"不可变 → 语义 → 环境"分组，每条五要素。

7.1 不可变相关

坑 1：光调用不接收返回值

  • 现象：d.add(1, 'day') 执行了，d 纹丝不动；
  • 根因：Day.js 不可变设计——所有方法返回新实例，原实例永不变；
  • 复现：第 6 章 Demo 的反例段；
  • 修复：d = d.add(1, 'day')；
  • 规避：ESLint 规则 no-unused-expressions 可拦截这类孤立调用。

7.2 语义相关

坑 2：格式符大小写写错

  • 现象：format('yyyy-MM-dd') 输出里的"日期"变成了星期缩写或无效字符；
  • 根因：Day.js 格式符有严格语义——YYYY 年 / DD 两位日 / dd 星期缩写 / HH 24 时（hh 是 12 时）；
  • 复现：对照官方 format 表逐字符检查；
  • 修复：改正大小写；
  • 规避：团队沉淀常用格式串常量（'YYYY-MM-DD HH:mm:ss' 等），不手打。

坑 3：diff / isSame 的粒度没给单位

  • 现象 A：d1.diff(d2, 'month') 明明跨了月却返回 0；现象 B：isSame(other) 永远 false；
  • 根因：diff 按完整单位计数（15 天不足整月 = 0）；isSame 不带单位是毫秒级比较；
  • 修复："同一天"用 isSame(x, 'day')；"月差"按业务语义换算（天差/30 或精确日历差）；
  • 规避：code review 约定——isSame/diff 不带单位参数的调用必须有注释说明理由。

坑 4：字符串解析的浏览器/时区歧义

  • 现象：同一段 dayjs('2026-10-15 08:00') 在不同环境差了 8 小时；
  • 根因：非 ISO 格式（空格分隔、无时区标记）的解析行为依赖实现；带 Z 的 ISO 按 UTC、不带按本地；
  • 修复：后端输出统一 ISO UTC（2026-10-15T00:00:00Z），前端用 utc 插件 dayjs.utc(x).local()；非标准格式用 customParseFormat 显式声明；
  • 规避：接口时间字段格式写进前后端契约文档。

7.3 环境相关

坑 5：插件方法报 not a function

  • 现象：dayjs().fromNow is not a function；
  • 根因：用了插件能力但没 extend 注册（utc/relativeTime/isBetween 都要）；
  • 修复：入口文件统一注册所有用到的插件；
  • 规避：封装 setupDayjs() 统一做插件与 locale 配置，业务侧只 import 这个入口。

8重点讲解

Q1：Day.js 为什么设计成不可变？

参考答案：三个理由。①安全性：时间对象常被多处传递（组件 props、状态、缓存），可变对象会被意外修改产生难查的 bug——不可变从根上消除这类问题；②可预测性：操作即返回新值，与 str.slice() 等原生习惯一致，链式调用语义清晰；③并发/缓存友好：实例可以放心缓存复用（不可变天然线程安全的单线程版）。

代价：忘接收返回值就"没生效"——这是新手最常踩的坑，但也正是不可变语义的直接体现。

Q2：为什么选 Day.js 而不是 Moment 或原生 Date？

参考答案：vs 原生——原生 Date 有月份 0 基、可变、解析歧义、格式化手写四大坑，Day.js 全部解决且入口统一；vs Moment——API 兼容使迁移成本低，但体积 2KB vs ~70KB、不可变 vs 可变、插件化 vs 单体，且 Moment 官方已进入维护模式并推荐新项目用替代品。结论：新项目默认 Day.js；存量 Moment 项目按模块渐进迁移。

加分点：能补一句"更复杂的时区场景会评估 luxon 或未来的 Temporal 标准"——说明选型视野在库之外。

Q3：isSame 不带单位和带 'day' 有什么区别？diff 的"整单位"语义是什么？

参考答案：isSame(x) 是毫秒级完全相等，两个不同的 dayjs() 调用几乎必然不等；isSame(x, 'day') 是日历日相等（同一天即 true）。diff(x, 'month') 计算完整月份跨度：10-15 与 9-30 差 15 天但不足整月，结果为 0。工程规则：比较与差值永远显式声明单位；"月差"类业务需求（如账龄 N 个月）要确认业务定义是"完整月"还是"日历月差"，两者实现不同。
