5.1Nginx 反向代理

Nginx 是前端最常用的 Web 服务器。正向代理代理客户端（VPN），反向代理代理服务器：

图 5.1-1　浏览器只知道 Nginx，Nginx 再把请求转发给后端或静态文件

Nginx 干什么

  • 静态资源服务：直接返回 HTML/JS/CSS 前端打包文件。
  • 反向代理：把 /api 请求转发给 Node 服务，解决跨域。
  • 负载均衡：把请求分给多个 Node 实例。
  • HTTPS 终止：在 Nginx 配证书，后端跑 HTTP 就行。
  • gzip 压缩、限流、缓存。

5.2Nginx 负载均衡策略

upstream backend {
  # 默认轮询，一个一个来
  server 127.0.0.1:3001;
  server 127.0.0.1:3002 weight=3;  # 权重，处理 3 倍请求
  # ip_hash;                       # 同一用户固定到同一台（解决 session）
}
策略说明场景
轮询（默认）依次分各服务器性能一样
加权轮询按 weight 比例分服务器配置不一样
ip_hash按客户端 IP 哈希固定需要会话保持
least_conn分给当前连接最少的请求耗时差异大

5.3消息队列

多一个中间件，换来异步和解耦。典型场景：用户下单后，要发邮件、发短信、扣库存、加积分——这些不用同步等。

💡 三个必须解决的问题：① 消息不能丢（生产确认+持久化+消费 ACK）；② 不能重复消费（消费端做幂等）；③ 积压了要能扩容消费。

6.1Git 分支策略

  • main：生产分支，每次合并都打 tag。
  • develop：开发集成分支。
  • feature/*：从 develop 切出来，开发完合并回 develop。
💡 merge vs rebase：merge 保留真实历史，会有分叉；rebase 把提交搬到最新后面，历史干净。公共分支用 merge，自己特性分支整理用 rebase。

6.2Docker 容器

容器和虚拟机的区别：虚拟机虚拟出一整套操作系统，容器共享宿主机内核，只隔离进程和文件系统，所以轻量秒级启动。

镜像分层

Docker 镜像是一层一层叠起来的，每层只读，多层共用。这就是为什么镜像可以复用、构建快。

6.3Dockerfile

# 后端 Dockerfile 示例
FROM node:20-alpine          # 基础镜像
WORKDIR /app                 # 工作目录
COPY package*.json ./        # 先拷依赖清单
RUN npm ci --production      # 装依赖（这层会缓存）
COPY . .                     # 再拷代码
EXPOSE 3000
CMD ["node", "dist/main.js"]
💡 构建优化关键：把变动少的层（依赖）放前面，变动多的层（代码）放后面。这样改代码不用重装依赖，利用镜像层缓存。

6.4Docker Compose

一个项目要同时跑前端、后端、MySQL、Redis、Nginx 五个容器，手动敲 docker run 太累，Compose 用一个 yml 编排：

services:
  web:       # 前端
    build: ./frontend
    ports: ["80:80"]
  api:       # 后端
    build: ./backend
    environment:
      - DB_HOST=mysql
  mysql:
    image: mysql:8
    volumes: ./data:/var/lib/mysql
  redis:
    image: redis:7

一条命令 docker compose up -d 全部启动。
