2.1盒模型与 BFC

每个 HTML 元素都是一个盒子，由内到外：content → padding → border → margin。

图 2.1-1　CSS 盒模型：从内到外 content / padding / border / margin

两种盒模型：

  • 标准盒模型 content-box：width 只算 content，实际占位 = width + padding + border。
  • IE 盒模型 border-box：width 包含 content+padding+border，实际占位更可控。项目里一般全局设 box-sizing: border-box。

BFC 是什么

BFC（块级格式化上下文）是一个独立的渲染容器，里面的布局不影响外面。触发条件：overflow:hidden、float、position:absolute、display:flex/grid 等。

💡 BFC 三个经典用途：① 清除浮动（父元素触发 BFC 就能包住浮动子元素）；② 阻止 margin 塌陷合并；③ 阻止元素被浮动元素覆盖（两栏布局）。

2.2Flex 布局

Flex 是一维布局：一根主轴 + 一根交叉轴。容器设 display:flex，子项自动排成弹性盒子。

属性作用常用值
justify-content主轴对齐flex-start / center / space-between
align-items交叉轴对齐flex-start / center / stretch
flex-direction主轴方向row / column
flex-grow剩余空间分配比例0（不放大）/ 1（平分）
flex-shrink空间不足时缩小比例1（默认缩小）
flex-basis初始占据主轴空间auto / 具体宽度
💡 flex:1 等价于 flex-grow:1; flex-shrink:1; flex-basis:0%——三个子项自动平分容器宽度，最常用。

2.3原型与原型链

JS 里每个对象都有一个隐藏属性 __proto__，指向它的原型对象。访问对象属性时，自身没有就沿着 __proto__ 往上找，这条链就是原型链。

三个关键角色

  • person.__proto__：实例的原型，指向构造函数的 prototype。
  • Person.prototype：构造函数的原型对象，所有实例共享的方法放在这。
  • Person.prototype.__proto__：再往上指向 Object.prototype，它的 __proto__ 是 null，链到头。
💡 new Person() 做了四件事：① 创建空对象；② 把空对象的 __proto__ 指向 Person.prototype；③ 把 Person 里的 this 绑到这个新对象上执行；④ 如果没返回对象，就返回这个新对象。

2.4闭包

闭包 = 函数 + 它能访问的外部函数变量。内部函数引用了外部函数的变量，外部函数执行完了，这个变量也不会被销毁。

function counter() {
  let count = 0;            // 外部变量
  return function () {      // 内部函数，闭包
    count++;
    console.log(count);
  };
}
const c = counter();
c(); // 1
c(); // 2   ← count 一直活着，没被回收

闭包的用途与坑

  • 用途：数据私有化（上面的 count 外部改不了）、函数柯里化、回调保存状态。
  • 经典面试题：for 循环里用 var + setTimeout，输出全是同一个值。解决：改用 let（块级作用域）或立即执行函数。
  • 坑：闭包持有大对象不释放，会造成内存泄漏。不用了手动置 null。

2.5this 指向

this 不看函数在哪定义，看函数怎么调用。四条规则按优先级：

调用方式this 指向示例
new 调用新创建的对象new Foo()
call/apply/bind显式指定的第一个参数foo.call(obj)
对象方法调用点前面那个对象obj.foo() → this 是 obj
普通调用严格模式 undefined，否则 windowfoo()
💡 箭头函数没有自己的 this，它的 this 定义时就固定了，继承外层作用域的 this。所以箭头函数当回调不会丢 this，但不能当构造函数。

2.6事件循环 Event Loop

JS 是单线程的，异步任务靠事件循环调度。任务分两种：

  • 宏任务：script 整体、setTimeout、setInterval、I/O、UI 渲染。
  • 微任务：Promise.then/catch/finally、queueMicrotask、MutationObserver。
图 2.6-1　一轮 Event Loop：同步 → 清空微任务 → 一个宏任务 → 再清微任务 → …
console.log(1);
setTimeout(() => console.log(2), 0);   // 宏任务
Promise.resolve().then(() => console.log(3)); // 微任务
console.log(4);
// 输出顺序：1 → 4 → 3 → 2
💡 口诀：先同步后异步；异步里微任务永远先于宏任务。每执行完一个宏任务，都要把微任务队列清空，再取一个宏任务。

2.7Promise 与 async/await

Promise 有三个状态：pending → fulfilled / rejected，状态一旦改变就不可逆。

静态方法等谁结果
Promise.all全部成功一个失败就整体失败
Promise.allSettled全部结束不管成败，都拿到结果
Promise.race谁先结束返回最快那个的结果
Promise.any任一成功都失败才算失败

async/await 是 Promise 的语法糖：await 暂停后面的代码，等 Promise resolve 再继续，错误用 try/catch 捕获。

2.8浏览器渲染流程

从拿到 HTML 到屏幕上出现像素，流水线如下：

  • 重排（Layout）：改了宽高、位置、字体，浏览器要重新算几何位置。代价大。
  • 重绘（Paint）：只改颜色、背景，位置没变。比重排便宜。
  • 合成：transform、opacity 这种交给 GPU，不触发重排重绘，最顺滑。
⚠️ 性能优化口诀：改样式尽量用 transform/opacity（合成层），避免频繁改 width/top/margin（重排）。

2.9Vue3 响应式原理

Vue2 用 Object.defineProperty 劫持对象的每个属性；Vue3 改用 Proxy 代理整个对象。

💡 核心三步走：① 渲染组件时读数据，把「谁用了这个数据」记下来（依赖收集）；② 数据被改，Proxy 的 set 拦截；③ 通知所有依赖它的组件重新渲染。这就是"响应式"。

2.10React Hooks 本质

Hooks（useState、useEffect…）靠链表按顺序存在函数组件对应的 Fiber 节点上。所以 Hooks 不能写在 if/循环里——顺序一变，React 就对不上号了。

Hook作用注意
useState函数组件里的状态setState 是异步批量更新
useEffect副作用（请求、订阅、DOM）依赖数组决定何时执行；return 是清理函数
useRef保存跨渲染的值 / DOM 引用改 .current 不触发渲染
useMemo缓存计算结果依赖不变就复用
useCallback缓存函数引用配合子组件 memo 使用
useContext跨层级共享数据避免 props 一层层透传

2.11跨域与缓存

跨域 CORS

浏览器同源策略要求：协议+域名+端口三者完全一致。不一致就是跨域，浏览器会拦截响应。

  • 简单请求：直接发，服务端回 Access-Control-Allow-Origin 浏览器就放行。
  • 非简单请求（如 PUT、自定义头）：先发 OPTIONS 预检请求，服务器同意了才发真实请求。

浏览器缓存

类型字段是否问服务器
强缓存Cache-Control / Expires不问，直接用本地
协商缓存ETag / If-None-Match；Last-Modified问服务器，没变就返 304
💡 优先级：强缓存 > 协商缓存。先看强缓存命中没，命中直接用；没命中再问服务器协商缓存。
