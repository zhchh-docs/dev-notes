7.1XSS 跨站脚本

攻击者把恶意脚本注入到网页里，浏览器执行后偷用户数据。三种类型：

类型原理例子
存储型恶意脚本存到数据库，所有访问者都中招评论区发 <script>偷cookie</script>
反射型脚本在 URL 参数里，服务器"反射"给当前用户钓鱼链接 ?q=<script>...</script>
DOM 型纯前端 JS 把不可信内容写进页面，不经过服务器location.hash 直接 innerHTML
💡 防御三板斧：① 输出到 HTML 时转义（< → &lt;）；② 富文本用白名单过滤；③ 加 CSP 响应头禁止执行未授权脚本。

7.2CSRF 跨站请求伪造

你登录了银行网站，再访问一个恶意网站，恶意网站偷偷用你的身份发请求转钱。浏览器会自动带上你的 Cookie。

💡 防御：① 关键操作要 CSRF Token（页面里带个随机串，恶意网站猜不到）；② Cookie 设 SameSite=Lax 禁止跨站带；③ 敏感操作二次确认。

7.3SQL 注入

用户输入拼接进 SQL，篡改了原本逻辑。比如登录：

// 危险写法：直接拼接
sql = "SELECT * FROM users WHERE name='" + name + "' AND pass='" + pass + "'"

// 用户输入：' OR '1'='1
// 结果变成：SELECT * FROM users WHERE name='' OR '1'='1' AND ...
// 永远为真，不用密码就能登录
💡 防御：永远不要拼接 SQL，用预编译语句（参数化查询），ORM 框架默认就是安全的。输入校验只是辅助，不能代替预编译。

7.4越权与 CSP

攻击说明防御
水平越权用户 A 改了 URL 里的 id，看到了用户 B 的数据每次查数据都校验"这条数据属于当前登录用户吗"
垂直越权普通用户访问了管理员接口接口加权限校验（RBAC）

CSP 内容安全策略：响应头里声明"页面只能加载哪些来源的脚本"，浏览器会拦截不在白名单的脚本，是 XSS 的第二道防线。

7.5密码安全

🚨 绝对不能明文存密码，也不能自己写 MD5（彩虹表一撞就出来）。正确做法：bcrypt——自带随机盐、计算慢，就算数据库泄露攻击者也破解不动。

8.3分布式 ID（雪花算法）

分库分表后，自增 ID 会冲突。雪花算法用 64 位数字生成全局唯一 ID：

0 | 41位时间戳 | 10位机器ID | 12位序列号
  • 时间戳：能算出自增趋势。
  • 机器 ID：不同机器不冲突。
  • 序列号：同一毫秒内多个 ID 递增。

8.4限流降级熔断

手段什么时候用干什么
限流防打挂自己超过 QPS 就拒绝请求
降级非核心功能拖累主流程推荐接口关了，下单还能用
熔断下游服务持续超时直接短路，不再调，等一会再试
💡 思路：系统要能在压力下"优雅地少做事"，而不是直接崩掉。保核心链路，牺牲边缘功能。

8.5容量预估

上线前先算一笔账，别等挂了再扩容：

  • QPS 估算：日活 × 人均请求数 / 86400 = 平均 QPS，峰值按 3~5 倍。
  • 单机承载：压测一台机器能扛多少 QPS，再除一下要几台。
  • 数据库：慢查询别拖，连接池大小合理。
  • 内存/磁盘/带宽：按峰值留 2 倍余量。
