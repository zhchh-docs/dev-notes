1.1网络分层模型

网络分层的目的是分工：每层只管自己的事，上层不用关心下层怎么实现。互联网实际用的是 TCP/IP 四层模型，OSI 七层是理论参考。

图 1.1-1　OSI 七层是理论，TCP/IP 四层是互联网实际运行的模型

记忆要点：我们写的 HTTP 请求在应用层，TCP 把它切成段并保证可靠传输（传输层），IP 负责把包从北京送到上海（网际层），剩下的交给网卡和网线（网络接口层）。

1.2TCP 三次握手

TCP 是面向连接的：发数据前必须先确认双方都能收发。三次握手就是建立连接的过程。

核心要点

  • SYN 是同步序列编号，ACK 是确认号。每次握手双方都交换了各自的初始序列号（seq）。
  • 第二次握手时服务端把 x+1 作为确认号，表示"我收到了你发的 x"。
  • 为什么三次：客户端要确认自己的发包能力和收包能力都正常，服务端也要确认自己的收发包能力正常。两次只能确认单向，三次才能双向确认。
⚠️ 面试高频：为什么不是两次？答：如果客户端发的 SYN 因为网络阻塞迟迟到达，客户端又重发了一次。服务端收到第一个迟到的 SYN 后，如果是两次握手就直接建立连接，但客户端根本没在等这个连接，服务端就白白等下去浪费资源。三次握手让客户端有机会在第三次 RST 掉这个无效连接。

TCP 怎么保证数据不丢、不乱、不重复？靠下面这几板斧：

机制作用一句话原理

1.5HTTP 与 HTTPS

HTTP 报文长什么样

POST /api/login HTTP/1.1          ← 请求行：方法 路径 协议
Host: example.com                  ← 请求头开始
Content-Type: application/json
Authorization: Bearer xxx
                                   ← 空行（头和体的分界）
{"user":"tom","pass":"***"}        ← 请求体

响应同理：状态行 HTTP/1.1 200 OK → 响应头 → 空行 → 响应体。

HTTPS = HTTP + TLS

HTTP 是明文传输，会被窃听和篡改。HTTPS 用 TLS 加密，核心是混合加密：非对称加密交换密钥，对称加密传数据。

💡 数字证书就是 CA 给服务端公钥做的"身份证"，客户端验证证书是合法 CA 签的，才敢用这个公钥加密。这就防了中间人冒充。

1.7进程与线程

进程线程
定位资源分配单位CPU 调度单位
拥有独立内存空间、文件句柄共享进程的内存，自己只有栈和寄存器
创建开销大（要独立地址空间）小（共享空间，只需建栈）
通信要 IPC（管道/共享内存/Socket）直接读写共享变量，但要加锁
崩溃影响一个进程挂了不影响别的一个线程挂了整个进程都挂
💡 类比：进程是工厂，线程是工人。工厂之间独立，工人之间共享工厂的设备，但多工人同时操作同一台设备要排队（加锁）。

1.8IO 模型与 epoll

后端高并发的秘密就在这。Node、Nginx、Redis 都是靠 IO 多路复用 用一个线程处理几万连接。

模型原理特点
阻塞 IO线程一直等数据到了才返回简单，但一个连接占一个线程，并发上不去
非阻塞 IO没数据立刻返回，线程不停问占 CPU
IO 多路复用select/poll/epoll 一个线程盯着一堆连接，哪个有数据就处理哪个高并发关键
异步 IO内核全程帮你干好，完成后通知你Linux 支持不完善

select / poll / epoll 对比

selectpollepoll
fd 数量1024 上限无上限无上限
效率每次全量遍历 O(n)每次全量遍历 O(n)事件通知 O(1)，只返回活跃 fd
内存拷贝每次拷贝整个 fd 数组每次拷贝fd 注册一次，放内核红黑树
💡 epoll 为什么快：select/poll 每次都要把几万个 fd 从用户态拷到内核态，再全部遍历一遍。epoll 只在注册时放一次，之后内核用事件通知"哪个 fd 就绪了"，应用直接处理活跃连接，O(1) 级别。

其他连接不占 CPU

1.9B+ 树索引（MySQL 为什么快）

MySQL InnoDB 的索引用 B+ 树。为什么不用二叉树、哈希？看图：

B+ 树为什么适合做数据库索引

  • 矮胖：每个节点是一页（16KB），能放几百个键，3~4 层就能存千万级数据，查一条记录只读 3~4 个磁盘页 → 3~4 次 IO。二叉树要几十次。
  • 只有叶子存数据：非叶子节点能放更多键，树更矮。
  • 叶子节点用双向链表相连：范围查询（where age > 18）找到起点后顺着链表扫就行，不用回中间层。
⚠️ 回表：二级索引叶子节点存的是主键值，还要拿主键再去聚簇索引查一次整行。如果查询的字段正好都在索引里（覆盖索引），就不用回表。

1.10字符编码 UTF-8

Unicode 是字符集（给每个字符一个唯一编号，叫码点），UTF-8 是编码方式（把码点变成字节存起来）。

字符Unicode 码点UTF-8 编码（字节）
AU+00410100 0001（1 字节）
汉U+6C4911100110 10110001 10001001（3 字节）
你U+4F6011100100 10111101 10100000（3 字节）

UTF-8 是变长编码：英文字母占 1 字节，中文占 3 字节。这种设计对英文兼容 ASCII，又能表示所有 Unicode 字符，所以成了互联网默认编码。

🚨 乱码怎么来的：文件是 UTF-8 存的，却用 GBK 打开，或者反过来——编码和解码用了不同的字符集，字节序列被错误解释，就成了乱码。解决：全链路统一 UTF-8。
