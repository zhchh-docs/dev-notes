JsPlumb 连线库

深入 定位：G6 分工协同 / beforeDrop 规则闸门 / 序列化还原

JsPlumb 只做一件事：在现成 DOM 元素（可以是带表单的 Vue 组件）之间拉线——Endpoint 锚定端口、Connector 自动跟随、Overlay 表达语义。本篇讲透与 G6 的双层分工（统一建边入口/同一坐标系）、beforeDrop 规则闸门、事件同步业务模型的单一数据源原则、序列化还原闭环与 Vue 成对生命周期，配双节点流程编辑器 Demo 与五个高频坑。

1简介与阅读指引

1.1 定位

JsPlumb 是一个 DOM 连线库——在现成 DOM 元素之间拉一条线。三要素：Endpoint（锚定在 DOM 边缘的端点）、Connector（两端的连线，随端点移动自动重算路径）、Overlay（箭头/标签等覆盖物）。它不管画布、不管布局、不管图模型——节点是你的 DOM（可以是带表单交互的 Vue 组件），它只负责连线这一件事。

1.2 痛点与适用：为什么不用图引擎硬扛

流程编辑器的节点是带输入框/下拉/按钮的 Vue 组件——搬进 G6 画布意味着把表单交互重写在图形对象里，成本极高。JsPlumb 的价值正在这里：节点保持 DOM 形态，只补连线层。选型判断见 1.3。

1.3 选型：JsPlumb vs G6

维度JsPlumbG6
定位DOM 连线层，无图模型完整图可视化引擎
节点已有 DOM/Vue 组件引擎画布内的图形对象
布局不管，节点位置由你定内置 dagre/force 等布局
取舍节点是现成 DOM、只需连线时叠加需要独立画布与图模型时主用

判断口诀：节点是"活的 DOM 组件"（带表单交互）→ JsPlumb 叠加连线层；需要自动布局/缩放平移/大规模图渲染 → G6 主导画布。两者可以协同（G6 管画布层 + JsPlumb 管端口连线层），但铁律是：连线入口必须统一，绝不让两套引擎同时建边（坑 1）。

1.4 学习目标与阅读指引

  1. 用 addEndpoint + connect 完成端点锚定与连线，理解 uuid 寻址；
  2. 用 beforeDrop 拦截非法连接，用 connection/connectionDetached 事件同步业务模型；
  3. 完成序列化/还原闭环（连线数据存库、重建端点后还原）；
  4. 掌握与 Vue 集成的生命周期纪律（挂载 init / 卸载 remove）与四个高频坑。

前置知识：Vue 组件生命周期；有流程编辑器/画布类业务背景更好。难度：★★★☆☆（API 简单，与框架/画布协同的细节是难点）。务必动手：第 6 章 Demo。

2核心模型

四个核心模型按依赖顺序：Endpoint（锚点）→ Connector 与 Overlay（视觉层）→ 拖拽建连与校验（交互层）→ 序列化（数据层）。

2.1 Endpoint：连线的锚点

端点分两种角色：source（可拖出连线）与 target（可接收连线）；一个节点可有多个端点（多输入/多输出端口）。uuid 是端点的稳定地址——给每个端点命名（uuid: 'nodeA-out'），之后建连线、序列化、还原全部用 uuid 寻址，不依赖 DOM 引用。anchor 定义端点贴在节点边缘的位置（Left/Right/Top/Bottom 或百分比坐标）。

2.2 Connector 与 Overlay：视觉层

Connector 是连线的路径类型：Straight（直线）/ Bezier（贝塞尔，最常用）/ Flowchart（直角流程线）/ StateMachine（状态机弧线）。连线随端点/节点移动自动重算路径——这是"连线层"的本质：你只管摆节点，线自己跟。Overlay 是线上的附加元素：Arrow 箭头表达方向、Label 标签表达语义（如"成功分支"）。

2.3 拖拽建连与校验：beforeDrop 是规则闸门

用户从 source 端点拖出临时线，释放到 target 端点时触发 beforeDrop——返回 false 直接拒绝，不产生连线。所有业务规则（不能自连、类型匹配、不允许环）都在这里拦截。建连成功后触发 connection 事件、断开触发 connectionDetached——这两个事件是"视觉层 → 业务模型"的同步点：画布上有什么线，由事件驱动你的数据模型（edges 数组），而不是反过来让引擎自说自话。

2.4 序列化：连线是数据，不是视觉痕迹

instance.getAllConnections() 导出全部连线，取每条的 source/target 端点 uuid 存库；还原时重建端点后逐条 connect({ uuids })。心智模型：连线数据（edges）是你的业务资产，JsPlumb 实例只是它的临时渲染器——刷新、切页、重建都从数据恢复，不依赖实例的存活。

3核心用法（按场景）

3.1 场景一：初始化端点与静态连线

import jsPlumb from 'jsplumb';
const instance = jsPlumb.getInstance({
  Connector: 'Bezier',
  Endpoint: 'Dot',
  PaintStyle: { stroke: '#9cae90' },
  HoverPaintStyle: { stroke: '#3d7a4f' }
});
// 在节点上锚定源/目标端点
instance.addEndpoint('nodeA', { anchor: 'Right', uuid: 'a-out', isSource: true });
instance.addEndpoint('nodeB', { anchor: 'Left', uuid: 'b-in', isTarget: true });
instance.connect({ uuids: ['a-out', 'b-in'] });   // 建立连线

3.2 场景二：拖拽建连 + 规则校验

// 初始结构固定 → 静态 connect；用户交互建连 → beforeDrop 校验后建
instance.bind('beforeDrop', (info) => {
  const ok = validLink(info.sourceId, info.targetId);   // 不能自连/类型匹配/无环
  if (!ok) toast.error('非法连接');
  return ok;          // false 则拒绝，不产生连线
});

3.3 场景三：事件同步业务模型

instance.bind('connection', (c) => {
  flowModel.addEdge(c.sourceId, c.targetId);      // 建 → 模型加边
});
instance.bind('connectionDetached', (c) => {
  flowModel.removeEdge(c.sourceId, c.targetId);   // 断 → 模型删边
});

单一数据源原则：业务模型是唯一事实，JsPlumb 只是投影——刷新/撤销/重做都从模型重建连线，永不"直接改画布"。

3.4 场景四：序列化存库与还原

const links = instance.getAllConnections().map(c => ({
  from: c.sourceId, to: c.targetId
}));
await api.save({ links });
// 还原（页面重开/切换流程）：重建所有节点端点后
links.forEach(l => instance.connect({ uuids: [l.from, l.to] }));

4进阶知识点【进阶】

首次学习可整章跳过。前置：拖拽建连与序列化已跑通。

4.1 与 G6 的协同架构：双层分工

复杂画布的标准分层：G6 管画布层（平移缩放、小地图、节点布局），JsPlumb 管端口连线层（DOM 端点锚定、拖拽建连）。两条纪律：①统一建边入口——所有"加边"动作走同一个函数（内部决定谁渲染），杜绝 G6 create-edge 与 JsPlumb 拖拽同时触发建两条线；②同一坐标系——容器缩放（transform: scale）必须两者同步，否则连线与节点错位（坑 4）。

4.2 Vue 集成的生命周期契约

节点是 Vue 组件时的成对纪律：mounted 里 addEndpoint、unmounted 里 jsPlumb.remove(element)。Vue 的组件复用（keep-alive/v-for 复用 DOM）会让旧端点残留——新组件以为自己是全新节点，端点却还挂着旧的连线。remove 是唯一正确的清理方式（它会连端点带相关连线一起清），detach 单条连线不够。

4.3 连线跟随：revalidate 的时机

节点位置变化（拖动、展开表单高度变化）后连线不跟随——调 instance.revalidate(el) 重算。工程化做法：用 ResizeObserver 监听节点尺寸变化自动 revalidate，而不是散落在业务代码里手动调。拖拽节点场景优先用 JsPlumb 自带的 draggable（内置跟随），混合 G6 拖拽时由 G6 的拖拽回调里统一 revalidate。

4.4 连线规则引擎：把 validLink 做成可配置

流程编辑器的连接规则会持续膨胀（类型匹配、端口容量、无环检测、跨分支限制）。把它做成规则数组：rules = [noSelf, typeMatch, capacity, noCycle]，beforeDrop 里逐条跑、失败收集原因给用户提示——比一坨 if-else 可维护得多。无环检测复用图的 DFS（模型层做，不在渲染层）。

6最小可运行 Demo

一个双节点流程编辑器：两个 Vue 节点（各带输入/输出端口）、拖拽建连 + 校验 + 序列化。

6.1 节点组件（生命周期契约）

// FlowNode.vue
props: ['id']
mounted() {
  // 挂载：锚定输出/输入端点（uuid = 节点id + 端口名，全局唯一）
  this.$plumb.addEndpoint(this.$el, {
    anchor: 'Right', uuid: this.id + '-out', isSource: true,
    maxConnections: 5,
  })
  this.$plumb.addEndpoint(this.$el, {
    anchor: 'Left', uuid: this.id + '-in', isTarget: true,
  })
},
beforeUnmount() {
  // ⭐ 卸载成对清理——组件复用场景不清理必留残留
  this.$plumb.remove(this.$el)
}

6.2 画布容器（校验 + 事件同步 + 序列化）

const instance = jsPlumb.getInstance({
  Connector: 'Bezier', Endpoint: 'Dot',
  PaintStyle: { stroke: '#9cae90' }, HoverPaintStyle: { stroke: '#3d7a4f' },
})

// 规则闸门
instance.bind('beforeDrop', (info) => {
  if (info.sourceId === info.targetId) { toast.error('不能自连'); return false }
  if (!validFlow(info.sourceId, info.targetId)) { toast.error('类型不匹配'); return false }
  return true
})
// 事件 → 模型（单一数据源）
instance.bind('connection', c => flowModel.addEdge(c.sourceId, c.targetId))
instance.bind('connectionDetached', c => flowModel.removeEdge(c.sourceId, c.targetId))

// 保存/还原
function save() {
  return instance.getAllConnections().map(c => ({ from: c.sourceId, to: c.targetId }))
}
function restore(links) {
  links.forEach(l => instance.connect({ uuids: [l.from, l.to] }))
}

6.3 逐段解析

  • uuid 命名约定（节点id-端口名）：序列化与还原全靠它寻址，节点增删不改其他连线；
  • beforeDrop 三规则：自连/类型/无环——校验前置，非法连接零视觉痕迹；
  • 事件同步模型：flowModel 是唯一事实，撤销重做、刷新还原都从模型重建；
  • 成对生命周期：mounted addEndpoint / beforeUnmount remove——Vue 复用场景的保命符。

6.4 生产改造扩展方向

  1. 规则引擎化：validFlow 拆成规则数组逐条校验并返回具体原因（4.4）；
  2. 接入 G6 画布层：统一建边入口 + 同步坐标系（4.1）；
  3. 连线 Label 绑业务语义（条件分支的"是/否"），随模型字段联动更新。

7常见坑 & Debug

五条高频坑，每条五要素。

7.1 坑 1：G6 与 JsPlumb 重复建边

  • 现象：一次拖拽出现两条连线（一条来自 G6 create-edge、一条来自 JsPlumb）；
  • 根因：双引擎都监听了拖拽释放事件，各自建边；
  • 复现：G6 画布模式下直接绑定 JsPlumb 拖拽；
  • 修复：统一建边入口——加边只走一个函数，内部决定渲染归属；另一引擎只读不写；
  • 规避：混合架构设计评审时先画"谁建边"的分工图（图 1）。

7.2 坑 2：Vue 组件卸载不清理端点

  • 现象：v-for 复用/切换流程后，节点上残留旧端点、连线指向错误节点；
  • 根因：端点是 JsPlumb 侧的状态，Vue 卸载 DOM 不会自动同步给 JsPlumb；
  • 修复：卸载钩子里 instance.remove(el)（端点+相关连线一起清）；
  • 规避：成对生命周期写进节点组件基类/组合函数（6.1）。

7.3 坑 3：节点移动后连线不跟随

  • 现象：拖动节点后连线停在原地"断线"；
  • 根因：连线路径由端点位置计算，位置变了不通知就不重算；
  • 修复：位置变化后调 instance.revalidate(el)；用 ResizeObserver/拖拽回调统一触发（4.3）；
  • 规避：节点拖拽优先用 JsPlumb 自带 draggable（内置跟随）。

7.4 坑 4：容器缩放导致坐标错位

  • 现象：画布缩放（scale 0.8）后连线端点与节点端口对不上；
  • 根因：JsPlumb 按未缩放坐标计算，容器的 CSS transform 没同步给它；
  • 修复：与画布引擎保持同一坐标系——缩放同步设置给 JsPlumb（zoom/setZoom），锚点计算才能对齐；
  • 规避：混合架构里"缩放权"只给一个引擎，另一个跟随。

7.5 坑 5：没有 beforeDrop 校验，非法连线入库

  • 现象：用户把输出连到自己的输入、把不兼容端口连起来，保存后流程执行报错；
  • 根因：只靠 UI 端口位置暗示规则，没有硬校验；
  • 修复：beforeDrop 拦截（规则引擎化，4.4），后端保存接口再校验一次；
  • 规避：连线规则前后端同一份定义——前端拦体验、后端拦底线。

8重点讲解

Q1：JsPlumb 和 G6 怎么选？两者如何协同？

参考答案：判断节点形态——节点是现成 DOM/Vue 组件（带表单交互），只需要在端口间连线 → JsPlumb 叠加连线层；需要独立画布（自动布局、平移缩放、大规模图）→ G6 主导。协同架构：G6 管画布层（布局/缩放/小地图），JsPlumb 管端口连线层（DOM 端点锚定、拖拽建连）。两条铁律：①统一建边入口——所有加边动作走一个函数，杜绝双引擎各建一条；②同一坐标系——缩放必须同步，否则连线错位。

Q2：连线的"数据-视觉"关系怎么设计？

参考答案：连线数据（edges）是业务资产，JsPlumb 实例只是临时渲染器。设计三原则：①事件同步——connection/connectionDetached 是视觉→模型的唯一同步点；②单一数据源——刷新/撤销/切换流程都从模型重建连线（重建端点 + connect(uuids)），不依赖实例存活；③uuid 寻址——端点用稳定的 uuid（节点id-端口名），序列化与还原不依赖 DOM 引用。

本质：与所有可视化库一样——"谁拥有数据，谁就是事实；渲染器可以随时重建"。

Q3：拖拽建连的校验应该放在哪？怎么做？

参考答案：beforeDrop 是前端闸门——释放到 target 时触发，返回 false 直接拒绝（零视觉痕迹）。规则建议引擎化：规则数组（不自连/类型匹配/端口容量/无环检测）逐条跑、失败给出具体原因提示。无环检测在模型层用图的 DFS 做。

分层：前端校验拦体验（即时反馈），后端保存接口必须再校验一次——连线规则前后端同一份定义，前端拦体验、后端拦底线（与文件上传的校验分层同理）。
