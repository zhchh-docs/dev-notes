◆本章目标

  • 能在 Docker / Linux / Windows 任一环境跑起一个 Redis 7.x 实例；
  • 会用 redis-cli 做连接、切库、测延迟、批量导入、在线改写配置等日常操作；
  • 能读懂一份 redis.conf 的关键 12 项，知道哪些必须改、哪些默认就够；
  • 掌握 CONFIG GET/SET/REWRITE 与 INFO 这一对"体检+调参数"的组合拳；
  • 踩坑时能按标准排查清单定位：连不上、密码错、保护模式、端口占用、数据消失。
前置要求：第 1 章。需要一台能跑命令行的机器（Windows 建议装 WSL2 或直接用 Docker）。

2.1 版本与四种安装方式怎么选

版本选择一句话：学习用最新版，生产只用稳定版（7.0/7.2/7.4），绝不碰 Windows 老旧二进制。

方式适合场景优点缺点
Docker本机学习、Mac/Windows一条命令搞定，秒起秒删，多实例方便数据要挂卷持久化，网络概念多一层
Linux 包管理虚拟机、开发机有 systemd 托管，接近生产形态仓库版本可能偏旧（需换官方源）
源码编译生产、云主机版本可控、可定制（如指定 jemalloc）要装 gcc/make，耗时几分钟
Windows 原生不推荐不用装虚拟机微软维护的分支停在 3.x/5.x 很久，特性缺失；用 WSL2/Docker 更好

本书所有命令以 Redis 7.x 为准；若你是 6.x，绝大多数命令完全一致，差异处会标注。

2.2 Docker 起手式（推荐）

# ① 最简：临时跑一个，容器删除即失效（仅练手）
docker run --name redis7 -p 6379:6379 -d redis:7.2 redis-server --appendonly yes

# ② 正式一点：数据挂到宿主机，避免容器删了数据也没了
mkdir -p ~/redis-lab/{conf,data}
docker run --name redis7 \
  -p 6379:6379 \
  -v ~/redis-lab/data:/data \
  -v ~/redis-lab/conf/redis.conf:/usr/local/etc/redis/redis.conf \
  -d redis:7.2 redis-server /usr/local/etc/redis/redis.conf

# ③ 进容器执行 cli（最常用）
docker exec -it redis7 redis-cli
127.0.0.1:6379> PING
PONG
127.0.0.1:6379> SET hello world EX 60
OK
127.0.0.1:6379> GET hello
"world"
127.0.0.1:6379> TTL hello
(integer) 57

想同时起三个实例做主从实验（第 43 章），直接用 compose：

# docker-compose.yml
services:
  redis-master:
    image: redis:7.2
    ports: ["6379:6379"]
    command: redis-server --appendonly yes
  redis-replica:
    image: redis:7.2
    ports: ["6380:6379"]
    command: redis-server --appendonly yes --replicaof redis-master 6379
docker compose up -d
docker compose logs -f redis-replica   # 看同步日志
提示：Docker 部署务必理解两件事——数据必须在卷里（/data 挂载），端口映射不能漏（-p 6379:6379），否则"连不上"和"重启后数据没了"这两个问题必然会依次找上你。

2.3 Linux 直接安装与 systemd 托管

# Ubuntu / Debian（官方源，版本较新）
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/redis.list
sudo apt update && sudo apt install -y redis-server

# CentOS / Rocky
sudo yum install -y epel-release && sudo yum install -y redis

# 源码编译（想要指定版本时）
wget https://download.redis.io/releases/redis-7.2.4.tar.gz
tar xzf redis-7.2.4.tar.gz && cd redis-7.2.4
make MALLOC=jemalloc -j$(nproc) && sudo make install

托管与日常运维：

sudo systemctl enable --now redis-server     # 开机自启
sudo systemctl status  redis-server
sudo systemctl restart redis-server
redis-cli SHUTDOWN NOSAVE                    # 优雅关机（NOSAVE 表示不触发 RDB）
redis-server /etc/redis/redis.conf &         # 前台/后台指定配置启动

# 多实例（同一台机跑两个 Redis，后续主从实验用）
redis-server --port 6380 --dir /var/lib/redis-6380 --daemonize yes
redis-cli -p 6380 PING

记住 --port / --dir / --daemonize / 配置文件路径 这四个启动参数：书上后面所有"同机起多个实例"的实验都靠它们。

2.4 redis-cli：不止是一条命令终端

大多数人只会 redis-cli 进去敲命令，但它更像一把瑞士军刀：

# 连接相关
redis-cli -h 127.0.0.1 -p 6379 -a password      # 带密码（-a 会被 ps 看到，建议用环境变量）
redis-cli -n 1                                  # 直接进 1 号库（逻辑分库，共 16 个）
redis-cli --raw                                 # 中文不转义（ "\xe4\xb8\xad" -> 中 ）
redis-cli -u redis://:pwd@host:6379/0           # URL 形式
redis-cli --tls --cacert ./ca.crt               # TLS 连接

# 非交互：直接拿结果，写脚本非常好用
redis-cli SET counter 0
redis-cli INCR counter                          # -> 1
redis-cli GET counter | xargs echo "counter is"

# 探测与诊断（运维高频）
redis-cli PING                    # PONG = 活着
redis-cli INFO server | head -20  # 版本、运行天數、进程号
redis-cli INFO stats | grep -E "keyspace_(hits|misses)"   # 命中率数据源（第 31 章）
redis-cli DBSIZE                  # 当前库 key 数量（O(1)，可随便用）
redis-cli --latency               # 实时延迟采样，找网络/阻塞问题
redis-cli --latency-history       # 每 15 秒一段的延迟历史
redis-cli --bigkeys               # 扫描大 key（第 17 章）
redis-cli --hotkeys               # 热 key（需 LFU 淘汰策略，第 18 章）
redis-cli --scan --pattern "user:*" --count 1000   # CLI 层分批扫描
redis-cli --stat                  # 每秒刷新一行的实时监控
redis-cli MONITOR                 # 打印所有命令（警告：生产勿用，吞吐会掉一半以上）

# 批量写入与清理
redis-cli SET big "$(cat huge.json)"         # 用 shell 变量塞进去
cat orders.txt | redis-cli --pipe            # 百万级写入用 pipeline 协议
redis-cli FLUSHDB                            # 清空当前库
redis-cli FLUSHALL ASYNC                     # 全库清（ASYNC 避免阻塞，7.x 默认异步选项）

交互模式下的小技巧

127.0.0.1:6379> TAB 补全            # 敲 SE + TAB 自动补全 SET
127.0.0.1:6379> HELP @string        # 查看 String 组全部命令
127.0.0.1:6379> SELECT 2            # 切库 0-15
127.0.0.1:6379> CLIENT LIST         # 看连接
127.0.0.1:6379> COMMAND COUNT       # 命令总数
127.0.0.1:6379> COMMAND INFO GET SET DEL    # 单命令的复杂度/标志
127.0.0.1:6379> CONFIG GET maxmemory
1) "maxmemory"
2) "0"
注意：Redis 的 16 个逻辑库（db0-db15）跟 MySQL 的 database 不是一回事。它只是个 key 前缀隔离，不支持权限隔离、不支持集群模式（Cluster 只有 db0）。正规做法是多个业务共享一个库、靠 key 前缀区分，见到用 SELECT 切换不同业务的架构要警惕。

2.5 redis.conf 与 CONFIG 命令

一份精简但能上手的 redis.conf，标注了每项的作用：

# ===== 网络 =====
bind 127.0.0.1 -::1        # 只监听本机；要外部访问改成 0.0.0.0 并务必配防火墙+密码
port 6379
protected-mode yes         # 无 bind、无密码时禁止外部连接，默认别关
tcp-keepalive 300
timeout 0                  # 0=不断开空闲连接（推荐长连接）

# ===== 安全 =====
requirepass Str0ng!Pass    # Redis 6+ 更推荐 ACL：ACL SETUSER appuser on >pwd ~cache:* +get +set
rename-command FLUSHALL "" # 把危险命令改名/禁用（第 53 章）

# ===== 内存 =====
maxmemory 4gb              # 必配！默认 0 表示不限制
maxmemory-policy allkeys-lru

# ===== 持久化 =====
appendonly yes             # 开启 AOF
appendfilename "appendonly.aof"
appendfsync everysec       # 折衷档
save 3600 1 300 100 60 10000
dir /var/lib/redis         # RDB/AOF 文件落盘目录，务必指定且可写
dbfilename dump.rdb

# ===== 日志 =====
logfile /var/log/redis/redis-server.log
loglevel notice

运行时改配置不用重启：

127.0.0.1:6379> CONFIG GET maxmemory*
1) "maxmemory"
2) "4294967296"
3) "maxmemory-policy"
4) "allkeys-lru"
127.0.0.1:6379> CONFIG SET maxmemory-policy volatile-lru
OK
127.0.0.1:6379> CONFIG REWRITE            # 把当前 SET 的值写回 redis.conf（注意权限）
127.0.0.1:6379> CONFIG SET appendonly yes # 在线开 AOF（触发一次全量刷盘）
警告：CONFIG SET 只在运行时生效，重启会丢。要么同步执行 CONFIG REWRITE，要么把改动同步到配置中心/Ansible/K8s ConfigMap——否则某天重启后你会发现"配置怎么退回去了"，这是运维最常见的背锅场景。

最后，INFO 是最全面的体检报告，常用小节：

小节能看到什么关键字段
server版本、模式、运行时长redis_version、uptime_in_days
clients连接数connected_clients、blocked_clients
memory内存与碎片used_memory_human、mem_fragmentation_ratio
persistenceRDB/AOF 状态rdb_last_bgsave_status、aof_last_bgrewrite_status
stats命中/未命中/淘汰keyspace_hits、keyspace_misses、evicted_keys
replication主从角色与偏移role、master_repl_offset、connected_slaves
commandstats命令调用次数与耗时cmdstat_get、cmdstat_hgetall

2.6 常见坑：环境问题排查清单

  1. 连不上（Connection refused）：先确认服务在运行（ps aux | grep redis 或 docker ps），再确认端口映射/防火墙/bind 地址。
  2. 远程连得上但 EXEC/读写被拒（DENIED Redis is running in protected mode）：因为你没配 bind 也没密码。三选一：绑定内网 IP、设 requirepass、或明确关闭 protected-mode（且必须配合防火墙）。
  3. NOAUTH Authentication required：设置了密码但客户端没带。-a pwd 或 AUTH pwd（注意 -a 会在 ps 里暴露，脚本里建议用环境变量）。
  4. 重启后数据没了：① 没开 AOF 且没触发过 RDB；② Docker 容器重建但没挂 volume；③ dir 目录不可写导致持久化失败（看 logfile）。
  5. MISCONF Redis is configured to save RDB snapshots but is currently not able to persist to disk：磁盘满、目录没权限或 bak 落地失败。此时写命令会被拒绝，属于自我保护，先清磁盘/修权限。
  6. 数据写入极慢：常见原因是每条命令一次 docker exec（RTT 叠加），或 AOF 设为 always，或客户端没用连接池。
  7. 本机 telnet 6379 能通但应用报超时：检查是否连错库（不存在的 db index 在某些客户端会报错）、是否用了集群协议连单机。
  8. 中文乱码：加 redis-cli --raw；程序里注意字符集统一 UTF-8。
排查口诀：先看存活（PING），再看网络（端口/防火墙），再看凭据（密码/ACL），最后看磁盘与配置（dir/logfile/maxmemory）。

✓ 本章小结

要点一句话
安装方式学习用 Docker；生产用官方源或源码编译；不用 Windows 原生版
Docker 三要素端口映射、数据卷挂载、配置文件挂载
redis-cli 高频-n/--raw/-a/--pipe/--scan/--bigkeys/--hotkeys/--latency/--stat
16 个逻辑库只是 key 前缀隔离，Cluster 下只有 db0，别用来隔离业务权限
必配项bind/requirepass/maxmemory/maxmemory-policy/appendonly/dir/logfile
CONFIG SET运行时生效，记得 REWRITE 或同步到配置管理
排查口诀存活 → 网络 → 凭据 → 磁盘与配置

✎ 本章习题

A 基础用 Docker 起一个 Redis 7.2 实例并挂载数据卷；写入 3 个带 TTL 的 key，删除容器后用 --raw 确认数据仍在。
B 进阶用 redis-cli --stat 观察 10 秒；然后用 INFO stats 取出 keyspace_hits 与 keyspace_misses，手工算出当前命中率（公式见第 31 章），并说出它为什么此刻不可信。
C 挑战不改配置文件的前提下，把当前实例的 maxmemory 设为 1GB、maxmemory-policy 设为 volatile-lru，并用 CONFIG REWRITE 落盘；随后查看 redis.conf，确认改动是否真的写进去了（如果没成功，说明原因）。
