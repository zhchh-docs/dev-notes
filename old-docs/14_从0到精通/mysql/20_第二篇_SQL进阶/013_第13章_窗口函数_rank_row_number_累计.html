13.1 准备实验表（可复现）

13.2 语法骨架：OVER 三件套

窗口函数 = 聚合/排名函数 + OVER()。OVER 里可以写三样东西：分区、排序、窗口范围。

SELECT
  product,
  amount,
  SUM(amount) OVER ()                                   AS total_all,  -- 全表总和
  SUM(amount) OVER (PARTITION BY category)              AS total_cat,  -- 本类目总和
  SUM(amount) OVER (PARTITION BY category ORDER BY sale_date) AS cum_cat -- 本类目累计
FROM sales_demo
ORDER BY category, sale_date;
和 GROUP BY 的核心区别：GROUP BY 把多行压成一行；窗口函数一行不少，只是在每行旁边挂上"它所在分区"的聚合结果。这就是它能出 TopN、累计、环比的根本原因。

13.3 row_number / rank / dense_rank

三种排名函数处理"并列"的方式不同——上一节故意插了两条 800.00 的并列，就是为了演示。

SELECT
  product,
  amount,
  ROW_NUMBER() OVER (ORDER BY amount DESC) AS rn,   -- 1,2,3,4,5... 不重复
  RANK()       OVER (ORDER BY amount DESC) AS rnk, -- 并列同名次，后续跳号：1,2,2,4
  DENSE_RANK() OVER (ORDER BY amount DESC) AS drnk  -- 并列同名次，不跳号：1,2,2,3
FROM sales_demo
WHERE category = '键盘'
ORDER BY amount DESC;
函数并列时的名次典型用途
ROW_NUMBER()硬排，绝不重复（并列也给不同号）分页去重、"每组只取第一条"（需先定好排序 tie-break）
RANK()并列同名次，下一名跳号（1,2,2,4）"并列第 2 名后，下一个就是第 4 名"的比赛榜
DENSE_RANK()并列同名次，不跳号（1,2,2,3）"金额档位"：第 3 名就是第 3 高的金额
为什么 ROW_NUMBER 翻页最稳：第 7 章分页的"排序键带唯一主键"原则，在窗口函数里同样适用——OVER (ORDER BY amount) 若并列，加 , id 兜底，名次才确定。

13.4 累计与滑动窗口

OVER 里再加 ROWS BETWEEN，就从"分区聚合"升级为"累计/滑动"计算。

-- ① 累计：从分区第一行累计到当前行（默认窗口 = ROWS UNBOUNDED PRECEDING）
SELECT
  sale_date, product, amount,
  SUM(amount) OVER (
    PARTITION BY category
    ORDER BY sale_date
  ) AS cum_amount
FROM sales_demo
WHERE category = '鼠标';

-- ② 滑动：当前行 + 前一行（相邻两笔的滚动和，常用于近 N 期均值）
SELECT
  sale_date, product, amount,
  AVG(amount) OVER (
    PARTITION BY category
    ORDER BY sale_date
    ROWS BETWEEN 1 PRECEDING AND CURRENT ROW
  ) AS avg_2rows
FROM sales_demo;
窗口框架写法含义
ROWS UNBOUNDED PRECEDING从分区第一行到当前行（累计）
ROWS BETWEEN 1 PRECEDING AND CURRENT ROW上一行 + 当前行（滚动 2 行）
ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING上一行 + 当前行 + 下一行（三行居中滑动）
RANGE BETWEEN ...（按值范围）按列值范围限定窗口，用于"同日期合并"等高级场景
不带 ORDER BY 的 OVER (PARTITION BY x) 窗口默认覆盖整个分区——这既是特性（分区总额）也是陷阱（忘了 ORDER BY 时"累计"变成"全区总和"，每行都一样）。写累计一定带 ORDER BY。

13.5 LAG / LEAD 环比

LAG 取上一行、LEAD 取下一行——环比、同比、"和上一笔比涨多少"的最简写法。

SELECT
  sale_date, product, amount,
  LAG(amount)       OVER (PARTITION BY product ORDER BY sale_date) AS prev_amount,   -- 上一日销售额
  amount - LAG(amount) OVER (PARTITION BY product ORDER BY sale_date) AS diff_vs_prev,
  LEAD(amount)      OVER (PARTITION BY product ORDER BY sale_date) AS next_amount    -- 下一日销售额
FROM sales_demo
WHERE product = '机械键盘A'
ORDER BY sale_date;
  • LAG(列)：取分区内按 ORDER BY 排好序后，当前行上一行的该列值；第一行没有上一行，返回 NULL；
  • LAG(列, 2)：往上数两行；LAG(列, 2, 0)：没有时给默认值 0（避免 NULL 参与计算）；
  • 环比增长率 (amount - LAG(amount)) / LAG(amount) 一行搞定，不用再自连接。

13.6 实战：组内 TopN

窗口函数最有名的应用：每个类目取累计销售额前 3 的商品。

-- 第一步：先按 (类目, 商品) 汇总
-- 第二步：在每个类目内按销售额排名
-- 第三步：外层筛 rank <= 3
SELECT category, product, total_amount, rn
FROM (
  SELECT
    category,
    product,
    SUM(amount) AS total_amount,
    ROW_NUMBER() OVER (
      PARTITION BY category
      ORDER BY SUM(amount) DESC, product ASC    -- 并列时按商品名定序
    ) AS rn
  FROM sales_demo
  GROUP BY category, product
) t
WHERE rn <= 3
ORDER BY category, rn;
SQL 执行顺序提醒：窗口函数在 WHERE/GROUP BY 之后、ORDER BY 之前计算——所以"用窗口结果筛行"必须包一层子查询/CTE（下一章），直接写 WHERE rn <= 3 放在同一层是报错的。这也是它和 HAVING 的区别。

✓ 本章小结

要点一句话
本质行不减少，每行挂上分区聚合结果
语法函数() OVER (PARTITION BY ... ORDER BY ... ROWS BETWEEN ...)
三种排名row_number 不并列、rank 跳号、dense_rank 不跳号
累计/滑动带 ORDER BY 才是累计；ROWS BETWEEN 定义窗口范围
LAG/LEAD取上一行/下一行，环比同比免自连接
组内 TopN内层排名外层筛 rn <= N
