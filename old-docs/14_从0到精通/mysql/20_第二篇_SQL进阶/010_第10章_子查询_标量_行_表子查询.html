第 10 章 子查询：标量/行/表子查询

教科书 第 10 章 / 共 72 章 · 预计 40 分钟

"查比平均价贵的商品""找下单最多的那个用户的所有订单"——这种"先算一个值、再拿它当条件"的需求，就是子查询的主场。按返回结果分，它有三种形态：标量子查询、行子查询、表子查询。

◆本章目标

  • 说出子查询的三种形态及各自返回的"形状"（一格 / 一行 / 一张表）；
  • 用标量子查询完成"和平均值比"这类条件，知道它在 SELECT 列表与 WHERE 中的写法；
  • 用 IN、ANY、ALL 配合表子查询表达集合比较；
  • 会用行构造器 (a, b) = (…, …) 简洁表达多列匹配；
  • 分清相关子查询与非相关子查询，知道派生表（FROM 里的子查询）的限制。

10.1 什么是子查询

括号里嵌套的 SELECT 就是子查询。按"返回形状"分类，决定了它能嵌在哪里、配什么运算符。

形态返回典型位置与搭配
标量子查询一格（一行一列）WHERE 比较右侧、SELECT 列表；配合 = > < 等
行子查询一行（可多列）配合行构造器 (a,b) = 子查询
表子查询一张表（多行多列）配合 IN / ANY / ALL / EXISTS；也可放 FROM 后当派生表

10.2 标量子查询

返回一格值，最常用——"比平均贵""高于最高"这类相对条件全靠它。

-- WHERE 里：查出比全站平均价贵的商品
SELECT id, name, price
FROM product
WHERE price > (SELECT AVG(price) FROM product WHERE is_deleted = 0);

-- SELECT 列表里：每个商品显示"比平均价高多少"
SELECT
  id,
  name,
  price,
  price - (SELECT AVG(price) FROM product) AS diff_to_avg
FROM product;

-- 多层嵌套：先算"3 号类目的平均价"，再和全站平均比
SELECT
  (SELECT AVG(price) FROM product WHERE category_id = 3) AS cat3_avg,
  (SELECT AVG(price) FROM product)                        AS all_avg;
必须保证只返回一格：标量子查询返回多行时直接报错（Subquery returns more than 1 row）——这是写的时候最常见的错误信息。用 LIMIT 1 或聚合函数把结果压成一格。

10.3 表子查询：IN / ANY / ALL

返回一列多行的表子查询，配合 IN（在集合里）、ANY/ALL（和集合中任一个/全部比）使用。

-- IN：查"有过已支付订单的用户"
SELECT id, name
FROM customer
WHERE id IN (
  SELECT customer_id
  FROM orders
  WHERE status = 'PAID'
);

-- NOT IN：反向（注意 NULL 陷阱，下一章细讲）
SELECT id, name FROM customer
WHERE id NOT IN (SELECT customer_id FROM orders);

-- ANY：比集合中"任意一个"大即可——等价于 > MIN(集合)
SELECT * FROM product
WHERE price > ANY (SELECT price FROM product WHERE category_id = 7);

-- ALL：比集合中"所有"都大——等价于 > MAX(集合)
SELECT * FROM product
WHERE price > ALL (SELECT price FROM product WHERE category_id = 7);
运算符等价语义读法
x IN (集合)x = 集合中某一个"在集合里"
x = ANY (子查询)等价 IN和任一相等
x > ALL (子查询)x > MAX(集合)比全都大
x < SOME (子查询)x < MAX(集合)（SOME = ANY 别名）比某个大就行
ANY/ALL 是 SQL 里最"反直觉"的运算符：> ALL 是比最大还大，> ANY 是比最小还大。工程实战中几乎没人用它（直接写成聚合子查询更清楚），读老代码认识即可。

10.4 行子查询（行构造器）

一次比较多列——(列1, 列2) = (值1, 值2)，这叫行构造器语法，MySQL 支持。

-- 场景：商品表 (category_id, price) 组合唯一，要找和"3 号类目、500 元"完全匹配的行
-- 老写法（啰嗦）
SELECT * FROM product
WHERE category_id = 3 AND price = 500;

-- 行构造器写法（多列时显著简洁）
SELECT * FROM product
WHERE (category_id, price) = (3, 500);

-- 配合表子查询：找 (category_id, price) 恰好等于"该类目最高价"的商品
SELECT * FROM product
WHERE (category_id, price) IN (
  SELECT category_id, MAX(price)
  FROM product
  WHERE is_deleted = 0
  GROUP BY category_id
);
行构造器 (a,b) = (x,y) 等价于 a=x AND b=y；当两个列的组合有联合索引时，MySQL 8.0 能走索引范围扫描，比 AND 写法并不慢。

10.5 相关子查询与派生表

子查询里若引用了外层表的列，就是"相关子查询"——外层每行都要把它重跑一遍；放 FROM 后面的子查询叫"派生表"。

-- 相关子查询：查出每个用户及其订单数（子查询引用了外层 c.id）
SELECT
  c.id,
  c.name,
  (SELECT COUNT(*)
   FROM orders o
   WHERE o.customer_id = c.id) AS order_cnt
FROM customer c;

-- 派生表：FROM 后面的子查询必须起别名
SELECT t.category_id, t.cnt
FROM (
  SELECT category_id, COUNT(*) AS cnt
  FROM product
  WHERE is_deleted = 0
  GROUP BY category_id
) AS t
WHERE t.cnt > 10;
  • 相关子查询 = 嵌套循环：外层 1 万行，子查询可能被执行 1 万次。数据量大时改用 JOIN（优化器 8.0 常能把相关子查询自动改写成半连接，第 23 章看 EXPLAIN 验证）；
  • 派生表必须起别名：FROM (SELECT ...) t 里 t 不能省，否则语法错；
  • MySQL 8.0 之前派生表的优化较弱（不能下推条件），8.0 的 derived table merging 与 condition pushdown 已经大幅改善。

✓ 本章小结

要点一句话
三种形状标量（一格）、行（一行）、表（多行），形状决定位置与运算符
标量子查询"和平均值比"类条件首选；多返回一格直接报错
IN / ANY / ALLIN 常用；> ALL = 比最大还大；ANY/ALL 读得懂即可
行构造器(a,b)=(x,y) 简洁表达多列等值匹配
相关子查询外层每行重跑一次，大数据量改写为 JOIN

✎ 本章习题

A 基础用标量子查询查出"价格高于全站商品平均价"的 3 号类目商品，返回 id、name、price。
B 进阶用表子查询 + IN 写出"买过 3 号类目商品的所有用户 id 与姓名"（需穿过 orders → order_item → product 三表）。
C 挑战用行构造器 (category_id, price) IN (SELECT category_id, MAX(price) ...) 查出每个类目下最贵的那件商品；再把它改写为 JOIN 版本，对比两条 SQL 的可读性差异。
