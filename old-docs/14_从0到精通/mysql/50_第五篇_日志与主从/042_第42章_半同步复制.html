第 42 章 半同步复制

教科书 第 42 章 / 共 72 章 · 预计 35 分钟

异步复制下主库提交就返回，从库挂了丢数据都不知道。半同步复制让主库至少等一个从库"签收"binlog 才返回——用一点点延迟换数据安全。

◆本章目标

  • 说清异步、半同步、全同步三种复制模式的差别；
  • 会安装并开启半同步插件（rpl_semi_sync_master / rpl_semi_sync_slave）；
  • 理解半同步"超时自动退化异步"的保护机制；
  • 知道半同步到底等从库"收到 binlog"还是"重放完成"；
  • 能判断自己的业务该不该上半同步。

42.1 异步 vs 半同步

默认复制是异步的：主库写完 binlog 就告诉客户端"成功了"，不管从库有没有收到。

  • 异步复制主库提交即返回，从库慢慢拉。性能最高，但主库宕机时"已提交未复制"的事务会丢；
  • 半同步复制主库提交后至少等一个从库把 binlog 写到 relay log才返回客户端。介于快慢之间；
  • 全同步复制等所有从库都重放完成才返回。最安全但最慢，MySQL 原生不直接提供（MGR 可近似）。
注意：半同步只保证"从库收到了 binlog"（写到 relay log），不是"从库重放完了"——所以它防的是"主库挂了数据丢"，不防"主从延迟导致读不到"。

42.2 插件安装与开启

半同步是插件式的：主库装 master 插件，从库装 slave 插件，再各开一个开关。

-- 主库上安装并开启半同步插件（8.0 插件名）
INSTALL PLUGIN rpl_semi_sync_master SONAME 'semisync_master.so';
SET GLOBAL rpl_semi_sync_master_enabled = 1;

-- 从库上安装并开启
INSTALL PLUGIN rpl_semi_sync_slave SONAME 'semisync_slave.so';
SET GLOBAL rpl_semi_sync_slave_enabled = 1;

-- 从库插件开启后，重启复制线程让它生效
STOP REPLICA;
START REPLICA;
Windows 下插件后缀是 .dll，Linux 下是 .so。想重启后保留，要把这两行写进 my.cnf：rpl_semi_sync_master_enabled=1（主）/ rpl_semi_sync_slave_enabled=1（从）。
-- 验证主库半同步状态
SHOW VARIABLES LIKE 'rpl_semi_sync_master_enabled';
SHOW STATUS LIKE 'Rpl_semi_sync_master_status';   -- ON 表示半同步正在生效

-- 从库侧
SHOW STATUS LIKE 'Rpl_semi_sync_slave_status';     -- ON 表示已在做半同步 ACK

42.3 关键参数与退化机制

半同步最聪明的设计：等不到 ACK 就自动退回异步，不让从库故障拖死主库。

参数含义
rpl_semi_sync_master_timeout主库等 ACK 的超时毫秒数，默认 10000（10 秒）。超时后自动退化为异步复制
rpl_semi_sync_master_wait_for_slave_count至少几个从库 ACK 才算数，默认 1
rpl_semi_sync_master_wait_pointAFTER_SYNC（8.0 默认，先同步 binlog 再返回）或 AFTER_COMMIT
退化机制是一把双刃剑：从库网络一抖动，主库悄悄退回异步，你以为有保护其实没有——所以要监控 Rpl_semi_sync_master_status 的 ON/OFF 变化，频繁 OFF 说明网络撑不起半同步。
半同步不是银弹：它每个事务都多一次网络往返，高并发下延迟会明显上升。对延迟敏感的业务（如秒杀）慎用，或只在关键写路径开启。

42.4 常见坑清单

  • 坑主库装了从库插件、从库装了主库插件：插件与角色不匹配，状态一直 ON 不了；
  • 坑以为半同步能解决主从延迟读不到：它只保证从库"收到"，重放还在后面排着队；
  • 坑超时退化成异步却无人知晓：监控 Rpl_semi_sync_master_status，告警 OFF 事件；
  • 坑把 wait_for_slave_count 设太大：要求三个从库都 ACK，任意一个慢全站写都被拖慢。

42.5 半同步监控指标

半同步开了不代表一直生效，退化了要立刻知道。

SHOW STATUS LIKE 'Rpl_semi_sync_master_status';   -- ON=生效，OFF=已退化
SHOW STATUS LIKE 'Rpl_semi_sync_master_no_tx';    -- 因超时未收到 ACK 的事务数
SHOW STATUS LIKE 'Rpl_semi_sync_master_yes_tx';  -- 正常收到 ACK 的事务数
yes_tx 增长正常、no_tx 突然抬头，说明网络在抖，半同步正在悄悄退化——这比宕机更隐蔽。
