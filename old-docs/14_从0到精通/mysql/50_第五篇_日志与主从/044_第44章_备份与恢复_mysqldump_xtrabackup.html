44.1 备份方式怎么选

先看数据量：小库逻辑备份最省事，大库物理热备才扛得住。

方式原理优点缺点
mysqldump（逻辑）导出成 SQL 文本体积小、跨版本、可读千万行以上慢，恢复更慢
xtrabackup（物理）直接拷贝数据文件热备不停机、快占空间大，需 prepare
binlog 增量记录备份后的修改事件秒级时间点恢复必须配合全量用
黄金组合：xtrabackup 每周全量 + binlog 实时增量 + 定期演练恢复。mysqldump 用于小库迁移与升级前兜底。

44.2 mysqldump 备份与恢复

mysqldump 把库导出成一串 CREATE/INSERT 语句，导入即重放。

# 备份整个库（带事务一致性、建库语句、表锁关闭）
mysqldump -uroot -p \
  --single-transaction \
  --master-data=2 \
  --routines --triggers \
  mydb > mydb_20261023.sql

# 只备份某几张表
mysqldump -uroot -p --single-transaction mydb order order_item > orders.sql

# 恢复：在新实例上直接执行这个 SQL 文件
mysql -uroot -p -e "CREATE DATABASE mydb;"
mysql -uroot -p mydb < mydb_20261023.sql
  • --single-transaction：InnoDB 下开一致性快照备份，不锁表；
  • --master-data=2：把备份时的 binlog 位点注释写进文件，PITR 从这里继续；
  • --routines/--triggers：把存储过程、触发器一起带走（默认不带，容易漏）。
mysqldump 恢复是"逐句重放"，百万级表恢复可能要几小时。大库别指望它做日常备份，它是迁移与兜底工具。

44.3 xtrabackup 物理热备

Percona 的 xtrabackup 直接拷贝 InnoDB 数据文件，备份时业务照常写。

# 全量备份（不停机）
xtrabackup --backup --user=root --password=xxx --target-dir=/backup/full_20261023

# prepare：把备份期间产生的 redo 重放完整，得到一致的数据
xtrabackup --prepare --target-dir=/backup/full_20261023

# 恢复：把 prepare 好的目录拷回数据目录（先停库、清空 datadir）
systemctl stop mysql
xtrabackup --copy-back --target-dir=/backup/full_20261023
chown -R mysql:mysql /var/lib/mysql
systemctl start mysql
MySQL 8.0 对应工具是 xtrabackup 8.0，版本要与服务端匹配。--prepare 这步不能省：备份时数据文件一直在变，要靠 redo 把它拉到一个时间点。

44.4 binlog 时间点恢复

全量备份只到某个时刻，之后的数据靠 binlog 补到你指定的"误操作前一秒"。

# 场景：凌晨 2 点全量，早上 10 点有人误 DROP TABLE，要恢复到 9:59
# 1) 先恢复全量备份（mysqldump 或 xtrabackup）
# 2) 从备份位点开始重放 binlog，截止到误操作时间点
mysqlbinlog --start-position=1574 \
  --stop-datetime="2026-10-23 09:59:50" \
  binlog.000010 binlog.000011 | mysql -uroot -p
误删/误改后第一时间：先停写、别再动 binlog 文件，确认要恢复到的位点再操作。恢复是"覆盖式重放"，做错方向会把数据搞得更乱。

44.5 常见坑清单

  • 坑从不演练恢复：备份文件损坏、权限不对，真出事才发现恢复不了；
  • 坑mysqldump 漏 --routines：存储过程没导出来，新库功能缺一半；
  • 坑xtrabackup 跳过 --prepare：直接把"备份中还在写"的文件拷回去，启动即崩；
  • 坑备份和数据放同一块盘：盘坏了备份一起没，备份要异地/异机。

44.5 备份保留与验证策略

备份不是备完就完，要定保留周期并定期做恢复演练。

  • 每周全量 + 每日 binlog 增量，保留至少一个月；
  • 每月挑一个备份做恢复演练，验证可用；
  • 备份文件异地存放，与数据盘分开。
没演练过恢复的备份等于没有备份——这是运维界用无数次事故换来的教训。

✓ 本章小结

要点一句话
选型小库 mysqldump，大库 xtrabackup，增量靠 binlog
mysqldump--single-transaction 一致性备份，导入即重放
xtrabackupbackup → prepare → copy-back 三步不能跳
PITR全量恢复后用 mysqlbinlog 重放到误操作前
铁律备份必须演练恢复、必须异地存放
