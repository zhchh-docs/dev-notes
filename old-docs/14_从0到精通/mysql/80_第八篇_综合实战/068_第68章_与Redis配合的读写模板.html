68.1 Cache-Aside 读模板

最常用的模式：读先问 Redis，没有再查库并回填；写先更库再删缓存。

# 伪代码：商品详情 Cache-Aside
def get_product(pid):
    key = f"product:{pid}"
    data = redis.get(key)
    if data:
        return json.loads(data)                 # 命中
    row = db.query("SELECT * FROM product WHERE id=?", pid)
    if row is None:
        redis.setex(key, 60, "NULL")           # 防穿透：空值也短缓存
        return None
    redis.setex(key, 3600, json.dumps(row))    # 回填，1h
    return row

# 写：先更新库，再删缓存（不是更新缓存）
def update_product(pid, price):
    db.execute("UPDATE product SET price=? WHERE id=?", price, pid)
    redis.delete(f"product:{pid}")            # 下次读自然回源最新值
坑：写操作"先更新缓存再更库"会把旧值写回缓存。正确是先更库、后删缓存，让下次读重新加载。删缓存失败要重试队列兜底。

68.2 穿透、击穿、雪崩

问题现象对策
穿透查不存在的 key，每次都打库空值短缓存 + 布隆过滤器
击穿热点 key 过期瞬间，并发全打库热点 key 不过期 / 互斥锁重建
雪崩大批 key 同时过期过期时间加随机抖动（3600±300s）
缓存三兄弟的区别：穿透是"查无此 key"，击穿是"单个热点过期"，雪崩是"成片同时过期"——对策分别是空值缓存、互斥锁、过期加随机。

68.3 库存计数与 Redis 配合

# 读多写少的库存展示：Redis 计数，MySQL 为准
# 下单时先 DECR 占位，再异步落库扣减
def try_dec_stock(pid, n=1):
    left = redis.decrby(f"stock:{pid}", n)
    if left < 0:
        redis.incrby(f"stock:{pid}", n)     # 超卖回滚
        return False
    return True
  • 原则：Redis 扛并发计数，MySQL 做最终一致，不能反过来；
  • 坑：Redis 库存与 DB 库存会短暂不一致，对账脚本定期校准。

68.4 缓存 key 设计与淘汰

key 规范乱，后期排查与迁移就是噩梦。

# 约定：业务:实体:id ，统一前缀
product:detail:55
stock:item:55
order:detail:NO202610230001

# 过期：热点长 TTL + 随机抖动防雪崩
SETEX product:detail:55 3600 $((RANDOM%300)) value
约定说明
统一前缀业务:实体:id，便于按前缀清理
空值短缓存防穿透，TTL 60 秒即可
过期加随机±5% 抖动，避免同批 key 同时失效
监控：缓存命中率、重建 QPS、删除失败重试队列长度，三项异常说明缓存层在退化。
  • 命中率长期低于 90%：key TTL 过短或热点漂移；
  • 重建 QPS 飙升：发生击穿，检查互斥锁是否生效。
