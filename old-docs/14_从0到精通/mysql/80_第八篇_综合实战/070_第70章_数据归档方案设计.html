70.1 归档对象与边界

不是所有表都归档：高频交易表才有量级压力，配置表不用动。

表归档时间边界理由
orders完成满 180 天量大，热库只留近半年
order_item跟随 orders外键连带，主表走则明细一起走
wallet_flow满 1 年对账保留期要求更长
users/product/inventory不归档量小且被引用，留热库
坑：只归档 orders 不归档 order_item，会留下一堆"孤儿明细"。归档必须按订单闭环为单位：一个订单主表 + 它的明细一起搬。

# 校验：归档库行数 = 源库候选行数，差异报警

70.3 回查与校验

-- 归档后校验：源库不应再有 180 天前的 FINISHED 订单
SELECT COUNT(*) FROM orders
WHERE status='FINISHED' AND finished_at < DATE_SUB(CURDATE(),INTERVAL 180 DAY);
-- 期望：0

-- 回查路径：客服查历史单，先热库，查不到去归档库同构表
-- SELECT * FROM archive.orders WHERE order_no='...';
归档方案的验收标准不是"搬走了多少"，而是"需要时能不能找回来"——回查路径不通的归档等于丢数据。

70.4 归档排期与监控

归档任务本身也是个作业，要排期、要监控。

-- 归档作业排期：每月凌晨低峰跑
-- 监控：每次跑完记录搬迁行数与耗时
CREATE TABLE IF NOT EXISTS archive_job_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  job_name VARCHAR(64), rows_moved INT,
  started_at DATETIME, finished_at DATETIME
);

-- 异常：搬迁行数为 0 或耗时突增，报警复查
归档任务必须限速（--limit）并避开业务高峰，否则它自己会成为压垮库的那个任务。
归档不是一次性项目：建月度作业 + 行数监控 + 回查路径文档，交给值班同学也能跑。
-- 月度校验：热库近半年订单数应稳定增长，不应出现历史数据残留
SELECT MIN(finished_at), MAX(finished_at), COUNT(*)
FROM orders WHERE status='FINISHED';
-- MIN 不应早于 180 天前

70.5 归档任务调度与幂等

归档是月度作业，必须可重入：失败重跑不会搬同一条、不会重复删。

-- 作业日志：每次跑都先记录开始，结束写结果
CREATE TABLE IF NOT EXISTS archive_job_log (
  id          BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  job_name    VARCHAR(64) NOT NULL,
  rows_moved  INT NOT NULL DEFAULT 0,
  status      VARCHAR(16) NOT NULL,          -- RUNNING/DONE/FAIL
  started_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  finished_at DATETIME NULL
);

-- 幂等保证：where 条件只命中"还在热库"的行，已搬走的自然不再命中
-- 重跑安全：pt-archiver 每批 commit-each，失败在某批重跑即可
  • 调度：cron 每月 1 号凌晨 2 点跑，避开业务高峰；
  • 幂等：搬迁与删除同批提交，源行消失即不可再命中；
  • 坑：并发触发两次同一归档任务会抢 IO，调度加分布式锁。

70.6 归档校验脚本

归档跑完做行数对账，差异报警。

-- 热库应已无 180 天前的 FINISHED 订单
SELECT COUNT(*) AS residual FROM orders
WHERE status='FINISHED'
  AND finished_at < DATE_SUB(CURDATE(), INTERVAL 180 DAY);  -- 期望 0

-- 归档库本次新增行数 = 源库候选行数
SELECT COUNT(*) FROM archive.orders
WHERE archived_at >= DATE_SUB(CURDATE(), INTERVAL 1 DAY);

-- 抽 10 个 order_no 双侧比对金额
对账失败先别删归档库数据，用 order_no 从 binlog 补回缺失行。

✓ 本章小结

要点一句话
对象orders+order_item 按 180 天归档，wallet_flow 1 年，主数据不归档
单位按订单闭环整体搬迁，不丢明细孤儿
校验源库候选行数应归零，归档库行数对账
回查归档库同构表，客服先热库后归档库
调度与幂等归档作业可重入、可监控，失败不重复搬数
归档校验行数对账+抽样双侧比对
