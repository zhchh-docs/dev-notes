◆本章目标

  • 把"一个小电商"的需求翻译成库表结构；
  • 掌握设计顺序：先业务实体，再关系，后索引；
  • 落地 users / product / orders / order_item / inventory / wallet_flow 六张核心表；
  • 理解范式与反范式的取舍；
  • 为后续章节（业务 SQL、报表、归档）铺好同一张库。

64.1 需求边界与实体清单

本章的电商是"卖货 + 下单 + 扣库存 + 资金流水"的最小闭环，不做优惠券、不做物流。

64.2 建库与用户表

CREATE DATABASE IF NOT EXISTS shop DEFAULT CHARSET utf8mb4;
USE shop;

CREATE TABLE users (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  nickname    VARCHAR(64)  NOT NULL,
  phone       VARCHAR(20)  NOT NULL,
  balance     DECIMAL(12,2) NOT NULL DEFAULT 0.00,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  is_deleted  TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_phone (phone)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
设计要点：金额一律 DECIMAL(12,2)，浮点会在对账时让你怀疑人生；is_deleted 软删位贯穿全书。

64.3 商品与库存

CREATE TABLE product (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  name        VARCHAR(128) NOT NULL,
  price       DECIMAL(12,2) NOT NULL,
  status      TINYINT NOT NULL DEFAULT 1,     -- 1上架 0下架
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';

CREATE TABLE inventory (
  product_id  BIGINT UNSIGNED NOT NULL,
  stock       INT NOT NULL DEFAULT 0,
  version     INT NOT NULL DEFAULT 0,          -- 乐观锁
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='库存表';
为什么库存单独一张表而不是放 product 里：库存是高频写热点，拆出来避免和商品读互相锁；version 列给乐观锁用，防止超卖。

64.4 订单主表与明细

CREATE TABLE orders (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  order_no     VARCHAR(32) NOT NULL,
  user_id      BIGINT UNSIGNED NOT NULL,
  total_amount DECIMAL(12,2) NOT NULL,
  status       VARCHAR(16) NOT NULL DEFAULT 'CREATED',
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  payed_at     DATETIME NULL,
  is_deleted   TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_user_created (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单主表';

CREATE TABLE order_item (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  order_id      BIGINT UNSIGNED NOT NULL,
  product_id    BIGINT UNSIGNED NOT NULL,
  product_name  VARCHAR(128) NOT NULL,          -- 商品快照：改名不影响历史订单
  price         DECIMAL(12,2) NOT NULL,         -- 成交单价快照
  quantity      INT NOT NULL,
  PRIMARY KEY (id),
  KEY idx_order (order_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单明细';
明细表里冗余 product_name 与 price 是刻意的反范式：订单是"成交那一刻的快照"，商品以后改名、改价都不能影响历史账单。

64.5 资金流水与索引复盘

CREATE TABLE wallet_flow (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id     BIGINT UNSIGNED NOT NULL,
  order_id    BIGINT UNSIGNED NULL,
  amount      DECIMAL(12,2) NOT NULL,          -- 正：入账 负：出账
  type        VARCHAR(16) NOT NULL,             -- RECHARGE/PAY/REFUND
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_user_created (user_id, created_at),
  KEY idx_order (order_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='资金流水';
设计决策理由
金额 DECIMAL杜绝浮点误差，对账精确到分
明细快照商品改名改价不影响历史订单
库存拆表高频写与商品读隔离，加乐观锁
(user_id, created_at)"我的订单列表"高频查询的联合索引

✓ 本章小结

要点一句话
六张表users/product/inventory/orders/order_item/wallet_flow 构成最小闭环
金额类型DECIMAL(12,2)，永远不用浮点存钱
快照冗余明细冗余商品名与成交价，是为历史账单负责
库存热点拆表 + version 乐观锁，应对超卖

✎ 本章习题

A 基础把上面六张表在本机 MySQL 里建出来，并插入 2 个用户、3 个商品。
B 进阶为什么订单明细里要存 product_name 而不是每次 JOIN product？举一个商品改名后出问题的场景。
C 挑战给 shop 库再补一张"购物车 cart"表（用户、商品、数量、加入时间），并给出它的主键与索引设计。
