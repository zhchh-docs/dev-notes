72.3 延伸路线

  • 深入：MySQL 源码（InnoDB 存储结构）、事务隔离级别实验；
  • 生态：Redis 集群、ES、消息队列与 MySQL 的协同；
  • 分布式：分库分表中间件（ShardingSphere）、分布式事务 Seata；
  • 定位：作为全栈工程师，你的目标是"能设计库表、能写业务 SQL、能定位慢查询、能做基础运维"，不是成为专职 DBA。

72.4 数据库能力怎么放进自我介绍

结合十年前端转全栈的背景，把数据库讲成你的增量。

  • 前端时期：熟悉关系型库基本查询与表设计；
  • 转全栈后：能独立完成库表设计、写业务 SQL、用 EXPLAIN 定位慢查询；
  • 进阶落地：做过缓存（Redis）与搜索（ES）配合，懂主从复制与基础运维；
  • 定位：不空谈架构，能讲出真实项目里"设计→优化→故障"的具体案例。
面试官想听的是"你真的用过、踩过、解决过"，把全书案例练成本人的故事，比背十页八股文管用。
全书收尾建议：把 shop 库从建表到报表、缓存、归档、压测完整走一遍，它就是你简历里的全栈项目案例。
  • 复习顺序：索引优化 → 事务锁 → 主从复制 → 运维调优；
  • 动手清单：建库、写下单事务、加索引、配 Redis、跑 sysbench。
