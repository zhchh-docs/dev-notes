69.1 为什么 LIKE 扛不住搜索

WHERE name LIKE '%机械%' 前导通配符必然全表扫，商品上十万行就慢得没法用。

-- 反例：前缀 % 无法走索引，全表扫描
SELECT * FROM product WHERE name LIKE '%机械键盘%';
-- EXPLAIN 看到 type=ALL，rows = 全表行数
能力MySQLElasticsearch
模糊/分词搜索LIKE 全表扫倒排索引，毫秒级
相关度排序无BM25 打分
实时更新事务强一致近实时（1s 级）
写入事务ACID最终一致
分工原则：MySQL 是事实来源（system of record），ES 是衍生索引（derived index）——搜索走 ES，详情与下单永远回 MySQL。

69.2 MySQL → ES 同步

同步两条路：业务双写，或 binlog 订阅（Canal/Debezium）。

# 应用层双写模板（简单场景）：先写库，成功后异步投 ES
def upsert_product(p):
    db.execute("UPDATE product SET name=?, price=? WHERE id=?", p.name, p.price, p.id)
    mq.send("product.sync", {"id": p.id, "name": p.name, "price": p.price})  # 异步
# 消费者消费消息写 ES，失败重试，保证最终一致

69.3 搜索查询模板

// ES 查询：按名称分词搜，返回 id 与相关度
GET /products/_search
{
  "query": { "match": { "name": "机械键盘" } },
  "_source": ["id"],
  "size": 20
}
# 双读模板：ES 拿 id，MySQL 取详情（价格/库存以库为准）
def search_products(kw):
    ids = es.search("products", kw)          # 只拿 id 列表
    if not ids:
        return []
    rows = db.query(
        f"SELECT * FROM product WHERE id IN ({','.join(['?']*len(ids))}) AND status=1",
        *ids)
    return rows
ES 里存的 name 可以搜，但价格、库存、上下架状态永远不要用 ES 的——它们更新快、ES 有延迟，下单与展示价格必须回 MySQL。

69.4 同步延迟与一致性兜底

用户刚改完商品，立刻搜索搜不到？需要兜底。

# 写库后主动触发一次同步（不等 binlog 延迟）
def update_product(p):
    db.execute("UPDATE product SET name=? WHERE id=?", p.name, p.id)
    es.upsert("products", p.id, p)   # 同步立即写 ES，binlog 再做最终校正
  • 体验写后即时同步，把"搜不到"窗口从秒级降到毫秒；
  • 兜底binlog 订阅做最终一致，漏掉的变更会被追平。
兜底：搜索结果页标注"数据更新可能延迟几秒"，管理预期比默默不一致更好。
-- 对账：定时抽查 ES 文档数与 MySQL 商品数是否一致
SELECT COUNT(*) FROM product WHERE status=1;
-- 与 ES _count 对比，偏差大触发全量重建

69.5 ES 索引模板与 SQL 侧配合

ES 索引不是全字段搬过去，只搬要搜的，价格库存留 MySQL。

// products 索引 mapping：name 中文分词，id 与分类精确
PUT /products
{
  "mappings": {
    "properties": {
      "id":      { "type": "long" },
      "name":    { "type": "text", "analyzer": "ik_max_word" },
      "category":{ "type": "keyword" },
      "status":  { "type": "byte" }
    }
  }
}
字段放哪
name / category进 ES，承担分词搜索与筛选
price / stock / status留 MySQL，展示时回查，避免脏读
id两边都存，ES 结果靠它回表

✓ 本章小结

要点一句话
分工MySQL 是事实来源，ES 是衍生搜索索引
同步binlog 订阅异步同步，业务不感知；失败重试保证最终一致
查询ES 只拿 id，详情/价格/库存回 MySQL
边界ES 近实时、非事务，不适合做扣库存这类强一致操作
索引模板分词映射怎么建，SQL 侧哪些字段进 ES
