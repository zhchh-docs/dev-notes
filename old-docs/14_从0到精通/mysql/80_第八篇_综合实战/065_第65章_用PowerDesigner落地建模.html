65.1 CDM 与 PDM 两层

建模不是画图，是两层抽象：CDM 描述业务概念，PDM 落到具体数据库。

层关注产物
CDM 概念模型实体、属性、关系，不管数据库类型业务 ER 图，和产品对需求用
PDM 物理模型字段类型、索引、外键、引擎可导出建表 SQL 的物理设计

65.2 建模操作要点

  • 新建 PDM，DBMS 选 MySQL 8.0；
  • 每个 Table 填写 Code（表名）与 Comment（中文说明）；
  • 字段指定 Data Type、Primary Key、Mandatory；
  • 关系线 1:N：users—orders、orders—order_item；
  • 索引在 Indexes 页签补 idx_user_created。
PowerDesigner 生成的 SQL 默认会带外键约束——互联网业务通常在建表时不建物理外键（由应用层保证），导出后要把 ALTER TABLE ... ADD CONSTRAINT FOREIGN KEY 删掉。

65.3 反向工程与命名规范

已有库也能反向生成模型：File → Reverse Engineer → Database。

-- 建模产物导出后，应该长这样（节选 orders）
CREATE TABLE orders (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  order_no   VARCHAR(32) NOT NULL,
  user_id    BIGINT UNSIGNED NOT NULL,
  ...
  PRIMARY KEY (id),
  KEY idx_user_created (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
规范约定
表名小写下划线复数：orders / order_item，不驼峰
主键统一 id，外键 表名_id
必填列created_at / updated_at / is_deleted 全套
注释表注释 + 关键列注释，生成文档的来源
建模工具的价值不是画图，是"模型即文档"：字段含义、关系、索引都在一张图上，新同事入职看它比看库表快十倍。

65.4 建模检查清单

出图前逐项打勾，避免返工。

-- 导出后对照检查
-- 1) 每表是否有主键 id
-- 2) 每表是否有 created_at / updated_at / is_deleted
-- 3) 金额列是否 DECIMAL
-- 4) 外键列是否 表名_id 且类型与主键一致
-- 5) 高频查询是否都有对应索引
SHOW CREATE TABLE orders\G
  • 规范表注释、列注释齐全，生成文档可读；
  • 反模式字段用英文缩写、不写注释，三个月后自己也看不懂。
模型版本：表结构变更走"改模型→导出 DDL→评审→执行"，不要直接改生产库再回头补模型。
-- 评审清单最后一项：索引是否覆盖核心查询
-- 我的订单列表 → idx_user_created(user_id, created_at)
SHOW INDEX FROM orders;

65.5 命名规范速查

模型评审最常见的争论是命名，提前立好规范。

对象约定
表名小写下划线复数：orders、order_item，不驼峰
主键统一 id，外键 表名_id
时间列created_at / updated_at，DATETIME
布尔标记is_deleted TINYINT，0/1
索引idx_列名 / uk_列名，见名知意
规范的价值：新人看字段名就懂含义，DBA 评审不再为命名来回改图。
