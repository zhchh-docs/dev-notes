51.1 ShardingSphere 是什么

ShardingSphere 是 Apache 基金会的开源分布式数据库中间件，提供分库分表、读写分离、分布式事务能力。

  • ShardingSphere-JDBC以 jar 嵌进 Java 应用，无额外部署，性能好；
  • ShardingSphere-Proxy独立部署，对外像个 MySQL，多语言都能连；
  • 对应用暴露的是逻辑表：你写 SELECT * FROM order WHERE user_id=?，由它路由到真实分表。

51.2 分库分表配置示例

以 ShardingSphere-Proxy 的 YAML 为例：订单表 order 按 user_id 对 4 取模，分到 order_0..order_3。

# 数据源：两个库 ds0、ds1
dataSources:
  ds0:
    url: jdbc:mysql://10.0.0.11:3306/db0
    username: root
    password: root
  ds1:
    url: jdbc:mysql://10.0.0.12:3306/db1
    username: root
    password: root

rules:
- !SHARDING
  tables:
    order:                       # 逻辑表名
      actualDataNodes: ds${0..1}.order_${0..3}   # 真实分片
      tableStrategy:
        standard:
          shardingColumn: user_id  # 分片键
          shardingAlgorithmName: order_mod
  shardingAlgorithms:
    order_mod:
      type: MOD                  # 取模算法
      props:
        sharding-count: 4
  keyGenerateStrategy:           # 分布式主键：雪花算法
    column: order_id
    keyGeneratorName: snowflake
几个关键词：actualDataNodes 列出"哪些库的哪些表"是分片；shardingColumn 是分片键；type: MOD 是取模算法；keyGenerateStrategy 指定主键用雪花（下一章详解）。

51.3 主从与读写分离配置

在同一套配置里给分片库配主从，ShardingSphere 自动把写路由主、读路由从。

# 读写分离规则（与分片规则并列）
rules:
- !READWRITE_SPLITTING
  dataSources:
    ds_rw:
      writeDataSourceName: ds0          # 写主
      readDataSourceNames:              # 读从
        - ds0_read0
        - ds0_read1
ShardingSphere 的价值：把"分库分表 + 读写分离 + 分布式主键"统一在一份配置里，应用只写逻辑 SQL，路由细节全交给中间件。
配置写错（分片键、算法、真实节点）不会立刻报错，而是静默路由错分片——上线前务必用真实数据验证几条 SQL 落到了预期分表。

51.4 常见坑清单

  • 坑查询不带分片键：SQL 不带 user_id，中间件只能广播到所有分表；
  • 坑跨分片分页排序ORDER BY ... LIMIT跨分片要归并，深分页极慢；
  • 坑以为中间件能做跨分片 join：它能广播后归并，但性能差，应靠冗余字段；
  • 坑分布式主键忘了配：分片后自增主键会撞，必须用雪花等全局 ID。

51.4 分片配置上线前验证

配置写错不会立刻报错，而是静默路由错分片。

-- 用不同 user_id 写入，核对落到了预期分表
INSERT INTO order(user_id, amount) VALUES (1, 99);
INSERT INTO order(user_id, amount) VALUES (5, 49);
-- 分别查 order_0 / order_1，确认 1%4=1 与 5%4=1 落点正确
上线前务必用真实数据核对几条 SQL 落点，别等用户投诉才发现路由错了。
