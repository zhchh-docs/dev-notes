59.1 工具箱全景

Percona Toolkit 是一组独立 Perl 脚本，不侵入 MySQL，生产环境用了十几年的事实标准。

工具干什么
pt-query-digest把慢日志/ general log / processlist 聚合成报告，按影响排序
pt-online-schema-change在线改表结构，不锁业务写入（下章主角之一）
pt-duplicate-key-checker找重复、冗余索引
pt-show-grants导出所有账号权限，做审计与备份
pt-table-checksum校验主从数据一致性
pt-archiver按条件归档大表数据，不锁表
pt-deadlock-logger持续记录死锁现场
安装（Linux）：yum install percona-toolkit 或从 percona.com 下载 tar 包；Windows 下可用 WSL 运行。

59.2 pt-query-digest：慢日志第一刀

慢日志原文几千行没法看，pt-query-digest 把它按 SQL 模板聚合，告诉你"哪条 SQL 偷走了最多时间"。

# 基本用法：直接喂慢日志
pt-query-digest /var/lib/mysql/slow.log

# 只分析某个库、按执行时间排序
pt-query-digest --filter '$event->{db} eq "shop"' slow.log

# 输出报告头部会告诉你：整体摘要 + Top SQL（每条带调用次数、耗时分布、扫描行数）
# 报告里重点看：
#   Exec time 的 P95/99  —— 平均快不代表尾巴不长
#   Rows examine / Rows sent —— 扫 10 万行返回 3 行的就是它
慢日志分析的黄金法则：先按"总耗时占比"排序（影响面），再看单条 RT 分位数（体验面）——别一上来优化执行最快但最少见的那条。

59.3 巡检类工具组合拳

日常巡检三件套：找冗余索引、导权限、看死锁。

# 1) 重复/冗余索引：那些"前缀重复"的索引白吃写入开销
pt-duplicate-key-checker --host=127.0.0.1 --user=root --ask-pass

# 2) 权限导出（审计/迁移前必备）
pt-show-grants --host=127.0.0.1 --user=root --ask-pass > grants_backup.sql

# 3) 死锁现场持续记录（挂在后台）
pt-deadlock-logger --create-dest-table --dest h=127.0.0.1,D=sys,t=deadlocks     --host=127.0.0.1 --user=root --ask-pass
pt 工具第一次跑在生产前，务必加 --dry-run（支持的工具）或先在从库/测试库跑一遍。任何带写操作的工具都不是"只读"。

59.4 pt-archiver：归档大表

不用 DELETE 删大表，按主键分批搬走——第 61 章的实操工具。

# 把订单表里 2023 年以前的行搬到归档库，源表逐批删除
pt-archiver   --source h=127.0.0.1,D=shop,t=orders   --dest h=10.0.0.20,D=archive,t=orders_2023   --where "created_at < '2024-01-01'"   --limit 1000 --commit-each   --progress 1000 --statistics
  • 要点--limit 1000 每批 1000 行，避免大事务；
  • 安全支持 --dry-run 先看它打算怎么搬；
  • 坑忘了 --dest 它就直接删源表行——先确认目标库表存在。

59.5 使用纪律

  • 先备份，再动手；写操作工具一律先在从库演练；
  • 不在业务高峰跑大工具（pt-archiver、pt-online-schema-change）；
  • 输出留痕：命令、时间、结果都写进运维工单。

59.6 其他常用命令速查

工具箱之外，记住这几个高频排查命令，现场更快。

# 查看谁在锁等待、谁被锁
SHOW ENGINE INNODB STATUS\G      # 找 LATEST DETECTED DEADLOCK 段

# 复制健康
SHOW REPLICA STATUS\G | grep -E 'Running|Behind'

# 表大小与碎片
SELECT table_schema, table_name,
       ROUND(data_length/1024/1024,1) AS data_mb,
       ROUND(index_length/1024/1024,1) AS index_mb
FROM information_schema.TABLES
WHERE table_schema='shop' ORDER BY data_length DESC;
