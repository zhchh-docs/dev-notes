56.1 Buffer Pool 是什么

InnoDB 所有数据读写都必须经过 Buffer Pool——磁盘页 16KB 被读进来缓存在内存，写操作先改内存页再异步刷盘。

它带来两个直接结果：一是读命中——热数据第二次访问不走磁盘；二是写合并——连续多次改同一页，只在它"变脏"被淘汰时刷一次盘。

56.2 大小怎么定：公式与实例拆分

官方建议：专用数据库服务器上，Buffer Pool 占物理内存的 50%~70%。

-- 设为物理内存的 ~60%（16G 机器 → 约 10G），8.0 支持在线调整大小
SET GLOBAL innodb_buffer_pool_size = 10737418240;   -- 字节数，10G
SET PERSIST innodb_buffer_pool_size = 10737418240;

-- 实例数：每个实例 1~2G，降低内部锁竞争
-- 10G 建议 8 个实例（每个 1.25G）
SHOW VARIABLES LIKE 'innodb_buffer_pool_instances';

-- 查看调整进度（8.0 在线 resize 是异步的）
SHOW STATUS LIKE 'InnoDB_buffer_pool_resize_status';
内存规模推荐配置
≤ 4Gbuffer pool 占 50%，instances=1，开发机够用
8~32G占 60%，instances = 每实例 1~2G
64G+占 60~70%，instances 8~16，注意给 OS page cache 和连接留 25%
坑：把 buffer pool 设成 90% 物理内存，看似激进，实则 OS 没有 page cache 可用、连接内存被挤爆，swap 一上整机瘫痪。留 25% 给系统不是保守，是保命。

56.3 LRU 的改良：年轻区与老年代

普通 LRU 扛不住"一次全表扫 100G"把热数据冲掉，InnoDB 把 LRU 分成两段。

-- 老年代比例：新读入的页先放老年代，命中后才晋升年轻区（默认 3/8）
SHOW VARIABLES LIKE 'innodb_old_blocks_pct';        -- 默认 37
-- 在老年代驻留多久后，第二次访问才算"真热"（毫秒，默认 1000）
SHOW VARIABLES LIKE 'innodb_old_blocks_time';       -- 默认 1000

-- 线性预读：连续读够 13 个页就批量拉下一区
-- 随机预读：同一个区已有太多页在缓存，触发异步预取
SHOW VARIABLES LIKE 'innodb_read_ahead_threshold';  -- 默认 56

效果：全表扫描这种"只碰一次"的页污染的是老年代，热数据所在的年轻区纹丝不动。这就是大表统计查询不再把业务打挂的底层原因。

InnoDB 的 LRU 不是"最近用过就不淘汰"，而是"用过两次才算热"——一次偶然访问不会碰瓷你的热数据。

56.4 怎么判断内存够不够

别凭感觉，命中率和脏页比例是硬指标。

-- 命中率：(1 - 未命中读/逻辑读)，应长期 > 99%
SHOW ENGINE INNODB STATUS\G
-- Buffer pool hit rate 1000 / 1000  —— 看到 999/1000 以下要警惕

-- 等价 SQL 口径
SELECT VARIABLE_NAME, VARIABLE_VALUE
FROM performance_schema.global_status
WHERE VARIABLE_NAME IN ('Innodb_buffer_pool_read_requests','Innodb_buffer_pool_reads');

-- 脏页比例：过高压写盘，过低说明刷盘过度
SELECT VARIABLE_NAME, VARIABLE_VALUE FROM performance_schema.global_status
WHERE VARIABLE_NAME LIKE 'Innodb_buffer_pool_pages%';
指标健康区间
Buffer pool 命中率> 99%；连续低于 99.5% 说明数据集已装不下
脏页比例5%~20% 正常；> 50% 说明刷盘跟不上写入
free 页数量长期接近 0 说明内存吃紧，且磁盘读持续上升
命中率低不一定要加内存——先查是不是有大表全表扫描、统计任务在污染缓冲池。抓慢查询往往比扩容便宜一个数量级。

56.5 change buffer 与自适应哈希

Buffer Pool 里两个"加餐"组件，各自解决一类热点。

  • change buffer：对非唯一二级索引的写（INSERT/DELETE/UPDATE）先记在内存，等该页被读入时再合并——大幅减少写放大。唯一索引用不了它（必须立刻校验）。
  • 自适应哈希索引 AHI：InnoDB 观察到某些索引前缀被高频等值查询，自动在内存建哈希。8.0 自动调优，一般保持默认。
SHOW VARIABLES LIKE 'innodb_change_buffer_max_size';  -- 占 buffer pool 比例，默认 25%
SHOW STATUS   LIKE 'Innodb_buffer_pool_wait_free';    -- >0 说明内存压力大到要等脏页刷出

✓ 本章小结

要点一句话
角色Buffer Pool 是 InnoDB 读写唯一通道，读缓存与写缓冲二合一
大小专用库占物理内存 60% 左右，留 25% 给系统，instances 按 1~2G 拆
LRU 改良年轻/老年代两段 + old_blocks_time，防全表扫描污染热数据
健康度命中率 >99%、脏页 5%~20%，异常先抓慢查询再谈扩容
加餐组件change buffer 服务非唯一二级索引写，AHI 自动加速等值热点
