62.1 账号与权限粒度

MySQL 账号 = user@host，权限分层到库、表、列，甚至 8.0 的角色（ROLE）。

-- 建账号：限定来源网段，强密码
CREATE USER 'app_order'@'10.0.%' IDENTIFIED BY '<strong-random-password>';

-- 只授指定库的 DML，不给 DDL/管理权限
GRANT SELECT, INSERT, UPDATE, DELETE ON shop.order TO 'app_order'@'10.0.%';
GRANT SELECT ON shop.product TO 'app_order'@'10.0.%';
FLUSH PRIVILEGES;   -- 8.0 GRANT 即时生效，这一句主要是习惯

-- 列级权限（8.0 支持）：客服只能看订单，看不到收货手机号
GRANT SELECT(id, status, amount) ON shop.orders TO 'cs_read'@'10.0.%';

-- 8.0 角色：把一组权限打包给人
CREATE ROLE 'order_read_role';
GRANT SELECT ON shop.orders TO 'order_read_role';
GRANT 'order_read_role' TO 'cs_read'@'10.0.%';
SET DEFAULT ROLE ALL TO 'cs_read'@'10.0.%';
原则落地做法
最小权限应用账号只授需要的 DML，不授 CREATE/ALTER/DROP/GRANT
按用途分号读、写、报表、迁移各一个账号，不共用
来源限制user@host 限定网段，禁止 % 通配
不共享 rootroot 只本地登录，远程一律个人账号+审计

62.2 密码与连接加密基线

传输不加密 = 内网抓包就能拿全量数据。

-- 密码策略（8.0 组件）
SET GLOBAL validate_password.policy = 'STRONG';
SET GLOBAL validate_password.length = 12;

-- 要求用户改密后必须 SSL
ALTER USER 'app_order'@'10.0.%' REQUIRE SSL;

-- 看现有账号的权限与来源
SELECT user, host, account_locked, password_expired FROM mysql.user;
SHOW GRANTS FOR 'app_order'@'10.0.%';
反模式清单：① 应用配置里 root@% 密码明文；② 所有环境共用一个库账号；③ 为了方便把 FILE/SUPER 授给应用号。这三条任意一条出现都要立刻整改。

62.3 审计与敏感数据

  • 开启企业审计插件（或社区版用 binlog + 代理层审计）；
  • 手机号、身份证落库前加密或脱敏，索引用哈希前缀；
  • 定期 pt-show-grants 导出权限做差异审计。
安全基线的本质：账号能做什么、从哪连、怎么传、谁在查——四件事都要有明确答案，答不上来就是缺口。

62.4 安全自检脚本

定期跑一遍，揪出宽松账号。

-- ① 来源带 % 的账号（过宽）
SELECT user, host FROM mysql.user WHERE host='%';

-- ② 拥有 SUPER/ FILE 等高危权限的账号
SELECT grantee, privilege_type FROM information_schema.USER_PRIVILEGES
WHERE privilege_type IN ('SUPER','FILE','PROCESS','SHUTDOWN');

-- ③ 密码已过期或未设密码策略的账号
SELECT user, host, account_locked, password_expired FROM mysql.user;
发现应用类账号带 SUPER/FILE 立即回收：REVOKE FILE ON *.* FROM 'app'@'10.0.%';，并排查是否有历史脚本依赖。
基线节奏：账号上线前评审权限，下线即回收；每季度导出一次 grants 做差异审计。
-- 过期账号清理：长期未登录或已离职人员
SELECT user, host FROM mysql.user
WHERE user NOT IN ('root','app_order','report_read');

62.5 日常巡检 SQL

把安全检查固化成几条 SQL，值班同学也能跑。

-- ① 来源网段带 % 的账号（过宽）
SELECT user, host FROM mysql.user WHERE host='%';

-- ② 持有 SUPER / FILE / SHUTDOWN 的非 root 账号
SELECT grantee, privilege_type
FROM information_schema.USER_PRIVILEGES
WHERE privilege_type IN ('SUPER','FILE','SHUTDOWN')
  AND grantee NOT LIKE '%root%';

-- ③ 长期未改密或锁定账号
SELECT user, host, account_locked, password_last_changed
FROM mysql.user ORDER BY password_last_changed;
  • 频率：每月一次，结果留痕到运维工单；
  • 红线：应用账号绝不能有 FILE/SUPER，发现立即 REVOKE。

62.6 密码策略基线

光靠人为记不住强密码，要用策略兜底。

-- 8.0 密码组件
SET GLOBAL validate_password.policy = 'STRONG';
SET GLOBAL validate_password.length = 12;
-- 应用账号要求 SSL 连接
ALTER USER 'app_order'@'10.0.%' REQUIRE SSL;
  • 轮换：每季度轮换应用账号密码，配置中心下发；
  • 反模式：密码写在代码仓库或启动脚本里，立即整改。
