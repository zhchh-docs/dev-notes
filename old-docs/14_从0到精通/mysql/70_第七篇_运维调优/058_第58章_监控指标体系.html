58.1 四类指标框架

监控不是越多越好：先分清"容量水位、性能延迟、健康信号、复制状态"四个篮子。

58.2 必抓的计数器

大部分指标来自全局状态计数器，采样一次差值就能算速率。

-- QPS：Com_select 等语句计数的增量
SHOW GLOBAL STATUS LIKE 'Com_select';
SHOW GLOBAL STATUS LIKE 'Com_insert';
SHOW GLOBAL STATUS LIKE 'Com_update';
SHOW GLOBAL STATUS LIKE 'Com_delete';

-- 慢查询速率
SHOW GLOBAL STATUS LIKE 'Slow_queries';

-- 连接与线程
SHOW GLOBAL STATUS LIKE 'Threads_connected';
SHOW GLOBAL STATUS LIKE 'Threads_running';    -- 活跃线程，比 connected 更敏感

-- InnoDB 健康
SHOW GLOBAL STATUS LIKE 'Innodb_buffer_pool_pages_dirty';
SHOW GLOBAL STATUS LIKE 'Innodb_row_lock_waits';
SHOW GLOBAL STATUS LIKE 'Innodb_row_lock_time_avg';
指标健康水位告警建议
Threads_running平时 < 20瞬时 > 50 且持续 1 分钟告警
Slow_queries 增速< 每秒 1 条1 分钟内突增 10 倍告警
缓冲池命中率> 99%跌破 99% 观察 10 分钟
Seconds_Behind_Source< 5s> 30s 告警，> 300s 严重
磁盘使用率< 70%80% 预警，90% 立即处理 binlog/数据
告警的艺术：趋势类指标（磁盘、慢查询数）看同比环比，突刺类（Threads_running、死锁数）看瞬时阈值——两套阈值别混用。

58.3 performance_schema：采样最有问题的 SQL

计数器告诉你"有多慢"，events_statements_summary_by_digest 告诉你"谁慢"。

-- 按平均耗时排序，找出全库最贵的 SQL 模板
SELECT DIGEST,
       LEFT(DIGEST_TEXT, 80) AS sql_text,
       COUNT_STAR AS exec_cnt,
       ROUND(AVG_TIMER_WAIT/1e9, 2) AS avg_ms,
       SUM_ROWS_EXAMINED,
       SUM_ROWS_SENT
FROM performance_schema.events_statements_summary_by_digest
WHERE SCHEMA_NAME = 'shop'
ORDER BY AVG_TIMER_WAIT DESC
LIMIT 10;

-- 按扫描行数排序：查了 100 万行只返回 1 行的元凶
SELECT LEFT(DIGEST_TEXT,80) sql_text, COUNT_STAR,
       ROUND(SUM_ROWS_EXAMINED/COUNT_STAR,0) AS rows_examined_avg
FROM performance_schema.events_statements_summary_by_digest
WHERE SCHEMA_NAME = 'shop'
ORDER BY rows_examined_avg DESC LIMIT 10;
8.0 里 digest 默认开启；若你的库查不到数据，先 UPDATE performance_schema.setup_consumers SET ENABLED='YES' WHERE NAME='events_statements_history'; 并确认 performance_schema=ON。

58.4 复制与告警联动

主从延迟是高可用体系的体温表，配合自动故障切换必须盯死。

-- 8.0.22+ 推荐视图
SHOW REPLICA STATUS\G
-- 关注：Replica_IO_Running=Yes、Replica_SQL_Running=Yes、
--      Seconds_Behind_Source、Last_Error

-- 一次到位的延迟判定（别只看 Seconds_Behind，它会在 IO 抖动时误报 0）
SELECT SERVICE_STATE, REPLYING_SOURCE_HOST,
       COALESCE(SECONDS_BEHIND_SOURCE, -1) AS lag
FROM performance_schema.threads
WHERE NAME = 'thread/sql/replica';

58.5 最小看板清单

不上大型监控系统也能跑起来的最小集：

  • 必看 5 张图：QPS/TPS、慢查询数、Threads_running、缓冲池命中率、主从延迟；
  • 每日巡检：磁盘、错误日志最近 24h、备份是否成功；
  • 反模式：把全部 300+ 状态变量塞进告警——告警疲劳等于没有告警。

✎ 本章习题

A 基础写出 QPS 的采样计算方法（两次 SHOW GLOBAL STATUS 差值除以时间）。
B 进阶从 events_statements_summary_by_digest 找出平均耗时最高的 5 条 SQL 模板，并判断它们是"真慢"还是"偶尔慢"（看 COUNT_STAR）。
C 挑战为什么 Seconds_Behind_Source 会在 IO 线程断开时误报 0？设计一个更可靠的主从延迟监控口径。
