第 9 章 多表连接：INNER/LEFT JOIN

教科书 第 9 章 / 共 72 章 · 预计 45 分钟

◆本章目标

  • 理解 JOIN 的物理过程：先笛卡尔积、再按连接条件过滤；
  • 熟练写 INNER JOIN 与 LEFT JOIN，知道各自保留哪些行；
  • 分清连接条件（ON）与过滤条件（WHERE），不再"连完结果少了一半"；
  • 会写三表连接、自连接（员工-经理）；
  • 用 LEFT JOIN ... IS NULL 写出"反连接"（找没下过单的用户）。

9.1 笛卡尔积与连接的本质

两张表连起来，第一步是"两两配对"——左表每行 × 右表每行，再用连接条件筛掉不配对的。

-- 千万别在生产跑：orders 1 万行 × customer 1 万行 = 1 亿行
SELECT * FROM orders, customer;

-- 等价的隐式连接写法（能用，但不推荐，可读性差）
SELECT o.order_no, c.name
FROM orders o, customer c
WHERE o.customer_id = c.id;

-- 显式 JOIN 写法（推荐：连接条件与过滤条件一目了然）
SELECT o.order_no, c.name
FROM orders o
INNER JOIN customer c ON c.id = o.customer_id;

别名 每张表起短别名（o=orders, c=customer），是 JOIN 语句的标配——列名重复（两表都有 id）时必须用别名区分。

忘记写连接条件 = 笛卡尔积。线上两表几十万行时就是事故级慢查询，这也是老 DBA 说"JOIN 先想条件再动笔"的原因。

9.2 INNER JOIN：取交集

INNER JOIN 只保留"左右都匹配得上"的行——订单没有对应用户（脏数据）的行、用户从没下过单的行，都不会出现。

-- 订单列表页：订单 + 用户名（必须两边都存在）
SELECT
  o.id,
  o.order_no,
  c.name    AS customer_name,
  o.amount,
  o.created_at
FROM orders o
INNER JOIN customer c ON c.id = o.customer_id
WHERE o.is_deleted = 0
ORDER BY o.created_at DESC
LIMIT 20;

9.3 LEFT JOIN：保左表

LEFT JOIN 保留左表全部行：右表匹配上就带出来，匹配不上就补 NULL——"没下过单的用户也要看到"，用它。

-- 需求：列出全部用户，有订单的显示最近一笔订单号，没订单的显示空
SELECT
  c.id,
  c.name,
  o.order_no,
  o.amount
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
                 AND o.is_deleted = 0      -- 右表过滤放 ON 里（下一节细讲）
ORDER BY c.id
LIMIT 20;

反连接：找"没有"的那批

-- 经典需求：找出从没有下过单的用户（沉睡用户召回）
SELECT c.id, c.name, c.phone
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;              -- 右表全是 NULL = 左表这行没匹配上
LEFT JOIN 后接 WHERE 右表主键 IS NULL，就是"反连接"——找左表中在右表没有对应行的记录。这个模式天天用，务必背下来。

9.4 ON 与 WHERE 的差别

这是 JOIN 最容易踩的坑：右表的过滤条件放 ON 还是 WHERE，结果完全不同。

-- 写法一：过滤条件放 ON（推荐）
SELECT c.name, o.order_no
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
                  AND o.status = 'PAID';
-- 语义：先只拿"已支付"的订单去连；没订单 / 没支付订单的用户仍保留，order_no 为 NULL

-- 写法二：过滤条件放 WHERE（结果完全不同！）
SELECT c.name, o.order_no
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.status = 'PAID';
-- 语义：连完之后再筛"右表 status = PAID"——没订单的用户 o.status 是 NULL，
-- NULL = 'PAID' 不成立，被 WHERE 丢掉，LEFT JOIN 退化成 INNER JOIN
位置ON（连接条件）WHERE（连完再过滤）
作用时机连接前决定右表参与哪些行连接后对成品结果集过滤
右表条件放 ON，未匹配的左表行照样保留放 WHERE，NULL 行被滤掉，LEFT 变 INNER
左表条件放哪都行（左表本来就全保留）通常放 WHERE 更清晰
记住一句话：左表条件写 WHERE，右表条件想"保留没匹配上的左表行"就写 ON，想"只要匹配上的"就写 WHERE。拿不准时先想清楚"这行没匹配上要不要留在结果里"。

9.5 多表连接与自连接

三表连：订单连用户、订单明细连商品；自连接：一张表连自己（员工表的经理列指向本表主键）。

-- 三表：订单 + 用户名 + 商品名（一行订单明细）
SELECT
  o.order_no,
  c.name    AS customer_name,
  p.name    AS product_name,
  oi.quantity,
  oi.unit_price
FROM orders o
INNER JOIN customer  c  ON c.id  = o.customer_id
INNER JOIN order_item oi ON oi.order_id = o.id
INNER JOIN product   p  ON p.id  = oi.product_id
WHERE o.id = 10086;

-- 自连接：员工表 manager_id 指向本表 id，查"每个人及其经理"
SELECT
  e.name       AS employee,
  m.name       AS manager
FROM employee e
LEFT JOIN employee m ON m.id = e.manager_id;
连接数的纪律：单条 SQL 建议不超过 3~4 张表 JOIN。再多说明模型设计或查询写法有问题（第 40 章拆库拆表会回来看这个）。MySQL 没有 SQL Server 那种 JOIN 上限，但每多一张表，优化器的搜索空间和锁范围都在膨胀。

JOIN 本质笛卡尔积 + 连接条件过滤；忘写条件 = 灾难
INNER JOIN只保留左右都匹配的行（交集）
