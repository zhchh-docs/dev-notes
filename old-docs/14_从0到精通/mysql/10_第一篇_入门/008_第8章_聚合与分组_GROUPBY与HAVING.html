8.1 五大聚合函数

聚合函数把多行压成一行——这是 SQL 从"查表"走向"统计"的分水岭。

-- 全表一把聚合：整张订单表一个总数
SELECT
  COUNT(*)        AS order_cnt,     -- 订单总数
  SUM(amount)     AS total_amount,   -- 总成交额
  AVG(amount)     AS avg_amount,     -- 客单价
  MAX(created_at) AS last_order,     -- 最近一笔下单时间
  MIN(created_at) AS first_order
FROM orders
WHERE is_deleted = 0;
函数语义对 NULL 的处理
COUNT(*)数行数（不管列值）NULL 行也算
COUNT(列)数"该列非 NULL"的行数NULL 行跳过
COUNT(DISTINCT 列)该列去重后的值个数先去重再数，NULL 跳过
SUM / AVG求和 / 平均自动忽略 NULL 行
MAX / MIN最大 / 最小值忽略 NULL
COUNT(列) ≠ COUNT(*)：统计表行数用 COUNT(*)；想数"有手机号的用户数"才用 COUNT(phone)。新同学最常犯的错就是用 COUNT(可空列) 去数总行数，结果永远少一截。
-- 一张表快速摸底三件套
SELECT
  COUNT(*)                              AS total_rows,
  COUNT(phone)                          AS with_phone,
  COUNT(DISTINCT category_id)           AS category_kind
FROM product;

8.2 GROUP BY 分组

GROUP BY 把行按某列"打包"，每个包出一行聚合结果。

-- 按类目分组：每个类目出一行
SELECT
  category_id,
  COUNT(*)    AS product_cnt,
  AVG(price)  AS avg_price,
  SUM(stock)  AS total_stock
FROM product
WHERE is_deleted = 0
GROUP BY category_id;

-- 多列分组：类目 + 状态 二维统计
SELECT category_id, status, COUNT(*) AS cnt
FROM product
GROUP BY category_id, status;

MySQL 8.0 默认开启 ONLY_FULL_GROUP_BY 模式，它强制要求：SELECT 列表里的非聚合列，必须全部出现在 GROUP BY 中。

-- 报错：name 既没在 GROUP BY 里，也没被聚合包起来
SELECT category_id, name, COUNT(*)
FROM product
GROUP BY category_id;
-- ERROR 1055: Expression #2 of SELECT list is not in GROUP BY ...

-- 为什么要拦：同一类目下有几十个 name，到底返回哪个？旧 MySQL 会"随机"给一个，
-- 结果报表时准时不准，这正是 8.0 默认开启该模式的原因
记住语义：GROUP BY 之后，结果集一行 = 一个分组。SELECT 里除了聚合列，只允许写"分组键本身"——想带别的列，就得用 MAX/MIN/ANY_VALUE() 之类显式决定取哪个。

8.3 HAVING 与 WHERE 的分工

同是"过滤"，WHERE 过滤的是分组前的行，HAVING 过滤的是分组后的组——位置不同，能力不同。

-- 需求：统计"卖得好的类目"——商品数超过 10 个、平均价超过 200 元
SELECT
  category_id,
  COUNT(*)   AS product_cnt,
  AVG(price) AS avg_price
FROM product
WHERE is_deleted = 0          -- 行级过滤：先把软删的扔掉（能下推就别放到 HAVING）
GROUP BY category_id
HAVING COUNT(*) > 10          -- 组级过滤：按聚合结果筛组
   AND AVG(price) > 200;
  • 能写 WHERE 就别写 HAVING：WHERE 在分组前过滤，数据量小、还能走索引；HAVING 是分组后才筛，等于白算了很多组；
  • HAVING 里才能用聚合条件：HAVING COUNT(*) > 10 写在 WHERE 里是非法的（行还没分出来，哪来的组计数）。

8.4 WITH ROLLUP 小计

MySQL 8.0 支持 WITH ROLLUP：分组结果之外自动追加小计行和总计行，出报表特别省事。

-- 按类目统计，末尾自动追加一行"全部合计"
SELECT
  category_id,
  COUNT(*)   AS cnt,
  SUM(stock) AS total_stock
FROM product
WHERE is_deleted = 0
GROUP BY category_id
WITH ROLLUP;
-- 返回：每个 category_id 一行 + 最后一行 category_id 为 NULL 的总计行

-- 8.0.20+ 支持 GROUPING() 函数区分"真 NULL"和"ROLLUP 产生的 NULL"
SELECT
  CASE WHEN GROUPING(category_id) = 1 THEN '全部类目' ELSE CAST(category_id AS CHAR) END AS cat,
  COUNT(*) AS cnt
FROM product
GROUP BY category_id
WITH ROLLUP;
BI 场景下 ROLLUP 用得不多（前端自己拼合计更灵活），但快速出"小计+总计"的一次性报表，它是最省力的写法。

8.5 常见坑清单

  • 坑COUNT(可空列) 当总数：永远少数 NULL 行，总行数用 COUNT(*)；
  • 坑GROUP BY 后 SELECT 非分组列：8.0 直接报错（ONLY_FULL_GROUP_BY），别再关掉它图省事；
  • 坑把聚合条件写进 WHERE：报语法错，聚合筛组一律 HAVING；
  • 坑AVG 被 NULL 拉偏理解：AVG 自动忽略 NULL 行——这通常是想要的，但如果业务想把 NULL 当 0 算，必须 COALESCE(列,0)；
  • 坑GROUP BY 隐式分组：SELECT 里有聚合函数、又没写 GROUP BY，整张表被当成一个隐式组——"查最大金额的订单的其他列"时要小心，那不是行级数据。

✓ 本章小结

要点一句话
聚合函数COUNT(*) 数行、COUNT(列) 数非空；SUM/AVG/MAX/MIN 自动忽略 NULL
GROUP BYSELECT 非聚合列必须是分组键；ONLY_FULL_GROUP_BY 是保护不是障碍
WHERE vs HAVINGWHERE 分组前行过滤（能下推、走索引）；HAVING 分组后组过滤（用聚合结果）
WITH ROLLUP自动追加小计/总计行，GROUPING() 区分合计 NULL
执行顺序FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

✎ 本章习题

A 基础统计每个类目（category_id）下商品数量、平均价格、总库存，只统计未软删且上架状态的商品，按商品数降序取前 10。
B 进阶在 A 的基础上加条件：只保留"商品数 ≥ 5 且平均价 ≥ 100 元"的类目；先写一版"把条件塞 WHERE 里"的错误 SQL 体会报错，再写对的版本。
C 挑战统计 orders 表：按"下单日期"分组，输出每天的订单数、总成交额、客单价；只保留成交额超过当天全店平均的日期（提示：需要组间比较，想想子查询或窗口函数——下两章会讲，先试着用 HAVING + 聚合表达能表达的部分）。
