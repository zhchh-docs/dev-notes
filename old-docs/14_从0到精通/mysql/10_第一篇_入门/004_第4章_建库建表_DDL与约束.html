4.1 CREATE TABLE 逐项拆解

以 bookshop 的商品表为例，逐行读懂它：

CREATE TABLE product (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  name        VARCHAR(100)    NOT NULL COMMENT '商品名',
  price       DECIMAL(10,2)   NOT NULL DEFAULT 0.00 COMMENT '售价',
  stock       INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '库存',
  status      TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1上架 0下架',
  created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP
                              ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';

拆解要点：

  • 列定义 = 列名 + 类型 + 可选修饰：可空性（NOT NULL）、默认值（DEFAULT）、自增（AUTO_INCREMENT）、注释（COMMENT）；
  • AUTO_INCREMENT 自动生成递增整数，必须配合键使用，通常就是主键；删掉最大行后编号不复用；
  • DEFAULT CURRENT_TIMESTAMP 自动填创建时间；ON UPDATE CURRENT_TIMESTAMP 让更新时间随 UPDATE 自动刷新——审计字段几乎每张表都该有；
  • 表选项：引擎 InnoDB（默认）、字符集 utf8mb4，表级 COMMENT 一句话说明用途。
COMMENT 不是装饰：半年后没人记得 status=2 是什么意思。注释写进 DDL，配合 SHOW CREATE TABLE 随时可查，是成本最低的文档。

4.2 六大约束：数据库的把关人

约束拦住什么写法示例
NOT NULL关键字段漏填name VARCHAR(100) NOT NULL
DEFAULT新行缺值stock INT NOT NULL DEFAULT 0
UNIQUE重复值（允许 NULL）UNIQUE KEY uk_phone (phone)
PRIMARY KEY无唯一标识；隐含 NOT NULL + UNIQUEPRIMARY KEY (id)
FOREIGN KEY引用不存在的数据FOREIGN KEY (cid) REFERENCES customer(id)
CHECK非法取值范围（8.0 起真正生效）CHECK (price >= 0)

给订单表加外键与 CHECK，感受完整形态：

CREATE TABLE orders (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '订单号',
  customer_id  BIGINT UNSIGNED NOT NULL COMMENT '下单客户',
  product_id   BIGINT UNSIGNED NOT NULL COMMENT '商品',
  quantity     INT UNSIGNED    NOT NULL DEFAULT 1 COMMENT '数量',
  amount       DECIMAL(12,2)   NOT NULL COMMENT '订单金额',
  created_at   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_customer (customer_id),
  CONSTRAINT fk_orders_customer FOREIGN KEY (customer_id)
    REFERENCES customer (id) ON DELETE RESTRICT ON UPDATE CASCADE,
  CHECK (quantity > 0),
  CHECK (amount >= 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';

外键用还是不用？

外键保证引用完整性（插一笔指向不存在客户的订单直接报错），代价是每次写入多一次父表检查、高并发下可能引发锁等待。因此存在两种流派：

  • 传统/强一致业务（财务、ERP）：建外键，让数据库兜底；
  • 互联网高并发业务：通常不建物理外键，靠应用层校验 + 定期对账保证一致性，并在关联列上建普通索引（KEY idx_customer）。
不建外键 ≠ 不需要约束：即使不建物理外键，逻辑上"订单必须属于某个客户"的规则依然要由应用层严格执行。

4.3 ALTER TABLE：改表怎么做

-- 加一列
ALTER TABLE product ADD COLUMN remark VARCHAR(255) NULL COMMENT '备注' AFTER status;

-- 改类型 / 改默认值（MODIFY 会重写整个列定义）
ALTER TABLE product MODIFY COLUMN name VARCHAR(200) NOT NULL COMMENT '商品名';

-- 改列名（CHANGE：旧名 新名 完整定义）
ALTER TABLE product CHANGE COLUMN remark note VARCHAR(255) NULL;

-- 删一列（危险：数据一起没）
ALTER TABLE product DROP COLUMN note;

-- 改表名
ALTER TABLE product RENAME TO goods;

两个必知事项：

  • 缩列有风险：把 VARCHAR(200) 缩成 50，超过 50 字符的数据会被截断或直接报错（取决于 SQL 模式）；改类型在大表上是昂贵操作（第 60 章细讲）；
  • IF EXISTS / IF NOT EXISTS：DROP TABLE IF EXISTS t、CREATE TABLE IF NOT EXISTS t，让初始化脚本可以重复执行不报错。

4.4 DROP / TRUNCATE / 重命名

操作行为能否回滚
DELETE逐行删，可带 WHERE，触发触发器事务内可以
TRUNCATE清空全表、重建表结构，速度快、自增归零不能（隐式提交）
DROP表定义+数据+索引全部删除不能（除非有备份）
TRUNCATE 和 DROP 默认不可回滚。生产环境执行前先跑一次备份或确认 binlog 开启；强烈建议把这两类语句设为 SQL 客户端的"高危确认"关键词。

4.5 生产级建表惯例

把本章内容收敛成一张"默认模板"，绝大多数业务表可以直接套：

CREATE TABLE t_xxx (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  -- ... 业务字段：一律 NOT NULL + DEFAULT，允许"暂无值"用默认值而非 NULL
  status      TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态，见字典表',
  is_deleted  TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '软删标记 0否 1是',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
                       ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  KEY idx_xxx (xxx)            -- 按查询需求建普通索引
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='表说明';
  • 命名：表名小写下划线、单数或复数二选一全库统一；索引前缀 idx_ / uk_，一眼分辨普通索引与唯一索引；
  • NULL 最小化：NULL 参与 IS NULL 判断、聚合和索引统计都有额外心智负担，能用默认值就不用 NULL；
  • is_deleted 软删：业务数据通常不许物理删除，打标记即可（第 5 章展开）；
  • id 用 BIGINT UNSIGNED：INT 约 21 亿，流水型表几年就可能耗尽，BIGINT 一次到位。
