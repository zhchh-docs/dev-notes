2.1 三种安装方式怎么选

方式优点 / 缺点适合谁
Docker一条命令起停、随时删掉重来、版本随意切换；需先装 Docker Desktop学习、开发（本书推荐）
官方安装包Windows 用 MSI 向导，注册成系统服务；卸载不彻底、易残留旧版本固定机器长期开发
云数据库（RDS）免运维、自带备份高可用；花钱、有网络依赖生产环境

学习期建议：用 Docker。学数据库一定会把库"玩坏"（改坏参数、删错表、锁死自己），Docker 里删掉容器重跑一条命令就能满血复活。

若选 Windows 原生安装：官网下载 MySQL Installer，选 Server only，设置 root 密码并务必记下来；装完在 services.msc 里能看到 MySQL80 服务随开机自启。配置文件默认在 C:\ProgramData\MySQL\MySQL Server 8.0\my.ini——第 55 章调参数时会回来找它。

2.2 用 Docker 起一个 MySQL

先确认 Docker 可用（PowerShell 执行 docker --version 不报错），然后一条命令起库：

docker run -d `
  --name mysql-book `
  -p 3306:3306 `
  -e MYSQL_ROOT_PASSWORD=root123 `
  -e MYSQL_DATABASE=bookshop `
  -v mysql-book-data:/var/lib/mysql `
  mysql:8.0

# 参数逐个说明（PowerShell 换行用反引号 `，Linux/macOS 用 \）：
# -d            后台运行
# --name        容器名，后面 stop/start/rm 都用它
# -p 3306:3306  宿主机 3306 端口映射到容器 3306
# MYSQL_ROOT_PASSWORD   root 密码（生产环境绝不能用弱密码）
# MYSQL_DATABASE        启动时顺手建一个 bookshop 库
# -v            数据目录挂到命名卷，删容器不丢数据

等待约 20 秒完成初始化，然后验证：

docker ps                          # STATUS 应为 Up
docker logs mysql-book --tail 20   # 看到 "ready for connections" 即成功
docker stop mysql-book             # 停止（数据保留在卷里）
docker start mysql-book            # 再次启动
最常见的坑：3306 端口被占用，容器起来又立刻退出，logs 里报 bind on address。解决：改映射为 -p 3307:3306，之后客户端连接端口填 3307。
版本约定：本书示例全部基于 mysql:8.0。8.0 与 5.7 在默认字符集（utf8mb4 vs latin1）、窗口函数、CTE 上差异明显，跟练请统一用 8.0。

2.3 命令行客户端：第一条 SQL

容器里自带 mysql 客户端，直接进容器连库：

docker exec -it mysql-book mysql -uroot -proot123

看到 mysql> 提示符说明已进入。依次敲下面这些命令：

SHOW DATABASES;          -- 有哪些库（information_schema 等是系统库，别动）
SELECT VERSION();        -- 8.0.xx，确认版本
SELECT USER(), CURRENT_USER();   -- 我是谁、以什么身份登录
USE bookshop;            -- 切换到启动时自动建的库
SHOW TABLES;             -- 空的，正常——还没有建表
SELECT NOW();            -- 服务器时间

-- 约定：分号 + 回车才执行；没写分号时提示符变成 -> 等你继续
-- exit 或 quit 退出客户端

也可以在宿主机单独装 mysql 客户端，用 mysql -h 127.0.0.1 -P 3306 -u root -p 连接——回车后再输密码，比把密码写在命令行里安全。

-p密码 中间不能有空格（-proot123）；-p 后面留空则交互式输密码。把密码明文写进命令行会被 shell 历史记录，属于坏习惯。

2.4 图形客户端 DBeaver

日常开发更常用图形客户端。推荐开源免费的 DBeaver Community（Navicat 是收费的同类工具，操作思路一致）：

  1. 新建连接：Database → New Database Connection，选 MySQL；
  2. 填连接信息：Host 127.0.0.1，Port 3306，用户 root，密码 root123；
  3. 下载驱动：首次连接提示下载 JDBC 驱动，点 Download；
  4. 测试：Test Connection 显示 Connected 后，左侧能看到 bookshop 库；
  5. SQL 编辑器：选中库右键 → SQL Editor；Ctrl+Enter 执行当前语句，Alt+X 执行全部。
建议：命令行与图形工具都要会。命令行在服务器排障时往往是唯一手段（生产环境通常没有图形界面）；图形工具擅长看结果、看表结构、看执行计划。

2.5 用户、密码与远程连接

root 是超级管理员，日常开发应该用最小权限的业务账号。MySQL 8.0 把"建用户"和"授权"分成两步：

-- 1. 创建用户：% 表示允许任意主机连接（学习环境可以这样）
CREATE USER 'dev'@'%' IDENTIFIED BY 'Dev_123456';

-- 2. 只授予 bookshop 库的增删改查权限
GRANT SELECT, INSERT, UPDATE, DELETE ON bookshop.* TO 'dev'@'%';

-- 3. 验证
SHOW GRANTS FOR 'dev'@'%';
docker exec -it mysql-book mysql -udev -pDev_123456   # 用新账号登录验证

初学者最常见的三个连接报错，对照排查：

报错原因与解法
Can't connect ... (111 / 10061)服务没起或端口不通：先 docker ps 确认容器 Up，再核对端口
Access denied for user密码错，或该用户不允许从你的来源主机连接（host 不是 %）
Unknown database库名拼错，用 SHOW DATABASES 核对
安全提醒：'dev'@'%' 加弱密码放到公网上，几分钟就会被扫描爆破。学习库也请用强密码；生产环境数据库端口只应对内网开放。

✓ 本章小结

要点一句话
安装方式学习期推荐 Docker：一条命令起停，玩坏即重建
关键命令docker run 起库；docker ps / logs / stop / start 管理生命周期
客户端命令行 mysql 用于排障，DBeaver 用于日常
用户与权限8.0 分两步：CREATE USER 再 GRANT，日常用最小权限账号
连接三查端口通不通 → 服务起没起 → 账号密码/来源主机对不对

✎ 本章习题

A 基础完成本章全部实操：Docker 起库、命令行登录、DBeaver 连接，记下 SELECT VERSION() 的结果。
B 进阶创建用户 reader，只授予 bookshop 的 SELECT 权限；用 reader 登录尝试 CREATE DATABASE test2;，观察并解释报错。
C 挑战把容器端口映射改成 3307 重建，分别用命令行和 DBeaver 连上它；再执行 docker volume ls 找到数据卷，思考：删容器（不删卷）后重跑同名容器，数据还在吗？动手验证。
