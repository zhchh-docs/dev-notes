◆本章目标

  • 掌握规则："proxy_pass 带 URI 就替换 location 匹配部分，不带就原样透传"；
  • 知道带变量时这条规则完全失效的全量透传语义；
  • 能用 curl + 一个回显后端验证任意组合的真实转发 URI；
  • 理解 rewrite → proxy_pass 链路上 $uri 的变化。

12.1 一张表看懂 URL 传递规则

设请求为 GET /api/user?id=1：

location 与 proxy_pass上游收到的 URI
location /api/ { proxy_pass http://b; }/api/user?id=1（原样）
location /api/ { proxy_pass http://b/; }/user?id=1（/api/ → /）
location /api/ { proxy_pass http://b/v2/; }/v2/user?id=1（/api/ → /v2/）
location /api/ { proxy_pass http://b$uri; }/api/user?id=1（带变量：只看表达式求值结果）
location /api/ { rewrite ^/api/(.*)$ /$1 break; proxy_pass http://b; }/user?id=1（rewrite 改 $uri 后原样透传）

判断口诀：proxy_pass 尾巴上有没有"URI 部分"（哪怕只是一个 /）——有，替换；没有，透传。唯一例外是值里含变量：此时 Nginx 只看变量算出来的最终值。

12.2 实验：亲眼对比四种写法

准备一个回显后端（打印收到的路径与参数）：

# echo_server.py
from http.server import BaseHTTPRequestHandler, HTTPServer

class H(BaseHTTPRequestHandler):
    def do_GET(self):
        body = f"path={self.path}\n".encode()
        self.send_response(200)
        self.send_header("Content-Type", "text/plain")
        self.end_headers()
        self.wfile.write(body)

HTTPServer(("127.0.0.1", 8080), H).serve_forever()
# 四个 location 分别指向回显服务
server {
    listen 80;
    location /a/ { proxy_pass http://127.0.0.1:8080; }
    location /b/ { proxy_pass http://127.0.0.1:8080/; }
    location /c/ { proxy_pass http://127.0.0.1:8080/v2/; }
    location /d/ { proxy_pass http://127.0.0.1:8080$uri; }
}
curl http://127.0.0.1/a/user?id=1    # path=/a/user?id=1
curl http://127.0.0.1/b/user?id=1    # path=/user?id=1
curl http://127.0.0.1/c/user?id=1    # path=/v2/user?id=1
curl http://127.0.0.1/d/user?id=1    # path=/d/user?id=1（参数丢了！）

第四行两个细节值得咀嚼：$uri 含 location 前缀 /d/（没被剥掉）；查询串没有跟随——带变量的 proxy_pass 不会自动附加 $args。

12.3 带变量的 proxy_pass 的特殊语义

  • 值里出现任意变量，Nginx 放弃内置规则，转发 URI = 变量表达式求值结果；
  • 查询串需要手动保留：proxy_pass http://b$uri$is_args$args;（$is_args 是 ? 或空串）；
  • 主机名含变量时需要 resolver 指令（Docker/K8s 环境常用 resolver 127.0.0.11 valid=10s;）；
  • 变量化即"每请求解析上游"，性能低于静态 upstream（第 14 章），仅用于动态路由/灰度。

把 12.1 的规则放进这条链路就通了：rewrite 阶段改的是 $uri；proxy_pass 无 URI 时把（可能已被改写的）$uri 整体透传；带 URI 时做前缀替换。

12.5 常见坑

  1. 多打的 / 让接口消失：proxy_pass http://b/; 想剥前缀，但上游其实要完整路径——回显实验一分钟定位；
  2. 带变量后参数蒸发：忘拼 $is_args$args，上游收到无参请求；
  3. 正则 location 中 proxy_pass 带 URI：直接报配置错（正则 location 不能有 URI 部分），只能用 rewrite 或变量方案；
  4. 前缀替换引发部分匹配错切：location /api 与 proxy_pass http://b/api/ 组合，/apifoo 也会被错误替换——location 一律带尾斜杠；
  5. resolver 缺失：变量化主机名报 no resolver defined to resolve xxx。

✓ 小结与习题

要点一句话
总规则proxy_pass 带 URI 则替换 location 前缀，不带则透传 $uri
变量例外含变量 = 全量自定义，$args 与 $is_args 要手动拼
排障方法回显后端 + curl，直接看上游收到什么
正则限制正则 location 里 proxy_pass 不能带 URI
A 基础跑通 12.2 的回显实验，四种写法逐一验证。
B 进阶用 rewrite ^/old/(.*)$ /new/$1 break; + 无 URI proxy_pass 实现 /old/x → 上游 /new/x，对照前缀替换写法。
C 挑战实现变量化转发 proxy_pass http://b$uri$is_args$args; 并验证带参请求完整到达；再补 resolver 消除告警。
