4.1 从 URL 到文件：静态请求的一生

图 4-1 静态请求处理流程

核心公式记住：磁盘路径 = root + URI。请求 /docs/a.html、root 为 /var/www，Nginx 就去读 /var/www/docs/a.html。读不到 → 404；读不到且无权限 → 403。

4.2 最小站点配置与验证

# 1. 准备站点文件
sudo mkdir -p /var/www/mysite
echo '<!doctype html><h1>Hello Nginx</h1>' | sudo tee /var/www/mysite/index.html
# 2. /etc/nginx/conf.d/mysite.conf
server {
    listen       80;
    server_name  mysite.example.com;   # 本机练习可写 _ 或 hosts 伪域名
    root         /var/www/mysite;      # 站点根目录
    index        index.html;           # 目录默认首页
}
# 3. 检查 + 重载 + 验证
sudo nginx -t && sudo nginx -s reload
curl -I http://127.0.0.1/        # 期待 HTTP/1.1 200 OK
curl  http://127.0.0.1/          # 看到 Hello Nginx
  • root 通常写在 server 层，整个站点共用；特定目录可在 location 覆盖（第 7 章对比 alias）；
  • listen 80 不写 IP 表示监听所有网卡；
  • 生产站点目录的习惯位置：/var/www/站点名 或 /opt/app/dist，不要放用户家目录（权限与 SELinux 麻烦）。

4.3 index：目录的默认首页

当请求 URI 以 / 结尾（即请求目录而非文件）时，Nginx 按 index 列表依次找：

index index.html index.htm index.php;
# 找到第一个存在的文件并内部重定向到它；都找不到：
#   autoindex off -> 403
#   autoindex on  -> 返回目录列表
  • index 是"内部重定向"：找到 index.html 后相当于重新以 /index.html 走一遍 location 匹配——所以 location / 与 location = /index.html 的行为会互相影响；
  • index 值还可以是绝对 URI（如 index /index.php?$query_string;），这是 PHP 站点常见写法。

4.4 403 的两大来源：权限与 SELinux

403 Forbidden 是静态部署第一杀手，按此清单排查：

来源现象/日志解决
文件权限error.log: open() failed (13: Permission denied)目录需对 worker 用户（nginx）可读+可执行：chmod -R o+rX /var/www/mysite；注意每一级父目录都要 x 权限
家目录保护站点放在 /home/xxx/dist 时 403家目录常为 700，别放站点；非要放则 chmod o+x /home/xxx
SELinux 上下文RHEL 系权限明明对仍 403restorecon -Rv /var/www（上下文应为 httpd_sys_content_t）；getenforce 确认状态
目录无 index 且 autoindex off请求的是目录而非文件补 index 文件或开 autoindex（4.5）

排障捷径：error.log 最后一行几乎总能告诉你 403 的真实原因——是 open 失败还是目录索引被禁，别靠猜。

4.5 autoindex：把目录变成文件列表

server {
    listen 80;
    server_name files.example.com;
    root /data/files;

    location /download/ {
        autoindex on;              # 开目录列表
        autoindex_exact_size off;  # 人类可读大小（MB/GB）
        autoindex_localtime on;    # 显示文件本地时间
        charset utf-8;             # 中文文件名不乱码
    }

    location /download/private/ {
        deny all;                  # 敏感目录直接拒绝（第 26 章安全）
    }
}
安全提醒：autoindex 会暴露完整文件树，只适合内网/临时分发。公网开着它等于把目录结构交给扫描器，用完即关。

4.6 静态优化的三个预设

server {
    listen 80;
    server_name static.example.com;
    root /var/www/static;

    sendfile       on;    # 内核态零拷贝发送（http 层通常已开）
    tcp_nopush     on;    # 响应头与文件头包一起发
    tcp_nodelay    on;    # keepalive 下小包立即发送

    location ~* \.(css|js|png|jpg|jpeg|gif|woff2|svg|ico)$ {
        expires    7d;                   # 浏览器缓存 7 天
        add_header Cache-Control "public";
    }
}
  • sendfile：文件不经用户态复制直接由内核送出，静态站点吞吐的基石；
  • expires：带 hash 文件名的构建产物可放心长缓存；index.html 不要长缓存，否则发版后用户拿到旧入口；
  • 大文件（视频/安装包）下载再加 sendfile_max_chunk 512k; 防止单连接吃满磁盘（第 22 章）。

4.7 常见坑

  1. root 写成相对路径：相对路径相对于编译时的 prefix，十有八九不是你想要的——永远写绝对路径；
  2. 新文件浏览器不更新：先 F12 勾 Disable cache 排除浏览器缓存，再查 index.html 是否被配了长 expires；
  3. 中文文件名乱码：目录列表场景加 charset utf-8;；
  4. 大小写不一致：Linux 文件系统区分大小写，/IMG/logo.png 与 /img/logo.png 是两个路径；
  5. 404 但文件明明在：用核心公式核对 root + URI 拼出的完整路径，curl -v 看实际请求 URI。

✓ 小结与习题

要点一句话
核心公式磁盘路径 = root + URI；目录请求交给 index 解析
最小三件套listen + server_name + root，index 补默认首页
403 排查权限（逐级目录 x）→ SELinux 上下文 → 目录无 index
静态优化sendfile 提吞吐，expires 管缓存；入口页短缓存、hash 资源长缓存
A 基础按 4.2 部署你的第一个站点，用 curl 验证 200，并故意把 root 写错一个字母观察 404。
B 进阶复现 403：把站点目录 chmod 700 后访问，阅读 error.log 的报错行，再按 4.4 清单修复。
C 挑战为静态资源目录配 expires 7d，同时保证 index.html 不缓存（单独 location 处理），用 curl -I 验证两类响应头的差异。
