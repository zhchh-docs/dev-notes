  • 在 Linux 上成功安装 Nginx 并打开欢迎页；

练习环境建议：Ubuntu 22.04 / Rocky 9 虚拟机或云主机一台；本机 Docker（docker run -d -p 8080:80 nginx）也能完成本章大部分练习。

2.1 三种安装路线怎么选

方式优点缺点适合
发行版仓库自带版一条命令装好，随系统更新版本偏旧，模块固定学习、内网非关键服务
官方仓库（nginx.org 源）版本新、可选官方模块包需手动加源生产环境首选
源码编译版本/模块/路径完全自控（brotli、lua 等）升级维护成本高需要特殊模块或深度定制

原则：生产优先官方仓库，学习随便哪种，只有缺模块时才编译。Docker 方式在第 30 章专题展开。

2.2 包管理器安装（推荐）

Ubuntu / Debian：接入官方 nginx.org 仓库

# 1. 依赖与签名 key
sudo apt update && sudo apt install -y curl gnupg2 ca-certificates lsb-release
curl https://nginx.org/keys/nginx_signing.key | sudo gpg --dearmor \
  -o /usr/share/keyrings/nginx-archive-keyring.gpg

# 2. 添加仓库（mainline 分支；求稳换 stable 对应源）
echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
http://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" \
  | sudo tee /etc/apt/sources.list.d/nginx.list

# 3. 安装并验证
sudo apt update
sudo apt install -y nginx
nginx -v        # 如 nginx version: nginx/1.27.x

CentOS / RHEL / Rocky

sudo tee /etc/yum.repos.d/nginx.repo <<'EOF'
[nginx-stable]
name=nginx stable repo
baseurl=http://nginx.org/packages/centos/$releasever/$basearch/
gpgcheck=1
enabled=1
gpgkey=https://nginx.org/keys/nginx_signing.key
EOF
sudo dnf install -y nginx
sudo systemctl enable --now nginx
systemctl status nginx --no-pager

验证：浏览器访问 http://服务器IP/，看到 "Welcome to nginx!" 即成功。

打不开按顺序查三处：① systemctl status nginx 服务起没起；② curl -I http://127.0.0.1 本机通不通（区分"服务问题"与"网络问题"）；③ 云安全组 / 系统防火墙（firewall-cmd --list-all）放行 80 没有。

2.3 源码编译安装

需要第三方模块（ngx_brotli、njs、lua-nginx-module 等）或精确控制参数时才走这条路：

# 1. 编译工具链（Ubuntu 示例）
sudo apt install -y build-essential libpcre2-dev zlib1g-dev libssl-dev git

# 2. 下载解压
wget https://nginx.org/download/nginx-1.27.4.tar.gz
tar -xzf nginx-1.27.4.tar.gz && cd nginx-1.27.4

# 3. configure：指定安装路径与模块
./configure \
  --prefix=/usr/local/nginx \
  --with-http_ssl_module \
  --with-http_v2_module \
  --with-http_gzip_static_module \
  --with-http_stub_status_module \
  --with-threads

# 4. 编译安装并启动
make -j$(nproc) && sudo make install
sudo /usr/local/nginx/sbin/nginx
  • --prefix：Nginx 的"家目录"，编译安装的一切都在它下面（conf/logs/html）；
  • --with-http_stub_status_module：提供状态页，第 22 章容量观测要用；
  • --with-threads：开启线程池，大文件磁盘 I/O 不阻塞 worker（第 22 章）。

编译安装的 Nginx 不会自动注册 systemd 服务——重启服务器后不会自启。要么手写 unit 文件，要么把启动命令挂进开机脚本，新手最容易栽在这里。

2.4 目录结构逐个认识

官方仓库安装后的关键路径——这张地图全书都会反复用到：

/etc/nginx/
├── nginx.conf              # 主配置：唯一的"入口"，include 其他文件
├── mime.types              # 扩展名 -> Content-Type 映射表
├── conf.d/                 # 常放自定义站点：*.conf 会被主配置 include
├── sites-available/        # (Debian 系) 所有站点配置"仓库"
├── sites-enabled/          # (Debian 系) 软链到 available 的才生效
├── modules-enabled/        # 动态模块加载清单
└── fastcgi_params 等参数文件 # 转发 FastCGI/uwsgi 时的默认参数集
/var/log/nginx/
├── access.log              # 访问日志（第 5 章）
└── error.log               # 错误日志：排障第一现场
/usr/share/nginx/html/      # 默认站点根目录（欢迎页在这里）
/var/lib/nginx/             # 缓存等运行时数据
路径要点
nginx.conf唯一的启动入口；官方包默认只 include conf.d/*.conf，Debian 包 include sites-enabled/*
mime.types决定返回的 Content-Type；新文件类型（如 woff2）不改它，浏览器可能当乱码下载
conf.d/ vs sites-*/两种组织习惯：一个"扔文件即生效"，一个"建软链才生效"。团队统一一种即可
error.log排障时永远先看它：权限、证书、上游不通，第一现场都在这
编译安装对照：所有东西收拢在 --prefix 下——/usr/local/nginx/conf/nginx.conf、logs/、html/。两套路径别背混，用 nginx -V 一眼确认。

2.5 nginx 命令行五把刀

nginx -t              # 语法检查：改完配置必做，"test ok" 才有资格 reload
nginx -s reload       # 平滑重载：master 重读配置，老 worker 处理完存量请求再退出
nginx -s quit         # 优雅停止：等存量请求处理完
nginx -s stop         # 立即停止（相当于 kill），仅卡死时使用
nginx -V              # 版本 + 编译参数：查"有没有某模块"的第一入口
nginx -T              # 打印合并后的完整配置（include 展开后），排障神器
命令作用使用纪律
-t只检查不生效任何改动后先 -t 再 reload，形成肌肉记忆
-s reload平滑加载新配置不断连接；配置有错时旧配置继续服务，看 error.log
-s quit优雅退出发版/下线用这个，别用 stop
-T输出最终生效配置排查"我改的怎么没生效"——多半是 include 路径错了

最重要的纪律：nginx -t && nginx -s reload ——两连写进肌肉记忆，本书所有章节的配置变更都遵循它。

2.6 常见坑

  1. 80 端口被占用：装了别的服务时报 bind() to 0.0.0.0:80 failed。用 ss -ltnp | grep :80 找到占用者，停掉或改端口；
  2. 防火墙/安全组没放行：本机 curl 通、外部不通，九成是它。云主机先查安全组；
  3. SELinux 拦截（RHEL 系）：反代报 connect() failed (13: Permission denied)，先 setsebool -P httpd_can_network_connect 1；
  4. 改了文件却没生效：可能编辑的是 sites-available 忘了软链，或主配置没 include 你的目录——nginx -T 看最终合并结果；
  5. reload "不生效"：语法错误时 master 继续用旧配置，去 error.log 找报错行号，而不是服务坏了。

✓ 小结与习题

要点一句话
安装选择生产用官方仓库，缺模块才编译，学习用 Docker 也行
目录地图nginx.conf 是唯一入口；conf.d / sites-enabled 放站点；error.log 是排障第一现场
命令五把刀-t 检查、-s reload 平滑、-s quit 优雅停、-V 查模块、-T 看合并配置
黄金纪律nginx -t && nginx -s reload，永远两连
A 基础在你自己的环境完成安装并打开欢迎页；用 nginx -V 记下版本与编译参数。
B 进阶在 conf.d/ 新建 test.conf（语法下一章讲，可先复制默认配置改名），用 nginx -T 确认它被合并进来。
C 挑战故意写一行不存在的指令，分别执行 nginx -t 与 nginx -s reload，观察输出差异与 error.log，理解"reload 失败不中断服务"的设计。
