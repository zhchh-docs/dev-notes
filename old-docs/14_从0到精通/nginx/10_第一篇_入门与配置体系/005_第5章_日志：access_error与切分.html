第 5 章 日志：access/error 与切分

教科书 第 5 章 / 共 32 章 · 预计 30 分钟 · 动手章节

日志是 Nginx 的行车记录仪：access.log 记录每一次请求的事实，error.log 记录每一次失败的原因。本章教你定义字段、读懂报错、按天切分，并给出分析日志的常用命令。

◆本章目标

  • 逐字段读懂默认 log_format main 的每一列；
  • 会定义自定义 log_format，为不同 server/location 分别落日志；

  • 用 logrotate 实现按天切分 + 自动清理，避免日志写满磁盘。

5.1 access.log 逐字段拆解

log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                  '$status $body_bytes_sent "$http_referer" '
                  '"$http_user_agent" "$http_x_forwarded_for"';
access_log  /var/log/nginx/access.log  main;

一行真实日志：

203.0.113.7 - - [19/Oct/2026:10:21:33 +0800] "GET /api/user?id=1 HTTP/1.1" 200 1024 "https://example.com/home" "Mozilla/5.0" "-"
字段含义排障价值
$remote_addr直接客户端 IP（未解析代理头）有 CDN/代理时不是真实用户 IP，见第 13 章
$remote_userBasic 认证用户名，通常为 -基本不用
$time_local请求完成时间（本地时区）对齐监控时间线
$request完整请求行：方法 + URI + 协议看具体请求了什么
$status响应状态码统计 4xx/5xx 比例的第一来源
$body_bytes_sent发给客户端的字节数带宽估算用 $bytes_sent 更准（含头部）
$http_referer来源页盗链分析
$http_user_agent客户端 UA爬虫/异常流量识别
$http_x_forwarded_for上游传来的 XFF 头多层代理时追溯链路

排障时最想看却默认没有的两样东西：请求耗时与上游耗时——$request_time 与 $upstream_response_time，第 24 章的"两个时间指标"就靠它们。

5.2 自定义 log_format 与分站点日志

http {
    # 自定义格式：加入耗时与上游信息（生产推荐）
    log_format timed '$remote_addr [$time_local] "$request" $status '
                     '$body_bytes_sent rt=$request_time '
                     'urt=$upstream_response_time "$http_user_agent"';

    server {
        listen 80;
        server_name app.example.com;

        access_log /var/log/nginx/app.access.log timed;

        location /healthz {
            access_log off;          # 健康检查刷屏，直接关掉
            return 200 "ok\n";
        }

        location /api/ {
            proxy_pass http://backend;
            access_log /var/log/nginx/api.access.log timed;
        }
    }
}
  • log_format 只能放 http 层；access_log 可逐层覆盖，包括 off；
  • 高流量场景加缓冲减少磁盘 I/O：access_log path main buffer=64k flush=5s;
  • error_log 没有 off，最低只能到 emerg。

5.3 error_log：级别体系与读法

级别典型内容使用场景
debug每一步处理细节，海量只配合 error_log 调试极难复现的问题
info / notice连接建立、upstream 选择等排查负载不均时可短暂开 info
warn / error配置告警、上游超时、权限失败生产默认档位
crit / alert / emerg无法绑定端口、磁盘耗尽故障已发生

读法三步：

  1. 看最后一屏：tail -n 50 /var/log/nginx/error.log，故障时间点就在最后；
  2. 认时间戳与进程号：2026/10/19 10:21:33 [error] 1234#1234: ... 中 1234#1234 是 pid#tid，可关联 access.log 时刻；
  3. 抓关键字：Permission denied（权限）、connect() failed (111)（上游拒绝）、timed out（上游超时）、SSL_do_handshake() failed（证书链问题）。

5.4 按天切分：logrotate 实战

# /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                 # 每天切一次
    rotate 14             # 保留 14 份，自动删除更早的
    missingok
    notifempty
    compress              # 旧日志 gzip
    dateext               # 文件名带日期：access.log-20261019
    sharedscripts
    postrotate
        # 通知 nginx 重新打开日志文件（等效 kill -USR1）
        [ -f /run/nginx.pid ] && kill -USR1 $(cat /run/nginx.pid)
    endscript
}

为什么要 USR1 信号：mv 改名后，Nginx 仍持有原文件描述符，继续写进改名后的文件。USR1 让所有 worker 重新打开日志路径，新日志才落进新文件。

# 手动测试切分（强制走一遍）
sudo logrotate -f /etc/logrotate.d/nginx
ls -lh /var/log/nginx/

源码编译安装通常没有这份配置文件，必须自己创建——日志写满磁盘会让 Nginx 无法写日志甚至影响服务。

5.5 日志分析常用命令

# 请求量 Top 10 来源 IP
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head

# 状态码分布
awk '{print $9}' access.log | sort | uniq -c | sort -rn

# 5 分钟内最慢的 10 个请求（timed 格式：rt= 字段）
grep -o 'rt=[0-9.]+' access.log | sort -t= -k2 -rn | head

# 找出所有 500 错误的请求行
awk '$9 == 500' access.log | tail -20

# 某个接口的 QPS（按秒统计）
grep '/api/order' access.log | awk '{print $4}' | cut -d: -f1-4 | uniq -c
规模大了以后把日志投给 ELK/Loki/Grafana 更合适，但 awk 是"服务器上只有 shell"时的救命技能，也是看懂监控指标背后逻辑的基础。

5.6 常见坑

  1. 日志磁盘写满：不配 logrotate 是慢性自杀；监控 df -h /var/log；
  2. 切分后日志继续写进旧文件：postrotate 忘了发 USR1（5.4）；
  3. buffer 丢日志：开 buffer 后进程崩溃时缓冲区里未 flush 的日志会丢——审计场景别用 buffer；
  4. 时间差 8 小时：$time_local 是服务器本地时区，容器里默认 UTC；统一用 $time_iso8601 或对齐容器时区；
  5. 健康检查刷爆日志：负载均衡探测每秒数次，务必 access_log off。

✓ 小结与习题

要点一句话
两本账access.log 记事实，error.log 记原因，排障先看后者
自定义格式把 $request_time / $upstream_response_time 写进日志，是性能分析的前提
切分机制logrotate 改名 + USR1 信号让进程重开文件描述符
卫生习惯healthz 关 access_log，日志级别生产用 warn
A 基础为本章 5.2 的 timed 格式落地到你的练习站点，发起几个请求并逐字段解读日志。
B 进阶手动执行一次 logrotate，验证切分后新请求写进新文件（对照 inode：ls -i）。
C 挑战用 awk 统计你日志里请求量 Top 5 的 URI 与平均 $request_time，找出"最忙又最慢"的接口。
