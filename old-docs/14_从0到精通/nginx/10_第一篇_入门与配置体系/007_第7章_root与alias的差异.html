第 7 章 root 与 alias 的差异

教科书 第 7 章 / 共 32 章 · 预计 25 分钟 · 核心必学

root 与 alias 只差一个词，行为却天差地别——"alias 后面忘写斜杠"与"alias 拼进 root 语义"是真实事故榜单的常客。本章用对照表与实验一次讲清。

◆本章目标

  • 背出两条拼接公式：root = 前缀 + 整个 URI；alias = 替换 location 匹配的部分；
  • 避免 alias 末尾斜杠的两大变体坑；
  • 会在正则 location 中用捕获组配合 alias；
  • 能独立完成"应用部署在子路径 /app/ 下"的静态映射。

7.1 拼接规则：两条公式

# 写法一：root
location /images/ {
    root /data;
}
# 请求 /images/a.png  ->  实际读取  /data/images/a.png
# 规律：磁盘路径 = root + 完整 URI

# 写法二：alias
location /images/ {
    alias /data/pics/;
}
# 请求 /images/a.png  ->  实际读取  /data/pics/a.png
# 规律：磁盘路径 = alias 替换掉 location 匹配到的那段 URI
指令拼接公式心智模型
rootroot + URI（URI 原样附加）"文件的根目录"，URI 会接着往下走
aliasalias + (URI - location 前缀)"路径别名"，把 URL 前缀映射成另一个磁盘目录

一句话：root 是"接着拼"，alias 是"替换着拼"。root 可用在 server/location/http 层；alias 只能用在 location 里。

7.2 alias 的末尾斜杠坑

# 坑一：alias 有斜杠，location 前缀没有
location /images {
    alias /data/pics/;
}
# /images/a.png   -> /data/pics//a.png  双斜杠，通常能容错但别依赖
# /imagesx/a.png  -> /data/pics/x/a.png 前缀误伤后被"切"出诡异路径！

# 坑二：location 有斜杠，alias 没有
location /images/ {
    alias /data/pics;
}
# /images/a.png   -> /data/picsa.png    直接拼错，404
铁律：location 前缀与 alias 的值要么都带尾斜杠，要么都不带。团队规范建议都带。

用 curl 验证（配合 error.log 观察实际查找的路径）：

curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/images/a.png
sudo tail -1 /var/log/nginx/error.log
# open() "/data/picsa.png" failed (2: No such file or directory)

7.3 正则 location 中的 alias

正则 location 里 alias 必须使用捕获组，否则 Nginx 不知道 URI 的哪部分要映射进磁盘路径：

location ~ ^/avatars/(.+\.(?:png|jpg|webp))$ {
    alias /data/avatars/$1;      # /avatars/u/1.png -> /data/avatars/u/1.png
    expires 30d;
}
  • $1 对应捕获组内容；正则必须"锚定"住要替换的前缀；
  • 捕获组要防目录穿越：允许 ../ 是隐患。生产上更简单的做法是文件按哈希平铺，从源头杜绝 ..。

7.4 选择决策

用 root用 alias
磁盘目录结构与 URL 一致（最常见）URL 前缀与磁盘目录名不一致
server 级统一根目录 + 各 location 微调把旧路径映射到新位置做兼容
配合 try_files 的 SPA 站点（默认选择）正则捕获组映射（头像、缩略图变体）

经验法则：默认用 root，只有"路径对不上"时才引入 alias——alias 能少用就少用，它是可读性与事故率的负资产。

7.5 实战：子路径部署前端应用

需求：主站在根路径，一个独立前端应用挂在 /admin/ 下，产物在磁盘的 /var/www/admin-dist：

server {
    listen 80;
    server_name portal.example.com;

    root /var/www/portal;

    # 子路径前端：alias 指向独立构建产物
    location /admin/ {
        alias /var/www/admin-dist/;
        try_files $uri $uri/ /admin/index.html;   # SPA 兜底，注意兜底路径
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
配套改造提醒：前端构建必须同步设置 base（Vite 的 base: '/admin/'、Vue Router 的 createWebHistory('/admin/')），否则资源会以根路径引用而 404。Nginx 只负责映射，路径前缀要两边一起改。

7.6 常见坑

  1. alias 忘尾斜杠或 location 忘尾斜杠（7.2 两大变体）；
  2. alias 与 try_files 混用拼错兜底路径：兜底要写 /admin/index.html 而不是 /index.html；
  3. 正则 location 里写 root 以为会替换前缀：root 永远"接着拼"，想替换只能 alias；
  4. 嵌套 location 继承混乱：location 里不写 root 会继承 server 的 root，拼出双层路径；
  5. alias 目录权限：同样要满足第 4 章 4.4 的权限清单。
