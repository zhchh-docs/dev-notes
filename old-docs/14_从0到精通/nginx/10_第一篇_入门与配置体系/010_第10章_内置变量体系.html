◆本章目标

  • 按"请求 / 连接 / 响应 / 上游"四大类建立变量索引；
  • 熟练使用 $uri、$args、$host、$arg_xxx、$http_xxx 等高频变量；
  • 用 map 派生自定义变量替代危险的 if；
  • 理解变量的惰性求值，避免无谓的性能损耗。

10.1 变量分类总览

类别代表变量用于
请求信息$request_method / $request_uri / $uri / $args / $arg_名 / $scheme / $http_头名路由、改写、日志
连接与客户端$remote_addr / $remote_port / $host / $server_port / $binary_remote_addr限流、访问控制
响应侧$status / $body_bytes_sent / $sent_http_头名 / $request_time日志、监控
上游（反代）$upstream_addr / $upstream_response_time / $upstream_status排障、负载分析（第二篇主角）

命名规则两条：$http_头名 取请求头（User-Agent → $http_user_agent，字母转小写、中划线转下划线）；$sent_http_头名 取 Nginx 将要发送的响应头。

10.2 高频变量详解

变量值（示例）注意点
$uri/docs/a.html已归一化、不含参数、随 rewrite 改变
$request_uri/docs/a.html?x=1原始完整 URI，永不因 rewrite 改变
$args / $query_stringx=1&y=2不含 ?；改写时单独处理
$arg_xxx$arg_id → 1取单个参数；注意注入风险
$hostexample.com依次取请求行、Host 头、server_name
$http_hostexample.com:8443原样 Host 头（含端口）
$schemehttpshttp/https 判断
$request_time0.056秒，含读请求体到发完响应

$uri 与 $request_uri 的分野是本章最重要考点：rewrite 改的是 $uri，$request_uri 记录用户最初敲的什么。跳转拼 URL 用后者，磁盘定位用前者。

10.3 map：派生自定义变量

http {
    # 依据 $http_user_agent 派生 $device 变量
    map $http_user_agent $device {
        default              desktop;
        ~*mobile             mobile;      # 正则匹配 UA
        ~*bot|spider         bot;         # 爬虫
    }

    server {
        location /api/ {
            # 把复杂条件收敛成一个变量再消费
            proxy_pass http://$device_backend;   # upstream 名变量化（需 resolver）
        }
    }
}
  • map 只能放 http 层；命中规则从上到下，default 兜底；正则条目支持 ~ / ~*；
  • map 的价值：把复杂条件收敛成一个变量，配置主体保持"读起来像 English"。

10.4 典型组合用法

# 用法一：区分内外网（第 21 章限流会用到）
geo $remote_addr $is_internal {
    default         0;
    10.0.0.0/8      1;
    192.168.0.0/16  1;
}

# 用法二：按接口版本分流
map $arg_version $api_upstream {
    default   backend_v1;
    "2"       backend_v2;
}

# 用法三：日志记录命中路径辅助排障
log_format debug_loc '$uri -> $document_root [$status] $request_time';

变量组合的威力在于声明式：条件写在 map/geo 里集中审阅，处理逻辑只消费结果变量——这是大型 nginx.conf 保持可读的关键。

10.5 惰性求值与性能

  • 大多数内置变量用到才算（lazy）：没出现在配置里的变量几乎零成本；
  • 例外警告：$request_body 每次求值要读完整请求体到内存——日志里加它等于全站强制缓冲请求体；
  • $http_* / $arg_* 逐请求解析，出现在 map/log_format 高频路径时注意匹配顺序（常用条目放前面）。

10.6 常见坑

  1. $uri 与 $request_uri 用反：跳转拼了 $uri 丢参数；磁盘路径用了 $request_uri 引入注入风险；
  2. $arg_* 直接拼进日志/上游：参数值未编码，有日志注入与上游注入风险，透传前要过滤；
  3. map 正则顺序不当：宽泛条目写在前面截胡具体条目；
  4. 变量用在静态指令：root/alias 支持变量但会走"每请求解析"，非必要不用；
  5. $request_body 默认为空：需配合 proxy_pass 或请求体缓冲场景才有值，日志里一直是 - 时先理解机制。

要点一句话

map 价值条件收敛为变量，替代危险的 if，配置声明式
