<section id="sec1" class="card">
  <h2><span class="num">◆</span>本章目标</h2>
  <ul>
    <li>背出 rewrite 四个 flag（last / break / redirect / permanent）的行为差异；</li>
    <li>理解 rewrite 在 server 与 location 两个阶段的执行时机与 10 次循环上限；</li>
    <li>独立完成 http→https、www 统一、旧路径兼容三个高频场景；</li>
    <li>明确什么时候该用 <code>return</code> 而不是 <code>rewrite</code>。</li>
  </ul>
</section>

<section id="sec2" class="card">
  <h2><span class="num">9.1</span> 语法与四个 flag</h2>
  <pre class="code" data-lang="nginx"><code>rewrite regex replacement [flag];</code></pre>
  <table>
    <colgroup><col style="width:18%"><col style="width:44%"><col style="width:38%"></colgroup>
    <thead><tr><th>flag</th><th>行为</th><th>典型场景</th></tr></thead>
    <tbody>
      <tr><td><code>last</code></td><td>停止当前 location 的后续指令，用新 URI <strong>重新走一遍 location 匹配</strong></td><td>改写后要换处理逻辑（最常用）</td></tr>
      <tr><td><code>break</code></td><td>停止 rewrite 指令集，<strong>留在当前 location</strong> 继续处理</td><td>改写后仍在原地处理（如映射磁盘路径）</td></tr>
      <tr><td><code>redirect</code></td><td>返回 302 临时重定向</td><td>临时跳转</td></tr>
      <tr><td><code>permanent</code></td><td>返回 301 永久重定向</td><td>域名迁移、协议统一</td></tr>
    </tbody>
  </table>
  <p>关键区分：<strong>last/break 是内部改写</strong>（用户地址栏不变，服务端换路径处理），<strong>redirect/permanent 是外部跳转</strong>（地址栏真的变，多一次往返）。</p>
</section>

<section id="sec3" class="card">
  <h2><span class="num">9.2</span> 执行阶段与循环机制</h2>
  <ol>
    <li><strong>server 阶段</strong>：请求进入 server 后、匹配 location 之前执行 server 层的 rewrite；</li>
    <li><strong>location 阶段</strong>：命中 location 后执行其中的 rewrite，flag 为 last 时重新走 location 匹配；</li>
    <li><strong>循环上限</strong>：内部重定向累计 10 次仍未终结 → 返回 500（error.log 关键字 <code>rewrite or internal redirection cycle</code>）。</li>
  </ol>
  <pre class="code" data-lang="nginx"><code># 经典循环事故：互相改写踢皮球
location /old/ { rewrite ^/old/(.*)$ /new/$1 last; }
location /new/ { rewrite ^/new/(.*)$ /old/$1 last; }   # 10 次后 500</code></pre>
  <p>排障手段：临时把 rewrite 换成 <code>return 200 "uri=$uri";</code> 观察实际 URI，或把 error_log 开到 notice 看内部重定向轨迹。</p>
</section>

<section id="sec4" class="card">
  <h2><span class="num">9.3</span> 三个经典场景</h2>
  <pre class="code" data-lang="nginx"><code># 场景一：HTTP 全部跳 HTTPS（第 18 章会用 308/497 精化）
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}

# 场景二：www 统一到裸域
server {
    listen 443 ssl;
    server_name www.example.com;
    return 301 https://example.com$request_uri;
}

# 场景三：旧路径兼容（内部改写，不跳转）
server {
    location / {
        rewrite ^/product/(\d+)$ /items?id=$1 last;
    }
    location /items {
        proxy_pass http://backend;
    }
}</code></pre>
  <ul>
    <li>跳转场景永远把 <code>$request_uri</code>（含查询串的原始 URI）拼回去，丢参数是常见事故；</li>
    <li>内部改写用 <code>$1</code> 捕获组；replacement 以 <code>?</code> 结尾可丢弃原查询串。</li>
  </ul>
</section>

<section id="sec5" class="card">
  <h2><span class="num">9.4</span> return 与 rewrite 的分界线</h2>
  <table>
    <colgroup><col style="width:50%"><col style="width:50%"></colgroup>
    <thead><tr><th>用 return</th><th>用 rewrite</th></tr></thead>
    <tbody>
      <tr><td>整体跳转（301/302/307/308）</td><td>需要正则捕获重组 URI</td></tr>
      <tr><td>直接给响应（文本/状态码）</td><td>内部路径映射且要重新匹配 location</td></tr>
      <tr><td>域名统一、协议统一（无重组逻辑）</td><td>旧 URL 结构到新结构的批量转换</td></tr>
    </tbody>
  </table>
  <p class="key-sentence">性能与可读性铁律：<strong>能用 return 就不用 rewrite</strong>。return 一条指令终结请求，rewrite 要走正则引擎并可能触发重新匹配。</p>
</section>

<section id="sec6" class="card">
  <h2><span class="num">9.5</span> if 的危险性</h2>
  <p>社区名言 "if is evil" 并非夸张——<code>if</code> 在 location 内与部分指令组合会产生反直觉行为：</p>
  <pre class="code" data-lang="nginx"><code># 安全用法：if 里只写 return 或 rewrite ... last
location /download/ {
    if ($arg_debug) { return 200 "debug\n"; }
    try_files $uri =404;
}

# 危险用法（勿模仿）：if 内配 proxy_pass / root
location / {
    if ($host = old.example.com) {
        proxy_pass http://legacy;   # 行为异常的著名温床
    }
}</code></pre>
  <p>纪律：<code>if (...)</code> 里只允许 <code>return</code> 或 <code>rewrite ... last</code>；其它判断需求改用 <code>map</code>（第 10 章）。</p>
</section>

<section id="sec7" class="card">
  <h2><span class="num">9.6</span> 常见坑</h2>
  <ol>
    <li><strong>跳转丢参数</strong>：<code>return 301 https://example.com;</code> 把路径和查询串全丢了——要拼 <code>$request_uri</code>；</li>
    <li><strong>replacement 里的查询串</strong>：新 URI 带 <code>?</code> 时原查询串被丢弃，想保留要显式拼接；</li>
    <li><strong>正则小括号没转义</strong>：URI 里的字面量 <code>(</code> 要写成 <code>\(</code>；</li>
    <li><strong>last 与 break 选错</strong>：映射磁盘路径用 break，换处理逻辑用 last；</li>
    <li><strong>循环 500</strong>：互相改写或改写到自己，看 error.log 的 cycle 关键字。</li>
  </ol>
</section>
