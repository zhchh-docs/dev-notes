<section id="sec1" class="card">
  <h2><span class="num">◆</span>本章目标</h2>
  <ul>
    <li>逐字段读懂默认 <code>log_format main</code> 的每一列；</li>
    <li>会定义自定义 <code>log_format</code>，为不同 server/location 分别落日志；</li>
    <li>掌握 error_log 的八个级别，遇到故障知道先开哪一级；</li>
    <li>用 logrotate 实现<strong>按天切分 + 自动清理</strong>，避免日志写满磁盘。</li>
  </ul>

<section id="sec2" class="card">
  <h2><span class="num">5.1</span> access.log 逐字段拆解</h2>
  <pre class="code" data-lang="nginx"><code>log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                  '$status $body_bytes_sent "$http_referer" '
                  '"$http_user_agent" "$http_x_forwarded_for"';
access_log  /var/log/nginx/access.log  main;</code></pre>
  <p>一行真实日志：</p>
  <pre class="code" data-lang="text"><code>203.0.113.7 - - [19/Oct/2026:10:21:33 +0800] "GET /api/user?id=1 HTTP/1.1" 200 1024 "https://example.com/home" "Mozilla/5.0" "-"</code></pre>
  <table>
    <colgroup><col style="width:26%"><col style="width:40%"><col style="width:34%"></colgroup>
    <thead><tr><th>字段</th><th>含义</th><th>排障价值</th></tr></thead>
    <tbody>
      <tr><td><code>$remote_addr</code></td><td>直接客户端 IP（未解析代理头）</td><td>有 CDN/代理时不是真实用户 IP，见第 13 章</td></tr>
      <tr><td><code>$remote_user</code></td><td>Basic 认证用户名，通常为 -</td><td>基本不用</td></tr>
      <tr><td><code>$time_local</code></td><td>请求完成时间（本地时区）</td><td>对齐监控时间线</td></tr>
      <tr><td><code>$request</code></td><td>完整请求行：方法 + URI + 协议</td><td>看具体请求了什么</td></tr>
      <tr><td><code>$status</code></td><td>响应状态码</td><td>统计 4xx/5xx 比例的第一来源</td></tr>
      <tr><td><code>$body_bytes_sent</code></td><td>发给客户端的字节数</td><td>带宽估算用 <code>$bytes_sent</code> 更准（含头部）</td></tr>
      <tr><td><code>$http_referer</code></td><td>来源页</td><td>盗链分析</td></tr>
      <tr><td><code>$http_user_agent</code></td><td>客户端 UA</td><td>爬虫/异常流量识别</td></tr>
      <tr><td><code>$http_x_forwarded_for</code></td><td>上游传来的 XFF 头</td><td>多层代理时追溯链路</td></tr>
    </tbody>
  </table>
  <p class="key-sentence">排障时最想看却默认没有的两样东西：<strong>请求耗时</strong>与<strong>上游耗时</strong>——<code>$request_time</code> 与 <code>$upstream_response_time</code>，第 24 章的"两个时间指标"就靠它们。</p>
</section>

<section id="sec3" class="card">
  <h2><span class="num">5.2</span> 自定义 log_format 与分站点日志</h2>
  <pre class="code" data-lang="nginx"><code>http {
    # 自定义格式：加入耗时与上游信息（生产推荐）
    log_format timed '$remote_addr [$time_local] "$request" $status '
                     '$body_bytes_sent rt=$request_time '
                     'urt=$upstream_response_time "$http_user_agent"';

    server {
        listen 80;
        server_name app.example.com;

        access_log /var/log/nginx/app.access.log timed;

        location /healthz {
            access_log off;          # 健康检查刷屏，直接关掉
            return 200 "ok\n";
        }

        location /api/ {
            proxy_pass http://backend;
            access_log /var/log/nginx/api.access.log timed;
        }
    }
}</code></pre>
  <ul>
    <li><code>log_format</code> 只能放 http 层；<code>access_log</code> 可逐层覆盖，包括 <code>off</code>；</li>
    <li>高流量场景加缓冲减少磁盘 I/O：<code>access_log path main buffer=64k flush=5s;</code></li>
    <li><code>error_log</code> 没有 off，最低只能到 <code>emerg</code>。</li>
  </ul>
</section>

<section id="sec4" class="card">
  <h2><span class="num">5.3</span> error_log：级别体系与读法</h2>
  <table>
    <colgroup><col style="width:18%"><col style="width:42%"><col style="width:40%"></colgroup>
    <thead><tr><th>级别</th><th>典型内容</th><th>使用场景</th></tr></thead>
    <tbody>
      <tr><td>debug</td><td>每一步处理细节，海量</td><td>只配合 error_log 调试极难复现的问题</td></tr>
      <tr><td>info / notice</td><td>连接建立、upstream 选择等</td><td>排查负载不均时可短暂开 info</td></tr>
      <tr><td><strong>warn / error</strong></td><td>配置告警、上游超时、权限失败</td><td><strong>生产默认档位</strong></td></tr>
      <tr><td>crit / alert / emerg</td><td>无法绑定端口、磁盘耗尽</td><td>故障已发生</td></tr>
    </tbody>
  </table>
  <p>读法三步：</p>
  <ol>
    <li><strong>看最后一屏</strong>：<code>tail -n 50 /var/log/nginx/error.log</code>，故障时间点就在最后；</li>
    <li><strong>认时间戳与进程号</strong>：<code>2026/10/19 10:21:33 [error] 1234#1234: ...</code> 中 1234#1234 是 pid#tid，可关联 access.log 时刻；</li>
    <li><strong>抓关键字</strong>：<code>Permission denied</code>（权限）、<code>connect() failed (111)</code>（上游拒绝）、<code>timed out</code>（上游超时）、<code>SSL_do_handshake() failed</code>（证书链问题）。</li>
  </ol>
</section>

<section id="sec5" class="card">
  <h2><span class="num">5.4</span> 按天切分：logrotate 实战</h2>
  <pre class="code" data-lang="ini"><code># /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                 # 每天切一次
    rotate 14             # 保留 14 份，自动删除更早的
    missingok
    notifempty
    compress              # 旧日志 gzip
    dateext               # 文件名带日期：access.log-20261019
    sharedscripts
    postrotate
        # 通知 nginx 重新打开日志文件（等效 kill -USR1）
        [ -f /run/nginx.pid ] &amp;&amp; kill -USR1 $(cat /run/nginx.pid)
    endscript
}</code></pre>
  <p><strong>为什么要 USR1 信号</strong>：mv 改名后，Nginx 仍持有原文件描述符，继续写进改名后的文件。USR1 让所有 worker 重新打开日志路径，新日志才落进新文件。</p>
  <pre class="code" data-lang="bash"><code># 手动测试切分（强制走一遍）
sudo logrotate -f /etc/logrotate.d/nginx
ls -lh /var/log/nginx/</code></pre>
  <p>源码编译安装通常没有这份配置文件，<strong>必须自己创建</strong>——日志写满磁盘会让 Nginx 无法写日志甚至影响服务。</p>
</section>

<section id="sec6" class="card">
  <h2><span class="num">5.5</span> 日志分析常用命令</h2>
  <pre class="code" data-lang="bash"><code># 请求量 Top 10 来源 IP
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head

# 状态码分布
awk '{print $9}' access.log | sort | uniq -c | sort -rn

# 5 分钟内最慢的 10 个请求（timed 格式：rt= 字段）
grep -o 'rt=[0-9.]+' access.log | sort -t= -k2 -rn | head

# 找出所有 500 错误的请求行
awk '$9 == 500' access.log | tail -20

# 某个接口的 QPS（按秒统计）
grep '/api/order' access.log | awk '{print $4}' | cut -d: -f1-4 | uniq -c</code></pre>
  <div class="note">规模大了以后把日志投给 ELK/Loki/Grafana 更合适，但 awk 是"服务器上只有 shell"时的救命技能，也是看懂监控指标背后逻辑的基础。</div>
</section>

<section id="sec7" class="card">
  <h2><span class="num">5.6</span> 常见坑</h2>
  <ol>
    <li><strong>日志磁盘写满</strong>：不配 logrotate 是慢性自杀；监控 <code>df -h /var/log</code>；</li>
    <li><strong>切分后日志继续写进旧文件</strong>：postrotate 忘了发 USR1（5.4）；</li>
    <li><strong>buffer 丢日志</strong>：开 buffer 后进程崩溃时缓冲区里未 flush 的日志会丢——审计场景别用 buffer；</li>
    <li><strong>时间差 8 小时</strong>：$time_local 是服务器本地时区，容器里默认 UTC；统一用 <code>$time_iso8601</code> 或对齐容器时区；</li>
    <li><strong>健康检查刷爆日志</strong>：负载均衡探测每秒数次，务必 <code>access_log off</code>。</li>
  </ol>
</section>
