<section id="sec2" class="card">
  <h2><span class="num">6.1</span> location 的五种写法</h2>
  <table>
    <colgroup><col style="width:26%"><col style="width:40%"><col style="width:34%"></colgroup>
    <thead><tr><th>写法</th><th>含义</th><th>典型用途</th></tr></thead>
    <tbody>
      <tr><td><code>location = /path</code></td><td>精确匹配，URI 完全相等</td><td>首页、健康检查，最高优先级</td></tr>
      <tr><td><code>location ^~ /static/</code></td><td>前缀匹配，命中后<strong>跳过正则检查</strong></td><td>静态资源目录，防正则劫持</td></tr>
      <tr><td><code>location ~ \.php$</code></td><td>区分大小写的正则</td><td>按扩展名分发</td></tr>
      <tr><td><code>location ~* \.(png|jpg)$</code></td><td>不区分大小写的正则</td><td>图片扩展名的事实标准写法</td></tr>
      <tr><td><code>location /path</code></td><td>普通前缀匹配</td><td>目录级分发，如 <code>/api/</code></td></tr>
    </tbody>
  </table>
  <p>易混点：<code>/path</code> 也命中 <code>/pathology</code>，<code>/path/</code> 只命中以其为前缀的路径；正则用 PCRE，支持捕获组 <code>$1 $2</code>。</p>
</section>

<section id="sec4" class="card">
  <h2><span class="num">6.3</span> 对照实验：亲眼看优先级</h2>
  <pre class="code" data-lang="nginx"><code>server {
    listen 80;
    server_name loc.example.com;

    location = /       { return 200 "exact /\n"; }          # ① 精确
    location /static/  { return 200 "prefix /static/\n"; }  # ④ 普通前缀
    location ^~ /img/  { return 200 "caret /img/\n"; }      # ② ^~ 前缀
    location ~ \.png$  { return 200 "regex png\n"; }        # ③ 正则
    location ~* \.(jpg|jpeg)$ { return 200 "regex jpg\n"; } # ③ 正则
}</code></pre>
  <pre class="code" data-lang="bash"><code>curl http://127.0.0.1/              # exact /
curl http://127.0.0.1/img/a.png     # caret /img/   ——^~ 拦下了正则
curl http://127.0.0.1/logo.PNG      # 404：~ 区分大小写，.PNG 不匹配 \.png$</code></pre>
  <p>再看关键请求 <code>/static/a.png</code>：它同时命中普通前缀 <code>/static/</code> 和正则 <code>\.png$</code>——前缀没加 <code>^~</code>，正则优先，返回 <code>regex png</code>。想让静态目录说了算，必须写 <code>^~</code>。</p>
  <p class="pit-sentence"><code>^~</code> 的意义就在这里：<strong>把某个前缀目录从正则手中"抢"回来</strong>。纯静态目录建议一律 ^~。</p>
</section>

<section id="sec5" class="card">
  <h2><span class="num">6.4</span> 嵌套 location</h2>
  <pre class="code" data-lang="nginx"><code>location /api/ {
    proxy_set_header Host $host;          # 外层公共配置

    location /api/public/ {
        proxy_pass http://public_svc;     # 内层继承外层的 proxy_set_header
    }

    location /api/admin/ {
        allow 10.0.0.0/8;                 # 内层叠加访问控制
        deny  all;
        proxy_pass http://admin_svc;
    }
}</code></pre>
  <ul>
    <li>嵌套只允许"前缀套前缀"，<strong>正则 location 内不能再嵌</strong>；</li>
    <li>普通指令可继承；数组型指令（add_header 等）嵌套即整体替换（3.6 节的坑同样适用）；</li>
    <li>嵌套两层封顶，再深可读性骤降。</li>
  </ul>
</section>
