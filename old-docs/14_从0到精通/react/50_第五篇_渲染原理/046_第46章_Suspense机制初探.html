第 46 章 Suspense 机制初探

教科书 第 46 章 / 共 64 章 · 预计 50 分钟 · 等待与 fallback

Suspense 让组件在等待资源（代码分包、数据、未来更多资源类型）期间，由就近的边界展示 fallback，而不是先写条件判断再手工切换加载态。本章建立机制心智：边界如何就近捕获、fallback 替换什么范围、Suspense 与错误边界如何分工，以及代码拆分与数据读取的基本写法。

◆本章目标

  • 理解 Suspense 的核心行为：组件等待资源时挂起，由最近的边界显示 fallback，资源就绪后替换为真实内容；
  • 掌握就近边界原则与嵌套边界的替换范围；

  • 识别 fallback 闪烁、边界过粗、忘记嵌套等常见问题。

46.1 回顾：路由懒加载中的 Suspense

第 33 章路由懒加载已经用过 Suspense：路由组件通过 React.lazy 动态导入，代码尚未下载完成时，fallback 显示加载提示。本章从使用层面深入到机制层面：Suspense 到底捕获了什么、fallback 替换的是哪一段界面、为什么可以嵌套多层。

import { lazy, Suspense } from 'react';
import { createBrowserRouter, RouterProvider } from 'react-router-dom';

const HomePage = lazy(() => import('../pages/HomePage'));
const AboutPage = lazy(() => import('../pages/AboutPage'));

const router = createBrowserRouter([
  {
    path: '/',
    element: (
      <Suspense fallback={<PageLoading />}>
        <HomePage />
      </Suspense>
    ),
  },
  {
    path: '/about',
    element: (
      <Suspense fallback={<PageLoading />}>
        <AboutPage />
      </Suspense>
    ),
  },
]);

export default function App() {
  return <RouterProvider router={router} />;
}
路由层面的完整配置规则见第 33 章；本节代码用于衔接上下文，重点观察 lazy 组件与 Suspense 的配对方式。

46.2 什么是 Suspense：等待时挂起、就近展示 fallback

当组件渲染所需的资源还没准备好（代码未下载、数据未返回），组件会在渲染期间把一个"等待中的 Promise"抛给 React；React 沿 Fiber 树向上查找最近的 <Suspense> 边界，先把该边界内等待中的部分替换为 fallback；等 Promise 完成后，再重新渲染并把真实内容替换回去。

图 46-1 Suspense 边界只替换内部等待中的子树，边界外内容保持不动

import { lazy, Suspense } from 'react';

const HeavyChart = lazy(() => import('./HeavyChart'));

function Dashboard() {
  return (
    <section>
      <h2>仪表盘</h2>
      <Suspense fallback={<div className="skeleton">图表加载中…</div>}>
        <HeavyChart />
      </Suspense>
    </section>
  );
}
边界提醒使用 lazy 的组件必须被 Suspense 包裹：模块下载期间找不到可显示的 fallback 时 React 会直接报错。路由级配置（46.1 节）通常在路由容器处统一设置一层边界兜底。
Suspense 不是一个"加载状态变量"的替代品；它把"等待中 → 内容就绪"的切换规则交给框架，组件代码只描述两种界面中的哪一种出现。

46.3 就近边界与嵌套规则

挂起状态沿树向上冒泡，直到遇到最近的 Suspense 边界才被捕获；边界可以嵌套：内层边界先捕获自己子树的等待，外层边界负责内层都挂起时的兜底。fallback 替换的是捕获它的那个边界内部等待中的子树，边界外的内容不参与替换。

import { lazy, Suspense } from 'react';

const Profile = lazy(() => import('./Profile'));
const Activity = lazy(() => import('./Activity'));

function UserPage() {
  return (
    <Suspense fallback={<PageFallback />}>
      <Header />
      <Suspense fallback={<PanelSkeleton />}>
        <Profile />
      </Suspense>
      <Suspense fallback={<PanelSkeleton />}>
        <Activity />
      </Suspense>
    </Suspense>
  );
}
规则说明
就近捕获子组件挂起时，向上找到第一个 Suspense 边界由它显示 fallback
替换范围只替换该边界内等待中的子树；同级其他边界各自独立显示 fallback
嵌套兜底内层边界存在时由内层处理；内层边界缺失，等待继续上抛到外层
独立等待多个内层边界分别等待各自资源，互不阻塞，各自替换各自区域
边界的位置决定 fallback 的覆盖范围：就近捕获、只替换等待子树。把常变的独立面板各自包一层，既能避免整页骨架屏，也让各面板互不等待。
粒度提示边界包得越粗，等待时被 fallback 替换的界面范围越大；包得越细，骨架屏覆盖的区域越小、体验越平滑。常见做法是为独立面板各设一层 Suspense。

46.4 三类可等待资源

Suspense 机制本身与资源类型解耦；当前生产中最成熟的两类是代码拆分与数据读取，第三类资源等待仍处于演进中，按官方文档口径了解即可。

资源类型机制与写法成熟度与备注
代码拆分React.lazy(() => import('./Comp')) 返回的组件在模块下载期间挂起，由 Suspense 显示 fallback生产可用，第 51 章代码分割专题展开
数据读取组件内通过 use 读取 Promise；Promise 完成前组件挂起，由边界展示 fallback。数据获取方式常与框架或数据层（如 TanStack Query 的集成方案）配合React 18/19 机制支持；业务中按所用数据层文档接入
其他资源等待图片、样式表等资源的 Suspense 等待属于实验性 / 演进方向不作为本章生产写法依据，关注官方文档更新
 
import { Suspense, use } from 'react';

function UserProfile({ userId }) {
  // use 接收一个 Promise：完成前组件挂起，交给 Suspense 显示 fallback
  const user = use(fetchUser(userId));
  return (
    <div>
      <h3>{user.name}</h3>
      <p>{user.bio}</p>
    </div>
  );
}

export default function ProfilePage({ userId }) {
  return (
    <Suspense fallback={<div>用户资料加载中…</div>}>
      <UserProfile userId={userId} />
    </Suspense>
  );
}
口径边界use 可在渲染期间读取 Promise 或 Context；数据请求的发起位置、缓存、去重、错误回退应由数据层统一管理，不要在组件里手写未缓存的 Promise 反复挂载。本章只建立"等待可被 Suspense 捕获"的机制心智。

46.5 Suspense 与错误边界的分工

等待失败与资源报错是两类不同状态：Suspense 只负责"还没准备好"；Promise 被拒绝、组件渲染抛错由错误边界（Error Boundary，第 37 章）捕获并展示降级 UI。两者可以在同一区域上下叠放，分别覆盖两类异常。

判断一个状态该归谁管，先看资源是"还没来"还是"来了但错了"：前者由 Suspense 显示加载占位，后者由错误边界显示降级界面；两类边界可以上下嵌套、互不替代。
对照项Suspense错误边界（Error Boundary）
处理状态资源尚未就绪（等待中）资源失败或组件渲染抛错（错误态）
触发条件渲染期间遇到挂起的 Promise子组件渲染、生命周期或构造函数抛出错误
展示内容fallback 加载态 / 骨架屏错误提示、重试按钮、降级界面
恢复方式Promise 完成后自动替换为真实内容通常需要用户重试或刷新触发重新渲染
 
import { Suspense, lazy } from 'react';
import ErrorBoundary from './ErrorBoundary';

const Comments = lazy(() => import('./Comments'));

function Article() {
  return (
    <ErrorBoundary fallback={<CommentError />}>
      <Suspense fallback={<CommentSkeleton />}>
        <Comments />
      </Suspense>
    </ErrorBoundary>
  );
}

错误边界本身是类组件（含 getDerivedStateFromError 与 componentDidCatch），具体实现与边界位置原则见第 37 章。

46.6 行为表现与常见坑

图 46-2 组件在已就绪、等待中、报错三种状态下分别由谁接管界面

常见坑原因与处理
画面反复闪烁骨架屏资源很快就绪却也先显示 fallback；可把边界放在更靠后的层级，或配合 Transition 避免短等待切换（第 45 章）
等待时整页被骨架屏覆盖边界包得太粗；为独立面板增加内层 Suspense，缩小替换范围
错误被吞掉、只看到一直转圈缺少错误边界；Promise 拒绝无人捕获，界面停在 fallback 状态
组件内手写未缓存 Promise，每次挂载重新请求等待期间重复挂载导致重复发起；应由数据层统一缓存与去重
把普通条件加载态写成 SuspenseSuspense 面向"挂起 Promise"的机制；普通状态判断仍用条件渲染表达
易错点Suspense 不会自己发起请求或下载模块：lazy 的动态 import、数据层的 Promise 才是等待来源。Suspense 只负责"捕获挂起并显示占位"，要把触发等待与显示等待这两件事分开理解。

✓ 本章小结

要点一句话
Suspense 行为组件等待资源时挂起，最近边界显示 fallback，就绪后替换为真实内容
就近边界等待沿树向上冒泡，由最近边界捕获；替换范围仅限该边界内等待子树
嵌套规则内层边界独立处理各自子树，外层兜底；粒度越细，骨架覆盖范围越小
代码拆分React.lazy 动态导入组件，下载期间由 Suspense 兜底
数据等待use 读取 Promise，完成前挂起；缓存与去重由数据层负责
与错误边界分工Suspense 管等待中，Error Boundary 管报错，两者叠放覆盖两类异常
常见坑骨架闪烁、边界过粗、缺错误边界、Promise 重复发起
