41.1 渲染即调用组件函数

函数组件本身就是一个普通 JavaScript 函数：React 在 render 阶段需要这棵界面时调用它，传入本次的 props，函数返回一段 JSX 对应的元素描述树，React 再拿这棵树去和旧树协调。

图 41-1 render 阶段调用组件函数：输入 props/state/context，输出元素描述树

// 组件函数 = 输入 props，返回元素描述
function Greeting({ name, theme }) {
  const [visible, setVisible] = useState(true);
  // 函数体里的计算与条件分支，都只是在描述"这一次渲染"的输出
  if (!visible) return null;
  return (
    <div className={theme}>
      <p>你好，{name}</p>
      <button onClick={() => setVisible(false)}>收起</button>
    </div>
  );
}
对照项类组件（历史写法）函数组件（现行写法）
产出界面的方式定义 render() 方法返回元素树执行函数体，return 元素树
状态保存位置实例上的 this.stateFiber 上的 Hooks 队列记录
this 绑定需要维护 this，事件回调常需绑定没有 this，闭包直接捕获当前值
副作用位置生命周期方法分散在多个钩子中useEffect 等 Hooks 集中在函数体内

41.2 props、state、context 的取值来源

组件函数体运行时，读到的三类值都来自 React 在 render 阶段为本次渲染准备好的记录，而不是组件实例上"实时"可变的属性：

本次渲染读到的 props、state、context 都是React 提前准备好的只读快照：函数体运行期间它们不会随事件回调里的 setState 改变；组件不需要、也不应该去"实时读取"某个可变的实例属性。
  • props：父组件本次渲染传入的值，由协调阶段写入对应 Fiber 的待处理属性；
  • state：本次渲染对应的 Hooks 队列里保存的值；之前的更新队列已经在 render 开始前合并出本次快照；
  • context：沿当前 Fiber 树向上找到最近匹配的 Provider，读取其本次提供的值。
function UserCard({ userId }) {
  // state 来自 Hooks 队列本次快照；context 来自最近的 Provider
  const [likes, setLikes] = useState(0);
  const { theme } = useContext(ThemeContext);

  // props.userId 是父组件本次传入的值
  return (
    <section className={theme}>
      <h3>用户 {userId} · 点赞 {likes}</h3>
    </section>
  );
}
这三类值在本次函数执行期间是只读快照：事件回调里调用 setState 并不会立刻改掉本次执行读到的值，而是登记一次新的更新，等待下一轮渲染。第 41.5 节把这一点展开。
理解"快照"是理解 React 事件回调与闭包行为的钥匙：本次渲染全程使用同一份输入，函数返回的元素树也由这份快照计算得出；下一次渲染才会读到合并后的新值。

41.3 Hooks 队列与调用顺序

组件函数里没有实例、没有 this，React 靠 Fiber 上的一条 Hooks 队列记录每个 Hook 对应的状态：第一次渲染时按调用顺序依次创建；之后每次渲染，React 从队列头部开始，按同样的调用顺序依次取出上一次的记录，与本次调用配对。

图 41-2 Hooks 队列按调用顺序配对，位置即身份

// 概念化：Fiber 上的 Hooks 队列只是一条顺序链表（教学示意）
fiber.hooks = {
  memoizedState: null,   // 当前 Hook 节点
  next: null,            // 下一个 Hook 节点
};

// 渲染时 React 内部概念化流程（非源码）：
// 1. 从头指针开始遍历；
// 2. 每调用一个 Hook，把上一次记录取出配对，再把指针推进到 next；
// 3. 函数返回时，队列尾节点即为本次渲染的最终状态。
原理印证条件调用 Hook 之所以报错或串状态，不是 React"规定了一个死板语法"，而是队列配对依赖顺序：少调用一次，后续所有 Hook 都会读到上一位的记录，状态张冠李戴。
易错点提前 return null 写在 Hooks 调用之前，与条件调用 Hook 是同一类错误：本次渲染少走了几个 Hook 调用，队列节点就会与本次调用错位。Hooks 必须位于组件函数顶层、无条件按固定顺序执行。

41.4 渲染必须纯净：为什么能重放

render 阶段可能被暂停、被丢弃、在 StrictMode 下被重复执行（第 19 章）。要让这种重复执行安全，组件函数必须是纯函数：相同的 props 与 state 输入，返回相同的元素树，执行期间不产生副作用。

渲染期间允许渲染期间禁止
读取 props、state、context 快照并做计算直接修改已有的 props 或 state 对象
调用 Hooks、声明事件回调与 JSX修改外部可变变量、计数器、全局对象
根据条件返回不同元素树或 null发起网络请求、订阅、直接操作真实 DOM
调用纯函数工具方法处理数据把渲染结果写入文件、缓存或外部存储
 
// ✗ 渲染期产生副作用：重复执行时外部计数被多次累加
let renderCount = 0;
function Counter() {
  renderCount += 1;                 // 禁止：修改外部可变值
  document.title = `第 ${renderCount} 次`;  // 禁止：直接操作外部系统
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}

// ✓ 副作用移到事件处理或 useEffect 中（第 10 章心智模型）
function Counter() {
  const [n, setN] = useState(0);
  useEffect(() => { document.title = `当前计数 ${n}`; }, [n]);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}
常见隐患从模块顶层导入的可变对象、单例缓存、浏览器全局计数，在渲染期被读取或改写同样属于不纯：StrictMode 双调用会让这类副作用重复发生。需要共享的可变状态应通过外部系统订阅（useSyncExternalStore，第 19 章）或 useRef 在受控方式下访问。
纯净性是 Fiber 可中断、可重放、可丢弃的前提条件：正因为渲染函数不改动外部世界，重复执行两遍得到相同结果才不会留下脏状态。

StrictMode 在开发环境下故意把组件函数调用两次，就是为了尽早暴露"渲染不纯"的问题；生产环境不会双调用（详见第 19 章）。

41.5 每次渲染都是一份独立快照

组件函数每被调用一次，函数体内的局部变量、事件回调、闭包都属于那一次渲染。本次渲染读到的 state、props 值不会因为后续 setState 而改变——事件回调捕获的是"渲染那一刻"的快照。

function SnapshotDemo() {
  const [n, setN] = useState(0);

  function handleClick() {
    setN(n + 1);   // 登记新更新；本次函数执行时读到的 n 不会变
    setTimeout(() => {
      // 这里闭包捕获的是本次渲染的 n，而不是更新后的最新值
      console.log('延迟看到的 n：', n);
    }, 1000);
  }

  return (
    <div>
      <p>当前 {n}</p>
      <button onClick={handleClick}>加一</button>
    </div>
  );
}
概念本次渲染快照下一次渲染
state 值本次函数执行全程读到同一个值重新调用函数，读取合并后的新值
事件回调闭包捕获本次的 props 与 state新渲染产生新回调，捕获新的快照
JSX 描述基于本次快照计算出的元素树基于新快照重新计算元素树，交协调阶段比较
易错点"连续点击按钮，回调里 n 怎么还是旧值"——不是闭包失效，而是每次渲染都有自己的快照。需要基于前一次状态计算时，使用函数式更新 setN(prev => prev + 1)（第 7 章）。

41.6 从函数返回到 Fiber 产出

把本章串回第 39、40 章的结构：调度器在时间片内推进到某个 Fiber 节点时，beginWork 发现这是函数组件，就调用对应的组件函数；函数返回元素树后，React 再遍历这棵元素树创建或更新子 Fiber 节点；子树处理完成后回到 completeWork 收尾、打副作用标记。

function Dashboard() {
  const [tab, setTab] = useState('home');
  // 本次渲染返回的元素树，被 beginWork 用于协调子 Fiber
  return (
    <main>
      <TabBar active={tab} onChange={setTab} />
      {tab === 'home' && <HomePanel />}
      {tab === 'me' && <MePanel />}
    </main>
  );
}
环节本章对应概念
调度进入节点时间片内到达 Dashboard 的 Fiber（第 40 章）
beginWork读取本次 props/state/context，调用组件函数取得元素树（39.5、本章 41.1）
子树协调遍历返回的元素树，配对或新建子 Fiber（第 42 章展开）
completeWork回溯收尾，收集插入、更新等副作用标记（第 42 章展开）
本章聚焦"组件函数内部发生了什么"；组件之间如何比较、副作用如何汇总提交，是下一章协调与提交的主题。

要点一句话
渲染即调用render 阶段调用函数组件，输入 props/state/context，返回元素描述树
