51.1 打包体积与首屏

构建工具会把项目里所有模块按依赖关系打包成一个或多个 bundle。如果所有页面、所有重型组件都在首屏 bundle 里，用户打开首页就要下载、解析、编译整份代码——即使他这次根本不会进入那些页面。首屏慢的常见原因之一，就是 bundle 里塞了大量当前路由用不到的代码。

代码分割（code splitting）的目标：把首屏不需要的代码拆成独立 chunk，等真正需要时再下载。React 层面的配合点是 React.lazy 与 Suspense，分包由构建工具完成。

51.2 React.lazy 与 Suspense 基础

React.lazy 接收一个返回 Promise 的函数（通常就是 () => import('./X')），返回一个组件：首次渲染该组件时，React 才去加载对应 chunk；加载期间由 Suspense 的 fallback 占位内容接管界面。

配套关系要记牢：Suspense 负责"加载期间显示什么"，错误边界负责"加载失败显示什么"；二者缺一时，加载态或失败态都会变成整页异常。
import { lazy, Suspense } from 'react';

// 首次渲染 OrderPage 时才下载它所在的 chunk
const OrderPage = lazy(() => import('./pages/OrderPage'));

export default function App() {
  return (
    <main>
      <Suspense fallback={<div className="page-loading">加载中…</div>}>
        <OrderPage />
      </Suspense>
    </main>
  );
}

两个配套要求：

  • 必须包在 Suspense 里：没有 fallback 时，加载期间无法渲染占位，会直接报错；
  • 必须配错误边界：网络失败、chunk 加载异常时，需要错误边界捕获并展示重试入口，否则整棵树进入错误状态（错误边界写法见第 37 章）。
import { Component } from 'react';

class RouteErrorBoundary extends Component {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  componentDidCatch(error) {
    console.error('页面 chunk 加载失败', error);
  }

  render() {
    if (this.state.hasError) {
      return <button onClick={() => window.location.reload()}>重试加载页面</button>;
    }
    return this.props.children;
  }
}
加载失败重试线上 chunk 文件名通常带内容哈希，发版后旧版本页面可能请求到已被清理的旧 chunk。错误边界里提供重试或引导刷新，比白屏或整页崩溃更友好。

51.3 路由级分割与组件级分割

分割粒度有两种常见选择，通常配合使用：

粒度做法适用与收益
路由级分割每个路由页面用 lazy 加载，进入路由时才下载对应页面 chunk最常见、收益最稳：首屏只下载当前路由，公共依赖单独成包
组件级分割页面内重型组件（图表编辑器、富文本、弹窗、文档预览）按需 lazy页面首屏先出主体，重型内容延迟加载；适合首屏不立即展示的部分
条件内加载在事件处理函数或条件分支里调用 import()，不需要 React 组件也可分割用于导出、打印、第三方工具等"用到才加载"的逻辑模块
 
import { createBrowserRouter, RouterProvider } from 'react-router-dom';
import { lazy, Suspense } from 'react';

const HomePage = lazy(() => import('./pages/HomePage'));
const OrderPage = lazy(() => import('./pages/OrderPage'));
const ReportPage = lazy(() => import('./pages/ReportPage'));

const withSuspense = (node) => (
  <Suspense fallback={<div className="page-loading">加载中…</div>}>
    {node}
  </Suspense>
);

const router = createBrowserRouter([
  { path: '/', element: withSuspense(<HomePage />) },
  { path: '/orders', element: withSuspense(<OrderPage />) },
  { path: '/report', element: withSuspense(<ReportPage />) },
]);

构建工具看到静态写在 lazy 参数里的 import() 调用，会把对应模块拆成独立 chunk；公共模块（React、路由库等）被多个 chunk 复用时会单独提取，避免重复打包。

与第 33 章的衔接：路由懒加载在 React Router 一章已介绍过基础写法；本章聚焦打包原理、分割粒度与预加载策略，路由配置细节不再重复。
不要把一个页面拆得过碎：每个 chunk 都有独立的网络请求开销，几个小 chunk 串行下载可能比一个中等 chunk 更慢。分割粒度要结合 chunk 大小与网络条件实测。

51.4 预加载策略：空闲、悬停、preload/prefetch

分割解决了"首屏不下载"，但进入下一路由时仍有等待。预加载（preloading / prefetching）在用户真正点击之前，利用碎片时间提前把 chunk 下载到浏览器缓存，点击时直接命中缓存。

策略时机与写法适用场景
空闲预加载首屏可交互后，用 requestIdleCallback（或 setTimeout 兜底）调用 import() 预取下一屏代码用户下一步动作比较确定（如登录后进首页）
悬停预加载导航链接 onMouseEnter / onFocus 时触发 import()桌面端导航菜单，悬停到点击之间通常有数百毫秒
preload声明当前导航很快需要的资源，优先级较高当前页面确认立刻要用的 chunk
prefetch声明未来可能需要的资源，浏览器空闲时低优先级下载下一路由、备用主题、可选语言包
 
// 同一个动态导入先预取一次，浏览器缓存后 React.lazy 再加载即命中
const preloadReportPage = () => import('./pages/ReportPage');
const ReportPage = lazy(preloadReportPage);

function NavLink({ to, children }) {
  // 悬停或键盘聚焦时提前下载目标 chunk
  const warmUp = () => {
    if (to === '/report') preloadReportPage();
  };
  return (
    <a href={to} onMouseEnter={warmUp} onFocus={warmUp}>
      {children}
    </a>
  );
}
// 空闲预加载：浏览器空闲时再预取，不抢占首屏关键任务
function scheduleIdle(cb) {
  if ('requestIdleCallback' in window) {
    requestIdleCallback(cb, { timeout: 2000 });
  } else {
    setTimeout(cb, 1200);
  }
}

// 首屏渲染完成后，预取用户最可能进入的下一路由
scheduleIdle(() => {
  import('./pages/ReportPage');
});
预加载的分寸：只预取确定会去的路由，不要把全站 chunk 都预取一遍，否则省下的首屏体积又被后台下载消耗掉，移动端流量与电量反而受损。

51.5 其他分割与瘦身手段

代码分割之外，还有几类降低 bundle 体积的常规手段：

手段原理注意点
Tree Shaking构建工具基于 ES Module 静态结构，剔除未被引用的导出使用命名导入；避免 CommonJS 动态导出；确认打包配置开启
第三方库按需引入组件库、工具库只导入用到的模块，不引入整包参考各库文档的按需加载写法，避免全量注册
重型第三方外置体积稳定的大型库通过 CDN 或独立 chunk 长期缓存权衡缓存命中率与多一次请求，不随意外置
条件加载模块非关键功能（打印、导出、编辑器）在事件里 import()加载期间给出按钮状态反馈，避免重复点击
资源瘦身图片压缩、字体子集化、图标按需生成 SVG体积问题不全在 JS，静态资源同样计入首屏成本
 
// ✗ 整包引入，未使用的导出无法被 Tree Shaking 剔除
import _ from 'lodash';

// ✓ 命名导入具体函数，便于构建工具剔除其余模块
import { debounce, throttle } from 'lodash-es';
Tree Shaking 依赖 ES Module 的静态导入结构：循环依赖、动态 require、运行时拼接的导入路径都会让工具无法判断哪些导出被使用，瘦身效果随之消失；接入第三方库时先确认它提供 ESM 产物。
体积优化要先看报告：用构建工具自带的包体积分析插件（如 webpack-bundle-analyzer、rollup-plugin-visualizer 一类）查看各 chunk 占比，针对最大的几块动手，而不是凭印象拆包。

51.6 度量与取舍

代码分割是有成本的：多 chunk 意味着多请求、多缓存层级、加载态管理与错误边界。判断优化是否值得，回到第 47 章的度量方法：

判断问题依据
首屏 bundle 是否真的过大查看构建产物各 chunk 体积；对照 Web Vitals 的 LCP 与首屏 JS 下载、解析时间
哪个路由/组件最值得拆包体积报告中占比最大、首屏又用不到的部分优先
分割后切换是否变快复测路由切换等待时间；配合预加载后观察交互响应（INP）
是否过度分割chunk 数量过多、小文件串行请求；合并相近模块，观察网络瀑布图
加载态是否可接受fallback 占位要与页面结构对齐，避免布局跳动；弱网下检查加载提示是否清晰
不要为分割而分割项目早期、页面很少、bundle 不大时，保持简单打包即可；等真实体积与首屏指标暴露问题后，再按本章顺序做路由分割、组件分割与预加载。
本章定位：代码分割解决"首屏代码量"，虚拟化解决"首屏 DOM 规模"，memo/useMemo 解决"重复渲染成本"——三类问题互不替代，第 55 章实战会把它们组合到一个页面上。

要点一句话
