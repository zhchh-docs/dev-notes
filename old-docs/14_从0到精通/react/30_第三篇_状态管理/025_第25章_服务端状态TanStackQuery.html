25.1 为什么服务端状态需要专门的查询库

服务端状态与客户端状态的本质区别：真相在后端，前端保存的只是一份副本。副本需要缓存复用、多组件共享、过期判断、失败重试与变更后刷新——这些能力手写一遍就是重复造轮子，TanStack Query 把它们标准化为 hook 配置。
能力手写 useEffect + useStateTanStack Query v5
同参数多组件共享缓存各组件独立请求，无法复用按 queryKey 自动共享缓存与去重
过期判断与后台刷新无概念，刷新页面即重取staleTime 区分新鲜 / 过期，后台静默重取
缓存回收组件卸载即丢失gcTime 控制无订阅缓存的回收时机
失败重试逐处手写 catch 与重试retry 次数与延迟策略声明式配置
竞态与取消手写 ignore 标记 / AbortControllerqueryFn 接收 signal，过期查询自动取消
三态字段每个组件维护多个布尔值hook 返回标准化状态字段，UI 分支统一
与第 24 章对照：RTK Query 面向 Redux 技术栈，TanStack Query 框架无关；本章及后续两章围绕 v5 展开，版本参数以官方文档为准。
手写请求解决的是「这次调用有没有发出」，查询库解决的是「这份数据在整个应用里如何被缓存、共享与刷新」——两者不是替代关系，而是层级关系。

25.2 接入：QueryClient 与 Provider

npm install @tanstack/react-query

应用根部创建一个 QueryClient 实例（缓存的全局容器），通过 QueryClientProvider 注入组件树。全局默认选项可以在这里集中配置，单个查询再按需覆盖。

import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60_000,          // 1 分钟内视为新鲜
      gcTime: 5 * 60_000,         // 无订阅 5 分钟后回收
      retry: 2,                   // 失败重试 2 次
    },
  },
});

export default function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <RootRoutes />
    </QueryClientProvider>
  );
}
QueryClient 实例应在组件模块级创建一次，不要写在组件函数体内反复 new；否则每次渲染都会得到一个全新缓存，等于没有缓存。

25.3 useQuery：queryKey、queryFn 与常用参数

useQuery 的配置对象里，queryKey 回答「这份缓存是谁」，queryFn 回答「怎么取到它」；两者配合，缓存的复用、去重与失效都由查询库自动完成。

useQuery 接收配置对象：queryKey 是缓存的唯一标识，结构即依赖维度；queryFn 是返回 Promise 的取数函数。参数变化时 hook 自动判定需要新的缓存条目。

import { useQuery } from '@tanstack/react-query';

async function fetchPosts() {
  const res = await fetch('/api/posts');
  if (!res.ok) throw new Error('请求失败');
  return res.json();
}

function PostList() {
  const { data: posts, isPending, isError, error, refetch } = useQuery({
    queryKey: ['posts'],
    queryFn: fetchPosts,
  });

  if (isPending) return <p>加载中…</p>;
  if (isError) return <p>出错了：{error.message}</p>;

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

详情类查询把路由参数放进 queryKey；queryFn 接收上下文对象，其中 signal 用于取消过期请求；select 对返回数据做派生变换，enabled 控制查询是否启用。

function PostDetail({ id }) {
  const post = useQuery({
    queryKey: ['post', id],
    queryFn: ({ signal }) =>
      fetch(`/api/posts/${id}`, { signal }).then((r) => r.json()),
    staleTime: 30_000,
    enabled: Boolean(id),
    select: (data) => ({
      title: data.title,
      excerpt: data.body.slice(0, 80),
    }),
  });
  // post.data 即变换后的 { title, excerpt }
}
queryFn 不要在闭包里直接引用过期的 props 或 state：参数应通过 queryKey 传入并从上下文读取，避免参数变化后仍使用旧值发请求。
参数作用
queryKey缓存键，数组结构即依赖维度；参数变化生成新缓存条目，前缀匹配用于批量失效
queryFn返回 Promise 的取数函数；接收 { queryKey, signal } 上下文
staleTime数据视为新鲜的时长（毫秒），期间重新挂载不重取
gcTime无任何订阅后缓存保留时长（毫秒），到期从缓存回收；v5 原名 cacheTime
placeholderData挂载瞬间展示的占位数据，如 keepPreviousData 保留上一页列表
enabled是否启用查询；依赖参数未就绪时设为 false 避免无效请求
select对成功数据做派生变换，只影响本组件读取结果，不改变缓存原始数据

25.4 查询状态机与返回字段

每个查询在缓存中处于一个标准状态机：pending（无数据、首次取数中）、success（取数成功）、error（取数失败）。hook 同时返回派生布尔字段，UI 按字段分支即可，不需要自己组合条件。

图 25-1 TanStack Query 查询状态机：pending → success / error，success 后可后台重取

字段含义
status查询状态机：'pending' / 'success' / 'error'
isPending处于 pending 且尚无成功数据，渲染首次加载态
isSuccess处于 success，data 可用
isError处于 error，error 可用
isFetching正在发起任意一次取数（首次或后台刷新），可用于骨架屏指示
data / error最近一次成功数据 / 错误对象，未就绪时为 undefined / null
refetch手动触发一次取数的函数
区分 isPending 与 isFetching：首次无数据用 isPending 渲染整页骨架；后台刷新用 isFetching 显示局部指示，不要让旧数据被加载态覆盖。

25.5 useMutation 与基础失效

写操作（新增、修改、删除）使用 useMutation：mutationFn 发起请求，成功后通过 useQueryClient 拿到缓存实例，调用 invalidateQueries 让相关列表缓存过期，触发后台重取。

import { useMutation, useQueryClient } from '@tanstack/react-query';

function NewPost() {
  const queryClient = useQueryClient();

  const addPost = useMutation({
    mutationFn: (body) =>
      fetch('/api/posts', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(body),
      }).then((r) => r.json()),
    onSuccess: () => {
      // 让 ['posts'] 前缀下的缓存过期，触发重取
      queryClient.invalidateQueries({ queryKey: ['posts'] });
    },
  });

  const submit = async () => {
    await addPost.mutateAsync({ title: '新文章' });
  };

  return (
    <button onClick={submit} disabled={addPost.isPending}>
      {addPost.isPending ? '提交中…' : '新增文章'}
    </button>
  );
}

mutation 同样返回 isPending、isError、error、data 等状态字段；乐观更新、快照回滚等进阶流程在第 27 章展开。

本章的 onSuccess 只做基础失效；点赞、收藏这类需要即时反馈的轻量操作，其乐观更新与快照回滚流程在第 27 章展开，不要在 mutation 里手写半套缓存替换逻辑。

25.6 v5 版本口径与迁移注意点

本档按 TanStack Query v5 编写，以下名称与行为与旧版存在差异，开发时以官方迁移指南为准，不要混用旧参数。

概念v5 现行写法旧版 / 易混写法
缓存回收时长gcTimev4 的 cacheTime 已更名，不再使用
首次加载态isPending旧版 isInitialLoading 概念由 isPending 承接
保留上一页数据placeholderData: keepPreviousData旧版 keepPreviousData: true 配置项已移除
取数上下文queryFn({ queryKey, signal })不要在闭包里直接引用已过期的参数
记忆口径：v5 里是 gcTime 不是 cacheTime；首次加载看 isPending，后台刷新看 isFetching。第 26 章继续讲缓存失效与刷新策略，第 27 章讲乐观更新与回滚。

✎ 本章习题

A 基础接入 QueryClientProvider 并配置全局默认：staleTime 30 秒、gcTime 10 分钟、失败重试 1 次；用 useQuery 获取 /api/users，分别渲染 isPending 加载态、isError 错误态与成功列表。
B 进阶实现用户详情查询：queryKey 为 ['user', id]，queryFn 使用 signal 取消过期请求；当 id 为空时 enabled: false；用 select 只暴露 name 与 email 两个字段。写出完整 hook 调用片段并说明 isPending 与 isFetching 在本组件各自用于什么 UI。
C 挑战为「评论列表 + 发表评论」设计 TanStack Query 方案：列表用 useQuery，发表用 useMutation，成功后失效评论列表；讨论 queryKey 应如何组织（文章 id 维度），使新增评论只刷新当前文章的评论而不波及其他文章；再说明 staleTime 设为 0 与 60 秒分别带来什么用户体验差异。
