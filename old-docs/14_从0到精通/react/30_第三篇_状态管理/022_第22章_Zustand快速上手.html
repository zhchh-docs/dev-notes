22.1 心智：组件树外的外部 store

Context 的值挂在组件树上，随 Provider 广播；Zustand 的 store 是一个组件树之外的普通对象，组件直接订阅它，不需要 Provider 包裹，也不存在「根上挂一个大 Context」的问题。

第 21 章提到 Context 没有 selector、整值广播；Zustand 正好补上这两点：store 本身是外部状态容器，每个组件用 selector 声明自己需要哪一片，只有这一片变化时组件才重渲染。

维度ContextZustand
状态位置React 组件树内，由 Provider 持有组件树外的外部 store 实例
订阅方式读取整个 Context 值，无 selectorselector 函数提取切片，按切片比较
Provider必须在祖先节点挂载不需要 Provider，直接调用 Hook
组件外读写无法脱离组件树读取getState / setState / subscribe
中间件生态无内置persist、immer、devtools 等官方中间件
Zustand 的核心契约：状态在树外，订阅在组件内，更新走 set 函数，不可变返回新对象。它比 Redux 少了样板，比 Context 多了切片订阅。

22.2 安装与 create 定义 store

npm install zustand

用 create 定义一个 store：传入一个 (set, get) => ({ ... }) 函数，返回状态字段与更新动作（actions）。set 用来更新状态，支持函数形式接收旧状态；get 用来在 action 内部读取当前状态。

import { create } from 'zustand';

const useCounterStore = create((set, get) => ({
  count: 0,
  step: 1,
  increment: () => set((state) => ({ count: state.count + state.step })),
  decrement: () => set((state) => ({ count: state.count - state.step })),
  reset: () => set({ count: 0 }),
  // action 内部需要读当前状态时用 get()
  double: () => get().count * 2,
}));

注意 set 与 React 的 setState 一样要求不可变更新：传入部分字段即可合并，对象内部字段需要展开后返回新对象，不要原地修改。

const useCartStore = create((set) => ({
  items: [],
  addItem: (product) =>
    set((state) => ({ items: [...state.items, product] })),
  removeItem: (id) =>
    set((state) => ({ items: state.items.filter((it) => it.id !== id) })),
}));
不要在 action 里原地改数组或对象（如 state.items.push(p)）。Zustand 依赖引用变化判断是否通知订阅者，原地修改后引用不变，组件不会重渲染。

22.3 组件使用：useStore 与 selector

组件接入 store 只需要一行调用：Hook 接收 selector，声明「我要哪一片」。订阅粒度由你写的 selector 决定，这正是 Zustand 相对 Context 整值广播的核心优势。

store 创建出来本身就是一个 Hook。在组件里调用它并传入 selector 函数，只提取需要的切片；selector 返回的值变化时组件才重渲染。

import { useCounterStore } from './stores/counterStore';

function Counter() {
  const count = useCounterStore((s) => s.count);
  const increment = useCounterStore((s) => s.increment);

  return (
    <div>
      <span>{count}</span>
      <button onClick={increment}>+1</button>
    </div>
  );
}
常见错误：调用 useCounterStore() 不传 selector，这会订阅整个 store——任何字段变化都触发本组件重渲染，等于退回 Context 的整值广播。selector 永远要写。
// ✗ 不传 selector：订阅整个 store，step 变化也会让本组件重渲染
const state = useCounterStore();

// ✓ 只订阅需要的切片
const count = useCounterStore((s) => s.count);

22.4 组件外读写：getState / setState / subscribe

因为 store 在组件树之外，非组件代码（工具函数、请求拦截器、路由守卫、事件回调）也能直接读写，不需要把状态塞进 Context 再层层传递。

// 读取当前状态（不订阅，不触发重渲染）
const currentCount = useCounterStore.getState().count;

// 直接更新状态（会通知所有订阅组件）
useCounterStore.setState({ count: 0 });

// 订阅状态变化，返回取消订阅函数
const unsubscribe = useCounterStore.subscribe((state, prevState) => {
  if (state.count !== prevState.count) {
    console.log('count 从', prevState.count, '变为', state.count);
  }
});

// 不再需要时取消订阅
unsubscribe();
API使用位置行为
useStore(selector)组件内订阅切片，切片变化触发重渲染
useStore.getState()组件内外均可读取当前快照，不订阅、不重渲染
useStore.setState(partial)组件内外均可合并更新状态并通知订阅者
useStore.subscribe(listener)组件内外均可监听状态变化，返回取消订阅函数

注意 getState 返回的是当前快照引用，后续状态变化不会更新这个局部变量：组件内需要响应变化必须走 useStore 订阅，组件外逻辑才在事件回调里用 getState 读取最新值。

在 useEffect 里订阅 store 时，cleanup 中必须调用返回的取消订阅函数，否则离开组件后监听器仍在执行（呼应第 10 章 cleanup 三时机）。

22.5 selector 稳定性与 useShallow

selector 返回原始值（数字、字符串、布尔）时，Zustand 用严格相等比较即可。一旦 selector 返回对象或数组字面量，每次渲染都会产生新引用，即使内容相同也会判定为变化，导致组件反复重渲染。

// ✗ selector 返回新对象字面量：引用每次都变，组件反复重渲染
const cart = useCartStore((s) => ({ items: s.items, total: s.items.length }));

v5 提供 useShallow（来自 zustand/react/shallow），对返回的对象 / 数组做浅比较：内容一致就不触发重渲染。

import { useShallow } from 'zustand/react/shallow';

// ✓ 浅比较：items 引用与 total 数值都没变时不重渲染
const cart = useCartStore(
  useShallow((s) => ({ items: s.items, total: s.items.length }))
);
selector 里不要放昂贵的派生计算：每次状态变化都会重新执行 selector；复杂派生应在组件内用 useMemo 完成，或交给专门的记忆化选择器处理。
selector 返回类型比较方式写法建议
原始值（number / string / boolean）严格相等 ===直接写 selector，无需额外处理
单个对象 / 数组字段引用相等selector 直接返回该字段，不要包新字面量
多字段组合成对象需要浅比较用 useShallow 包裹 selector

22.6 TypeScript、store 拆分与持久化

22.6.1 TypeScript 标准写法

v5 推荐使用柯里化形式 create<State>()((set, get) => ...)，让 state 与 actions 的类型在整个 store 内自动推断。

type CounterState = {
  count: number;
  increment: () => void;
  decrement: () => void;
};

const useCounterStore = create<CounterState>()((set) => ({
  count: 0,
  increment: () => set((s) => ({ count: s.count + 1 })),
  decrement: () => set((s) => ({ count: s.count - 1 })),
}));

22.6.2 按领域拆分多个 store

与第 20 章分层一致：不同领域各建一个 store（counter、cart、user、theme），而不是把所有状态塞进一个巨型 store。store 之间需要联动时，在 action 内通过 getState 读取其他 store，或用事件回调解耦。

22.6.3 persist 中间件持久化

需要刷新后保留的共享状态（主题、语言、登录偏好），用官方 persist 中间件把指定字段写入 localStorage，并通过 name 指定存储键名。

import { create } from 'zustand';
import { persist } from 'zustand/middleware';

const useThemeStore = create(
  persist(
    (set) => ({
      theme: 'light',
      toggle: () =>
        set((s) => ({ theme: s.theme === 'light' ? 'dark' : 'light' })),
    }),
    { name: 'theme-storage' }
  )
);
持久化只适合非敏感的偏好类状态；登录令牌等敏感信息不应明文写入 localStorage，应由后端会话或 HttpOnly Cookie 管理。

22.7 与 Pinia、Redux 的概念对照

熟悉 Vue Pinia 的读者可以按下表迁移心智；注意 Zustand 的 action 直接调用 set，而 Pinia 的 action 内允许直接修改 state，写法习惯并不相同。

✎ 本章习题

A 基础用 create 实现一个待办 store：包含 todos 数组、addTodo(text)、toggleTodo(id)、clearCompleted() 三个 action，全部使用不可变更新；再写出一个组件，分别订阅 todos 数量与 addTodo。
B 进阶下面这段组件代码会在每次 store 任意字段变化时重渲染，且组合切片写法会造成引用抖动。指出两处问题并改写：const user = useUserStore(); const profile = useUserStore((s) => ({ name: s.name, email: s.email })); 要求写出修正后的两行代码并说明 useShallow 的作用。
C 挑战为「购物车」设计 Zustand store：条目含 id / name / price / qty，提供加购、改数量、移除、清空；实现「加购后若用户已登录则把购物车同步到后端」的联动（在 action 内读取 user store 状态判断）；再用 persist 把购物车持久化到本地，说明刷新后与后端数据冲突时应优先以哪一方为准。
