第 13 章 useRef：DOM 引用与可变值

教科书 第 13 章 / 共 64 章 · 预计 45 分钟 · 渲染周期里的「私人备忘录」

useRef 常被当成「只能拿 DOM 节点」的小工具，其实它有两副面孔：一是对 DOM 节点或组件实例的引用，二是跨渲染周期保持不变的可变容器。本章讲清 ref 对象的结构、它与 state 的本质差异、四类标准用法，以及渲染期间读写 ref 这一高频陷阱。

◆本章目标

  • 理解 useRef(initial) 返回的是一个带 .current 属性的普通对象，且该对象在组件整个生命周期内保持同一个引用；
  • 能把 useRef 与 useState 的差异讲清楚：是否触发渲染、是否参与渲染输出、是否进入依赖数组；

13.1 useRef 的两种身份

提到 ref，新手首先想到「把 ref 属性挂到 DOM 标签上，然后通过 ref.current 拿到这个节点」。这只是它的第一副面孔。第二副面孔来自官方文档对 useRef 的定义：它返回一个可变容器，其 .current 属性在组件重新渲染之间保持不变。

可以把 ref 想象成组件在 React 渲染周期之外的一块私人备忘录：渲染一次次跑，备忘录本体始终是同一个；里面记什么、什么时候记，React 不会因此重新渲染，也不会盯着它做变更检测。

图 13-1 useRef 的两种身份：节点引用与可变容器共用同一个 .current 机制

import { useRef } from 'react';

function Demo() {
  // 身份一：初始值为 null，等待 ref 属性挂上真实节点
  const inputRef = useRef(null);

  // 身份二：容器本体不变，里面可以存任意值
  const clickCountRef = useRef(0);

  function handleClick() {
    clickCountRef.current += 1;          // 修改备忘录，不触发渲染
    inputRef.current && inputRef.current.focus();
  }

  return <input ref={inputRef} />;
}

13.2 ref 与 state：本质区别对照表

新手最容易把「要记住的值」一律写成 useState，结果界面为了一个不需要显示的计数反复重渲染。理解下面这张表，就能在两者之间做正确选择。

对比项useStateuseRef
修改后是否触发渲染是：调用 setter 安排一次重渲染否：直接改 .current，React 无感
值是否参与渲染输出是：显示值必须来自 state/props/派生计算否：渲染期间读取 .current 不保证最新
是否进入 effect 依赖数组是：变化的值需要重新同步时写入依赖否：React 不追踪 .current，写进依赖没有意义
初始值计算惰性初始化函数参数可避免每次渲染重算每次渲染都会读取传入的初始参数，但只有首次生效
适合保存什么驱动界面更新的显示数据DOM 节点、定时器 ID、订阅句柄、给旧闭包读的最新值
判断口诀：这个值变了，界面要不要跟着变？ 要，用 state；不要，用 ref。
// ✗ 不需要显示的计数也用 state：组件每次点击都重渲染
const [count, setCount] = useState(0);
function onClick() { setCount(c => c + 1); }

// ✓ 只在事件处理里读取、不显示 → ref
const countRef = useRef(0);
function onClick() { countRef.current += 1; }
红线渲染输出（JSX）里直接读取 ref.current 是反模式：ref 的更新不会触发渲染，你看到的永远是上一次渲染读到的值。显示数据必须走 state。

13.3 四类标准用法

ref 的两类身份遵守同一条底层规则：组件实例持有同一个 ref 对象，它的生命周期与组件绑定；组件卸载时，ref 中保存的节点引用与句柄一并失效。

用法一：DOM 节点引用，触发聚焦 / 滚动 / 测量

function SearchForm() {
  const boxRef = useRef(null);

  useEffect(() => {
    boxRef.current && boxRef.current.focus();
  }, []);

  function jumpToTop() {
    boxRef.current && boxRef.current.scrollIntoView({ behavior: 'smooth' });
  }

  return (
    <>
      <button onClick={jumpToTop}>回到搜索框</button>
      <input ref={boxRef} placeholder="搜索" />
    </>
  );
}

用法二：保存上一次渲染的值（previous 值）

function usePrevious(value) {
  const prevRef = useRef(undefined);
  useEffect(() => {
    prevRef.current = value;      // 渲染提交后记录当前值，下一轮再读就是上一次
  }, [value]);
  return prevRef.current;
}

function Profile({ userId }) {
  const prevUserId = usePrevious(userId);
  // 可以据此判断「用户是否切换了档案」并执行过渡逻辑
}

用法三：保存定时器 / 订阅 / 第三方实例句柄

function Chat({ roomId }) {
  const socketRef = useRef(null);

  useEffect(() => {
    const socket = io(`/room/${roomId}`);
    socketRef.current = socket;
    socket.on('message', appendMessage);
    return () => {
      socket.disconnect();
      socketRef.current = null;
    };
  }, [roomId]);
}

用法四：把最新值交给旧闭包读取（latest ref 模式）

第 11 章 11.3 提到过这一模式：某个副作用只想读最新值、又不希望该值进入依赖导致反复重建。用 ref 作为「最新值信箱」即可。

function Notice({ theme, text }) {
  const themeRef = useRef(theme);
  useEffect(() => { themeRef.current = theme; }, [theme]);

  useEffect(() => {
    const timer = setInterval(() => {
      toast(themeRef.current, text);   // 读到最新主题，定时器不随 theme 重建
    }, 5000);
    return () => clearInterval(timer);
  }, [text]);
}
场景选择原因
按钮点击后输入框聚焦DOM 引用 ref命令式调用原生方法，无需界面状态
记录用户点过多少次但不展示可变容器 ref不触发渲染，避免无谓重绘
下拉选项决定界面文案与配色useState变化必须反映到输出
effect 内需要读取最新回调但不重建订阅latest ref信箱模式绕过闭包陈旧问题

13.4 ref 对象结构与回调 ref

useRef(initialValue) 返回的对象结构极其简单：

{ current: initialValue }   // 整个组件生命周期内都是同一个对象引用

当这个 ref 被挂到 DOM 标签上，React 在节点挂载后把真实 DOM 赋给 current，卸载时再把 current 置回 null。

回调 ref：传入函数而不是对象

除了传 ref 对象，ref 属性还可以接收一个函数：节点挂载时 React 调用它并传入节点，卸载时再次调用并传入 null。需要感知「挂载/卸载时刻」或动态创建节点时，回调 ref 更顺手。

function List({ items }) {
  return (
    <ul>
      {items.map((item) => (
        <li
          key={item.id}
          ref={(node) => {
            if (node) { /* 挂载：node 是 li 元素 */ }
            else { /* 卸载：node 为 null，做清理 */ }
          }}
        >
          {item.title}
        </li>
      ))}
    </ul>
  );
}
注意回调 ref 在组件每次渲染时可能被先调用 null 再调用节点（内联函数形式），不要在回调里写昂贵逻辑；需要稳定引用时，把回调 useCallback 包起来，或直接使用 ref 对象。
ref 对象本身引用恒定，React 不会追踪 .current 的变化；需要「值变化触发界面更新」的场景，一律回到 useState，不要在 ref 与 state 之间摇摆。

与类组件时代的 createRef() 相比，函数组件里始终使用 useRef：createRef 每次渲染都生成新对象，没有跨渲染保持身份这一特性。子组件要把内部 DOM 暴露给父组件，需要 forwardRef 与 ref 转发机制，第 56 章组件库实战会结合 Ant Design 的 ref 用法展开。

13.5 常见坑与反模式

反模式后果正确做法
渲染期间写 ref.current = value双调用并发渲染时行为不可预测，违反渲染纯净性写在事件处理、effect 或 latest ref 的同步 effect 中
条件渲染分支内的 ref 直接读取current 为 null，调用 .focus() 抛错读取前判空：ref.current && ref.current.focus()
把 ref.current 写进 JSX 显示ref 更新不触发渲染，显示与真实值脱节显示数据改用 state，ref 仅用于命令式操作与备忘录
把 ref 对象放进 effect 依赖数组对象引用恒定，依赖永远不触发，lint 也不会报错提醒你依赖里只写响应式值；ref 本身不进依赖
用 ref 存 props 并在渲染中比较新旧 props渲染期间读写 ref，StrictMode 双渲染下结果混乱用 usePrevious 模式把赋值放到 effect 里
 
// ✗ 渲染期间写 ref：并发渲染与 StrictMode 下会出问题
function Counter({ step }) {
  const prevStep = useRef(step);
  prevStep.current = step;          // 渲染期写入，禁止
  return <div>{step}</div>;
}

// ✓ 放到 effect 里，提交后再记录
function Counter({ step }) {
  const prevStep = useRef(step);
  useEffect(() => { prevStep.current = step; }, [step]);
  return <div>{step}</div>;
}
记住 React 的渲染必须是纯函数：同样的 props 与 state 跑出同样的 JSX，不产生外部可观察的写入。ref 是外部备忘录，渲染期间只允许读、不允许写。

13.6 与 Vue 模板 ref 对照及排查清单

Vue 3 中 ref() 是响应式状态容器，模板里自动解包，修改即触发视图更新；React 的 useRef 定位更接近 Vue 的 shallowRef 配合「不参与响应式追踪」的场景，而 DOM 引用对应 Vue 模板里的 ref="inputRef"。跨框架迁移时最容易混淆的就是这一点：React 的 ref 不是响应式状态。

从 Vue 迁移过来最常见的错误：把需要显示的计数器、开关状态存进 useRef，然后困惑界面为什么不更新——React 不会监听 .current，这是两套响应式模型的根本差异。
  1. 调用 ref.current.focus() 报 null → 节点在条件分支中尚未挂载；先判空，或在 effect 里等待挂载完成；
  2. 改了 ref 界面没反应 → 该值其实需要显示，改用 useState；
  3. effect 里读到旧值 → 用 latest ref 信箱模式，或按第 11 章规则补齐依赖；
  4. 定时器/订阅在组件卸载后仍触发 → 句柄存在 ref 中，cleanup 里释放并置 null；
  5. 跨层级共享主题、用户信息等数据时，ref 无能为力——下一章 useContext 解决的正是「数据穿过组件树向下传」的问题。
小结口诀：DOM 节点挂 ref，不显示的备忘录也挂 ref；要显示、要重渲染，一律回到 state。

✓ 本章小结

要点一句话
两种身份DOM/组件实例引用 + 跨渲染保存的可变容器
与 state 区别改 ref.current 不触发渲染、不参与渲染输出、不进依赖数组
