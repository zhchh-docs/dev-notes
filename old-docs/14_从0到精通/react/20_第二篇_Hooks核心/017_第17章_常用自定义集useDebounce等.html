17.1 useDebounce：搜索输入防抖

防抖 Hook 解决的是「高频连续事件只关心最后一次结果」的问题：它内部用一个状态保存采纳值、一个计时器管理延迟窗口，调用方拿到的始终是停顿之后的最新值。

用户在搜索框敲入「react hooks」，每敲一个字符都发一次请求，会产生大量即将被覆盖的无效请求。防抖的做法是：记录最新值，延迟 delay 毫秒再采纳；期间新值到来就取消旧计时、重新等待。最终只在输入停顿之后发出一次请求。

图 17-1 防抖时序：密集输入被合并，停顿 delay 后只触发一次副作用

import { useState, useEffect } from 'react';

function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);   // 新值到来 / 卸载时取消旧计时
  }, [value, delay]);

  return debounced;
}

// 搜索框
function SearchBox() {
  const [keyword, setKeyword] = useState('');
  const debouncedKeyword = useDebounce(keyword, 300);

  useEffect(() => {
    if (!debouncedKeyword) return;
    let ignore = false;
    fetch(`/api/search?q=${debouncedKeyword}`)
      .then((r) => r.json())
      .then((data) => { if (!ignore) setResults(data); });
    return () => { ignore = true; };
  }, [debouncedKeyword]);

  return <input value={keyword} onChange={(e) => setKeyword(e.target.value)} />;
}
注意搜索请求本身的竞态处理不能省：防抖只减少请求数量，不解决「先发出的老请求后返回覆盖新结果」的问题，仍需第 11 章的 ignore 标记或 AbortController。

17.2 useThrottle：滚动与尺寸节流

节流与防抖容易混淆：节流是固定时间窗口内最多执行一次，窗口内的新事件被忽略；防抖是等事件停下来再执行。滚动位置更新、窗口尺寸重算、鼠标拖拽都属于高频连续事件，适合节流。

import { useState, useEffect, useRef } from 'react';

function useThrottle(value, interval = 200) {
  const [throttled, setThrottled] = useState(value);
  const lastRunRef = useRef(Date.now());

  useEffect(() => {
    const now = Date.now();
    const elapsed = now - lastRunRef.current;
    if (elapsed >= interval) {
      lastRunRef.current = now;
      setThrottled(value);
    } else {
      const timer = setTimeout(() => {
        lastRunRef.current = Date.now();
        setThrottled(value);
      }, interval - elapsed);
      return () => clearTimeout(timer);
    }
  }, [value, interval]);

  return throttled;
}

// 使用方式：先监听窗口尺寸变化，再把高频的 width 节流后交给样式判断
function ResponsiveSidebar() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const onResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);
  }, []);

  const throttledWidth = useThrottle(width, 200);
  return <aside className={throttledWidth < 768 ? 'mini' : 'full'}>菜单</aside>;
}
对比项防抖 debounce节流 throttle
核心规则停止触发后再等 N 毫秒执行一次每 N 毫秒最多执行一次
事件模型合并密集事件，只采纳最后一次按时间窗采样，中间事件丢弃
典型场景搜索建议、表单校验、窗口 resize 后布局计算滚动监听、拖拽进度、鼠标移动统计
即时反馈需求不适合：用户等待停顿才有反应适合：滑动过程中保持阶段性反馈
选型口诀：「停下来才算数」用防抖，「隔一会儿来一下」用节流。

17.3 usePrevious：记住上一次值

组件有时需要对比当前 props/state 与上一次的值：判断用户是否切换了档案、记录动画方向、检测某个布尔开关从关到开的跳变。这正是第 13 章 ref「保存上一次值」身份的标准封装。

import { useRef, useEffect } from 'react';

function usePrevious(value) {
  const prevRef = useRef(undefined);
  useEffect(() => {
    prevRef.current = value;      // 提交后记录当前值，下一轮读到的就是上一次
  }, [value]);
  return prevRef.current;
}

function Profile({ userId }) {
  const prevUserId = usePrevious(userId);
  const switched = prevUserId !== undefined && prevUserId !== userId;
  return (
    <div className={switched ? 'profile flash' : 'profile'}>
      当前用户 {userId}
    </div>
  );
}
注意读取顺序：ref 在 effect 提交后才写入，因此首次渲染返回 undefined；判断「是否发生过切换」时必须先排除首次渲染，不能直接假定上一次值存在。

17.4 useLocalStorage 持久化 Hook

持久化 Hook 把「读缓存 → 改状态 → 写回存储」这条链路封装起来：调用方像使用普通 useState 一样取值与赋值，存储细节、异常降级与 key 变更处理都藏在 Hook 内部。

让 state 与 localStorage 双向同步：初始化时读取缓存，setter 更新时写回存储，key 变化时重新读取。组件卸载不影响持久化数据本身。

import { useState, useCallback } from 'react';

function useLocalStorage(key, initialValue) {
  const [stored, setStored] = useState(() => {
    try {
      const raw = window.localStorage.getItem(key);
      return raw !== null ? JSON.parse(raw) : initialValue;
    } catch {
      return initialValue;
    }
  });

  const setValue = useCallback((value) => {
    setStored((prev) => {
      const next = typeof value === 'function' ? value(prev) : value;
      try {
        window.localStorage.setItem(key, JSON.stringify(next));
      } catch { /* 隐私模式等写入失败时静默降级 */ }
      return next;
    });
  }, [key]);

  return [stored, setValue];
}

// 使用
function ThemeSwitch() {
  const [mode, setMode] = useLocalStorage('theme', 'light');
  return (
    <button onClick={() => setMode(mode === 'light' ? 'dark' : 'light')}>
      当前：{mode}
    </button>
  );
}
选择持久化位置的原则：跨会话保留的偏好放 localStorage，仅当前向导流程需要的中间状态放 sessionStorage，只在组件内存里流转的临时值留在 useState；不要把表单草稿之外的业务数据塞进浏览器存储充当后端数据库。
注意写入存储时要捕获异常：隐私模式、存储配额满、序列化失败都会让 setItem 抛错；Hook 内部静默降级为仅内存状态，避免一次存储错误拖垮整棵组件树。
存储方案生命周期适用数据
localStorage持久保留，关闭浏览器后仍在主题偏好、侧边栏折叠状态、表单草稿
sessionStorage标签页会话内有效，关闭即清一次性向导进度、暂存的路由状态
组件内 useState组件生命周期内有效临时输入、hover 状态、表单中间值

17.5 工具集：点击外部、媒体查询、只跑一次

useOnClickOutside：点击弹层外部时关闭

import { useEffect } from 'react';

function useOnClickOutside(ref, handler) {
  useEffect(() => {
    const listener = (event) => {
      if (!ref.current || ref.current.contains(event.target)) return;
      handler(event);
    };
    document.addEventListener('pointerdown', listener);
    return () => document.removeEventListener('pointerdown', listener);
  }, [ref, handler]);
}

useMediaQuery：响应式断点 Hook

import { useState, useEffect } from 'react';

function useMediaQuery(query) {
  const [matches, setMatches] = useState(() =>
    window.matchMedia(query).matches
  );

  useEffect(() => {
    const mql = window.matchMedia(query);
    const onChange = (e) => setMatches(e.matches);
    mql.addEventListener('change', onChange);
    setMatches(mql.matches);
    return () => mql.removeEventListener('change', onChange);
  }, [query]);

  return matches;
}

// 使用
function Layout() {
  const isMobile = useMediaQuery('(max-width: 768px)');
  return isMobile ? <MobileNav /> : <DesktopNav />;
}

useEffectOnce：仅在挂载后执行一次

import { useEffect } from 'react';

function useEffectOnce(fn) {
  useEffect(() => fn(), []);   // 空依赖：挂载一次；StrictMode 下开发期会双跑（第 19 章）
}
不要把「只在挂载时跑一次」理解成可以省略 cleanup：useEffectOnce 包裹的订阅、定时器在卸载时仍然必须释放；StrictMode 开发期的「挂载 → 清理 → 再挂载」会立刻暴露漏写 cleanup 的问题（第 19 章）。
Hook职责关键 cleanup / 边界
useDebounce延迟采纳最新值cleanup 取消计时器
useThrottle按时间窗采样窗口计时到期回调可被清理
usePrevious保存上一次渲染值首次渲染值为 undefined，需判空
useOnClickOutside外部点击关闭弹层卸载时移除 document 监听
useMediaQuery订阅断点匹配状态卸载时移除 change 监听

17.6 自研与成熟库选型及排查清单

上面这些 Hook 逻辑短小、需求稳定，自研一遍有助于理解原理；但生产项目中，边界情况（SSR 环境、销毁竞态、自定义比较、服务端首屏值）需要反复打磨。复杂交互直接采用成熟库的经过验证的实现是更稳妥的工程决策。

判断维度自研 Hook采用成熟库（ahooks / react-use）
逻辑规模状态 + 单 effect + 单一 cleanup多参数、多模式、边界分支多
SSR 兼容需自己判断 window 是否存在库已处理服务端环境
测试覆盖项目内补单元测试库自带测试矩阵与语义版本承诺
依赖体积零额外依赖按需引入，注意 tree-shaking
  1. 防抖 Hook 改动后旧计时器仍在跑 → 检查 effect cleanup 是否清理了上一个 setTimeout；
  2. useLocalStorage 读取到旧缓存 → 确认初始化用了惰性函数 useState(() => …)，避免每次渲染重复解析；
  3. 点击外部 Hook 在弹层打开瞬间误触发关闭 → 监听 pointerdown 而非 click，并在打开按钮事件中阻止冒泡；
  4. 自定义 Hook 在条件分支里被调用而报错 → 第 18 章将从底层原理解释这个错误为什么无法绕过；
  5. 本章所有 Hook 都遵守「顶层调用、cleanup 成对」的规则，下一章拆开 React 内部实现，看规则背后的 Hook 链表。
小结口诀：停下来用防抖，隔一阵用节流；ref 存上次值，存储写双向同步；简单逻辑自己写，复杂交互交给成熟库。

✓ 本章小结

要点一句话
防抖事件停止触发后延迟 N 毫秒才执行一次；适合输入搜索、表单校验
节流固定时间窗内最多执行一次；适合滚动、resize、拖拽
usePrevious用 ref 保存上一次渲染的值，effect 提交后记录
持久化 Hookstate 与 localStorage 双向同步，key 变化重新读取
选型通用交互逻辑自研成本低；复杂场景直接用 ahooks / react-use 成熟实现

✎ 本章习题

A 基础实现 useDebounce(value, delay)：返回延迟后的等值；当 value 在 delay 内再次变化时，重置计时器。在搜索框中把延迟值作为请求关键词使用。
B 进阶实现 useOnClickOutside(ref, handler)：监听 pointerdown，事件目标不在 ref 节点内时调用回调；组件卸载时移除监听。说明为什么这里需要在 effect 依赖里判断 ref.current 的存在时机。
C 挑战为 useLocalStorage 增加跨标签页同步能力：监听 storage 事件，其他标签页修改同一 key 时当前组件同步更新；再讨论与 Zustand 这类状态持久化方案相比，这套手写方案的能力边界在哪里。
