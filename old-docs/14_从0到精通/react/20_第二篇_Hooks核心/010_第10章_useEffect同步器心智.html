第 10 章 useEffect：同步器心智

教科书 第 10 章 / 共 64 章 · 预计 55 分钟 · 全书分水岭

useEffect 是 React 里最容易用错的 API，错因几乎都源于心智模型的偏差：把它当成「生命周期钩子」，而不是「与外部系统保持同步」。本章重构这套心智——effect 何时执行、什么时候根本不需要写 effect、以及四类典型用例的规范写法。

◆本章目标

  • 建立正确心智：useEffect 是"让组件与 React 之外的系统保持同步"的通道，不是 mounted/updated hook；
  • 能对 effect 与现实副作用（订阅、计时器、DOM 操作、请求）逐一写出规范代码；
  • 记住"三个时机"与"提交后才异步执行"这两条时序规则；
  • 能识别根本不需要 effect的场景（派生值、在事件里做事）并用正确写法替代；
  • 知道 effect 里常见的三类错误：陈旧闭包、无限循环、重复请求。

10.1 effect 不是生命周期钩子

Vue 的 onMounted、老版本 React 的 componentDidMount 让很多人带着"在挂载那一刻做点事"的思维写 effect。这个模型在 React 里会持续出错，因为 effect 真正关心的是：

React 官方定义：useEffect 让你把组件与外部系统同步起来。所谓"外部系统"是指 React 渲染管不到的东西：浏览器 API、第三方 Widget、WebSocket、定时器、后台服务的 Actor 等等。

之所以叫"Effect（副作用）"，是因为这些操作在渲染期间禁止执行（渲染必须是纯的，见第 41 章）。effect 的作用就是：把渲染之外的事情推迟到提交之后再做。

useEffect(() => {
  // 建立连接（同步开始）
  const conn = createConnection(serverUrl, roomId);
  conn.connect();
  // 断开连接（同步结束）—— cleanup
  return () => conn.disconnect();
}, [serverUrl, roomId]);   // 依赖：这两个值变了就重新同步

这段代码的语义是"只要 serverUrl 或 roomId 变化，就重新建立一次连接"，与"挂载"毫无关系。你用"挂载时连接、卸载时断开"去理解它，就会在 roomId 变化时漏掉重建逻辑——这就是大量"聊天室串线""数据显示滞后" bug 的源头。

Effect 的心智模型：建立 → 清理 → 再建立的循环，而不是"一次性的挂载钩子"。

10.2 从生命周期到同步：对照表

场景生命周期思维（易错）同步思维（正确）
房间切换挂载时连 / 卸载时断，切换时忘了重连依赖 [roomId]，变化时先断旧的再连新的
搜索请求输入时发请求，结果乱序返回的竞态依赖 [keyword] + cleanup 忽略过期响应
监听事件重复 addEventListener 不移除cleanup 里 removeEventListener
定时器多次 setInterval 叠加cleanup 里 clearInterval
 
// 典型 bug：以生命周期思维写的聊天室
function ChatRoom({ roomId }) {
  const [messages, setMessages] = useState([]);
  useEffect(() => {
    const conn = createConnection(roomId);
    conn.on('message', m => setMessages(prev => [...prev, m]));
    conn.connect();
    return () => conn.disconnect();
  }, [roomId]);   // ← 依赖写对就自动支持"切换房间"，无需任何额外代码
}

10.3 执行时机与时序图

图 10-1 useEffect 的执行时机：渲染 → 提交 → 绘制 → 异步执行

三条必须记住的时序规则：

  1. effect 在每次渲染后都可能执行，是否执行取决于依赖数组是否变化；
  2. effect 是异步执行的（晚于浏览器绘制），因此不能在里面指望"用户看不到中间状态"；
  3. cleanup 先于新 effect 执行，且组件卸载时必定执行——这是所有资源释放的地方。

10.4 什么时候不该写 effect

官方给出的三条"你不需要 Effect"的场景，能删掉半数以上新手代码：

① 根据 props/state 计算显示值 → 别放进 state，直接算

// ✗ 多余：effect 里 set 另一个 state，等于渲染两遍
const [fullName, setFullName] = useState('');
useEffect(() => setFullName(first + ' ' + last), [first, last]);

// ✓ 派生即可
const fullName = first + ' ' + last;

② 事件里要做的事 → 放进事件处理函数

// ✗ 把"提交后弹提示"写成 effect + flag
const [submitted, setSubmitted] = useState(false);
useEffect(() => { if (submitted) toast('提交成功'); }, [submitted]);

// ✓ 直接在提交的地方做
async function submit() {
  await api.save(data);
  toast('提交成功');
}

③ 重置子组件状态 → 用 key

// ✗ effect 里手动清空子组件状态
useEffect(() => { setComment(''); }, [userId]);

// ✓ 换 key 让 React 重建它
<CommentBox key={userId} />

每次准备写 useEffect(() => setState(...), [deps]) 时，先停三秒：这其实是"把一个值同步到另一个值"吗？如果是，几乎总能通过直接计算省掉它。

10.5 四类典型用例的规范写法

① 浏览器 API 事件监听

useEffect(() => {
  const handler = (e) => { if (!ref.current.contains(e.target)) onClose(); };
  document.addEventListener('pointerdown', handler);
  return () => document.removeEventListener('pointerdown', handler);
}, [onClose]);

② 定时器

useEffect(() => {
  const id = setInterval(() => setTick(t => t + 1), 1000);
  return () => clearInterval(id);      // 不清会导致切换后多个定时器并存
}, []);

③ 网络请求（含竞态处理）

useEffect(() => {
  let ignore = false;                  // 本次请求是否已过期
  setLoading(true);
  fetch(`/api/users?q=${keyword}`)
    .then(r => r.json())
    .then(data => { if (!ignore) setUsers(data); })   // 过期响应直接丢弃
    .finally(() => { if (!ignore) setLoading(false); });

  return () => { ignore = true; };
}, [keyword]);

④ 操作 DOM（第三方库）

useEffect(() => {
  const chart = echarts.init(elRef.current);
  chart.setOption(option);
  return () => chart.dispose();        // 防止内存泄漏与重复初始化
}, [option]);
关于请求：以上写法用于理解原理；生产请用第 25 章的 TanStack Query，它自带缓存、去重、竞态与重试。

10.6 常见坑清单

现象原因 / 解法
页面卡死 / 疯狂请求effect 里 setState 而依赖包含这个 state → 无限循环；检查是否真的需要写 effect（见 10.4）
拿到的是旧数据陈旧闭包：依赖数组漏写变量；把用到的响应式值全写进依赖
请求结果覆盖顺序错乱竞态；用 ignore 标记或 AbortController（第 11 章）
监听器越加越多没写 cleanup；严格模式下会立刻暴露（双倍报警）
开发环境请求发两次StrictMode 故意双调用，生产不会发生（第 19 章）
effect 里读到旧 DOM 尺寸绘制后才执行是设计如此；需同步测量请用 useLayoutEffect（第 12 章）

✓ 本章小结

要点一句话
心智模型effect = 与外部系统同步，而非生命周期钩子
执行时机渲染 → 提交 → 绘制 → 异步执行 effect
cleanup依赖变化前与卸载时执行，负责断开同步
依赖的意义决定"什么时候需要重新同步"

典型用例监听、定时器、请求（带 ignore）、第三方实例 dispose
