2.1 前置：Node 与包管理器

React 项目虽然跑在浏览器里，但代码需要"编译打包"，这一步发生在你的电脑上因此必须先有 Node.js 运行环境。

版本选择

组件推荐版本说明
Node.js18 LTS 及以上（推荐 20 LTS）Vite 5+ 要求 Node 18+；偶数版本为长期支持
npmNode 自带最省心，默认选项，生态最全
pnpm8+硬链接复用依赖，磁盘占用小、安装快，monorepo 首选
yarn4.x历史包袱多的团队仍在用，新项目一般不选

本书命令统一用 npm（保证任何机器都能直接跑）；如果你用 pnpm，把 npm install 换成 pnpm install、npm run dev 换成 pnpm dev 即可，语义完全一致。

# 装好后先确认版本（三条命令都应该正常输出版本号）
node -v      # v20.x.x
npm -v       # 10.x.x
where npm    # Windows 用 where；macOS/Linux 用 which npm
坑 1国内网络下 npm install 慢或超时：换源即可——npm config set registry https://registry.npmmirror.com。团队合作建议写入 .npmrc 文件并提交仓库，避免每人各配一套。

编辑器

推荐 VS Code，并安装三个插件就够用全书：ESLint（实时报错）、Prettier（自动格式化）、ES7+ React/Redux snippets（输入 rfce 回车生成组件骨架）。React 官方另有 React Developer Tools 浏览器扩展，第六篇性能分析时会重度使用。

2.2 用 Vite 创建第一个项目

为什么是 Vite老教材用的是 create-react-app（CRA），它基于 webpack，冷启动动辄 30 秒以上，且已停止维护。Vite 的做法截然不同：开发时不打包整个项目，而是利用浏览器原生 ESM，只编译当前用到的模块，因此冷启动常在 300ms 内，热更新几乎瞬时。Vite 也是 Vue / React / Svelte 官方推荐的现代起点。

# 交互式创建（推荐第一次用，能看到所有模板选项）
npm create vite@latest my-app

# 一步到位：指定项目名 + React 模板
npm create vite@latest my-app -- --template react

# 想要 TypeScript？
npm create vite@latest my-app -- --template react-ts

cd my-app
npm install
npm run dev

执行后终端会打印 Local: http://localhost:5173/，浏览器打开即可看到 React 的旋转 logo 页面——你的第一个 React 应用已经跑起来了。

图 2-1 Vite 开发模式：按需编译 vs 全量打包

判断题："Vite 只是快，功能少"——错。dev 用按需编译，build 依然走 Rollup 产出压缩过的静态产物，功能与 webpack 等价。

2.3 项目结构逐项解读

Vite React 模板生成的目录很小，但每个文件都有明确职责：

my-app/
├── index.html            # 唯一的 HTML 页面（SPA 入口）
├── package.json          # 依赖清单 + 脚本命令
├── package-lock.json     # 依赖版本锁定（务必提交仓库）
├── vite.config.js        # Vite 配置：插件、别名、代理、端口
├── .eslintrc.cjs         # 代码规范配置（新版可能是 eslint.config.js）
├── public/
│   └── vite.svg          # 原样拷贝、不参与编译的静态资源（favicon 等）
└── src/
    ├── main.jsx          # JS 入口：把组件挂载到 DOM
    ├── App.jsx           # 根组件
    ├── App.css           # App 组件样式
    ├── index.css         # 全局样式
    └── assets/
        └── react.svg     # 参与编译的资源（import 后会得到 URL）
文件一句话职责
index.html项目唯一的真实 HTML；里面只有一个空的 <div id="root"> 和一条 <script type="module"> 引用。所有界面都由 JS 动态塞进去——这就是 SPA（单页应用）。
package.json声明依赖与脚本。dependencies 是运行必需（react、react-dom），devDependencies 只在开发期用（vite、eslint）。
vite.config.js此处配置 @vitejs/plugin-react 插件（它负责 JSX 转译与热更新），我们会在 2.6 节往里加别名。
public/不参与构建的资源，引用时用绝对路径 /vite.svg。适合放 favicon、robots.txt。
src/assets/参与构建的资源，必须 import 使用，构建时会被加哈希重命名，利于 CDN 缓存。
坑 2把 public 和 assets 用反，是新手最常见的"图片本地能显示、构建后 404"。判断标准很简单：需要被 import 参与打包的放 assets，需要原样保留路径的放 public。

2.4 启动链路：index.html → main.jsx → App

看懂这条链路，你就知道"页面到底是怎么出现的"，以后遇到白屏也能秒定位。

第 1 环：index.html

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/vite.svg" />
    <title>Vite + React</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

注意 <script type="module">——它让浏览器以 ES Module 方式加载 main.jsx，这正是 Vite 能按需编译的前提。

第 2 环：main.jsx（真正创造 React 应用的地方）

import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App.jsx'
import './index.css'

// 1. 找到 index.html 里那个空的 div
const container = document.getElementById('root')

// 2. 创建根实例并渲染 <App /> 到里面
ReactDOM.createRoot(container).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
)

逐层解释：

  • createRoot() 是 React 18 的新 API（老版本的 ReactDOM.render 已废弃）。拿到 root 对象后才有并发渲染能力。
  • .render(<App />) 表示"请把 App 组件渲染出来的界面放进这个容器"。React 从这里开始递归执行所有组件函数。
  • <React.StrictMode> 严格模式：开发环境下的"放大镜"，会把开发期常见错误（副作用未清理、废弃 API）暴露出来。坑提示它会导致开发环境 effect 执行两次——这不是 bug，第 19 章专门讲。
  • import './index.css' 直接 import CSS：Vite 会把它注入页面。这是"构建工具提供的能力"，不是 JS 语法。

第 3 环：App.jsx

import { useState } from 'react'
import reactLogo from './assets/react.svg'
import './App.css'

function App() {
  const [count, setCount] = useState(0)

  return (
    <>
      <div>
        <a href="https://vite.dev" target="_blank">
          <img src={reactLogo} className="logo react" alt="React logo" />
        </a>
      </div>
      <h1>Vite + React</h1>
      <div className="card">
        <button onClick={() => setCount((c) => c + 1)}>
          count is {count}
        </button>
      </div>
    </>
  )
}

export default App

三个值得记的点：<> ... </> 是 Fragment（空标签，允许返回多个并列节点）；{count} 是在 JSX 里嵌入 JS 表达式；export default 让 main.jsx 能 import App from './App.jsx'。这些细节第 3 章展开。

一句话串起来：浏览器加载 index.html → 加载 main.jsx → createRoot + render(<App />) → React 执行 App 函数得到 JSX → 生成真实 DOM 插入 #root → 界面出现。

2.5 dev / build / preview 三条命令

命令做了什么什么时候用
npm run dev启动开发服务器（默认 5173），带热更新 HMR，代码不压缩、错误信息友好日常写代码
npm run build生产构建：压缩、去 dead code、生成带哈希文件名，输出到 dist/部署前
npm run preview本地起静态服务预览 dist 产物（验证打包结果）部署前自检
npm run lint跑 ESLint 检查规范提交前 / CI
 
npm run build
# vite v5.x.x building for production...
# dist/index.html                  0.46 kB │ gzip:  0.30 kB
# dist/assets/index-a1b2c3d4.css   1.20 kB │ gzip:  0.62 kB
# dist/assets/index-e5f6g7h8.js  143.21 kB │ gzip: 46.05 kB
# ✓ built in 1.24s

dist/ 目录就是可以丢给 Nginx / 静态托管的一堆静态文件。文件名里的哈希用于长效缓存：内容变了哈希就变，用户浏览器会自动拉新文件。

坑 3直接双击 dist/index.html 用浏览器打开通常白屏——它以绝对路径 /assets/xxx.js 引用资源，必须放在服务器根路径下（用 npm run preview 或 Nginx）。若必须支持子目录部署，需在 vite.config.js 设 base: './'。

2.6 团队项目必配：别名、ESLint、环境变量

路径别名 @

避免出现 ../../../components/Button 这种"一层层往上翻"的相对路径地狱。两处同时配置（Vite 负责构建，编辑器负责跳转）：

// vite.config.js
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import path from 'node:path'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': path.resolve(__dirname, './src') },
  },
  server: { port: 5173, open: true },
})
// jsconfig.json（TS 项目用 tsconfig.json 的 paths）
{
  "compilerOptions": { "baseUrl": ".", "paths": { "@/*": ["src/*"] } },
  "include": ["src"]
}

配好后：import Button from '@/components/Button'。

环境变量

Vite 规定只有以 VITE_ 开头的变量才会被注入前端代码里（防止私钥泄露）：

# .env.development（会被 git 忽略之外的版本提交，注意别放密钥）
VITE_API_BASE=https://dev-api.example.com

# .env.production
VITE_API_BASE=https://api.example.com
// 使用：import.meta.env.VITE_API_BASE
const res = await fetch(import.meta.env.VITE_API_BASE + '/users')
console.log(import.meta.env.MODE)  // 'development' | 'production'
坑 4前端环境变量没有任何保密性——它会原封不动出现在打包产物里，任何人都能从 JS 文件翻出来。数据库密码、第三方 Secret 必须放后端。

ESLint 与格式化

模板已自带 ESLint。团队里建议统一：安装 Prettier，在 VS Code 设置 editor.formatOnSave: true，并把 .vscode/settings.json 提交仓库。这样"代码风格争论"从第一天就被消灭。

✓ 本章小结

要点一句话
技术栈Node 18+ / npm / Vite + React 18 是当前创建 React 项目的标准姿势
Vite 快的原理开发态不打包，用浏览器原生 ESM 按需编译；生产态用 Rollup 打包
index.htmlSPA 里只有一个空 #root 和一条 module 脚本
main.jsxcreateRoot(container).render(<App />) 是整个应用的起点
StrictMode开发期放大镜，会导致 effect 双调用，不是 bug
三条命令dev 开发、build 产出 dist、preview 本地验产物
工程化别名 @ + VITE_ 前缀环境变量 + 统一 lint/format
