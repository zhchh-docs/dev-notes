6.1 条件渲染的四种写法

// ① 早返回（if）—— 分支逻辑复杂时可读性最好
function Panel({ user }) {
  if (!user) return <Empty />;
  if (user.banned) return <Banned />;
  return <Profile user={user} />;
}

// ② 三元 —— 二选一
<div>{isEdit ? <EditForm /> : <ReadonlyView />}</div>

// ③ && —— 有没有（注意第 3 章讲过的 0 陷阱）
<div>{notifications.length > 0 && <Bell list={notifications} />}</div>

// ④ 查表（映射对象）—— 多分支的优雅解，避免嵌套三元堆砌
const STATUS_VIEW = {
  loading: <Skeleton />,
  empty: <Empty text="暂无数据" />,
  error: <ErrorBox />,
  done: <Content />,
};
<div>{STATUS_VIEW[status] ?? null}</div>
写法适用场景警告
早返回分支体量大、逻辑各异组件 return 分散，别写太长
三元简单的二选一嵌套两层以上立刻重构
&&可选的附加元素左侧可能是 0 / NaN
查表状态机式多分支分支各自需要独立组件
可读性红线嵌套三元："{a ? <A/> : b ? <B/> : c ? <C/> : null}"。改造手法二选一：① 抽成 renderByStatus() 函数返回 JSX；② 拆成多个小组件各自负责一个分支。
// 重构示范：把嵌套三元换成"具函数 + switch"
function renderBody(status, data) {
  switch (status) {
    case 'loading': return <Skeleton />;
    case 'error':   return <ErrorBox retry={refetch} />;
    case 'empty':   return <Empty />;
    case 'done':    return <DataView data={data} />;
    default:        return null;
  }
}

return <section>{renderBody(status, data)}</section>;

6.2 复杂分支：先分状态，再谈写法

新手写异步页面最常见的错误是"用散落的布尔量表达状态"：loading、isEmpty、hasError 三个变量互相组合，会出现"既加载又空又错误"的非法组合。正确做法是用单一状态字段表达互斥状态。

// ✗ 三个布尔量：非法组合无穷多
const [loading, setLoading] = useState(false);
const [error, setError] = useState(null);
const [list, setList] = useState([]);

// ✓ 单状态字段：互斥且完整
const [state, setState] = useState({ status: 'loading', data: [], error: null });

async function load() {
  setState({ status: 'loading', data: [], error: null });
  try {
    const data = await api.list();
    setState({ status: data.length ? 'done' : 'empty', data, error: null });
  } catch (error) {
    setState({ status: 'error', data: [], error });
  }
}
界面要先"建模"再"写 JSX"：状态机建模清楚，条件渲染自然变简单。第三篇的 TanStack Query 就是把这个模式产品化了。

6.3 列表渲染：map 与链式处理

function TodoList({ todos }) {
  return (
    <ul>
      {todos
        .filter(t => !t.done)                       // ①筛选
        .sort((a, b) => b.priority - a.priority)     // ②排序（注意要拷副本！）
        .slice(0, 20)                                 // ③截断
        .map(t => (                                   // ④渲染
          <TodoItem key={t.id} todo={t} />
        ))}
    </ul>
  );
}

// ⚠ sort 会原地修改数组实例！todos 是 props 时禁止直接用
const sorted = [...todos].sort((a, b) => b.priority - a.priority);
坑 1Array.prototype.sort / reverse / splice 会原地修改数组。对 props 或 state 里的数组直接调用，等于在数据来源上动手脚（违反第 4 章 props 只读），务必先 [...arr] 拷贝。

另外，JSX 里的链式运算每次渲染都会重新执行一遍；数据量很大时应把"计算"提前到第 49 章讲的 useMemo 中。

6.4 key 的作用：给节点一个身份证

React 更新列表时，要知道"新的这一项和旧的哪一项是同一个东西"。key 就是它的判断依据：

  • key 相同 → 判定为同一个元素，复用已有的 DOM 节点与组件状态，只更新变化的属性；
  • key 不同或缺失 → 判定为旧节点消失、新节点出现，销毁旧节点并创建新 DOM。

6.5 为什么不能用 index 做 key

先给一个能复现的真实 bug：

function Demo() {
  const [list, setList] = useState([{ id: 1, text: 'A' }, { id: 2, text: 'B' }]);

  return (
    <div>
      <button onClick={() => setList([{ id: Date.now(), text: 'New' }, ...list])}>
        头部插入
      </button>
      {list.map((item, index) => (
        // ✗ 用 index 作 key
        <div key={index}>
          <input defaultValue={item.text} />
          <span>{item.text}</span>
        </div>
      ))}
    </div>
  );
}

复现步骤：① 在第一个输入框里把 A 改写成 "AAA"；② 点击"头部插入"。你会看到 "AAA" 还留在第一个位置，而它本该跟着 id=1 的数据跑到第二行——输入框里的内容错位了。

原因：插入后 key 序列仍是 0,1,2。React 认为"下标 0 还是那个节点"，于是只把 0 号节点的显示文本从 A 改成 New，而 <input> 的 DOM 值由浏览器自己维护（非受控），React 不会重置，便留下了旧的用户输入。

结论只有当列表永不重排、永不增删、永不插入头部时 index 才是安全的。而真实业务里这条假设几乎必被打破。默认就用稳定业务 id。

同理，key={Math.random()} 更糟：每次渲染 key 都变，React 会销毁重建全部节点，输入焦点丢失、动画重播、性能崩塌。

6.6 key 的正确来源与常见坑

key 来源是否可用说明
后端 id / uuid最佳稳定、与渲染顺序无关
业务唯一值（邮箱、SKU）可用保证不重复即可
数组 index仅静态列表动态列表会产生状态错位
Math.random()禁止每次渲染都变，等于全量重建
复合 key可用如 {row.col}，用于虚拟表格单元格
 
// 后端没给 id 时：在"数据落地"处一次性生成，而不是渲染时生成
import { nanoid } from 'nanoid';

function addDraft() {
  // ✓ 创建数据时就带上 id，之后永远稳定
  setRows(prev => [...prev, { id: nanoid(), title: '', qty: 1 }]);
}

其余要点

  • key 只在兄弟节点间有意义：父组件不需要 key；不同数组的 key 重名也无所谓。
  • key 会强制组件重建：想让某组件"彻底重置"（比如切换 tab 后清掉内部状态），改它的 key 是官方推荐手段：<Form key={userId} />。
  • key 不进入 props：props.key 取不到，它是 React 内部字段；要用请另起一个 prop 名（如 id）。
  • Fragment 需要 key 时用全标签：<React.Fragment key={id}>，短语法 <> 无法加属性。
