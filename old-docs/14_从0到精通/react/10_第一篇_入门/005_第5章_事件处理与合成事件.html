5.1 绑定的三种写法

function Toolbar() {
  // ① 具名函数 + 传引用（最推荐：可读、可做依赖优化）
  const handleSave = () => {
    console.log('save');
  };

  return (
    <div>
      <button onClick={handleSave}>保存 ①</button>

      {/* ② 内联箭头函数：需要传参或逻辑极简时用 */}
      <button onClick={() => console.log('save inline')}>保存 ②</button>

      {/* ③ 直接内联语句：不推荐，可读性差 */}
      <button onClick={console.log('bad')}>不要这样 ③</button>
    </div>
  );
}
头号坑写法 ③ 是错的：onClick={fn()} 会在渲染过程中立刻执行 fn，把它的返回值（通常是 undefined）赋给 onClick。现象是"页面一打开就触发一次，之后点击毫无反应"。口诀：onClick 后面一定是函数本身，不是函数调用。

为什么不涉及 this

类组件时代需要用 this.handleClick = this.handleClick.bind(this) 或箭头函数属性来锁死 this；函数组件里根本没有 this，这一整类问题自动消失——这是 Hooks 被广泛接受的直接原因之一。

5.2 SyntheticEvent 合成事件

你拿到的 event 对象并不是浏览器原生的 Event，而是 React 包装的 SyntheticEvent（合成事件）。它做两件事：

  1. 抹平浏览器差异：target、currentTarget、preventDefault() 等在各浏览器表现一致；
  2. 统一接口：所有事件类型（鼠标、键盘、表单、触摸）都继承自同一 SyntheticEvent，都有同样的 stopPropagation 等方法。
function SearchInput() {
  const handleChange = (e) => {
    console.log(e.target.value);      // 输入值
    console.log(e.target.name);       // 表单控件 name，常用于一个 handler 管多个字段
    console.log(e.type);              // 'change'
    console.log(e.nativeEvent);       // 需要时用这个拿原生事件
  };

  const handleKeyDown = (e) => {
    if (e.key === 'Enter') console.log('回车提交');
    if (e.key === 'Escape') e.currentTarget.blur();
  };

  return <input name="kw" onChange={handleChange} onKeyDown={handleKeyDown} />;
}
常用属性/方法说明
e.target触发事件的真实 DOM 元素（可能是子元素）
e.currentTarget绑定事件处理器的那个元素（本组件内的节点）
e.preventDefault()阻止默认行为（表单提交跳转、链接跳转）
e.stopPropagation()阻止继续冒泡
e.nativeEvent原生 Event，需要 passive、isTrusted 等特性时用

历史遗留：事件池（event pooling）

React 16 及以前复用事件对象以节省内存，因此在 setTimeout 里访问 e.target 会得到 null，必须 e.persist()。React 17 起事件池已被移除，现在你可以安全地异步访问事件对象。老教程里的 persist() 在现代代码里不需要了。

5.3 传参的三种姿势

function List({ items, onRemove }) {
  return (
    <ul>
      {/* ① 内联箭头包装：最直观，最常用 */}
      {items.map(it => (
        <li key={it.id}>
          {it.title}
          <button onClick={() => onRemove(it.id)}>删除 ①</button>

          {/* ② bind：可以在定义处固定部分参数 */}
          <button onClick={onRemove.bind(null, it.id)}>删除 ②</button>

          {/* ③ data-* + 事件委托：大量同构子项时的性能写法 */}
          <button data-id={it.id} onClick={handleClickDelegated}>删除 ③</button>
        </li>
      ))}
    </ul>
  );

  function handleClickDelegated(e) {
    onRemove(Number(e.target.dataset.id));
  }
}
方式优点代价
内联箭头直观、灵活每次渲染产生新函数，会让 memo 子组件失效（第 48 章）
bind语法紧凑同样产生新函数，可读性一般
data-*父层一个 handler，子项零函数类型信息丢失，需转字符串
实践建议：普通列表用 ①；成千上万行表格的行操作用 ③ 或虚拟列表（第 50 章）；性能敏感且需要固定引用时配合 useCallback（第 49 章）。

5.4 阻止默认行为与冒泡

function FormDemo() {
  const handleSubmit = (e) => {
    e.preventDefault();        // 阻止表单默认提交导致的整页刷新
    // e.stopPropagation();    // 阻止向父元素冒泡（极少需要）
    const data = new FormData(e.target);
    console.log(Object.fromEntries(data));
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="username" />
      <button type="submit">提交</button>   {/* type="submit" 才触发 */}
    </form>
  );
}

阶段原生写法React JSX 属性

// 典型场景：点击卡片任意处跳转，但点内部按钮不跳转
function Card({ onClick }) {
  return (
    <div onClick={onClick}>
      <h4>标题</h4>
      <button onClick={(e) => { e.stopPropagation(); doDelete(); }}>删除</button>
    </div>
  );
}
坑原生 addEventListener 里写的监听器不受 React 合成事件约束：e.stopPropagation() 能阻止 React 内部冒泡，但无法阻止挂在 document 上的原生监听；反之用原生 stopPropagation 会同时挡住 React 事件。混合使用时务必清楚两套体系的先后顺序（下一节）。

滚动 / 触摸与 passive

touchmove、wheel、scroll 等事件里调用 preventDefault 在现代浏览器中需要 { passive: false }，而 React 的 onWheel 等默认是 passive。确实要阻止滚动时，用 useEffect + el.addEventListener('touchmove', fn, { passive: false })。

5.5 事件委托：React 到底把监听挂在哪

不是给每个 <button onClick> 都挂一个真实监听器——React 用的是事件委托：在容器上挂少量监听器，由它统一分发。

图 5-1 React 17+ 事件委托到根容器（16 及以前委托到 document）

为什么要改（React 17 的重要变更）：

  • 一个页面存在多个 React 版本/多个根时，旧方案事件都挂在 document 上会互相干扰；改到根容器后天然隔离；
  • 混用其他库（jQuery）时，在 #root 外层 stopPropagation 就能彻底阻止 React 收到事件，行为可预测。
// 委托带来的一个重要现象：多个同类型 handler 按 React 树顺序执行
<div onClick={() => console.log('父')}>     {/* 后执行 */}
  <button onClick={() => console.log('子')} />  {/* 先执行 */}
</div>

调试价值：在 DevTools 的 Elements 面板看 #root 的 Event Listeners，你会发现只有 React 挂的少数几个监听器——所有 onClick 都在数据流里，不在 DOM 上。

5.6 常见坑清单

现象原因 / 解法
页面一加载就自动执行点击逻辑onClick={fn()} 传成了调用结果；改为 onClick={fn} 或箭头包装
表单提交后整页刷新没有 e.preventDefault()，或按钮缺 type="button"
异步里读 e.target 为 nullReact 16 事件池遗留；17+ 已修复，升级即可（老项目可 e.persist()）
子元素点击导致父元素同时响应冒泡；在子元素 handler 里 e.stopPropagation()
onScroll 不触发滚动容器必须真的可滚动且有固定高度；监听 window 滚动要用原生监听
移动端滚动里阻止默认无效passive 限制，改用原生监听并显式 { passive: false }
给自定义组件写 onClick 无效自定义组件上的 onClick 只是普通 props，需在内部转发到真实 DOM：<div onClick={props.onClick}>
