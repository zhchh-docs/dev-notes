判断的第一性问题其实是：这个项目的样式规范由谁定义？

  • 有专职 UI/设计并且要长期维护 → CSS Modules / CSS-in-JS，语义类名便于对话与迭代；

9.2 CSS Modules 完整用法

Vite 内置支持：文件名带 .module.css 即自动启用，无需任何配置。

/* Button.module.css */
.btn { padding: 6px 16px; border: 1px solid #d8e2cc; border-radius: 6px; }
.primary { background: #2d6a3f; color: #fff; }
/* 组合：复用其它类的规则 */
.large { composes: btn; padding: 10px 22px; }
/* 引用全局类 */
.icon { composes: app-icon from global; }
/* 局部作用域里写全局选择器 */
.card :global(.ant-btn) { margin-left: 8px; }
import styles from './Button.module.css';

export default function Button({ type = 'primary', size, children }) {
  const cls = [styles.btn, styles[type], size === 'large' && styles.large]
    .filter(Boolean).join(' ');
  return <button className={cls}>{children}</button>;
}

构建后类名会变成 _btn_1a2b3 这类哈希串，因此不同文件中的同名类不会互相污染。

坑 1选择器里写标签选择器（.btn span）没问题，但不能靠外部覆写模块类：哈希类名对外不可见。组件应当在 props 上开放 className 让外部合并（第 4 章准则 6）。
坑 2styles['primary'] 能用，但 styles.primary 更利于 IDE 补全；连字符类名只能用方括号：styles['btn-lg']。建议统一用 camelCase 命名。

9.3 动态类名：clsx / classnames

npm install clsx
import clsx from 'clsx';

function Alert({ type = 'info', muted, className, children }) {
  return (
    <div className={clsx(styles.alert, styles[type], muted && styles.muted, className)}>
      {children}
    </div>
  );
}

// 也支持对象形式，条件复杂时更易读
clsx({
  [styles.btn]: true,
  [styles.disabled]: disabled,
  [styles.large]: size === 'large',
});

原则：类名组装逻辑放进 clsx，JSX 里只留一行。这样 review 时一眼能看出"哪些类在哪些条件下生效"。

9.4 原子类：Tailwind 的心智模型

Tailwind 提供大量单一职责的工具类，直接在 JSX 里组合出样式：

// 不再先写 CSS 再起类名，而是"所见即所得"
<button className="px-4 py-2 rounded-md bg-green-700 text-white hover:bg-green-800
                   disabled:opacity-50 transition-colors">
  提交
</button>
# Vite + React 接入（Tailwind v3）
npm i -D tailwindcss postcss autoprefixer
npx tailwindcss init -p
// tailwind.config.js
export default {
  content: ['./index.html', './src/**/*.{js,ts,jsx,tsx}'],  // 据此摇树，务必写全
  theme: { extend: { colors: { brand: '#2d6a3f' } } },
  plugins: [],
};
维度收益代价
开发速度不用起类名、不用切文件JSX 变长，可读性两极分化
一致性配色/间距被约束在几档设计师给的任意像素值难以还原
产物体积摇树后很小content 配错会导致样式全丢
动态类可用模板字符串不能拼接：`text-${color}` 会被摇树删掉
 
// ✗ 动态拼接无效（构建时扫不到完整类名）
<span className={`text-${size}`} />

// ✓ 建映射表，写出完整字符串
const SIZE = { sm: 'text-sm', md: 'text-base', lg: 'text-lg' };
<span className={SIZE[size]} />

9.5 CSS 变量与主题切换

主题切换最省心的实现是 CSS 自定义属性：变量随根节点切换而全局生效，无需 React 重渲染。

/* theme.css */
:root {
  --color-bg: #ffffff;
  --color-text: #1f2e1f;
  --color-primary: #2d6a3f;
}
[data-theme='dark'] {
  --color-bg: #152010;
  --color-text: #d8e2cc;
  --color-primary: #4f8a63;
}
.card { background: var(--color-bg); color: var(--color-text); }
function ThemeToggle() {
  const [dark, setDark] = useState(false);

  useEffect(() => {
    document.documentElement.dataset.theme = dark ? 'dark' : 'light';
  }, [dark]);

  return <button onClick={() => setDark(d => !d)}>切换主题</button>;
}

关键点：把主题写在 DOM 属性上，而不是往每个组件传 props——后者会让主题变更引发全树重渲染。这一点在第 21 章（Context 粒度）会再回来。

9.6 常见坑与选型清单

  1. 样式不生效：检查优先级（第三方库用 !important 时，业务侧可用 :where() 降低自身优先级、或提高层级）；
  2. CSS Modules 类名冲突：只可能发生在同一文件内；:global 声明的类会逃逸出作用域，慎用；
  3. 全局样式放哪：src/index.css（reset、字体、变量），组件样式一律 Modules；
  4. 动态内联值的性能：拖拽/动画场景直接改 style 会频繁触发样式计算，宜用 CSS 变量 + transform；
  5. 产物体积：Tailwind 配好 content；Modules 天然按需。
本书默认：后续章节示例统一使用 CSS Modules 的类名写法（如 <div className={styles.panel}>），并在必要时加一行 Tailwind 等价写法。
