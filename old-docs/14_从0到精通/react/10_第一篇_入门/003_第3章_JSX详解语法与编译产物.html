◆本章目标

  • 明确回答"JSX 到底是什么"——它不是模板引擎、不是字符串，而是编译成函数调用的语法糖；
  • 能手写 JSX 对应的 jsx() 调用产物，看得懂 type/props/children 三层结构；

3.1 JSX 不是模板，是语法糖

先摆三条容易混淆的事实：

  1. JSX 不是 HTML 字符串。<h1>Hi</h1> 编译后不是 "<h1>Hi</h1>"，而是一个描述界面的 JS 对象（React 元素）。
  2. JSX 没有被浏览器直接支持。浏览器只认识 JS 编译器插件（Babel / SWC / esbuild）在运行前把它转成普通 JS。这就是为什么"不配插件就无法使用 JSX"。
  3. 它不是必需品，但很难不用。你可以完全不用 JSX 写 React（第 2 点的函数调用形式），只是可读性极差。

JSX 的设计初衷是：把"描述 UI 结构"这件事的语法成本降到接近 HTML，同时保留 JS 的全部能力（变量、循环、条件、函数）。

一句话：JSX = 用 XML 风格写 JS 函数调用。看清这一层，后面的写法与报错都不再神秘。

3.2 看编译产物：jsx() 调用

这段 JSX：

const el = <h1 className="title">Hello, {name}</h1>;

在 React 17 之后（automatic runtime，也是 Vite 模板默认）被编译为：

import { jsx as _jsx } from 'react/jsx-runtime';

const el = _jsx('h1', { className: 'title', children: ['Hello, ', name] });

而更早的 classic runtime（React 16 及以前、部分老教程）会编译为：

const el = React.createElement('h1', { className: 'title' }, 'Hello, ', name);

两者差别：

模式automatic（17+ 默认）classic（老版）
需要手写 import React不需要必须 import React from 'react'
编译函数react/jsx-runtime 的 jsx()React.createElement()
性能略优（减少一层属性处理）—
坑 1网上老教程里"必须写 import React from 'react' 否则报 React is not defined"的说法，在现代 + Vite 项目中已不成立。反过来，如果你在 Vite 项目里删掉这行却报错，说明配的是 classic runtime（检查构建配置或老版 babel 配置）。

深入理解 Element 对象

const el = <button disabled>确定</button>;

console.log(el);
// {
//   type: 'button',                 // 标签名 / 组件函数
//   key: null,
//   ref: null,
//   props: { disabled: true, children: '确定' },
//   $$typeof: Symbol(react.element) // 防 XSS 的内部标记
// }

记住这个结构：元素 = type（是什么）+ props（属性与子节点）+ key/ref。第五篇讲 Fiber（{#sec}第 39 章）时，会发现 Fiber 节点正是基于这些信息生成的。

// 完全不用 JSX 也能写 React —— 证明 JSX 只是糖
const el2 = { type: 'button', props: { children: '确定', disabled: true } };

// 嵌套结构的写法
const list = _jsx('ul', { children: [
  _jsx('li', { children: 'A' }),
  _jsx('li', { children: 'B' }),
]});

3.3 三种插值写法

JSX 里用 { } 进入"JS 世界"，且只能放表达式（能求值出结果的代码片段），不能放语句（if、for、switch 直接写会报错）。

① 内容插值

const user = { name: '张三', vip: true, score: 88 };

<p>姓名：{user.name}</p>
<p>等级：{user.vip ? 'VIP' : '普通'}</p>
<p>学分：{user.score + 2}</p>
<p>标签：{formatTag(user)}</p>   {/* 函数调用也可以，只要是表达式 */}

② 属性插值（引号换成花括号）

const avatar = 'https://x.com/a.png';
const id = 'user-1';

<img src={avatar} alt="头像" data-id={id} />
<div title={undefined}>title 为 undefined 时不出现在 DOM 上</div>

写法区分：src="abc" 传的是字符串字面量；src={avatar} 传的是变量的值。写错就会把变量名当成字面字符串传下去。

③ 样式插值（两个花括号不是语法特殊）

// 外层 {}：进入 JS；内层 { color: 'red' }：一个普通对象字面量
<p style={{ color: 'red', fontSize: 18 }}>红色 18px</p>

// 提取出来更清晰（推荐）
const dangerStyle = { color: '#b91c1c', fontWeight: 700 };
<p style={dangerStyle}>危险</p>

style 用 camelCase（fontSize 而非 font-size），数字会被自动加上 px（0 不加）。

为什么 for 不能直接写在 JSX 里

// ✗ 错误：for 是语句，JSX 里放不了
<ul>{ for (let i = 0; i < 3; i++) <li>{i}</li> }</ul>

// ✓ 正确：用表达式产出数组 —— map
<ul>{ [0, 1, 2].map(i => <li key={i}>{i}</li>) }</ul>

判断口诀："能不能被 const x = <这里> 承接？" —— 能就是表达式，可以放进 {}。

3.4 属性命名规则

JSX 属性名用 camelCase，与 HTML 习惯不同。差异来自"JSX 最终是 JS 对象属性"这一事实——JS 里保留字、连字符都不友好。

HTML 写法JSX 写法原因
class="box"className="box"class 是 JS 关键字
for="name"htmlFor="name"for 是 JS 关键字
onclick="fn()"onClick={fn}React 合成事件统一 camelCase，且传函数本身而非调用
tabindex="1"tabIndex={1}camelCase 统一
readonlyreadOnly同上
data-id="1"data-id="1"（不变）自定义属性保持原样
<input disabled><input disabled /> 或 disabled={true}布尔属性：给值即为真
 
// 常见坑：值是 false 时 attribute 不会出现在 DOM 上
<input disabled={false} />        // DOM：<input>（无 disabled）
<input disabled={'false'} />      // DOM：<input disabled>（字符串 'false' 是真值！）

// spread 批量传属性（写组件封装时高频）
const inputProps = { type: 'text', placeholder: '请输入', maxLength: 20 };
<input {...inputProps} value={v} onChange={handle} />
坑 2checked/value 这类"受控属性"一旦给了值就必须配 onChange，否则会报 You provided a `value` prop to a form field without an `onChange` handler——第 8 章详解。

3.5 子节点、Fragment 与渲染规则

组件必须返回单个根（或用 Fragment）

// ✗ 报错：Adjacent JSX elements must be wrapped in an enclosing tag
function Bad() {
  return <h1>标题</h1><p>正文</p>;
}

// ✓ 方案一： Fragment 全标签
function Good1() {
  return (
    <React.Fragment>
      <h1>标题</h1>
      <p>正文</p>
    </React.Fragment>
  );
}

// ✓ 方案二：语法糖（最常用），唯一可用属性是 key
function Good2() {
  return (
    <>
      <h1>标题</h1>
      <p>正文</p>
    </>
  );
}

Fragment 的价值：不在真实 DOM 里多产生一层 div。写表格、Flex 布局时这一层多余容器会破坏样式和结构。

渲染真值表（务必背下来）

插值内容渲染结果典型踩坑
{false}什么都不渲染本想显示 "false"
{null} / {undefined}什么都不渲染条件渲染的自然用法
{0}渲染出 0见下方劝退表
{''} / {[]}渲染空内容—
{NaN}渲染 "NaN"计算错误直接上屏
{{ a: 1 }}报错对象不能作为 React 子节点
 
const items = [];

// ✗ 经典 bug：空列表时屏幕上赫然显示一个 "0"
<div>{items.length && <List items={items} />}</div>

// ✓ 修法一：布尔化
<div>{items.length > 0 && <List items={items} />}</div>
// ✓ 修法二：!! 转 Boolean
<div>{!!items.length && <List items={items} />}</div>

条件渲染的三种写法

// 1. 三元：二选一
{isLogin ? <UserPanel /> : <LoginBtn />}

// 2. &&：要不要（注意上面说的 0 陷阱）
{hasMore && <LoadMore />}

// 3. 早返回 / 提取变量：分支复杂时使用
if (loading) return <Skeleton />;
if (error) return <ErrorBox msg={error} />;
return <Content data={data} />;
坑 3嵌套三元才是可读性的头号杀手。"{a ? <X/> : b ? <Y/> : c ? <Z/> : null}" 这种写法一旦出现就该拆函数调用或组件。第 6 章给重构手法。

报错信息（关键词）原因与解法

统一对策：浏览器控制台的 React 报错通常带具体组件名与行号，且多数附有大文档链接。养成读完整报错的习惯，效率会高于任何搜索。
