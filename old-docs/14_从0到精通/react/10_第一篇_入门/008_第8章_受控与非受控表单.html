第 8 章 受控与非受控表单

8.1 受控组件：数据唯一真源

受控组件：表单元素的值由 React 的 state 决定，用户输入通过 onChange 写回 state。它完全符合第 1 章的 UI = f(state)——输入框显示的永远是 state 的投影。

function LoginForm() {
  const [form, setForm] = useState({ username: '', password: '' });

  const update = (key) => (e) => setForm(f => ({ ...f, [key]: e.target.value }));

  return (
    <form onSubmit={submit}>
      <input value={form.username} onChange={update('username')} placeholder="用户名" />
      <input type="password" value={form.password} onChange={update('password')} />
      <button type="submit">登录</button>
    </form>
  );
}
受控的收益：值随时可用、可随时改写。因为输入框内容就是 state，你可以轻松做"输入即时转大写""禁用某些字符""根据 A 字段自动填 B 字段"，甚至做"撤销/重做"。
坑 1给了 value 却没给 onChange，输入框会变成只读且带警告（You provided a `value` prop to a form field without an `onChange` handler）。若还需要"多个更新累加"，务必用第 7 章讲的函数式更新。

8.2 非受控组件：让 DOM 自己管

非受控组件：不给 value，只给 defaultValue，值由 DOM 自己维护，需要时用 ref 读取。

function SearchBar({ onSearch }) {
  const inputRef = useRef(null);

  const submit = (e) => {
    e.preventDefault();
    onSearch(inputRef.current.value);   // 用时才读，渲染期间不参与
  };

  return (
    <form onSubmit={submit}>
      <input ref={inputRef} defaultValue="" placeholder="输入关键词" />
      <button>搜索</button>
    </form>
  );
}
维度受控非受控
值存在哪React stateDOM 节点
每次输入是否重渲染是否
值能否被程序随时改写可以只能操作 DOM
适合场景需要联动/校验/格式化的表单搜索框、第三方插件嵌入、大表单性能敏感

默认选择受控；只有当你明确意识到"每次输入都重渲染"成为瓶颈，或必须与某个直接操作 DOM 的第三方库协作时，才考虑非受控。

file input 只能非受控：出于安全，浏览器不允许 JS 设置 <input type="file"> 的值，只能用 ref 读取 files[0]，或第 61 章讲的拖拽/粘贴上传。

8.3 各类表单元素的正确写法

元素取值受控写法要点
input[type=text]e.target.valuevalue + onChange
textareae.target.value用 value 属性，而不是子节点
checkboxe.target.checkedchecked + onChange
radioe.target.value同组 name 相同，checked={val===item.value}
selecte.target.value写在 <select value> 上，而非 option 的 selected
select multipleArray.from(target.selectedOptions).map(o => o.value)value 为数组
filee.target.files[0]只能非受控
 
function ProfileForm() {
  const [form, setForm] = useState({
    name: '', gender: 'male', agree: false, city: 'bj', tags: [], avatar: null,
  });
  const patch = (k, v) => setForm(f => ({ ...f, [k]: v }));

  return (
    <form>
      <input value={form.name} onChange={e => patch('name', e.target.value)} />

      <label><input type="radio" name="gender" value="male"
        checked={form.gender === 'male'} onChange={e => patch('gender', e.target.value)} />男</label>
      <label><input type="radio" name="gender" value="female"
        checked={form.gender === 'female'} onChange={e => patch('gender', e.target.value)} />女</label>

      <label><input type="checkbox"
        checked={form.agree} onChange={e => patch('agree', e.target.checked)} />同意条款</label>

      <select value={form.city} onChange={e => patch('city', e.target.value)}>
        <option value="bj">北京</option>
        <option value="sh">上海</option>
      </select>

      <select multiple value={form.tags}
        onChange={e => patch('tags', Array.from(e.target.selectedOptions, o => o.value))}>
        <option value="js">JS</option><option value="ts">TS</option>
      </select>

      <input type="file" onChange={e => patch('avatar', e.target.files[0])} />
    </form>
  );
}

8.4 一个 handler 管多个字段

给十个字段写十个 useState 是典型的新手代码。更合适的做法有两种：

方案一：name 属性 + 计算属性名

const [form, setForm] = useState({ username: '', email: '', phone: '' });

const handleChange = (e) => {
  const { name, value, type, checked } = e.target;
  setForm(f => ({ ...f, [name]: type === 'checkbox' ? checked : value }));
};

<input name="username" value={form.username} onChange={handleChange} />
<input name="email"    value={form.email}    onChange={handleChange} />

方案二：FormData（原生 API，适合字段多且无需即时联动）

function submit(e) {
  e.preventDefault();
  const data = Object.fromEntries(new FormData(e.target));
  // { username: 'zs', email: 'a@b.com', ... }
  onSubmit(data);
}

注意：FormData 只能拿到带 name 且非禁用的字段；checkbox 未勾选时不出现在结果里，需要的话显式处理。

8.5 提交、校验与错误提示

function RegisterForm() {
  const [form, setForm] = useState({ email: '', password: '', confirm: '' });
  const [errors, setErrors] = useState({});
  const [submitting, setSubmitting] = useState(false);

  const validate = (f) => {
    const err = {};
    if (!/^\S+@\S+\.\S+$/.test(f.email)) err.email = '邮箱格式不正确';
    if (f.password.length < 8) err.password = '密码至少 8 位';
    if (f.password !== f.confirm) err.confirm = '两次输入不一致';
    return err;
  };

  const submit = async (e) => {
    e.preventDefault();
    const err = validate(form);
    setErrors(err);
    if (Object.keys(err).length) return;      // 校验不过不提交

    setSubmitting(true);
    try {
      await api.register(form);
    } finally {
      setSubmitting(false);                   // 无论成败都要结束提交态
    }
  };

  return (
    <form onSubmit={submit} noValidate>
      <input name="email" value={form.email}
        onChange={e => setForm(f => ({ ...f, email: e.target.value }))} />
      {errors.email && <p className="error">{errors.email}</p>}
      <button disabled={submitting}>{submitting ? '提交中…' : '注册'}</button>
    </form>
  );
}
校验时机优点缺点
提交时实现最简单，不打断输入反馈滞后
失焦时（onBlur）体验好，干扰小需额外状态记录 touched
输入时（onChange）反馈即时刚输第一个字符就报红，体验差
实践推荐：touched 之后才报错（首次不改脏不提示）。这套"touched + dirty + errors"的组合正是 react-hook-form 的核心，详见第 35、36 章（与 zod 配合做到"校验规则即类型"）。

8.6 选型建议与常见坑

  • 小表单（≤ 5 个字段）：手写受控即可，代码量比引入库还少。
  • 中大型表单：react-hook-form（非受控思路 + 精确重渲染）性能与开发体验双优。
  • 跨字段联动强的动态表单：受控 + 状态机心智，或 RHF 的 watch。
  • 校验库：zod / yup，产出 schema 同时喂给 TS 类型。
坑清单
  • value 忘了配 onChange → 输入框不能打字；
  • defaultValue 初始值来自异步数据时：数据回来再渲染也改不动默认值，需 key={data.id} 重置或改为受控；
  • 把受控值初始化为 null（而非空字符串）会报 changing an uncontrolled input to be controlled；
  • disabled 的字段不会被 FormData 收集；
  • 提交后 finally 里还原 submitting，否则按钮永久 loading。

✓ 本章小结

要点一句话
受控value + onChange，state 是唯一真源，默认方案
非受控defaultValue + ref，DOM 自管；file input 只能非受控
checkbox/radio取 checked；radio 靠 name 分组
selectvalue 写在 select 上，多选取 selectedOptions
多字段技巧name + 计算属性名，或 FormData 一次性收集
校验时机touched 后再报错；复杂表单交给 RHF + zod
