A.1基础状态与副作用 Hooks

这一组是函数组件日常使用频率最高的 Hooks，覆盖状态、副作用、引用、上下文与缓存。

Hooks签名 / 关键参数行为要点所在章节
useState const [state, setState] = useState(initialState) 返回当前状态与更新函数；setState(next) 可传新值，也可传 setState(prev => next) 函数式更新；更新触发重渲染；状态不可变更新，不直接改写原值。 见第 7 章
useEffect useEffect(setup, dependencies?) 把组件与外部系统同步；setup 可返回 cleanup；不传依赖数组：每次渲染后执行；[]：仅挂载后执行；依赖变化：先执行旧 cleanup 再执行新 setup；提交后异步执行。 见第 10、11 章
useLayoutEffect useLayoutEffect(setup, dependencies?) 签名与依赖规则同 useEffect，但在浏览器绘制前同步执行；适合测量布局后立刻修正 DOM，避免视觉跳动；滥用会阻塞绘制，常规副作用仍用 useEffect。 见第 12 章
useRef const ref = useRef(initialValue) 返回带 .current 的可变对象；修改 ref.current 不触发重渲染；两类用途：保存 DOM 节点引用、在多次渲染之间保存不参与渲染的可变值。 见第 13 章
useContext const value = useContext(SomeContext) 读取组件树中最近一层 Provider 提供的值；Provider 值变化会让所有消费该 Context 的组件重渲染；粒度需控制，避免大范围订阅。 见第 14、21 章
useReducer const [state, dispatch] = useReducer(reducer, initialArg, init?) reducer(state, action) => newState 为纯函数；dispatch(action) 派发动作；适合多字段联动、状态转移明确的状态机；可替代部分 useState 组合。 见第 15 章
useMemo const memoizedValue = useMemo(calculateValue, dependencies) 缓存昂贵计算的结果；依赖不变时复用上一次的返回值；依赖变化才重新计算；不要为"省几行代码"到处包裹，先测量是否真的昂贵。 见第 49 章
useCallback const memoizedFn = useCallback(fn, dependencies) 缓存函数引用；等价于 useMemo(() => fn, dependencies)；配合 memo 子组件稳定回调引用，避免因函数引用每次新建导致子组件无效重渲染。 见第 49 章

基础写法骨架

import { useState, useEffect, useReducer } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  // 函数式更新：基于前一个状态计算新状态
  const inc = () => setCount(prev => prev + 1);

  useEffect(() => {
    document.title = `计数：${count}`;
    // 本场景没有需要清理的外部系统，故不返回 cleanup
  }, [count]);

  return <button onClick={inc}>{count}</button>;
}

function reducer(state, action) {
  switch (action.type) {
    case 'add': return { n: state.n + 1 };
    case 'reset': return { n: 0 };
    default: return state;
  }
}

function Machine() {
  const [state, dispatch] = useReducer(reducer, { n: 0 });
  return (
    <div>
      <span>{state.n}</span>
      <button onClick={() => dispatch({ type: 'add' })}>加一</button>
      <button onClick={() => dispatch({ type: 'reset' })}>重置</button>
    </div>
  );
}
易错点：useMemo 与 useCallback 不是"默认性能优化"，它们本身也有依赖比较与缓存的成本；先定位真实瓶颈，再决定是否包裹（见第 49 章）。

A.2并发与高级 Hooks

这一组面向并发渲染、外部 store 订阅、服务端一致性等进阶场景，日常业务中按需使用。

Hooks签名 / 关键参数行为要点所在章节
useTransition const [isPending, startTransition] = useTransition() startTransition(() => { setHeavyState(...) }) 把其中的状态更新标记为非紧急过渡；过渡期间 isPending 为 true；过渡更新可被紧急更新打断。 见第 45 章
useDeferredValue const deferredValue = useDeferredValue(value, initialValue?) 返回滞后于 value 的副本；输入变化后先保留旧值，主线程空闲时再更新；常用于输入框即时响应、结果列表延后刷新。 见第 45 章
useId const id = useId() 生成在服务端渲染与客户端水合之间保持一致的唯一 ID；用于表单 label 与控件关联等需要稳定标识的场景；不能当作列表 key 使用。 见第 53 章
useSyncExternalStore const snapshot = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?) 订阅 React 之外的外部 store；subscribe 注册变更回调，getSnapshot 返回不可变快照；保证读取一致性、避免 tearing；第三方状态库内部常基于它实现。 见第 22 章
useInsertionEffect useInsertionEffect(setup, dependencies?) 在布局副作用之前执行，专供 CSS-in-JS 库向 DOM 注入样式；普通业务组件不应使用，组件内副作用请用 useEffect 或 useLayoutEffect。 见第 9 章
useDebugValue useDebugValue(value, format?) 为自定义 Hook 在 React DevTools 中显示调试标签；format 为可选格式化函数；不影响组件运行逻辑。 见第 16 章 
import { useTransition, useDeferredValue } from 'react';

function SearchPage({ keyword, results }) {
  const [isPending, startTransition] = useTransition();
  const deferredKeyword = useDeferredValue(keyword);

  // 输入框保持紧急更新；结果列表使用滞后值，避免大列表阻塞输入
  const shownResults = results.filter(r => r.includes(deferredKeyword));

  return (
    <div>
      <input value={keyword} onChange={e => startTransition(() => setKeyword(e.target.value))} />
      {isPending ? '加载中…' : <List items={shownResults} />}
    </div>
  );
}

A.3React 核心 API

除 Hooks 外，本书用到的 React 顶层接口与组件级 API 汇总如下。

API签名 / 关键参数行为要点所在章节
startTransition startTransition(scope) 独立于组件的非紧急更新标记函数；scope 回调内的状态更新被标记为过渡；与 useTransition 的区别是它不带 isPending 状态。 见第 45 章
lazy const C = lazy(() => import('./C')) 定义按需加载的组件；工厂函数返回 Promise，解析后得到含 default 导出的模块；lazy 组件必须包裹在 Suspense 内使用。 见第 33、51 章
Suspense <Suspense fallback={<Loading />}>…</Suspense> 在子组件（懒加载组件、尚未就绪的数据请求）完成期间显示 fallback；可嵌套分层显示加载态。 见第 33、46 章
StrictMode <StrictMode><App /></StrictMode> 仅在开发模式下启用：双重调用组件渲染函数、函数组件内的 effect setup/cleanup，提前暴露不纯逻辑与缺失清理；生产环境不产生额外行为。 见第 19 章
createRoot const root = createRoot(domNode); root.render(<App />) React 18 创建并发根节点的入口；替代旧版 ReactDOM.render；需要先取得挂载容器 DOM，再调用 render 挂载组件树。 见第 2 章 
import { StrictMode, Suspense, lazy, createRoot } from 'react';
import { createRoot as rootAPI } from 'react-dom/client';

const HeavyChart = lazy(() => import('./HeavyChart'));

function App() {
  return (
    <Suspense fallback={<div>图表加载中…</div>}>
      <HeavyChart />
    </Suspense>
  );
}

const container = document.getElementById('root');
const root = createRoot(container);
root.render(
  <StrictMode>
    <App />
  </StrictMode>
);
版本口径：以上接口对应 React 18/19 主线；旧版类组件生命周期（componentDidMount 等）只在第 10 章做对照讲解，不在日常速查范围内。

A.4状态管理生态 API

第三篇状态分层落地时用到的 Zustand、Redux Toolkit、RTK Query 与 TanStack Query 关键接口。

A.4.1 Zustand

API签名 / 关键参数行为要点所在章节
create const useStore = create((set, get) => ({ … })) 创建全局 store Hook；set(partial, replace?) 更新状态，get() 读取当前状态；组件内用 useStore(selector) 挑选切片，选择器返回引用不变时不触发重渲染。 见第 22 章
getState / setState useStore.getState()、useStore.setState(partial) 在组件之外读取或更新 store；subscribe(listener) 可手动订阅变更。 见第 22 章 
import { create } from 'zustand';

const useCart = create((set) => ({
  items: [],
  addItem: (item) => set((state) => ({ items: [...state.items, item] })),
  clear: () => set({ items: [] }),
}));

// 组件内：只订阅需要的切片
function CartPanel() {
  const count = useCart((s) => s.items.length);
  const clear = useCart((s) => s.clear);
  return <button onClick={clear}>清空购物车（{count} 件）</button>;
}

A.4.2 Redux Toolkit 与 RTK Query

API签名 / 关键参数行为要点所在章节
configureStore configureStore({ reducer: { … }, middleware? }) 创建 Redux store，内置开发者工具、不可变更新检查与常用中间件；reducer 为各切片 reducer 的映射对象。 见第 23 章
createSlice createSlice({ name, initialState, reducers }) 生成切片：自动派发 action 类型字符串并导出对应 action creator；reducers 内可直接"改写"写法，由内部工具转为不可变更新；返回 actions 与 reducer。 见第 23 章
createAsyncThunk createAsyncThunk(type, payloadCreator) 创建处理异步逻辑的 thunk，自动派发 pending / fulfilled / rejected 动作；在切片的 extraReducers 中订阅这些动作更新状态。 见第 23 章
createApi createApi({ reducerPath, baseQuery, endpoints }) RTK Query 定义服务端数据接口；endpoints 中声明 query 或 mutation，自动生成带缓存能力的查询与变更 hooks。 见第 24 章 
import { configureStore, createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; },
    decrement: (state) => { state.value -= 1; },
  },
});

export const { increment, decrement } = counterSlice.actions;

export const store = configureStore({
  reducer: { counter: counterSlice.reducer },
});

A.4.3 TanStack Query v5

API签名 / 关键参数行为要点所在章节
useQuery useQuery({ queryKey, queryFn, staleTime?, gcTime?, placeholderData? }) 声明式查询服务端数据；返回 data / isPending / isError / error / isFetching 等状态；queryKey 作为缓存标识数组；v5 中缓存时长参数为 gcTime（旧名 cacheTime 已更名）。 见第 25、26 章
useMutation useMutation({ mutationFn, onSuccess?, onError? }) 处理新增、修改、删除等变更操作；返回 mutate / mutateAsync / isPending；配合 onSuccess 使对应 queryKey 缓存失效刷新。 见第 27 章
useQueryClient const client = useQueryClient() 取得查询客户端实例；client.invalidateQueries({ queryKey }) 标记缓存过期并重新拉取；也可手动更新缓存数据。 见第 26、27 章 
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';

function UserList() {
  const { data, isPending, isError } = useQuery({
    queryKey: ['users'],
    queryFn: () => fetch('/api/users').then((r) => r.json()),
  });

  const client = useQueryClient();
  const removeUser = useMutation({
    mutationFn: (id) => fetch(`/api/users/${id}`, { method: 'DELETE' }),
    onSuccess: () => client.invalidateQueries({ queryKey: ['users'] }),
  });

  if (isPending) return <p>加载中…</p>;
  if (isError) return <p>加载失败</p>;
  return (
    <ul>
      {data.map((u) => (
        <li key={u.id}>{u.name}
          <button onClick={() => removeUser.mutate(u.id)}>删除</button>
        </li>
      ))}
    </ul>
  );
}

A.5路由生态 API

第四篇使用 React Router v7 声明式路由方案，关键接口如下。

API签名 / 关键参数行为要点所在章节
createBrowserRouter const router = createBrowserRouter(routes) 基于浏览器 History API 创建路由实例；routes 为路由对象数组，可嵌套 children 声明层级。 见第 29 章
RouterProvider <RouterProvider router={router} /> 把路由实例挂载到应用根节点，渲染当前匹配路由对应的组件树。 见第 29 章
Outlet <Outlet /> 嵌套路由的占位组件：父路由组件中渲染子路由匹配结果的位置。 见第 30 章
useNavigate const navigate = useNavigate(); navigate(to, options?) 编程式导航；options 可含 replace、state；守卫校验失败、操作成功后用于跳转。 见第 32 章
useParams const params = useParams() 读取当前路由的动态参数（如 /user/:id 中的 id）。 见第 31 章
useLocation const location = useLocation() 读取当前 URL 对应的 location 对象，含 pathname、search、state 等。 见第 31 章
loader / action 路由对象上的 loader、action 函数 loader 在路由匹配后、渲染前加载数据；action 处理路由表单提交；组件内通过 useLoaderData() 读取 loader 返回值。 见第 34 章
redirect redirect(url, init?) 在 loader / action 中抛出重定向响应，由路由层跳转到目标路径。 见第 32、34 章
NavLink <NavLink to={to}>…</NavLink> 带激活态样式的导航链接；当前路由匹配时自动附加激活类名，可自定义 className 或 style 函数。 见第 29 章 
import { createBrowserRouter, RouterProvider, Outlet, useParams, NavLink } from 'react-router-dom';

function Layout() {
  return (
    <div>
      <nav>
        <NavLink to="/" end>首页</NavLink>
        <NavLink to="/users">用户</NavLink>
      </nav>
      <Outlet />
    </div>
  );
}

function UserDetail() {
  const { id } = useParams();
  return <p>用户 ID：{id}</p>;
}

const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />,
    children: [
      { path: 'users/:id', element: <UserDetail /> },
    ],
  },
]);

export default function App() {
  return <RouterProvider router={router} />;
}

A.6表单与其他生态 API

表单、列表虚拟化与第七篇实战中常用的生态库关键接口。

API签名 / 关键参数行为要点所在章节
useForm const { register, handleSubmit, formState, control } = useForm({ resolver? }) react-hook-form 表单入口；register(name) 把原生输入框接入表单；handleSubmit(onValid) 返回提交处理器；formState.errors 存放校验错误；controller 模式通过 control 接入受控组件。 见第 35 章
zodResolver resolver: zodResolver(schema) 把 zod schema 接到 useForm，表单校验规则集中声明在 schema 中，可同时推导 TypeScript 类型。 见第 36 章
FixedSizeList <FixedSizeList height width itemCount itemSize renderRow /> react-window 固定行高列表虚拟化组件；只渲染可视区域附近的行；renderRow 接收 { index, style } 返回行节点；不等高场景使用 VariableSizeList。 见第 50 章
ConfigProvider <ConfigProvider theme={{ token }} locale={…}>…</ConfigProvider> Ant Design 全局配置容器；集中注入主题 token、语言包等，后代组件自动继承。 见第 56 章
useTranslation const { t, i18n } = useTranslation() react-i18next 入口；t(key, options?) 按当前语言读取文案；i18n.changeLanguage(lng) 切换语言。 见第 59 章
echarts.init 等 echarts.init(el)、chart.setOption(option)、chart.dispose()、chart.resize() ECharts 实例生命周期：初始化绑定 DOM、传入配置、销毁释放、窗口尺寸变化后重算；实例清理须在 effect cleanup 中完成。 见第 60 章
RTL 测试接口 render(<App />)、screen.getByRole()、fireEvent、userEvent、waitFor React Testing Library：渲染组件并以用户视角查询元素；userEvent 模拟真实交互；waitFor 等待异步断言条件成立。 见第 62 章

表单与虚拟化骨架

import { useForm } from 'react-hook-form';
import { FixedSizeList } from 'react-window';

function ProfileForm() {
  const { register, handleSubmit, formState: { errors } } = useForm();
  const onSubmit = (data) => console.log(data);
  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('name', { required: '姓名必填' })} />
      {errors.name && <p>{errors.name.message}</p>}
      <button type="submit">提交</button>
    </form>
  );
}

function BigList({ rows }) {
  return (
    <FixedSizeList
      height={480}
      width="100%"
      itemCount={rows.length}
      itemSize={36}
      renderRow={({ index, style }) => (
        <div style={style}>{rows[index].label}</div>
      )}
    />
  );
}
