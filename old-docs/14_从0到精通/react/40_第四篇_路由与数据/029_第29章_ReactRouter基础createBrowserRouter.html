◆本章目标

  • 理解单页应用（SPA）中前端路由的职责：把 URL 映射到要渲染的组件，页面切换不重新请求整页 HTML；
  • 能用 createBrowserRouter 配合 RouterProvider 搭出一个三条路由的最小工程；
  • 说清 route 对象上 path / element / index / children / loader / action / errorElement / lazy 各自的归属章节；
  • 掌握 Link、NavLink、useNavigate 的使用场景与关键参数；
  • 知道 History 模式与 Hash 模式的部署差异，能定位「刷新子路径 404」「整页刷新」等典型故障。

29.1 为什么需要前端路由

传统多页应用中，URL 是服务器上的一个文件或一条后端映射：浏览器输入地址、请求整页 HTML、服务器返回新页面、浏览器卸载旧页面再绘制新页面。React SPA 只有一个 HTML 入口，所有组件都在同一个运行时里，URL 变化由前端自己决定渲染哪个组件，这层映射就是前端路由。

路由的抽象可以跨框架对照：Vue 的 vue-router 在浏览器端把 URL 映射到组件；Java Spring MVC 的 @RequestMapping 在服务端把 URL 映射到 Controller 方法；React Router 与 vue-router 同属浏览器端这一层，API 思维相近——路径表、嵌套层级、参数、守卫、重定向一一对应。
维度传统多页应用SPA + 前端路由
页面切换浏览器整页请求 HTML，旧页面被卸载组件级切换，运行时与内存状态保留
URL 映射位置服务器路由表 / 文件系统浏览器端 route 配置表
切换体验白屏等待网络往返本地切换，可做过渡动画与缓存
刷新行为服务器重新返回整页回到入口 HTML，再由路由表重建当前界面
典型技术JSP、Thymeleaf、多页静态站React Router、vue-router、Angular Router

React Router 当前主流版本为 v7，它提供两类 API：一类是本篇重点的数据路由（data router）——路由配置挂在 route 对象上，loader、action、errorElement、嵌套布局都围绕它组织；另一类是早期的 BrowserRouter + Routes 元素写法，仍可运行，但官方推荐新项目使用数据路由。

阅读提示：本章只建立路由底座；数据加载（loader）在第 34 章，表单提交（action）在第 34、35 章，错误降级（errorElement）在第 37 章，懒加载（lazy）在第 33 章。本章先认识字段名与归属，不展开内部机制。

29.2 安装与最小可用工程

先在 Vite 工程中安装路由依赖：

npm install react-router-dom

v7 中 react-router-dom 与 react-router 提供同一套数据路由 API，日常开发从 react-router-dom 导入即可。最小工程的目录约定如下：

src/
├── main.tsx              # 入口：创建路由并挂载 RouterProvider
├── pages/
│   ├── Home.tsx
│   ├── About.tsx
│   └── Contact.tsx
└── router.tsx            # 也可单独把 route 配置抽到这里

入口文件用 createBrowserRouter 定义路由表，再用 RouterProvider 把路由器交给应用根节点：

import React from 'react'
import ReactDOM from 'react-dom/client'
import { createBrowserRouter, RouterProvider } from 'react-router-dom'
import Home from './pages/Home'
import About from './pages/About'
import Contact from './pages/Contact'

// 路由表：每条记录描述「URL 路径 → 渲染哪个组件」
const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/about', element: <About /> },
  { path: '/contact', element: <Contact /> },
])

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
)
RouterProvider 是整个路由上下文的提供者：导航组件、路由 Hooks、loader 与错误边界都必须处在它的子树内，否则抛出 "useNavigate must be used within a RouterProvider" 一类错误。

三个页面组件各自返回标题与一段说明即可，例如 Home.tsx：

export default function Home() {
  return (
    <main>
      <h2>首页</h2>
      <p>这是路径 / 匹配到的页面组件。</p>
    </main>
  )
}
为什么不用老写法 <BrowserRouter><Routes>？v7 官方推荐数据路由：loader、action、errorElement、嵌套布局与数据预取都绑定在 route 对象上；老的元素式写法虽然兼容，但本篇统一使用数据路由口径，避免两套 API 混淆。

29.3 route 对象字段一览

一条 route 对象就是路由表中的一行。下面这张表把 v7 route 对象的常用字段一次列全，并标注归属章节，后续各章只在对应小节深入。

字段类型 / 取值职责深入章节
path字符串路径片段匹配 URL，支持 :id 参数段与 * 通配段第 31 章
elementReact 元素路径匹配成功后渲染的组件本章
index布尔值索引路由：父路径恰好匹配时渲染的默认子路由第 30 章
childrenroute 对象数组嵌套子路由，配合父级 Outlet 占位第 30 章
loader函数进入路由前加载数据，组件内用 useLoaderData 读取第 34 章
action函数处理 POST / 表单提交，返回 useActionData 读取的结果第 34 章
errorElementReact 元素本分支渲染、loader、action 抛错时的降级 UI，用 useRouteError 读错误第 37 章
lazy异步函数路由级代码分割，按需下载组件与模块第 33 章
id字符串路由唯一标识，供 useRouteLoaderData 跨层级读取父级数据第 30 章
caseSensitive布尔值路径匹配是否区分大小写，默认不区分—
hydrateFallbackReact 元素SSR 流式水合期间的占位组件第 52 章

带少量字段标注的 route 对象长这样，先建立整体观感：

const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    children: [
      { index: true, element: <Home /> },
      {
        path: 'about',
        element: <About />,
        errorElement: <AboutError />,   // 第 37 章
      },
    ],
  },
])
一张路由表由若干 route 对象组成：路径决定匹配条件，element 决定渲染结果，其余字段决定加载、提交、降级与分包行为。理解了「字段归属章节」，后面每一章只是把对应字段从路由表上挂起来用。
对照 Spring MVC：route 对象近似 Controller 层的映射表——path 对应路径，element 对应视图渲染，loader 近似进入页面前准备模型数据的服务端查询；区别在于 loader 在浏览器端执行，数据仍来自后端接口。

29.4 两种配置风格：对象式与元素式

除了 29.2 的对象数组写法，React Router 还提供 createRoutesFromElements，把 <Route> JSX 元素编译成等价的 route 对象数组。两种风格在运行时生成的路由配置完全等价，区别只在配置位置与团队偏好。

风格写法特征优点适用场景
对象式createBrowserRouter([{ path, element, ... }])配置集中、便于拆分与单元测试、与 loader/action 声明紧邻中大型工程、数据路由项目
元素式createRoutesFromElements(<Route>...)阅读时像组件树，嵌套层级直观偏好 JSX 配置的小中型项目
 
import {
  createBrowserRouter,
  createRoutesFromElements,
  Route,
} from 'react-router-dom'
import Home from './pages/Home'
import About from './pages/About'

const router = createBrowserRouter(
  createRoutesFromElements(
    <Route path="/" element={<RootLayout />}>
      <Route index element={<Home />} />
      <Route path="about" element={<About />} />
    </Route>
  )
)
两种风格必须二选一：createBrowserRouter 直接接收对象数组时不要再塞 <Route> 元素；用元素式时必须套 createRoutesFromElements，不能把 <Route> 直接传给 RouterProvider。

本篇正文统一使用对象式配置——loader、action、errorElement 在同一个对象字面量里上下排列，阅读链路最短；团队若约定 JSX 配置，按上表换成元素式即可，不影响后续章节任何 Hook 的用法。

29.5 导航三件套：Link、NavLink、useNavigate

页面间跳转有三种官方入口，各自对应一类场景：声明式链接、当前项高亮、编程式跳转。

API形态典型场景关键参数 / 返回值
Link组件：<Link to="/about">导航栏、列表项、卡片点击跳转to、replace、state、relative
NavLink组件，继承 Link侧边栏、标签页等需要高亮当前路由的导航项className / style / children 可接收 { isActive, isPending }；end 控制匹配范围
useNavigateHook，返回 navigate 函数事件回调、提交成功后跳转、权限判断后跳转navigate(to, { replace, state, relative })；navigate(-1) 返回上一页

导航栏中 Link 与 NavLink 常常并排出现：

import { Link, NavLink } from 'react-router-dom'

export default function NavBar() {
  return (
    <header className="nav">
      <Link to="/">品牌名</Link>
      <nav>
        <NavLink
          to="/about"
          className={({ isActive }) =>
            isActive ? 'nav-item active' : 'nav-item'
          }
        >
          关于我们
        </NavLink>
        <NavLink
          to="/contact"
          className={({ isActive }) =>
            isActive ? 'nav-item active' : 'nav-item'
          }
        >
          联系我们
        </NavLink>
      </nav>
    </header>
  )
}

编程式跳转用 useNavigate，常见于事件回调与提交成功后的跳转：

import { useNavigate } from 'react-router-dom'

export default function SubmitButton() {
  const navigate = useNavigate()

  async function handleClick(id) {
    // 普通跳转：历史记录里留下当前页，用户可返回
    navigate(`/detail/${id}`)

    // replace: true 替换当前历史记录，登录成功后常用，避免返回键回到登录页
    // navigate('/login', { replace: true })

    // navigate(-1) 等价于浏览器后退按钮
  }

  return <button onClick={() => handleClick(7)}>查看详情</button>
}
内部导航只有三条官方通道：声明式 Link、高亮版 NavLink、编程式 navigate；三者都走 History API，不触发浏览器整页加载。
禁止用原生 <a href="/about"> 做 SPA 内部跳转：原生锚点会让浏览器整页刷新，内存中的状态、表单草稿全部丢失。内部导航一律使用 Link / NavLink / navigate；外链（跳转到第三方站点）才用 <a href="https://..." target="_blank" rel="noreferrer">。
NavLink 默认做前缀匹配：to="/" 在任何页面都会被判为 active。给父级或索引项加 end 属性，让它只在精确匹配时高亮；嵌套布局中的侧边栏高亮规则在第 30 章继续展开。

29.6 部署模式与常见坑清单

createBrowserRouter 基于浏览器 History API，URL 保持干净的层级形态（/about、/users/123）；另一种模式 createHashRouter 在 URL 中用 # 分段，兼容性更好但 URL 带哈希符号。

  • History（默认，createBrowserRouter）：URL 为 /about、/users/123 的干净层级形态；服务端必须把未知路径回退到入口 index.html；语义干净，工程默认使用。
  • Hash（createHashRouter）：URL 形如 /#/about，# 之后的分段由前端解析；无需服务端配合，适合静态托管、旧设备兼容等备选场景。
生产部署注意：Vite 开发服务器已内置 SPA fallback；生产环境 Nginx、Apache、静态对象存储必须配置「所有未命中文件的路径都返回 index.html」，否则用户在子路径刷新页面时，服务器找不到对应文件直接返回 404。这是上线后最高频的路由故障。
现象原因解法
点击链接整页刷新、白屏重载内部导航写了原生 <a href>换成 Link、NavLink 或 navigate
刷新 /about 返回 404生产服务端未配置 SPA fallbackNginx try_files $uri $uri/ /index.html; 一类回退规则
useNavigate 抛出 RouterProvider 上下文错误页面组件挂在路由器之外，或漏挂 RouterProvider确认组件由 route 的 element 渲染，根节点包裹 RouterProvider
导航项样式永远不高亮NavLink 的 className 写死字符串，没接 isActiveclassName 改为函数 ({ isActive }) => ...
刷新登录页又被踢回登录页跳转后历史记录残留登录页（第 32 章守卫专题）跳转时加 replace: true
本章路由表仍是最小组件配置；第 30 章讲嵌套布局与 Outlet，第 33 章给路由表接入 lazy 代码分割，第 34 章再为每条路由补上 loader 与 action。

✎ 本章习题

A 基础用 createBrowserRouter 配置三条路由：/、/about、/contact，分别渲染三个返回标题的页面组件；在根布局顶部用 Link 列出三个入口，点击验证不发生整页刷新。
B 进阶把 29.4 的对象式路由表改写成 createRoutesFromElements 元素式版本；给「关于我们」导航项使用 NavLink，激活时文字变绿、加粗；并说明两种写法在运行时生成的配置对象是否存在差异。
C 挑战写一个最小对照：同一个内部路径分别用 <a href="/about"> 与 <Link to="/about"> 渲染，观察浏览器开发者工具 Network 面板的差异；查阅 Nginx 文档写出 SPA fallback 的 try_files 配置行，并解释为什么生产环境直接刷新子路径会返回 404。
