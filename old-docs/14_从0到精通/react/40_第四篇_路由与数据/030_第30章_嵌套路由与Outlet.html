第 30 章 嵌套路由与 Outlet

教科书 第 30 章 / 共 64 章 · 预计 40 分钟 · 布局壳与子路由插槽

后台系统、电商站点都有共同的外壳：侧边栏、顶栏、面包屑只出现一次，中间内容随菜单切换。本章用 route 的 children 与 Outlet 把这套布局壳抽成父级路由，讲清索引路由、相对路径、父子数据共享与 Outlet context。

◆本章目标

  • 理解嵌套路由解决的核心问题：公共外壳只渲染一次，子页面只替换中间内容区；
  • 能用 children 配置父子路由，并在父布局中用 <Outlet /> 留出子路由插槽；
  • 区分索引路由（index: true）与普通子路由的匹配时机；
  • 掌握相对路径在 Link、useNavigate 中的拼接规则；
  • 能用父级 loader + useRouteLoaderData 与 Outlet context 在父子路由之间共享数据。

30.1 为什么需要嵌套路由

一个后台系统通常是这套结构：左侧菜单 + 顶部栏 + 右侧内容区。如果为每个页面单独写一个组件，就要在每个页面里重复粘贴菜单与顶栏；更隐蔽的问题是切换子页面时外壳被整体卸载重建，菜单滚动位置、折叠状态全部丢失。嵌套路由把外壳提升为父级路由，子页面只替换内容区。

这套心智在其他框架中同样存在：vue-router 的 children 数组配合 <router-view> 是同一模型；Spring MVC 站点常用布局模板（Thymeleaf layout / Sitemesh）把公共页眉页脚抽成装饰层。React Router 的父布局组件与 Outlet 扮演的正是装饰层角色。
维度扁平路由（每页重复外壳）嵌套路由（父级共享外壳）
外壳代码每个页面组件粘贴一份菜单与顶栏父布局组件只写一次，子页面专注内容
切换行为整页组件树重建，外壳状态丢失外壳保持挂载，仅替换 Outlet 区域
菜单高亮每页各自判断当前路径父级导航统一根据当前层级高亮
公共数据每个子页面重复请求用户信息父级 loader 加载一次，子级共享读取
URL 层级路径之间无父子语义/settings/profile 天然表达归属关系
本章示例以后台设置页为主线：父级 /settings 提供侧边菜单，子级 profile、security、billing 在内容区切换。

30.2 children 配置与 Outlet 占位

在 route 对象上声明 children 数组即可建立父子层级；父路由的 element 是布局组件，组件内部必须渲染 <Outlet />——React Router 在匹配到子路由后，把子路由组件挂载到这个插槽位置。

import { createBrowserRouter, RouterProvider } from 'react-router-dom'
import SettingsLayout from './pages/settings/SettingsLayout'
import Profile from './pages/settings/Profile'
import Security from './pages/settings/Security'
import Billing from './pages/settings/Billing'
import NotFound from './pages/NotFound'

const router = createBrowserRouter([
  {
    path: '/settings',
    element: <SettingsLayout />,
    children: [
      { path: 'profile', element: <Profile /> },
      { path: 'security', element: <Security /> },
      { path: 'billing', element: <Billing /> },
    ],
  },
  { path: '*', element: <NotFound /> },
])

export default function App() {
  return <RouterProvider router={router} />
}

父布局组件的职责是渲染外壳与菜单，中间用 Outlet 标出子路由落点：

import { NavLink, Outlet } from 'react-router-dom'

export default function SettingsLayout() {
  return (
    <div className="settings-shell">
      <aside className="settings-menu">
        <NavLink to="profile" end>个人资料</NavLink>
        <NavLink to="security" end>账号安全</NavLink>
        <NavLink to="billing" end>账单订阅</NavLink>
      </aside>
      <section className="settings-content">
        {/* 子路由组件在这里渲染 */}
        <Outlet />
      </section>
    </div>
  )
}
父布局不渲染子组件，只提供插槽；插槽里放什么，由当前 URL 命中哪条子路由决定。没有 <Outlet />，子路由组件永远不会显示——这是嵌套路由新手最常见的漏写项。
注意 29.5 讲过的 end：本例菜单 to="profile" 本身是叶子路径，加不加 end 影响不大；若菜单指向父路径（如 to="/settings"），必须加 end，否则进入子页面时父菜单依然保持高亮。

30.3 索引路由 index

访问 /settings 时，父路径精确匹配了父布局，但三条子路由（profile、security、billing）都没命中，Outlet 区域会渲染空白。索引路由就是为「父路径恰好匹配时渲染什么」准备的子路由：它配置 index: true，不写 path。

const router = createBrowserRouter([
  {
    path: '/settings',
    element: <SettingsLayout />,
    children: [
      { index: true, element: <SettingsHome /> },
      { path: 'profile', element: <Profile /> },
      { path: 'security', element: <Security /> },
    ],
  },
])
维度索引路由 index: true普通子路由 path: 'xxx'
匹配条件父路径精确匹配、且未命中任何子路径URL 片段与 path 匹配
URL 形态沿用父路径，如 /settings拼接父路径，如 /settings/profile
能否带路径参数不携带子级参数可声明 :id 等参数段（第 31 章）
典型用途设置首页、欢迎面板、默认统计卡片具体功能页面
与 Outlet 关系占据父级 Outlet 的默认位置命中后占据 Outlet 位置
一个父路由下最多一条索引路由；index: true 的路由不要再写 path，二者语义互斥。索引路由同样可以配置自己的 loader、errorElement 与 lazy。

30.4 嵌套层级中的相对路径

子路由的 path 是相对父路径拼接的：父 /settings + 子 profile 得到 /settings/profile。配置时不要在子级重复写父前缀；组件内 Link 与 navigate 的 to 同样遵循相对规则，需要理解「相对谁」这层语义。

写法语义注意点
以 / 开头绝对路径，从域名根开始拼接跨层级跳转时使用，与当前位置无关
不以 / 开头相对当前路由层级拼接默认 relative: 'route'，按路由定义层级计算
navigate('..')回到上一层级完成子任务后返回父级常用；relative: 'path' 可按 URL 段回退
 
import { Link, useNavigate } from 'react-router-dom'

export default function Profile() {
  const navigate = useNavigate()

  return (
    <div>
      {/* 相对父路径：当前在 /settings/profile，结果仍是 /settings/security */}
      <Link to="security">前往账号安全</Link>

      {/* 绝对路径：跨到顶层 /users/123 */}
      <Link to="/users/123">查看用户</Link>

      <button onClick={() => navigate('..')}>返回设置首页</button>
    </div>
  )
}
嵌套配置里路径默认按层级拼接：父级前缀 + 子级片段；组件内 Link 与 navigate 的相对路径同样以路由定义层级为基准，而不是按 URL 当前段随意回退。
路径前缀最容易写反：子路由 path: '/settings/profile'（带前导斜杠）在嵌套配置中虽然能工作，但会让层级语义混乱；团队约定子级一律省略前导斜杠，路径拼装规则统一可预期。

30.5 父子数据共享：父 loader 与 Outlet context

后台外壳常常需要当前登录用户、组织信息等公共数据。父路由配置 loader 后，数据随父级路由加载一次；子组件不必重新请求，通过两条官方通道读取。

方式一：父级 loader + useRouteLoaderData

父路由配置 id 与 loader，子组件用 useRouteLoaderData('root') 按 id 取数；useLoaderData 只返回当前路由自己的 loader 数据。

const router = createBrowserRouter([
  {
    path: '/settings',
    id: 'settings-root',
    loader: async () => {
      const res = await fetch('/api/me')
      return res.json()
    },
    element: <SettingsLayout />,
    children: [{ index: true, element: <SettingsHome /> }],
  },
])
import { useLoaderData, useRouteLoaderData } from 'react-router-dom'

export default function Profile() {
  // 当前路由自身的 loader 数据（本页没有 loader 时为 undefined）
  const own = useLoaderData()
  // 按 id 读取父级 loader 共享的用户信息
  const me = useRouteLoaderData('settings-root')

  return <p>当前账号：{me.name}（角色：{me.role}）</p>
}

方式二：Outlet context 透传布局级普通值

不经过 loader 的本地状态（如侧边栏折叠状态、主题对象）由父布局通过 <Outlet context={{ ... }} /> 下发，子组件用 useOutletContext 读取：

import { useState, Outlet, useOutletContext } from 'react-router-dom'

function SettingsLayout() {
  const [collapsed, setCollapsed] = useState(false)
  return (
    <div className="settings-shell">
      <Outlet context={{ collapsed, setCollapsed }} />
    </div>
  )
}

function Profile() {
  const { collapsed, setCollapsed } = useOutletContext()
  return <button onClick={() => setCollapsed(!collapsed)}>折叠菜单</button>
}
取数方式数据来源适用内容
useLoaderData()当前路由自身的 loader本页专属数据
useRouteLoaderData(id)指定 id 的祖先路由 loader父级用户信息、组织信息等共享模型数据
Outlet context + useOutletContext父布局组件实例状态折叠状态、主题、布局事件回调等本地值
父子共享数据分两类归属：模型数据走父级 loader + useRouteLoaderData，随路由进入阶段加载；本地布局状态走 Outlet context，随父组件实例存活。两类通道不要混用——把用户信息塞进 context 会绕过 loader 的错误归属与缓存时机。
loader 的完整执行时机、错误归属与缓存语义在第 34 章展开；本节只需理解「父级加载一次、子级按 id 读取」的共享模型。

30.6 常见坑清单

现象原因解法
子路由点击后页面一片空白父布局漏写 <Outlet />在布局组件内容区补上插槽
访问父路径 /settings 空白无内容缺少索引路由兜底添加 { index: true, element: ... }
子路径拼接成 /settings/settings/profile子级 path 又写了父前缀子级路径省略前导斜杠与重复前缀
父级菜单在子页面仍保持高亮NavLink 做前缀匹配未加 end父级导航项加 end
子组件读到的父级数据是 undefinedid 写错，或误用 useLoaderData 读父级核对路由 id，改用 useRouteLoaderData(id)
切换子页面时父级用户信息重复请求数据写在子级 loader 或组件 state 中上移到父级 loader，子级共享读取
父级 Outlet 只渲染当前命中的子路由；如果子路由之间需要保留滚动位置或局部状态，应把状态提升到父级组件或状态管理工具，而不是期待子组件实例在切换间保留。
嵌套层级同样可以继续嵌套：三级后台（区域 → 部门 → 成员）只需在子路由上再挂 children 与一层 Outlet，规则完全一致；层级过深时注意给每一级配置清晰的 id，便于跨层取数。

✎ 本章习题

A 基础配置一组 /dashboard 嵌套路由：父布局含侧边菜单与 Outlet，索引路由渲染「概览」卡片，子路由 team、projects 分别渲染对应页面；在菜单中用 NavLink 实现当前项绿色高亮。
