37.1 React 错误处理的盲区

组件渲染期间读取 user.name 而 user 为 null、第三方图表初始化失败，这类异常默认会沿组件树冒泡到根部，React 卸载整棵组件树，页面白屏。错误边界（Error Boundary）就是在组件树上设置「拦截网」：子树渲染抛错时，边界捕获错误并渲染降级 UI，避免整站崩溃。

对照其他体系：vue-router 提供 onErrorCaptured 钩子拦截子树渲染错误；Java Spring MVC 用 @ControllerAdvice 全局异常处理器兜底；React 错误边界属于「组件树层级的 try/catch」，只作用于渲染阶段的子树，而不是全包络的异常处理器。
错误类型抛出位置捕获方式
渲染错误组件函数体、渲染表达式、子组件渲染期间被最近祖先错误边界捕获，渲染降级 UI
事件处理器错误onClick 等回调内部抛出不冒泡到错误边界；用 try/catch 自行处理或交给全局上报
异步错误setTimeout、Promise 回调、接口 then 中抛出不受边界管辖；try/catch 或 .catch 处理，必要时设置全局未捕获监听
资源加载错误图片、脚本、chunk 加载失败浏览器 error 事件或路由 chunk 兜底（第 33 章），不属于渲染边界
边界自身错误错误边界组件渲染降级 UI 时抛错向上冒泡到更外层边界，最终根部兜底

图 37-1 错误冒泡与分级拦截：局部边界先隔离区块，未被拦截的错误逐层上交到路由边界与根部边界

记住边界的能力边界：它不是全局 try/catch。事件回调里的异常、Promise 拒绝、定时器异常不会触发错误边界；这些场景必须显式捕获后展示错误提示或写入状态。

37.2 类错误边界：两个生命周期方法

官方错误边界必须是类组件，由两个静态 / 生命周期方法配合：static getDerivedStateFromError(error) 在捕获错误后返回状态更新，让边界切换到降级 UI；componentDidCatch(error, info) 用于副作用——错误上报、日志记录、埋点。

import { Component } from 'react'

class ErrorBoundary extends Component {
  constructor(props) {
    super(props)
    this.state = { hasError: false, message: '' }
  }

  // 捕获子树渲染错误：返回新状态，驱动降级 UI
  static getDerivedStateFromError(error) {
    return { hasError: true, message: error.message }
  }

  // 副作用场所：上报日志、埋点、刷新监控
  componentDidCatch(error, info) {
    console.error('组件树崩溃：', error, info.componentStack)
    reportError(error, info.componentStack)
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="error-fallback">
          <p>这部分内容暂时无法显示</p>
          <p className="error-detail">{this.state.message}</p>
        </div>
      )
    }
    return this.props.children
  }
}

export default ErrorBoundary
方法调用时机职责
static getDerivedStateFromError(error)子树渲染抛错后、重渲染之前返回状态对象；保持纯函数，不做副作用与上报
componentDidCatch(error, info)错误捕获后的提交阶段执行副作用：上报、日志、告警；info.componentStack 提供组件堆栈
错误边界捕获的是子树的渲染错误，不是自身：边界组件自己渲染时抛错，会向上传递；把边界放在需要隔离的区块外层，而不是出错组件内部。

37.3 函数组件思路与第三方封装

React 官方尚未提供函数组件形式的错误边界 Hooks（useEffect 捕获不到渲染期错误，模型上无法替代）。工程实践中普遍使用社区封装 react-error-boundary：底层仍是类边界，对外暴露 ErrorBoundary 组件与 useErrorBoundary 钩子，函数组件工程直接包裹使用。

npm install react-error-boundary
import { ErrorBoundary } from 'react-error-boundary'

function Fallback({ error, resetBoundary }) {
  return (
    <div className="error-fallback">
      <p>区块加载失败</p>
      <p className="error-detail">{error.message}</p>
      <button onClick={resetBoundary}>重试</button>
    </div>
  )
}

export default function Dashboard() {
  return (
    <section>
      <ErrorBoundary FallbackComponent={Fallback} onError={reportError}>
        <ChartPanel />
      </ErrorBoundary>
      <ErrorBoundary FallbackComponent={Fallback} onError={reportError}>
        <MemberTable />
      </ErrorBoundary>
    </section>
  )
}

resetBoundary 把边界状态恢复为无错误，再次渲染子树；resetKeys 可在依赖数据变化时自动重置边界，避免上一次崩溃的状态长期卡住区块。

不引入第三方库时，把 37.2 的类边界封装成一次，全工程复用即可；函数组件业务代码只负责声明「这块区域被谁包裹」，不需要再接触类生命周期。
react-error-boundary 的 FallbackComponent 每次渲染都会收到新的 error 与 resetBoundary 对象；不要在降级组件内把 error.message 复制进本地 useState，否则 resetBoundary 之后旧错误文案仍停留在界面上。

37.4 路由级 errorElement 与错误归属

数据路由为每条路由提供 errorElement：loader / action 抛错、路由组件渲染抛错，都会被归到对应路由的错误边界；未在本路由拦截时向上冒泡到祖先路由的 errorElement。边界内用 useRouteError() 读取抛出的错误对象，区分响应状态码与普通异常。

import {
  createBrowserRouter, RouterProvider, useRouteError, useLoaderData,
} from 'react-router-dom'

function PostDetail() {
  const post = useLoaderData()
  return <article>{post.title}</article>
}

function PostError() {
  const error = useRouteError()
  const status = error.status ?? 500
  const message = error.statusText ?? error.message ?? '页面异常'

  if (status === 404) return <h2>文章不存在</h2>
  return (
    <div className="error-page">
      <h2>加载失败（{status}）</h2>
      <p>{message}</p>
    </div>
  )
}

const router = createBrowserRouter([
  {
    path: '/posts/:postId',
    loader: async ({ params }) => {
      const res = await fetch(`/api/posts/${params.postId}`)
      if (!res.ok) throw new Response('Not Found', { status: res.status })
      return res.json()
    },
    element: <PostDetail />,
    errorElement: <PostError />,
  },
])
维度React 错误边界路由 errorElement
捕获范围包裹子树的渲染错误当前路由 loader、action、组件渲染错误，可向上冒泡到祖先路由
错误读取类边界 state 持有 erroruseRouteError() 返回抛出对象，可识别 Response 状态码
配置位置组件树中声明式包裹路由表 errorElement 字段，与 loader、action 同层
典型用途页面内局部区块隔离（卡片、图表、面板）整页加载失败、404、403、服务端错误的路由级降级
组合关系可嵌入路由组件内部做二次细分隔离作为路由层级的最后一道拦截网
两套边界按层级分工：路由 errorElement 归属页面级失败（loader、action、主组件），React 错误边界归属页面内局部区块失败；页面路由边界兜底整页，组件边界兜底卡片与面板，二者可以嵌套组合。
loader 抛出的 Response 与普通 Error 形状不同：状态码在 error.status，状态文本在 error.statusText；展示前先判空，避免读取 undefined 的 message。

37.5 降级 UI 的分级设计

错误隔离不是「全部换成整页报错」。按影响范围分级兜底：小区块失败不影响整页浏览，面板失败保留外壳导航，整页崩溃才展示全局降级。设计时同时明确重试入口与错误上报责任。

分级设计的判断顺序：先看失败是否波及页面主任务——单个图表失败只替换卡片，面板失败保留导航与其他分组，主数据不可用才进入整页降级；每一级降级都要带返回路径或重试入口，不能只展示一句「出错了」。
级别触发场景降级策略
局部卡片单个图表、评论流、推荐位抛错卡片内部显示精简占位 + 重试按钮，周围内容保持可用
面板区块设置页某分组、侧边组件失败区块替换为提示条，导航与其余面板保留
整页路由loader 失败、主组件渲染崩溃、404 / 403errorElement 展示状态化提示，提供返回首页入口
根部兜底未被任何层级拦截的崩溃根部边界展示全局错误页，强制上报后刷新页面

降级组件需要处理「重试」：边界拦截错误后，内部错误状态不会自动消失；重置方式是改变组件 key 重新挂载，或调用封装库提供的 resetBoundary。

import { ErrorBoundary } from 'react-error-boundary'

function ProfilePanel({ userId }) {
  return (
    <ErrorBoundary
      FallbackComponent={ProfileFallback}
      resetKeys={[userId]}
      onError={(err) => reportError(err, 'ProfilePanel')}
    >
      <ProfileContent userId={userId} />
    </ErrorBoundary>
  )
}

function ProfileFallback({ error, resetBoundary }) {
  return (
    <div className="panel-error">
      <p>个人资料加载失败</p>
      <button onClick={resetBoundary}>重新加载</button>
      <a href="/">返回首页</a>
    </div>
  )
}
错误上报应在 componentDidCatch、onError 或全局未捕获监听中完成，附带页面路径、用户标识、组件堆栈与接口状态；本地开发时控制台输出堆栈便于定位，生产环境上报聚合平台供复盘。

37.6 常见坑清单

现象原因解法
写了边界但事件回调抛错仍白屏错误边界只拦截渲染期错误，事件与异步不在范围事件内 try/catch 展示提示；Promise 加 .catch
错误被静默吞掉，线上无感知降级 UI 只渲染文案，未调用上报接口componentDidCatch / onError 中上报错误与堆栈
一个区块崩溃导致整页不可用边界只挂在根部，粒度过大按卡片、面板拆分多个边界，局部隔离
点重试后仍停留在错误页边界错误状态未重置，组件未重新挂载调用 resetBoundary，或用 key 变更强制重建
路由错误提示读不到状态码把 Response 当普通 Error 读取 message优先取 error.status、error.statusText，再回退 error.message
异步 chunk 加载失败后无兜底懒加载失败未纳入边界处理（第 33 章）外层 Suspense + 错误边界组合，必要时配置重新加载入口
错误边界不是用来「保证不出错」的：它的价值是把崩溃限制在最小范围，给用户可理解的兜底界面，同时把现场上报给开发者。分支预判、空值保护、类型校验（第 36 章）才是减少崩溃数量的前置工作。

✎ 本章习题

A 基础实现一个类错误边界 ErrorBoundary：捕获子树渲染错误后显示「区块暂时无法显示」与错误信息，在 componentDidCatch 中调用 console.error 上报；用它包裹一个故意读取空对象属性的演示组件，观察降级 UI 是否生效。
B 进阶为 /posts/:postId 路由配置 errorElement：404 显示「文章不存在」，其他状态码显示「加载失败」与状态码；用 useRouteError 区分 Response 与普通异常；再在页面内用局部边界包裹一个评论图表组件，演示局部失败不影响文章主体。
C 挑战为后台首页设计三级降级方案：推荐位卡片失败、统计面板失败、整页崩溃各自展示什么 UI、边界挂在哪一层、重试如何重置、错误上报携带哪些现场信息；再找出本方案中三个「错误边界抓不到」的场景，分别写出对应的 try/catch 或 .catch 处理代码。
