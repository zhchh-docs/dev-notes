◆本章目标

  • 能用 :paramName 声明路径参数，在组件中通过 useParams 读取；
  • 清楚 useParams 返回值始终是字符串，掌握数字、枚举等类型转换与校验位置；
  • 会用 useSearchParams 读写查询字符串，控制是否写入历史记录；
  • 能用 * 通配段声明兜底路由与嵌套通配，配合 useParams 读取通配内容；
  • 能在 params、query、location.state 三种传参方式之间按场景选型。

31.1 路径参数 :id 与 useParams

路由表里把动态片段写成冒号开头的参数段，例如 /users/:userId/posts/:postId。访问 /users/123/posts/45 时，userId 匹配 123、postId 匹配 45；组件内调用 useParams() 即可拿到这组键值对。

const router = createBrowserRouter([
  {
    path: '/users/:userId/posts/:postId',
    element: <PostDetail />,
  },
])
import { useParams } from 'react-router-dom'

export default function PostDetail() {
  const params = useParams()
  const userId = params.userId
  const postId = params.postId

  return (
    <div>
      <h2>文章 {postId}</h2>
      <p>作者编号：{userId}</p>
    </div>
  )
}

路径片段分三类，匹配规则逐级明确：

片段类型写法说明
静态段users逐字符相等才匹配，如 /users
参数段:userId匹配非斜杠的任意一段，同层级参数名必须唯一
通配段* 或 files/*匹配剩余整段路径，值通过 useParams()['*'] 读取
参数段匹配的是一段路径（不含斜杠）；一段路径内若同时出现文字与编号（如 user-123），需要自己在组件或 loader 内拆分，路由不会替你解析结构。

图 31-1 URL 分段拆解：静态段、参数段与查询段分别落到不同的读取通道

参数属于「页面身份」：同一组件服务于无数条记录，区别只在 URL 里的编号；查询参数属于「视图状态」：筛选、分页、排序随用户操作变化。选型时先问这个信息是否标识一条资源，答案为是就进路径段。
对照 vue-router：:userId 与 $route.params.userId 概念一一对应；Spring MVC 中 @PathVariable Long userId 则在服务端完成类型绑定，前端这一层不承担类型转换。

31.2 参数类型转换与校验

useParams() 返回的每个值都是字符串（或 undefined），即便 URL 里是数字编号。直接把字符串传给接口、参与比较或计算，容易出现「123 与 '123' 不等」「NaN 参与计算」一类问题。类型转换与校验应放在 loader 或组件顶部，失败后给出明确的失败归宿。

const router = createBrowserRouter([
  {
    path: '/users/:userId/posts/:postId',
    loader: async ({ params }) => {
      const postId = Number(params.postId)
      if (!Number.isInteger(postId) || postId <= 0) {
        // 非法编号：抛 404 响应，交给本路由的 errorElement 渲染（第 37 章）
        throw new Response('Not Found', { status: 404 })
      }
      const res = await fetch(`/api/posts/${postId}`)
      if (!res.ok) throw new Response('Post Not Found', { status: res.status })
      return res.json()
    },
    element: <PostDetail />,
    errorElement: <PostError />,
  },
])
参数类型转换方式失败处理位置
数字编号Number(params.id)，再用 Number.isInteger 校验loader 内 throw new Response(..., { status: 404 })
枚举状态判断是否属于允许集合，如 'open' | 'closed'不合法则 throw redirect('/404') 或回退默认值
字符串文本无需转换，注意长度与字符范围由 zod 在表单场景校验（第 36 章）接口侧再次校验
可选参数先判 params.id === undefined 再取用缺失时渲染空态或重定向到默认项
不要把未校验的参数直接拼进 SQL 或本地规则表达式。前端校验只改善体验，服务端接口必须独立校验与转义；动态参数拼路径时保持模板字符串清晰，避免参数值含空格或特殊字符导致 URL 异常。

31.3 查询参数 useSearchParams

筛选条件、搜索关键词、分页页码、排序方向这类「非路径归属」的信息，放在 URL 查询字符串中最自然：/posts?page=2&q=react。useSearchParams() 返回一对值：当前查询参数（URLSearchParams 实例）与更新函数，用法接近组件状态。

import { useSearchParams } from 'react-router-dom'

export default function PostList() {
  const [searchParams, setSearchParams] = useSearchParams()
  const q = searchParams.get('q') ?? ''
  const page = Number(searchParams.get('page') ?? 1)

  function handleSearch(e) {
    // 输入关键词后更新查询参数，URL 同步变为 /posts?q=xxx
    setSearchParams({ q: e.target.value, page: '1' })
  }

  function goNextPage() {
    // replace: true 表示替换历史记录，分页前进不堆积可回退条目
    setSearchParams({ q, page: String(page + 1) }, { replace: true })
  }

  return (
    <div>
      <input value={q} onChange={handleSearch} placeholder="搜索文章" />
      <button onClick={goNextPage}>第 {page + 1} 页</button>
    </div>
  )
}
方案读取方式适用判断
useSearchParams()返回响应式查询参数与更新函数，写回 URL 自动触发重渲染页面内需要读写、需要 URL 可分享可刷新的场景，首选
useLocation().search拿到原始字符串，自行 new URLSearchParams(...) 解析只需读取、不写回的边角场景
原生 URLSearchParams纯工具类，无路由响应式绑定非组件代码、工具函数中解析字符串
setSearchParams 传入对象会整体替换当前查询参数；想保留其他参数、只改一项时，先从 searchParams 取值再构造新对象，或使用函数形式 setSearchParams(prev => { prev.set('page', '2'); return prev })。

31.4 通配符 * 与 404 兜底

当所有明确路径都未命中时，需要一条兜底路由渲染「页面不存在」。路由表末尾配置 path: '*' 即可捕获剩余路径；嵌套层级中还可以写 files/* 捕获父路径之下的任意子路径。

const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/users/:userId', element: <UserProfile /> },
  { path: '*', element: <NotFound /> },
])
import { useParams, Link } from 'react-router-dom'

export default function NotFound() {
  const params = useParams()
  const missingPath = params['*']

  return (
    <div>
      <h2>404：页面不存在</h2>
      <p>未找到路径：{missingPath}</p>
      <Link to="/">返回首页</Link>
    </div>
  )
}

匹配按路由表顺序与路径明确度综合判定：静态段优先于参数段，参数段优先于通配段；同一层级多条规则不会互相抢占，* 只承接前面未命中的部分。

匹配优先级由明确度决定：静态段 > 参数段 > 通配段；* 只承接前面未命中的剩余路径，不会抢占具体路由的匹配机会。
若工程已有父级布局，兜底路由应放在嵌套结构的最外层，避免 404 页面被错误地套进某个功能外壳；第 32 章守卫重定向、第 37 章错误边界会分别处理「无权限」与「渲染抛错」两类异常页面。

31.5 三种传参方式对照：params、query、state

从列表页进入详情页，数据可以走三条通道：路径参数、查询参数、导航状态。三者的可读性、刷新保留能力与适用场景不同，选型时先看参数是否属于「页面身份」。

import { useNavigate, useLocation } from 'react-router-dom'

function ListRow({ id, title }) {
  const navigate = useNavigate()

  function openDetail() {
    // state 携带不适合出现在 URL 的临时上下文，刷新后丢失
    navigate(`/posts/${id}`, { state: { from: 'list', title } })
  }

  return <button onClick={openDetail}>{title}</button>
}

function Detail() {
  const location = useLocation()
  const from = location.state?.from
  return <p>从 {from ?? '直接访问'} 进入</p>
}
方式表达内容刷新 / 分享保留典型用途
路径参数 :id页面身份标识，如资源编号URL 自带，刷新与分享都保留详情页、个人主页、归档页面
查询参数 ?q=&page=可选筛选、排序、分页状态URL 自带，可作为可收藏的筛选视图搜索结果、列表筛选、分页排序
location.state临时上下文：来源页、上一步操作、临时提示仅保存在历史记录中，刷新与复制链接后丢失登录后返回原页、面包屑来源、跨页弹窗状态
三种通道的可分享性依次递减：路径参数与查询参数都写在 URL 里，复制链接即可复现同一视图；state 只存在于当前历史记录条目，刷新、新开标签、复制链接后即丢失。需要「可分享」的状态一律进 URL。
不要把敏感信息或大对象塞进 state：它存在于浏览器历史记录中，可被同页代码读取，且无法被用户直接看到；持久化参数一律进 URL，需要长期保存的数据走接口与本地存储（第 25 章服务端状态、第 26 章缓存策略）。

31.6 常见坑清单

现象原因解法
数字比较失败、计算得到 NaN参数是字符串，未做 Number() 转换loader 或组件顶部转换并校验整数范围
切换详情页时组件保留旧数据路径参数变化但组件实例未重建，未把参数纳入数据依赖在 loader 中以 params.id 为查询条件；需要强制重建时给路由组件加 key
刷新后 state 里的来源信息消失state 不在 URL 中，刷新历史记录被重建必须保留的上下文改为查询参数或路径参数
查询参数被整体清空setSearchParams 传对象覆盖了其他键合并现有参数，或使用函数式更新
同层级两条路由参数名冲突同一父路由下参数段使用了重复名字或不同顺序保持路径段结构一致，参数名按职责命名
中文、空格出现在 URL 导致乱码参数未做编码直接拼接使用 encodeURIComponent，由 Link to 自动处理路径部分
参数变化不等于组件重建：从 /posts/1 跳到 /posts/2 时复用同一组件实例，若数据请求只写在挂载 effect 中会读到旧编号；以 params.id 为条件的 loader 会随导航重新执行，这也是第 34 章推荐 loader 的原因之一。

✎ 本章习题

A 基础配置路由 /projects/:projectId，详情组件用 useParams 读取编号并展示；列表中每行用 Link 指向对应项目路径，点击进入后可刷新页面保持内容。
B 进阶为项目详情 loader 增加校验：编号必须为正整数，否则抛出 404 响应；再在列表页接入 useSearchParams，实现关键词搜索与页码更新，URL 形如 /projects?q=react&page=2。
C 挑战实现「从搜索结果进入详情，详情页返回按钮回到原搜索列表」的链路：用 location.state 记录来源与筛选条件；分析刷新详情页后该方案的行为变化，并给出改用查询参数保存来源筛选的等价实现，说明两者取舍。
