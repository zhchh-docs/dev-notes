35.1 受控表单的痛点

第 8 章讲过受控组件：表单值由 React state 持有，onChange 回调里 setState。字段少的时候清晰直接；一旦是十几二十个字段的编辑页，每次按键都会触发整个表单组件重渲染，输入流畅度、大列表联动、第三方控件订阅都会受拖累。

// 手写受控：每个字段一个 state，整表随按键重渲染
function ProfileForm() {
  const [name, setName] = useState('')
  const [email, setEmail] = useState('')
  const [city, setCity] = useState('')
  const [bio, setBio] = useState('')

  function onSubmit(e) {
    e.preventDefault()
    api.save({ name, email, city, bio })
  }

  return (
    <form onSubmit={onSubmit}>
      <input value={name} onChange={e => setName(e.target.value)} />
      <input value={email} onChange={e => setEmail(e.target.value)} />
      <input value={city} onChange={e => setCity(e.target.value)} />
      <textarea value={bio} onChange={e => setBio(e.target.value)} />
    </form>
  )
}
维度手写 useState 受控react-hook-form
状态存储每个字段一个 React state内部存储字段值，原生控件通过 ref 注册，不经过组件 state
输入重渲染按键即触发表单组件重渲染注册期间默认不重渲染，读取 watch 或 formState 的字段才订阅更新
校验时机自行书写规则与错误展示逻辑register 规则、formState.errors 自动联动
提交取值逐个读取 state 组装对象handleSubmit 回调直接拿到校验后的字段对象
学习成本无需额外依赖，心智直观需要理解 ref 注册、Controller、formState 订阅模型
react-hook-form v7 的核心思路：原生 HTML 输入框自己持有值，表单库通过 ref 把元素登记进内部存储；只有订阅了某个字段的视图（watch、formState.errors）才在值变化时更新。这与 Vue v-model 的双向绑定不同，也和第 7 章 useState 的组件状态模型分属两条路线。
性能差异的根源在状态归属：useState 把字段值放进组件渲染循环，每次输入都参与重渲染；react-hook-form 把值放进表单内部存储，组件只在订阅字段时才跟随更新。

35.2 useForm 核心 API 全景

先安装依赖，再用 useForm 拿到方法与状态；register 把原生输入框接入表单，handleSubmit 在提交时先校验、再把干净的字段对象交给回调。

npm install react-hook-form
import { useForm } from 'react-hook-form'

type Inputs = {
  name: string
  email: string
  bio: string
}

export default function ProfileForm() {
  const {
    register,
    handleSubmit,
    formState: { errors },
  } = useForm<Inputs>({
    defaultValues: { name: '', email: '', bio: '' },
  })

  function onValid(data: Inputs) {
    // data 已通过校验，结构就是 Inputs
    api.save(data)
  }

  return (
    <form onSubmit={handleSubmit(onValid)}>
      <input {...register('name')} placeholder="姓名" />
      {errors.name && <p className="field-error">{errors.name.message}</p>}

      <input {...register('email')} placeholder="邮箱" />
      {errors.email && <p className="field-error">{errors.email.message}</p>}

      <textarea {...register('bio')} placeholder="个人简介" />
      <button type="submit">保存</button>
    </form>
  )
}
API作用常用返回 / 参数
useForm()表单入口，返回方法与状态集合配置 defaultValues、mode、resolver、criteriaMode
register(name, rules?)把原生控件注册到内部存储，返回 ref、onChange、onBlur、name规则对象见 35.3；用展开运算符接到元素上
handleSubmit(onValid, onInvalid?)提交处理器：先校验，成功回调收字段对象，失败回调收错误与字段第二个参数可用于失败时聚焦首个错误字段
formState.errors当前校验错误集合，按字段名索引errors.name?.message；订阅后随校验更新
watch(name?)读取字段当前值并订阅重渲染传字段名单个读取，不传读取整表
control传给 Controller 连接非原生控件见 35.5
reset(values?)重置字段值与错误状态提交成功后清空表单常用
setValue(name, value, options?)程序化写入某个字段值可配置 shouldValidate、shouldDirty
getValues()读取当前字段值，不触发订阅与重渲染事件回调中取数，避免 watch 的渲染代价
trigger(name?)手动触发校验字段联动、分步表单校验场景

35.3 register 选项与原生校验规则

register 的第二个参数是规则对象，react-hook-form 内置了与 HTML 校验属性对应的规则，错误信息通过 message 自定义；规则不满足时写入 formState.errors。

<form onSubmit={handleSubmit(onValid)}>
  <input
    {...register('name', {
      required: '姓名不能为空',
      minLength: { value: 2, message: '姓名至少 2 个字符' },
      maxLength: { value: 20, message: '姓名最多 20 个字符' },
    })}
    placeholder="姓名"
  />
  {errors.name && <p className="field-error">{errors.name.message}</p>}

  <input
    {...register('email', {
      required: '邮箱不能为空',
      pattern: {
        value: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
        message: '邮箱格式不正确',
      },
    })}
    placeholder="邮箱"
  />
  {errors.email && <p className="field-error">{errors.email.message}</p>}

  <input
    type="number"
    {...register('age', {
      min: { value: 18, message: '必须年满 18 岁' },
      max: { value: 99, message: '年龄超出范围' },
      valueAsNumber: true,
    })}
  />
  {errors.age && <p className="field-error">{errors.age.message}</p>}

  <button type="submit">提交</button>
</form>

常用注册规则按类型分组如下，规则对象既可以传布尔值，也可以传 { value, message } 自定义错误文案：

  • required：必填校验，值为布尔值或错误信息字符串；
  • minLength / maxLength：字符串长度上下界；
  • min / max：数值上下界；
  • pattern：正则匹配，如邮箱格式；
  • validate：自定义校验函数，返回 true 表示通过，返回字符串表示错误信息；
  • valueAsNumber / valueAsDate：取值时自动完成类型转换，避免数字输入以字符串提交。
字段结构简单、规则集中时，内置规则足够；跨字段规则、对象嵌套、枚举与服务端同步校验交给 zod resolver，见第 36 章。

35.4 watch 与受控联动

页面需要根据某个字段实时变化时（勾选「订阅邮件」展开通知偏好、选择城市显示对应分区），用 watch 读取字段值并订阅更新。watch 是少数会触发组件重渲染的 API，应只订阅真正参与渲染的字段。

import { useForm } from 'react-hook-form'

export default function NotifyForm() {
  const { register, handleSubmit, watch, formState: { errors } } = useForm({
    defaultValues: { subscribe: false, channel: 'email' },
  })

  // 只订阅 subscribe 字段；勾选后才渲染渠道选项
  const subscribe = watch('subscribe')

  return (
    <form onSubmit={handleSubmit(onValid)}>
      <label>
        <input type="checkbox" {...register('subscribe')} />
        订阅邮件通知
      </label>

      {subscribe && (
        <select {...register('channel')}>
          <option value="email">邮件</option>
          <option value="sms">短信</option>
        </select>
      )}

      <button type="submit">保存</button>
    </form>
  )
}
  • register 原生控件：输入时不触发组件重渲染，值保存在内部存储，适合普通文本、数字、勾选、单选等原生输入；
  • watch('field')：订阅该字段，值变化时当前组件重渲染，用于条件显隐、实时预览、字段间联动；
  • getValues('field')：读取当前值但不订阅、不重渲染，用于事件回调、提交前取值、校验辅助函数；
  • 额外 useState 镜像会形成双份状态，容易不同步，不推荐；需要受控行为时优先 watch 或 Controller。
不要在 watch() 不传参数的情况下订阅整表：每按一个键都重渲染整个表单。联动只订阅具体字段；非渲染用途的取值走 getValues()。

35.5 Controller：非原生控件接入

第三方组件（下拉选择器、日期选择器、富文本、开关组件）不暴露原生 ref 与标准 onChange，register 无法直接接管。Controller 在表单存储与组件之间架桥：render 回调提供 field（onChange、onBlur、value、ref、name）与 fieldState（error、isTouched），由你把它们接到第三方组件的对应属性上。

import { useForm, Controller } from 'react-hook-form'
import Select from './components/Select'   // 第三方下拉，value + onChange 受控接口

export default function AddressForm() {
  const { control, handleSubmit, formState: { errors } } = useForm({
    defaultValues: { city: '', district: '' },
  })

  return (
    <form onSubmit={handleSubmit(onValid)}>
      <Controller
        name="city"
        control={control}
        rules={{ required: '请选择城市' }}
        render={({ field, fieldState }) => (
          <Select
            value={field.value}
            onChange={field.onChange}
            onBlur={field.onBlur}
            options={cityOptions}
            placeholder="选择城市"
          />
        )}
      />
      {errors.city && <p className="field-error">{errors.city.message}</p>}

      <button type="submit">保存</button>
    </form>
  )
}
接入方式条件说明
register组件是原生 input / select / textarea，可转发 ref性能最优，无需额外包装
Controller第三方组件、自定义受控组件、需要自定义事件协议桥接 field 与 fieldState，错误状态从 fieldState.error 读取
组件库表单封装Ant Design 等组件库的 Form.Item 体系第 57 章表格与表单页实战会给出库内方案，与 react-hook-form 按团队约定二选一
Controller 的本质是把表单内部存储桥接到受控组件的 props 协议：field.value 对应组件的值属性，field.onChange 对应更新回调，field.onBlur 对应失焦回调；桥接完成后，第三方组件同样受表单校验、错误与重置体系管理。
第三方组件若内部维护自己的状态，务必把 field.value 作为受控值传入，不要在组件内部另存一份初始值；提交后 reset 才能把第三方组件一并带回初始状态。

35.6 提交状态、脏状态与重置

formState 暴露一组只读状态，用于按钮禁用、未保存提示、提交成功反馈；handleSubmit 的成功回调拿到校验后的字段对象，失败回调拿到错误集合。

状态使用顺序：提交中用 isSubmitting 防重复点击，未保存用 isDirty 决定按钮与离开提示，是否可提交用 isValid 判断，回填基准用 defaultValues 与 reset 维护。四者职责互不重叠，不要用一个布尔状态包揽全部。
import { useForm } from 'react-hook-form'

export default function ArticleForm() {
  const {
    register,
    handleSubmit,
    reset,
    formState: { errors, isSubmitting, isDirty, isValid },
  } = useForm({
    defaultValues: { title: '', content: '' },
    mode: 'onTouched',
  })

  async function onValid(data) {
    await api.save(data)
    // 提交成功后重置为新的初始值，isDirty 回到 false
    reset({ title: '', content: '' })
  }

  function onInvalid(errors) {
    // 失败回调：可在这里聚焦首个错误字段、记录埋点
    console.warn('表单校验未通过', errors)
  }

  return (
    <form onSubmit={handleSubmit(onValid, onInvalid)}>
      <input {...register('title', { required: '标题必填' })} />
      {errors.title && <p className="field-error">{errors.title.message}</p>}
      <textarea {...register('content', { required: '正文必填' })} />
      <button type="submit" disabled={isSubmitting || !isDirty || !isValid}>
        {isSubmitting ? '保存中…' : '保存文章'}
      </button>
    </form>
  )
}
状态 / 配置含义典型用途
isSubmitting提交回调执行期间为 true按钮禁用、防止重复提交
isDirty当前值与初始值是否有差异未保存离开提示、提交按钮启用条件
isValid当前是否全部通过校验（受 mode 影响）提交按钮启用条件
isLoading异步默认值加载期间（异步 defaultValues）编辑页回填期间展示骨架
mode校验触发时机：onSubmit、onBlur、onChange、onTouched、all默认 onSubmit；体验优先选 onBlur 或 onTouched
reset(values?)重置值、错误、脏状态与触碰状态提交成功清空、编辑数据回填后重置基准
isDirty 比较的是当前值与 defaultValues（或最近一次 reset 的基准），不是与接口原始数据；异步回填完成后必须调用 reset(data) 刷新基准，否则一进入编辑页表单就处于「未保存」状态。

35.7 常见坑清单

现象原因解法
编辑页回填后一按键就提示必填未配置 defaultValues，或回填后未调用 reset 同步基准值异步数据到达后 reset(data)；初始值通过 defaultValues 提供
输入框不受控制、值不回显第三方组件没接 field.value，或自定义组件未转发 ref改用 Controller，把 field 完整接到受控属性
整表每按一键都重渲染watch() 未传字段名订阅整表只订阅参与渲染的字段，事件取值用 getValues
错误信息不更新、读到旧 errors未把 errors 从 formState 中正确解构订阅确认 formState: { errors } 解构写法；resolver 模式见第 36 章
数字字段提交时变成字符串原生输入未配 valueAsNumber规则中开启 valueAsNumber: true，或在 zod schema 中转换（第 36 章）
提交成功后表单仍显示旧值回调内忘记 reset，或回填数据未作为新基准成功后 reset() 或传入新的默认值对象
一个表单只挂一个 useForm 实例；分步表单若需要各自独立的提交与校验，应拆分组件并各自持有实例，不要在同一实例里用字段前缀模拟多组表单。

要点一句话
