◆本章目标

  • 理解前端守卫的职责边界：改善体验、减少无效渲染，真正的鉴权必须由服务端完成；
  • 能在路由 loader 中检查登录态，未登录时 throw redirect('/login?from=...')；
  • 会用受保护布局路由把公共页面与受保护页面分组，统一执行角色检查；
  • 掌握 redirect() 函数、<Navigate> 组件、useNavigate 三种重定向入口的区别；
  • 能区分路由级、组件级、按钮级权限检查各自的位置与失效风险。

32.1 守卫解决什么问题

守卫（guard）回答一个问题：当前用户有没有资格进入这条路由？典型检查包括：是否登录、是否具备角色、是否属于资源所有者、是否满足访问条件。React Router v7 没有 vue-router 那样独立的 beforeEach 全局钩子，守卫逻辑落在路由 loader 与受保护布局上——loader 在组件渲染之前执行，天然适合做进入前检查。

体系守卫入口检查失败动作
Vue vue-routerrouter.beforeEach 全局前置守卫、路由独享 beforeEnternext('/login') 中断并跳转
React Router v7路由 loader 或受保护布局 loaderthrow redirect('/login') 中断进入流程
Spring MVC拦截器 HandlerInterceptor、方法级 @PreAuthorize返回 401 / 403 响应，跳转登录页
组件内判断渲染前 if (!user) return <Login />本页内切换内容，不中断路由匹配
前端守卫不是安全边界。用户可以直接改 URL、绕过前端路由调用接口；登录态校验、角色鉴权、资源归属判断必须在服务端接口独立完成。前端守卫的价值是：避免匿名用户看到受保护页面的骨架、减少无效请求、给出明确的登录引导。

32.2 loader 内守卫：throw redirect

先封装一个读取当前会话的工具（真实工程中可结合第 22、23 章的状态管理或第 25 章的服务端状态），再在受保护路由的 loader 中检查：未登录就抛出 redirect，并把当前路径作为回跳参数带给登录页。

// auth.js —— 会话读取工具（示意实现，真实工程对接状态管理或接口）
export function getCurrentUser() {
  const token = localStorage.getItem('token')
  if (!token) return null
  // 解析本地缓存的用户信息；过期判断由服务端接口兜底
  const raw = localStorage.getItem('user')
  return raw ? JSON.parse(raw) : null
}
import { createBrowserRouter, redirect } from 'react-router-dom'
import { getCurrentUser } from './auth'
import Profile from './pages/Profile'
import Login from './pages/Login'

const router = createBrowserRouter([
  {
    path: '/profile',
    loader: ({ request }) => {
      const user = getCurrentUser()
      if (!user) {
        // 记录来源路径，登录成功后回跳；search 由 request.url 解析得到
        const from = new URL(request.url).searchParams.get('from') ?? ''
        const target = from ? `/login?from=${encodeURIComponent(from)}` : '/login'
        throw redirect(target)
      }
      return user
    },
    element: <Profile />,
  },
  { path: '/login', element: <Login /> },
])

登录页提交成功后，读取 from 参数回跳原页面：

import { useNavigate, useSearchParams } from 'react-router-dom'

export default function Login() {
  const navigate = useNavigate()
  const [searchParams] = useSearchParams()

  async function onSubmit(values) {
    await api.login(values)
    const from = searchParams.get('from')
    navigate(from ?? '/', { replace: true })
  }

  return <form onSubmit={...}>{/* 表单字段见第 35 章 */}</form>
}
拦截位置执行时机特点与风险
路由 loader组件渲染之前，路由匹配阶段推荐：可中断进入流程、可携带回跳参数；失败走 redirect 或错误边界
受保护布局 loader父级匹配阶段，覆盖整组子路由守卫逻辑集中一份，适合后台整组页面（见 32.3）
组件内 if 判断组件渲染期间页面骨架先渲染再跳转，存在短暂闪现；不适合做整组路由守卫
redirect(to) 在 loader 或 action 中是抛出的：throw redirect('/login')，它中断当前路由的数据加载流程并触发跳转；写成普通 return redirect(...) 不会产生中断效果。

32.3 组合守卫：受保护布局包裹子路由

后台系统通常是一整组页面都需要登录。把守卫放进父级布局路由的 loader，公共页面与受保护页面在路由表中分块排列，子路由自动继承父级检查，无需逐条重复判断。

import { createBrowserRouter, redirect } from 'react-router-dom'
import { getCurrentUser } from './auth'
import AdminLayout from './layouts/AdminLayout'
import Dashboard from './pages/admin/Dashboard'
import MemberList from './pages/admin/MemberList'
import Login from './pages/Login'
import Home from './pages/Home'

const router = createBrowserRouter([
  // 公共页面：无需登录
  { path: '/', element: <Home /> },
  { path: '/login', element: <Login /> },

  // 受保护分组：父级 loader 统一守卫
  {
    path: '/admin',
    loader: ({ request }) => {
      const user = getCurrentUser()
      if (!user) {
        const from = new URL(request.url).pathname
        throw redirect(`/login?from=${encodeURIComponent(from)}`)
      }
      if (user.role !== 'admin') {
        // 已登录但角色不足：进入 403 提示页
        throw redirect('/forbidden')
      }
      return user
    },
    element: <AdminLayout />,
    children: [
      { index: true, element: <Dashboard /> },
      { path: 'members', element: <MemberList /> },
    ],
  },
  { path: '/forbidden', element: <Forbidden /> },
])
这与 vue-router 的嵌套 children 守卫、Spring MVC 的拦截器按路径前缀匹配是同一思路：把检查规则挂在分组入口，组内成员自动获得保护。新增后台页面时只需在 children 中追加路由，不必重复写登录判断。
父级 loader 返回的用户信息可通过 useRouteLoaderData 在子页面读取（第 30 章 30.5）；守卫失败抛出的 redirect 会中断整组子路由的进入流程。

32.4 Navigate 组件与声明式重定向

除了在 loader 中 throw redirect，还有两类重定向入口：组件内渲染 <Navigate> 做声明式跳转，事件回调中 useNavigate 做编程式跳转。三者使用场景不同。

import { Navigate } from 'react-router-dom'

// 旧路径永久迁移：访问 /home 直接跳到新路径
export default function HomeRedirect() {
  return <Navigate to="/" replace />
}
入口写法典型场景
redirect() 函数throw redirect(to, init?)loader / action 中的守卫、提交成功后跳转、数据不存在时转 404
<Navigate> 组件<Navigate to="/new" replace />组件渲染期间的声明式跳转，如旧路径迁移、条件渲染兜底
useNavigate()navigate(to, { replace, state })事件回调、异步操作完成后的编程式跳转
选型顺序先看触发位置：loader / action 内的中断跳转用 redirect()；组件渲染期间的声明式兜底用 <Navigate>；事件回调与异步完成后的跳转用 useNavigate。三者最终都操作 History API，差别只在调用时机与上下文。
重定向默认在历史记录中留下新条目；登录成功、旧路径迁移、守卫跳转都应加 replace: true（redirect(to, { replace: true }) 或 <Navigate replace />），否则用户点返回键会再次触发守卫，形成「登录页 ↔ 受保护页」来回弹跳。

32.5 权限分级：路由级、组件级、按钮级

权限检查不止「能不能进页面」，还包括「页面内看到哪些区块」「能不能点某个按钮」。三层检查位置不同，失效风险也不同。

层级实现位置职责与风险
路由级父级 / 路由 loader 守卫决定能否进入整组页面；只做入口引导，不替代接口鉴权
组件级页面组件内按角色渲染区块、表格列、弹窗入口控制可见范围；角色判断来自父级 loader 数据或状态管理
按钮级操作按钮按角色 disabled 或不渲染减少误操作；按钮隐藏不代表接口安全，删除、修改等接口必须服务端鉴权
 
import { useRouteLoaderData } from 'react-router-dom'

export default function MemberList() {
  const me = useRouteLoaderData('admin-root')

  return (
    <section>
      <h2>成员列表</h2>
      {/* 组件级：非管理员不展示批量操作区 */}
      {me.role === 'admin' && (
        <div className="bulk-actions">
          <button>批量导出</button>
          {/* 按钮级：仅超级管理员可见删除入口 */}
          {me.role === 'superadmin' && <button>批量删除</button>}
        </div>
      )}
    </section>
  )
}
权限粒度由粗到细分层落地：路由级决定进不进得来，组件级决定看得到哪些区块，按钮级决定点不点得了操作。三层前端检查只负责展示收敛，真正的授权判断在服务端接口逐次复核。
前端隐藏按钮只是体验优化：用户可以通过控制台、抓包直接调用接口。写操作接口必须在服务端校验角色与资源归属；前端三层检查与服务端鉴权是叠加关系，不是替代关系。

32.6 常见坑清单

现象原因解法
受保护页面骨架先闪一下再跳登录页守卫写在组件内 if 判断，渲染后才跳转上移到路由 loader，渲染前完成检查
点返回键在登录页与受保护页之间来回弹守卫跳转未使用 replace，历史记录残留受保护页redirect(to, { replace: true }) 或 <Navigate replace />
登录成功后回跳路径丢失未把 from 写入查询参数，或登录页跳转时未读取守卫抛出 /login?from=当前路径，登录成功后 navigate(from, { replace: true })
角色不足仍能进入页面只在前端判断角色，服务端接口未鉴权接口层独立校验角色与资源归属，前端只做展示层控制
守卫顺序错乱导致误放行公共路由与受保护分组排列顺序、路径前缀冲突公共路由前置，受保护分组集中排列；前缀路径保持明确层级
刷新受保护页被踢回登录页会话仅存内存状态，刷新后丢失；本地 token 过期未处理持久化 token 与用户信息，接口 401 时统一跳登录（第 25 章拦截器思路）
守卫只校验「当前有没有登录、角色是什么」，不要在 loader 里维护业务表单状态或发起写操作；跳转回跳参数 from 必须经过 encodeURIComponent，且登录成功后用 replace: true 落地，避免历史记录里残留未授权条目。

✎ 本章习题

A 基础为 /profile 路由编写 loader 守卫：未登录时跳转到 /login 并携带 from 参数；登录页读取 from，登录成功后 replace 回跳原页面。
B 进阶把 /admin 整组页面收进受保护布局路由：父级 loader 校验登录与 role === 'admin'，子路由包含索引页与成员列表；角色不足时重定向到 /forbidden；在成员列表中按角色条件渲染「批量导出」按钮。
C 挑战实现资源归属守卫：/orders/:orderId 进入前校验当前用户是否为订单所有者，不属于则跳 403；写出 loader 校验流程，并列出哪些环节仍必须由服务端接口复核，说明仅靠前端守卫会留下哪些可被绕过的路径。
