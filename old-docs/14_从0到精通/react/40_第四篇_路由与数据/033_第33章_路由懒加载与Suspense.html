◆本章目标

  • 理解代码分割的动机：首屏只下载当前路由必需的代码，其余页面按需加载；
  • 能用 React.lazy + <Suspense fallback={...}> 实现组件级懒加载；

  • 会设计骨架屏加载态、使用链接预取，并定位 chunk 404 一类部署故障。

33.1 为什么需要代码分割

默认构建会把所有页面组件、第三方库打进一个 JavaScript bundle。用户打开首页就要下载后台管理、报表、设置等从未访问过的代码，首屏下载、解析、执行时间随工程规模线性增长。代码分割（code splitting）利用动态 import() 让构建工具把不同路由拆成独立 chunk：进入对应路由时才下载那一块。

维度单体打包路由级代码分割
首屏下载量整站全部 JS 一次性下载仅首页所需 chunk，其余按需
缓存粒度任一页面改动导致整包缓存失效各 chunk 独立缓存，改动页面只重下对应块
切换页面成本代码已在内存，切换即时首次进入需下载 chunk，配合骨架屏过渡
构建产物单个主 bundle主 bundle + 若干路由 chunk（Vite / Rollup 自动命名）
适用阶段小型工具站、演示项目页面数量多、第三方依赖重的中大型工程
代码分割的核心取舍是首屏体积与切换等待的交换：少下载不常用代码换取更快首屏，代价是首次进入个别页面要多一次 chunk 往返；骨架屏与预取正是用来抵消这一代价的体验手段。
构建产物分析属于工程化专题（第 51 章代码分割与预加载继续展开）；本章聚焦运行时写法：怎么把页面组件声明为懒加载、加载期间显示什么。

33.2 React.lazy 与 Suspense 基础

React.lazy 接收一个返回 Promise 的工厂函数（通常是 () => import('./Page')），返回一个可在普通组件树中使用的懒加载组件。加载期间必须用 <Suspense fallback={占位内容}> 包裹，React 在 chunk 就绪前先渲染 fallback。

import { lazy, Suspense } from 'react'
import Home from './pages/Home'

// 组件级懒加载：只有渲染到 About 时才下载对应 chunk
const About = lazy(() => import('./pages/About'))
const Settings = lazy(() => import('./pages/Settings'))

export default function App() {
  return (
    <main>
      <Home />
      <Suspense fallback={<div className="page-loading">加载中…</div>}>
        <About />
        <Settings />
      </Suspense>
    </main>
  )
}
规则正确写法错误 / 限制
包裹位置懒组件被 <Suspense> 包裹缺少 Suspense 会在加载期间抛出错误
导出方式目标组件使用 export default命名导出需先在工厂函数内解构包装，lazy 不直接支持
调用位置模块顶层定义 const X = lazy(...)不能在条件语句、循环、事件回调中创建懒组件
工厂函数() => import('./Page')，返回 Promise工厂函数每次重新执行会重复触发下载，应保持稳定引用
命名导出处理方式：若页面只有 export function About()，在工厂函数内解构并包装为默认导出：lazy(() => import('./About').then(m => ({ default: m.About })))。更推荐页面文件统一使用默认导出，保持路由表整洁。

33.3 路由级 lazy：数据路由的分包字段

在数据路由中，更自然的做法是给 route 对象配置 lazy 字段：进入该路由时，组件以及配套的 loader、action、errorElement 等模块一起按需下载，路由表本身保持轻量。

import { createBrowserRouter, RouterProvider } from 'react-router-dom'

const router = createBrowserRouter([
  { path: '/', lazy: async () => {
      const { default: Home } = await import('./pages/Home')
      return { Component: Home }
    },
  },
  {
    path: '/about',
    lazy: async () => {
      // 组件、loader、action 可在同一模块内一起延迟加载
      const { default: About, aboutLoader } = await import('./pages/About')
      return { Component: About, loader: aboutLoader }
    },
  },
  {
    path: '/settings',
    lazy: async () => {
      const { default: Settings } = await import('./pages/Settings')
      return { Component: Settings }
    },
  },
])

export default function App() {
  return <RouterProvider router={router} />
}
写法工作方式适用场景
组件级 React.lazy + Suspense组件树内声明懒组件，由最近的 Suspense 提供 fallback非路由组件：弹窗、面板、图表、重型编辑器
路由级 lazy 字段进入路由时下载组件及配套 loader / action，路由框架管理加载态页面级分包，与数据路由配置集中在同一张路由表
路由 lazy 返回对象中的键对应 route 字段：Component 对应 element 渲染组件，loader、action、errorElement、HydrateFallback 均可延迟提供；未提供的字段沿用路由表上的静态配置。
不要在一条路由上同时使用组件级 React.lazy 与路由 lazy 做重复分包：两层延迟会叠加两次等待，错误归属也会分散。页面级分包统一走路由 lazy，非路由重型组件才用组件级 Suspense。

33.4 HydrateFallback 与 SSR 占位概念

客户端渲染中，Suspense fallback 出现在 chunk 下载期间；服务端渲染（SSR，第 52 章展开）场景下，页面 HTML 先流式下发，浏览器在水合（hydration）对应路由之前，需要一个独立的占位组件，这就是路由字段 hydrateFallback 的职责。

const router = createBrowserRouter([
  {
    path: '/reports',
    lazy: async () => {
      const { default: Reports } = await import('./pages/Reports')
      return {
        Component: Reports,
        HydrateFallback: () => <div className="skeleton">报表加载中…</div>,
      }
    },
  },
])
  • Suspense fallback：出现在客户端下载懒组件 chunk 期间，纯客户端渲染与 SSR 水合完成后都可能出现；
  • hydrateFallback / HydrateFallback：出现在 SSR 页面下发后、当前路由完成水合之前，仅服务端渲染工程需要配置（第 52、53 章专题）。
本章只需建立概念：hydrateFallback 服务于 SSR 流式渲染；纯 Vite 客户端工程不会触发它，不必在每个路由上配置。SSR 与水合的完整机制见第 52、53 章。

33.5 加载态体验：骨架屏与链接预取

chunk 下载期间的占位内容直接影响体感。整页转圈会让用户以为卡死；骨架屏用与页面结构一致的灰色块先占住版面，内容就绪后自然替换。

function ReportSkeleton() {
  return (
    <div className="skeleton-page">
      <div className="skeleton-block h-8 w-40" />
      <div className="skeleton-block h-4 w-full" />
      <div className="skeleton-block h-4 w-3/4" />
      <div className="skeleton-block h-56 w-full" />
    </div>
  )
}

// 路由级写法中，框架加载期间的占位由 RouterProvider 周边的 Suspense 承接
export default function App() {
  return (
    <Suspense fallback={<ReportSkeleton />}>
      <RouterProvider router={router} />
    </Suspense>
  )
}
加载态策略表现适用
全屏转圈 Spinner页面整体遮罩 + 居中图标极小工程、单次操作反馈
骨架屏 Skeleton版面结构先出现，内容随后填充路由切换、首屏报表与详情页
局部占位条仅内容区显示条状加载，外壳保持不动嵌套布局中的子路由切换
加载态设计的目标是让等待可预期：骨架屏先给出版面结构，用户知道内容即将出现；整页转圈只表达「正在加载」而不表达「将加载什么」，在路由切换场景下体感更差。占位块的尺寸、位置应与目标页面对齐，避免内容填充时版面跳动。

减少等待时间的另一条路是预取：Link 在悬停（intent）或渲染（render）时提前下载目标路由 chunk，点击时代码已在本地。prefetch 属性控制预取强度。

import { Link } from 'react-router-dom'

// prefetch="intent"：悬停、获得焦点时预取（默认值）
// prefetch="render"：链接渲染到页面就预取
// prefetch="none"：关闭预取，如广告位、低频外链
export default function Nav() {
  return (
    <nav>
      <Link to="/reports" prefetch="intent">报表</Link>
      <Link to="/settings" prefetch="render">设置</Link>
    </nav>
  )
}
预取强度按访问概率选择：高频入口用 prefetch="render" 随页面渲染提前下载，常规导航用默认 intent 在悬停时预取，低频或广告位用 none 关闭预取以节省带宽。

33.6 常见坑清单

现象原因解法
进入路由报 "A component suspended while responding to synchronous input"懒组件缺少 Suspense 包裹在外层补 <Suspense fallback={...}>，路由级 lazy 检查框架是否已提供上下文
部署后刷新页面报 chunk 加载失败、白屏文件名带 hash，旧版本 HTML 引用的 chunk 已被新版本覆盖；或静态服务器未配 fallback发布时保留历史版本 chunk；配置 SPA fallback；对关键路由关闭分包或配置 chunk 加载失败重试
懒组件拿到 undefined 报错目标文件使用命名导出，lazy 直接读取默认导出失败工厂函数内解构 .then(m => ({ default: m.X }))，或改为默认导出
切换页面瞬间骨架屏反复闪烁chunk 体积过大、fallback 无过渡；关键首屏页面被错误分包大依赖单独拆包；高频路由保留在主 bundle；骨架屏高度与目标版面对齐
懒加载在条件分支中创建导致报错const X = lazy(...) 写在 if 或函数内部所有懒组件提升到模块顶层定义
StrictMode 下 chunk 被下载两次开发模式双重挂载触发重复执行，生产环境不发生属开发期正常现象，以生产构建行为为准（第 19 章）
chunk 文件名带内容 hash 时，旧版本 HTML 引用的 chunk 会在新版本发布后被清理；长生命周期页面（后台 SPA）要配置 chunk 加载失败的重试或强制刷新提示，不能只靠 Suspense 占位。
代码分割不是拆得越细越好：过细的 chunk 会让弱网下的路由切换变成多次往返。先按路由拆分，再用第 51 章的产物分析定位大依赖（图表库、编辑器）单独拆包，避免凭感觉切分。

✎ 本章习题

A 基础把 /about 与 /settings 两条路由改写成数据路由 lazy 字段写法；为懒加载期间配置一个「文字加载中」的 fallback，切换页面验证网络面板中两个 chunk 分别按需下载。
B 进阶为后台报表页设计骨架屏：标题行、两行摘要、一张图表占位块，结构与报表页一致；把报表路由的 Link 设为 prefetch="intent"，说明悬停时网络面板发生了什么，以及 prefetch="none" 适用的场景。
C 挑战模拟一次「发布新版本后旧用户加载 chunk 失败」的故障：描述触发链路，写出 chunk 加载失败时的错误边界兜底思路（结合第 37 章），并给出至少两条部署侧缓解措施（历史 chunk 保留、SPA fallback、关键路由不拆包）。
