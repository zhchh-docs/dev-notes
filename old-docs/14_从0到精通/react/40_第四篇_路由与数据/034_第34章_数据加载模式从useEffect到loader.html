34.1 旧式写法：useEffect 手写请求状态机

没有数据路由概念时，页面数据请求通常写在组件内：三个 useState 分别承担 loading、error、data，useEffect 在挂载或依赖变化时发起请求，并用 ignore 标记忽略过期响应（第 10、11 章的竞态处理思路）。

import { useState, useEffect } from 'react'

export default function PostList() {
  const [posts, setPosts] = useState([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState(null)

  useEffect(() => {
    let ignore = false
    setLoading(true)
    fetch('/api/posts')
      .then(res => {
        if (!res.ok) throw new Error('请求失败')
        return res.json()
      })
      .then(data => { if (!ignore) setPosts(data) })
      .catch(err => { if (!ignore) setError(err) })
      .finally(() => { if (!ignore) setLoading(false) })
    return () => { ignore = true }
  }, [])

  if (loading) return <p>加载中…</p>
  if (error) return <p>加载失败：{error.message}</p>
  return (
    <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>
  )
}
问题说明
数据请求晚于首次渲染组件先以空状态绘制，挂载后才发请求，首屏必然出现一轮 loading 闪烁
竞态需手工防护参数切换时旧响应可能后到，要靠 ignore 或 AbortController 丢弃过期结果
错误归属分散每个页面重复写 error 状态与兜底 UI，无法在路由层统一拦截降级
状态重复造轮子loading / error / data 三件套在每个列表页复制粘贴，缓存与重试无从谈起
切换路由残留快速跳转时未完成的请求与组件卸载耦合，清理逻辑分散在各 effect 中
这套写法在理解组件生命周期时是必要的；进入工程实践后，数据获取有两条成熟路线：路由 loader 负责页面级预取，TanStack Query 负责服务端状态的缓存、重试与后台刷新（第 25 章）。

34.2 loader：进入路由前完成数据加载

数据路由的 loader 是挂在 route 对象上的异步函数：路由匹配成功后、组件首次渲染之前执行，返回值通过 useLoaderData() 交给组件。用户看到页面时，数据已经在手，首屏不再先画空态再补数据。

import { createBrowserRouter, RouterProvider, useLoaderData } from 'react-router-dom'

async function postsLoader() {
  const res = await fetch('/api/posts')
  if (!res.ok) throw new Response('加载失败', { status: res.status })
  return res.json()
}

function PostList() {
  const posts = useLoaderData()
  return (
    <ul>
      {posts.map(p => <li key={p.id}>{p.title}</li>)}
    </ul>
  )
}

const router = createBrowserRouter([
  { path: '/posts', loader: postsLoader, element: <PostList /> },
])

export default function App() {
  return <RouterProvider router={router} />
}

等待 loader 期间的导航状态由 useNavigation() 暴露：用户从其他页面跳过来时，state 为 'loading'，当前页面可在侧边栏、按钮上展示「正在进入」的过渡态。

import { useNavigation } from 'react-router-dom'

export default function AppShell() {
  const navigation = useNavigation()
  const pending = navigation.state === 'loading'

  return (
    <div>
      {pending && <div className="top-progress" />}
      {/* 页面内容由 Outlet 渲染（第 30 章） */}
      <Outlet />
    </div>
  )
}
loader 在渲染前运行，组件拿到的就是完整数据；组件内不再需要为页面主数据维护 loading 状态，渲染分支从「空态 → 加载中 → 成功」简化为「成功渲染 / 错误降级」两条路径。

34.3 loader 参数、返回值与错误抛出

loader 接收一个上下文对象，携带当前请求与路由参数；返回值可以是任意可序列化数据（对象、数组、字符串等），组件用 useLoaderData 读取。加载失败时抛出 Response、Error 或 redirect，交给该路由（或祖先路由）的 errorElement 处理，错误边界机制在第 37 章展开。

字段 / 行为内容说明
requestRequest 对象读取 request.url 解析当前路径与查询参数；loader 内可发起后续 fetch
params路径参数对象与 useParams() 同源，如 params.postId（第 31 章）
context路由器提供的共享上下文可注入自定义依赖（如查询客户端、鉴权客户端）
返回值任意可序列化数据组件通过 useLoaderData() 获取；结构由接口返回值决定
抛 404 / 403throw new Response('Not Found', { status: 404 })状态码进入 useRouteError()，由 errorElement 分级展示
抛重定向throw redirect('/login?from=...')守卫场景复用，见第 32 章
 
const router = createBrowserRouter([
  {
    path: '/posts/:postId',
    loader: async ({ params }) => {
      const postId = Number(params.postId)
      if (!Number.isInteger(postId) || postId <= 0) {
        throw new Response('Not Found', { status: 404 })
      }
      const res = await fetch(`/api/posts/${postId}`)
      if (res.status === 404) throw new Response('Post Not Found', { status: 404 })
      if (!res.ok) throw new Response('Server Error', { status: 500 })
      return res.json()
    },
    element: <PostDetail />,
    errorElement: <PostError />,
  },
])
loader 在浏览器端执行，仍需遵守浏览器网络边界：跨域由服务端 CORS 配置；敏感校验与归属判断在服务端接口完成，loader 只负责取数与引导降级。

34.4 模式对照：useEffect 与 loader

图 34-1 两种数据获取模式的时序对比：loader 把数据加载前移到渲染之前

维度useEffect 手写请求路由 loader
触发时机组件挂载或依赖变化之后路由匹配后、组件渲染之前
首屏表现先空态、再 loading、后成功，两轮渲染首次渲染即携带数据，无空态闪烁
竞态处理手工 ignore / AbortController路由切换时旧导航被框架中断，避免过期结果写入新页面
错误归属组件内 error 状态 + 本页兜底抛出 Response / Error，由路由 errorElement 统一降级
loading 来源组件内 loading 状态useNavigation().state === 'loading'
缓存与重试无内置能力，需要自行实现路由数据在会话期间保留，不做跨标签页缓存；复杂服务端状态交 TanStack Query
不要把组件内 useEffect 请求原样搬进 loader：effect 模式下的 loading 状态、竞态 ignore 标记在 loader 中都不需要——框架承担导航中断与渲染前等待，保留旧写法只会叠加两套状态管理。

34.5 action：路由级表单提交与 mutation

与 loader 对应，action 是挂在 route 上的提交处理函数：表单通过 <form method="post"> 或 useSubmit 触发，框架把 Request 交给 action；提交期间 useNavigation().state 为 'submitting'，action 返回值由 useActionData 读取。提交成功后通常 redirect 到结果页，并触发相关 loader 重新取数。

import {
  createBrowserRouter, redirect, useActionData, useNavigation,
} from 'react-router-dom'

async function createPostAction({ request }) {
  const formData = await request.formData()
  const title = formData.get('title')
  const body = formData.get('body')

  const res = await fetch('/api/posts', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title, body }),
  })
  if (!res.ok) {
    // 返回校验/错误信息，组件用 useActionData 展示
    return { ok: false, message: '提交失败，请重试' }
  }
  const data = await res.json()
  // 成功后重定向到详情页，并触发列表 loader 重新执行
  return redirect(`/posts/${data.id}`)
}

function PostForm() {
  const actionData = useActionData()
  const navigation = useNavigation()
  const submitting = navigation.state === 'submitting'

  return (
    <form method="post">
      {actionData && !actionData.ok && <p className="form-error">{actionData.message}</p>}
      <input name="title" placeholder="标题" />
      <textarea name="body" placeholder="正文" />
      <button disabled={submitting}>{submitting ? '提交中…' : '发布'}</button>
    </form>
  )
}

const router = createBrowserRouter([
  { path: '/posts/new', action: createPostAction, element: <PostForm /> },
])
维度手写 fetch 提交路由 action
触发方式handleSubmit 回调内 fetch POST原生 <form method="post"> 或 useSubmit 触发
提交中状态组件内 submitting 布尔状态useNavigation().state === 'submitting'
错误反馈组件状态保存服务端错误，手工渲染提示action 返回值由 useActionData 读取
成功跳转回调内 navigateaction 内 redirect，并自动触发相关 loader 重取
无 JS 降级依赖 JavaScript 事件绑定原生表单语义更完整，可配合渐进增强策略
loader 与 action 是数据路由的两个对称入口：loader 读取数据、在进入前完成；action 写入数据、在提交后执行。两者共享 request、params 上下文，错误都抛给 errorElement，成功后由框架触发相关 loader 重新取数。
表单交互层（受控、校验、错误提示）使用 react-hook-form 与 zod，见第 35、36 章；action 负责服务端提交与重定向，两者在一个页面内分工协作。

34.6 选型边界：loader 与 TanStack Query

工程中两类数据需求并存：页面进入即需要、随路由归属的路由级数据；跨组件共享、需要缓存、后台刷新、失效控制的服务端状态。React Router loader 解决前者，TanStack Query（第 25 章）解决后者，二者不互相替代。

维度路由 loaderTanStack Query v5
数据归属当前路由页面的主数据跨组件复用的服务端状态（用户信息、字典、列表缓存）
缓存能力路由会话内保留，无过期策略staleTime、gcTime、后台刷新、窗口聚焦重取
竞态与重试导航级中断，无内置重试请求去重、自动重试、过期标记、乐观更新（第 27 章）
触发位置路由匹配阶段集中配置组件内 useQuery 声明依赖与查询键
典型场景详情页主记录、页面骨架所需概览数据可搜索列表、评论流、通知轮询、全局用户信息
选型先回答「这份数据属于谁」：属于当前路由页面主记录的进 loader；属于跨组件共享、需要缓存与后台刷新的服务端状态进 TanStack Query。一份数据只选一条通道，避免在路由 loader 与查询缓存之间重复请求。
不要把 loader 当缓存层使用：同一数据在多个路由 loader 中重复请求时，应上移为 TanStack Query 查询；反之，把纯页面主数据塞进 useQuery 也会丢失路由预取带来的「渲染前就绪」优势。
action 返回的错误信息只在当前提交周期内有效：useActionData 不会自动随导航清空，组件卸载或重定向后读取到的可能是上一次提交的残留结果；成功路径务必 redirect，不要停留在原页面依赖旧 action 数据。
