61.1 上传的本质：文件流到 FormData

浏览器上传文件的标准方式是用 FormData 把 File 对象放进 multipart 请求体，用 fetch 或 XMLHttpRequest 发送。antd Upload 只是把"选文件 → 上传"这套交互封装好，真正的网络请求仍要交给你的接口。

const formData = new FormData();
formData.append('file', file);           // 文件字段
formData.append('folder', 'avatars');    // 附加业务字段
formData.append('userId', '1001');

// 用 fetch 上传（携带鉴权 header）
const res = await fetch('/api/upload', {
  method: 'POST',
  body: formData,
  headers: { Authorization: `Bearer ${token}` },
});
不要手设 Content-Type当 body 是 FormData 时，不要手动设置 Content-Type——浏览器会自动带上带 boundary 的 multipart/form-data; boundary=...`。手动设置会丢失 boundary 导致后端解析失败。

61.2 antd Upload 受控文件列表

Upload 是受控组件：fileList 由 state 持有，onChange 回写。配合第 35 章 Form，还能作为 Form.Item 的表单字段一起提交：

import { Upload, Button } from 'antd';
import { UploadOutlined } from '@ant-design/icons';
import { useState } from 'react';

function AvatarUpload() {
  const [fileList, setFileList] = useState([]);

  return (
    <Upload
      fileList={fileList}
      onChange={({ fileList: next }) => setFileList(next)}
      // 见下一节：customRequest 决定真正上传
    >
      <Button icon={<UploadOutlined />}>选择文件</Button>
    </Upload>
  );
}
Upload 受控的关键是 fileList 里每个 file 都携带 status（uploading/done/error/removed）与 response（接口返回值）。列表 UI 完全由这组受控数据驱动，与第 6 章受控组件一脉相承。

61.3 customRequest 自定义上传

默认 Upload 会走它的内置 xhr；要接自己的接口与鉴权，用 customRequest 接管。它收到 { file, onSuccess, onError, onProgress }，你在里面发请求并回调：

function customRequest({ file, onSuccess, onError, onProgress }) {
  const formData = new FormData();
  formData.append('file', file);
  formData.append('type', 'avatar');

  const xhr = new XMLHttpRequest();
  xhr.open('POST', '/api/upload');
  xhr.setRequestHeader('Authorization', `Bearer ${getToken()}`);

  // 进度回调
  xhr.upload.onprogress = (e) => {
    if (e.lengthComputable) onProgress({ percent: Math.round((e.loaded / e.total) * 100) });
  };

  xhr.onload = () => {
    if (xhr.status === 200) {
      const data = JSON.parse(xhr.responseText);
      onSuccess(data);            // 结果写入 file.response
    } else {
      onError(new Error(`上传失败：${xhr.status}`));
    }
  };
  xhr.onerror = () => onError(new Error('网络错误'));
  xhr.send(formData);
}
用 XMLHttpRequest（而非 fetch）是为了拿到上传进度事件 upload.onprogress——fetch 目前对上传进度支持有限。需要进度条时，customRequest 内用 xhr 是常见做法。

61.4 前置校验：类型与大小

上传前用 beforeUpload 做校验：返回 false 阻止上传，抛 Error 会进入 onChange 且 status 变 error。类型判断用扩展名或 MIME 均可，大小用字节比较：

function beforeUpload(file) {
  const isImg = ['image/jpeg', 'image/png', 'image/webp'].includes(file.type);
  if (!isImg) {
    message.error('仅支持 jpg/png/webp 图片');
    return Upload.LIST_IGNORE; // 忽略，不加入列表
  }
  const isLt5M = file.size / 1024 / 1024 < 5;
  if (!isLt5M) {
    message.error('图片需小于 5MB');
    return Upload.LIST_IGNORE;
  }
  return true;
}

<Upload beforeUpload={beforeUpload} ... />
校验返回行为适用
true继续上传校验通过
false阻止上传，但文件仍进列表需要自己手动上传的流程
Promise.reject阻止并标为 error校验失败给出明确提示
Upload.LIST_IGNORE忽略，不进列表类型/大小不符直接丢弃
只用 file.type 判断类型不可靠（可被伪造），后端仍要基于文件内容做类型检测（如 magic number）与大小限制。前端校验是体验，后端校验是安全，与第 58 章权限边界同一原则。

61.5 进度、成功与失败状态

上传状态由 fileList 里的 file.status 与 file.percent 驱动：customRequest 里回调 onProgress 更新 percent，onSuccess 置 done，onError 置 error。展示交给 antd，业务只需管理回调。

// 在 onChange 里汇总当前是否全部成功
function onChange({ file, fileList: next }) {
  setFileList(next);
  const uploading = next.some((f) => f.status === 'uploading');
  const hasError = next.some((f) => f.status === 'error');
  setBusy(uploading);
  setHasError(hasError);
}
提交联动：表单里"上传中不能提交、有失败不能提交"。用上面的汇总判断控制提交按钮 disabled，避免用户在上传未完成/失败时提交不完整数据。

61.6 图片预览与已传文件回显

图片上传后要能预览、编辑时要把已传文件回显。回显的做法是：把已存在文件的 URL 放进 fileList，文件对象形如 { uid: '-1', name, status: 'done', url }（uid 用字符串编号避免与本地文件冲突）：

// 编辑回显：把后端返回的已有文件映射成 fileList
const initialFileList = existingFiles.map((f) => ({
  uid: `-${f.id}`,          // 负 uid 表示"非本地新建"
  name: f.name,
  status: 'done',
  url: f.url,
  response: { id: f.id, url: f.url },
}));

// 预览：antd 内置 Image 预览，用 onPreview 触发
onPreview={(file) => {
  window.open(file.url ?? file.response?.url, '_blank');
}}
回显文件用负值 uid（如 -1）是 antd 约定，用来区分"已上传的存量"与"本地上传的新文件"；提交时据此把存量文件 id 与新上传结果合并给后端。

61.7 大文件分片与断点续传

大文件（视频、压缩包）整文件上传慢且失败难恢复。工程上的通用方案是分片上传 + 断点续传：

  • 分片：把文件按固定大小（如 2MB）切成 Blob 片段，逐片上传；
  • 标识：每片带 fileHash + chunkIndex，后端按 hash 重组；
  • 并发：限制同时上传的片数（如 3 片），避免一次发太多；
  • 续传：先问后端"该文件已有哪些片"，跳过已传片继续传剩余；
  • 合并：全部片传完，调合并接口让后端按 hash 拼回文件。
const CHUNK = 2 * 1024 * 1024; // 每片 2MB

function sliceFile(file) {
  const chunks = [];
  for (let start = 0; start < file.size; start += CHUNK) {
    chunks.push(file.slice(start, start + CHUNK));
  }
  return chunks;
}
工程衔接：分片逻辑与前端框架关系不大，可抽成独立工具模块复用。真正的断点续传还需要后端配合（查询已传分片、按 hash 合并），本章给前端侧概念，落地时与后端约定接口协议。
