60.1 ECharts 定位与引入方式

ECharts 是 Apache 基金会下的开源图表库，生态成熟、中后台 BI 用得最多。它和 React 没有"原生绑定"——echarts.init(dom, theme, opts) 直接操作一个 DOM 容器，实例生命周期由开发者管理。正因为此，React 里集成 ECharts 的核心就是：把实例生命周期对齐到 React 的挂载/更新/卸载。

npm install echarts
# 如需 React 封装，可加 echarts-for-react（常用），本章讲更透明的自封装
两种路线：用现成封装 echarts-for-react（省事、把生命周期和 resize 都处理了）；或自封装（更可控、更贴合项目主题与按需）。本章以自封装讲透原理，你掌握后两种都能理解。

60.2 option 驱动的图表本质

ECharts 是声明式的：你描述一份 option（series 系列、xAxis 横轴、tooltip 提示等），它负责画出来。改图表就是改 option 再 setOption。这与 React 声明式 UI 的心智高度一致——所以数据是 option，组件只是载体。

const option = {
  xAxis: { type: 'category', data: ['周一', '周二', '周三'] },
  yAxis: { type: 'value' },
  series: [
    {
      name: '订单量',
      type: 'bar',
      data: [120, 200, 150],
      itemStyle: { color: '#2d6a3f' },
    },
  ],
  tooltip: { trigger: 'axis' },
};
理解 ECharts 的关键是"option 就是图表的全部"：类型（bar/line/pie…）、数据、样式、交互都在 option 里。React 组件只需负责"option 变了就 setOption"，这是封装的基础。

60.3 实例生命周期：初始化与销毁

在 useEffect 里 init 实例，并把实例存 ref；清理函数里 dispose 释放。注意：init 只做一次（依赖空数组），不要因为数据变化重新 init，否则会产生多个实例、内存泄漏。

import * as echarts from 'echarts';
import { useEffect, useRef } from 'react';

function SimpleChart({ option }) {
  const domRef = useRef(null);
  const chartRef = useRef(null);

  useEffect(() => {
    // 仅挂载时创建实例一次
    chartRef.current = echarts.init(domRef.current);
    chartRef.current.setOption(option);
    return () => {
      chartRef.current.dispose(); // 卸载时释放，防内存泄漏
      chartRef.current = null;
    };
  }, []); // 注意：不依赖 option

  // 数据变化时更新（下面小节细讲）

  return <div ref={domRef} style={{ width: '100%', height: 360 }} />;
}
实例重复创建的坑若把 init 放进依赖 option 的 effect，option 一变就重新 init + dispose，旧实例刚销毁又新建——不仅闪烁，折叠容器里还可能因旧实例未清理而累积。init 只跑一次，更新走 setOption。

60.5 数据变化：setOption 与 notMerge

option 变化用第二个 effect 调 setOption(option, notMerge)。notMerge 决定是否合并旧配置：增量更新用 false（保留已有组件），完全重建用 true。多数看板场景传 true 更省心，避免残留旧 series。

useEffect(() => {
  const chart = chartRef.current;
  if (!chart) return;
  chart.setOption(option, true); // true = 不合并，直接按新 option 重建
}, [option]);
不要忘了在数据变化 effect 里判空（实例可能尚未 init 或已 dispose）。React 严格模式下 effect 会双执行，配合 init 只跑一次 + setOption 判空 才能稳定。

60.6 resize 与容器自适应

图表容器尺寸变化（窗口缩放、侧栏收起、折叠面板展开）时，ECharts 不会自动重排，必须调 chart.resize()。监听 window.resize 是基本做法；更稳妥用 ResizeObserver 观察容器本身（窗口没变但容器变了也生效）。

useEffect(() => {
  const chart = chartRef.current;
  if (!chart) return;
  const ro = new ResizeObserver(() => chart.resize());
  ro.observe(domRef.current);
  return () => ro.disconnect();
}, []);
衔接说明：容器自适应与前一篇性能优化里"长列表"同源——都是"元素进入视口/容器尺寸变化时再做昂贵操作"。用 ResizeObserver 而非简单监听 window 事件，能覆盖布局联动带来的容器变化。
折叠面板/路由切换隐藏图表时，容器宽度可能为 0，resize 会画成一条缝。隐藏前 dispose 或隐藏后 resize，配合"容器有宽度再渲染"判断，避免图表在不可见容器里被压扁。

60.7 封装成可复用 React 组件

把上面的生命周期收进一个 <Chart option={...} height={...} /> 组件：接收 option 与高度，内部管理实例、resize、销毁，并提供 loading 与主题。业务只传 option，图表细节全部封装：

import { useEffect, useRef } from 'react';
import * as echarts from 'echarts';

export default function Chart({ option, height = 360, theme }) {
  const domRef = useRef(null);
  const chartRef = useRef(null);

  useEffect(() => {
    chartRef.current = echarts.init(domRef.current, theme);
    return () => { chartRef.current.dispose(); chartRef.current = null; };
  }, [theme]);

  useEffect(() => {
    chartRef.current?.setOption(option, true);
  }, [option]);

  useEffect(() => {
    const chart = chartRef.current;
    if (!chart) return;
    const ro = new ResizeObserver(() => chart.resize());
    ro.observe(domRef.current);
    return () => ro.disconnect();
  }, []);

  return <div ref={domRef} style={{ width: '100%', height }} />;
}

// 业务用法
<Chart option={orderTrendOption} height={320} theme="forest" />;
封装的收益是把 ECharts 的"命令式生命周期"翻译成 React 的"声明式组件"：业务只管给 option，实例创建/更新/resize/销毁全部内部化。这是"库命令式 → 组件声明式"的标准封装模式。

60.8 按需引入与主题

全量 import * as echarts 会打包全部图表类型，体积较大。按需引入用 echarts/core + 只注册用到的图表与组件：

import * as echarts from 'echarts/core';
import { BarChart, LineChart, PieChart } from 'echarts/charts';
import {
  TitleComponent, TooltipComponent, GridComponent,
  LegendComponent, DatasetComponent,
} from 'echarts/components';
import { CanvasRenderer } from 'echarts/renderers';

echarts.use([
  BarChart, LineChart, PieChart,
  TitleComponent, TooltipComponent, GridComponent, LegendComponent, DatasetComponent,
  CanvasRenderer,
]);
模块作用
echarts/core核心入口，不含具体图表，需手动注册
echarts/charts图表类型：Bar/Line/Pie/Scatter…
echarts/components组件：Title/Tooltip/Grid/Legend/Dataset…
echarts/renderers渲染器：CanvasRenderer / SVGRenderer

主题可通过 echarts.init(dom, theme) 的第二个参数传入注册过的主题名；也可统一在 option 里用 color 数组定制色板，与项目森林绿视觉一致。记住：注册过的图表类型用不到时，会有运行时警告提示你补充 use()。

按需引入后，所有 option 里用到的图表类型与组件都要在 echarts.use 里注册，漏注册图表会白屏且控制台报 "not found: XXXChart"。新增图表类型时同步补注册。
