57.1 列表页的"三态"数据模型

后台列表页几乎都是服务端分页：数据不在前端全量缓存，而是把查询条件、页码、页大小传给后端，由后端返回当前页数据与总数。因此列表页的状态被拆成三块：

  • 查询条件（filters）：关键词、状态、日期范围等搜索项；
  • 分页（pagination）：current 页码、pageSize 每页条数、total 总数（total 通常由后端返回）；
  • 数据列表（dataSource）：当前页的行数据，伴随 loading 状态。

图 57-1 列表页三态与请求参数的关系

核心联动规则：搜索条件变化时，页码必须重置为 1——否则你从第 3 页搜关键词，返回的是新条件下的第 3 页，页面会显得"跳到奇怪位置"。这是后台分页最容易漏的细节。

57.2 Table 列配置与受控数据

Table 是受控组件：columns 描述列结构，dataSource 提供行数据，pagination 对象控制分页显示与回调。列里放按钮、状态标签都通过 render 返回 ReactNode：

import { Table, Tag, Space, Button } from 'antd';

const statusColor = { PAID: 'green', PENDING: 'orange', FAILED: 'red' };

const columns = [
  { title: '订单号', dataIndex: 'id', key: 'id', width: 180 },
  { title: '客户', dataIndex: 'customer', key: 'customer' },
  {
    title: '状态',
    dataIndex: 'status',
    key: 'status',
    render: (v) => <Tag color={statusColor[v]}>{v}</Tag>,
  },
  { title: '金额', dataIndex: 'amount', key: 'amount', align: 'right' },
  {
    title: '操作',
    key: 'action',
    render: (_, record) => (
      <Space>
        <Button size="small" onClick={() => onEdit(record)}>编辑</Button>
        <Button size="small" danger onClick={() => onDelete(record)}>删除</Button>
      </Space>
    ),
  },
];
rowKey 铁律Table 必须有稳定唯一 rowKey（业务主键，如 rowKey="id"）。没有它，antd 会用行索引当 key，删除/更新/展开行时会出现行状态错乱。这与第 6 章列表 key 的原则一致，只是落在表格场景。
<Table
  rowKey="id"
  columns={columns}
  dataSource={rows}
  loading={loading}
  pagination={{
    current,
    pageSize,
    total,
    showSizeChanger: true,
  }}
  onChange={(pagination) => {
    setCurrent(pagination.current);
    setPageSize(pagination.pageSize);
  }}
/>

57.3 服务端分页与搜索联动

把三态合成一个请求。搜索表单用 Form 收集条件，onFinish 时把条件写进 state 并重置页码到 1，随后请求。用一个 useEffect 监听「条件 + 页码 + 页大小」变化统一发起请求：

import { useEffect, useState } from 'react';
import { Form, Input, Select, DatePicker, Button } from 'antd';

function OrderListPage() {
  const [form] = Form.useForm();
  const [filters, setFilters] = useState({ keyword: '', status: '' });
  const [pagination, setPagination] = useState({ current: 1, pageSize: 10, total: 0 });
  const [rows, setRows] = useState([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    let ignore = false;
    setLoading(true);
    fetchOrders({
      ...filters,
      page: pagination.current,
      pageSize: pagination.pageSize,
    }).then((res) => {
      if (ignore) return;
      setRows(res.list);
      setPagination((p) => ({ ...p, total: res.total }));
    }).finally(() => { if (!ignore) setLoading(false); });
    return () => { ignore = true; };
  }, [filters, pagination.current, pagination.pageSize]);

  function onSearch(values) {
    setFilters(values);      // 条件变化
    setPagination((p) => ({ ...p, current: 1 })); // 必须重置页码
  }

  return (
    <>
      <Form form={form} layout="inline" onFinish={onSearch}>
        <Form.Item name="keyword"><Input placeholder="订单号/客户" /></Form.Item>
        <Form.Item name="status">
          <Select options={[{ value: 'PAID', label: '已支付' }, { value: 'PENDING', label: '待支付' }]} allowClear />
        </Form.Item>
        <Form.Item><Button type="primary" htmlType="submit">搜索</Button></Form.Item>
      </Form>
      <Table ... />
    </>
  );
}
不要在 onChange 里同时改 filters 和 current 两处状态并各自触发一次请求——那样会出现双请求。用 onSearch 一次性更新（filters 新值 + current 归 1），让唯一的数据流由 useEffect 驱动。

57.4 编辑弹窗与受控表单

编辑通常用 Modal 弹窗 + Form：点"编辑"把行记录 setFieldsValue 进表单，点"新增"则清空。关键区别是 initialValues 只在首次挂载生效，二次打开不会重置，所以编辑场景应优先用 form.setFieldsValue(record)。

import { Modal, Form, Input, message } from 'antd';
import { useEffect } from 'react';

function OrderEditModal({ open, record, onClose, onSave }) {
  const [form] = Form.useForm();

  useEffect(() => {
    if (open) {
      if (record) form.setFieldsValue(record); // 编辑：回填行数据
      else form.resetFields();                 // 新增：清空
    }
  }, [open, record, form]);

  async function handleOk() {
    const values = await form.validateFields();
    await onSave(values);
    message.success('保存成功');
    onClose();
  }

  return (
    <Modal title={record ? '编辑订单' : '新增订单'} open={open} onOk={handleOk} onCancel={onClose}>
      <Form form={form} layout="vertical">
        <Form.Item name="customer" label="客户" rules={[{ required: true }]}>
          <Input />
        </Form.Item>
        <Form.Item name="amount" label="金额" rules={[{ required: true }]}>
          <InputNumber min={0} precision={2} style={{ width: '100%' }} />
        </Form.Item>
      </Form>
    </Modal>
  );
}
受控边界：Modal 的 open 由父组件控制，Form 的 value 由 Form.Item name 管理，两者各自受控、互不越界。关闭弹窗不销毁时，用 forceRender/destroy 策略决定 Form 是否保留旧值。

57.5 校验、异步校验与提交

antd Form 用 rules 声明式校验；需要"用户名是否已存在"这类服务端校验时，用带 validator 的规则做异步校验。提交时先 validateFields，成功才进入保存，避免"没校验就发请求"。

<Form.Item
  name="username"
  label="用户名"
  rules={[
    { required: true, message: '请输入用户名' },
    {
      validator: async (_, value) => {
        if (!value) return;
        const taken = await checkUsername(value); // 服务端校验
        if (taken) throw new Error('用户名已存在');
      },
      validateTrigger: 'onBlur',
    },
  ]}
>
  <Input />
</Form.Item>
校验时机异步校验默认在提交与指定 trigger 时跑；高频 onChange 触发服务端校验会造成请求风暴。用户名校验用 validateTrigger: 'onBlur'，提交仍统一走 validateFields。

57.6 复用：把列表页抽象成通用模块

同一个后台有成百个列表页，结构高度一致。可抽象一个 ProTable 式通用组件：把「分页 state + 请求 + 条件重置」收进内部，页面只负责提供请求函数与列配置。这里给出最小骨架，理解抽象点即可：

// usePagedQuery：把三态 + 请求封装成一条 hooks
function usePagedQuery(fetcher) {
  const [filters, setFilters] = useState({});
  const [pagination, setPagination] = useState({ current: 1, pageSize: 10, total: 0 });
  const [data, setData] = useState([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    let ignore = false;
    setLoading(true);
    fetcher({ ...filters, page: pagination.current, pageSize: pagination.pageSize })
      .then((res) => { if (ignore) return; setData(res.list); setPagination((p) => ({ ...p, total: res.total })); })
      .finally(() => { if (!ignore) setLoading(false); });
    return () => { ignore = true; };
  }, [filters, pagination.current, pagination.pageSize, fetcher]);

  return { data, loading, filters, pagination, setFilters, setPagination };
}
抽象层次内容收益
usePagedQuery三态 + 请求 + 重置联动分页逻辑一份维护
通用列表组件表头/分页/空态/loading 组合视觉与交互统一
页面级配置columns + fetcher + 操作列业务差异留页面
抽象要克制：通用组件只收"所有列表都一样的逻辑"，不要把单个页面的特殊列、特殊权限判断也塞进去——过度抽象比重复代码更难维护。

57.7 常见坑与错误边界

  • 双请求：搜索同时改条件与页码、或 useEffect 依赖了非必要对象；用单一数据源 + 依赖收敛解决；
  • total 归位：删除最后一页最后一条后 total 变化，current 可能越界，需在响应后判断并回退页码；
  • key 冲突：rowKey 用了可重复字段（如 status）导致渲染错乱，必须用唯一主键；
  • 弹窗旧值：setFieldsValue 前未 reset，编辑后切新增仍带旧数据；用 useEffect 按 open/record 分支重置；
  • 请求竞态：连续翻页或切换条件时旧响应晚到覆盖新响应；用 ignore 标志或请求序号丢弃过期响应（上面代码已示范 ignore）。
列表页问题的本质，多数是状态归属不清 + 数据流不唯一。把三态放对位置、让 useEffect 成为唯一请求入口、用 ignore 防竞态，这类页面就能稳定。
