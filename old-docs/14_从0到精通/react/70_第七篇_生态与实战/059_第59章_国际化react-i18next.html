59.1 i18n 是什么与 i18next 的定位

国际化（internationalization，缩写 i18n，因为单词首尾 i/n 之间隔着 18 个字母）指的是：让应用支持多种语言，切换语言时文案、格式、方向随之变化。在前端落地时，我们不会为每种语言各写一套页面，而是把"文案"抽成翻译资源，用一套逻辑 + 多份语言文件渲染。

i18next 是当前 React 生态最主流的国际化框架，核心库只负责翻译能力，react-i18next 是它的 React 绑定，提供 useTranslation 等 hooks。

包职责
i18next翻译核心：语言管理、翻译资源、插值/复数/命名空间
react-i18nextReact 绑定：useTranslation / Trans / I18nextProvider
i18next-browser-languagedetector自动检测浏览器语言，可选
i18next-http-backend从远端按需加载翻译资源，大型项目可选

59.2 初始化 i18next 与翻译资源

安装并用 initReactI18next 把 i18next 接入 React。翻译资源按语言组织成嵌套对象，key 通常用点号路径引用：

npm install i18next react-i18next
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

const resources = {
  'zh-CN': {
    translation: {
      common: { confirm: '确认', cancel: '取消', save: '保存' },
      order: { title: '订单管理', total: '共 {{count}} 条', empty: '暂无订单' },
    },
  },
  'en-US': {
    translation: {
      common: { confirm: 'Confirm', cancel: 'Cancel', save: 'Save' },
      order: { title: 'Orders', total: '{{count}} records', empty: 'No orders' },
    },
  },
};

i18n.use(initReactI18next).init({
  resources,
  lng: 'zh-CN',        // 默认语言
  fallbackLng: 'en-US', // 缺 key 时回退的语言
  interpolation: { escapeValue: false }, // React 已处理转义
});

export default i18n;
翻译资源的引用路径就是 key：t('order.title') 会去当前语言文件里找 order.title。资源用嵌套对象 + 点号路径，天然支持按模块（common/order/user…）分区维护。

59.3 useTranslation 与 t 函数

在组件里用 useTranslation() 拿到 t 函数，调用 t('key') 取当前语言的文案。语言切换后，用到 t 的组件会自动重渲染——这是 react-i18next 通过订阅语言变化实现的。

import { useTranslation } from 'react-i18next';

function OrderToolbar({ onSave }) {
  const { t } = useTranslation();

  return (
    <div>
      <h1>{t('order.title')}</h1>
      <Button type="primary" onClick={onSave}>{t('common.save')}</Button>
    </div>
  );
}
不要在 t 的返回值上再拼接 JSX 文案（如 t('a') + ' ' + t('b')）——语言之间语序不同，拼接会坏。要组合文案请用插值或 Trans 组件，把变量交给 t 处理。

59.4 插值、复数与命名空间

带变量的文案用插值：翻译模板里写 {{name}}，t 的第二个参数传对象替换。复数语法 _one/_other 处理"1 条 / 多条"：

// 翻译资源（zh-CN）
{
  "order": {
    "greeting": "你好，{{name}}",
    "itemCount_one": "共 {{count}} 条订单",
    "itemCount_other": "共 {{count}} 条订单"
  }
}
const { t } = useTranslation();

<p>{t('order.greeting', { name: user.name })}</p>
<p>{t('order.itemCount', { count: items.length })}</p>

复数在英文里区分单复数（_one/_other），中文通常两者相同也照写即可。命名空间用于把资源按域拆开（ns: 'order'），适合大型应用隔离维护：

// 用命名空间指定资源域
const { t } = useTranslation('order');
// 此时 t('title') 从 order 命名空间取，而不是默认的 translation
复数 key 约定i18next 的复数依赖 count 字段与 _one/_other 后缀约定；漏写 count 参数或后缀写错，会回退到 _other 甚至原始 key。写复数文案时严格按 i18next 的 Plural 规则。

59.5 语言切换与持久化

切换语言调用 i18n.changeLanguage('en-US')。为了让用户选择在刷新后保留，通常存到 localStorage，并在初始化时读取；更省事的是用 i18next-browser-languagedetector 自动检测与持久化。

import i18n from '../i18n';

function LanguageSwitch() {
  return (
    <Select
      value={i18n.language}
      onChange={(lng) => i18n.changeLanguage(lng)}
      options={[
        { value: 'zh-CN', label: '中文' },
        { value: 'en-US', label: 'English' },
      ]}
    />
  );
}
衔接说明：语言选择本质是"全局状态 + 持久化"，与你第 3 篇学的状态管理同源。若项目已用 Zustand/Redux，可把语言放 store 并同步 i18n；但多数项目直接 changeLanguage + 持久化即可，不必过度设计。

59.6 与 antd 组件语言联动

antd 组件自带的文案（分页"上一页"、日期选择等）由 ConfigProvider locale 控制，和你的业务文案是两套系统。切换语言时两者要同步切换：把 i18next 语言变化反映到 ConfigProvider 的 locale 上。

import { ConfigProvider } from 'antd';
import zhCN from 'antd/locale/zh_CN';
import enUS from 'antd/locale/en_US';
import { useTranslation } from 'react-i18next';

const localeMap = { 'zh-CN': zhCN, 'en-US': enUS };

function App() {
  const { i18n } = useTranslation();
  const locale = localeMap[i18n.language] || enUS;

  return (
    <ConfigProvider locale={locale}>
      <AppShell />
    </ConfigProvider>
  );
}
不要只切 i18next 忘了 antd locale——会出现"你自己写的按钮中文了，但 DatePicker 还是英文"。antd locale 是组件库自己的系统，必须和业务语言用同一个语言源驱动，避免分叉。

59.7 翻译资源组织与维护

随着页面变多，翻译资源会迅速膨胀。几点维护建议：

  • 按模块分文件：common、order、user 等各建一个语言文件，而不是把所有 key 堆一个巨大对象；
  • key 命名有语义：用「模块.页面.元素」分级，避免用中文当 key、也避免超长无结构 key；
  • 缺失回退：设好 fallbackLng，并开启 key 缺失的提醒（开发期）以便及时补齐；
  • 减少拼接：凡涉及变量一律插值，让翻译者能调整语序；
  • 后端文案分离：接口返回的提示语若需要国际化，后端也应返回 code 而非中文文案，前端按 code 映射翻译。
国际化的最佳实践不是"把中文字符串换成 t()"，而是从一开始就把所有面向用户的文案当资源对待：key 稳定、变量插值、语言文件独立——这样加语言只是加一份翻译，不动组件逻辑。
