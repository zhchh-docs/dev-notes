19.1 模块与包的形态

myproject/
├── main.py                  ← 入口脚本
├── utils.py                 ← 模块（一个 .py 文件）
└── package/                 ← 包（一个目录）
    ├── __init__.py          ← 包的标识（可为空）
    ├── models.py
    └── services/
        ├── __init__.py
        └── user.py          ← 子包里的模块

要点：

  • 模块名 = 文件名（不含 .py）。utils.py 导入时写作 import utils；
  • 包 = 含 __init__.py 的目录。Python 3.3+ 支持"命名空间包"（无 __init__.py 也能导入），但正规项目请保留它；
  • __init__.py 在包首次被导入时执行，常用来导出便捷接口或做初始化。
# package/__init__.py
'''用户相关的包。'''
from .models import User          # 相对导入：把常用名字提到包一级

__all__ = ["User", "create_user"]   # 定义 from package import * 时导出什么
__version__ = "1.0.0"

# 使用方
# from package import User        ← 不用知道 User 在哪个子模块
常见坑把文件命名为 json.py、random.py、email.py、types.py、test.py 等标准库同名的名字，会导致"顶替标准库"的诡异报错。命名前先想想标准库里有没有同名的（第 2 章已提醒）。

19.2 四种导入写法

# ① 导入整个模块（推荐：命名空间清晰，不会污染当前作用域）
import os
print(os.path.join("a", "b"))

# ② 导入并起别名
import numpy as np
import pandas as pd

# ③ 从模块导入指定名字（用得多，但要注意重名）
from datetime import datetime, timedelta
print(datetime.now())

# ④ 从模块导入并起别名（解决重名、缩短长名字）
from collections import defaultdict as dd
import matplotlib.pyplot as plt
写法优点注意
import mod来源清晰，无命名冲突每次要写模块名前缀
import mod as m缩短长名字约定俗成的别名要遵守（np/pd/plt）
from mod import x使用时更短可能与本文件名字冲突
from mod import *省事禁止在生产代码里用：污染命名空间、来源不明
强烈建议① 标准库、第三方、本地导入分三组、中间空一行（PEP 8），组内按字母序；② 不用 import *；③ from x import y 导入的是值的绑定——若模块里后来改了 y，你这里的 y 不会跟着变（想跟着变就 import x 再用 x.y）。
# 导入顺序示范（isort / ruff 会自动整理，第 36 章）
# ① 标准库
import os
import sys
from pathlib import Path

# ② 第三方
import httpx
from fastapi import FastAPI

# ③ 本地
from myproject.config import settings
from myproject.services import user_service

19.3 搜索路径与 sys.path

import foo 时，解释器按顺序在三处找 foo：

  1. 内置模块（sys.builtin_module_names）；
  2. sys.path 列表里的目录——依次是：脚本所在目录（或当前工作目录）→ PYTHONPATH 环境变量 → 标准库目录 → site-packages（第三方包）；
  3. 找不到就抛 ModuleNotFoundError。
import sys
print(sys.path[:3])          # 前几项通常是脚本目录与标准库路径
print(sys.builtin_module_names[:5])

# 诊断"明明装了却找不到"的三板斧
import mypkg
print(mypkg.__file__)        # 实际导入的是哪个文件？（关键！）
print(sys.modules["mypkg"])  # 模块对象
print(sys.version)           # 确认解释器版本
高频事故"我明明 pip install 了，运行时却 ModuleNotFoundError"——九成是装到了另一个解释器/环境。用 python -m pip install 并用同一个 python 运行（第 2 章）；再用 print(mypkg.__file__) 确认导入来源。

模块被导入时会执行一遍顶层代码，并缓存到 sys.modules（同一个进程里只执行一次）：

# 只执行一次 → 可以用模块级变量做"单例"
# config.py
print("config 被导入")           # 多次 import 也只打印一次
settings = {"debug": True}

# main.py
import config
import config          # 第二次导入：直接用缓存，不再执行 print
print(config.settings)

19.4 __name__ 与 __main__

每个模块都有一个 __name__：

  • 被导入时：__name__ 等于模块名（如 "utils"）；
  • 直接运行时：__name__ 等于 "__main__"。
# utils.py
def add(a, b):
    return a + b

print("模块名:", __name__)

if __name__ == "__main__":        # 只有"直接运行本文件"时才执行
    print("自检：", add(1, 2))
$ python utils.py
模块名: __main__
自检： 3

$ python -c "import utils"
模块名: utils

这个约定的三个价值：

  1. 让文件既是模块又是脚本：库代码里放自检/演示；
  2. 防止副作用：被导入时不会自动跑测试或打印；
  3. 多进程必需：Windows 上 multiprocessing 会重新导入主模块，没有 __main__ 守卫会导致无限递归启动子进程（第 54 章）。
# 推荐的脚本骨架
'''模块说明：一句话干什么。'''

import logging

logger = logging.getLogger(__name__)      # 用 __name__ 让日志带上模块名


def main():
    logging.basicConfig(level=logging.INFO)
    logger.info("开始执行")
    # ... 业务逻辑


if __name__ == "__main__":
    main()          # 入口逻辑放函数里，便于测试与复用

19.5 循环导入与相对导入

循环导入：症状与四种解法

# a.py
import b                    # ① 执行到这，开始导入 b
def fa(): return b.fb()

# b.py
import a                    # ② b 又导入 a，而 a 还没执行完 → 部分初始化
def fb(): return a.fa()     # ③ 可能报 AttributeError / ImportError
解法做法
① 重构（首选）把双方都要用的代码抽到第三个模块 c.py，让 a、b 都依赖 c
② 延迟导入把 import b 移到函数内部，调用时才导入
③ 改用局部引用不改 import，改成 from b import fb（有时可行，有时只是转移问题）
④ 依赖倒置高层定义接口，低层实现；由入口装配（第 24 章协议与依赖注入）

循环导入往往是设计耦合过重的信号。解法一（抽出公共模块）+ 解法四（依赖倒置）才是治本；延迟导入只是止痛药。

相对导入 vs 绝对导入

# 包内模块（package/services/user.py）里：
from ... import config              # 相对导入：. 当前包，.. 上级包，... 上上级
from ..models import User           # 上级包的 models
from . import helpers               # 当前包里的 helpers

# 绝对导入（推荐，尤其在项目内部）
from myproject.models import User
from myproject.config import settings
常见坑① 相对导入只能用在包内，直接运行一个包内脚本（python package/services/user.py）会报 ImportError: attempted relative import with no known parent package——正确做法是 python -m package.services.user；② 相对导入不能超出顶层包（... 越过项目根目录会报错）。

✓ 第二篇小结

函数与进阶语法篇（第 10-19 章）到此结束。十章的核心可以收束成五条：

主题一句话
函数（10-11）传对象引用：重新绑定外部无感，原地修改外部有感；默认参数用 None 哨兵
作用域与闭包（12）LEGB 查找；闭包携带状态；循环里用 lambda i=i: 冻结
推导式与生成器（13-15）惰性求值省内存；迭代器一次性；for 靠 StopIteration 结束
装饰器（16）@d ≡ f = d(f)，定义时执行；必须加 functools.wraps
异常与模块（18-19）EAFP 风格、不吞异常；__main__ 守卫防副作用

三条工程习惯，请在这一篇结束时固化下来：

  1. 写装饰器必加 @functools.wraps，否则框架（FastAPI / pytest）会读错函数；
  2. 异常只捕获能处理的，处理不了就包装后上抛，日志只记一次；
  3. 脚本入口用 if __name__ == "__main__": main()，既方便测试，也是多进程安全的前提。
