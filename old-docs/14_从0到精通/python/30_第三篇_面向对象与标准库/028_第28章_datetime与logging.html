28.1 date/time/datetime/timedelta

datetime 模块有四个核心类：date（只有日期）、time（只有时间）、datetime（日期+时间）、timedelta（时间差）。

from datetime import date, time, datetime, timedelta

d = date(2026, 10, 23)               # 只有年月日
t = time(14, 30)                      # 只有时分秒
dt = datetime(2026, 10, 23, 14, 30)   # 日期+时间

now = datetime.now()                  # 本地当前时间（naive）
print(now.year, now.month, now.day, now.hour)

# timedelta：时间差，可加减
in_three_days = now + timedelta(days=3, hours=4)
last_week = now - timedelta(weeks=1)

# 两个 datetime 相减 → timedelta
delta = datetime(2026, 12, 31) - datetime(2026, 1, 1)
print(delta.days)                     # 364

# datetime 拆出 date / time
print(now.date(), now.time())
口诀：datetime 加 timedelta 得到 datetime；datetime 减 datetime 得到 timedelta。不要手动算"下个月 5 号"，交给 timedelta 与 relativedelta（dateutil 第三方包）。

28.2 strftime 与 strptime

strftime = datetime → 字符串（格式化输出）；strptime = 字符串 → datetime（按格式解析）。名字里的 f 是 format，p 是 parse。

格式码含义示例输出
%Y四位年2026
%m两位月（01-12）10
%d两位日23
%H24 制小时14
%M分钟30
%S秒05
%f微秒（6 位）123456
%z时区偏移+0800
%a / %A周几（短/全名）Fri / Friday
 
from datetime import datetime

# 输出：datetime → str
dt = datetime(2026, 10, 23, 14, 30, 5)
print(dt.strftime("%Y-%m-%d %H:%M:%S"))   # 2026-10-23 14:30:05
print(dt.strftime("%Y/%m/%d"))              # 2026/10/23

# 解析：str → datetime
parsed = datetime.strptime("2026-10-23", "%Y-%m-%d")
print(parsed)                               # 2026-10-23 00:00:00
坑：%Y 是四位年，%y 是两位年（26 代表 2026）。解析别人给的字符串前，先看清楚它到底是 2026 还是 26，否则年份直接错一个世纪。

28.3 aware/naive、时区与 ISO 8601

不带时区信息的 datetime 叫 naive（朴素），带时区的叫 aware（感知）。后端跨时区场景一律用 aware。

from datetime import datetime, timezone
from zoneinfo import ZoneInfo

# 推荐写法：拿 UTC aware 时间
utc_now = datetime.now(timezone.utc)
# 3.12 起 datetime.utcnow() 已弃用——它返回 naive UTC，容易踩坑

# 转成上海时区（Windows 上若报 ZoneInfoNotFoundError，先 pip install tzdata）
sh = utc_now.astimezone(ZoneInfo("Asia/Shanghai"))
print(sh.strftime("%Y-%m-%d %H:%M %Z"))

# ISO 8601：与前端 Date.toISOString() 对齐的标准格式
print(utc_now.isoformat())                 # 2026-10-23T06:30:05.123456+00:00
back = datetime.fromisoformat("2026-10-23T14:30:05+08:00")

# 时间戳（epoch 秒）：与前端 new Date(ts) / Unix 系统时间对齐
ts = utc_now.timestamp()
from_ts = datetime.fromtimestamp(ts, tz=timezone.utc)
坑别存 naive 本地时间。数据库里存 naive datetime，迁移服务器时区、跨机房部署后全乱套。行业惯例：存 UTC（timestamp 或 ISO 8601 带 offset），展示层再转用户本地时区——和前端 new Date(isoString) 收到 UTC 再按浏览器本地渲染是同一套思路。
版本提示：zoneinfo 从 Python 3.9 起进入标准库；3.11 起 fromisoformat 支持几乎全部 ISO 8601 变体。Windows 上系统不带 tzdata，需要 pip install tzdata。

28.4 logging：级别与 basicConfig

logging 把日志按严重级别分级，可以动态开关——生产环境只收 WARNING 以上，调试时开 DEBUG。

级别数值什么时候用
DEBUG10调试细节，生产关闭
INFO20正常流程记录（请求到达、任务完成）
WARNING30出乎意料但能继续（磁盘快满了）
ERROR40某件事失败了（某个请求处理崩了）
CRITICAL50系统级致命
 
import logging

# 全局配置：在程序入口做一次
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)

logging.debug("不会出现——级别低于 INFO")
logging.info("服务启动")
logging.warning("磁盘剩余不足 10%")
logging.error("处理订单 123 失败")

28.5 Handler 体系与模块级 logger 惯例

logging 的核心模型：Logger 产生记录 → 若干 Handler 决定写到哪 → Formatter 决定长什么样。一个 Logger 可以同时挂多个 Handler。

图 28-1 Logger / Handler / Formatter 的关系

# 模块级惯例：每个文件顶部拿一个自己的 logger
# services/order.py
import logging
logger = logging.getLogger(__name__)     # __name__ = "services.order"

def pay(order_id):
    logger.info("开始支付订单 %s", order_id)
    try:
        ...
    except Exception:
        logger.exception("订单 %s 支付失败", order_id)   # 自动带堆栈

# 文件滚动：超过 10MB 切一个，保留 5 个历史
from logging.handlers import RotatingFileHandler
import logging
h = RotatingFileHandler("app.log", maxBytes=10*1024*1024, backupCount=5, encoding="utf-8")
h.setFormatter(logging.Formatter("%(asctime)s [%(levelname)s] %(name)s: %(message)s"))
root = logging.getLogger()
root.addHandler(h)
对比项printlogging
级别无，全部输出DEBUG~CRITICAL 可动态开关
目的地stdout，难重定向多 Handler：控制台/文件/远程
时间/模块名自己拼字符串Formatter 自动加
异常堆栈要手动 traceback.print_exclogger.exception 自动带
生产环境关掉要改代码改 level 即可
安全红线：日志里绝不打印密码、token、身份证、手机号全文。需要排查时只打尾号或脱敏后的值——日志会被采集、检索、留存半年，等于把敏感信息复制了几百份。
