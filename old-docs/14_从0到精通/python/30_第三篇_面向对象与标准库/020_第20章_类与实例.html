20.1 class 与 __init__：定义一个类

类是对象的蓝图：用 class 声明一个名字，__init__ 是构造时的初始化钩子，实例属性统统挂在 self 上。

下面这个 Dog 类，几乎就是 JS class 的 Python 写法，但请注意两处细节：方法第一个参数显式写 self；属性必须通过 self.xxx 声明。

class Dog:
    # __init__ 在实例被创建后自动调用，相当于构造函数体
    def __init__(self, name: str, age: int):
        self.name = name      # 实例属性：每个实例一份
        self.age = age

    def bark(self) -> str:    # 实例方法：第一个参数永远是 self
        return f"{self.name}: 汪汪！"


d = Dog("阿黄", 3)
print(d.bark())                 # 阿黄: 汪汪！
print(d.name, d.age)            # 阿黄 3

和 JS 对照：JS 用 constructor(name, age) 加 this.name = name；Python 没有独立的 constructor 关键字，__init__ 负责"把刚造好的实例填好"。真正"造实例"的动作由 __new__ 完成（下一章讲），日常几乎用不到。

Python 没有 private 关键字。约定俗成：_name（单下划线）表示"内部使用，别从外部碰"；__name（双下划线）会触发名称改写（name mangling），只是防止子类意外覆盖，并不是真正的访问控制。

20.2 self 的真相：没有 this 魔法

self 不是关键字，也不是编译器藏起来的"当前对象"——它就是实例方法被调用时，解释器自动传进来的第一个位置参数。你甚至可以把它改名。

这是前端转全栈最容易误解的一点。JS 里 this 的取值由调用方式决定（点前面是谁、有没有 bind、箭头函数），是动态绑定的；Python 的 self 则是显式传参，没有绑定悬念：

d = Dog("阿黄", 3)

# 两种写法完全等价：
print(d.bark())                 # 阿黄: 汪汪！
print(Dog.bark(d))              # 阿黄: 汪汪！

点语法 d.bark() 只是语法糖：解释器看到 d 是 Dog 的实例，就去类上找 bark，再把 d 作为第一个参数塞进去。也就是说：

  • self 是谁？就是点前面那个实例，明明白白写在参数列表里；
  • 想访问实例上的数据？必须写 self.name，直接写 name 会被当成局部变量——这是新手最常见的 NameError；
  • 名字叫 self 是全社区约定，换成 this、me 也能跑，但永远不要换，可读性成本极高。

图 20-1 self 是显式传入的第一个参数

记住这句话：d.bark() 等于 Dog.bark(d)。理解了这一行，Python 的面向对象就理解了一半。

20.3 实例属性 vs 类属性

类属性挂在类本身上、所有实例共享；实例属性挂在 self 上、每个实例独有。读属性时沿"实例 → 类"链查找，写属性永远只落在实例上。

这一节直接对应 JS 的"实例自有属性 vs 原型链属性"，但 Python 的查找与写入规则有一个极易踩的坑。

class Dog:
    species = "Canis lupus"      # 类属性：所有实例共享一份

    def __init__(self, name):
        self.name = name        # 实例属性

a = Dog("阿黄")
b = Dog("小白")

print(a.species)               # Canis lupus（实例上没有，顺着找到类）
print(b.species)               # Canis lupus

Dog.species = "Canis familiaris"
print(a.species, b.species)    # 两个都变了 —— 它们共享类属性

a.species = "专属"              # 注意：这不是改类属性！
print(a.species)               # 专属（在 a 身上新建了一个实例属性，遮住了类属性）
print(b.species)               # Canis familiaris（b 不受影响）
常见坑想"给所有实例统一改一个值"，却写成 实例.属性 = 新值——结果只是在这一个实例上新建了同名属性，把类属性遮住（shadow）了。要改共享值，永远改类本身：Dog.species = 新值。这与 JS 里 obj.count++ 会在实例上新建属性、而不是修改 Class.prototype.count 是同一个机制。

更隐蔽的坑：可变类属性被所有实例共享

class Team:
    members = []                # 类属性，且是可变对象！

    def add(self, name):
        self.members.append(name)   # append 不改"绑定"，改的是同一个 list

t1 = Team(); t1.add("甲")
t2 = Team(); t2.add("乙")
print(t1.members)               # ['甲', '乙'] —— t1 看到了 t2 的数据！

正确做法是把可变对象放进 __init__，让它成为每个实例独有的实例属性：self.members = []。下一章的 @dataclass 用 field(default_factory=list) 解决的正是这个坑。

对比项PythonJS 对照
共享数据类属性（写在 class 体里）Class.prototype.x 或 static 字段
实例独有数据__init__ 里 self.x = ...constructor 里 this.x = ...
读取查找顺序先实例 dict，再沿类往上先自有属性，再沿原型链
写入落点永远写进实例 dict永远写进实例自有属性
共享可变对象类属性是 list/dict 时全局共享，极易踩坑原型上的数组被所有实例共享，同理

20.4 三种方法形态：实例方法 / 类方法 / 静态方法

类里能定义三种"函数"：实例方法（拿 self）、@classmethod（拿 cls）、@staticmethod（什么都不拿）。选哪个，取决于这个函数需不需要访问对象。

class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    # ① 实例方法：要操作具体实例
    def show(self):
        return f"{self.year}-{self.month:02d}-{self.day:02d}"

    # ② 类方法：第一个参数是类本身（cls），常用于"备选构造函数"
    @classmethod
    def from_string(cls, s: str):
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)         # 用 cls 而不是硬写 Date，子类化时才正确

    # ③ 静态方法：跟类、实例都没关系，只是逻辑上归这个类管
    @staticmethod
    def is_leap(year: int) -> bool:
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)


d = Date.from_string("2026-10-23")
print(d.show())                  # 2026-10-23
print(Date.is_leap(2026))        # False
形态第一个参数典型用途JS 对应
实例方法self（实例）读写实例属性原型方法 / 普通方法
@classmethodcls（类）备选构造函数、操作类属性static 方法（但 JS static 拿不到动态类）
@staticmethod无逻辑相关的工具函数static 方法 / 普通函数
为什么 from_string 用 cls 而不是 Date？若以后写了子类 USDate(Date)，子类继承 from_string 时 cls 自动是 USDate，造出来的就是子类实例；硬写 Date(...) 会把子类"降级"回父类。这是 classmethod 相对 staticmethod 的核心价值。

不要无脑给所有函数加 @staticmethod。如果一个方法既不用 self 也不用 cls，而且和这个类没有强逻辑归属，那它更应该是一个普通模块级函数——放到类里只是徒增调用层级。

20.5 一切皆对象：内置类型与 isinstance

在 Python 里，整数、函数、类本身都是对象，都能被赋值给变量、传进函数。这是"一切皆对象"的落地含义。

print(isinstance(5, int))               # True
print(isinstance("hi", str))            # True
print(type(5))                          # <class 'int'>

# 类本身也是对象，可以赋值、传递
MyDog = Dog
x = MyDog("小黑")
print(x.name)                           # 小黑

# 函数也是对象
def add(a, b): return a + b
f = add
print(f(2, 3))                           # 5

isinstance 还是 type？

判断一个对象"是不是某类"，有两种写法，差别在是否考虑继承：

class Animal: pass
class Dog(Animal): pass

d = Dog()
print(isinstance(d, Dog))               # True
print(isinstance(d, Animal))             # True —— 考虑继承，狗也是动物
print(type(d) is Animal)                # False —— type 只看"确切是哪个类"
print(type(d) is Dog)                    # True

日常判断类型一律用 isinstance；只有当你需要"严格等于某个类、连子类都不算"时才用 type(x) is 某类。type(x) == 某类 这种写法基本不该出现。

这与 JS 的 instanceof 思路一致（沿原型链判断），而 type(d) is Dog 更像 JS 里检查构造函数是否严格相等。记住：Python 主流是鸭子类型（下一章和第 24 章展开），很多时候你根本不该写 isinstance——能跑就行。

20.6 与 JS/TS 的一页对照

把这一章的心智模型一次性对齐，后续就不会反复"翻译"：

概念PythonJS / TS
当前实例引用self（显式第一个参数）this（动态绑定）
构造初始化__init__constructor
私有性下划线约定 / name mangling#private 硬私有 / TS private
类方法@classmethod 拿 clsstatic（拿不到动态类）
类型判断isinstance（看继承）instanceof / typeof
类型系统运行时鸭子类型 + 可选注解TS 编译时结构化类型

最大的思维转换：JS 的 this 是"调用时猜"，Python 的 self 是"签名里写死"。前者灵活但易错，后者啰嗦但无歧义——这正是两门语言性格差异的缩影。
