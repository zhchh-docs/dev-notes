21.1 继承与 super()

继承让子类复用父类的属性与方法；super() 则是"顺着 MRO 链找下一个类"的开关——它不是简单的"父类指针"。

class Employee:
    def __init__(self, name: str, salary: float):
        self.name = name
        self.salary = salary

    def role(self) -> str:
        return "员工"


class Developer(Employee):
    def __init__(self, name, salary, lang):
        super().__init__(name, salary)   # 先让父类把 name/salary 填好
        self.lang = lang                 # 再补自己的字段

    def role(self) -> str:               # 覆盖（override）父类方法
        return f"{self.name} 是 {self.lang} 开发"


d = Developer("阿明", 30000, "Python")
print(d.role())                        # 阿明 是 Python 开发
print(d.salary)                        # 30000（继承来的属性）
常见坑子类忘记调用 super().__init__(...)，父类那部分属性就没被初始化，运行到一半抛 AttributeError。养成习惯：子类 __init__ 第一行先 super().__init__(...)。注意 Python 3 的 super() 不需要写 super(Developer, self)，解释器自动补全。

JS 里你写 constructor 第一行往往要先 super(...) 才能用 this——Python 也是同样的规矩，只是没有"不 super 就不能用 self"这条硬语法，但漏了照样炸。

21.2 MRO 方法解析顺序

MRO（Method Resolution Order）是一张"从类到祖先类"的查找链表。多继承时，调一个方法到底先命中谁，完全由这张表决定，而不是看括号里写谁先谁后。

Python 用 C3 线性化算法算出 MRO，保证：子类在父类前、按声明顺序、且在菱形继承里公共祖先只出现一次。随时可以查：

class A:
    def hello(self): print("A")

class B(A):
    def hello(self): print("B"); super().hello()

class C(A):
    def hello(self): print("C"); super().hello()

class D(B, C):
    def hello(self): print("D"); super().hello()


D().hello()
# 输出：
# D
# B
# C
# A

print([c.__name__ for c in D.__mro__])
# ['D', 'B', 'C', 'A', 'object']

图 21-1 菱形继承的 C3 线性化顺序

关键认知：super() 在 D 的实例上调用时，它不是"绑定到 B 的父类 A"，而是"在 D 的 MRO 里，B 的下一个是 C"。这就是为什么上面 B 之后会打印 C。理解这一点，多继承才不会变成玄学。

21.3 多继承与 mixin

Python 允许一个类继承多个父类。实践中几乎不用它来做"真·多分类"，而是用 mixin（混入）：把一组可复用的小能力打包成类，按需叠加。

import json

class JsonMixin:
    """能把自身 __dict__ 序列化成 JSON 的混入类。"""
    def to_json(self) -> str:
        return json.dumps(self.__dict__, ensure_ascii=False)


class LoggerMixin:
    def log(self, msg: str):
        print(f"[{self.__class__.__name__}] {msg}")


# 业务类只管自己的数据，能力像搭积木一样 mix 进来
class User(JsonMixin, LoggerMixin):
    def __init__(self, name, age):
        self.name = name
        self.age = age


u = User("阿紫", 20)
u.log("创建成功")                 # [User] 创建成功
print(u.to_json())                # {"name": "阿紫", "age": 20}
mixin 的写法约定：① 它不单独被实例化，也不该是业务的"主父类"；② 它通常不定义 __init__，避免和业务类的初始化打架；③ 命名以 Mixin 结尾。这与 JS/TS 里用组合、接口默认方法提供横切能力是同一思路，只是 Python 用多继承把它做得更轻。

mixin 排在主类后面还是前面？经验法则是"能力类在前、主业务类在后"（如 class User(JsonMixin, LoggerMixin)），让业务类的方法优先于 mixin 的默认实现。真有冲突时，用 cls.__mro__ 查一眼最稳。

21.4 魔法方法分组速览

魔法方法（dunder method，双下划线开头结尾）是 Python 运算符与内置函数的"钩子"：你实现了 __len__，len(obj) 就会自动调它。

按用途分四组记忆，不用背全部，混个脸熟即可：

分组方法触发时机 / 作用
表示与打印__str__ / __repr__print、f-string 调 __str__；调试/repr() 调 __repr__（后者要"能还原对象"）
相等与可哈希__eq__ / __hash__== 走 __eq__；放进 set / 作 dict 键需要 __hash__
容器协议__len__ / __getitem__ / __iter__让对象支持 len()、obj[i]、for x in obj
可调用__call__实例能像函数一样 obj(...) 调用
上下文管理__enter__ / __exit__配合 with 语句（第 25 章详解）
运算符重载__add__ / __sub__ / __lt__ 等让 + - < > 作用于你的类

下面用一个 Vector 类把高频几个串起来：

class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):                       # 调试友好：能看出参数
        return f"Vector({self.x}, {self.y})"

    def __add__(self, other):                 # 支持 v1 + v2
        return Vector(self.x + other.x, self.y + other.y)

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __len__(self):
        return 2                              # 二维向量，长度恒为 2


v = Vector(1, 2)
print(v)                    # Vector(1, 2)（repr 兜底）
print(v + Vector(3, 4))     # Vector(4, 6)
print(v == Vector(1, 2))     # True
print(len(v))               # 2
常见坑只覆盖 __eq__ 而不定义 __hash__，类会自动变成不可哈希（实例不能放进 set、不能当 dict 键）。需要时同时实现两者，或显式 __hash__ = None 表明不可哈希。这是与 JS 完全不同的心智：JS 对象一律按引用比较，没有运算符重载。

21.5 __new__ 与不可变对象

__new__ 才是真正"造实例"的方法，__init__ 只是给现成实例填值。日常你用不到它；它的主战场是不可变类型的子类化。

为什么？像 int、str、tuple 这类不可变对象，值在对象创建那一刻就固定了，__init__ 里再改已经晚了。这时要在 __new__ 阶段就干预：

class Positive(int):
    def __new__(cls, value):
        # int 不可变，必须在造对象时就校验
        if value <= 0:
            raise ValueError("必须为正数")
        return super().__new__(cls, value)


x = Positive(10)
print(x + 5)               # 15（它真的是个 int）
# Positive(-3)            # 抛 ValueError
记住分工：__new__(cls, ...) 负责"创建并返回实例"，是类方法性质；__init__(self, ...) 负责"初始化已有实例"。99% 的业务类只写 __init__；__new__ 还藏着单例、不可变值子类等进阶用法，用到再查。

21.6 与 JS 继承对照

概念PythonJS / TS
继承语法class D(B, C) 多继承class D extends B 单继承
调父类super()（按 MRO 找下一个）super()（只指直接父类）
方法查找顺序C3 线性化，可查 __mro__原型链，单链条
运算符/内置函数魔法方法重载（+、len()）无；只能写普通方法
混入能力多继承 mixin 类组合 / 接口默认方法 / 装饰器

最大区别：JS 是单原型链 + 无运算符重载；Python 是多继承 MRO + 魔法方法。前者逼你用组合，后者允许你用继承——但工程经验同样是：组合优先于继承，mixin 要克制。
