3.1 git init 做了什么

git init 只做一件事：在当前目录创建 .git 子目录——它就是仓库本体，里面装着全部历史、配置、索引。外面的文件叫"工作区"，此时它们还没被 Git 管理。

mkdir -p ~/git-lab/ch03 && cd ~/git-lab/ch03
git init
# hint: Using 'main' as the name for the initial branch...
# Initialized empty Git repository in /home/you/git-lab/ch03/.git/

ls -A
# .git

三件值得记住的细节：

  • 只对当前目录生效，不会递归给子目录建库。想让整个项目受控，就在项目根执行一次；
  • 初始分支名由 init.defaultBranch 决定（第 2 章配过就是 main），否则 Git 会提示默认 master；
  • 可以后悔：删掉 .git 目录，仓库就消失了（工作区文件仍在）——这是"取消 init"的干净做法。
不要在已有仓库的子目录里再 init：嵌套仓库会让外层 Git 把内层当成"未跟踪目录"，后续各种灵异现象。需要多仓库并存请用 submodule（第 28 章）。

3.2 场景演练：第一次提交

完整走一遍：建文件 → 看状态 → 暂存 → 提交 → 再看状态。

# 1. 造一个文件
echo "# 我的第一个 Git 仓库" > README.md

# 2. 看状态：README.md 处于 Untracked（未跟踪）
git status
# On branch main
# No commits yet
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#         README.md
# nothing added to commit but untracked files present

# 3. 暂存
git add README.md

# 4. 再 status：已进入 "Changes to be committed"
git status
# Changes to be committed:
#   new file:   README.md

# 5. 提交
git commit -m "docs: 添加项目说明文件"
# [main (root-commit) a1b2c3d] docs: 添加项目说明文件
#  1 file changed, 1 insertion(+)
#  create mode 100644 README.md

# 6. 提交后再看：工作区干净
git status
# On branch main
# nothing to commit, working tree clean

注意 (root-commit) —— 表示这是根提交，即没有父提交的第一个节点。后续提交会显示 [main 3f2e1d0] 这样的普通提交。

一次提交 = 给项目拍一张"已进库文件"的全景快照，并写下谁、何时、为什么。

3.3 .git 目录解剖

.git/
├── HEAD          # 当前指向的分支（文本文件：ref: refs/heads/main）
├── config        # 本仓库配置（local 层）
├── description   # 仅供 GitWeb 使用，可忽略
├── index         # 暂存区（二进制）：记录已 add 的文件与其 blob 哈希
├── objects/      # 对象数据库：所有 blob / tree / commit / tag
│   ├── 3b/
│   │   └── 18e512d...   # 实际对象（前两位做目录，后 38 位做文件名）
│   ├── info/
│   └── pack/
├── refs/
│   ├── heads/    # 本地分支（每个分支一个文件，内容是提交哈希）
│   └── tags/     # 标签
├── hooks/        # 钩子脚本样例（第 30 章）
└── logs/         # reflog 记录（第 23 章的"后悔药"）
成员作用你该知道的程度
objects/内容寻址数据库，存所有版本内容删了就丢历史，永远别手动改
index暂存区快照git add 就是改它
refs/heads/分支 = 一个存哈希的小文件第 11 章讲"分支即指针"
HEAD指向"当前所在分支"分离 HEAD 状态见第 22 章
config仓库级配置第 2 章的 local 层

3.4 add / commit 到底生成了什么对象

Git 有四种对象：blob（文件内容）、tree（目录结构）、commit（提交）、tag（标签）。用底层命令亲眼看一遍：

# 造一个目录 + 文件并提交
mkdir src && echo 'print("hi")' > src/app.py
git add src/app.py
git commit -m "feat: 添加入口脚本"

# 查看本次提交对象的内容
git cat-file -p HEAD
# tree 8f2a1c9b3e...          <- 指向根目录快照
# parent a1b2c3d4...          <- 父提交（形成历史链）
# author Zhang San  1718000000 +0800
# committer Zhang San  1718000000 +0800
#
# feat: 添加入口脚本

# 看 tree：目录是怎么记的
git cat-file -p HEAD^{tree}
# 100644 blob 9daeafb9...  README.md
# 040000 tree 5c1e2f0a...  src

# 看 blob：文件内容本体
git cat-file -p 9daeafb9
# # 我的第一个 Git 仓库

由此得到一条清晰的链条：commit → tree → blob。提交指向"根目录快照"，目录快照指向"子目录和文件内容"，文件内容按内容哈希去重存储。

为什么 Git 不会重复存储未改动的文件：第二次 commit 里的 README.md 仍指向同一个 blob 对象——内容没变，哈希就没变，对象被复用。这就是"快照却不占空间"的秘密。

3.5 空提交、跳过暂存区与 -a 的陷阱

# 允许空提交：常用于"触发 CI"或"打一个标记点"
git commit --allow-empty -m "chore: 触发流水线重新构建"

# 一步提交所有"已跟踪文件"的改动（注意：不含新文件！）
git commit -am "fix: 修正拼写"

# 新手最爱的错误：以为 -am 能提交新文件
echo "new" > NEW.md
git commit -am "add new file"     # ❌ NEW.md 是 untracked，-a 不带它
# 正确做法：
git add NEW.md && git commit -m "docs: 新增 NEW.md"

坑王：git commit -a 只自动暂存已跟踪文件的修改和删除，永远不管新文件。新文件必须先 git add 一次纳入跟踪。

3.6 仓库的两种来源：init 与 clone

方式命令适用场景
initgit init（空库）→ 之后 git remote add项目从零开始，本地先建库，再关联远程
clonegit clone <url> [目录名]已有远程仓库，直接下载（自动配好 origin、自动检出）
 
# init 路线（本地起项目）
git init
git add . && git commit -m "chore: 初始化项目"
git remote add origin git@github.com:you/demo.git
git push -u origin main

# clone 路线（参与已有项目）
git clone git@github.com:you/demo.git          # 目录名 = demo
git clone git@github.com:you/demo.git mydemo   # 自定义目录名
git clone --depth 1 git@github.com:you/demo.git # 只取最近一次提交（浅克隆，CI 常用）

clone 与 init 的本质差别：clone = init + remote add + fetch + checkout 的组合拳，它自动把远程全部历史拉到本地并签出工作区。

⚠ 常见坑清单

  • 坑 1：在项目子目录执行 init → 嵌套仓库；解决：删掉内层 .git，在根目录重新 init；
  • 坑 2：git add . 把 node_modules、dist、密钥一起加进去 → 第 8 章的 .gitignore 根治；
  • 坑 3：commit 报 nothing to commit → 忘了 add，或改动文件已被 .gitignore 忽略（用 git status --ignored 确认）；
  • 坑 4：提交后发现不该提交的文件 → 用 git rm --cached 摘出（第 7 章），历史里已有的要改写（第三篇）；
  • 坑 5：仓库目录名含中文/空格 → 多数情况可用，但 CI 与部分工具链易出问题，建议英文短名。

✓ 本章小结与习题

要点一句话
init 的本质创建 .git 目录；删掉它等于取消仓库
一次提交的对象链commit → tree → blob，未变文件复用同一 blob
.git 关键成员objects（历史）/ index（暂存）/ refs（分支）/ HEAD（当前）
-a 的边界只管已跟踪文件，新文件必须手动 add
init vs clone从零建库 vs 下载已有库（含远程与检出）
A 基础新建空目录，init 后创建 README.md 并提交；用 git cat-file -p HEAD 观察 commit 的 tree 与 parent 字段。
B 进阶创建两个内容完全相同的文件（不同文件名），提交后查看 tree：它们的 blob 哈希是否相同？这说明了什么？
C 挑战用 git hash-object -w 文件名 手工把一段内容写入对象库，再用 git cat-file 取回，说明"内容寻址"的含义。
