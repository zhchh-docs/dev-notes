9.1 远程是什么：一个别名 + 一个 URL

"远程仓库（remote）"在 Git 里只是存了一对"别名 → URL"映射的配置项，写在 .git/config 中：origin 是 clone 时自动起的默认别名，别无玄机。

git remote -v
# origin  https://github.com/you/demo.git (fetch)
# origin  https://github.com/you/demo.git (push)

# 增 / 改 / 删
git remote add upstream https://github.com/company/demo.git
git remote set-url origin git@github.com:you/demo.git
git remote remove upstream
git remote rename origin github

# 看某个远程的详情（分支映射、HEAD）
git remote show origin

一个仓库可以同时配多个远程——典型场景：自己 fork 的仓库用 origin，上游原仓库用 upstream（第 38 章"多远程与镜像"深入）。

9.2 HTTPS 还是 SSH

协议优点缺点
HTTPS无需配置；企业网络（443 端口）几乎总能连通每次可能要输 token/密码；需配凭据管理器
SSH配一次永久免密；密钥更安全可控需生成并上传公钥；部分公司网络封 22 端口
 
# SSH 密钥生成（一次即可）
ssh-keygen -t ed25519 -C "you@example.com"        # 推荐 ed25519
# 老系统不支持时：ssh-keygen -t rsa -b 4096 -C "you@example.com"

# 复制公钥内容，粘贴到 GitHub → Settings → SSH and GPG keys
cat ~/.ssh/id_ed25519.pub

# 验证连通性
ssh -T git@github.com
# Hi username! You've successfully authenticated...

# 已有 HTTPS 远程，改为 SSH
git remote set-url origin git@github.com:you/demo.git
HTTPS 的 token 时代：GitHub 自 2021 年起不再接受账号密码做 HTTPS 推送，需使用 Personal Access Token（PAT）或凭据管理器。遇到 Authentication failed 多半是密码还在用。
# 凭据管理（避免重复输入）
git config --global credential.helper manager     # Windows / 新版 Git
git config --global credential.helper osxkeychain # macOS
git config --global credential.helper 'cache --timeout=3600'  # Linux

9.3 clone 的完整过程与常用参数

git clone <url> 实际做了四件事：

  1. init：建本地仓库（或建目录再 init）；
  2. remote add origin <url>：配好远程别名；
  3. fetch：把远程全部对象下载到本地对象库（含所有分支的历史）；
  4. checkout：按远程 HEAD 创建本地分支（如 main）并签出工作区。
git clone git@github.com:you/demo.git              # 目录名 = demo
git clone git@github.com:you/demo.git mydemo       # 自定义目录名
git clone -b develop git@github.com:you/demo.git   # 直接签出 develop 分支
git clone --depth 1 git@github.com:you/demo.git    # 浅克隆：只取最近一次提交（CI 常用）
git clone --depth 1 --branch v1.2.0 <url>          # 只要某个 tag 的快照
git clone --recurse-submodules <url>               # 连子模块一起拉（第 28 章）
git clone --filter=blob:none <url>                 # 部分克隆：按需下载文件内容（超大仓库）
浅克隆的代价：--depth 1 只有最新提交，git log 看不到历史、blame 不准、无法回溯。需要完整历史时补：git fetch --unshallow。

9.4 远程追踪分支：origin/main 是什么

这是初学者的关键分水岭。Git 里有两类"看起来像远程分支"的东西：

名称本质能否直接提交
远程分支（服务器上）别人仓库里的指针不能直接操作
远程追踪分支 origin/main你本地的一份"上次通信时远程长什么样"的快照不能（只读快照）
本地分支 main你自己的指针能
 
git branch -a
# * main                      # 本地分支
#   remotes/origin/main       # 远程追踪分支（本地存的一份快照）
#   remotes/origin/develop

git branch -vv
# * main   3f2e1d0 [origin/main] feat: 登录功能
#                    ^追踪关系    ^本地比远程领先的提示会出现在这里

关键认知：origin/main 不会自动更新！它只在你执行 fetch / pull / push 时才刷新。所以"我看到 origin/main 落后了"可能只是你很久没 fetch 的假象。

9.5 fetch / pull / push 的层次关系

图 9-1 fetch 只更新"远程追踪分支"，pull 才动你的工作分支，push 只上传提交

# 推荐习惯：先 fetch 看清再决定
git fetch origin
git log --oneline main..origin/main     # 别人新提交了什么
git diff main origin/main --stat        # 差异概览
git merge origin/main                   # 确认后再合并（或用 rebase）

# 一键版（等于 fetch + merge）
git pull
git pull --rebase        # fetch + rebase（历史更线性，第 14 章）

# 上传
git push origin main
git push -u origin feature/x   # 首次推送并建立追踪关系，之后只需 git push
git push --force-with-lease    # 安全强推（第 18 章）

为什么推荐先 fetch：pull 会自动改你的工作分支与工作区；fetch 永远安全（只下载对象、只更新追踪分支），让你先看清楚再决定怎么合。

9.6 场景演练：从零把本地项目推上远程

# 1. 本地已有项目 → 建库并提交
cd my-project
git init
git add . && git commit -m "chore: 初始化项目"

# 2. 在 GitHub 上新建"空"仓库（不要勾选 README/LICENSE，否则会有历史冲突）

# 3. 关联远程并推送
git remote add origin git@github.com:you/my-project.git
git branch -M main                     # 确保本地分支叫 main
git push -u origin main
# Enumerating objects...  To github.com:you/my-project.git
#  * [new branch]      main -> main
#  branch 'main' set up to track 'origin/main'.

# 4. 之后日常三连
git add . && git commit -m "feat: xxx"
git push

# 5. 换电脑继续：直接 clone
git clone git@github.com:you/my-project.git
常见失败：non-fast-forward：远程已有提交（比如网页上建了 README），本地历史与之分叉。解决：先 git pull --rebase origin main 再 push；不要一上来就 --force（会覆盖他人提交）。

⚠ 常见坑清单

  • 坑 1：permission denied (publickey) → SSH key 没配好或没加进 ssh-agent；用 ssh -T 排查；
  • 坑 2：HTTPS 报密码错误 → 需要用 PAT 而非账号密码；
  • 坑 3：以为 origin/main 是最新的 → 它只在 fetch/pull/push 时更新，先 git fetch；
  • 坑 4：git push 没指定分支报错 → 首次用 -u 建立追踪；或配置 push.default=current；
  • 坑 5：clone 下来只有默认分支 → 其他分支在本地有追踪分支，用 git switch 分支名 即可自动创建本地分支。

✓ 本章小结与习题

要点一句话
remote 本质别名 → URL 的映射，可多个（origin / upstream）
协议选择SSH 免密安全；HTTPS 通用但需 token
clone 四步init + remote add + fetch + checkout
origin/main本地保存的"远程上次的样子"，只在通信时刷新
三个动作fetch 只下载、pull = fetch+合并、push 只上传
A 基础创建一个本地项目，推到 GitHub 新空仓库，用 git remote -v 与 git branch -vv 验证远程与追踪关系。
B 进阶在另一目录 clone 同一仓库，两边各提交一次，练习"先 fetch 看差异，再决定 merge 或 rebase"，记录两种做法下 git log --graph 的形状差异。
C 挑战为仓库添加第二个远程 upstream（随便用一个公开仓库 URL），从它 fetch 后查看 git branch -a，说明"多远程"适合什么协作场景。
