◆本章目标

  • 在任意操作系统完成 Git 安装，并用 git --version 验证；
  • 完成身份配置——不配它，第一次 commit 就会被拒绝；
  • 理解 core.autocrlf 三个取值的含义，选定适合自己系统的值；
  • 知道配置有 system / global / local 三层，出问题时会用 git config --list --show-origin 定位。
本章演练环境：任意终端。Windows 用户推荐 Git Bash 或 PowerShell，macOS/Linux 用户用自带终端。

2.1 安装：三大系统各一条路

系统推荐方式说明
Windows官网下载 git-scm.com/download/win（Git for Windows）自带 Git Bash（推荐日常用）与右键菜单；安装项保持默认即可，换行符一页建议选默认"Checkout Windows-style"（详见 2.4）
macOSxcode-select --install 或 brew install git前者装 Apple 版本；想用新版用 Homebrew
Linuxsudo apt install git（Debian/Ubuntu）或 sudo dnf install git（Fedora）发行版仓库版本略旧，一般够用
Windows 安装坑：如果之前装过 Git，升级时建议直接覆盖安装新版本；多个 Git（如 scoop、官网、IDE 内置）并存时，命令行里生效的是 PATH 靠前的那个。

2.2 验证安装与获取帮助

# 验证：能打印版本号即安装成功
git --version
# git version 2.45.1 (示例)

# 查看任意命令的帮助（离线手册）
git help commit          # 浏览器打开完整手册
git commit -h            # 终端快速摘要（最常用）

# 查看某类命令清单
git help -a              # 全部命令
git help -g              # 概念手册（glossary）

习惯养成：记不住参数时先敲 git 命令 -h，一屏列出全部选项；要深入再 git help。这比搜索引擎更快更准。

2.3 身份配置：user.name 与 user.email

每个提交都会署名，署名来源就是这两个配置。不配置的话，第一次 commit 会直接报错拒绝：

git config --global user.name  "Zhang San"
git config --global user.email "zhangsan@example.com"

# 验证
git config user.name
git config user.email

# 查看全部生效配置及其来源文件
git config --list --show-origin

三点澄清：

  • 它只是署名，不是登录凭据——填什么都合法，但推送到 GitHub 时要和平台账号邮箱一致才会显示头像、计入贡献图；
  • 邮箱请用真实可收件的邮箱：协作工具、CI 通知、代码评审提醒都可能发到这里；
  • 公司机器与个人项目分离：可以在某个仓库里用 local 层覆盖（见 2.6），避免用公司邮箱提交个人开源项目。
常见坑：配置写错后改过来，只影响之后的提交——历史提交的署名不会跟着变。要改历史署名需要历史改写技术（第三篇）。

2.4 换行符之战：autocrlf 与 .gitattributes

Windows 用 CRLF（\r\n）表示换行，macOS/Linux 用 LF（\n）。同一个人在两种系统间切换，git diff 可能显示"整文件都改了"。Git 用 core.autocrlf 处理转换：

取值行为适合谁
true提交时 CRLF→LF，检出时 LF→CRLFWindows 个人开发（Git for Windows 默认推荐）
input提交时 CRLF→LF，检出时不转换macOS / Linux，或希望仓库永远是 LF 的团队
false什么都不转换明确知道自己在干什么的人
 
# Windows 用户推荐
git config --global core.autocrlf true
# macOS / Linux 用户推荐
git config --global core.autocrlf input

但个人配置救不了团队——团队级方案是在仓库根目录放 .gitattributes，它随仓库走、对所有人生效：

# .gitattributes（仓库根目录）
* text=auto eol=lf      # 文本文件统一 LF 入库
*.bat text eol=crlf     # Windows 脚本必须 CRLF
*.png binary            # 二进制不做任何转换

个人 autocrlf 管"我的手"，团队 .gitattributes 管"全队的规矩"——协作仓库两者都要有。

2.5 提升体验的五个配置

# 1. 默认分支名：新仓库 init 时用 main（与 GitHub 默认一致）
git config --global init.defaultBranch main

# 2. 别名：把常用长命令变短
git config --global alias.st status
git config --global alias.lg "log --oneline --graph --decorate --all"
# 之后 git st / git lg 即可

# 3. 全局忽略文件：与项目无关的个人垃圾（如 .DS_Store、编辑器配置）
git config --global core.excludesfile ~/.gitignore_global

# 4. pull 的默认行为：rebase 还是 merge（第二篇详解，先记结论）
git config --global pull.rebase false   # 保持 merge（默认）

# 5. 记住远程凭据（避免每次输密码；Windows 用 manager，Linux 用 cache）
git config --global credential.helper manager   # macOS: osxkeychain

别名建议：只别名"高频且长"的命令（lg、st），别把 commit 改成 c——教程、同事的屏幕、Stack Overflow 里的命令你都对照不上。

2.6 配置的三个层级与优先级

层级flag文件位置典型用途
system--system安装目录（如 C:\Program Files\Git\etc\gitconfig）机器上所有用户，很少改
global--global~/.gitconfig（家目录）个人身份、别名、换行符
local--local（默认）仓库内 .git/config某仓库特殊的身份或远程

优先级：local > global > system——越"近"的越赢。典型场景：公司电脑上全局配公司邮箱，个人开源仓库里局部覆盖：

cd my-opensource-project
git config user.email "me@personal.com"    # 只对本仓库生效

# 排查"到底哪个配置生效了"
git config --list --show-origin | findstr user.email   # Windows
git config --list --show-origin | grep user.email      # macOS/Linux

⚠ 常见坑清单

  • 坑 1：commit 报 Please tell me who you are —— 没配 user.name/email，回 2.3 补上；
  • 坑 2：GitHub 头像不显示、贡献墙空白 —— 提交邮箱与 GitHub 账号绑定邮箱不一致；
  • 坑 3：git diff 满屏 ^M 或整文件飘红 —— 换行符混乱；配置 autocrlf 后需重新检出（下一章末尾给出修复命令）；
  • 坑 4：改了配置没生效 —— 被 local 层覆盖了，用 --show-origin 找真凶；
  • 坑 5：公司邮箱提交了个人项目 —— 在个人仓库设 local 级 user.email，并把该仓库标记为工作边界。

要点一句话

身份配置user.name/email 是提交署名；邮箱要与平台账号一致
换行符个人靠 autocrlf，团队靠 .gitattributes

排查利器git config --list --show-origin
A 基础完成安装与全局身份配置，运行 git config --list --show-origin，截图标注 user.name 与 user.email 各来自哪个文件。
