25.1 Set 的“不重复”契约

Set 的核心是不允许重复元素。判断“重复”靠的是对象的 equals()：当集合中已存在 e.equals(新元素) 为 true 的元素时，添加会被拒绝。所以“把自定义对象放进 Set 必须正确重写 equals 与 hashCode”是铁律。

Set<String> s = new HashSet<>();
s.add("a"); s.add("a");     // 第二次添加无效，size 仍为 1
s.contains("a");            // true
s.size();                   // 1

25.2 HashSet：哈希表实现

HashSet 底层是 HashMap（只用 key）。添加元素时先算 hashCode() 定位桶，再用 equals() 在同一桶内比对。因此无序、增删查近似 O(1)。若两个对象 equals 为 true 但 hashCode 不同，会被放进不同桶，导致“重复元素”漏判——这正是必须同时重写两者原因。

// 正确重写：equals 相同则 hashCode 必相同
class User {
  String id;
  public boolean equals(Object o){...}
  public int hashCode(){ return Objects.hash(id); }
}
常见坑只重写 equals 不重写 hashCode，对象能进 HashSet 却查不出来；用可变字段做 hashCode，修改后元素就“丢失”了。

25.3 TreeSet：红黑树有序集

TreeSet 底层是 TreeMap（红黑树），元素按大小有序，支持范围查询（subSet/headSet）。它要求元素可比较：要么类实现 Comparable，要么构造时传入 Comparator，否则运行时抛 ClassCastException。

// 用 Comparator 按长度排序
Set<String> ts = new TreeSet<>((a,b)->Integer.compare(a.length(), b.length()));
ts.add("apple"); ts.add("hi");  // 按长度而非字典序排列
ts.first(); ts.last();          // 取最小/最大
ts.subSet("b", "m");            // 范围视图

25.4 LinkedHashSet 与选型

实现特征适用
HashSet无序、O(1)默认去重，绝大多数场景
TreeSet有序、O(log n)需要排序/范围查询
LinkedHashSet保插入顺序去重且要保持先后顺序
去重默认 HashSet；要排序用 TreeSet；既要去重又要保序用 LinkedHashSet。
