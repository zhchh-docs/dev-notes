23.1 Collection 与 Map：顶层分野

Java 集合框架（Java Collections Framework，JCF）的入口只有一个分岔口：一条路是 Collection，一条路是 Map。看懂这个分岔，后面所有类都有归属。

从 Java 2（JDK 1.2）起，集合框架把散落各处的 Vector、Hashtable、数组、自建链表统一收编，用一套接口 + 实现来组织。它的顶层就这么两个：

  • Collection：一组单个元素的容器，add 一个放一个，遍历时拿出的是元素本身；
  • Map：一组键值对（key-value）的容器，put 一对存一对，按 key 取值。
一句话区分：Collection 装"东西"，Map 装"目录"——前者回答"里面有什么"，后者回答"某个名字对应什么"。

用代码感受一下两种"放数据"的姿势：

import java.util.*;

public class TopSplit {
    public static void main(String[] args) {
        // Collection 一族：存单个元素
        List<String> names = new ArrayList<>();
        names.add("李白");
        names.add("杜甫");          // 一次放一个

        // Map 一族：存键值对
        Map<String, Integer> age = new HashMap<>();
        age.put("李白", 61);
        age.put("杜甫", 58);        // 一次放一对
        System.out.println(age.get("李白"));  // 61，按 key 取 value
    }
}

注意一个让初学者困惑的点：Map 并不继承 Collection。它们是平级的两条血脉，都间接服务于"管理多个对象"这一总目标，但在接口设计上彼此独立。如果你想遍历 Map 的"值集合"，要用 map.values()、map.keySet() 或 map.entrySet() 这些视图方法，把键值对转成 Collection 视角再看。

维度CollectionMap
存储单元单个元素 E键值对 K-V
核心增删add(E) / remove(E)put(K,V) / remove(K)
取数据遍历 / 索引（仅 List）get(K)
是否含 key 概念无有，key 唯一

23.2 Collection 三支：List / Set / Queue

Collection 之下分出三根主枝，每一支都是一个接口，背后规定了一种"数据摆放的语义契约"：

List —— 有序、可重复、可索引

  • 有序：插入顺序被保留，按索引（0 开始）访问，get(3) 永远拿到第 4 个；
  • 可重复：同一个元素可以出现多次，[a, a, b] 合法；
  • 典型实现：ArrayList（动态数组）、LinkedList（双向链表）、Vector（线程安全但老旧）。

Set —— 无序（多数）、不可重复

  • 不可重复：靠 equals + hashCode 判断"是不是同一个"，想加第二个相同的会被拒绝；
  • 是否有序取决于具体实现：HashSet 不保序，LinkedHashSet 保插入序，TreeSet 按排序序；
  • 典型用途：去重、成员判定（"在不在集合里"）。

Queue —— 排队、按规则出队

  • 语义是队列：先进先出（FIFO）是最常见形态，但也有双端队列 Deque、优先队列 PriorityQueue；
  • 提供 offer、poll、peek 等"入队/出队/看队头"方法，比直接用 List 的 remove(0) 语义更清晰；
  • 典型实现：LinkedList（同时是 List 和 Deque）、ArrayDeque、PriorityQueue。
选哪一支，先看"数据本身想怎么被对待"：要顺序+可重复 → List；要唯一 → Set；要排队处理 → Queue。
List<Integer> list = new ArrayList<>(List.of(3, 1, 3));   // [3,1,3] 允许重复
Set<Integer> set  = new HashSet<>(List.of(3, 1, 3));     // [1,3]   重复被吞掉
Queue<Integer> q  = new LinkedList<>();
q.offer(10); q.offer(20);
System.out.println(q.poll());   // 10（先来的先走）
System.out.println(q.peek());   // 20（看队头但不移除）

23.3 接口与实现分离的设计哲学

这是集合框架最值得反复品味的一点：你要的是"能装东西的容器"，而不是"某个具体结构"。框架因此把"能做什么"（接口）和"怎么做"（实现）彻底拆开。

以 List 为例，它只是一个接口，规定了"有序、可重复、可索引"这一组行为；而 ArrayList 和 LinkedList 是两种完全不同的实现——一个底层是动态扩容的数组，一个底层是双向链表。它们都能满足 List 的契约，但性能特征天差地别：

操作ArrayList（数组）LinkedList（链表）
按索引随机访问 get(i)O(1) 极快O(n) 要逐个走
尾部增删均摊 O(1)O(1)
中间插入/删除O(n) 要搬移O(n) 找位置 O(n)

接口与实现分离带来了两个直接好处：

  • 算法与结构解耦：排序、查找、遍历这些算法只认 List 接口，不关心底下是数组还是链表——换实现不影响上层逻辑；
  • 可替换、可扩展：今天用 ArrayList，明天发现中间插入太多改 LinkedList，只要声明类型是接口，调用处一行都不用改（前提是不依赖具体实现的特有方法）。
常见坑别在需要随机访问高频的场景选 LinkedList，它的"插入快"只在已知节点时成立；按索引插入其实更慢，因为先要 O(n) 走到那个位置。这是面试里最容易翻车的"想当然"。

23.4 为什么面向接口编程

"面向接口编程"不是口号，而是集合框架逼你养成的最实惠习惯。变量、参数、返回值都声明成接口类型，而不是具体类。

// 推荐：左边是接口，右边是具体实现，二者可自由组合
List<String> list = new ArrayList<>();      // 今天用数组实现
// 某天改成：List<String> list = new LinkedList<>();  // 调用处零改动

// 方法参数也用接口，最灵活：谁都能传进来
static void printAll(List<String> data) {    // 收 ArrayList 也收 LinkedList
    for (String s : data) System.out.println(s);
}

// 不推荐：把实现类写死在签名里
static void printAll(ArrayList<String> data) {  // 只能收 ArrayList，丧失通用性
}

面向接口编程的回报：

  • 松耦合：调用方只依赖契约，不依赖细节，实现类可独立演化；
  • 易测试：传入一个 mock 实现就能测逻辑，不必真的搬一个 ArrayList；
  • 易替换：性能瓶颈时只换 new 右边的实现，接口两侧不动；
  • 对接框架：Spring、JDK 工具类（Collections.sort、Arrays.asList）统统接收接口类型，写死实现类反而处处碰壁。
记住这条铁律：写类型时，能写 List 就不写 ArrayList，能写 Map 就不写 HashMap——把"用哪种实现"的决定，尽量推迟到 new 的那一刻。

当然也有例外：当你确实需要某个实现独有的能力（比如 LinkedList 的 getFirst/addFirst，或 HashMap 的 computeIfAbsent 实际在 Map 接口上也有），再退而声明具体类型，但那是少数。

23.5 各实现类一句话定位

把常用实现类在"地图"上的位置记牢，后面每章都是逐个展开。这里先给一句话定位，建立第一印象：

实现类一句话定位
ArrayList默认 List，动态数组，查得快、改中间慢，绝大多数场景的首选
LinkedList双向链表，首尾操作强，随机访问弱，同时是 Queue/Deque 实现
Vector / Stack老牌线程安全 List，方法全 synchronized，新版代码基本别用
HashSet默认 Set，靠 hashCode 去重，不保序、最快
LinkedHashSetHashSet 加链表，去重且保插入顺序
TreeSet红黑树实现，自动按元素排序，要求元素可比较
HashMap默认 Map，数组+链表+红黑树，键值对查询的万能解
LinkedHashMapHashMap 加链表，保插入/访问顺序，可做 LRU 缓存
TreeMap按 key 排序的 Map，适合需要"范围查询/有序遍历"的字典
PriorityQueue优先队列，出队顺序由优先级决定而非入队顺序
ArrayDeque用数组实现的双端队列，栈和队列的高效替代

到这里，集合框架的全景图就立起来了：顶层两条线（Collection / Map）→ Collection 三分支（List / Set / Queue）→ 每分支若干实现。下一章我们钻进最常用的 List，把 ArrayList 与 LinkedList 的扩容、定位与误区别个底朝天。
