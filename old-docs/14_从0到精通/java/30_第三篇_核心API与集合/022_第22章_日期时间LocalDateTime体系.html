22.1 老 API 的坑

旧的 java.util.Date 和 Calendar 设计糟糕：月份从 0 开始、年份从 1900 起算、可变且线程不安全、时区藏得深。Java 8 引入 java.time（JSR-310）彻底重写。

新 API 三原则：不可变（线程安全）、清晰分离（日期/时间/带时区）、人类可读的月份 1-12。

22.2 LocalDate / LocalTime / LocalDateTime

LocalDate d = LocalDate.now();          // 2026-10-20
LocalTime t = LocalTime.now();          // 14:30:05
LocalDateTime dt = LocalDateTime.now(); // 2026-10-20T14:30:05
LocalDate bd = LocalDate.of(2000, 1, 1);// 2000-01-01（月份是 1！）
dt.plusDays(1).plusHours(3);            // 不可变：返回新对象
dt.getYear(); dt.getMonthValue();        // 2026 / 10

所有"加减"方法都返回新对象，原对象不变——这是它线程安全的关键。

22.3 格式化与解析

DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm");
String s = dt.format(f);                       // 日期 → 字符串
LocalDateTime p = LocalDateTime.parse("2026-10-20 14:30", f); // 字符串 → 日期
常见坑老代码里 SimpleDateFormat 是线程不安全的，多线程共享会出乱码；新项目一律用 DateTimeFormatter（不可变、可共享）。

22.4 时区与 Duration/Period

ZonedDateTime z = ZonedDateTime.now(ZoneId.of("Asia/Shanghai"));
Duration dur = Duration.between(t1, t2);   // 精确到 纳秒/秒 的时间量
Period p = Period.between(d1, d2);          // 年/月/日 的日历量
dur.toHours(); p.getMonths();
  • Duration：基于时间量（小时、分钟、秒），用于"两个时刻差"；
  • Period：基于日历量（年、月、日），用于"生日到今天"这种；
  • 跨时区业务用 ZonedDateTime / OffsetDateTime，别用裸 LocalDateTime 存绝对时刻。

✓ 本章小结

要点一句话
老 APIDate/Calendar 可变、月份0起、线程不安全，已弃用

时区/量ZonedDateTime 管时区；Duration 管时刻差，Period 管日历差
