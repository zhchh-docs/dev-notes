28.1 没有泛型的痛

在泛型出现前，集合只能存 Object，取出来必须强制转型，一旦存错类型，运行时才抛 ClassCastException，bug 很难定位。泛型把类型检查提前到编译期。

// 旧写法：取元素必须强转，类型不安全
List list = new ArrayList();
list.add("s"); list.add(123);
String s = (String) list.get(1); // 运行时才崩

// 泛型：编译期就拦住
List<String> list2 = new ArrayList<>();
list2.add(123); // 编译错误，类型不对

28.2 泛型类、方法与接口

用尖括号声明类型参数 <T>，T 在使用处被具体类型替换。泛型方法把类型参数写在返回值前，泛型接口（如 Comparable<T>）让实现类绑定类型。

class Box<T> {
  private T value;
  public void set(T v){ this.value = v; }
  public T get(){ return value; }
}
Box<String> b = new Box<>();
b.set("hi"); String v = b.get(); // 无需强转

static <T> T first(List<T> list){ return list.get(0); } // 泛型方法

28.3 泛型擦除与限制

Java 泛型是编译期语法糖，运行期类型参数被擦除为 Object（或上界）。因此有一些限制：不能 new T[]、不能 instanceof T、不能创建泛型数组。

// T.class 不存在；instanceof 不可用
// List<Integer> 与 List<String> 运行期是同一个类（类型擦除）
// 故方法重载 List<Integer> 与 List<String> 会冲突
常见坑List<Integer> a 和 List<String> b 用 == 或 instanceof 无法区分，因运行期都被擦成 List。

28.4 通配符与 PECS 直觉

泛型不可协变：List<String> 不是 List<Object> 的子类。通配符解决“只读/只写”场景：? extends T（上界，生产者，能取不能存）与 ? super T（下界，消费者，能存不能取）。口诀 PECS：Producer Extends, Consumer Super。

// 生产者：从集合中读取 T，用 extends
void copy(List<? extends Number> src, List<? super Number> dst){
  for (Number n : src) dst.add(n); // src 取，dst 存
}
上界“只能往外拿”，下界“只能往里放”——这是泛型容器协作的安全边界。
