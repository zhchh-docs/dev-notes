82.1 引入 starter-aop 与第一个切面

一句话定位：Spring Boot 项目中加入 AOP 只需一个 starter；容器检测到 @Aspect Bean 后自动为匹配的目标 Bean 生成代理。

<!-- pom.xml：AOP starter 自动引入 spring-aop 与 aspectjweaver -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
import org.aspectj.lang.annotation.Aspect;
import org.springframework.stereotype.Component;

@Aspect                 // 声明这是一个切面类（不是普通组件，需要被 AOP 框架识别）
@Component              // 同时注册为 Spring Bean：@Aspect 本身不具备组件扫描语义
public class ServiceLogAspect {
    // 切点、通知方法在后续小节逐个展开
}
常见坑：只写 @Aspect 而漏写 @Component，切面类不会被扫描注册，所有通知静默不执行；反过来，只写 @Component 漏写 @Aspect，它只是一个普通 Bean，不参与代理织入。两个注解缺一不可。

82.2 五种通知类型与 JoinPoint

一句话定位：通知决定"在方法的哪个时机执行什么逻辑"；五种通知覆盖前置、后置、正常返回、异常抛出与环绕全部时机。

注解执行时机典型用途 / 可获得信息
@Before目标方法执行前入参日志、权限校验、参数预处理；JoinPoint 可取方法签名与参数
@After方法退出时（finally 语义，无论正常或异常）资源清理、连接归还；拿不到返回值与异常类型
@AfterReturning方法正常返回后返回值日志、结果改写；通过 returning 属性绑定返回值
@AfterThrowing方法抛出异常后异常上报、错误指标；通过 throwing 属性绑定异常对象
@Around包裹整个方法调用（前后都能控制）耗时统计、事务、重试、缓存；必须调用 ProceedingJoinPoint.proceed() 放行
 
import org.aspectj.lang.JoinPoint;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.*;

@Aspect
@Component
public class NotifyDemoAspect {

    // JoinPoint 是连接点的描述对象：方法签名、参数、目标对象都从这里取
    @Before("execution(* com.demo.service..*.*(..))")
    public void beforeLog(JoinPoint jp) {
        System.out.println("[Before] 进入 " + jp.getSignature().toShortString()
                + " 参数=" + java.util.Arrays.toString(jp.getArgs()));
    }

    @AfterReturning(pointcut = "execution(* com.demo.service..*.*(..))",
                    returning = "result")   // 返回值绑定到方法形参 result
    public void afterReturn(JoinPoint jp, Object result) {
        System.out.println("[AfterReturning] 正常返回 " + jp.getSignature().getName()
                + " 结果=" + result);
    }

    @AfterThrowing(pointcut = "execution(* com.demo.service..*.*(..))",
                   throwing = "ex")
    public void afterThrow(JoinPoint jp, Exception ex) {
        System.out.println("[AfterThrowing] 抛出异常 " + ex.getClass().getSimpleName());
    }

    @After("execution(* com.demo.service..*.*(..))")
    public void afterFinally(JoinPoint jp) {
        System.out.println("[After] finally 退出 " + jp.getSignature().getName());
    }

    // 环绕通知：必须手动 proceed() 放行目标方法，否则目标根本不执行
    @Around("execution(* com.demo.service..*.*(..))")
    public Object around(ProceedingJoinPoint pjp) throws Throwable {
        System.out.println("[Around] 前");
        Object result = pjp.proceed();              // 放行到目标方法
        System.out.println("[Around] 后");
        return result;                             // 必须把返回值交还给调用方
    }
}

82.3 切点表达式三剑客

一句话定位：切点表达式决定"通知贴在哪些方法上"；execution 按方法签名圈定，within 按类型圈定，@annotation 按自定义注解圈定。

// ① execution：最常用，描述方法签名
// execution( 修饰符  返回值  包.类.方法(参数)  抛出异常 )
// 匹配 com.demo.service 包及其子包下所有类的所有 public 方法
@Before("execution(public * com.demo.service..*.*(..))")
public void onService(JoinPoint jp) { /* ... */ }
// 星号含义：* 匹配任意返回值/任意一层包；.. 匹配任意多层包；(..) 匹配任意参数列表

// ② within：按类型圈定，比 execution 粗，只管"这个类的方法"
@Before("within(com.demo.service..*)")
public void onServiceClass(JoinPoint jp) { /* ... */ }

// ③ @annotation：被指定注解标注的方法才命中（适合做"标记式"扩展点）
@Before("@annotation(com.demo.annotation.AuditLog)")
public void onAudit(JoinPoint jp) { /* ... */ }

// 组合：&& 与、|| 或、! 非
@Around("within(com.demo.service..*) && !@annotation(com.demo.annotation.SkipLog)")
public Object logged(ProceedingJoinPoint pjp) throws Throwable { /* ... */ }

// 抽取可复用切点：@Pointcut 定义一次，多处引用
@Pointcut("execution(* com.demo.service..*.*(..))")
public void serviceLayer() {}

@Before("serviceLayer()")
public void beforeService(JoinPoint jp) { /* ... */ }

@AfterReturning("serviceLayer()")
public void afterService(JoinPoint jp) { /* ... */ }
表达式圈定对象常见场景
execution方法级：返回值、包、类名、方法名、参数均可限定按包/层/方法名批量织入，最灵活
within类型级：类所在包即命中其所有方法整层 Service 统一日志，写法更短
@annotation标注了指定注解的方法按需开启：@AuditLog、@RateLimit 等显式标记
@within / @target标注了指定注解的类的所有方法整类启用功能，避免逐方法标注

82.4 日志切面实战

一句话定位：一个生产可用的日志切面至少做到：记录类名方法名、参数、异常，且参数要做长度裁剪，避免日志爆炸。

import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.*;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;

@Aspect
@Component
public class AccessLogAspect {

    private static final Logger log = LoggerFactory.getLogger(AccessLogAspect.class);
    private static final int ARG_LIMIT = 500;   // 单个参数日志截断长度

    // 复用切点：service 包下所有方法
    @Pointcut("execution(* com.demo.service..*.*(..))")
    public void serviceMethods() {}

    @Around("serviceMethods()")
    public Object aroundService(ProceedingJoinPoint pjp) throws Throwable {
        String signature = pjp.getSignature().toShortString();
        Object[] args = pjp.getArgs();
        if (log.isDebugEnabled()) {
            log.debug("调用 {}，参数={}", signature, truncate(java.util.Arrays.toString(args)));
        }
        try {
            Object result = pjp.proceed();
            if (log.isDebugEnabled()) {
                log.debug("返回 {}，结果={}", signature, truncate(String.valueOf(result)));
            }
            return result;
        } catch (Throwable ex) {
            log.error("异常 {}，原因={}", signature, ex.getMessage());
            throw ex;                               // 异常必须原样抛出，不能吞掉
        }
    }

    private String truncate(String s) {
        if (s == null) return "null";
        return s.length() > ARG_LIMIT ? s.substring(0, ARG_LIMIT) + "…(已截断)" : s;
    }
}
// 业务类保持纯净：不写一行日志代码，切面自动包裹
@Service
public class OrderService {
    public Order createOrder(OrderRequest req) {
        // 此处只有业务；入参、返回、异常由 AccessLogAspect 统一记录
        return orderRepository.save(req.toOrder());
    }
}
常见坑：环绕通知里 proceed() 抛异常后若 catch 住不再抛出，目标方法对调用方就表现为"没报错"——吞异常是 AOP 事故高发点。日志切面只记录、不转换、不吞异常。

82.5 耗时统计切面与 @Order 顺序

一句话定位：耗时统计是最典型的 @Around 场景；当多个切面命中同一个方法时，@Order 决定它们的包裹层数——数字越小越外层。

import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

@Order(10)                                    // 数字小 = 外层切面，先进入后退出
@Aspect
@Component
public class MetricsAspect {

    @Around("execution(* com.demo.service..*.*(..))")
    public Object measure(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.nanoTime();
        String name = pjp.getSignature().toShortString();
        try {
            return pjp.proceed();
        } finally {
            long cost = (System.nanoTime() - start) / 1_000_000;
            Metrics.record(name, cost);       // 上报指标（计数器/直方图）
            if (cost > 300) {                 // 慢方法阈值告警
                Metrics.alertSlow(name, cost);
            }
        }
    }
}

@Order(20)                                    // 日志切面在统计切面内层
@Aspect
@Component
public class AccessLogAspect { /* 82.4 内容 */ }

两个切面同时命中 OrderService.createOrder 时，调用栈顺序为：MetricsAspect 进入 → AccessLogAspect 进入 → 目标方法 → AccessLogAspect 退出 → MetricsAspect 退出。@Order 值相同或都未声明时，切面顺序由 Spring 解析结果决定，不稳定——多切面场景务必显式标注顺序。

金句：事务切面（下一章）天然应该是最外层切面——先开事务，再进入日志与业务；Spring 事务切面默认 Ordered.LOWEST_PRECEDENCE 附近，自定义切面记得用更小的 @Order 值把自己放到外层或内层，避免统计到事务提交等待时间。

82.6 切面不生效排查手册

一句话定位：AOP 失效九成原因是"调用没走代理"，其余是切点写错、Bean 没注册、方法不可代理四类。按下面清单逐项排查。

82.6.1 自调用失效：this 引用绕过代理

@Service
public class OrderService {

    public void batchCreate(List<OrderRequest> list) {
        for (OrderRequest req : list) {
            this.createOrder(req);          // ❌ this 是目标对象，不是代理！
        }                                   // 切面不会触发
    }

    // 正确做法一：注入自身代理（注意 @Lazy 防止构造期循环依赖）
    private final OrderService self;
    public OrderService(@Lazy OrderService self) { this.self = self; }

    public void batchCreateFixed(List<OrderRequest> list) {
        for (OrderRequest req : list) {
            self.createOrder(req);          // ✅ 走代理对象，切面生效
        }
    }

    // 正确做法二：把需要被切的方法拆到另一个 Bean，注入后调用
    // 正确做法三：AopContext.currentProxy() 取代理（需 exposeProxy=true）
}

82.6.2 其他常见失效现场

现场原因排查动作
方法是 private / final / static代理无法覆写或拦截该方法提升为 public 非 final；静态方法改实例方法
new 出来的对象直接调用该对象不是 Spring 容器管理的代理 Bean通过容器注入 Bean；确认类带 @Service 等注解
切点表达式不匹配包名、方法名、返回值写错；子包用 . 而不是 ..临时加 @Before 打印 jp.getSignature()，逐步放宽表达式验证
切面类漏写 @Component切面未注册进容器，通知无人织入补 @Component；确认扫描包覆盖切面所在包
同类内部方法互相调用同 82.6.1，this 直连目标对象拆类、自注入代理或 AopContext.currentProxy()
注意：Spring AOP 拦截的是代理对象上的外部方法调用。理解这一条，就能理解事务、缓存、权限等所有基于 AOP 的机制为何在自调用场景下同样失效——第 83 章会再次遇到它。

✓ 本章小结

要点一句话
切面注册@Aspect 声明切面 + @Component 注册 Bean，两者缺一不可
五种通知Before 前置、After finally、AfterReturning 正常返回、AfterThrowing 异常、Around 环绕控制全程
切点三剑客execution 方法级、within 类型级、@annotation 注解级；@Pointcut 抽取复用
实战要点日志只记录不吞异常；耗时用 Around + finally；@Order 小值在外层
失效根因this 自调用绕过代理；private/final/static、非容器 Bean、表达式不匹配其次排查
