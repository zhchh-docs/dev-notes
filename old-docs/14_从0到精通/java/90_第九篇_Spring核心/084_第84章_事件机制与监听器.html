第 84 章 事件机制与监听器

教科书 第 84 章 / 共 112 章 · 预计 40 分钟 · 第九篇：切面与事务实战

下单成功后要发短信、发站内信、更新积分、推送报表——主流程不该直接认识这些后续动作。Spring 事件机制用观察者模式把"发生了什么"与"谁来响应"解耦：发布者只发事件，监听器各自订阅。本章讲透 ApplicationEvent、@EventListener、事务绑定时机与异步监听，并排查监听器异常牵连主流程等高频问题。

84.1 观察者模式回顾

一句话定位：观察者模式定义对象间的一对多依赖——主题状态变化时自动通知所有观察者；Spring 事件机制是它在容器中的标准化落地。

// 没有事件机制时：主流程直接认识每个后续动作，依赖硬编码、越写越胖
@Service
public class OrderService {
    private final SmsSender sms;
    private final MailSender mail;
    private final PointService points;
    private final ReportService report;
    // 构造器注入四个下游；新增通知渠道就要改这里（违反开闭原则）

    public void createOrder(Order order) {
        orderDao.save(order);
        sms.send(order.getPhone(), "下单成功");      // 主流程被下游逻辑打断
        mail.send(order.getEmail(), "订单回执");
        points.add(order.getUserId(), order.getAmount());
        report.record(order);
    }
}

// 引入事件后：主流程只发布"订单已创建"事件，后续动作由各自监听器响应
@Service
public class OrderService {
    private final ApplicationEventPublisher publisher;
    public OrderService(ApplicationEventPublisher publisher) {
        this.publisher = publisher;
    }
    public void createOrder(Order order) {
        orderDao.save(order);
        publisher.publishEvent(new OrderCreatedEvent(order.getId()));
        // 不认识 SmsSender、MailSender、PointService —— 依赖方向反转
    }
}
金句：事件机制不是为了"异步"，而是为了解耦：主流程只关心业务事实，下游要做什么由下游自己订阅。异步只是可选增强（84.5）。

84.2 ApplicationEvent 与 ApplicationListener

一句话定位：事件对象继承 ApplicationEvent 携带业务数据；发布器把事件交给容器广播；监听器实现 ApplicationListener<T> 接收对应类型。

import org.springframework.context.ApplicationEvent;

// ① 自定义事件：封装需要传递的业务数据
public class OrderCreatedEvent extends ApplicationEvent {

    private final Long orderId;
    private final Long userId;
    private final java.math.BigDecimal amount;

    public OrderCreatedEvent(Object source, Long orderId, Long userId,
                             java.math.BigDecimal amount) {
        super(source);                  // source：事件最初发生的对象（发布者）
        this.orderId = orderId;
        this.userId = userId;
        this.amount = amount;
    }

    public Long getOrderId() { return orderId; }
    public Long getUserId() { return userId; }
    public java.math.BigDecimal getAmount() { return amount; }
}

// ② 发布事件：注入 ApplicationEventPublisher（容器自动提供）
import org.springframework.context.ApplicationEventPublisher;
import org.springframework.stereotype.Service;

@Service
public class OrderService {
    private final ApplicationEventPublisher publisher;
    public OrderService(ApplicationEventPublisher publisher) {
        this.publisher = publisher;
    }

    public void createOrder(Order order) {
        orderDao.save(order);
        publisher.publishEvent(new OrderCreatedEvent(
                this, order.getId(), order.getUserId(), order.getAmount()));
    }
}

// ③ 传统接口式监听器：实现 ApplicationListener 泛型指定事件类型
import org.springframework.context.ApplicationListener;
import org.springframework.stereotype.Component;

@Component
public class OrderCreatedSmsListener
        implements ApplicationListener<OrderCreatedEvent> {

    private final SmsSender smsSender;
    public OrderCreatedSmsListener(SmsSender smsSender) {
        this.smsSender = smsSender;
    }

    @Override
    public void onApplicationEvent(OrderCreatedEvent event) {
        smsSender.send(event.getUserId(), "订单 " + event.getOrderId() + " 创建成功");
    }
}

84.3 @EventListener 注解式监听

一句话定位：不必实现接口，任意 Bean 的方法加上 @EventListener，参数类型即订阅事件类型；可在一个方法上监听多个事件，也可返回另一个事件形成链式发布。

import org.springframework.context.event.EventListener;
import org.springframework.stereotype.Component;

@Component
public class OrderNotifyListeners {

    private final MailSender mailSender;
    private final PointService pointService;

    public OrderNotifyListeners(MailSender mailSender, PointService pointService) {
        this.mailSender = mailSender;
        this.pointService = pointService;
    }

    // 方法参数 = 订阅的事件类型；方法名自由
    @EventListener
    public void onOrderCreated(OrderCreatedEvent event) {
        mailSender.send(event.getUserId(), "订单回执：" + event.getOrderId());
    }

    @EventListener
    public void addPoints(OrderCreatedEvent event) {
        pointService.earn(event.getUserId(), event.getAmount());
    }

    // 链式发布：方法返回值会作为新事件再次发布（事件驱动的流程编排）
    @EventListener
    public PointGrantedEvent onPointsEarned(OrderCreatedEvent event) {
        return new PointGrantedEvent(this, event.getUserId(),
                pointService.current(event.getUserId()));
    }
}
方式ApplicationListener 接口@EventListener 注解
声明形式implements ApplicationListener<T>，重写 onApplicationEvent任意方法加注解，参数类型即事件类型
多事件监听一个实现类只能绑一个泛型事件@EventListener 可标注多个方法，组合灵活
事件链需在监听器内手动 publishEvent方法返回值自动作为新事件发布
适用场景框架级组件、需要强类型约束的通用监听业务代码主流写法，简洁直观

84.4 @TransactionalEventListener 事务时机

一句话定位：普通 @EventListener 在事件发布的当下同步执行；@TransactionalEventListener 把监听器绑定到事务的特定阶段执行——最常用的 AFTER_COMMIT 保证"数据库落库成功后再发通知"。

import org.springframework.transaction.event.TransactionPhase;
import org.springframework.transaction.event.TransactionalEventListener;
import org.springframework.stereotype.Component;

@Component
public class OrderNotifyListeners {

    // 默认 phase = AFTER_COMMIT：事务提交成功后才执行；无事务时直接执行
    @TransactionalEventListener
    public void afterCommit(OrderCreatedEvent event) {
        // 订单已确认落库，此刻发短信不会发出"幽灵订单"通知
        smsSender.send(event.getUserId(), "下单成功");
    }

    // 显式指定事务阶段
    @TransactionalEventListener(phase = TransactionPhase.AFTER_ROLLBACK)
    public void afterRollback(OrderCreatedEvent event) {
        // 事务回滚后执行：记录失败告警、补偿检查
        alertService.notify("订单创建失败：" + event.getOrderId());
    }

    @TransactionalEventListener(phase = TransactionPhase.BEFORE_COMMIT)
    public void beforeCommit(OrderCreatedEvent event) {
        // 事务提交前执行：可参与同一事务，异常会导致回滚；慎用
    }

    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMPLETION)
    public void afterCompletion(OrderCreatedEvent event) {
        // 事务结束（提交或回滚都触发）：清理类、日志类动作
    }
}
事务阶段触发时机典型用途
BEFORE_COMMIT事务提交之前，仍在事务内提交前补充数据校验；异常会回滚主事务
AFTER_COMMIT（默认）事务提交成功之后发短信、邮件、推送、外部回调——主流程已确认成功
AFTER_ROLLBACK事务回滚之后失败告警、补偿任务登记、人工介入提醒
AFTER_COMPLETION事务结束（提交或回滚）之后不区分结果的收尾动作：埋点、日志、资源清理
注意：@TransactionalEventListener 依赖当前存在事务上下文；发布事件的方法若没有事务，监听器默认直接丢弃不执行。需要"无事务也照跑"时配置 fallbackExecution = true。

84.5 @Async 异步监听与顺序控制

一句话定位：监听器方法加 @Async 后由线程池调度异步执行，主流程不必等待短信、邮件完成；多个监听器的顺序用 @Order 控制。

// ① 启动类开启异步支持（漏写 @EnableAsync，@Async 不会生效）
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableAsync;

@Configuration
@EnableAsync
public class AsyncConfig { }

// ② 异步监听器：调用线程立即返回，监听器在线程池中执行
import org.springframework.scheduling.annotation.Async;
import org.springframework.transaction.event.TransactionalEventListener;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

@Component
public class OrderAsyncListeners {

    @Async
    @Order(1)                                   // 同步监听场景下的先后顺序
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void sendSmsAsync(OrderCreatedEvent event) {
        smsSender.send(event.getUserId(), "下单成功");
    }

    @Async
    @Order(2)
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void grantPointsAsync(OrderCreatedEvent event) {
        pointService.earn(event.getUserId(), event.getAmount());
    }
}
  • 异步线程池：默认使用 Spring 内置的 SimpleAsyncTaskExecutor（每次新建线程，不适合生产）；生产环境应在配置类中声明 ThreadPoolTaskExecutor 并通过 @Async("线程池 Bean 名") 指定；
  • 异步与事务：@Async 方法在新线程执行，脱离原事务上下文，方法内需要独立事务应自行标注 @Transactional；
  • 顺序语义：@Order 只控制同一广播器内监听器的执行顺序；一旦加 @Async，顺序不再保证，有先后依赖的动作不要拆成两个异步监听器。

84.6 事件机制两大坑排查

一句话定位：默认同步广播意味着监听器与主流程共用调用线程、共享异常传播路径；事务内事件的发布时机决定监听器读到的数据是否可见。

84.6.1 坑一：监听器异常反向牵连主流程

// 主流程：事务内保存订单并发布事件
@Transactional
public void createOrder(Order order) {
    orderDao.save(order);
    publisher.publishEvent(new OrderCreatedEvent(this, order.getId(), ...));
}

// 监听器：短信网关超时抛异常（同步传播回主流程，导致订单事务回滚！）
@EventListener
public void onCreated(OrderCreatedEvent event) {
    smsSender.send(...);        // 网关抛 RuntimeException → 主流程一并失败
}

修复方向：

  1. 通知类监听器使用 @TransactionalEventListener(AFTER_COMMIT) 并加 @Async，主流程提交成功后才异步通知，失败不回滚订单；
  2. 监听器内部 try-catch 并记录错误日志，把"通知失败"降级为可补偿问题，不让异常冒泡；
  3. 关键下游动作结合消息队列（第 108 章附近）削峰填谷、失败重投。

84.6.2 坑二：事务内发布事件，监听器读到未提交数据

@Transactional
public void createOrder(Order order) {
    orderDao.save(order);
    publisher.publishEvent(new OrderCreatedEvent(this, order.getId(), ...));
    // 此时订单尚未提交；若监听器用另一个连接去查订单，可能查不到（脏读隔离下）
}

// ❌ 普通 @EventListener：发布瞬间同步执行，读到的是未提交或不可见状态
// ✅ @TransactionalEventListener(AFTER_COMMIT)：提交后执行，数据可见，语义正确
问题表现修复
监听器异常回滚主事务下游通知失败，订单跟着回滚AFTER_COMMIT + @Async；监听器内部兜底捕获
监听器查不到订单数据事务未提交，另一连接读不到记录改用 AFTER_COMMIT 时机；事件携带快照数据而非事件里再查库
@Async 不生效方法仍同步执行检查启动类是否加 @EnableAsync；确认调用走代理 Bean
@TransactionalEventListener 未执行发布方法无事务上下文，事件被丢弃加 fallbackExecution = true 或保证发布路径处于事务中

✓ 本章小结

要点一句话
模式本质观察者模式的容器化落地：发布者不认识订阅者，事件类型决定路由
两种监听ApplicationListener 接口强类型；@EventListener 注解简洁，支持事件链
事务时机AFTER_COMMIT 最常用：提交成功再通知；BEFORE_COMMIT 在事务内；AFTER_ROLLBACK 处理失败；AFTER_COMPLETION 收尾
异步监听@Async + @EnableAsync，指定线程池；异步后顺序不保证，脱离原事务
两大坑同步监听器异常会冒泡回滚主流程；事务内事件要用 AFTER_COMMIT 保证数据可见

✎ 本章习题

A 基础对比普通 @EventListener 与 @TransactionalEventListener 的执行时机；列出四种事务阶段各自适合的动作类型。
B 进阶实现"用户注册成功"事件：发布 UserRegisteredEvent，分别写邮件监听器与积分礼包监听器，都绑定 AFTER_COMMIT；在注册事务中人为制造回滚，验证监听器不执行。
C 挑战把邮件监听器改造为 @Async 异步执行，配置独立线程池 Bean；再构造一个"监听器抛异常导致主事务回滚"的事故现场，用 AFTER_COMMIT + 内部 try-catch 修复并验证；最后说明事件驱动与消息队列在解耦强度、失败补偿上的差异。
