图 78-1 Bean 生命周期八阶段

面试速答版：实例化 → 属性填充 → Aware → BeanPostProcessor 前置 → 初始化回调 → BeanPostProcessor 后置（AOP 代理在这生成）→ 使用 → 销毁回调。

78.2 初始化与销毁的回调方式

import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;

@Component
public class CacheWarmer implements InitializingBean, DisposableBean {
    @PostConstruct                    // ① 推荐：JSR-250，依赖注入完成后
    public void warm() { System.out.println("1 @PostConstruct：预热缓存"); }

    @Override                          // ② 接口回调
    public void afterPropertiesSet() { System.out.println("2 afterPropertiesSet"); }

    // ③ XML/@Bean(initMethod="customInit") 指定的方法（略）

    @PreDestroy                        // 容器关闭时
    public void clean() { System.out.println("4 @PreDestroy：释放资源"); }

    @Override
    public void destroy() { System.out.println("3 destroy"); }
}
// 执行顺序：@PostConstruct → afterPropertiesSet → @Bean(initMethod) → destroy 系同理

常见坑：@PostConstruct 方法必须无参、非 static；prototype Bean 的销毁回调不会执行（容器不管它的身后事，第 80 章）。

78.3 BeanPostProcessor：扩展的钥匙

import org.springframework.beans.factory.config.BeanPostProcessor;

/** 对容器里"所有 Bean"统一加工——Spring 各大功能的插入点 */
@Component
public class TimingPostProcessor implements BeanPostProcessor {
    @Override
    public Object postProcessBeforeInitialization(Object bean, String name) {
        // 初始化前：可包装/替换 bean；@Autowired 之外的定制处理
        return bean;
    }
    @Override
    public Object postProcessAfterInitialization(Object bean, String name) {
        // 初始化后：AOP 代理、@Async 代理都在这里把原 Bean 换成代理对象
        System.out.println("[after] " + name + " → " + bean.getClass().getSimpleName());
        return bean;
    }
}
// 你熟悉的这些功能都靠它实现：
// @Autowired 注入（AutowiredAnnotationBeanPostProcessor）
// AOP 代理（AbstractAutoProxyCreator，第 81 章）
// @Async / @Transactional 的代理包装
理解了 BeanPostProcessor，"Spring 为什么能给任意 Bean 加代理/注入/校验"就有了统一答案：所有 Bean 都要过一道后置处理流水线。

78.4 Aware 系列接口

想让 Bean 知道"容器的存在"（拿名字、拿工厂、拿上下文），实现 Aware 接口即可——属性填充之后、初始化回调之前触发：

@Component
public class AwareDemo implements BeanNameAware, ApplicationContextAware {
    private String beanName;
    private ApplicationContext ctx;

    @Override public void setBeanName(String name) { this.beanName = name; }
    @Override public void setApplicationContext(ApplicationContext c) { this.ctx = c; }

    public void info() {
        System.out.println("我叫 " + beanName
            + "，容器里有 " + ctx.getBeanDefinitionCount() + " 个 Bean");
    }
}
// 常用：BeanNameAware / BeanFactoryAware / ApplicationContextAware /
//      EnvironmentAware / ApplicationEventPublisherAware（第 84 章事件用）

使用建议：Aware 让 Bean 耦合到 Spring API，能不用就不用；业务代码优先构造器注入具体依赖，而不是自己抓容器到处找 Bean（Service Locator 反模式）。

78.5 实测：观察一个 Bean 的一生

import org.springframework.context.annotation.*;

public class LifecycleMain {
    public static void main(String[] args) {
        try (var ctx = new AnnotationConfigApplicationContext()) {
            ctx.register(AppConfig.class);
            ctx.refresh();                              // 触发全部创建
            var svc = ctx.getBean(CacheWarmer.class);
            System.out.println("使用中：" + svc.getClass().getSimpleName());
            // ctx.close() 由 try-with-resources 触发 → 销毁回调
        }
    }
}
// 预期输出顺序（穿插所有 Bean）：
//   实例化（构造器输出）
//   1 @PostConstruct：预热缓存
//   2 afterPropertiesSet
//   [after] cacheWarmer → CacheWarmer
//   使用中：CacheWarmer
//   4 @PreDestroy：释放资源
//   3 destroy

✓ 本章小结

要点一句话
八阶段定义→实例化→注入→Aware→前置→初始化→后置（代理）→销毁
回调顺序@PostConstruct → afterPropertiesSet → initMethod
PostProcessor全容器 Bean 的加工流水线；AOP/@Autowired 的实现落点
Aware让 Bean 拿到容器设施；能不用就不用
坑位@PostConstruct 无参非静态；prototype 无销毁回调
