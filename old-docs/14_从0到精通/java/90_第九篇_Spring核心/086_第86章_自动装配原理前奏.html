86.1 @Autowired 解析流程：byType → byName

一句话定位：容器先按注入点类型在容器中查找候选 Bean；命中唯一直接注入；命中多个时再按字段名/参数名作为 Bean 名二次筛选；仍无法唯一确定则抛异常。

图 86-1 容器装配决策：先类型、后名称，冲突时交由 @Qualifier / @Primary 裁决

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class OrderService {

    // byType：容器中恰好一个 PaymentClient 类型 Bean → 直接注入
    private final PaymentClient paymentClient;

    // 构造器注入同样走 byType → byName 解析；单构造器可省略 @Autowired（见 86.5）
    public OrderService(PaymentClient paymentClient) {
        this.paymentClient = paymentClient;
    }
}

// 多候选时的名称匹配示例：
// 接口 PaymentClient 有两个实现：alipayClient、wechatPayClient
// 注入点字段名为 alipayClient → byName 命中 alipayClient
@Service
public class ReportService {
    @Autowired
    private PaymentClient alipayClient;   // 名称与 Bean 名一致，二次筛选成功
}
常见坑：字段名与 Bean 名不一致是多实现场景下最常见的启动报错来源。重命名字段时要同步检查 Bean 名，或直接用 @Qualifier 显式点名（86.3），不要依赖字段名隐式匹配。

86.2 required=false 与缺失处理

一句话定位：默认 required = true，找不到匹配 Bean 启动即失败；设为 false 后找不到则注入 null，不阻断容器启动。

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class ReportService {

    // 可选依赖：环境中存在 MailSender 才注入，不存在保持 null
    @Autowired(required = false)
    private MailSender mailSender;

    public void report() {
        if (mailSender != null) {            // 使用前必须判空
            mailSender.send("report@example.com", "日报已生成");
        } else {
            System.out.println("未配置邮件通道，跳过发送");
        }
    }
}

// 构造器参数上的 required=false：Spring 4.3+ 单构造器场景需配合 ObjectProvider
// 或 setter 注入表达可选依赖；构造器参数无法直接写 required=false 语义
@Service
public class LegacyReportService {
    private MailSender mailSender;

    @Autowired(required = false)
    public void setMailSender(MailSender mailSender) {
        this.mailSender = mailSender;
    }
}
场景required = true（默认）required = false
无匹配 Bean启动抛 NoSuchBeanDefinitionException注入 null，容器正常启动
多实现冲突抛 NoUniqueBeanDefinitionException同样抛异常（缺失与冲突是两类问题）
使用纪律必填依赖早失败、早暴露使用前判空；null 分支必须有兜底逻辑
推荐位置构造器参数（必填优先）setter 注入表达可选依赖

86.3 多实现冲突：@Qualifier 与 @Primary

一句话定位：同一接口多个实现时，@Primary 声明"默认选我"，@Qualifier 在注入点显式点名某一个；两者可叠加，Qualifier 优先级高于 Primary。

import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.context.annotation.Primary;
import org.springframework.stereotype.Component;
import org.springframework.stereotype.Service;

public interface NotifyChannel {
    void send(String to, String msg);
}

// 实现一：标注 @Primary，作为无点名时的默认候选
@Component
@Primary
public class MailNotifyChannel implements NotifyChannel {
    public void send(String to, String msg) { /* 邮件发送 */ }
}

// 实现二：Bean 名 wechatNotifyChannel
@Component
public class WechatNotifyChannel implements NotifyChannel {
    public void send(String to, String msg) { /* 微信发送 */ }
}

@Service
public class CustomerNotifyService {

    private final NotifyChannel defaultChannel;
    private final NotifyChannel wechatChannel;

    // ① 第一个参数不点名：命中 @Primary 的 MailNotifyChannel
    // ② 第二个参数 @Qualifier 显式点名 wechatNotifyChannel，覆盖 Primary 默认
    public CustomerNotifyService(
            NotifyChannel defaultChannel,
            @Qualifier("wechatNotifyChannel") NotifyChannel wechatChannel) {
        this.defaultChannel = defaultChannel;
        this.wechatChannel = wechatChannel;
    }
}
// 自定义 @Qualifier 注解：把"渠道标签"做成可复用的限定符
import org.springframework.beans.factory.annotation.Qualifier;
import java.lang.annotation.*;

@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Qualifier
public @interface Channel {
    String value();
}

// 实现上标注标签，注入点按标签选择，避免依赖 Bean 名
@Component
@Channel("wechat")
public class WechatNotifyChannel implements NotifyChannel { /* ... */ }

@Service
public class NotifyService {
    public NotifyService(@Channel("wechat") NotifyChannel channel) { /* ... */ }
}
金句：@Primary 解决"默认实现"问题，@Qualifier 解决"按需点名"问题；策略集合需要全部实现时不要二选一，用 List/Map 集合注入（86.4）。

86.4 ObjectProvider 延迟获取与集合注入

一句话定位：ObjectProvider<T> 是容器提供的延迟查找句柄，需要时才向容器索取 Bean；注入 List<T>、Map<String, T> 则一次性收拢该类型全部实现。

import org.springframework.beans.factory.ObjectProvider;
import org.springframework.stereotype.Service;
import java.util.List;
import java.util.Map;

@Service
public class ChannelRouter {

    // 集合注入：容器把 NotifyChannel 全部实现收拢为 Map，key = Bean 名
    private final Map<String, NotifyChannel> channels;

    // ObjectProvider：不立即持有实例，调用 getObject() 时才解析
    private final ObjectProvider<ReportExporter> exporterProvider;

    public ChannelRouter(Map<String, NotifyChannel> channels,
                         ObjectProvider<ReportExporter> exporterProvider) {
        this.channels = channels;
        this.exporterProvider = exporterProvider;
    }

    public void notify(String channelName, String to, String msg) {
        NotifyChannel channel = channels.get(channelName);
        if (channel == null) throw new IllegalArgumentException("未知渠道");
        channel.send(to, msg);
    }

    public void exportReport() {
        ReportExporter exporter = exporterProvider.getIfAvailable(); // 不存在返回 null
        if (exporter != null) exporter.export();
    }
}

// List 注入同样成立：List<NotifyChannel> 按顺序收拢全部实现；
// ObjectProvider 还支持 getIfUnique()：唯一实现返回实例，多个或缺失返回 null
注入形态行为典型用途
ObjectProvider<T>延迟解析；getObject() 现取，getIfAvailable() 容错prototype 每次新实例、可选重资源、打破启动期循环
List<T>收拢同类型全部 Bean，按注册顺序排列策略集合、责任链、批量处理器
Map<String, T>key 为 Bean 名，value 为实例按名称路由策略（如渠道、支付方式选择）
数组 T[]与 List 等价的全部实现收拢偏好数组语义的老代码

86.5 @Resource 对比与单构造器注入

一句话定位：@Resource 是 JSR-250 规范注解，先按名称后按类型；@Autowired 是 Spring 注解，先按类型后按名称。Spring 4.3+ 单构造器可省略注入注解。

import jakarta.annotation.Resource;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class AccountService {

    // @Resource：默认按 Bean 名找 accountDao；找不到再按类型兜底
    // name 属性显式指定 Bean 名，不再回退类型匹配
    @Resource(name = "accountDaoJdbc")
    private AccountDao accountDao;

    // @Autowired：先按类型 AccountDao，多候选时再按字段名 accountDao 匹配
    @Autowired
    private AccountDao backupDao;
}

// 单构造器自动注入（Spring 4.3+）：类只有一个构造器，构造器参数自动装配，
// 无需书写 @Autowired；这是本书一直推荐的构造器注入写法的底层规则
@Service
public class OrderService {
    private final OrderDao orderDao;
    private final PaymentClient paymentClient;

    // 构造器上没有 @Autowired，容器依然按类型装配两个参数
    public OrderService(OrderDao orderDao, PaymentClient paymentClient) {
        this.orderDao = orderDao;
        this.paymentClient = paymentClient;
    }
}
// 注意：存在多个构造器时容器不会猜，必须在某个构造器上显式标注 @Autowired
维度@Autowired（Spring）@Resource（JSR-250）
解析顺序先 byType，多候选再 byName先 byName，找不到再 byType
限定符配合 @Qualifier 点名name 属性直接指定 Bean 名
可选依赖required = false无 required 语义；依赖缺失启动报错
可标注位置构造器、方法、参数、字段字段、setter 方法（不支持构造器参数）
跨框架Spring 专有Java EE / Jakarta 规范，可迁移到其他容器

86.6 装配规则小结与 Boot 铺垫

一句话定位：本章讲的"按类型找候选、按名称/限定符裁决、集合收拢全部"正是 Spring 容器装配的通用规则；SpringBoot 自动配置只是把这套规则搬到"类路径条件 + 配置类 + 默认 Bean"的自动化场景。

  • 基础装配规则：容器持有全部 Bean 定义，注入点按类型检索候选，唯一即注入，多个由 Primary、Qualifier、名称依次裁决；
  • 集合与延迟：List/Map 收拢全部实现是策略模式的标准落点；ObjectProvider 把获取时机推迟到使用时刻；
  • 规范边界：Spring 项目内以 @Autowired 构造器注入为主；需要标准注解兼容时用 @Resource；
  • Boot 自动配置预告：下一篇会看到 @EnableAutoConfiguration 根据类路径上存在的类自动注册 DataSource、DispatcherServlet 等 Bean；"条件判断 + 类型装配"的底层思路与本章候选解析一脉相承。
// 预告：SpringBoot 自动配置的核心句式（第 88 章附近展开，此处先建立印象）
// 容器启动时读取 META-INF/spring/...AutoConfiguration.imports 中的配置类；
// 配置类上的条件注解判断类路径、Bean 是否存在，再用 @Bean 注册默认实现：
//
// @ConditionalOnClass(DataSource.class)        // 类路径有 DataSource 才生效
// @ConditionalOnMissingBean(DataSource.class)   // 用户没自定义才用默认实现
// @Configuration
// public class DataSourceAutoConfiguration {
//     @Bean
//     @ConditionalOnMissingBean
//     public DataSource dataSource(DataSourceProperties props) { ... }
// }
// 这套"候选已存在就跳过、不存在才兜底"的规则，正是本章装配流程的框架化升级。

✓ 本章小结

要点一句话
解析顺序@Autowired 先 byType，唯一注入；多个再 byName；仍冲突抛 NoUniqueBeanDefinitionException
可选依赖required=false 缺失时注入 null，使用前判空；多候选冲突不受 required 豁免
冲突裁决@Primary 定默认，@Qualifier 点名优先；自定义注解式 Qualifier 支持标签路由
延迟与集合ObjectProvider 按需现取；List/Map 收拢全部实现供策略与责任链使用
规范与铺垫@Resource 先名后类型、JSR-250 标准；单构造器免注解；Boot 自动配置是条件化候选装配的升级

A 基础复述 @Autowired 的解析流程：候选为 0、为 1、大于 1 分别如何处理；写出 NoUniqueBeanDefinitionException 的两种修复注解。
B 进阶定义一个 PaymentChannel 接口及 Alipay、Wechat、Card 三个实现，用 Map 注入实现按渠道名路由；再为其中一个实现加 @Primary，验证不点名注入时的默认选择。
