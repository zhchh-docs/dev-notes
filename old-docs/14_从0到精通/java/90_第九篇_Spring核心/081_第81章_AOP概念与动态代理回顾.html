81.1 横切关注点：业务里的公共碎片

一句话定位：关注点（Concern）是程序中一类特定功能；散落在多个业务模块、与核心业务无关的关注点，叫做横切关注点（Cross-cutting Concern）。

@Service
public class OrderService {
    public Order createOrder(OrderRequest req) {
        long t0 = System.currentTimeMillis();        // ① 日志：谁调用了什么参数
        log.info("createOrder 入参={}", req);
        try {
            Order order = doCreate(req);
            auditLog.record("订单创建", currentUser()); // ② 审计：操作留痕
            log.info("createOrder 成功，耗时={}ms",
                     System.currentTimeMillis() - t0); // ③ 计时
            return order;
        } catch (Exception e) {
            log.error("createOrder 失败", e);          // ④ 异常记录
            metrics.increment("order.fail");           // ⑤ 指标埋点
            throw e;
        }
    }
    private Order doCreate(OrderRequest req) { /* 真正业务 */ return null; }
}
  • 代码分散（Scattering）：日志、权限、事务、埋点同样的代码复制到几十个 Service；
  • 代码混乱（Tangling）：业务方法里混着非业务逻辑，读代码时主线被打断；
  • 修改成本高：日志格式调整要改几十个文件，漏改一处就是隐患。
金句：AOP 的目标不是替代面向对象，而是把"贯穿所有对象、不属于某一个对象"的逻辑从业务类里剥离出来，集中维护；业务代码只保留"做什么"，"前后做什么"交给切面。

81.2 AOP 核心术语六讲

一句话定位：AOP 术语不多，但每个通知注解（下一章的 @Before、@Around…）都要落到这些概念上，先把名词固定下来。

术语含义（本书用语 + 英文）
切面 Aspect横切逻辑本身的模块化单元，对应一个带 @Aspect 的类；日志切面、事务切面都是切面。
连接点 Join Point程序执行中可以插入切面的时机点；Spring AOP 中只支持方法执行（调用前/后/抛出异常等）。
切点 Pointcut用表达式圈定"哪些连接点需要被通知"，例如"所有 com.demo.service 包下 public 方法"。
通知 Advice切面在切点处执行的动作本身，分前置、后置、返回后、异常后、环绕五种；对应 @Before 等注解。
目标对象 Target Object被代理、被织入通知的原始业务对象；切面逻辑围绕它执行。
织入 Weaving把切面应用到目标对象、创建代理对象的过程；分编译期、类加载期、运行期三种时机。

81.3 静态代理回顾（第 42 章衔接）

一句话定位：代理模式在调用方与真实对象之间插入一个同接口的代理类，由它前后增强、转发调用；静态代理为每个目标接口手写一个代理类。

// 目标接口
public interface OrderService {
    Order createOrder(OrderRequest req);
}

// 真实对象：只写业务
public class OrderServiceImpl implements OrderService {
    public Order createOrder(OrderRequest req) {
        System.out.println("执行业务：创建订单");
        return new Order();
    }
}

// 静态代理：同接口，持有真实对象，前后加日志
public class OrderServiceLogProxy implements OrderService {
    private final OrderServiceImpl target;
    public OrderServiceLogProxy(OrderServiceImpl target) { this.target = target; }

    public Order createOrder(OrderRequest req) {
        System.out.println("[代理] 前置日志：方法入参=" + req);
        Order result = target.createOrder(req);     // 转发真实调用
        System.out.println("[代理] 后置日志：返回=" + result);
        return result;
    }
}

// 使用：调用方拿到的是代理，不是原始实现
// OrderService svc = new OrderServiceLogProxy(new OrderServiceImpl());
  • 优点：实现直观、编译期绑定、调试路径清晰；
  • 硬伤：一个接口就要写一个代理类；接口新增方法，代理必须同步修改；想给 100 个 Service 加日志，就要手写 100 个代理——这正是动态代理要消灭的重复劳动。

81.4 动态代理：JDK 与 CGLIB 对比

一句话定位：动态代理在运行期自动生成代理类，无需手写；Java 生态有两套实现——基于接口的 JDK 动态代理，基于继承的 CGLIB 代理。

81.4.1 JDK 动态代理（基于接口）

import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

public class LogInvocationHandler implements InvocationHandler {
    private final Object target;
    public LogInvocationHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[JDK 代理] 前置：" + method.getName());
        Object result = method.invoke(target, args);   // 反射转发真实方法
        System.out.println("[JDK 代理] 后置：" + method.getName());
        return result;
    }

    @SuppressWarnings("unchecked")
    public static <T> T wrap(T target, Class<T> iface) {
        InvocationHandler h = new LogInvocationHandler(target);
        return (T) Proxy.newProxyInstance(
            iface.getClassLoader(),
            new Class<?>[]{ iface },                 // 必须提供接口
            h);
    }
}
// OrderService proxy = LogInvocationHandler.wrap(impl, OrderService.class);
// 代理对象与真实对象都实现 OrderService 接口；代理类在运行期生成于 jdk.proxy 包

81.4.2 CGLIB 代理（基于继承）

// CGLIB 不要求接口：在运行期生成目标类的子类，覆写方法织入逻辑
import org.springframework.cglib.proxy.Enhancer;
import org.springframework.cglib.proxy.MethodInterceptor;
import org.springframework.cglib.proxy.MethodProxy;

public class CglibLogProxy {
    @SuppressWarnings("unchecked")
    public static <T> T wrap(T target) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(target.getClass());   // 父类 = 目标类
        enhancer.setCallback((MethodInterceptor) (obj, method, args, proxy) -> {
            System.out.println("[CGLIB 代理] 前置：" + method.getName());
            Object result = proxy.invokeSuper(obj, args); // 调用父类原始方法
            System.out.println("[CGLIB 代理] 后置：" + method.getName());
            return result;
        });
        return (T) enhancer.create();
    }
}
// 注意：final 类不能被继承 → CGLIB 无法代理；目标方法若 final/private 也无法被覆写拦截
维度JDK 动态代理CGLIB 代理
代理依据实现目标接口继承目标类，生成子类
接口要求必须至少有一个接口不需要接口
受限条件无接口的类不能被代理final 类、final/private 方法不能被代理
性能特点生成快；方法调用经反射，单次略慢生成略慢；调用期直接走子类，后续更快
Spring 默认规则Bean 实现了接口 → 默认用 JDK 代理无接口或强制 proxyTargetClass=true → 用 CGLIB
内存与缓存代理类缓存于 JVM，不重复生成字节码在运行期由 ASM 框架生成并缓存
注意：Spring Boot 2.x 之后默认 proxyTargetClass=true，即统一使用 CGLIB；但无论哪种代理，被代理对象的方法内部自调用（this.method()）都不会经过代理——第 82 章把这条坑展开排查。

81.5 Spring AOP 织入时机与 AspectJ 简述

一句话定位：Spring AOP 是运行期织入的代理型 AOP 框架，只支持方法级连接点；AspectJ 是功能完整的原生 AOP 实现，可在编译期/类加载期织入，支持字段、构造器等更丰富的连接点。

  • 编译期织入：AspectJ 编译器（ajc）在源码编译阶段把切面代码织入类字节码；性能最好、能力最全，但需要特殊编译流程；
  • 类加载期织入（LTW）：类加载进 JVM 时由织入代理修改字节码；需要配置加载时织入器；
  • 运行期织入（Spring AOP）：容器为 Bean 创建代理对象，调用时在代理内部执行通知；不修改原类字节码，与 IoC 容器天然结合，配置成本最低。
// Spring AOP 能力边界（面试常考）：
// ✅ 支持：方法执行前后、返回后、异常后、环绕；Spring 容器内 Bean 之间的调用拦截
// ❌ 不支持：拦截字段读写、构造器调用、静态方法、类内部 this 自调用
// 超出这些需求（如字段注入时做校验、拦截 new 对象）→ 需要 AspectJ

// 两类实现的依赖关系：Spring AOP 采用 AspectJ 的注解体系
//（@Aspect、@Pointcut、@Before …），但底层代理机制是 Spring 自己的
// 即：用 AspectJ 的"语法注解"，跑 Spring AOP 的"运行期代理"。
金句：日常业务里的日志、计时、权限、事务，Spring AOP 已经够用；只有当连接点超出方法执行（字段、构造器）或追求极致织入性能时，才需要引入 AspectJ。

✓ 本章小结

要点一句话
横切关注点日志/事务/权限/埋点等贯穿多模块、与业务无关的公共逻辑
六术语切面是模块，切点圈方法，通知是动作，连接点是时机，目标是原始对象，织入是生成代理
静态代理同接口手写代理类，直观但重复劳动大，无法规模化覆盖
双动态代理JDK 靠接口反射，CGLIB 靠继承子类；Boot 默认 CGLIB（proxyTargetClass=true）
Spring AOP 边界运行期代理织入，仅方法级；字段/构造器拦截需 AspectJ
