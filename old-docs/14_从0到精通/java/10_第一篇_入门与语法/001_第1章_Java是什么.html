1.1 三层认知：语言 / JVM / 生态

初学者 80% 的困惑，来自把三个不同层面的东西压成一个词"Java"。拆开看，每一层回答的问题完全不同。

日常对话里的"Java"其实同时指三样东西：一门语言、一台虚拟机、一个生态。它们分别回答"你怎么写代码"、"程序怎么跑起来"、"你靠什么干活"这三个问题。

图 1-1　"Java"一词背后的三层结构

Java 语言是一套语法规则：怎么声明变量、怎么定义类、怎么表达继承。它由《Java 语言规范》（JLS）定义。本篇的大部分章节都在这一层——学语法。

JVM（Java Virtual Machine）是一台"想象的计算机"，由《JVM 规范》定义。它不认识 Java 语言，只认识一种叫字节码（bytecode，.class 文件）的中间格式。任何语言只要能编译出合法字节码，就能跑在 JVM 上——Kotlin、Scala、Groovy 都是这么来的。

Java 生态是围绕这门语言生长出来的整个世界：构建工具 Maven/Gradle、Web 框架 Spring、服务器 Tomcat、大数据引擎 Hadoop/Flink……工程能力的大头在这一层。

"学 Java"最终是三件事：学语言语法、懂 JVM 原理、用生态工具。三层混着学容易迷路，分层建立认知才走得远。

为什么要强调这个区分？举两个真实场景：

  • 面试问"JVM 内存模型"，答的应该是 JVM 层的事，扯到语言语法就露怯了；
  • 看到"Kotlin 也是 JVM 语言"不再惊讶——因为 JVM 只认字节码，不认语言。

1.2 一次编写，到处运行

1995 年 Java 的口号 "Write Once, Run Anywhere" 不是营销话术，而是一个具体的工程方案：把"翻译"从目标机器挪回了开发机。

C/C++ 编译出来的程序是机器码，直接说给某种 CPU 听：x86 的程序不能跑在 ARM 上，Windows 的程序不能跑在 Linux 上。Java 的做法分两步：

  • 第一步（开发机上）：javac 把 .java 源码编译成 .class 字节码——一种面向"想象的计算机"的指令，与任何真实 CPU 无关；
  • 第二步（目标机器上）：java 命令启动 JVM，由它逐条解释/即时编译字节码，翻译成当前机器的机器码。

图 1-2　"一次编写，到处运行"的实现路径

于是三个常被搞混的名词可以用一句话钉死：

名词全称一句话定位
JVMJava Virtual Machine执行字节码的虚拟机，核心引擎，只认 .class
JREJava Runtime EnvironmentJVM + 运行期核心类库，"能跑程序"的最小套装
JDKJava Development KitJRE + 开发工具（javac、javadoc、jstack…），"能开发程序"的完整套装
包含关系：JDK ⊃ JRE ⊃ JVM。写代码装 JDK，只跑程序装 JRE 就够——这也是为什么 IDE 会反复问"你的 JDK 在哪"。
常见坑网上教程常说"编译型语言 vs 解释型语言"，把 Java 归为其中一种。实际上 Java 是"先编译成字节码、再由 JVM 解释 + 即时编译（JIT）执行"的混合模式，第 67 章讲 JIT 时你会看到这套设计如何做到"慢启动、快运行"。

最后留一个第一印象：下面这个程序第 3 章才会逐词拆解，现在只需要感受"所有代码都住在类里"这门语言的秩序感：

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
// 运行输出：Hello, Java!

1.3 Java 的应用版图

选择学一门语言，本质是选择它背后的就业市场与问题域。Java 的地盘清晰而广阔。

领域代表性技术为什么是 Java
后端服务 / 微服务Spring Boot、Spring Cloud生态最成熟，人才池最大，互联网公司主力栈
大数据Hadoop、Spark、Flink、Kafka核心组件基本由 JVM 系语言写成
AndroidAndroid SDK（Java/Kotlin）官方语言之一，Kotlin 也跑在 JVM 上
企业级软件银行、保险、电信核心系统稳定、向后兼容好、久经生产考验
中间件Elasticsearch、RocketMQ、Nacos高性能服务端组件的常见实现语言

看不到的领域也有它的边界：操作系统内核、游戏引擎核心、嵌入式这些对延迟和体积极端敏感的场景，仍是 C/C++/Rust 的天下；脚本化、数据处理快速验证则是 Python 的舒适区。

常见坑Java 和 JavaScript 的名字相似纯属历史营销：1995 年 Netscape 借 Java 的名气把 LiveScript 改名 JavaScript。两者语法都借了 C 风格，但类型系统、运行模型、应用领域几乎完全不同——Java 是静态类型的编译到字节码的语言，JavaScript 是动态类型的解释执行的语言。

1.4 版本与 LTS：该学哪个

Java 从 2018 年起每 6 个月发一个版本，但不是每个版本都值得追——跟着 LTS 走就对了。

LTS（Long-Term Support，长期支持版）是官方承诺长期维护的版本，也是企业实际生产的选型。非 LTS 版本更像是"下一次大更新的预览通道"。

版本发布年份关键特性与本教程的关联
Java 82014Lambda、Stream、新日期时间 API——许多老系统仍停在 8
Java 112018首个收费授权波动的 LTS，模块化后第一个 LTS
Java 172021record 正式化、switch 增强、密封类——本教程的基线版本
Java 212023虚拟线程正式化，并发编程的新范式（第六篇会讲）
本教程以 Java 17（LTS）为基线书写，涉及更新版本特性时会显式标注版本号。学语法优先选 17：既覆盖现代写法，又与企业主流兼容。

一个务实的认知：语言特性只是小头，绝大多数语法在 8 就已定型；17 之后的新特性大多是"让代码更短、更安全"的打磨。所以不要陷入"版本焦虑"——先把 8~17 的主干学扎实，新特性按需补即可。

1.5 与其他语言的坐标

没有"最好的语言"，只有"为哪种取舍而生的语言"。把 Java 放进坐标系，你才知道自己买到了什么、放弃了什么。

语言类型系统核心取舍
C / C++静态、手动内存管理极致性能与底层控制，代价是开发效率与内存安全
Java静态、GC 自动回收性能与安全的均衡点：牺牲一点启动速度和内存，换来稳定性、可维护性与庞大生态
Python动态开发效率极高，运行慢、大型项目重构难
JavaScript动态浏览器垄断地位，语言本身的历史包袱多
Go静态、GC编译快、并发原语简洁，牺牲泛型表达力（1.18 后改善）
Kotlin / Scala静态（JVM 上）在 JVM 生态上做语法改良，与 Java 互操作

Java 的性格可以概括成一句话：宁可啰嗦一点，也要让编译器替你把关。静态类型让大部分低级错误在编译期暴露；自动垃圾回收让程序员从内存管理中解放；强规范（包结构、命名习惯、异常体系）让百人协作的百万行项目成为可能——这正是它在企业级后端长盛三十年的根本原因。

JVM 语言家族：一个平台，多种语言

1.1 节说过 JVM 只认字节码。于是围绕同一台虚拟机长出了一个语言家族：

  • Kotlin：Android 官方首选，空安全、语法简洁，与 Java 100% 互操作；
  • Scala：大数据早期主力（Spark 原生语言），类型系统强大但学习曲线陡；
  • Groovy：动态语法，Gradle 构建脚本的语言。

这个家族的意义在于：你花时间学的 JVM 知识（内存、GC、类加载、并发模型）对所有 JVM 语言通用，这是比语法更保值的投资。

静态类型 + 虚拟机 + 生态沉淀 = Java 的立身之本。它的啰嗦是"把混乱挡在编译期"的代价，学语法时你会反复体会到这层设计意图。
