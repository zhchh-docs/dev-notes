4.1 变量与强类型

变量是内存里一块有名字的存储空间。强类型意味着：声明时必须写类型，之后只能装这个类型的数据。

int age = 25;          // 声明 + 初始化
double price;          // 只声明，未初始化
price = 9.9;           // 之后赋值（首次使用前必须赋值）

age = "二十五";         // 编译错误！int 不能装 String
age = 26;              // 可以再赋新值（同类型）
  • 声明：类型 变量名 = 初始值;
  • 局部变量必须先初始化再用——否则编译错误 variable might not have been initialized；
  • 类型错误在编译期就被拦下，这是静态语言送你的第一份保险。
数据类型分两大阵营：基本类型（primitive）直接存值，引用类型（reference）存对象的地址。本章讲基本类型；String 等引用类型第 9 章起展开。

4.2 八种基本类型总表

类型字节范围默认值(字段)典型用途
byte1-128 ~ 1270二进制数据、IO
short2约 ±3.2 万0少见，兼容历史
int4约 ±21 亿0整数的默认选择
long8约 ±922 亿亿0L时间戳、大编号
float4约 7 位有效数字0.0f省内存的浮点
double8约 15 位有效数字0.0d浮点的默认选择

实践建议很简单：整数默认 int，大了换 long；小数默认 double；逻辑用 boolean。byte/short 只在明确要省内存或对接二进制协议时用。

int count = 42;
long totalBytes = 8_589_934_592L;   // 超过 int 范围必须加 L
double ratio = 0.618;
boolean isVip = true;
char grade = 'A';

4.3 字面量的各种写法

字面量（literal）就是代码里直接写出来的值。Java 的写法比多数教程说的丰富：

// 整型：四种进制 + 下划线分隔
int dec  = 1_000_000;     // 十进制，下划线增强可读性
int hex  = 0xFF;          // 十六进制 = 255
int oct  = 010;           // 八进制 = 8（前缀 0，慎用！）
int bin  = 0b1010;        // 二进制 = 10
long big = 9_223_372_036_854_775_807L;  // long 后缀 L

// 浮点：f/d 后缀与科学计数法
float  f = 3.14f;         // float 必须加 f
double d1 = 3.14;
double d2 = 1.2e3;        // 科学计数法 = 1200.0

// 字符与转义
char a = 'A';
char cn = '中';
char nl = '\n';           // 换行
char tab = '\t';          // 制表符
char quote = '\'';        // 单引号本身
char uni = '\u4e2d';      // Unicode 写法，等于 '中'

// 布尔
boolean ok = true, fail = false;
常见坑int x = 010; 是 8 不是 10——以 0 开头的整数是八进制。别让前导零悄悄进你的代码。

4.4 常量 final 与 var

用 final 修饰的变量只能赋值一次，习惯上常量名全大写：

final double TAX_RATE = 0.13;
final int MAX_RETRY = 3;
TAX_RATE = 0.2;   // 编译错误：不能给 final 变量重新赋值

Java 10 起局部变量可用 var 让编译器推断类型，右侧是什么类型它就是什么类型：

var name = "张三";        // 推断为 String
var scores = new int[10]; // 推断为 int[]
var x;                    // 编译错误：没有初始值无法推断
var 只能用于有初始值的局部变量，不能用于字段、方法参数、返回值。用或不用是风格问题：类型名太长时（如泛型嵌套）用 var 更清爽。

4.5 三大经典坑

坑一：浮点误差

System.out.println(0.1 + 0.2);
// 输出 0.30000000000000004，不是 0.3！

二进制无法精确表示 0.1、0.2 这类十进制小数，误差在累加中暴露。结论：金额计算用 BigDecimal（第 21 章介绍），展示时先格式化。

坑二：整型溢出

int max = Integer.MAX_VALUE;
System.out.println(max + 1);
// 输出 -2147483648——溢出后绕回最小值，不报错！

坑三：char 参与算术

char c = 'A';
System.out.println(c + 1);   // 输出 66（int）！不是 'B'
System.out.println((char)(c + 1)); // 强转后才是 'B'

char 本质是无符号整数（Unicode 码点），参与运算时自动提升为 int。

一句话防坑：钱不用 double，大数不指望 int，char 运算记得强转。
