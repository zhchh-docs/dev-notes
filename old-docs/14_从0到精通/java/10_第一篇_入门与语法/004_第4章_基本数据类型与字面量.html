◆本章目标

Java 是静态类型语言：每个变量出生时就登记了类型，且终身不变。本章把八种基本类型这张"体检表"记熟，并把两组经典坑排掉。

  • 理解静态类型的含义：声明即约定，编译器据此把关；
  • 记住八种基本类型的字节数与适用场景，分清基本类型与引用类型；
  • 掌握整型/浮点/字符/布尔/字符串字面量的正确写法；
  • 亲手制造并理解浮点误差与 int/long 溢出两个必考坑；
  • 会用 var 局部变量类型推断，同时知道什么时候不该用它。

4.1 静态类型：变量一生的约定

声明变量的完整语法是"类型 + 名字 + 赋值"。这个看似啰嗦的格式，正是编译器替你把关的依据。

int age = 25;          // 声明：age 从此是 int，终身不变
age = 26;              // OK：可以换值，但不能换类型
// age = "二十六";      // 编译错误：不兼容的类型
double price;          // 只声明不赋值也合法
price = 9.9;           // 局部变量使用前必须赋值

Java 的类型分两大族，本篇聚焦基本类型（primitive），引用类型从第 11 章展开：

族成员变量里存的是什么
基本类型（8 种）byte/short/int/long、float/double、char、boolean值本身
引用类型（无数种）String、数组、一切类与接口对象的"地址"（引用）
"变量里存的是值本身还是地址"是贯穿全书的一根主线：第 7 章的参数传递、第 8 章的数组别名、第 20 章的 equals 对比，都是这条主线的不同站点。

4.2 八种基本类型体检表

八种类型按"存什么"分四组：整数、浮点、字符、布尔。记字节数不是为了背诵，是为了判断"够不够用、会不会溢出"。

类型字节范围（约）典型用途
byte1-128 ~ 127二进制数据、节省内存的场景
short2±3.2 万少见，历史兼容
int4±21 亿默认整数类型，日常首选
long8±922 亿亿时间戳、ID、大数计数
float4约 6~7 位有效数字少见，需加 f 后缀
double8约 15 位有效数字默认浮点类型（但别用于钱！）
char2一个 UTF-16 代码单元单个字符，单引号
boolean—true / false逻辑判断，只此二值

三条实用规则：

  • 整数没有特别理由就用 int，超范围用 long；byte/short 只在省内存或对接二进制协议时用；
  • 浮点默认 double；float f = 3.14f 必须带 f 后缀（见 4.3 节）；
  • 整数字面量默认是 int 类型——这一句正是下面溢出坑的伏笔。
金额计算一律不用 float/double：用 BigDecimal（字符串构造）或以"分"为单位的 long。浮点误差对金额是事故级 bug。

4.3 字面量的正确写法

字面量（literal）是直接写在代码里的"字面值"。每种类型有自己的书写规则，写错编译器会立即拦截。

// 整数：四种进制 + 下划线分隔（下划线纯为人读友好，编译期忽略）
int dec  = 1_000_000;      // 十进制，一百万
int hex  = 0xFF;           // 十六进制，255
int oct  = 010;            // 八进制，8（前导 0 就是八进制，易误读！）
int bin  = 0b1010;         // 二进制，10

// 浮点：默认 double，float 必须带 f
double d = 3.14;
float  f = 3.14f;
double sci = 1.2e3;        // 科学计数法 = 1200.0

// 字符：单引号 + 单字符；转义序列
char c1 = 'A';
char c2 = '中';
char nl = '\n';            // 换行
char u   = '\u0041';       // Unicode 写法，也是 'A'

// 布尔与字符串
boolean ok = true;
String s = "双引号才是字符串";
常见坑①long big = 10000000000; 编译报错——整数字面量默认 int，100 亿超了 int 范围。正确写法 10000000000L。L 后缀让字面量自身是 long。②八进制 010 是 8 不是 10：日常代码尽量别写前导零。③单引号双引号天差地别：'A' 是 char（数字 65），"A" 是 String 对象。

char 本质上是"存字符编码的无符号整数"，可以参与算术——这正是第 5 章 'A'+1=66 的伏笔：

char c = 'A';
System.out.println((int) c);  // 65：'A' 的编码值
c++;                          // char 可以自增
System.out.println(c);        // B

4.4 浮点误差与 long 溢出

两个必考坑：一个来自二进制小数的先天缺陷，一个来自定长整数的边界。面试和事故现场都常见。

坑一：0.1 + 0.2 为什么不等于 0.3

System.out.println(0.1 + 0.2 == 0.3);   // false！
System.out.println(0.1 + 0.2);          // 0.30000000000000004

原因：二进制无法精确表示十分之一（就像十进制写不尽 1/3），0.1 存进去的是"最接近的二进制近似值"。两个近似值相加，误差浮出水面。

  • 比较浮点：不用 ==，用"差值小于极小数"：Math.abs(a - b) < 1e-9；
  • 金额计算：用 BigDecimal 且必须用字符串构造：new BigDecimal("0.1")（用 double 构造会把误差一起带进去）；
  • 展示层面：格式化输出 String.format("%.2f", 0.1 + 0.2) 得 0.30。

坑二：int 溢出——悄悄变成负数

int max = Integer.MAX_VALUE;      // 2147483647
System.out.println(max + 1);      // -2147483648：绕回起点，编译器不报错！

// 更隐蔽的形态：先溢出再赋值给 long，为时已晚
long wrong = Integer.MAX_VALUE + 1;            // 结果仍是 -2147483648
long right = Integer.MAX_VALUE + 1L;           // 2147483648：先变 long 再算

// 最经典的形态：计算"天数 * 毫秒"时溢出
int days = 25;
long bad = days * 24 * 60 * 60 * 1000;         // 25 天起溢出为负！
long good = days * 24L * 60 * 60 * 1000;       // 在链路早期把任一项变 long
溢出防范口诀：让链路中最早可能越界的那个值先升位（加 L）。表达式从左到右逐项运算，每一步临时结果的类型在当时就定了。
常见坑溢出不会抛异常、不会警告，静默发生。凡涉及时间戳（毫秒级 13 位）、文件字节数、大额积分的表达式，都要主动检查"乘起来会不会很大"。

4.5 var 与类型安全的选择

Java 10 引入 var：局部变量的类型推断。它不是动态类型——类型仍在编译期锁定，只是让你少写一遍。

var count = 10;                        // 推断为 int，之后仍只能赋 int
var names = new ArrayList<String>();   // 推断为 ArrayList<String>
// count = "abc";                      // 依然编译错误：var 不是 JS 的 var

// var 的价值在长类型名场景，可读性反而更好
var map = new HashMap<String, List<Integer>>();
  • 只能用于有初始化值的局部变量：字段、方法参数、返回值都不能用 var；
  • 右值一目了然时用 var（new 表达式）；右值看不出类型时写显式类型，读者不需要跳转定义；
  • var 是"书写便利"不是"类型放松"——编译期检查与显式声明完全一致。

4.6 初见包装类：为什么 int 不是一切

集合、泛型这些"只收对象"的容器容不下基本类型——于是每种基本类型都有一个对应的"包装类"。现在只需建立概念，细节在第三篇展开。

基本类型包装类一句话说明
byte / short / intByte / Short / IntegerInteger 最常用，带 MAX_VALUE 等常量
long / float / doubleLong / Float / DoubleDouble.parseDouble 解析字符串
char / booleanCharacter / BooleanCharacter.isDigit 等判断工具
 
// 装箱：基本类型 → 对象；拆箱：对象 → 基本类型
Integer boxed = 42;             // 自动装箱（编译器插入 Integer.valueOf）
int plain = boxed;              // 自动拆箱（插入 intValue()）

// 包装类上的实用工具
int max = Integer.MAX_VALUE;    // 2147483647，第 4.4 节的主角
int n = Integer.parseInt("123");// 字符串转数字，第 3 章习题用过
常见坑拆箱一个 null 的包装类会抛 NullPointerException：Integer x = null; int y = x; 编译不报错、运行炸裂。"包装类可能为 null"是它在业务代码里与基本类型最大的行为差异。

记一个规则即可收尾：领域内的字段与方法参数优先用基本类型（不可能是 null、没有装箱开销）；需要"没有值"这个状态、或要放进集合时才用包装类。第三篇讲到泛型约束时会回扣这条规则。

✓ 本章小结

要点一句话总结
静态类型变量出生定类型终身不变，编译器据此把关
两大类型族基本类型存值本身，引用类型存对象地址
类型选择整数默认 int、超了用 long；浮点默认 double 但不碰钱
字面量long 加 L、float 加 f、前导 0 是八进制、单引号是 char
浮点误差二进制表示的先天缺陷：比较用极小差值，金额用 BigDecimal
溢出静默发生不报错；让链路最早的越界值先升位
var局部变量类型推断，静态本质不变，右值清晰时才用
