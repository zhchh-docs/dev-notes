◆本章目标

本章只有一个验收标准：终端里 java -version 正确输出，IDEA 里能新建项目并运行代码。过程中遇到任何报错，直接翻 2.5 节排查表。

2.1 装 JDK：选版本与验证

先明确一件事：装的是 JDK，不是"Java"。JDK = 编译器 + 运行环境 + 工具箱（见 1.2 节的包含关系）。

选哪个发行版

JDK 有多个"品牌"（发行版），字节码层面彼此兼容：

发行版说明
Oracle JDK官方出品，生产环境商用需注意授权条款
Eclipse Temurin（推荐）Adoptium 项目出品，免费、开源、更新稳定，学习与生产皆宜
Amazon Corretto / 阿里 Dragonwell云厂商维护的免费发行版，常用于对应云平台
学习阶段选择：Eclipse Temurin 的 Java 17（LTS）。不要纠结发行版——它们实现同一个规范，将来切换成本几乎为零。

安装与验证

Windows 下载 .msi 安装包一路下一步；macOS 用 .pkg 或 brew install temurin@17。安装完成后打开新终端（不是装之前就开着的窗口）验证：

java -version
# 输出示例：
# openjdk version "17.0.10" 2024-01-16
# OpenJDK Runtime Environment Temurin-17.0.10+7
# OpenJDK 64-Bit Server VM Temurin-17.0.10+7 (mixed mode)

javac -version
# 输出示例：javac 17.0.10
  • 两条命令都有输出 → 安装成功；
  • java 有输出但 javac 提示"不是内部或外部命令" → 装的大概率是 JRE，或 PATH 没配好，看 2.2 节；
  • 版本号不对（比如想装 17 却输出 1.8） → 机器上有多个 JDK，看 2.5 节第 2 条。
常见坑验证命令一定要在新开的终端里执行。环境变量是进程启动时读取的，老窗口感知不到新配置——这是"我明明装好了却找不到命令"的头号原因。

2.2 配置 JAVA_HOME 与 Path

两个环境变量、两种职责：Path 决定"命令找不找得到"，JAVA_HOME 决定"其他工具去哪找 JDK"。

环境变量作用谁在用它
Path命令行搜索可执行程序的目录列表终端里的 java / javac 命令
JAVA_HOME指向 JDK 安装根目录Maven、Gradle、Tomcat、IDEA 等工具

Windows 推荐配置姿势（系统设置 → 高级系统设置 → 环境变量）：

新建系统变量 JAVA_HOME = C:\Program Files\Eclipse Adoptium\jdk-17.0.10.7-hotspot

编辑 Path，新增一条（用引用写法，升级 JDK 只改一处）：
%JAVA_HOME%\bin

macOS / Linux 通常包管理器会自动配好；手动配置写在 ~/.zshrc 或 ~/.bashrc：

export JAVA_HOME=$(/usr/libexec/java_home -v 17)   # macOS
export PATH=$JAVA_HOME/bin:$PATH
Path 里写 %JAVA_HOME%\bin 而不是写死完整路径：将来升级 JDK 只改 JAVA_HOME 一处，Path 不动。这是"单一事实来源"思想在你机器上的第一次应用。
常见坑①Path 里可能残留 C:\Program Files\Common Files\Oracle\Java\javapath 这类历史项，它优先于你新加的目录，导致版本"改不动"——删掉或下移它。②变量值末尾多打了分号或空格，会让整个目录失效。③改完必须重开终端。

2.3 IDEA 安装与关键设置

IDEA 分两个版本：Community 免费版够用完整个前八篇；Ultimate 付费版多的是 Web/框架支持（第九、十篇再考虑）。

从 JetBrains 官网下载 Community 版安装后，先做三个设置（File → Settings，macOS 是 Preferences）：

  1. 确认 JDK：File → Project Structure → SDK，选中刚装的 17。IDEA 能自动探测本机 JDK 列表；
  2. 设置编码：Settings → Editor → File Encodings，三处全部选 UTF-8。编码不一致是中文乱码的根源；
  3. 调整字体：Settings → Editor → Font，选带中文等宽支持的字体方案，避免代码注释里的中文变成方块。
常见坑不要为了"显得专业"上来就配 Maven 镜像、装十几款插件。初学阶段插件越多越容易互相干扰，一个干净的 IDEA + 一个正确的 JDK 就是最佳起点。

2.4 新建项目并跑通第一个类

用最小步骤验证整条工具链：New Project → src 下建类 → 点绿色三角运行。

步骤：File → New → Project，语言选 Java，构建系统选 IntelliJ（暂时不要选 Maven，第三篇再引入），JDK 选 17，项目名随意。然后在 src 目录右键 → New → Java Class，输入类名 Hello：

public class Hello {
    public static void main(String[] args) {
        System.out.println("环境就绪！");
    }
}
// 点击 main 左侧绿色三角 → Run，控制台输出：环境就绪！

这一行输出意味着整条链路都通了：IDEA 找到了 JDK → javac 把 .java 编译成 .class（在项目 out 目录里）→ JVM 执行字节码 → 输出回显到控制台。

两个值得现在就养成的小习惯：

  • 类名与文件名必须一致（Hello 必须住在 Hello.java 里），public 类更是强制；
  • 用 IDEA 底部的 Terminal 标签页敲一次 java -version——IDE 内置终端同样走环境变量，顺便再验证一次配置。

2.5 常见安装事故排查表

报错不可怕，可怕的是不知道从哪查。对照下表按序排查，90% 的环境问题都能就地解决。

症状原因与处理
java 不是内部或外部命令Path 没生效：确认配了 %JAVA_HOME%\bin，并重开终端再试
版本输出不对（如显示 1.8）多 JDK 冲突：Path 里旧目录优先级更高，删旧项或把新项上移
错误: 找不到或无法加载主类在错误目录执行了命令，或类名/文件名大小写不一致
中文乱码IDEA 编码三处未统一为 UTF-8（见 2.3 节）；Windows 老终端可先执行 chcp 65001
IDEA 提示 "Project JDK is not defined"Project Structure → SDK 未选择，或误选了 JRE 目录
Maven/Gradle 报 "JAVA_HOME is not set"JAVA_HOME 未配置或值写错（应指向 JDK 根目录，不是 bin 子目录）
装了 32 位 JDK 出现诡异崩溃统一换 64 位 JDK，别在位数上省事
环境问题排查三板斧：①java -version、javac -version、echo %JAVA_HOME% 三连问；②重开终端再验证一次；③打开 Path 逐条检查优先级。

2.6 进阶：多版本 JDK 共存

真实工作里常常"老项目要 Java 8，新项目要 17"。从现在起就养成"项目级指定 JDK"的习惯，别依赖全局默认。

  • IDEA 层面：每个项目在 Project Structure 里独立指定 SDK，互不影响——这是最常用的切换方式；
  • 命令行层面：Windows 可用 set JAVA_HOME=... 临时切换当前窗口；macOS/Linux 用 export JAVA_HOME=$(/usr/libexec/java_home -v 8)；
  • 版本管理工具：SDKMAN!（macOS/Linux）或 jenv 可以一条命令全局/局部切换，团队协作时配合 .sdkmanrc 固定版本。
# macOS/Linux 用 SDKMAN! 管理多版本
sdk list java                 # 查看可安装的所有发行版与版本
sdk install java 17.0.10-tem  # 安装 Temurin 17
sdk use java 8-tem            # 当前窗口切到 8（use 只影响当前会话）
sdk default java 17.0.10-tem  # 设置默认版本
常见坑不要试图把所有项目"统一升级到同一个 JDK"来解决冲突——老项目的依赖可能根本不支持新版本。正确的思路是"每个项目锁定自己的 JDK"，而不是"全局唯一"。

一个仪式感建议：装好环境后，把 java -version、javac -version、echo %JAVA_HOME% 三条命令的输出贴进你的学习笔记第一页。三周后遇到环境问题时，这就是你的"出厂快照"。

✎ 本章习题

A 基础在你机器上执行 java -version 与 echo %JAVA_HOME%（macOS 用 echo $JAVA_HOME），确认两条命令与变量三者版本一致。
B 进阶机器上若装了多个 JDK，调整 Path 中 %JAVA_HOME%\bin 的位置，观察命令行版本变化后再恢复——亲手制造并修复一次"多 JDK 冲突"。
C 挑战不依赖 IDEA，用记事本写 Hello.java，并在终端手动完成编译运行（具体命令第 3 章展开，试着先凭直觉走通）。

参考答案见附录 C（撰写中）。下一章把 main 方法逐词拆开，并离开 IDE 的保护伞，用命令行亲手走一遍 javac → java 的完整流程——那是你以后排障的底牌。
