3.1 main 方法逐词拆解

main 不是关键字，却是一个约定俗成的"大门牌"——JVM 只认这个签名的方法作为起点。

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
片段含义展开一句
public访问修饰符对一切开放——JVM 在类外面调它，必须 public（第 12 章细讲）
static静态的属于类而不属于对象——JVM 启动时还没有任何对象，只能调静态方法（第 11、17 章递进）
void返回类型不返回任何值。JVM 不需要它返回什么，进程退出码用别的方式表达
main方法名约定名。JVM 按名查找入口，写成 Main 就找不到
String[] args参数命令行参数数组。后面马上用到它
现在只需要"背下签名 + 知道它是 JVM 的入口"。其中 public 与 static 的完整原理分别在第 12、17 章，到时回看这张表会有完全不同的理解。

命令行参数怎么用？java Hello Tom 18 传进去的两个词会被装进 args：

public class Greet {
    public static void main(String[] args) {
        System.out.println("收到参数个数：" + args.length);
        System.out.println("第一个参数：" + args[0]);
    }
}
// 命令行：java Greet Tom 18
// 运行输出：
// 收到参数个数：2
// 第一个参数：Tom
// 若不带参数直接 java Greet，第二行会抛 ArrayIndexOutOfBoundsException——数组下标越界，第 8 章再见

3.2 命令行编译运行全流程

IDE 帮你做了三件事：找 javac、拼参数、跑 java。亲手做一遍，以后"IDEA 能跑、命令行不能跑"就不再是灵异事件。

新建一个纯目录（不放 src 里），写入 Hello.java，然后：

# 第 1 步：编译。在 Hello.java 所在目录执行
javac Hello.java
# 成功后目录里多出 Hello.class（字节码，给 JVM 看的，人看不懂很正常）

# 第 2 步：运行。注意：参数是【类名】，不是文件名！
java Hello
# 输出：Hello, Java!

# 顺带体验：让 JVM 输出它在执行字节码这件事
javap -c Hello    # 反汇编字节码，能看到 invokevirtual 等指令（现在只需围观）
  • javac 吃文件名（Hello.java），java 吃类名（Hello）——不带扩展名。混用是新手第一大报错来源；
  • java 命令去哪找 Hello.class？默认在当前目录找。换个目录运行就要用 classpath 参数（第 39 章类加载时再展开）；
  • 改了源码必须重新编译再运行——javac 不会自动跟踪变更，IDE 的"自动构建"替你做了这一步而已。

3.3 编译期错误 vs 运行期错误

报错的第一反应不该是"改"，而是先问一句：这是编译期报的还是运行期报的？

维度编译期错误运行期错误
报错者javacJVM（以 Exception/Error 形式抛出）
典型例子少分号、类名拼错、类型不匹配除以零、数组越界、空指针
程序跑了吗根本没跑，没有 .class跑了一半，在出错行中断
排查方式读编译器提示的行号与错误码读异常栈的第一行与第一行"属于你的代码"帧

看两个真实例子：

// 例 1：编译期错误——分号都没跑得上
int a = 10        // ← 缺分号
// javac 报：error: ';' expected

// 例 2：运行期错误——编译通过，跑到一半炸了
int a = 10;
int b = a / 0;    // javac 无话可说（语法完全合法）
// 运行报：Exception in thread "main" java.lang.ArithmeticException: / by zero
静态类型语言的福利：一大类错误（拼写、类型、漏写）被拦在编译期，代价是要学会读编译器的"话"。编译器提示永远是排查的第一手资料，比搜索引擎快。
常见坑读运行期异常栈别从下往上读——第一行是异常类型与原因，往下第一个属于你项目包名的 at 行才是出错位置，中间那些 JDK 内部帧（java.lang.*）先跳过。

3.4 程序入口的三要素

为什么 main 必须是 public、static、void？把三要素放回"JVM 启动时世界是什么样"的场景，答案自然浮现。

  • public：JVM 是类外部的调用者，非 public 它够不着（严格说某些 JVM 版本能调非 public，但规范要求 public，照做即可）；
  • static：JVM 启动时还没有任何对象。静态方法属于类本身，不需要"先 new 一个对象再调"；
  • 签名精确匹配：String[] args 可写成 String... args（可变参数，第 7 章），但参数类型错了 JVM 就找不到入口，报"main 方法不是 static"之类的运行期错误。
// 这些写法 JVM 都不认（试着运行会得到各种错误提示）
static void main(String[] args) { }              // 缺 public：入口不可见
public void main(String[] args) { }              // 缺 static：没有对象可调
public static int main(String[] args) { return 0; }  // 返回类型不对
public static void Main(String[] args) { }       // 大小写敏感：这不是 main
一个类可以没有 main（比如工具类），也可以多个类各有 main——运行时用 java 类名 指定从哪个入口启动。

3.5 围观字节码：class 文件里有什么

JDK 自带 javap 反汇编工具。现在围观一次，是为了让"编译成字节码"从口号变成眼见为实。

public class Add {
    public static void main(String[] args) {
        int sum = 3 + 5;
        System.out.println(sum);
    }
}
javac Add.java
javap -c Add
# 输出（节选）：
# public static void main(java.lang.String[]);
#   Code:
#      0: iconst_3          // 把常量 3 压入操作数栈
#      1: iconst_5          // 把常量 5 压入操作数栈
#      2: iadd              // 弹出两个数相加，结果压回栈
#      3: istore_1          // 存入局部变量 1（就是 sum）
#      4: getstatic     #7  // 取 System.out
#      7: iload_1           // 加载 sum
#      8: invokevirtual #13 // 调用 println
#     11: return

三个第一印象，现在记下即可：

  • 字节码指令很短（iconst、iadd、return），操作的是一个"操作数栈"——JVM 是一台栈式计算机；
  • 3 + 5 在编译期就被算成了 8（javac 的常量折叠优化），运行时根本不再加；
  • 调用方法对应 invokevirtual 等指令——第 14 章讲多态时，你会回来找 invokevirtual 与 invokestatic/invokeinterface 的区别，那是"动态分派"的字节码证据。
javap 是全书出场率最高的"显微镜"：多态分派（第 14 章）、字符串拼接优化（第 9 章）、泛型擦除（第 28 篇延伸）都靠它取证。把它加进你的工具箱。
