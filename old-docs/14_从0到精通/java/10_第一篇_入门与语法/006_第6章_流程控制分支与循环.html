6.1 if / else 与嵌套

分支的本质就是一句话：满足条件走这边，否则走那边。Java 的 if 后面跟的小括号里必须是布尔表达式（结果是 true 或 false），不能像某些语言里把 0 当假、非 0 当真。

基本形态

int score = 88;

if (score >= 60) {
    System.out.println("及格");
} else {
    System.out.println("不及格");
}

// 多分支用 else if 串联，谁先命中谁就结束整条链
if (score >= 90) {
    System.out.println("优秀");
} else if (score >= 75) {
    System.out.println("良好");
} else if (score >= 60) {
    System.out.println("及格");
} else {
    System.out.println("不及格");
}
  • 匹配规则：else 永远就近匹配它上面最近的那个还没配对的 if；
  • 单语句可省大括号，但强烈建议永远写 {}，否则"悬挂 else"和后续加行会坑死你自己；
  • 布尔不可缩写：if (a == 1) 不能写成 if (a)，这与 C/C++ 不同，是初学者转语言的高频错题。

嵌套分支与"卫语句"

分支里再套分支就是嵌套。嵌套别太深（超过三层就该重构），实战里常用"提前 return"的卫语句把嵌套拍平：

// 嵌套写法：读着累
if (age >= 18) {
    if (hasId) {
        System.out.println("放行");
    } else {
        System.out.println("请出示证件");
    }
}

// 卫语句：条件不满足立刻结束，主干更清晰
if (age < 18) {
    System.out.println("未成年禁止进入");
    return;
}
if (!hasId) {
    System.out.println("请出示证件");
    return;
}
System.out.println("放行");
常见坑把 == 写成 = 是经典事故：if (x = 5) 在 Java 里会编译报错（因为赋值结果是 int，不是 boolean），这点比 C 安全；但若是 if (b = true) 则合法且永远为真，务必警惕。

6.2 switch：分支的另一把刀

当判断的是同一个变量的多个离散值时，switch 比一长串 if / else if 更清爽，而且编译器有时能优化成查表，效率更高。

经典写法与"case 穿透"

int day = 3;
switch (day) {
    case 1:
        System.out.println("周一");
        break;
    case 2:
        System.out.println("周二");
        break;
    case 6:
    case 7:                 // 故意穿透：周六周日都走到这里
        System.out.println("周末");
        break;
    default:
        System.out.println("工作日");
}
  • case 穿透：某个 case 执行完后不会自动停止，会继续往下走，直到遇到 break。漏写 break 是最常见 bug；
  • default：都不匹配时的兜底，位置随意，习惯放最后；
  • switch 的表达式类型早期只支持 byte / short / char / int 及其包装类、enum、String（Java 7+）。

Java 12+ 箭头语法（推荐）

新版 switch 用 -> 替代冒号，箭头右边默认不穿透，且可写成表达式返回值，彻底消灭漏写 break 的隐患：

// 语句形式：箭头后单条语句不穿透
switch (day) {
    case 1 -> System.out.println("周一");
    case 2 -> System.out.println("周二");
    case 6, 7 -> System.out.println("周末");   // 多值合并，逗号分隔
    default  -> System.out.println("工作日");
}

// 表达式形式：直接赋值，必须覆盖所有情况（或用 default）
String name = switch (day) {
    case 1 -> "周一";
    case 2 -> "周二";
    case 6, 7 -> "周末";
    default -> "工作日";
};
结论一句话：老项目维护留意 break 穿透；新代码优先用 -> 箭头语法，更安全、更短、还能当表达式用。

6.3 for 与增强 for

标准 for：四件套

for (初始化; 条件; 步进) 最擅长"知道要跑多少遍"的场景，比如遍历下标：

// 打印 0 到 9
for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

// 倒序、跳步都行
for (int i = 100; i >= 1; i -= 2) {
    System.out.println(i);
}
  • 三个部分都可以省略，但分号不能省；for (;;) 是死循环写法之一；
  • 循环变量 i 的作用域只在 for 体内，出了循环就不可见（Java 比 C 更安全）。

增强 for（for-each）：遍历集合/数组专用

当你只关心"每个元素是什么"、不关心下标时，增强 for 更简洁也更不易出错：

int[] nums = {3, 1, 4, 1, 5, 9};
int sum = 0;
for (int n : nums) {      // 依次取出每个元素交给 n
    sum += n;
}
System.out.println(sum);

// 遍历字符串里的字符
for (char c : "hello".toCharArray()) {
    System.out.print(c + " ");
}
常见坑增强 for 拿不到下标，也不能在遍历时安全地删除/修改集合元素（会触发 ConcurrentModificationException）。需要下标或增删，请回到标准 for 或迭代器。

6.4 while 与 do-while

当循环次数"不确定、靠条件决定"时，用 while 比 for 更自然。

// while：先判条件，成立才进。可能一次都不执行
int n = 0;
while (n < 3) {
    System.out.println(n);
    n++;
}

// do-while：先执行一次，再判条件。至少执行一次
int m = 0;
do {
    System.out.println("我先做一次：" + m);
    m++;
} while (m < 3);
选哪个？不确定次数、且"可能一遍都不用跑"用 while；"至少要先做一遍再判断"（如菜单先显示再等输入）用 do-while。
  • 两者都要注意更新循环变量，否则条件永远成立就成了死循环；
  • 死循环的正统写法还有 while (true) { ... }，常在内部用 break 退出（见下节）。

6.5 break 与 continue

  • break：立刻终止当前整个循环，跳到循环后面的代码；
  • continue：跳过本次剩余语句，直接进入下一轮条件判断。
// break：找到第一个 7 的倍数就停
for (int i = 1; i <= 100; i++) {
    if (i % 7 == 0) {
        System.out.println("第一个 7 的倍数是 " + i);
        break;
    }
}

// continue：只打印奇数（偶数被跳过）
for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) {
        continue;
    }
    System.out.println(i);
}

带标签的 break：跳出多层循环

嵌套循环里，裸 break 只能跳出最内层。想一次跳出外层，得给外层循环贴个标签：

outer:                          // 标签名加冒号，贴在循环前
for (int i = 0; i < 5; i++) {
    for (int j = 0; j < 5; j++) {
        if (i == 2 && j == 2) {
            break outer;        // 直接跳出 outer 那一层，i、j 循环都结束
        }
        System.out.println(i + "," + j);
    }
}
// 标签 break 之后从这里继续往下走
常见坑标签只能贴在循环语句前（不能贴在 if 上），且 continue 标签 也能用——它会跳到标签所在循环的下一次迭代。滥用标签会让控制流难读，能靠布尔标志或抽方法解决时优先后者。

6.6 嵌套循环实战

嵌套循环就是"外层走一遍，内层走一圈"。最经典的练手是九九乘法表和找质数，两者都教会你"边界和下标怎么定"。

// 九九乘法表：i 控制行，j 控制列
for (int i = 1; i <= 9; i++) {
    for (int j = 1; j <= i; j++) {     // j <= i 保证上半三角，不重复
        System.out.print(j + "*" + i + "=" + (i * j) + "\t");
    }
    System.out.println();              // 一行结束换行
}

用 break 提前结束内层判断

判断质数时，只要发现一个能整除的因子就可以用 break 提前放弃，避免无谓循环：

for (int n = 2; n <= 50; n++) {
    boolean isPrime = true;
    for (int i = 2; i * i <= n; i++) {   // 只验到 sqrt(n)，效率更高
        if (n % i == 0) {
            isPrime = false;
            break;                       // 找到一个因子就说明不是质数
        }
    }
    if (isPrime) {
        System.out.print(n + " ");
    }
}
常见坑嵌套循环的边界最易错：i < 9 还是 i <= 9、"<"少跑一次还是多跑一次。写完后用最小例子（如 n=3）手算一遍，比凭感觉靠谱。
