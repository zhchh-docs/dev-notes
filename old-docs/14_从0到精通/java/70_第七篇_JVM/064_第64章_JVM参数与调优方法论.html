64.1 参数分类与读写法

一句话定位：-Xms512m 是标准参数（稳定），-Xmx2g 是 -X 类参数（HotSpot 约定），-XX:+UseG1GC 是 -XX 类（JVM 行为开关），稳定性依次降低。

  • 布尔型开关：-XX:+PrintFlagsFinal 打开，-XX:-UseCompressedOops 关闭；
  • 数值型：-XX:MaxGCPauseMillis=100；数字后缀 k/m/g 或不带单位；
  • 查看所有参数当前值：java -XX:+PrintFlagsFinal -version | findstr HeapSize；
  • 查看进程实际生效参数：jcmd <pid> VM.flags。
# 查看默认值与"产品级"参数（product 表示官方支持）
java -XX:+PrintFlagsFinal -version 2>&1 | findstr /i "MaxHeapSize UseG1GC"

# 运行中的进程改不了 -Xms，但部分诊断参数可以动态调
jinfo -flag +HeapDumpOnOutOfMemoryError <pid>
jinfo -flag HeapDumpPath=<pid> path=/dumps

64.2 必会的核心参数清单

参数典型值作用
-Xms / -Xmx相等，如 4g初始/最大堆，防扩容抖动
-XmnG1 下不设新生代大小（G1 自动调节更好）
-XX:MetaspaceSize256m触发元空间扩容的阈值，避免启动期反复 Full GC
-XX:MaxMetaspaceSize512m元空间上限，防类加载泄漏打爆本机内存
-XX:+UseG1GC—指定收集器（JDK 9+ 默认）
-XX:MaxGCPauseMillis100~200G1 停顿目标
-Xss默认 1m线程栈大小；深递归调大，海量线程调小
-Xlog:gc* / -XX:+PrintGCDetails—GC 日志（9+ / 8 写法）
-XX:+HeapDumpOnOutOfMemoryError必开OOM 时自动转储堆快照
-XX:HeapDumpPath/dumps快照落盘位置
-XX:MaxDirectMemorySize按需直接内存上限
-XX:+ExitOnOutOfMemoryErrorK8s 建议OOM 直接退出，让编排器重启

常见坑：容器环境（Docker/K8s）里老 JDK 8 会把容器限制当物理机读，堆默认过大被 cgroup 杀掉——JDK 8u191+ 务必显式设 -Xmx，或用 -XX:+UseContainerSupport（新版本默认开启）。

64.3 GC 日志怎么读

[2026-01-05T10:12:03.456+0800] GC(12) Pause Young (Normal)
    (G1 Evacuation Pause) 2048M->412M(4096M) 18.9ms

读法：GC(12)          第 12 次 GC
     Pause Young      年轻代回收（G1 的 Young GC）
     2048M->412M      回收前堆占用 → 回收后堆占用
     (4096M)          当前堆容量
     18.9ms           本次 STW 停顿

要盯的三个信号：
① 回收后堆占用持续走高（老年代在涨）→ 缓存/泄漏或缓存过大
② 频率：每分钟 > 10 次 Young GC → 新生代太小或流量分配问题
③ 出现 Pause Full → 兜底 Full GC 被触发，必须查原因

GCViewer、GCEasy（gceasy.io）等工具能把日志画成趋势图，比肉眼扫快得多。

64.4 调优方法论：五步循环

  1. 明确指标：和业务对齐——吞吐优先还是 P99 延迟优先？停顿预算多少？
  2. 采集基线：默认参数跑压测，记录 GC 频率/停顿/晋升速率/对象分配速率；
  3. 形成假设："Young GC 每 3 秒一次且 Survivor 频繁晋升 → 新生代偏小"；
  4. 一次只改一个参数，重新压测对比；
  5. 记录归档：改了什么、前后数据对比，写入运维手册——下次从别人的经验出发。
调优的优先级永远是：架构与代码 > 收集器选择 > 堆大小 > 细粒度参数。一个 O(n²) 的循环，比任何 GC 参数都能拖垮服务。
反模式清单：堆设成机器内存的 95%（没给堆外和 OS 留空间）；-Xms 与 -Xmx 不等导致频繁扩容；无日志裸奔调参；一次改五六个参数后归因失效。

64.5 一个完整的调参模板

# 4C8G 容器、G1、生产级起步模板
java \
  -Xms4g -Xmx4g \
  -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m \
  -XX:+UseG1GC -XX:MaxGCPauseMillis=150 \
  -Xss1m \
  -Xlog:gc*:file=/logs/gc-%t.log:time,uptime,level,tags:filecount=5,filesize=50m \
  -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/dumps \
  -XX:+ExitOnOutOfMemoryError \
  -Dfile.encoding=UTF-8 \
  -jar app.jar --spring.profiles.active=prod

# 记住这个比例感：机器 8G → 堆 4G（一半）→ 老年代约 2.7G
# 单机部署多进程时，各进程堆之和 ≤ 物理内存 × 0.6

✓ 本章小结

要点一句话
参数三层标准参数 > -X > -XX；jcmd VM.flags 看实际生效值
核心清单Xms=Xmx、Metaspace、G1+停顿目标、GC 日志、OOM 转储
日志三信号回收后水位走高、频率过密、出现 Full GC
调优循环定指标→基线→假设→单变量改→归档；代码 > 收集器 > 参数
容器陷阱老 JDK 8 显式设 Xmx；ExitOnOutOfMemoryError 配合 K8s
