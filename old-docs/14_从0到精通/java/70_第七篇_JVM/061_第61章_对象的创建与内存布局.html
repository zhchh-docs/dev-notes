61.1 new 一个对象的五步流水线

一句话定位：JVM 收到字节码 new 后依次做五件事——检查类、分配内存、清零、设置对象头、执行构造器。

步骤做什么关键点
1 类检查常量池定位类符号引用，检查是否已加载、解析、初始化没加载就先触发类加载（第 60 章）
2 分配内存在堆中划出对象大小的空间指针碰撞或空闲列表
3 初始化零值实例字段全部赋默认零值所以字段不赋值也有默认值
4 设置对象头哈希码、GC 分代年龄、锁标志、类型指针第 49 章锁升级就藏在这
5 执行构造器先父类构造器再子类，执行字段显式赋值与代码块此刻对象才"可用"
 
public class Person {
    private int age = 18;              // 步骤 3 先置 0，步骤 5 才变 18
    private String name;

    public Person(String name) {
        System.out.println("构造器里 age = " + age);  // 已经是 18
        this.name = name;
    }
    public static void main(String[] args) {
        Person p = new Person("张三");  // 对应 new + invokespecial <init>
    }
}

常见坑：new 字节码只完成"分配 + 清零 + 设头"，构造器由 invokespecial 单独触发。所以"new 出来的引用没执行构造器"是不存在的，但字段可见性时序问题（构造器中 this 逃逸）真实存在。

61.2 内存分配：指针碰撞与空闲列表

两种分配策略

  • 指针碰撞（Bump the Pointer）：堆规整（已用与未用各在一边），分配就是把分界指针挪一段。Serial、ParNew 这类带压缩的收集器使用；
  • 空闲列表（Free List）：堆不规整，JVM 维护一张"哪些块可用"的列表，找一块够大的分配。CMS 这种标记-清除式收集器使用。

并发竞争与 TLAB

堆是共享的，多个线程同时 new 会争抢同一块内存。JVM 用两层方案：

  1. 失败重试 + 锁：对分配动作同步（CAS 或加锁）；
  2. TLAB（Thread Local Allocation Buffer）：每个线程在 Eden 里预分一小块"自留地"，线程内分配不用同步——绝大多数对象在这里诞生，速度接近栈分配。
// 观察 TLAB 是否开启（默认开启）
// java -XX:+PrintFlagsFinal -version | findstr TLAB
//     bool UseTLAB                           = true
//TLAB 配额：-XX:TLABSize / 自动按线程动态调整
分配不是"去大堆里找地方"，而是"去自己 TLAB 里顺序拿"——这是 Java 对象分配快到可以和 C 媲美的核心原因。

61.3 对象的内存布局：头/数据/填充

图 61-1 对象在堆中的三段式布局

  • Mark Word（8 字节）：复用存储——无锁时是 hashCode/分代年龄；偏向锁时是线程 ID；轻量级锁是指向栈中锁记录的指针；重量级锁指向 monitor；
  • 类型指针：指向方法区中的类元数据，开启压缩指针（默认）占 4 字节；
  • 数组对象额外多 4 字节记录长度；
  • 对齐填充：HotSpot 要求对象起始地址是 8 字节整数倍。

61.4 对象的访问定位

栈上的 reference 如何找到堆里的对象？两种主流方案：

方案机制优缺点
句柄reference 指向句柄池，句柄再指向实例与类型数据GC 移动对象时只改句柄，reference 稳定；多一次转发开销
直接指针reference 直接指向对象，对象头里有类型指针少一次转发、更快（HotSpot 采用）；GC 移动对象要改引用

HotSpot 选择了直接指针，因为对象访问在 Java 里极其频繁，省一次寻址收益巨大。

61.5 实测对象大小：jol 工具

OpenJDK 的 Java Object Layout（jol）能把对象布局打印出来：

// Maven: org.openjdk.jol:jol-core:0.17
import org.openjdk.jol.info.ClassLayout;

public class SizeDemo {
    private int a;          // 4B
    private long b;         // 8B
    private Object o;       // 4B（压缩指针）

    public static void main(String[] args) {
        System.out.println(ClassLayout.parseClass(SizeDemo.class).toPrintable());
    }
}
// 输出要点：OFFSET  SIZE  TYPE DESCRIPTION
//   0  12        (object header)      Mark Word + 类型指针
//  12   4  long  SizeDemo.b
//  16   4   int  SizeDemo.a
//  20   4        (object alignment gap)   —— 补齐 8 的倍数
//  实例合计 24 字节

常见坑：字段顺序影响填充量——小字段排一起能省内存，这正是 @Contended / 缓存行对齐与字段重排优化的出发点。压缩指针在堆 > 32GB 时自动失效，引用变 8 字节，大堆应用要留意"内存反而变多"。

✓ 本章小结

要点一句话
创建五步类检查→分配→清零→设头→构造器；字节码 new 与 invokespecial 配合
分配策略规整堆用指针碰撞，零碎堆用空闲列表；TLAB 让分配无锁化
内存布局Header(12B) + Instance Data + 8B 对齐；空对象 16B
访问定位HotSpot 用直接指针；句柄方案以空间换 GC 灵活性
压缩指针4GB 内引用压到 4B；堆超 32GB 失效需权衡
