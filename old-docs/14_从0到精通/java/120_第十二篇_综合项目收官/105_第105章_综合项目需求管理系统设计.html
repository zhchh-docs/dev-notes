105.1 项目定位与业务背景

一句话定位：一个面向中小研发团队的内部需求管理系统——员工提交业务需求，审批人分级评审，项目经理跟踪落地状态，全程留痕、可统计。它不是办公 OA 的全量复刻，而是为了把本书主线知识点跑通而做的"教学级完整系统"。

105.1.1 为什么选这个题材

  • 业务闭环完整：包含登录鉴权、表单提交、状态流转、列表查询、通知推送、统计报表，覆盖典型 CRUD 与工作流场景；
  • 技术覆盖均衡：既能演示常规分层与事务，又能自然引入缓存（热门需求列表）、消息队列（审批通知、超时提醒）与压测（查询接口优化）；
  • 边界清晰可控：不引入复杂的前端工程与第三方商业服务，后端为主、前端为已有技术栈调用，适合全栈学习者聚焦主线；
  • 与前序章节呼应：登录鉴权呼应 Spring Security 与 JWT 章节，状态机呼应枚举与状态模式，缓存与消息队列是第 108、109 章的落地载体。

105.1.2 核心业务流程

  1. 员工在系统内填写标题、描述、优先级、期望完成时间，提交需求；
  2. 系统记录草稿，进入"待审批"状态，通知直属审批人；
  3. 审批人同意 → 流转为"已立项"；驳回 → 回到提交人修改；退回后可再次提交；
  4. 项目经理更新开发进度（进行中 / 已完成 / 已关闭），全程生成审批记录与操作日志；
  5. 管理员维护账号、角色与字典（优先级、状态枚举）。
项目主线从 105 章到 110 章，我们围绕这一套需求持续迭代：106 章写后端接口，107 章前后端联调，108 章接缓存，109 章接消息队列，110 章压测调优——每一章都能在这套系统上看到改动前后的对比。

105.2.1 状态枚举先定义

需求状态是贯穿全项目的核心枚举，越早固定越好，避免后期到处改字符串判断：

  • DRAFT 草稿：刚创建尚未提交；
  • PENDING 待审批：已提交，等待审批人处理；
  • APPROVED 已立项：审批通过，等待排期开发；
  • REJECTED 已驳回：审批未通过，可修改后重新提交；
  • IN_PROGRESS 进行中：开发落地中；
  • CLOSED 已关闭：完成或终止，不再变更。
设计提醒状态之间的合法流转必须显式定义（例如 APPROVED 才能进入 IN_PROGRESS，CLOSED 为终态不可回退），不要让前端随意传一个状态字符串覆盖数据库——106 章的状态机会把这层约束落到代码里。

105.3 技术选型与版本基线

选型原则：成熟主流、与本书前序章节一致、本地可跑通；不为了"看起来高级"引入团队不熟悉的框架。基线版本：JDK 17、Spring Boot 3.x。

缓存Redis7.x会话与热点数据缓存，第 108 章专门接入

105.4 数据库设计与 ER 关系

核心三张业务表：sys_user（用户）、requirement（需求）、approval_record（审批记录）；另加一张 operation_log（操作日志）承接后续留痕需求。

图 105-1 核心表 ER 关系

-- 用户表：角色用枚举字符串简化，RBAC 关联表留待后台管理模块
CREATE TABLE sys_user (
    id            BIGINT       PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
    username      VARCHAR(32)  NOT NULL UNIQUE COMMENT '登录名',
    password      VARCHAR(100) NOT NULL COMMENT 'BCrypt 加密后的口令',
    real_name     VARCHAR(32)  NOT NULL COMMENT '真实姓名',
    role          VARCHAR(16)  NOT NULL DEFAULT 'EMPLOYEE' COMMENT 'EMPLOYEE / APPROVER / MANAGER / ADMIN',
    department    VARCHAR(32)  COMMENT '所属部门',
    status        TINYINT      NOT NULL DEFAULT 1 COMMENT '1 启用 0 停用',
    create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) COMMENT '用户表';

-- 需求表：status 存放 105.2 定义的状态枚举，priority 为 P0/P1/P2
CREATE TABLE requirement (
    id            BIGINT       PRIMARY KEY AUTO_INCREMENT COMMENT '需求ID',
    title         VARCHAR(120) NOT NULL COMMENT '标题',
    description   TEXT         COMMENT '详细描述',
    status        VARCHAR(16)  NOT NULL DEFAULT 'DRAFT' COMMENT '状态枚举',
    priority      VARCHAR(8)   NOT NULL DEFAULT 'P1' COMMENT 'P0/P1/P2',
    creator_id    BIGINT       NOT NULL COMMENT '提交人ID',
    approver_id   BIGINT       COMMENT '当前审批人ID',
    expect_date   DATE         COMMENT '期望完成日期',
    view_count    INT          NOT NULL DEFAULT 0 COMMENT '浏览量（热门排序用）',
    create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_creator (creator_id),
    INDEX idx_status   (status),
    INDEX idx_priority (priority)
) COMMENT '需求表';

-- 审批记录表：一次审批动作落一行，历史可追溯
CREATE TABLE approval_record (
    id              BIGINT      PRIMARY KEY AUTO_INCREMENT,
    requirement_id  BIGINT      NOT NULL COMMENT '需求ID',
    approver_id     BIGINT      NOT NULL COMMENT '审批人ID',
    action          VARCHAR(16) NOT NULL COMMENT 'APPROVE / REJECT / RETURN',
    comment         VARCHAR(500) COMMENT '审批意见',
    create_time     DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_requirement (requirement_id)
) COMMENT '审批记录表';

-- 操作日志表：谁在什么时间改了哪条需求，供后台审计查询
CREATE TABLE operation_log (
    id            BIGINT       PRIMARY KEY AUTO_INCREMENT,
    operator_id   BIGINT       NOT NULL,
    target_type   VARCHAR(16)  NOT NULL COMMENT 'REQUIREMENT / APPROVAL',
    target_id     BIGINT       NOT NULL,
    action        VARCHAR(32)  NOT NULL,
    detail        TEXT,
    create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_target (target_type, target_id)
) COMMENT '操作日志表';
设计点取舍说明后续影响
状态字段存枚举字符串可读性优于数字编码，配合 MyBatis-Plus 枚举处理器106 章状态机以枚举判断合法流转
approval_record 只追加不更新审批历史是审计证据，不做物理删除与覆盖查询历史时按 requirement_id 倒序分页
冗余 view_count热门列表高频读，避免每次 count 关联表108 章缓存此列表，注意计数与缓存一致性
不建角色权限中间表教学项目角色固定四种，先在 user.role 单字段落地112 章扩展为微服务时再演进 RBAC 表结构
统一 create_time / update_time每张业务表必备，排障与对账有据可查MyBatis-Plus 自动填充处理器统一维护

105.5 分层架构与目录结构

延续本书 Spring 章节确立的经典分层：controller 接请求、service 写业务、mapper 碰数据库；entity 映射表、dto 收参数、vo 返前端，三类对象各司其职，106 章展开讲清边界。

图 105-2 经典三层 + 基础设施横切

req-manage-system/
├── src/main/java/com/example/reqmanage/
│   ├── ReqManageApplication.java        # 启动类
│   ├── common/                          # 通用层：统一响应、异常、常量、工具
│   │   ├── result/R.java
│   │   ├── exception/BizException.java
│   │   └── handler/GlobalExceptionHandler.java
│   ├── config/                           # Web/Security/Redis/MQ 配置类
│   ├── controller/                       # 入口层：UserController、RequirementController、ApprovalController
│   ├── service/                         # 业务层：接口 + impl 实现
│   │   └── impl/
│   ├── mapper/                           # MyBatis-Plus Mapper 接口
│   ├── entity/                           # 数据库实体（表映射）
│   ├── dto/                              # 入参对象：LoginDTO、RequirementCreateDTO
│   ├── vo/                               # 出参对象：UserVO、RequirementVO
│   ├── enums/                            # 状态枚举、角色枚举、错误码
│   └── security/                         # JWT 过滤器、登录用户上下文
├── src/main/resources/
│   ├── application.yml                   # 主配置（数据源、Redis、MQ）
│   └── application-dev.yml               # 开发环境覆盖
└── pom.xml

分层原则一句话：controller 不写业务判断，service 不直接返回数据库实体，mapper 不出现业务词汇。层与层之间只传 DTO / VO，不把 entity 泄露到前端。

先把接口清单定下来，前后端按清单并行开发；统一前缀 /api，统一 JSON 响应体，错误码按模块分段（1xxxx 鉴权、2xxxx 需求、3xxxx 审批）。

105.7 开发计划与里程碑

本篇七章对应七个里程碑，每章结束都应得到一个可运行、可演示的增量版本；不提前实现后续章节才引入的缓存、MQ 代码。

章节里程碑内容产出物验收标准
105需求拆解、选型、库表设计、架构与接口清单设计文档、SQL 脚本、接口表清单可指导后端开工，库表可建库执行
106项目骨架、登录鉴权、需求 CRUD、审批状态机、统一异常可登录的后端单体应用Postman 跑通登录与审批全流程
107跨域配置、开发代理、接口文档与前后端字段对齐可与前端工程联调的后端浏览器跨域请求不被拦截，文档字段一致
108Redis 接入、热门列表缓存、一致性与三大问题防护带缓存的查询接口缓存命中率可观测，穿透/击穿/雪崩有应对
109RabbitMQ 接入，审批结果异步通知、消费幂等异步消息链路重复投递不产生重复通知，消息可重投
110JMeter 压测、瓶颈定位、调优与复测对比压测报告与调优记录核心接口 TP99 与错误率达到约定指标

工程习惯每个里程碑结束打一个 Git 标签（如 v0.1-backend-ready），缓存、MQ、调优各成一次可回滚的提交——出问题时能干净地回到上一个可用状态。
