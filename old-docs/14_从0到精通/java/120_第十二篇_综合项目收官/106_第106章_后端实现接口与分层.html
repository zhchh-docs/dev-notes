结构原则包结构反映业务边界而不是技术层级的简单复制：先按 controller/service/mapper 分层，再在每一层内按业务模块分文件；业务复杂后可进一步演进为按模块分包（每个模块内部自带 controller/service/entity）。

106.2 分层职责与对象分类

分层不是形式主义的目录切分，而是让变化各归其位：HTTP 协议细节留在 controller，业务规则留在 service，SQL 细节留在 mapper。

层职责不允许做的事
Controller接收请求、校验入参、鉴权上下文取值、调用 service、组装 VO、返回 R写业务判断、直接操作 Mapper、拼装 SQL 条件
Service 接口声明业务能力与事务语义，供 controller 与其他 service 依赖注入 Mapper 之外的 Web 对象
Service 实现业务规则、状态流转、事务边界、组合多个 Mapper、调用基础设施处理 HttpServletRequest 细节、返回 entity 给上层
Mapper数据库读写、条件构造、关联查询，方法名表达数据语义出现审批、通知等业务动词与分支判断

106.2.1 entity / dto / vo 为什么必须分开

对象用途字段特征流向
entity与数据库表映射，MyBatis-Plus 操作的载体含自增主键、create_time、update_time 等表字段mapper ↔ service，不越出后端
dto接收前端入参，承载校验注解只含表单需要的字段，可按接口拆分多个前端 → controller → service
vo返回前端的视图模型可关联展示字段（如提交人姓名），剔除敏感字段（password）service → controller → 前端

106.3 统一响应与全局异常

前端最恨的不是报错，而是每次报错格式都不一样：有时返回 HTML 错误页，有时字段名变了。统一 R<T> 与 @RestControllerAdvice 把所有出口收拢成一种格式（第 91 章异常体系的落地）。

// common/result/R.java —— 统一响应体
public class R<T> {
    private int code;          // 0 成功；非 0 为业务错误码
    private String message;
    private T data;

    public static <T> R<T> ok(T data) {
        R<T> r = new R<>();
        r.code = 0; r.message = "success"; r.data = data;
        return r;
    }
    public static <T> R<T> fail(ErrorCode ec) {
        R<T> r = new R<>();
        r.code = ec.getCode(); r.message = ec.getMessage();
        return r;
    }
    // getter / setter 省略
}

// common/exception/ErrorCode.java —— 错误码分段：1xxxx 鉴权，2xxxx 需求，3xxxx 审批
public enum ErrorCode {
    USERNAME_OR_PASSWORD_WRONG(10001, "用户名或密码错误"),
    TOKEN_INVALID(10002, "登录已过期，请重新登录"),
    REQUIREMENT_NOT_FOUND(20001, "需求不存在"),
    REQUIREMENT_NOT_EDITABLE(20002, "当前状态不可编辑"),
    STATUS_TRANSITION_ILLEGAL(30001, "状态流转不合法"),
    NO_PERMISSION(30002, "无操作权限");

    private final int code;
    private final String message;
    ErrorCode(int code, String message) { this.code = code; this.message = message; }
    public int getCode() { return code; }
    public String getMessage() { return message; }
}

// common/exception/BizException.java —— 业务异常携带错误码
public class BizException extends RuntimeException {
    private final ErrorCode errorCode;
    public BizException(ErrorCode ec) { super(ec.getMessage()); this.errorCode = ec; }
    public ErrorCode getErrorCode() { return errorCode; }
}
// common/handler/GlobalExceptionHandler.java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 业务异常：按错误码返回 R.fail，HTTP 状态码仍为 200，由前端按 code 判断
    @ExceptionHandler(BizException.class)
    public R<Void> handleBiz(BizException e) {
        return R.fail(e.getErrorCode());
    }

    // 参数校验异常（@Valid 失败）：提取第一条字段错误信息
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + " " + f.getDefaultMessage())
                .findFirst().orElse("参数校验失败");
        R<Void> r = R.fail(ErrorCode.PARAM_INVALID);
        // 覆盖 message 为具体字段提示
        return r;
    }

    // 兜底异常：不把堆栈暴露给前端，记录日志后返回系统错误
    @ExceptionHandler(Exception.class)
    public R<Void> handleOther(Exception e) {
        log.error("未处理异常", e);
        return R.fail(ErrorCode.SYSTEM_ERROR);
    }
}
设计提醒教学项目里业务失败也返回 HTTP 200、靠 code 区分；正式项目可对鉴权失败返回 401、权限不足返回 403。无论选哪种，前端必须只认一种约定，不要一半接口用状态码、一半用 code。

106.4 登录接口与 JWT 签发

登录链路：校验账号口令（BCrypt 比对）→ 生成 JWT（用户 id、角色、过期时间）→ 返回 token 与用户视图；后续请求由过滤器解析令牌、把当前用户放进上下文。

// dto/LoginDTO.java —— 入参带 Bean Validation 注解
public class LoginDTO {
    @NotBlank(message = "登录名不能为空")
    private String username;
    @NotBlank(message = "口令不能为空")
    private String password;
    // getter / setter 省略
}

// vo/LoginVO.java
public class LoginVO {
    private String token;
    private UserVO user;
    // getter / setter 省略
}

// controller/AuthController.java
@RestController
@RequestMapping("/api/auth")
public class AuthController {
    private final AuthService authService;
    public AuthController(AuthService authService) { this.authService = authService; }

    @PostMapping("/login")
    public R<LoginVO> login(@Valid @RequestBody LoginDTO dto) {
        return R.ok(authService.login(dto));
    }

    @PostMapping("/logout")
    public R<Void> logout() {
        authService.logout();
        return R.ok(null);
    }
}
// service/impl/AuthServiceImpl.java
@Service
public class AuthServiceImpl implements AuthService {
    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;
    private final JwtTokenProvider tokenProvider;

    public AuthServiceImpl(UserMapper userMapper,
                           PasswordEncoder passwordEncoder,
                           JwtTokenProvider tokenProvider) {
        this.userMapper = userMapper;
        this.passwordEncoder = passwordEncoder;
        this.tokenProvider = tokenProvider;
    }

    @Override
    public LoginVO login(LoginDTO dto) {
        SysUser user = userMapper.selectByUsername(dto.getUsername());
        if (user == null
                || !passwordEncoder.matches(dto.getPassword(), user.getPassword())) {
            throw new BizException(ErrorCode.USERNAME_OR_PASSWORD_WRONG);
        }
        if (user.getStatus() == 0) {
            throw new BizException(ErrorCode.USER_DISABLED);
        }
        String token = tokenProvider.generate(user.getId(), user.getRole());
        LoginVO vo = new LoginVO();
        vo.setToken(token);
        vo.setUser(UserVO.from(user));
        return vo;
    }

    @Override
    public void logout() {
        // 教学版：无状态 JWT 不做服务端会话；演示中可把 token 加入 Redis 黑名单
    }
}

JWT 工具类只负责三件事：生成令牌（签名 + 过期时间）、解析令牌（验签 + 取声明）、校验有效期；密码使用 BCryptPasswordEncoder 单向散列，数据库不存明文。

106.5 需求 CRUD 实现

以"新建需求"和"分页列表"为例：controller 只做参数接收与 VO 组装，service 完成归属判断与状态初始化，mapper 借助 MyBatis-Plus 条件构造器完成查询。

// dto/RequirementCreateDTO.java
public class RequirementCreateDTO {
    @NotBlank(message = "标题不能为空")
    @Size(max = 120, message = "标题最长 120 字")
    private String title;
    private String description;
    private String priority;          // P0 / P1 / P2
    private LocalDate expectDate;
    // getter / setter 省略
}

// controller/RequirementController.java
@RestController
@RequestMapping("/api/requirements")
public class RequirementController {
    private final RequirementService requirementService;
    public RequirementController(RequirementService s) { this.requirementService = s; }

    @PostMapping
    public R<Long> create(@Valid @RequestBody RequirementCreateDTO dto) {
        Long id = requirementService.create(dto, CurrentUser.getUserId());
        return R.ok(id);
    }

    @GetMapping
    public R<PageResult<RequirementVO>> page(RequirementQueryDTO query) {
        return R.ok(requirementService.page(query));
    }

    @GetMapping("/{id}")
    public R<RequirementVO> detail(@PathVariable Long id) {
        return R.ok(requirementService.detail(id));
    }

    @PostMapping("/{id}/submit")
    public R<Void> submit(@PathVariable Long id) {
        requirementService.submit(id, CurrentUser.getUserId());
        return R.ok(null);
    }
}
// service/impl/RequirementServiceImpl.java（节选）
@Service
public class RequirementServiceImpl implements RequirementService {
    private final RequirementMapper requirementMapper;
    private final ApprovalRecordMapper recordMapper;

    public RequirementServiceImpl(RequirementMapper m, ApprovalRecordMapper r) {
        this.requirementMapper = m; this.recordMapper = r;
    }

    @Override
    public Long create(RequirementCreateDTO dto, Long userId) {
        Requirement entity = new Requirement();
        entity.setTitle(dto.getTitle());
        entity.setDescription(dto.getDescription());
        entity.setPriority(dto.getPriority() == null ? "P1" : dto.getPriority());
        entity.setExpectDate(dto.getExpectDate());
        entity.setCreatorId(userId);
        entity.setStatus(RequirementStatus.DRAFT.name());   // 新建即草稿
        requirementMapper.insert(entity);
        return entity.getId();
    }

    @Override
    public void submit(Long id, Long userId) {
        Requirement req = requireById(id);
        if (!req.getCreatorId().equals(userId)) {
            throw new BizException(ErrorCode.NO_PERMISSION);
        }
        // 仅草稿可提交，否则由状态机抛流转非法（见 106.6）
        RequirementStatus.from(req.getStatus())
                .transition(RequirementStatus.PENDING);
        req.setStatus(RequirementStatus.PENDING.name());
        requirementMapper.updateById(req);
    }

    private Requirement requireById(Long id) {
        Requirement req = requirementMapper.selectById(id);
        if (req == null) throw new BizException(ErrorCode.REQUIREMENT_NOT_FOUND);
        return req;
    }
}

分页列表使用 MyBatis-Plus 的 Page 对象与条件构造器：状态、优先级为精确匹配，标题为模糊匹配，按创建时间倒序；返回 PageResult 携带当前页、总条数与记录列表。

106.6 审批流转状态机

状态机的核心是一张合法流转表：当前状态 → 允许到达的下一状态。代码里用枚举内置这张表，任何流转先查表再落库，杜绝前端传什么状态就写什么状态。

当前状态允许流转到触发动作 / 操作者
DRAFT 草稿PENDING 待审批；（删除草稿）提交人本人
PENDING 待审批APPROVED 已立项；REJECTED 已驳回审批人
REJECTED 已驳回PENDING 待审批；DRAFT（放弃）提交人本人修改后重提
APPROVED 已立项IN_PROGRESS 进行中；CLOSED 已关闭项目经理
IN_PROGRESS 进行中CLOSED 已关闭项目经理
CLOSED 已关闭终态，不可流转—
 
// enums/RequirementStatus.java
public enum RequirementStatus {
    DRAFT, PENDING, APPROVED, REJECTED, IN_PROGRESS, CLOSED;

    private static final Map<RequirementStatus, Set<RequirementStatus>> NEXT = Map.of(
        DRAFT,       EnumSet.of(PENDING),
        PENDING,     EnumSet.of(APPROVED, REJECTED),
        REJECTED,    EnumSet.of(PENDING, DRAFT),
        APPROVED,    EnumSet.of(IN_PROGRESS, CLOSED),
        IN_PROGRESS, EnumSet.of(CLOSED),
        CLOSED,      EnumSet.noneOf(RequirementStatus.class)
    );

    public static RequirementStatus from(String code) {
        return RequirementStatus.valueOf(code);
    }

    public void transition(RequirementStatus target) {
        if (!NEXT.get(this).contains(target)) {
            throw new BizException(ErrorCode.STATUS_TRANSITION_ILLEGAL);
        }
    }
}
// service/impl/ApprovalServiceImpl.java（审批动作，事务见 106.7）
@Service
public class ApprovalServiceImpl implements ApprovalService {
    private final RequirementMapper requirementMapper;
    private final ApprovalRecordMapper recordMapper;

    public ApprovalServiceImpl(RequirementMapper r, ApprovalRecordMapper a) {
        this.requirementMapper = r; this.recordMapper = a;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void approve(Long requirementId, Long approverId, String comment) {
        Requirement req = requirementMapper.selectById(requirementId);
        if (req == null) throw new BizException(ErrorCode.REQUIREMENT_NOT_FOUND);

        RequirementStatus current = RequirementStatus.from(req.getStatus());
        current.transition(RequirementStatus.APPROVED);   // 先校验合法流转

        req.setStatus(RequirementStatus.APPROVED.name());
        requirementMapper.updateById(req);

        ApprovalRecord record = new ApprovalRecord();
        record.setRequirementId(requirementId);
        record.setApproverId(approverId);
        record.setAction("APPROVE");
        record.setComment(comment);
        recordMapper.insert(record);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void reject(Long requirementId, Long approverId, String comment) {
        // 与 approve 对称：状态置为 REJECTED，追加一条 REJECT 记录
        Requirement req = requirementMapper.selectById(requirementId);
        if (req == null) throw new BizException(ErrorCode.REQUIREMENT_NOT_FOUND);
        RequirementStatus.from(req.getStatus())
                .transition(RequirementStatus.REJECTED);
        req.setStatus(RequirementStatus.REJECTED.name());
        requirementMapper.updateById(req);

        ApprovalRecord record = new ApprovalRecord();
        record.setRequirementId(requirementId);
        record.setApproverId(approverId);
        record.setAction("REJECT");
        record.setComment(comment);
        recordMapper.insert(record);
    }
}
状态机价值流转合法性收敛在一处：以后新增"撤回"动作，只改枚举表与对应 service 方法，不会在十几个接口里散落字符串判断。

106.7 事务边界与常见坑

审批动作同时改需求状态、写审批记录，必须在一个事务里：状态改了但记录没落库，就会出现"系统显示通过、历史里查不到审批人"的脏数据。

106.7.1 事务注解放哪里

  • 放在 service 实现类的公开方法上（或接口方法上），一个方法 = 一个事务边界；controller 层不加事务——请求级别事务粒度过粗，会把只读查询也裹进事务；
  • @Transactional(rollbackFor = Exception.class) 显式指定回滚异常，因为默认只对 RuntimeException 与 Error 回滚；受检异常不回滚是新代码最常踩的坑；
  • 事务内不要混入 RPC、消息发送、长耗时循环：一旦事务边界过大，数据库连接被占住，并发上来先打满连接池。

106.7.2 本项目高频坑清单

坑一：DTO 与实体混用图省事把 Requirement 实体直接作为 @RequestBody 入参：前端能伪造 id、createTime、status 等字段绕过校验。入参一律用 DTO，字段由 service 显式拷贝。
坑二：把 entity 直接返回前端实体含 password、updateTime 等内部字段，直接返回会泄露敏感信息并把表结构暴露给前端；出参一律转 VO，在 VO 上用静态工厂方法 UserVO.from(entity) 做映射。
坑三：事务粒度过粗把一个 @Transactional 方法写成"先查列表、再循环逐条改、最后发通知"，单条失败回滚整批；正确做法是按业务单元拆方法，批量场景用分批事务并记录失败明细。
自检口诀事务只包"必须同生共死"的一组写操作；查询、远程调用、发消息都放到事务之外——109 章接入消息队列时，异步通知要在事务提交之后再发。

✓ 本章小结

要点一句话
骨架分层controller 接请求、service 写规则、mapper 碰数据库；entity/dto/vo 三类对象分开
统一出口R<T> 统一响应 + @RestControllerAdvice 兜底，错误码分段管理，前端只认一套格式
登录鉴权BCrypt 比对口令，JWT 携带用户 id 与角色，过滤器解析后写入登录上下文
状态机枚举内置合法流转表，先查表再落库；终态不可回退，流转规则收敛在一处
事务纪律事务放 service 写方法、rollbackFor 指定异常；不裹查询与远程调用，DTO/entity/vo 不混用
