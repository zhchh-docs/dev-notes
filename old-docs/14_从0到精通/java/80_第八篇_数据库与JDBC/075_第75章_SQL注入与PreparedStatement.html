75.1 注入如何发生：可复现演示

一句话定位：字符串拼接让"用户输入的值"变成"SQL 的语法"——引号闭合、注释符截断，攻击者就能改写语义。

// 危险写法：拼接（仅用于教学，严禁出现在真实代码）
public boolean loginBuggy(Connection conn, String user, String pass)
        throws SQLException {
    String sql = "SELECT * FROM account WHERE username = '" + user
               + "' AND password = '" + pass + "'";   // ← 灾难现场
    try (Statement st = conn.createStatement();
         ResultSet rs = st.executeQuery(sql)) {
        return rs.next();
    }
}
// 正常调用：loginBuggy(conn, "alice", "123456")
//   生成：SELECT * FROM account WHERE username='alice' AND password='123456'

// 攻击调用：loginBuggy(conn, "alice", "' OR '1'='1")
//   生成：SELECT * FROM account WHERE username='alice'
//         AND password='' OR '1'='1'      ← 恒真，密码校验失效！
// 更狠的：pass = "'; DROP TABLE account; --"（配合 allowMultiQueries）
危害不止绕登录：拖库（UNION 全表导出）、删表、提权。OWASP 十大漏洞常年榜首，法律后果严重——攻击生产系统是刑事犯罪，本章所有演示只在自建测试库进行。

75.2 根治：PreparedStatement 原理

// 安全写法：参数化——SQL 结构与数据彻底分离
public boolean login(Connection conn, String user, String pass)
        throws SQLException {
    String sql = "SELECT * FROM account WHERE username = ? AND password = ?";
    try (PreparedStatement ps = conn.prepareStatement(sql)) {
        ps.setString(1, user);      // 无论内容是什么，都只是"一个字符串值"
        ps.setString(2, pass);
        try (ResultSet rs = ps.executeQuery()) {
            return rs.next();
        }
    }
}
// 同样的恶意输入 "' OR '1'='1" 会被当成字面密码去比对 → 查不到 → 拒绝

为什么有效：PreparedStatement 先发送带占位符的 SQL 模板给数据库预编译，语法树已定；参数随后单独传输并填充到"值"的位置。数据永远进不了语法树，引号、注释符都只是字符。

两附赠收益：① 预编译语句可被数据库缓存复用，同结构反复执行更快；② 类型由 setXxx 显式约束，顺带挡掉一批类型混淆错误。

注意：加了 PreparedStatement 但仍拼接进 SQL 模板（如 "... WHERE id IN (" + ids + ")"）等于白防。原则：占位符数量可以是动态的，占位符内容必须永远是值。

75.3 参数化盲区：动态表名与 ORDER BY

有些位置不能放 ?：表名、列名、排序方向是语法结构不是值。处理原则：白名单校验，绝不透传。

// 场景 1：动态排序字段——白名单映射
private static final Set<String> SORTABLE = Set.of("id", "name", "created_at");

public List<User> list(String sortField, boolean asc) throws SQLException {
    if (!SORTABLE.contains(sortField))
        throw new IllegalArgumentException("非法排序字段: " + sortField);
    String order = asc ? "ASC" : "DESC";                  // 二选一，非用户原文
    String sql = "SELECT id, name FROM user ORDER BY " + sortField + " " + order;
    // sortField 经白名单，order 是常量——拼接重新安全
    ...
}

// 场景 2：IN 列表——占位符数量动态生成
String placeholders = ids.stream().map(x -> "?").collect(joining(","));
String sql = "SELECT * FROM user WHERE id IN (" + placeholders + ")";
// 拼进 SQL 的只有 '?'，真正的值逐个 setLong——安全

// 场景 3：LIKE 模糊查询——通配符是值的一部分，照常参数化
ps.setString(1, "%" + escapeLike(keyword) + "%");   // 转义 % _ \ 语义歧义

75.4 纵深防御清单

  1. 参数化优先：所有值全部走 PreparedStatement/MyBatis #{}；
  2. 白名单兜底：表名、列名、排序方向用枚举/集合校验；
  3. 最小权限：应用账号只给增删改查，不给 DDL/DROP（第 69 章的 app 账号）；
  4. 错误信息克制：数据库报错原样返回会泄露表结构与 SQL，统一转通用错误（第 91 章）；
  5. 审计与告警：静态扫描（SpotBugs/自定义规则）拦拼接 SQL；WAF 作为外层缓冲；
  6. 不信任任何输入：包括内部接口、请求头、文件内容。

75.5 审查：找出项目里的注入点

# 快速扫描疑似拼接点（团队 code review 前置筛查）
grep -rn "createStatement" --include="*.java" src/ | grep -v test
grep -rn "Statement stmt" --include="*.java" src/
grep -rnE "\+ *(request|param|keyword|name|id)[^;]*\+" --include="*.java" src/

# MyBatis 项目重点查：${} 是字符串替换（注入！），#{} 才是参数化
grep -rn '\${' --include="*.xml" src/main/resources/
发现处置
createStatement + 拼接改 PreparedStatement；确需动态结构则白名单
MyBatis ${orderBy}改白名单映射或 @Param + case when；校验后仍建议白名单
动态表名来自用户重新设计：不应该存在——用枚举路由到固定的多张表查询方法

✓ 本章小结

要点一句话
注入本质数据被解释成代码；引号与注释符改变 SQL 语义
根治手段预编译：语法树先行，参数只填值位
盲区处理表名/列名/排序用白名单；IN 用动态占位符
纵深防御参数化 + 白名单 + 最小权限 + 克制报错 + 扫描
