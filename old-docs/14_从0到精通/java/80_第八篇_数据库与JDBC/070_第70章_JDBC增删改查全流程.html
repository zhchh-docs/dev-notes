70.1 JDBC 四大核心对象

对象职责生命周期
DriverManager管理驱动、创建连接JVM 级
Connection与数据库的一条会话（含事务上下文）昂贵！应复用（连接池）
Statement/PreparedStatement承载 SQL 与参数、执行随语句创建销毁
ResultSet查询结果的游标随语句关闭而失效

建连是重操作（TCP 握手 + 认证 + 会话初始化），单次几毫秒到几十毫秒——所以下一章要讲连接池。本章先用 DriverManager 原生方式把流程学透。

70.2 查询：executeQuery 与结果集遍历

import java.sql.*;
import java.util.ArrayList;
import java.util.List;

public class UserQuery {
    public static List<String> findByName(String keyword) throws SQLException {
        String url = "jdbc:mysql://localhost:3306/jdbc_demo?serverTimezone=Asia/Shanghai";
        List<String> names = new ArrayList<>();
        String sql = "SELECT id, name, email FROM user WHERE name LIKE ?";

        try (Connection conn = DriverManager.getConnection(url, "app", "App#123456");
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, "%" + keyword + "%");        // 参数从 1 开始
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {                       // 游标先前进再读
                    long id = rs.getLong("id");
                    String name = rs.getString("name");
                    String email = rs.getString("email");
                    names.add(id + " / " + name + " / " + email);
                }
            }
        }
        return names;
    }
    public static void main(String[] args) throws SQLException {
        findByName("张").forEach(System.out::println);
    }
}
  • ? 占位符 + setXxx(index, value)：参数下标从 1 开始，不是 0；
  • rs.next()：游标初始指向第一行之前，必须先 next 再读；
  • 读字段建议用列名（getString("name")）而非序号——SQL 改列顺序时代码不炸；
  • 取值方法与类型匹配：getLong/getInt/getString/getObject，错配会有隐式转换陷阱。

70.3 增删改：executeUpdate 与主键回填

public class UserDao {
    private final Connection conn;
    public UserDao(Connection conn) { this.conn = conn; }

    /** 插入并回填自增主键 —— 返回新记录 id */
    public long insert(String name, String email) throws SQLException {
        String sql = "INSERT INTO user(name, email) VALUES(?, ?)";
        try (PreparedStatement ps = conn.prepareStatement(
                sql, Statement.RETURN_GENERATED_KEYS)) {   // 关键参数
            ps.setString(1, name);
            ps.setString(2, email);
            int rows = ps.executeUpdate();                 // 返回受影响行数
            if (rows != 1) throw new SQLException("插入失败 rows=" + rows);
            try (ResultSet keys = ps.getGeneratedKeys()) {
                keys.next();
                return keys.getLong(1);                    // 拿到自增 id
            }
        }
    }

    public int updateEmail(long id, String email) throws SQLException {
        try (PreparedStatement ps = conn.prepareStatement(
                "UPDATE user SET email = ? WHERE id = ?")) {
            ps.setString(1, email);
            ps.setLong(2, id);
            return ps.executeUpdate();                     // 0 表示没匹配到行
        }
    }

    public int delete(long id) throws SQLException {
        try (PreparedStatement ps = conn.prepareStatement(
                "DELETE FROM user WHERE id = ?")) {
            ps.setLong(1, id);
            return ps.executeUpdate();
        }
    }
}
语义提醒：executeUpdate 返回的行数在 MySQL 中默认是"真正被改变的行"——更新成相同值算 0。需要"匹配到的行数"时在 URL 加 useAffectedRows=false（默认即匹配行数语义的另一种驱动配置，务必以实测为准并在团队内统一）。

70.4 资源关闭顺序与 try-with-resources

关闭顺序必须与创建顺序相反：ResultSet → Statement → Connection。写错顺序可能造成连接泄漏。try-with-resources 按声明逆序自动关闭，天然正确：

// 嵌套 try 写法（推荐）：作用域清晰，逐层自动关闭
try (Connection conn = ds.getConnection()) {
    try (PreparedStatement ps = conn.prepareStatement(sql)) {
        ps.setXxx(...);
        try (ResultSet rs = ps.executeQuery()) {
            while (rs.next()) { /* ... */ }
        }   // rs 关闭
    }       // ps 关闭
}           // conn 关闭（归还给连接池）

常见坑：连接池时代，"忘了关"不是连接消失，而是池被借空——症状是服务突然全部请求卡在获取连接处。第 71 章连接池配置里会有对应排查法。

70.5 ResultSet 行映射成对象

public record User(long id, String name, String email) {}

public List<User> mapAll(Connection conn) throws SQLException {
    List<User> list = new ArrayList<>();
    try (PreparedStatement ps = conn.prepareStatement(
             "SELECT id, name, email FROM user ORDER BY id");
         ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            list.add(new User(
                rs.getLong("id"),
                rs.getString("name"),
                rs.getString("email")));   // 每行 → 一个 record
        }
    }
    return list;
}
// 注意：NULL 值的处理——rs.getString 对 NULL 返回 null（安全），
// rs.getInt 对 NULL 返回 0（危险！）。可能为 NULL 的数值列用 getObject 判空。

手写映射是最朴素的 ORM。MyBatis（第 76 章）只是把这个"行 → 对象"的过程配置化、缓存化——映射的本质不变。

✓ 本章小结

要点一句话
对象层级Connection 会话 → Statement 语句 → ResultSet 游标
查询? 占位 + setXxx(1 起)；next() 先行；按列名取值
写操作executeUpdate 返回行数；RETURN_GENERATED_KEYS 回填主键
关闭rs→ps→conn 逆序；try-with-resources 一劳永逸
NULL 陷阱getInt 对 NULL 返 0；数值可空列用 getObject
