69.1 JDBC 是什么：一套契约

一句话定位：JDBC（Java Database Connectivity）是 JDK 提供的一组接口（Connection/Statement/ResultSet…），真正的实现在各数据库的驱动 jar 里——这正是第 60 章 SPI 机制的教科书案例。

69.3 引入驱动与三种加载方式

<!-- Maven 引入驱动（JDBC 4.x 对应 mysql-connector-j 8.x） -->
<dependency>
  <groupId>com.mysql</groupId>
  <artifactId>mysql-connector-j</artifactId>
  <version>8.3.0</version>
</dependency>
// 方式一：老式显式加载（JDBC 4.0 之前必须）
Class.forName("com.mysql.cj.jdbc.Driver");   // 触发驱动类的静态块注册

// 方式二：现代写法——什么都不用写！
// JDK 6+ 的 SPI 机制会扫描 jar 里 META-INF/services/java.sql.Driver
// DriverManager 初始化时自动注册所有驱动（第 44 章讲过原理）

// 方式三：系统属性指定（极少用）
// java -Djdbc.drivers=com.mysql.cj.jdbc.Driver MyApp
结论：现代项目不需要写 Class.forName。但面试和排查旧代码仍要懂它——驱动类的静态代码块里执行了 DriverManager.registerDriver(this)，这就是"加载即注册"。

69.4 驱动注册背后：SPI 机制

MySQL 驱动 jar 里有文件 META-INF/services/java.sql.Driver，内容一行：

com.mysql.cj.jdbc.Driver

DriverManager 的静态初始化会调用 ServiceLoader.load(Driver.class)，扫描 classpath 上所有 jar 的该文件并实例化注册。这里有个精妙细节：DriverManager 由 Bootstrap 层加载，"够不着"应用 classpath 上的驱动，所以它借用了线程上下文类加载器来加载驱动——这正是第 60 章"打破双亲委派"的第一个实战案例。

// 自己动手验证 SPI（Java 层视角）
import java.sql.DriverManager;
import java.util.Enumeration;

public class CheckDrivers {
    public static void main(String[] args) {
        Enumeration<java.sql.Driver> ds = DriverManager.getDrivers();
        while (ds.hasMoreElements()) {
            java.sql.Driver d = ds.nextElement();
            System.out.println(d.getClass().getName()
                + "  ← 由 " + d.getClass().getClassLoader() + " 加载");
        }
    }
}
// 输出：com.mysql.cj.jdbc.Driver  ← 由 appClassLoader 加载

69.5 建立第一条连接与常见报错

import java.sql.Connection;
import java.sql.DriverManager;

public class FirstConnection {
    public static void main(String[] args) throws Exception {
        String url = "jdbc:mysql://localhost:3306/jdbc_demo"
            + "?useSSL=false&serverTimezone=Asia/Shanghai"
            + "&characterEncoding=utf8";
        try (Connection conn = DriverManager.getConnection(url, "app", "App#123456")) {
            System.out.println("连接成功：" + conn.getMetaData().getDatabaseProductVersion());
        }   // try-with-resources 自动关闭——连接必须关闭！
    }
}
报错原因与解法
No suitable driver found没引驱动 jar，或驱动版本与 URL 前缀不匹配（com.mysql.jdbc.Driver 是老类名）
Communications link failure数据库没启动 / 端口错 / 防火墙；先 telnet 3306 验证
Access denied for user账号密码错，或该账号无远程访问权限（'app'@'%' vs 'app'@'localhost'）
Unknown databaseURL 里的库名拼错或未建库
The server time zone value…未设 serverTimezone，老驱动+新 MySQL 的经典坑

✓ 本章小结

要点一句话
JDBC 定位java.sql 契约 + 厂商驱动实现；换库换 jar 不换代码
驱动加载现代项目零配置（SPI 自动注册）；Class.forName 是旧识
SPI 联动DriverManager 用线程上下文类加载器加载驱动（打破委派实例）
连接纪律URL 带时区与编码；连接必须 try-with-resources 关闭
报错排查先分类：类没有→依赖；连不上→网络；拒了→权限

✎ 本章习题

A 基础解释"驱动 jar 里的 class 文件为什么要遵守 java.sql 的接口"——用第 60 章的语言回答。
B 进阶打开驱动 jar，找到 META-INF/services/java.sql.Driver 并查看内容；删除它再运行连接程序，观察报错。
C 挑战用最小权限账号 + 错误密码、错误库名、停掉的 MySQL 各制造一次报错，建立自己的"报错→原因"速查卡。
