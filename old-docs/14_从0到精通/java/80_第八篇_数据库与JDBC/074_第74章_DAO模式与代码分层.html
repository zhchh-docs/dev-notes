74.1 为什么需要分层

图 74-1 Entity/DAO/Service 三层职责

  • 可替换：DAO 是接口，今天 JDBC 实现，明天 MyBatis 实现，Service 零改动；
  • 可测试：Service 依赖 DAO 接口，单测时注入"内存假 DAO"即可，不需要数据库（第 99 章）；
  • 可读：想找数据逻辑去 DAO，想找业务规则去 Service——位置即语义。

74.2 Entity：数据载体

/** user 表的实体——只装数据，不含业务 */
public class User {
    private Long id;
    private String name;
    private String email;

    public User() {}                                   // 反射/框架需要无参构造

    public User(String name, String email) {
        this.name = name; this.email = email;
    }
    // getter/setter（略，IDE 生成）——分层世界里"啰嗦"是必要的礼貌
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }

    @Override public String toString() {
        return "User{id=%d, name='%s', email='%s'}".formatted(id, name, email);
    }
}

现代写法用 record 或 Lombok @Data 压缩样板代码；但理解手写版有助于看懂框架生成的等价物。

74.3 DAO：接口 + 实现分离

/** 数据访问契约——Service 只认识这个接口 */
public interface UserDao {
    long insert(User user);
    Optional<User> findById(long id);
    List<User> findByNameLike(String keyword);
    int updateEmail(long id, String email);
    int deleteById(long id);
}

/** JDBC 实现——所有 SQL 与连接细节被圈在这里 */
public class UserDaoJdbc implements UserDao {
    private final DataSource ds;
    public UserDaoJdbc(DataSource ds) { this.ds = ds; }

    @Override
    public long insert(User u) {
        String sql = "INSERT INTO user(name, email) VALUES(?, ?)";
        try (Connection conn = ds.getConnection();
             PreparedStatement ps = conn.prepareStatement(
                 sql, Statement.RETURN_GENERATED_KEYS)) {
            ps.setString(1, u.getName());
            ps.setString(2, u.getEmail());
            ps.executeUpdate();
            try (ResultSet keys = ps.getGeneratedKeys()) {
                keys.next();
                return keys.getLong(1);
            }
        } catch (SQLException e) { throw new DataAccessException("插入失败", e); }
    }

    @Override
    public Optional<User> findById(long id) {
        String sql = "SELECT id, name, email FROM user WHERE id = ?";
        try (Connection conn = ds.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setLong(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                return rs.next() ? Optional.of(mapRow(rs)) : Optional.empty();
            }
        } catch (SQLException e) { throw new DataAccessException("查询失败", e); }
    }
    private User mapRow(ResultSet rs) throws SQLException {
        User u = new User(rs.getString("name"), rs.getString("email"));
        u.setId(rs.getLong("id"));
        return u;
    }
    // findByNameLike / updateEmail / deleteById 同理（略）
}
DAO 把 SQLException 翻译成自定义的 DataAccessException——上层不必处理受检异常，也阻断了"SQL 细节向上泄漏"。这个思路在 Spring 里被 DataAccessException 体系发扬光大。

74.4 Service：业务编排层

public class UserService {
    private final UserDao userDao;                    // 依赖接口！
    public UserService(UserDao userDao) { this.userDao = userDao; }

    public long register(String name, String email) {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("姓名不能为空");
        if (userDao.findByNameLike(name).stream().anyMatch(x ->
                x.getEmail().equalsIgnoreCase(email)))
            throw new IllegalStateException("该邮箱已注册");
        return userDao.insert(new User(name, email));  // 编排：校验+查重+入库
    }
}

public class Main {
    public static void main(String[] args) {
        UserDao dao = new UserDaoJdbc(PoolSetup.create());  // 组装在入口
        UserService service = new UserService(dao);
        System.out.println("新用户 id = " + service.register("王五", "ww@demo.com"));
        // 换实现只需一行：UserDao dao = new UserDaoMyBatis(...);
    }
}

常见坑：组装点在"最外层"（main/Spring 容器），各层内部只依赖接口——这就是控制反转的雏形，第 77 章 IoC 会把它自动化。

74.5 转换与分层纪律

  1. 依赖方向：Controller → Service → DAO，禁止反向与跨层（Controller 直接拿 DAO）；
  2. 数据类型：层间传值推荐各自的模型（DO/DTO/VO），简单项目可共用 Entity 但要守住"不越层"；
  3. 事务边界：事务开在 Service 层（第 83 章 Spring 事务即落在此层）；
  4. 异常翻译：DAO 抛数据访问异常，Service 抛业务异常，表现层统一转响应（第 91 章）。

✓ 本章小结

要点一句话
分层收益可替换（DAO 实现可换）、可测试（接口可 mock）、可读（位置即语义）
Entity纯数据载体；record/@Data 消样板
DAO接口 + 实现；SQL、连接、异常翻译全部圈内
Service业务规则与编排；依赖接口；组装放最外层
纪律单向依赖、事务在 Service、异常逐层翻译
