100.1 日志的重要性与门面体系

一句话定位：日志是系统运行轨迹的持久化记录；SLF4J 是统一门面，Logback 是 Spring Boot 默认实现，业务代码只面向门面编程，实现可替换。

前端调试依赖浏览器控制台与 console.log，后端服务没有终端可看，必须把关键事件写入文件或日志平台，供排障、审计与监控使用。System.out.println 的问题：级别不分、不能落文件、不能按包过滤、线程与时间戳缺失、生产环境无法关闭。

图 100-1 业务代码面向 SLF4J 编程，底层实现由依赖决定

  • 门面模式：业务代码 import org.slf4j.Logger，切换 Logback / Log4j2 不改业务代码；
  • Spring Boot 默认栈：spring-boot-starter-logging 引入 Logback，并通过桥接包把其他框架的日志（JCL、Log4j、JUL）统一路由到 SLF4J；
  • 版本冲突信号：启动时 SLF4J 打印 Class path contains multiple SLF4J bindings 或 Failed to load class org.slf4j.impl.StaticLoggerBinder，说明依赖里混入了多套实现或缺少实现。

100.2 级别、占位符与日志写法

一句话定位：日志级别从低到高 TRACE < DEBUG < INFO < WARN < ERROR；配置某级别后，只输出该级别及以上的日志；消息用 {} 占位符惰性拼接。

级别语义典型场景
TRACE最细粒度的追踪细节方法入参出参、循环内部步骤，生产默认关闭
DEBUG开发调试细节中间状态、缓存命中、SQL 参数，测试环境开启
INFO关键业务节点与运行轨迹请求进入、订单创建、定时任务起止、外部调用成功
WARN可恢复的异常苗头重试成功、参数兜底、降级触发、慢调用告警候选
ERROR需要介入的失败事件业务流程中断、外部调用失败、未捕获异常，必须带堆栈
 
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;

@Service
public class OrderService {
    // 标准声明：类名作为 logger 名，便于按包名过滤
    private static final Logger log = LoggerFactory.getLogger(OrderService.class);

    public Order createOrder(Long userId, Long skuId, int count) {
        // ① 占位符 {}：级别未开启时不做字符串拼接，性能安全
        log.info("创建订单 userId={} skuId={} count={}", userId, skuId, count);

        if (count > 100) {
            // ② WARN：可恢复的边界情况，记录上下文供后续观察
            log.warn("下单数量偏大 userId={} count={}", userId, count);
        }

        try {
            return doCreate(userId, skuId, count);
        } catch (ExternalPayException e) {
            // ③ 异常对象作为最后一个参数单独传入，堆栈才会完整打印
            log.error("支付失败 userId={} skuId={}", userId, skuId, e);
            throw new BizException("下单失败，请稍后重试", e);
        }
    }
}
禁止写法：log.debug("订单详情：" + order) 在 DEBUG 关闭时仍会执行字符串拼接与 order.toString()，高并发下白白消耗 CPU；必须用占位符。需要条件判断时用 if (log.isDebugEnabled()) 包裹重型对象构造。

常见坑把异常信息拼进占位符字符串、最后不传 Throwable：log.error("失败 " + e.getMessage()) 会丢失堆栈，排障时只剩一行消息。异常对象永远作为方法最后一个参数传入。

100.3 logback-spring.xml 配置

一句话定位：配置文件放在 src/main/resources/logback-spring.xml；通过 appender 定义输出目的地，encoder 定义格式，rollingPolicy 定义文件滚动与归档策略。

<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <!-- 引入 Spring Boot 默认配置，继承其基础规则 -->
  <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

  <!-- 控制台输出 -->
  <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
      <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%logger{36}] [traceId=%X{traceId}] %msg%n</pattern>
      <charset>UTF-8</charset>
    </encoder>
  </appender>

  <!-- 滚动文件：按天 + 按大小切割，归档压缩，限制历史总量 -->
  <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>logs/order-service.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
      <fileNamePattern>logs/order-service.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
      <maxFileSize>100MB</maxFileSize>
      <maxHistory>30</maxHistory>          <!-- 保留 30 天 -->
      <totalSizeCap>5GB</totalSizeCap>      <!-- 归档总量上限 -->
      <cleanHistoryOnStart>true</cleanHistoryOnStart>
    </rollingPolicy>
    <encoder>
      <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%logger{36}] [traceId=%X{traceId}] %msg%n</pattern>
      <charset>UTF-8</charset>
    </encoder>
  </appender>

  <!-- 业务包级别单独调优 -->
  <logger name="com.example.bookstore" level="INFO"/>
  <logger name="org.springframework.web" level="INFO"/>

  <!-- 开发环境只输出控制台；生产环境文件 + 控制台 -->
  <springProfile name="dev">
    <root level="INFO">
      <appender-ref ref="CONSOLE"/>
    </root>
  </springProfile>
  <springProfile name="prod">
    <root level="INFO">
      <appender-ref ref="CONSOLE"/>
      <appender-ref ref="FILE"/>
    </root>
  </springProfile>
</configuration>
组件职责常用配置项
ConsoleAppender输出到标准输出（容器日志采集依赖它）encoder、pattern、charset
RollingFileAppender写入文件并按策略滚动归档file、rollingPolicy、encoder
SizeAndTimeBasedRollingPolicy时间 + 文件大小双维度切割fileNamePattern、maxFileSize、maxHistory、totalSizeCap
logger按包/类名设置级别与 appendername、level、additivity
springProfileSpring 环境条件块，仅 logback-spring.xml 支持name="dev" / "prod"

常见坑文件名写成 logback.xml 时不支持 <springProfile> 与 <springProperty>，环境块会被静默忽略；需要 Spring 扩展就必须使用 logback-spring.xml。

100.4 MDC 与 traceId 链路标识

一句话定位：MDC（Mapped Diagnostic Context）是线程内的日志上下文映射；请求入口生成 traceId 放入 MDC，pattern 中用 %X{traceId} 输出，同一请求的日志即可串联检索。

// ① 请求过滤器：进入时生成 traceId 写入 MDC，结束后清理
@Component
public class TraceIdFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String traceId = Optional.ofNullable(request.getHeader("X-Trace-Id"))
                .orElse(UUID.randomUUID().toString().replace("-", ""));
        MDC.put("traceId", traceId);
        response.setHeader("X-Trace-Id", traceId);
        try {
            chain.doFilter(request, response);
        } finally {
            MDC.remove("traceId");   // 线程池复用下必须清理，避免串号
        }
    }
}
// ② 异步线程池：默认不传递 MDC，用 TaskDecorator 复制上下文
public class MdcTaskDecorator implements TaskDecorator {
    @Override
    public Runnable decorate(Runnable runnable) {
        Map<String, String> context = MDC.getCopyOfContextMap();  // 主线程快照
        return () -> {
            if (context != null) MDC.setContextMap(context);       // 子线程恢复
            try {
                runnable.run();
            } finally {
                MDC.clear();
            }
        };
    }
}

@Configuration
public class AsyncConfig {
    @Bean
    public ThreadPoolTaskExecutor businessExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(8);
        executor.setMaxPoolSize(16);
        executor.setQueueCapacity(500);
        executor.setTaskDecorator(new MdcTaskDecorator());   // 挂到线程池
        executor.initialize();
        return executor;
    }
}
  • 同步链路：同一请求线程内 MDC 自动可用，pattern 中 %X{traceId} 即取值；
  • 异步线程：@Async、CompletableFuture、手动 new Thread 都不继承 MDC，必须通过 TaskDecorator 或包装 Runnable 显式传递；
  • 线程池复用：请求结束必须 MDC.remove，否则下一个复用该线程的请求会带上上一个 traceId，日志串号；
  • 跨服务传播：调用下游时把 traceId 放入请求头（如 X-Trace-Id），过滤器优先读取入口头值，实现跨服务串联。

100.5 Spring Boot 日志属性配置

一句话定位：不写 XML 也能完成常规调优——application.yml 中的 logging.* 属性覆盖级别、文件位置与格式；需要滚动策略、异步 appender 时再回到 logback-spring.xml。

logging:
  level:
    root: INFO
    com.example.bookstore: DEBUG          # 业务包单独调为 DEBUG
    org.springframework.jdbc.core: DEBUG  # SQL 参数调试
  file:
    name: logs/order-service.log           # 输出文件（与 path 二选一）
  pattern:
    console: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%logger{36}] %msg%n"
    file: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%logger{36}] [traceId=%X{traceId}] %msg%n"
  logback:
    rollingpolicy:
      max-file-size: 100MB
      max-history: 30
      total-size-cap: 5GB
属性作用
logging.level.root根 logger 级别，全局默认阈值
logging.level.<包名>按包/类单独设置级别，覆盖 root
logging.file.name日志文件完整路径名（与 logging.file.path 二选一）
logging.pattern.console / .file控制台 / 文件输出格式模板
logging.logback.rollingpolicy.*Spring Boot 托管的滚动策略参数（大小、天数、总量）

配置优先级：logback-spring.xml 中的显式配置优先于 application.yml 属性；一旦引入自定义 XML，Boot 默认文件 appender 规则即由 XML 接管，注意不要两边重复定义导致行为不一致。

100.6 常见坑：级别滥用、异步丢失与重复打印

① 级别滥用与打点位置错误

业务正常流程刷大量 DEBUG、异常堆栈只打 INFO，都会让真正的告警信号淹没。纪律：INFO 只记录关键节点；循环体内、高频调用路径不打 INFO；异常必须 ERROR 且带堆栈。logger 声明为 private static final，不要在方法内反复 LoggerFactory.getLogger。

② 异步 appender 的队列与丢日志

<appender name="ASYNC_FILE" class="ch.qos.logback.classic.AsyncAppender">
  <queueSize>512</queueSize>            <!-- 队列容量，默认 256 -->
  <discardingThreshold>0</discardingThreshold>  <!-- 0 表示不丢弃任何级别 -->
  <neverBlock>false</neverBlock>       <!-- 队列满时阻塞业务线程，避免丢日志 -->
  <appender-ref ref="FILE"/>
</appender>

异步 appender 把日志先入队列、后台线程批量写出，降低 IO 阻塞；但队列满时默认策略会丢弃低级别日志（discardingThreshold），且异步线程上下文中 MDC 已在主线程快照中复制——配置不当会出现"生产 ERROR 日志缺行"。对财务、审计类日志建议关闭丢弃或直接同步落盘。

③ 重复打印

同一条日志出现两遍，最常见原因：root 挂了 CONSOLE 与 FILE，业务 logger 又显式挂了一份 appender，且 additivity 未关闭。子 logger 配置：

<!-- additivity=false：不再向 root 向上传递，避免重复输出 -->
<logger name="com.example.bookstore" level="INFO" additivity="false">
  <appender-ref ref="FILE"/>
</logger>

另一种重复来自依赖冲突：classpath 中同时存在 logback-classic 与 log4j-to-slf4j 之外的其他实现，启动告警中先看绑定数量，再用 mvn dependency:tree 排除多余实现。

排障顺序日志异常先看启动绑定告警 → 核对级别配置与包名 → 检查 additivity 与 appender 挂载 → 确认异步队列策略 → 最后排查 MDC 线程传递。

✓ 本章小结

要点一句话
门面体系业务面向 SLF4J 编程，Logback 为 Spring Boot 默认实现，切换实现不改业务代码
级别TRACE < DEBUG < INFO < WARN < ERROR，配置级别以上才输出；异常对象单独传最后参数
占位符{} 惰性拼接避免无效 toString；重型对象先判断 isDebugEnabled
配置logback-spring.xml 支持 springProfile；Console/RollingFile appender + 时间大小滚动策略
MDC入口写 traceId、pattern 用 %X 输出；异步线程 TaskDecorator 复制；用完 remove 防串号
高频坑级别滥用、异步队列丢日志、additivity 未关导致重复打印

✎ 本章习题

A 基础按从低到高列出五个日志级别，说明 INFO 与 WARN 的语义边界；解释为什么日志消息必须用 {} 占位符。
B 进阶为现有 Spring Boot 工程接入 TraceIdFilter 与 MdcTaskDecorator，在异步任务日志中验证 traceId 跨线程保持一致。
C 挑战构造一次重复打印问题（业务 logger 与 root 同时挂 appender），用 additivity=false 修复；再人为制造多 SLF4J 绑定告警，用依赖树排除多余实现。
