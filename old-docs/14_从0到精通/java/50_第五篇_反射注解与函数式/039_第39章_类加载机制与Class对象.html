39.1 类加载三步

加载（Loading）
  ↓  通过全类名找到 .class 字节码，读入内存，变成 Class 对象
链接（Linking）
  ├─ 验证：字节码结构合法？魔数 CAFEBABE、版本号、安全性检查
  ├─ 准备：为静态变量分配内存并赋零值（static int i = 0，此时还不是 100）
  └─ 解析：符号引用（常量池里的名字）→ 直接引用（内存地址）
初始化（Initialization）
     执行 <clinit>()：静态变量真正赋初值 + 静态代码块
  • 加载是 JVM 说了算，也可以自己来——自定义类加载器（第 60 章展开）；
  • 初始化的顺序：父类先于子类，静态变量和静态块按代码书写顺序执行；
  • 面试常考："准备阶段赋零值、初始化阶段赋初值"——所以 static int i = 100 在准备后是 0，clinit 之后才是 100。

初始化的触发时机（主动引用）

  • new 一个类、读写静态字段（final 常量除外，编译期已进常量池）、调用静态方法；
  • 反射 Class.forName（注意 initialize 参数）、初始化子类时父类先初始化；
  • main 方法所在类、JMH/Mock 等 Agent 注入的类。
常见坑通过数组定义引用类（new User[10]）不会触发 User 初始化；通过子类访问父类静态字段，只初始化父类——被动引用的细节是面试重灾区。

39.2 类加载器与双亲委派

JVM 有三层"搬运工"，加上自定义的共四类：

Bootstrap ClassLoader      C++ 写的，加载 JDK 核心（rt.jar / java.base 模块）
   ↑ parent
Extension/Platform ClassLoader  加载 JDK 扩展模块（jdk.*）
   ↑  parent
Application ClassLoader   加载 classpath 下的类（你自己写的 90% 在这里）
   ↑  parent
Custom ClassLoader        你自己写的（Tomcat、Spring Boot Loader、SPI 打破点）

双亲委派：一个加载器收到加载请求，先问 parent"你加载过吗"，一路往上到 Bootstrap；都加载不了，自己才动手。

  • 好处：防止重复加载、防止核心类被篡改——你自己写一个 java.lang.String 永远加载不进来；
  • 打破它的场景：JDBC（Bootstrap 要去加载 Application 层的驱动，于是有了 Thread.contextClassLoader）、Tomcat（每个 WebApp 要隔离同名类）；
  • 打破的方法：继承 ClassLoader 重写 loadClass，不走 parent 委派链。
双亲委派是"安全优先"的默认策略；上下文类加载器是 JDK 留给 SPI 的"后门"——第 44 章会看到它如何让 Bootstrap 加载到扩展代码。

39.3 三种获取 Class 的方式

// ① 类字面常量：编译期已知，最常用
Class<User> c1 = User.class;

// ② Class.forName：会触发初始化，用于加载驱动等副作用场景
Class<?> c2 = Class.forName("com.mysql.cj.jdbc.Driver");

// ③ 对象.getClass：运行时才知道具体类型
Object obj = service.getById(1);
Class<?> c3 = obj.getClass();   // User.class == c3 为 true
  • 三者拿到的是同一个 Class 对象（每个类在 JVM 里只有一份 Class 实例）；
  • Class.forName(name, false, loader) 第二个参数控制是否初始化——框架加载类但不一定立刻 clinit；
  • Class 对象是反射的入口：newInstance、getMethod、getDeclaredField 全从这里出发（下一章）；
  • 泛型擦除后，Class<T> 运行期只是 Class，但编译期能帮你做类型检查。
顺带记一个 API 谱系：getMethods() 拿 public（含继承），getDeclaredMethods() 拿自己声明的所有（不含继承）——"Declared"这个前缀在反射 API 里到处都是。

✓ 本章小结

要点一句话
三步加载（字节码→Class）→ 链接（验证/准备/解析）→ 初始化（clinit）
准备 vs 初始化准备赋零值，初始化才赋代码里的初值
触发new/静态读写/反射/子类触发父类；数组定义不触发
双亲委派先问 parent 后自己加载；SPI 用上下文类加载器破局
Class 获取类字面常量 / forName（初始化）/ getClass（运行时）

✎ 本章习题

A 基础写一个带静态代码块和静态变量的类，分别用 User.class、Class.forName、getClass() 三种方式获取 Class，验证三者相等，并观察静态代码块何时打印（哪种方式触发、哪种不触发）。
B 进阶继承关系实验：父类有静态字段 A，子类通过 Child.A 访问它——用 -verbose:class 或打印语句验证只有父类被初始化、子类没有；再画一张类初始化触发与不触发的清单表。
C 挑战写一个自定义类加载器：继承 ClassLoader，defineClass 加载一段字节数组（可以先用 javac 编译再读文件），打破双亲委派重写 loadClass，观察自己写的 java.lang.String 能否被加载、以及会抛什么异常。
