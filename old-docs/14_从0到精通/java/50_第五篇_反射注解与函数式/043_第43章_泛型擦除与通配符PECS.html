43.1 泛型只存在于编译期

Java 泛型（JDK 5）为了兼容没有泛型的存量代码，选择了擦除式实现：编译期把类型参数替换成边界（默认 Object），运行期 List<String> 和 List<Integer> 是同一个类。

List<String> names = new ArrayList<>();
List<Integer> ages = new ArrayList<>();

// 编译期：names.add("x") 合法，names.add(1) 编译错误
// 运行期：
names.getClass() == ages.getClass();        // true！都是 ArrayList.class
names.getClass().getTypeParameters()[0].getName();   // "E"，不是 String
  • 擦除到上界：<T extends Number> 擦成 Number，无界擦成 Object；
  • 编译期会在必要处插入强转：names.get(0) 实际是 (String) list.get(0)——所以泛型有轻微开销但换来类型安全；
  • 对比 C#/Kotlin 的具现化泛型（reified），泛型信息保留到运行期——这也是 Java 不能 new T[].length 访问类型信息的根源。

43.2 擦除引发的怪现象

// ① 不能实例化类型参数
T t = new T();              // 编译错误
T[] arr = new T[10];       // 编译错误（只能 new ArrayList<T>[10] 这种）

// ② instanceof 泛型必炸
if (list instanceof List<String>) { }   // 编译错误
// 擦除后只可能是 List，JDK 干脆禁止这种写法

// ③ 不能重载：擦除后签名冲突
void f(List<String> a) { }
void f(List<Integer> a) { }   // 编译错误：name clash

// ④ 静态上下文不能用类的类型变量
class Box<T> {
    static T value;          // 编译错误：T 属于实例
}

// ⑤ 泛型数组的"合法丑态"
List<?>[] arr = new List[10];   // 只能这样，配合 @SafeVarargs 用
  • 规避手段：传 Class<T> clazz 参数用反射 new；要数组就传 IntFunction<T[]> 生成器；
  • JDK 保留的逃生门：泛型信息在签名（Signature 属性）和超类/字段上仍可反射读取——getGenericSuperclass 就是靠它拿到真实泛型，Jackson/Spring 的类型解析依赖这个。

43.3 通配符与 PECS

// 需求：写一个方法，把 src 的元素拷到 dst
static <T> void copy(List<? extends T> src, List<? super T> dst) {
    for (T t : src) dst.add(t);
}

这条签名就是 PECS 原则的教科书：Producer Extends, Consumer Super——

  • ? extends T：容器只产出 T（读出来当 T 用），不能往里加（除 null）；
  • ? super T：容器只消费 T（能 add T 及其子类），读出来只能是 Object；
  • JDK 自己就这么用：Collections.copy(List<? super T> dest, List<? extends T> src)；
  • 《Effective Java》原话：如果参数化类型表示一个 T 的生产者，用 <? extends T>；如果表示消费者，用 <? super T>；两者都是，就别用通配符。
List<Integer> ints = List.of(1, 2, 3);
List<Number> nums = new ArrayList<>();
copy(ints, nums);              // 完美：Integer  extends Number，Number super Integer

List<Object> objs = new ArrayList<>();
copy(nums, objs);              // 也合法：泛型协变的自由
// 但 copy(objs, nums) 编译错误：Object 不是 Integer 的生产者
记住 PECS：要读用 extends，要写用 super，Java 的泛型型变全押在通配符上。

✓ 本章小结

要点一句话
擦除编译期语法糖：List<String> 与 List<Integer> 运行期同一个类
怪现象不能 new T[]、instanceof 泛型、同签名重载冲突、静态上下文无 T
逃生门传 Class<T> 反射创建；Signature 属性保留泛型供反射读取
PECS生产者 extends、消费者 super；Collections.copy 是范本
读写法? extends T 读出来是 T、写只能 null；? super T 能 add、读是 Object

✎ 本章习题

A 基础验证擦除：创建 List<String> 和 List<Integer>，打印 getClass() 是否相等，并用反射读取 getTypeParameters() 的名字。
B 进阶实现 <T> T[] toArray(List<T> list, IntFunction<T[]> generator)，对比 list.toArray(new T[0]) 为什么不行；再写一个 max(List<? extends Comparable>) 验证 extends 只能读。
C 挑战写一个泛型工具 merge(Map<String, ? extends Number> a, Map<String, ? super Number> b) 把 a 的值加 1 后放进 b；然后分别尝试把两个参数都改成 ? extends 或都改成 ? super，观察编译错误并解释。最后用《Effective Java》PECS 原文精神写三行注释。
