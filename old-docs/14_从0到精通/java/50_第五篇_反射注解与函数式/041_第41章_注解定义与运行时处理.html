◆本章目标

  • 理解注解的本质：给代码贴标签，标签本身不干活；
  • 掌握四个元注解：@Target、@Retention、@Documented、@Inherited；
  • 会定义自己的注解并配默认值；
  • 会用反射在运行时读取注解并驱动行为（Spring/JUnit 的机制）。

41.1 注解：代码上的标签

注解（Annotation）是 JDK 5 引入的元数据机制：它本身不改变程序行为，但读它的代码（框架、编译器、APT）会按标签行事。

@Override                      // 编译器检查：这方法真的重写父类了吗？
@Deprecated                    // IDE 划线警告 + javadoc 标注
@SuppressWarnings("unchecked") // 编译器闭嘴，别报未检查转换

public class UserService {
    @Override
    public String toString() { return "UserService"; }
}
  • 没有 @Override，拼错方法名就悄悄变成"新增方法"；有了它，编译器直接报错——注解是编译期的安全带；
  • @SuppressWarnings 让编译器在局部范围闭嘴，比全局忽略干净；
  • 自定义注解是框架的"配置语言"：@Component、@Transactional、@Test……你写业务，框架读注解。

41.2 元注解四件套

元注解是"注解的注解"，定义你的注解能用在哪、活多久：

@Target(ElementType.METHOD)              // 能贴在哪：方法/类/字段/参数/包……
@Retention(RetentionPolicy.RUNTIME)    // 活到哪：SOURCE(编译丢) / CLASS(默认) / RUNTIME(反射可读)
@Documented                             // 会进 javadoc
@Inherited                              // 子类继承父类的这个注解
public @interface Loggable { }
  • Retention 决定生死：@Override 是 SOURCE（编译完就扔）；Lombok 靠 SOURCE+APT；Spring/@Test 必须 RUNTIME，否则反射读不到；
  • @Target 漏写 = 哪里都能贴（包括类型、参数），框架注解一般都收紧范围；
  • @Inherited 只对类的继承有效，接口实现、字段、方法都不继承。
写框架注解三连问：贴哪（Target）？活多久（Retention 必须 RUNTIME）？要不要继承（Inherited）？

41.3 自定义注解与反射读取

// 定义：注解元素就是"方法"，可以有默认值
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Loggable {
    String value() default "INFO";        // 用 value() 才能 @Loggable("DEBUG") 省略名
    boolean printArgs() default false;    // 有默认值，使用时可省略
}

// 使用
public class OrderService {
    @Loggable("DEBUG")
    public void pay(long orderId) { /* ... */ }
}

反射读取——这才是注解"活过来"的时刻：

for (Method m : OrderService.class.getDeclaredMethods()) {
    Loggable ann = m.getAnnotation(Loggable.class);   // 没有注解返回 null
    if (ann != null) {
        System.out.println(m.getName()
            + " 日志级别=" + ann.value()          // 读元素值
            + " 打印参数=" + ann.printArgs());
    }
}
// 输出：pay 日志级别=DEBUG 打印参数=false
  • 注解元素的类型只允许：基本类型、String、Class、枚举、注解、以及它们的一维数组；
  • 没有元素的注解叫标记注解（@Override 就是）；
  • Spring AOP 的流程：切点表达式匹配到方法 → getAnnotation 读 @Transactional → 决定开事务——"注解本身不干活，干活的永远是读它的代码"；
  • 重复注解需要 @Repeatable 配容器注解（Java 8+），多用于 @Scheduled 这类场景。

✓ 本章小结

要点一句话
本质元数据标签；注解不干活，读注解的代码干活
RetentionSOURCE 编译丢 / CLASS 默认 / RUNTIME 反射可读，框架注解必须 RUNTIME
元素规则无参=标记；value() 才能省略名；类型受限（基本/String/Class/枚举/注解/数组）
读取getAnnotation / getAnnotations，反射遍历类、方法、字段
应用Spring 条件装配、AOP、JUnit 执行、Lombok 编译期生成

✎ 本章习题

A 基础定义 @Loggable（value 默认 "INFO"，printArgs 默认 false，Target=METHOD，Retention=RUNTIME），在测试类的方法上贴不同参数，用反射读取并打印每个方法的注解配置。
B 进阶实现一个极简"注解驱动的校验器"：定义 @Range(min, max) 贴到字段上，写方法用反射遍历对象字段，越界时收集错误信息返回 List<String>——模拟 Bean Validation（@Min/@Max）的最简骨架。
C 挑战写一个"注解驱动的日志切片"：定义 @Loggable 贴方法，运行时用反射 + 动态代理（下一章）实现"调用前打印 value 级别的日志、printArgs=true 时打印参数、调用后打印耗时"——不需要 Spring，纯 JDK 实现。
