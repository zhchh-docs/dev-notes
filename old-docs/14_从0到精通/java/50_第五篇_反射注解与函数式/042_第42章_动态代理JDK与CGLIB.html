42.1 从静态代理到动态代理

代理模式：给目标对象套一个"壳"，在调用前后加料（日志、事务、权限），使用方无感知。静态代理的问题是——每个接口都要手写一个代理类，十个接口十个壳，重复代码爆炸。

// 静态代理：为 UserService 手写壳
class UserServiceProxy implements UserService {
    private final UserService target;
    public void pay() {
        log("before");          // 加料
        target.pay();           // 转发
        log("after");
    }
    // 每个方法都要这么包一遍……接口一多就想哭

动态代理的思路：把"转发 + 加料"的通用逻辑抽到一个 handler，运行期按接口动态生成代理类——AOP（面向切面编程）的 Java 底座。

42.2 JDK 动态代理

// 目标接口 + 实现
public interface UserService { void pay(long orderId); }
public class UserServiceImpl implements UserService {
    public void pay(long orderId) { System.out.println("支付：" + orderId); }
}

// 调用处理器：所有方法调用都会流经这里
InvocationHandler handler = new InvocationHandler() {
    private final Object target;              // 被代理的真实对象
    handler(Object t) { this.target = t; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) {
        System.out.println("[日志] 调用 " + method.getName());
        Object result = method.invoke(target, args);   // 反射调用真实方法
        System.out.println("[耗时] " + method.getName() + " 完成");
        return result;
    }
};

// 生成代理对象
UserService proxy = (UserService) Proxy.newProxyInstance(
        UserService.class.getClassLoader(),
        new Class<?>[]{UserService.class},
        handler);

proxy.pay(1001L);   // 输出日志 → 真实支付 → 输出耗时
  • invoke 三个参数：proxy（代理对象自己，慎用易死循环）、method（被调的方法）、args（参数，无参为 null 不是空数组）；
  • 代理类运行时由 JVM 生成字节码，实现目标接口，方法体统一转发给 invoke——所以只能代理接口；
  • 生成一次可复用；创建成本高（字节码生成），别在循环里 newProxyInstance。

42.3 CGLIB 与选型

没有接口的类怎么办？CGLIB（Code Generation Library）通过继承生成子类，重写父类方法织入逻辑：

// CGLIB（Spring 4.3 前内置，之后随 Spring Core 打包为独立依赖）
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserServiceImpl.class);     // 指定父类
enhancer.setCallback((MethodInterceptorCallback) (obj, method, args1, proxy) -> {
    System.out.println("[CGLIB] before " + method.getName());
    Object r = proxy.invokeSuper(obj, args1);       // 调用父类真实方法
    System.out.println("[CGLIB] after");
    return r;
});
UserServiceImpl proxy = (UserServiceImpl) enhancer.create();
对比项JDK 动态代理CGLIB
实现方式实现接口，运行期生成字节码继承目标类，生成子类字节码
前提目标必须有接口类不能 final、方法不能 final/private
性能调用走反射 invoke，略慢FastClass 机制，调用更快
生态JDK 自带Spring Boot 2.x 已改用 ByteBuddy；CGLIB 逐步退场
Spring AOP 选型逻辑：目标有接口用 JDK 代理，没接口用 CGLIB/ByteBuddy 子类代理；Spring Boot 2.x 起默认 ByteBuddy。
常见坑代理对象内部方法互调（this.b()）不走代理——因为 this 是目标对象不是代理对象。Spring 的解法是 AopContext.currentProxy() 或避免自调用，这是事务不生效的头号原因。

✓ 本章小结

要点一句话
动机静态代理一个接口一套壳；动态代理把加料逻辑抽成通用 handler
JDK 代理InvocationHandler + Proxy.newProxyInstance，必须有接口
CGLIB生成子类重写方法；类/方法不能 final；现多被 ByteBuddy 替代
拼图注解（标记）+ 反射（读取）+ 动态代理（织入）= Spring AOP
自调用坑代理内 this 调用不走增强，事务失效头号原因
