45.1 把代码当值传递

Java 8 之前，"把一段行为传给方法"只能靠匿名内部类，样板代码淹没了重点：

// Java 7：排序要传入一个 Comparator"行为"
button.addActionListener(new ActionListener() {
    @Override public void actionPerformed(ActionEvent e) {
        System.out.println("clicked");
    }
});

// Java 8：Lambda —— 去掉类名、方法名，只留参数和逻辑
button.addActionListener(e -> System.out.println("clicked"));

语法骨架：(参数) -> { 逻辑 }，编译器把它编译成目标接口的实例——不是匿名类的语法糖，而是invokedynamic 指令的动态调用。

// 六种形态全览
() -> 42                              // 无参，表达式体（自动 return）
() -> { return 42; }                  // 无参，语句体
(int a, int b) -> a + b                // 带类型
(a, b) -> a + b                        // 类型推断
(String s) -> { System.out.println(s); }  // 单参可省括号 s -> ...
x -> x * 2                            // 单参无括号最简形态
  • 单行表达式体：编译器自动 return，不需要分号；多行语句体：必须 {} 和显式 return；
  • Lambda 没有 this——它引用的是外层的 this（匿名内部类的 this 是匿名类自己）；
  • 变量捕获：只捕获事实上的 final（局部变量只赋值一次即可，不用写 final 关键字）。

45.2 四大函数式接口

java.util.function 包预置了 40+ 个接口，先记住这"四大天王"：

// ① 消费型：接一个参数，不返回
Consumer<String> c = s -> System.out.println(s);
c.accept("hi");

// ② 供给型：不接参数，产出一个
Supplier<Integer> s = () -> (int) (Math.random() * 100);
s.get();

// ③ 函数型：T 进 R 出（转换）
Function<String, Integer> f = Integer::parseInt;
f.apply("42");                       // 42

// ④ 断言型：T 进 boolean 出
Predicate<String> p = str -> str.isEmpty();
p.test("");                          // true
  • 常用变体：BiConsumer/BiFunction（两个参数）、UnaryOperator（T→T，Function 的特例）、IntPredicate/LongFunction（避免装箱的基本类型版）；
  • 接口按参数个数 + 有无返回值记，函数名不用死记：accept/get/apply/test；
  • 自定义接口满足"只有一个抽象方法"就是函数式接口，可加 @FunctionalInterface 让编译器校验（但 default/static 方法可以有多个）。

45.3 匿名内部类 → Lambda 等价改写

// 等价改写 1：Runnable
new Thread(new Runnable() {
    public void run() { System.out.println("old"); }
}).start();
new Thread(() -> System.out.println("new")).start();

// 等价改写 2：Comparator
Collections.sort(names, new Comparator<String>() {
    public int compare(String a, String b) { return a.length() - b.length(); }
});
names.sort((a, b) -> a.length() - b.length());

// 等价改写 3：Swing/AWT 监听
btn.addActionListener(e -> { JOptionPane.showMessageDialog(null, e); });
常见坑① Lambda 的目标类型由上下文决定——赋值给哪个接口就编译成哪个接口，重载方法间可能 ambiguous；② Lambda 里 this 指向外部类，匿名内部类 this 指向自己，改写时若原代码用了匿名类的 this 会改变语义；③ 捕获的局部变量必须 effectively final。
Lambda 省掉的是"类壳"，留下的是"行为"——行为参数化，是函数式编程进入 Java 的入口。

✎ 本章习题

A 基础把三个传统匿名内部类（Runnable、Comparator、ActionListener）分别改写为 Lambda，编译运行对比行为一致。
B 进阶用四大函数式接口搭一个"数据处理小管线"：Supplier 产随机数 10 个 → Function 平方 → Predicate 过滤偶数 → Consumer 打印；全部用 Lambda 组合，并思考为什么比 for 循环更易读。
C 挑战定义自己的函数式接口 @FunctionalInterface interface TriFunction<A,B,C,R> { R apply(A a, B b, C c); }，实现一个"三联查找"：给三个谓词，找到第一个满足的返回其标签；再尝试去掉 @FunctionalInterface 加一个抽象方法，观察编译器报什么错、错在哪。
