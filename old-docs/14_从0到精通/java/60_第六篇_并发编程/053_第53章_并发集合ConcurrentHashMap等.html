53.1 老办法为什么不行

// HashMap 多线程 put → 结构被破坏：数据丢失、get 返回 null
// JDK 7 扩容时头插法还会形成环形链表 → CPU 100% 的经典事故
// Hashtable：全表一把锁，所有操作排队——安全但慢
Map<K,V> sync = Collections.synchronizedMap(new HashMap<>());  // 同样全表锁
// 而且"复合操作"依然不安全：
if (!sync.containsKey(k)) { sync.put(k, v); }   // check 与 put 之间会被插队！
  • 复合操作（先检查后行动）即使用了同步包装类也有竞态——需要 putIfAbsent/computeIfAbsent 这类原子复合方法；
  • 结论：并发容器不是"加锁的集合"，而是为高频并发场景重新设计的数据结构。

53.2 ConcurrentHashMap：分段锁 → CAS+红黑树

JDK 7：Segment 分段锁——默认 16 段，每段一把锁。不同段的写互不阻塞，理论并发度 = 段数。缺点：结构复杂、并发度固定。

JDK 8：CAS + synchronized 锁单个桶——结构回归 HashMap（数组+链表+红黑树）：

// put 的核心逻辑（简化）
static final int HASH = spread(key.hashCode());
Node<K,V>[] tab = table;
int i = (n - 1) & HASH;
Node<K,V> f = tabAt(tab, i);          // volatile 读桶头
if (f == null) {
    // 桶空：CAS 放入新节点，无锁！
    casTabAt(tab, i, null, new Node<K,V>(HASH, key, value));
} else {
    synchronized (f) {                 // 桶非空：只锁这个桶头
        // 链表遍历/红黑树插入
    }
}
  • 锁粒度从"段"细化到"桶"，冲突概率大幅下降；空桶写入纯 CAS，零锁开销；
  • size() 不再数一遍：用 CounterCell 分段计数（LongAdder 思路，第 55 章），弱一致；
  • get 全程无锁（Node.val 和 next 是 volatile）；迭代器是弱一致的——遍历时看到的是某一时刻的快照，不抛 ConcurrentModificationException；
  • key/value 都不允许 null（并发下 null 语义有歧义：是"没有"还是"值为 null"？）。
CHM 并发读安全、写粒度极细，但要原子组合用 API：putIfAbsent、computeIfAbsent、merge——别自己 check-then-act。

53.3 CopyOnWrite 与 BlockingQueue 家族

CopyOnWriteArrayList：读无锁、写复制

// 写：复制整个数组 → 修改副本 → volatile 替换引用
// 读：永远读当前数组，不加锁、迭代器不抛异常
List<Listener> listeners = new CopyOnWriteArrayList<>();   // 典型：监听器列表
  • 适合读极多写极少（监听器/配置列表）；写 O(n) 复制，高频写是灾难；
  • 弱一致性：写完立刻读可能读到旧数组——发布订阅场景可接受。

BlockingQueue：生产者-消费者专用

BlockingQueue<Order> queue = new ArrayBlockingQueue<>(1000);
queue.put(order);            // 满了阻塞（背压）
queue.take();                // 空了阻塞——第 57 章用它搭模式

// 家族选型
// ArrayBlockingQueue    有界数组，一把锁，稳定
// LinkedBlockingQueue   可选有界（默认无界！慎用），两把锁读写分离
// SynchronousQueue      零容量，一手交钱一手交货（CachedThreadPool 用它）
// PriorityBlockingQueue 优先级出队
// DelayQueue            延迟出队（定时任务池的底层）
  • put/take 阻塞版；offer/poll 带超时版；add/remove 立即失败版——按业务选择；
  • LinkedBlockingQueue 当"有界队列"用必须手动传容量，默认 Integer.MAX_VALUE 等于无界。

✓ 本章小结

要点一句话
HashMap 并发丢数据 + JDK 7 环形链死循环；同步包装类防不了复合操作竞态
CHM JDK 8空桶 CAS、非空桶 synchronized(f)，锁到桶；读全程无锁
原子组合putIfAbsent/computeIfAbsent/merge，拒绝 check-then-act
CopyOnWrite读无锁写复制，适合读极多写极少的监听器/配置
BlockingQueueput/take 阻塞即背压；Linked 默认无界要传容量

✎ 本章习题

A 基础用多线程并发向 HashMap 和 ConcurrentHashMap 各 put 10000 条，统计两个结果集大小并解释差异；再对 CHM 测试 computeIfAbsent 实现"线程安全缓存"。
B 进阶用 CopyOnWriteArrayList 实现"事件总线"：register/unregister 监听器，publish 时遍历触发；测量 1000 次写 + 100 万次读的耗时，和 synchronizedList 对比，写结论。
C 挑战用 ArrayBlockingQueue（容量 10）搭一个双生产者-三消费者模型：生产者 put 比消费快，观察队列打满后生产者阻塞（打印"背压中"）；换成 LinkedBlockingQueue 不传容量，用 -Xmx128m 跑，观察 OOM——写出"有界 vs 无界"的结论。
