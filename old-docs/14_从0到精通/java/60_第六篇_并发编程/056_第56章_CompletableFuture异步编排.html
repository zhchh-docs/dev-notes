◆本章目标

  • 说清 Future 的局限：阻塞 get、无法链式、无法组合；
  • 掌握 supplyAsync/thenApply/thenAccept 的链式写法；
  • 会用 thenCompose/thenCombine/anyOf/allOf 编排多个异步任务；
  • 处理异常传播与超时，写出生产可用的异步代码。

56.1 Future 的局限

// Future 时代的痛点
Future<String> f = executor.submit(() -> queryUser(id));
String user = f.get();          // ① 阻塞！主线程干等
// ② 拿到结果后想再异步查订单？再 submit 一次，手工传递
// ③ 两个并行查询要合并？自己 CountDownLatch 拼装
// ④ 异常藏在 ExecutionException 里，一层 unwrap
// ⑤ 没有回调：结果好了也没人通知你

CompletableFuture（JDK 8）把"异步任务"变成可编排的值：链式声明依赖、组合多个 Future、异常沿链传播——Java 版的 Promise。

56.2 链式编排 API

// 创建：supplyAsync 有返回值 / runAsync 无返回值
CompletableFuture<String> name = CompletableFuture.supplyAsync(
        () -> userService.getName(id));

// 转换：thenApply（有入参有返回）→ 相当于 map
CompletableFuture<Integer> len = name.thenApply(String::length);

// 消费：thenAccept（有入参无返回）/ thenRun（无入参无返回）
name.thenAccept(n -> log.info("got {}", n));

// 注意 thenApply vs thenApplyAsync：
// thenApply     由"完成当前阶段的线程"或主线程执行（快，可能挤占）
// thenApplyAsync 显式丢回线程池（可控，推荐传自定义 executor）
name.thenApplyAsync(String::length, businessPool);
  • 命名规律：then/when 开头是"完成后"，Async 后缀表示切线程池；
  • 不传 executor 时默认用 ForkJoinPool.commonPool()——全局共享、并行度 = 核数-1；IO 任务会饿死 CPU 任务，生产必须传业务线程池；
  • 同步阻塞的 get/join 依旧存在，但好代码里它只出现在链条尽头。

56.3 组合、异常与超时

// ① 串行依赖：thenCompose（上一个结果触发下一个异步任务）→ 相当于 flatMap
CompletableFuture<Order> order =
        CompletableFuture.supplyAsync(() -> queryUser(id))
                .thenCompose(user -> asyncQueryOrder(user.getDefaultOrderId()));

// ② 并行合并：thenCombine（两个都完成后合并）
CompletableFuture<Price> p1 = asyncQueryPrice(sku);
CompletableFuture<Coupon> p2 = asyncQueryCoupon(user);
CompletableFuture<BigDecimal> final = p1.thenCombine(p2,
        (price, coupon) -> price.minus(coupon));

// ③ 聚合：allOf 等全部 / anyOf 任一完成
CompletableFuture.allOf(f1, f2, f3).join();     // 常配合后续统一取值
CompletableFuture.anyOf(主源, 备源, 缓存源);      // 竞速，谁快用谁

// ④ 异常传播与恢复
CompletableFuture.supplyAsync(() -> risky())
        .exceptionally(ex -> fallback())         // 出错给兜底值
        .handle((result, ex) -> ex == null ? result : deal(ex));  // 无论成败都执行

// ⑤ 超时（JDK 9+）
asyncQuery()
        .orTimeout(500, TimeUnit.MILLISECONDS)          // 超时抛 TimeoutException
        .completeOnTimeout(DEFAULT, 500, MILLISECONDS); // 超时给默认值
  • 异常规则：链条任一环抛异常，后续正常步骤全被跳过，直到 exceptionally/handle 接住——try/catch 的异步版；
  • thenCompose vs thenCombine：串行接龙用 Compose（flatMap 语义），并行合流用 Combine；
  • allOf 返回 CompletableFuture<Void>，要拿各结果得在 join 后逐个 get——封装个工具方法更顺手。
常见坑① 链中间thenApply里调阻塞IO——挤占 commonPool；② 忘了 exceptionally 也没 handle，异常静默消失；③ 在链条里改共享可变状态又搞出竞态——异步代码同样要遵守不可变/ confinement 原则。

✓ 本章小结

要点一句话
Future 痛点get 阻塞、不能链式、不能组合、无回调
链式supplyAsync 起、thenApply 转、thenAccept 收
编排thenCompose 串行、thenCombine 并行合流、allOf/anyOf 聚合竞速
异常沿链传播，exceptionally 兜底、handle 统一处理
工程要点传自定义线程池、设超时、别在链中做阻塞 IO

✎ 本章习题

A 基础用 supplyAsync + thenApply + thenAccept 组成一条链：异步取用户名 → 转大写 → 打印；分别用默认池和自定义池跑，用打印线程名观察差异。
B 进阶实现"聚合查询"：并行查用户/订单/优惠券三个服务（各 sleep 模拟耗时），allOf 等待后合并成一份展示对象；把其中一个改成必定抛异常，用 exceptionally 给出兜底数据——对比去掉兜底后的行为。
C 挑战实现"多源竞速缓存"：缓存源（快但可能 miss）、主库源（稳但慢）两个 CompletableFuture，anyOf 竞速取先完成者，若缓存 miss 则再走主库并异步回填缓存；全部用 CompletableFuture 组合实现，禁止阻塞 get 出现在中间环节。
