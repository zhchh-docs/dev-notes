47.1 线程与进程

  • 进程：操作系统资源分配的基本单位，一个 JVM 是一个进程；
  • 线程：CPU 调度的基本单位，一个进程里多条线程共享堆和方法区，各自独享栈、程序计数器；
  • 共享带来效率也带来冲突：两条线程同时改一个对象的字段——数据竞争（第 49-55 章的主题）；
  • Java 里线程是"一对一"映射到操作系统内核线程的（JDK 21 之前的默认模型），所以 Java 线程数有上限（默认栈 1MB，几千个就吃力）；
  • JDK 21 引入虚拟线程（Virtual Thread，Project Loom）：JVM 调度的轻量线程，百万级并发——新项目值得关注，但本章先建立经典模型。

47.2 三种创建方式

// 方式一：继承 Thread（少用——Java 单继承，占了位置就没法继承别的类）
class MyThread extends Thread {
    public void run() { System.out.println("hello from " + getName()); }
}
new MyThread().start();

// 方式二：实现 Runnable（推荐解耦：任务和线程分离，还能配线程池）
Runnable task = () -> System.out.println("hello from " + Thread.currentThread().getName());
new Thread(task, "worker-1").start();

// 方式三：实现 Callable（能返回结果、能抛受检异常）
Callable<Long> calc = () -> {
    Thread.sleep(100);
    return System.currentTimeMillis();
};
  • start() 才是启动线程，run() 直接调用只是普通方法——经典面试坑；
  • Runnable 无返回值、不能抛受检异常；Callable 用 Future 接结果（配合线程池，见第 52 章）；
  • 线程命名：new Thread(task, "order-worker-1")——线上看线程名排查问题，别用默认的 Thread-0；
  • main 线程结束不等于 JVM 结束：还有非守护线程在跑，JVM 就等着。守护线程（setDaemon(true)）随主线程消亡，GC 等就是守护线程。

47.3 线程池预告

// 正确姿势：把任务丢给线程池，复用线程，别来一条 new 一条
ExecutorService pool = Executors.newFixedThreadPool(4);
pool.submit(() -> { /* 任务 */ });        // submit 返回 Future
pool.shutdown();                          // 不再接任务，已提交的跑完
常见坑① for 循环里 new Thread 跑 10000 个任务——创建/销毁开销拖垮系统；② 用完线程池不 shutdown，JVM 不退出（非守护线程）；③ Executors 的 newFixedThreadPool 用无界队列，OOM 风险——第 52 章详解为什么别用。
创建线程是入门，管理线程是工程：把"新建"的冲动留给测试代码，生产一律走线程池。

✓ 本章小结

要点一句话
进程/线程进程是资源单位，线程是调度单位；线程共享堆、独享栈
创建方式继承 Thread（占继承位，少用）/ Runnable（解耦，推荐）/ Callable（带返回值）
start vs runstart 起线程，run 只是普通方法调用
守护线程setDaemon(true)，主线程结束它跟着结束
工程化生产用线程池；裸 new Thread 是反模式

✎ 本章习题

A 基础分别用继承 Thread、实现 Runnable、Lambda 三种方式创建线程打印 1~10，观察三种方式下 Thread.currentThread().getName() 的默认命名；再给线程起自定义名字。
B 进阶写 Callable 任务计算 1+2+...+100，用 FutureTask 包装后在主线程 get 结果；对比：如果不用 FutureTask，主线程怎么知道子线程算完了？思考同步等待的代价。
