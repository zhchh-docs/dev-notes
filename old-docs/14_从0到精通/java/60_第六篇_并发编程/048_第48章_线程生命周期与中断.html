48.1 六种状态

NEW（新建）          ── start() ──▶ RUNNABLE（可运行）
                                       │ 拿到 CPU 时间片就在跑，
                                       │ 没拿到就在就绪队列等
RUNNABLE ── 阻塞/等待事件 ──▶ BLOCKED（等锁）      synchronized 拿不到锁
         ── wait/join ────▶ WAITING（无限等）      wait()、join() 无超时
         ── sleep/wait(超时) ▶ TIMED_WAITING（限时等） sleep(n)、wait(n)
任何状态 ── run() 结束/异常 ──▶ TERMINATED（终止）
  • RUNNABLE 把"运行中"和"就绪中"合并了——JVM 视角只看你是否愿意被调度，占不占 CPU 是 OS 的事；
  • BLOCKED 专指等对象锁（synchronized）；LOCK 接口（ReentrantLock）等锁表现为 WAITING/TIMED_WAITING，jstack 里显示 parking；
  • 线程只能从阻塞/等待中自然返回或被打断——这就是下一节的主题。

48.2 协作式中断

为什么 stop() 被废弃？强行杀死线程，锁不会释放、数据停在半路——就像拔掉运行中机器的电源。Java 选择了协作式中断：调用方发"请求"，被中断方自己决定何时何地响应。

Thread t = new Thread(() -> { /* ... */ });
t.start();
t.interrupt();                 // 不是"杀死"，是置中断标志位 = true

// 被中断方查询标志
t.isInterrupted()              // 查标志，不清除
Thread.interrupted()           // 静态方法，查当前线程并【清除】标志——坑！

// 阻塞方法被 interrupt 会抛 InterruptedException 并清除标志
Thread.sleep(1000);            // 等待时被 interrupt → 抛异常
  • sleep/wait/join 是可中断的：收到中断信号抛 InterruptedException，同时清除中断标志——所以 catch 里通常要 Thread.currentThread().interrupt() 恢复标志再退出；
  • 循环任务的标准写法：while (!Thread.currentThread().isInterrupted()) { ... }；
  • 吞掉 InterruptedException 是经典错误——等于拒绝停机请求，线程池 shutdown 时任务不肯停。

48.3 优雅停止线程

public class OrderWorker implements Runnable {
    private volatile boolean running = true;    // 标志位（volatile 保证可见）

    public void stop() { running = false; }

    @Override
    public void run() {
        while (running) {
            Order order = queue.poll(1, TimeUnit.SECONDS);   // 限时阻塞
            if (order == null) continue;                     // 没任务，回来查标志
            if (Thread.currentThread().isInterrupted()) {    // 双保险
                System.out.println("被中断，保存现场后退出");
                break;
            }
            process(order);
        }
        cleanup();   // 收尾：刷缓存、关资源
    }
}
  • 模式：标志位 + 限时阻塞 + 响应中断——三者齐了才能秒停；
  • shutdown 场景：executor.shutdown() 等任务跑完；shutdownNow() 给所有线程发 interrupt；
  • stop 标志用 volatile：否则你的修改可能一直留在自己线程的工作内存里，别的线程永远看不到（第 50 章细讲）。
停止线程 = 发信号 + 对方配合；优雅 = 它有机会保存现场、释放资源，而不是被当场击毙。

✓ 本章小结

要点一句话
六态NEW / RUNNABLE / BLOCKED / WAITING / TIMED_WAITING / TERMINATED
BLOCKED专指 synchronized 等锁；ReentrantLock 等锁显示 parking
中断协作式：interrupt 置标志，阻塞方法抛 InterruptedException 并清标志
吞异常catch 里要恢复中断：Thread.currentThread().interrupt()
优雅停止volatile 标志 + 限时阻塞 + 响应中断 + 收尾逻辑

A 基础写一个线程 sleep(5000)，主线程 1 秒后 interrupt 它，捕获 InterruptedException 并打印"收到中断信号"；再验证 interrupt 后 isInterrupted() 的值（注意抛异常时标志被清了）。
