96.1 @EnableScheduling 与定时任务概览

一句话定位：启动类加 @EnableScheduling 开启 Spring 调度容器；任务 Bean 的方法标注 @Scheduled，调度器按规则在后台线程触发执行；方法必须无参、返回 void（或 Future 供编排）。

package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableScheduling;

@SpringBootApplication
@EnableScheduling                 // 开启定时任务调度容器
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
package com.example.demo.task;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

@Component
public class ReportTask {

    private static final Logger log = LoggerFactory.getLogger(ReportTask.class);

    /** 启动后延迟 10 秒执行，之后每 5 分钟一次 */
    @Scheduled(initialDelay = 10_000, fixedRate = 300_000)
    public void generateDailyReport() {
        log.info("生成定时报表，当前线程：{}", Thread.currentThread().getName());
        // 报表生成、数据汇总逻辑
    }
}

96.2 fixedRate / fixedDelay / cron 对比

一句话定位：固定间隔按时间轴触发，cron 按日历规则触发；任务耗时可能超过间隔时，三者行为差异直接决定任务是否堆积。

方式语义计时起点适用场景
fixedRate每 N 毫秒触发一次上一次任务开始时刻周期短、耗时稳定的轮询；耗时超间隔会排队堆积
fixedDelay上一次结束后再等 N 毫秒触发上一次任务结束时刻任务之间需要留出处理间隔的清理、对账类任务
cron按日历表达式触发（秒/分/时/日/月/周）日历规则命中时刻每日凌晨、每周一、每月 1 号等自然时间点
initialDelay启动后延迟 N 毫秒首次执行应用启动时刻避免启动期与初始化抢资源，常与上两者组合
 
@Component
public class ScheduleExamples {

    // 每 30 秒一次，启动 5 秒后首次执行
    @Scheduled(initialDelay = 5_000, fixedRate = 30_000)
    public void pollQueue() { }

    // 上一次执行结束 10 秒后再执行下一次
    @Scheduled(fixedDelay = 10_000)
    public void cleanTempFiles() { }

    // 每天凌晨 2 点执行（cron 六段）
    @Scheduled(cron = "0 0 2 * * ?")
    public void nightlyBackup() { }

    // 每周一上午 9 点执行
    @Scheduled(cron = "0 0 9 ? * MON")
    public void weeklyReport() { }
}

96.3 cron 表达式字段表

一句话定位：Spring 的 @Scheduled cron 使用六段格式（秒 分 时 日 月 周），从左到右精度递减；日与周互斥，其中一个用 ? 表示不指定。

位置取值范围常用写法与示例
秒0–590 表示整秒；*/10 表示每 10 秒
分0–590 整点；15,30,45 表示三个半点
时0–232 表示凌晨 2 点；9–18 表示 9 点到 18 点每小时
日1–311 表示每月 1 号；与周互斥，另一方写 ?
月1–12 或 JAN–DEC* 每月；6 表示六月
周1–7 或 SUN–SATMON 周一；与日互斥，另一方写 ?
表达式含义
0 0 2 * * ?每天凌晨 2:00:00
0 30 9 ? * MON-FRI工作日上午 9:30:00
0 0 0 1 * ?每月 1 号零点整
0 */5 * * * ?每 5 分钟整（秒位 0，分位每 5 分钟）
0 0 12 ? * SUN每周日中午 12 点整
注意Spring cron 六段比 Quartz 七段（含年）少一段；日与周同时指定会互相冲突，必须把其中一段置 ?。任务方法抛异常会被调度器记录日志，下一轮仍按规则触发，但要在方法内做好异常隔离。

96.4 @Async 与线程池配置

一句话定位：接口响应前不需要等待的动作（发邮件、写日志、推送通知）用 @Async 异步执行；默认使用 SimpleAsyncTaskExecutor 每次新建线程，生产环境必须替换为自定义 ThreadPoolTaskExecutor。

package com.example.demo.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableAsync;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

import java.util.concurrent.Executor;
import java.util.concurrent.ThreadPoolExecutor;

@Configuration
@EnableAsync                          // 开启异步方法支持
public class AsyncConfig {

    @Bean("bizExecutor")
    public Executor bizExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);              // 核心线程数
        executor.setMaxPoolSize(16);              // 最大线程数
        executor.setQueueCapacity(200);           // 等待队列容量
        executor.setThreadNamePrefix("biz-async-");
        // 队列满后由调用线程兜底执行，避免任务静默丢弃
        executor.setRejectedExecutionHandler(
                new ThreadPoolExecutor.CallerRunsPolicy());
        executor.initialize();
        return executor;
    }
}
@Service
public class NotifyService {

    private static final Logger log = LoggerFactory.getLogger(NotifyService.class);

    // 指定使用 bizExecutor 线程池；方法返回 void 或 Future<T>
    @Async("bizExecutor")
    public void sendWelcomeMail(Long userId) {
        log.info("异步发送欢迎邮件，用户：{}，线程：{}",
                userId, Thread.currentThread().getName());
        // 邮件发送逻辑；异常由 96.5 的异步异常处理器接管
    }
}
@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService userService;
    private final NotifyService notifyService;

    public UserController(UserService userService, NotifyService notifyService) {
        this.userService = userService;
        this.notifyService = notifyService;
    }

    @PostMapping
    public Result<UserVO> create(@Valid @RequestBody UserCreateRequest request) {
        UserVO user = userService.create(request);
        notifyService.sendWelcomeMail(user.id());   // 不等待邮件结果即返回
        return Result.ok(user);
    }
}
自调用失效@Async 与 @Transactional 一样基于 AOP 代理：同类内部方法直接调用另一个 @Async 方法，绕过代理导致异步不生效；异步方法必须放在独立 Bean 中，由外部调用。

96.5 异步异常处理与分布式任务

一句话定位：void 返回的异步方法抛异常不会回到调用方，需要实现 AsyncUncaughtExceptionHandler 统一记录；多实例部署时本地调度器会在每个实例重复触发任务，需要分布式协调机制避免重复执行。

package com.example.demo.config;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.aop.interceptor.AsyncUncaughtExceptionHandler;
import org.springframework.context.annotation.Configuration;
import java.lang.reflect.Method;

@Configuration
public class AsyncExceptionConfig implements AsyncUncaughtExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(AsyncExceptionConfig.class);

    @Override
    public void handleUncaughtException(Throwable ex, Method method, Object... params) {
        log.error("异步任务异常：方法 {}，参数 {}，原因：{}",
                method.getName(), params, ex.getMessage(), ex);
        // 可在此接入告警通知：邮件、短信、监控平台 Webhook
    }
}

分布式定时任务方向（了解即可）：单实例下 @Scheduled 足够；部署多个副本后每个实例都会执行同一任务，重复对账、重复发通知。常见解法：

  • ShedLock：基于数据库或 Redis 给定时任务加分布式锁，同一时刻只允许一个实例抢到执行权；
  • xxl-job / Quartz 集群：任务调度中心统一分发，执行器注册后领取任务，支持分片、失败重试与控制台管理；
  • 消息驱动：任务触发消息进入队列，由单一消费组串行消费，天然避免并发重复执行。

96.6 常见坑排查

坑：调度默认单线程Spring 定时任务默认使用单个调度线程，一个任务卡顿会阻塞其他任务；多任务场景可配置 TaskScheduler 线程池，或把耗时任务拆分到异步线程池执行。

坑：时区不对容器默认 UTC 时区时，cron 按 UTC 触发会比北京时间晚 8 小时；部署环境显式设置 spring.jackson.time-zone 与 JVM 时区（TimeZone.setDefault 或容器 TZ 环境变量）。

坑：任务重叠执行fixedRate 下上一轮未结束新一轮又开始，操作同一批数据造成重复处理；任务需具备幂等性，或改用 fixedDelay、加锁与并发阈值控制。

坑：@Async 失效同类自调用、方法非 public、未开启 @EnableAsync、线程池 Bean 名写错，都会导致异步退化为同步执行；排查时先打印线程名确认是否进入指定线程池。
