88.1 application.yml 语法与类型绑定

一句话定位：SpringBoot 默认从 classpath 根目录读取 application.yml（或 application.properties），用缩进表达层级，把配置项按命名空间组织成树，启动时由 Environment 统一收纳。

# src/main/resources/application.yml
server:
  port: 8080                      # 服务端口
  servlet:
    context-path: /api            # 上下文路径（可选）

spring:
  application:
    name: demo-service
  datasource:
    url: jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: "123456"           # 含特殊字符时加引号
    driver-class-name: com.mysql.cj.jdbc.Driver

demo:
  client:
    timeout: 3000                # 毫秒
    enabled: true
    allowed-origins:             # 列表写法（短横线 + 空格）
      - https://a.example.com
      - https://b.example.com
    features:
      cache: true
      retry: 3

语法要点

  • 缩进即层级：同一层级对齐，子项比父项多缩进两格（或四格，全文统一）；禁止用 Tab，YAML 只认空格；
  • 键名用中划线：driver-class-name 对应 Java 字段 driverClassName，这就是松散绑定（88.5）；
  • 类型自动推断：数字、布尔、字符串、列表、嵌套 Map 均可直接书写；含 #、:、开头特殊符号的值要加引号；
  • properties 等价：spring.datasource.url=... 与 yml 树状写法完全等价，团队可任选其一，不混用最稳妥。
类型yml 写法绑定到 Java 字段
字符串name: demoString name
整数 / 长整数timeout: 3000int / long timeout
布尔enabled: trueboolean enabled
列表allowed-origins: 后接 - 项List<String> allowedOrigins
嵌套对象features: 下再缩进一层内部类 Features features
时间 / 数据大小period: 30s；max-size: 10MBDuration / DataSize（自动换算）

88.2 @Value 与 @ConfigurationProperties 对比

一句话定位：@Value 是"单点注入"，一个注解取一个值，写法轻；@ConfigurationProperties 是"整组绑定"，把前缀下的一整棵配置树映射到一个 POJO，适合成组配置与校验。

// 路线一：@Value 逐个注入，适合零散、少量配置
@Component
public class AppSettings {

    @Value("${demo.client.timeout:2000}")        // 冒号后是缺省值
    private int timeout;

    @Value("${demo.client.enabled:true}")
    private boolean enabled;

    @Value("${spring.application.name}")
    private String appName;
}
// 路线二：@ConfigurationProperties 整组绑定，POJO 持有一整段配置
@Component
@ConfigurationProperties(prefix = "demo.client")
public class ClientProperties {

    private int timeout = 2000;                 // 缺省值写在字段上
    private boolean enabled = true;
    private List<String> allowedOrigins = new ArrayList<>();
    private Features features = new Features();

    // getter / setter 不可省略（绑定靠 setter）
    public int getTimeout() { return timeout; }
    public void setTimeout(int timeout) { this.timeout = timeout; }
    public boolean isEnabled() { return enabled; }
    public void setEnabled(boolean enabled) { this.enabled = enabled; }
    public List<String> getAllowedOrigins() { return allowedOrigins; }
    public void setAllowedOrigins(List<String> v) { this.allowedOrigins = v; }
    public Features getFeatures() { return features; }
    public void setFeatures(Features f) { this.features = f; }

    public static class Features {
        private boolean cache;
        private int retry;
        public boolean isCache() { return cache; }
        public void setCache(boolean cache) { this.cache = cache; }
        public int getRetry() { return retry; }
        public void setRetry(int retry) { this.retry = retry; }
    }
}
维度@Value@ConfigurationProperties
绑定粒度单个属性，注解写在字段上整组属性映射到 POJO，前缀声明在类上
类型安全弱：取值后手工转换，类型错误到注入期才暴露强：字段类型与 setter 驱动绑定，启动期即可校验
列表 / 嵌套对象支持繁琐，需 SpEL 表达式拼装原生支持 List、Map、内部类嵌套
元数据提示无配合配置元数据可在 IDE 获得补全与文档提示
校验需手工判断类上可加 @Validated 与 jakarta.validation 注解（第 90 章）
适用场景零散单点配置、缺省值兜底成组业务配置、第三方客户端参数封装（推荐主力路线）
选型结论业务成组配置一律走 @ConfigurationProperties；@Value 只留给个别零散开关或需要 SpEL 默认值的场景。

88.3 多环境 profile 切换

一句话定位：同一套代码在开发、测试、生产环境连不同数据库、开不同开关；profile 机制让每个环境一份独立配置文件，启动时声明激活哪一份。

# src/main/resources/application.yml（公共配置，三套环境共享）
spring:
  application:
    name: demo-service
  profiles:
    active: dev                 # 默认激活 dev；打包/部署时可被外部覆盖

demo:
  client:
    timeout: 2000
# src/main/resources/application-dev.yml（开发环境）
server:
  port: 8081
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo_dev?useSSL=false&serverTimezone=Asia/Shanghai
    username: dev
    password: dev123
demo:
  client:
    enabled: true
    features:
      cache: false              # 开发环境关闭缓存，便于调试
# src/main/resources/application-prod.yml（生产环境）
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://10.0.0.8:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai
    username: app
    password: ${DB_PASSWORD}  # 敏感值走环境变量，不写进仓库
demo:
  client:
    enabled: true
    features:
      cache: true

三种激活方式（优先级从低到高）

  1. 配置文件内声明：spring.profiles.active=dev，作为默认值；
  2. 命令行参数：java -jar app.jar --spring.profiles.active=prod；
  3. 环境变量 / 系统属性：SPRING_PROFILES_ACTIVE=prod（环境变量名大写下划线形式），容器部署最常用。

88.4 配置优先级阶梯

一句话定位：同一个配置项可以从十多个来源注入，SpringBoot 按固定顺序排列，位置越靠前优先级越高，高优先级覆盖低优先级。下表只列实战中最常打交道的层级。

优先级来源说明与示例
1（最高）命令行参数--server.port=9090，java -jar 后直接追加
2操作系统环境变量SERVER_PORT=9090，容器 / 云平台注入常用
3JVM 系统属性-Dserver.port=9090
4jar 包外部 application-{profile}.yml与 jar 同级目录的 config/ 子目录或当前目录，便于不改包改配置
5jar 包内部 application-{profile}.ymlclasspath 内 profile 文件
6jar 包外部 application.yml部署目录下的外置配置文件
7（最低）jar 包内部 application.yml代码仓库内的默认公共配置

配置名称之间还有命名映射规则：环境变量 SERVER_PORT、系统属性 server.port、配置文件 server.port 指向同一个键，这也是松散绑定在环境维度的体现。

部署惯例生产环境把数据库密码、第三方密钥放在环境变量或部署平台密钥管理中，仓库内 application-prod.yml 只保留结构与非敏感默认值；上表优先级保证外部注入能覆盖仓库内默认值。

88.5 松散绑定、校验与占位符

松散绑定（Relaxed Binding）

配置键写法不必与字段名逐字符一致：allowed-origins、allowedOrigins、ALLOWED_ORIGINS 都能绑定到 allowedOrigins 字段。但 @Value("${demo.client.allowedOrigins}") 走的是精确匹配，不会做松散转换——这也是两种路线的差异之一。

// 配置类 + 启动期校验：缺字段、格式错在启动时直接失败
@Validated
@Component
@ConfigurationProperties(prefix = "demo.client")
public class ClientProperties {

    @NotNull(message = "回调地址不能为空")
    private String callbackUrl;

    @Min(100) @Max(60000)
    private int timeout;

    @Pattern(regexp = "^https?://.*")
    private String baseUrl;

    // getter / setter 略
}

占位符与默认值

spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/demo
    username: ${DB_USER:root}
    password: ${DB_PASSWORD:}        # 未提供则为空串
demo:
  greeting: 你好，${spring.application.name}
  • ${键名:默认值}：环境变量或其他配置源取不到时用冒号后的默认值；
  • 占位符可以引用另一个配置键，形成配置嵌套；
  • 占位符解析失败且无默认值时启动期抛 IllegalArgumentException，把问题挡在上线前。

88.6 常见坑排查

坑：YAML 缩进错乱把 datasource 缩进多了一格、或一行混用 Tab，解析器报 yaml.scanner.ScannerError。排查时把出错文件贴进 YAML 校验器，确认空格层级与官方模板逐字对齐。

坑：配置改了不生效先核对优先级：命令行 / 环境变量是否用更高优先级覆盖了文件值；再确认 profile 文件命名是 application-{profile}.yml 且放在 classpath 根；最后确认 @ConfigurationProperties 类存在 setter、字段名与配置键对应。

坑：@Value 取不到列表试图用 @Value("${demo.allowed-origins}") 直接注入 List，SpEL 只会把逗号串当成一个字符串；列表绑定必须走 @ConfigurationProperties。

注意3.x 基线中 spring.profiles.active 在 application.yml 内声明仍有效；若一个类上同时用 @Profile 注解条件化 Bean，激活的 profile 名称需与注解值完全一致（区分大小写）。

✓ 本章小结

要点一句话
yml 语法缩进表达层级，键名中划线，类型自动推断，禁用 Tab
两条注入路线@Value 单点零散；@ConfigurationProperties 成组、类型安全、可校验（推荐主力）
profile 机制application-{环境}.yml 分组，active 声明 / 命令行 / 环境变量逐级覆盖
优先级阶梯命令行 > 环境变量 > 系统属性 > 外置文件 > 包内 profile 文件 > 包内公共文件
绑定细节松散绑定适用于配置类；@Value 精确匹配；占位符支持缺省值与跨键引用

✎ 本章习题

A 基础复述：@Value 与 @ConfigurationProperties 的三点差异；profile 文件如何命名；命令行参数与包内 application.yml 谁优先？
B 进阶为上一章工程编写 dev 与 prod 两套配置：dev 用本地库、prod 数据库连接走环境变量占位符；用 --spring.profiles.active=prod 启动，观察端口与数据源日志；给一组第三方 API 参数写 @ConfigurationProperties 配置类并加 @Min/@Max 校验。
