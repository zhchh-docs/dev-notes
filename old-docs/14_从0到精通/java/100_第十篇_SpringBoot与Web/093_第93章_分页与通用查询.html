93.1 PageHelper 原理与用法

一句话定位：PageHelper 是 MyBatis 拦截器插件：调用 startPage(pageNum, pageSize) 把分页参数放进 ThreadLocal，紧随其后的第一条查询 SQL 被拦截器改写为 LIMIT 分页语句并额外执行 count 查询，结果包装成 PageInfo。

<dependency>
    <groupId>com.github.pagehelper</groupId>
    <artifactId>pagehelper-spring-boot-starter</artifactId>
    <version>2.1.0</version>
</dependency>
@Service
public class UserService {

    private final UserMapper userMapper;

    public UserService(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    public PageInfo<UserVO> pageQuery(String keyword, Integer status,
                                       int pageNum, int pageSize) {
        // 1. 开启分页：只对紧随其后的第一条查询生效
        PageHelper.startPage(pageNum, pageSize);

        // 2. 紧跟一条 Mapper 查询（条件动态 SQL 写在 XML 中）
        List<User> list = userMapper.selectByCondition(keyword, status);

        // 3. 包装为 PageInfo，含 total、pageNum、pages、list 等字段
        PageInfo<User> page = new PageInfo<>(list);
        return page.convert(UserVO::from);
    }
}

93.2 MyBatis-Plus 分页插件

一句话定位：MyBatis-Plus（MP）是 MyBatis 的增强工具，内置 CRUD 与条件构造器；分页通过注册 PaginationInnerInterceptor 拦截器实现，分页信息封装在 Page 对象里，比 ThreadLocal 方案更显式、线程安全。

<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
    <version>3.5.9</version>
</dependency>
// 分页拦截器配置
package com.example.demo.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        PaginationInnerInterceptor pagination =
                new PaginationInnerInterceptor(DbType.MYSQL);
        pagination.setMaxLimit(50L);          // 单页最大条数，防止前端传超大 size
        interceptor.addInnerInterceptor(pagination);
        return interceptor;
    }
}
// 实体类与 Mapper（Mapper 继承 BaseMapper 即获得通用 CRUD）
@TableName("sys_user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String userName;
    private String email;
    private Integer status;
    // getter / setter 略
}

public interface UserMapper extends BaseMapper<User> { }
@Service
public class UserService {

    private final UserMapper userMapper;

    public UserService(UserMapper userMapper) { this.userMapper = userMapper; }

    public Page<User> page(int pageNum, int pageSize, String keyword) {
        Page<User> page = new Page<>(pageNum, pageSize);
        LambdaQueryWrapper<User> wrapper = Wrappers.<User>lambdaQuery()
                .like(StringUtils.hasText(keyword), User::getUserName, keyword)
                .orderByDesc(User::getCreatedAt);
        // 自动执行 count 与分页 SQL，结果回填到 page 对象
        return userMapper.selectPage(page, wrapper);
    }
}
维度PageHelperMyBatis-Plus 分页
参数传递ThreadLocal，startPage 紧邻查询Page 对象作为方法参数，显式传递
侵入性不写 SQL，兼容现有 XML Mapper实体继承约定，Mapper 继承 BaseMapper
条件拼装条件写在 XML 动态 SQL 中Wrapper 链式拼装，类型安全
线程模型ThreadLocal 用完即清，异步线程不继承对象参数传递，天然线程安全
适用场景遗留 MyBatis 工程增量加分页新工程希望减少 XML 与重复 CRUD

93.3 分页参数模型与统一返回

一句话定位：无论底层用哪个分页方案，接口层都收敛到同一套入参与返回结构：入参 page/size 校验默认值，返回 list/total/page/size/pages，前端分页组件直接对接。

// 分页入参（查询条件 DTO 可继承本类）
public class PageQuery {

    @Min(value = 1, message = "页码不能小于 1")
    private Integer page = 1;

    @Min(value = 1, message = "每页条数不能小于 1")
    @Max(value = 50, message = "每页条数不能超过 50")
    private Integer size = 10;

    public int getOffset() { return (page - 1) * size; }
    // getter / setter 略
}

// 分页出参泛型结构
public record PageResult<T>(List<T> list, long total, int page, int size, int pages) {

    public static <T> PageResult<T> of(List<T> list, long total, int page, int size) {
        int pages = size == 0 ? 0 : (int) Math.ceil((double) total / size);
        return new PageResult<>(list, total, page, size, pages);
    }
}
# GET /api/users?page=1&size=10&keyword=张
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [ { "id": 1, "name": "张三" } ],
    "total": 23,
    "page": 1,
    "size": 10,
    "pages": 3
  }
}
纪律page、size 必须在入口校验范围（第 90 章 Validation）；偏移量由后端按 (page-1)*size 计算，前端只传页码不传 offset，避免非法偏移。

93.4 Wrapper 条件构造器

一句话定位：MP 的 Wrapper 用链式方法表达 where 条件；QueryWrapper 写字段名字符串，LambdaQueryWrapper 用方法引用，编译期检查列名，重构安全，推荐后者。

方法条件语义等价 SQL 片段
eq(column, value)等于status = ?
ne(column, value)不等于status <> ?
gt / ge / lt / le大于 / 大于等于 / 小于 / 小于等于age >= ?
like(column, value)模糊匹配两侧 %name LIKE CONCAT('%', ?, '%')
likeLeft / likeRight左侧 / 右侧模糊name LIKE CONCAT('%', ?)
in(column, collection)集合包含id IN (?, ?, ?)
between(column, left, right)区间闭区间created_at BETWEEN ? AND ?
orderByAsc / orderByDesc排序ORDER BY created_at DESC
condition 参数位首个布尔参数为 false 时跳过该条件动态条件天然支持
 
public PageResult<UserVO> search(UserQuery query) {
    Page<User> page = new Page<>(query.getPage(), query.getSize());

    LambdaQueryWrapper<User> wrapper = Wrappers.<User>lambdaQuery()
            .like(StringUtils.hasText(query.getKeyword()),
                    User::getUserName, query.getKeyword())
            .eq(query.getStatus() != null, User::getStatus, query.getStatus())
            .between(query.getStartTime() != null,
                    User::getCreatedAt, query.getStartTime(), query.getEndTime())
            .orderByDesc(User::getCreatedAt);

    Page<User> result = userMapper.selectPage(page, wrapper);
    List<UserVO> voList = result.getRecords().stream()
            .map(UserVO::from).toList();
    return PageResult.of(voList, result.getTotal(), query.getPage(), query.getSize());
}

93.5 逻辑删除与自动填充

一句话定位：逻辑删除不执行 DELETE，而是把删除标记字段置为已删值，所有查询自动追加未删条件；创建时间、更新时间等公共字段由 MP 自动填充，业务代码无需手写。

@TableName("sys_user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String userName;

    @TableLogic                                   // 逻辑删除标记
    private Integer deleted;

    @TableField(fill = FieldFill.INSERT)          // 插入时填充
    private LocalDateTime createdAt;

    @TableField(fill = FieldFill.INSERT_UPDATE)  // 插入与更新时填充
    private LocalDateTime updatedAt;
}
# application.yml：逻辑删除字段取值约定
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
// 自动填充处理器：插入/更新时回填公共字段
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createdAt",
                LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updatedAt",
                LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updatedAt",
                LocalDateTime.class, LocalDateTime.now());
    }
}

开启逻辑删除后，deleteById 实际执行 UPDATE sys_user SET deleted=1 WHERE id=?；普通查询自动追加 deleted = 0 条件，历史数据保留可追溯。

93.6 常见坑排查

坑：count 不准PageHelper 对带 LEFT JOIN、分组 GROUP BY 的复杂 SQL 自动 count 会失真；此时手写 count 查询，或改用 MP 分页并自行校验总数。联表分页优先在主表分页，关联字段延后组装。

坑：Wrapper 被复用同一个 Wrapper 对象先用于 count 查询、又用于数据查询，条件被二次拼接导致 SQL 异常；每次查询新建 Wrapper，不要把它声明为字段或缓存复用。

坑：Page 对象随意 new 后传错MP 的 selectPage 会把 records 与 total 回填到传入的 Page；不要用外部新建的 Page 取数据，也不要把分页对象在多个查询间传递复用。

坑：PageHelper startPage 错位startPage 之后不是紧跟 Mapper 查询（中间插入日志、条件构造、其他 Mapper 调用），分页参数会被错误语句消费，下一条查询反而不分页；保持 startPage 与目标查询相邻。

选型提醒同一工程不要同时上 PageHelper 与 MP 分页两套机制，拦截器叠加容易行为混乱；新工程优先 MP，遗留工程继续 PageHelper。
