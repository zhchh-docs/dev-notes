90.1 校验注解清单

一句话定位：校验注解标注在 DTO 字段上声明约束，Hibernate Validator（参考实现）在对象被校验时逐条检查；注解名与约束一一对应，message 可覆盖默认提示。

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
注解约束适用类型与备注
@NotNull值不能为 null字符串、数字、对象；空串 "" 仍通过
@NotBlank字符串非 null 且去空格后长度大于 0仅字符串；用户名、密码必填首选
@NotEmpty非 null 且非空（字符串长度、集合大小、数组长度）字符串、List、数组、Map
@Size(min, max)长度 / 集合大小区间字符串、集合、数组
@Min(value) / @Max(value)数字最小 / 最大值BigDecimal、int、long 等数值类型
@Positive / @PositiveOrZero正数 / 非负金额、数量类字段常用
@Email符合邮箱格式字符串；不强制顶级域名时可配合 @Pattern
@Pattern(regexp)匹配正则表达式手机号、身份证、密码强度等自定义格式
@DecimalMin / @DecimalMax大数值区间金额等 BigDecimal 字段
@Past / @Future日期在过去 / 未来LocalDate、LocalDateTime、Date
三兄弟别混用@NotNull 拦不住空串；@NotBlank 只用于字符串；@NotEmpty 管集合与字符串的"非空"。字符串必填写 @NotBlank，集合必填写 @NotEmpty，数字必填写 @NotNull。

90.2 @Valid 触发校验

一句话定位：DTO 上写满注解只是"声明规则"；控制器方法参数前加 @Valid，Spring MVC 才会在进入方法体前执行校验，失败直接抛 MethodArgumentNotValidException。

package com.example.demo.dto;

import jakarta.validation.constraints.*;

public class UserCreateRequest {

    @NotBlank(message = "姓名不能为空")
    @Size(min = 2, max = 20, message = "姓名长度须在 2 到 20 之间")
    private String name;

    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;

    @Min(value = 0, message = "年龄不能为负数")
    @Max(value = 150, message = "年龄超出合理范围")
    private Integer age;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String phone;

    // getter / setter 略（校验通过 setter 访问字段）
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }
    public String getPhone() { return phone; }
    public void setPhone(String phone) { this.phone = phone; }
}
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/users")
public class UserController {

    @PostMapping
    public Result<UserVO> create(
            @Valid @RequestBody UserCreateRequest request) {   // @Valid 触发校验
        return Result.ok(userService.create(request));
    }
}

90.3 @Validated 分组校验

一句话定位：新建与更新共用一个 DTO，但约束不同——新建时 id 为空、更新时 id 必填。分组校验用空接口标识分组，注解上指定 groups，控制器参数用 @Validated(分组类) 选择本次生效的约束。

// 分组标识接口：空接口，仅用于类型区分
public interface CreateGroup { }
public interface UpdateGroup { }

public class UserRequest {

    @NotNull(groups = UpdateGroup.class, message = "更新时 id 必填")
    private Long id;

    @NotBlank(groups = {CreateGroup.class, UpdateGroup.class},
              message = "姓名不能为空")
    @Size(min = 2, max = 20, groups = {CreateGroup.class, UpdateGroup.class})
    private String name;

    @Email(groups = {CreateGroup.class, UpdateGroup.class}, message = "邮箱格式不正确")
    private String email;

    // getter / setter 略
}
import org.springframework.validation.annotation.Validated;

@RestController
@RequestMapping("/api/users")
public class UserController {

    @PostMapping
    public Result<UserVO> create(
            @Validated(CreateGroup.class) @RequestBody UserRequest request) {
        return Result.ok(userService.create(request));
    }

    @PutMapping("/{id}")
    public Result<UserVO> update(
            @PathVariable Long id,
            @Validated(UpdateGroup.class) @RequestBody UserRequest request) {
        request.setId(id);
        return Result.ok(userService.update(request));
    }
}
维度@Valid@Validated
来源jakarta.validation 标准注解Spring 提供的扩展注解
分组能力不支持，校验默认组全部生效支持 groups 参数，按分组选择约束
位置可标注在方法参数、字段、嵌套对象上可标注在类级别与方法参数上
嵌套对象字段上写 @Valid 可级联校验内部对象嵌套级联仍需配合 @Valid
失败异常@RequestBody 场景抛 MethodArgumentNotValidException类级别 / 非 body 参数校验抛 ConstraintViolationException

90.4 自定义校验注解

一句话定位：内置注解覆盖不了业务格式（如车牌、身份证、自定义枚举取值）时，自定义注解 + 校验器：注解声明元数据，ConstraintValidator 写判定逻辑，二者通过 @Constraint(validatedBy = ...) 绑定。

// 第一步：定义注解
package com.example.demo.validation;

import jakarta.validation.Constraint;
import jakarta.validation.Payload;
import java.lang.annotation.*;

@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = PhoneValidator.class)
public @interface Phone {
    String message() default "手机号格式不正确";
    Class<?>[] groups() default { };
    Class<? extends Payload>[] payload() default { };
}
// 第二步：实现校验器
package com.example.demo.validation;

import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;

public class PhoneValidator implements ConstraintValidator<Phone, String> {

    private static final java.util.regex.Pattern P =
            java.util.regex.Pattern.compile("^1[3-9]\\d{9}$");

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        // null 交给 @NotNull 判断，本注解只负责格式，避免双重提示
        if (value == null) return true;
        return P.matcher(value).matches();
    }
}
// 第三步：在 DTO 上使用
public class UserCreateRequest {

    @Phone(message = "手机号格式不正确")
    private String phone;

    @NotBlank
    private String name;
    // 其余字段略
}
设计纪律自定义校验器对 null 返回 true，把"是否必填"交给 @NotNull/@NotBlank；一个校验注解只表达一条约束，组合使用比写一个大而全的注解更清晰。

90.5 校验失败异常与衔接全局处理

一句话定位：校验失败不会静默跳过，而是抛出标准异常；控制器方法上的 @RequestBody @Valid 失败抛 MethodArgumentNotValidException，类级别 @Validated 的参数校验失败抛 ConstraintViolationException，缺 body 时抛 HttpMessageNotReadableException。

// 仅预览：提取字段错误信息的写法，完整处理器在第 91 章落地
import org.springframework.web.bind.MethodArgumentNotValidException;
import java.util.stream.Collectors;

private String extractMessage(MethodArgumentNotValidException ex) {
    return ex.getBindingResult().getFieldErrors().stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.joining("；"));
}

错误信息按字段聚合后，统一放进第 89 章的 Result 响应体，前端即可在表单旁逐字段提示。本章先记住异常类型与提取入口，第 91 章把所有异常映射到同一响应结构。

90.6 常见坑辨析

坑：只写注解不加 @ValidDTO 字段上注解齐全，控制器参数却漏写 @Valid 或 @Validated，校验完全不触发，非法参数直接进入业务层——这是最常见的"校验失效"原因。

坑：嵌套对象不级联请求体里包含另一个对象（如订单里的收货地址），内层对象字段上的注解不会自动校验；需要在外层字段上加 @Valid 触发级联。

public class OrderCreateRequest {
    @NotBlank
    private String remark;

    @Valid                                   // 级联校验内部对象
    @NotNull
    private AddressDTO address;
}

public class AddressDTO {
    @NotBlank(message = "省份不能为空")
    private String province;
    @NotBlank(message = "详细地址不能为空")
    private String detail;
}

坑：3.x 命名空间用错Spring Boot 3.x 基线中校验注解属于 jakarta.validation.constraints，不要再引入 javax.validation；旧教程的包名在 3.x 工程中会报类找不到。

补充校验注解需要 getter/setter 可访问；record 类型组件构造器参数上可直接标注约束，配合 @Valid 同样生效。

✓ 本章小结

要点一句话
依赖与命名空间spring-boot-starter-validation，3.x 使用 jakarta.validation
注解选型字符串必填 NotBlank、集合必填 NotEmpty、数字必填 NotNull，格式用 Size/Min/Max/Email/Pattern
触发方式@Valid 触发默认组；@Validated 携带分组选择约束
分组校验空接口标识分组，注解 groups 指定，控制器参数 @Validated(分组) 选择
自定义注解@Constraint 绑定 ConstraintValidator，null 放行、只判格式
