89.1 内嵌服务器与控制器两种注解

一句话定位：引入 spring-boot-starter-web 后，Tomcat 内嵌在进程内，Spring MVC 的 DispatcherServlet 自动注册；控制器类用 @RestController 标注，方法返回值直接序列化为 JSON 响应体。

注解含义适用场景
@Controller标注控制器组件；方法返回值默认走视图解析器，指向页面模板传统服务端渲染（Thymeleaf 页面），返回视图名
@RestController= @Controller + @ResponseBody；类下所有方法返回值直接作为响应体，由 Jackson 序列化为 JSON前后端分离接口开发（本书主线）
 
package com.example.demo.controller;

import org.springframework.web.bind.annotation.*;

@RestController                                    // 整个类返回 JSON
@RequestMapping("/api/users")                      // 类级公共路径前缀
public class UserController {

    @GetMapping("/{id}")                          // 方法级映射与类前缀拼接
    public String get(@PathVariable Long id) {
        return "user-" + id;
    }
}

89.2 请求映射家族与 HTTP 方法

一句话定位：@RequestMapping 是总注解，可通过 method 属性限定 HTTP 方法；四个派生注解把方法限定写进注解名，语义更直观。

注解绑定方法语义
@GetMappingGET查询资源，参数走 URL，请求无 body，应保持幂等与安全
@PostMappingPOST新建资源或提交动作，参数走 JSON 请求体
@PutMappingPUT整体更新资源，参数走请求体，语义幂等
@PatchMappingPATCH局部更新资源，只提交变更字段
@DeleteMappingDELETE删除资源，路径携带资源标识，语义幂等
@RequestMapping不限定（可 method=...）类级公共前缀，或需要同时支持多方法时使用
 
@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping
    public List<User> list() { return List.of(); }

    @GetMapping("/{id}")
    public User getById(@PathVariable Long id) { return new User(); }

    @PostMapping
    public User create(@RequestBody UserCreateRequest req) { return new User(); }

    @PutMapping("/{id}")
    public User update(@PathVariable Long id, @RequestBody UserUpdateRequest req) {
        return new User();
    }

    @DeleteMapping("/{id}")
    public void delete(@PathVariable Long id) { }
}

映射路径支持通配与正则：/files/{name:.+} 可把点号后的内容整体纳入路径变量；类级前缀与方法级路径拼接，便于按资源分组。

89.3 三类参数绑定

一句话定位：参数从哪里来，决定用哪个注解——路径段用 @PathVariable，URL 查询串用 @RequestParam，JSON 请求体用 @RequestBody。

注解取值位置典型示例与说明
@PathVariableURL 路径段 /users/{id}路径占位符名称与参数名一致可省略 value；类型不匹配会抛类型转换异常
@RequestParam查询串 ?page=1&size=10 或表单字段required 默认 true，缺失抛 400；可设 defaultValue；同名多值用 List 接收
@RequestBody请求体 JSON由 Jackson 反序列化为对象；一个方法只能有一个；Content-Type 通常为 application/json
无注解（对象）查询串 + 表单字段按属性名绑定简单查询条件对象可省略注解，Spring 自动按属性名装配
 
@RestController
@RequestMapping("/api/users")
public class UserController {

    // GET /api/users/123?detail=true
    @GetMapping("/{id}")
    public User get(@PathVariable Long id,
                    @RequestParam(name = "detail", required = false, defaultValue = "false")
                    boolean detail) {
        return userService.getById(id, detail);
    }

    // GET /api/users?keyword=张&page=1&size=10
    @GetMapping
    public PageResult<User> page(UserQuery query,
                                  @RequestParam(defaultValue = "1") int page,
                                  @RequestParam(defaultValue = "10") int size) {
        return userService.page(query, page, size);
    }

    // POST /api/users，Content-Type: application/json
    @PostMapping
    public User create(@RequestBody UserCreateRequest request) {
        return userService.create(request);
    }
}
// 查询条件对象：字段名与查询串键名对应，Spring 自动装配
public class UserQuery {
    private String keyword;
    private Integer status;
    // getter / setter 略
}

// 请求体 DTO：与数据库实体分离，避免暴露内部字段
public record UserCreateRequest(String name, String email, Integer age) { }
分层纪律接口入参用独立的 DTO/record 接收，不要直接把数据库实体（Entity）暴露给前端；出参同样用 VO 组装，字段口径由接口层控制。这与第 92 章 Mapper 层、第 91 章响应体配合形成完整分层。

89.4 RESTful 设计规范

一句话定位：REST 把 URL 当作资源标识，HTTP 方法表达动作，状态码表达结果；资源用名词复数，动作不写进路径，查询条件交给查询串。

规范点推荐做法反例
路径用名词复数/api/users、/api/users/123/orders/api/getUser、/api/deleteUser?id=1
动作交给 HTTP 方法GET 查询、POST 新建、PUT 更新、DELETE 删除路径里写 /api/updateUser
层级表达从属/api/users/123/orders/456把层级关系压平成扁平接口列表
状态码语义准确200 成功、201 创建、204 删除成功、400 参数错、404 不存在、500 服务端错无论成败一律返回 200，错误塞在 body 里
幂等性GET、PUT、DELETE 重复调用结果一致；POST 重复提交可能产生重复资源用 GET 执行写操作
 
# 一套典型的用户资源接口
GET    /api/users?page=1&size=10        # 列表查询
GET    /api/users/123                    # 单个查询
POST   /api/users                        # 新建，响应 201 + Location 头
PUT    /api/users/123                    # 整体更新
PATCH  /api/users/123                     # 局部更新
DELETE /api/users/123                     # 删除，响应 204
前端视角前端熟悉的 axios.get('/users')、axios.post('/users', data) 正是这套语义的 JS 映射；后端按规范出接口，前端不需要为每个动作记特殊路径。

89.5 统一响应体雏形

一句话定位：接口返回统一结构 code / message / data，前端按 code 判断业务成败；本章先给雏形，第 91 章再由全局异常处理把错误响应也纳入同一结构。

/** 统一响应体：泛型承载业务数据 */
public record Result<T>(Integer code, String message, T data) {

    public static <T> Result<T> ok(T data) {
        return new Result<>(0, "success", data);
    }

    public static <T> Result<T> fail(Integer code, String message) {
        return new Result<>(code, message, null);
    }
}

@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping("/{id}")
    public Result<UserVO> get(@PathVariable Long id) {
        return Result.ok(userService.getById(id));
    }

    @PostMapping
    public Result<UserVO> create(@RequestBody UserCreateRequest request) {
        return Result.ok(userService.create(request));
    }
}
# 成功响应示例
HTTP/1.1 200 OK
Content-Type: application/json

{
  "code": 0,
  "message": "success",
  "data": { "id": 123, "name": "张三", "email": "z@example.com" }
}

本章先把成功路径的结构统一起来；参数校验失败、业务异常、系统异常如何也返回同一结构，分别由第 90 章与第 91 章解决。

89.6 前端视角对照与常见坑

// 前端 axios 调用对照（与 89.2 接口一一对应）
import axios from 'axios'

const api = axios.create({ baseURL: '/api' })

export const fetchUsers = (page = 1, size = 10) =>
  api.get('/users', { params: { page, size } })

export const fetchUser = (id) => api.get(`/users/${id}`)

export const createUser = (payload) =>
  api.post('/users', payload)            // payload 自动序列化为 JSON body

export const updateUser = (id, payload) =>
  api.put(`/users/${id}`, payload)

export const deleteUser = (id) => api.delete(`/users/${id}`)

坑：GET 携带请求体HTTP 规范未禁止 GET body，但浏览器、代理、缓存层行为不一致；查询参数一律走查询串，写操作才用 body。后端 @GetMapping 方法上不要加 @RequestBody。

坑：状态码乱用业务失败也返回 200、把错误码放在 body，前端无法借助 HTTP 层统一拦截；规范做法是错误语义映射到对应状态码，业务错误码再放进响应体（第 91 章细化）。

坑：@RequestParam 与 @PathVariable 混用路径段缺失占位符却用 @PathVariable 取值、或把查询参数写成路径变量，启动绑定期或调用期报错；先画清 URL 结构再选注解。

跨域提示前后端分离开发时浏览器会发起 CORS 预检；生产环境通常由网关或反向代理同源转发，开发期可用 @CrossOrigin 或全局 CORS 配置放开，第 91 章后段会给出全局配置写法。

✓ 本章小结

要点一句话
控制器注解@RestController = @Controller + @ResponseBody，接口开发一律使用
方法映射@GetMapping/@PostMapping/@PutMapping/@DeleteMapping 对应查询/新建/更新/删除
参数绑定路径段 PathVariable、查询串 RequestParam、JSON 体 RequestBody
