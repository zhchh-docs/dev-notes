95.1 MultipartFile 接收文件

一句话定位：表单 multipart/form-data 上传的文件由 Spring 封装为 MultipartFile，控制器方法参数按表单字段名接收；对象、字节流、原始文件名、大小、内容类型都可从该对象读取。

package com.example.demo.controller;

import com.example.demo.common.Result;
import com.example.demo.service.FileStorageService;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;
import java.util.List;

@RestController
@RequestMapping("/api/files")
public class FileController {

    private final FileStorageService storageService;

    public FileController(FileStorageService storageService) {
        this.storageService = storageService;
    }

    /** 单文件上传：表单字段名 file */
    @PostMapping("/upload")
    public Result<String> upload(@RequestParam("file") MultipartFile file) {
        String url = storageService.store(file);
        return Result.ok(url);
    }

    /** 多文件上传：同一字段多个文件 */
    @PostMapping("/upload-batch")
    public Result<List<String>> uploadBatch(@RequestParam("files") List<MultipartFile> files) {
        List<String> urls = files.stream().map(storageService::store).toList();
        return Result.ok(urls);
    }
}
MultipartFile 方法用途
getOriginalFilename()客户端提交的原始文件名（不可直接信任，需清洗）
getContentType()浏览器声明的 MIME 类型（可伪造，仅作辅助判断）
getSize()文件字节大小
getBytes() / getInputStream()读取文件内容；大文件优先流式处理
isEmpty()是否为空文件（未选择或零字节）
transferTo(File)写入指定磁盘位置

95.2 上传大小与请求限制

一句话定位：Boot 默认对单文件与整个 multipart 请求设上限，超出抛 MaxUploadSizeExceededException；在配置中按业务调大阈值，并把异常纳入第 91 章全局异常处理。

# application.yml
spring:
  servlet:
    multipart:
      enabled: true
      max-file-size: 10MB          # 单个文件上限
      max-request-size: 20MB       # 单次 multipart 请求总上限
      file-size-threshold: 2KB     # 超过该阈值写入临时磁盘，否则留内存
      location:                    # 临时目录留空使用系统默认
      resolve-lazily: false        # 关闭延迟解析，大小超限尽早抛异常
配置项说明
max-file-size单个上传文件大小上限，超限抛 MaxUploadSizeExceededException
max-request-size一次 multipart 请求整体大小上限，含多文件与表单字段
file-size-threshold内存缓冲阈值，超出后写入临时文件，防止大文件撑爆堆内存
location临时文件目录；留空使用系统临时目录（95.6 讲清理问题）

95.3 本地存储策略与安全边界

一句话定位：落盘前必须做三件事——校验类型白名单、生成新文件名、把目标路径约束在存储根目录之内；原始文件名只用于展示，绝不直接拼进磁盘路径。

package com.example.demo.service;

import com.example.demo.common.BizException;
import com.example.demo.common.ErrorCode;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.nio.file.*;
import java.util.Set;
import java.util.UUID;

@Service
public class FileStorageService {

    private static final Set<String> ALLOWED_EXT =
            Set.of("png", "jpg", "jpeg", "gif", "pdf");

    private final Path rootDir;

    public FileStorageService(@Value("${file.upload-dir:./uploads}") String uploadDir)
            throws IOException {
        this.rootDir = Paths.get(uploadDir).toAbsolutePath().normalize();
        Files.createDirectories(rootDir);
    }

    public String store(MultipartFile file) {
        if (file.isEmpty()) {
            throw new BizException(ErrorCode.PARAM_INVALID, "上传文件为空");
        }
        String original = StringUtils.cleanPath(
                file.getOriginalFilename() == null ? "" : file.getOriginalFilename());
        String ext = getExtension(original);
        if (!ALLOWED_EXT.contains(ext)) {
            throw new BizException(ErrorCode.PARAM_INVALID, "文件类型不允许");
        }
        // 重命名：UUID 防重名与覆盖，扩展名取自白名单校验结果
        String storedName = UUID.randomUUID().toString().replace("-", "") + "." + ext;

        Path target = rootDir.resolve(storedName).normalize();
        // 路径穿越校验：解析后必须仍在根目录之内
        if (!target.startsWith(rootDir)) {
            throw new BizException(ErrorCode.PARAM_INVALID, "非法文件路径");
        }
        try {
            Files.copy(file.getInputStream(), target, StandardCopyOption.REPLACE_EXISTING);
        } catch (IOException e) {
            throw new BizException(ErrorCode.SYSTEM_ERROR, "文件保存失败");
        }
        return "/static/" + storedName;
    }

    private String getExtension(String filename) {
        int dot = filename.lastIndexOf('.');
        if (dot < 0 || dot == filename.length() - 1) return "";
        return filename.substring(dot + 1).toLowerCase();
    }
}
安全红线：路径穿越攻击者提交 filename="../../etc/cron.d/evil"，若直接拼接 rootDir + "/" + filename 会写出根目录。必须 normalize() 后用 startsWith(rootDir) 约束，文件名最终以系统生成的 UUID 为准。
双重校验扩展名白名单之外，图片类上传建议读取文件头魔数（magic number）二次确认真实类型；仅信任 contentType 可被伪造绕过。可执行脚本（jsp/html/svg）绝不允许存入可执行目录。

95.4 静态资源映射

一句话定位：本地落盘的文件需要通过 HTTP 访问；注册资源处理器，把 URL 路径前缀映射到磁盘目录，浏览器或前端即可直接加载图片与附件。

package com.example.demo.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.ResourceHandlerRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebResourceConfig implements WebMvcConfigurer {

    @Value("${file.upload-dir:./uploads}")
    private String uploadDir;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/static/**")
                .addLocations("file:" + uploadDir + "/");
    }
}
# application.yml：自定义上传目录与对外前缀
file:
  upload-dir: ./uploads
spring:
  web:
    resources:
      static-locations: classpath:/static/,classpath:/public/
  • classpath 静态资源：默认从 /static/、/public/、/resources/、/META-INF/resources/ 提供内置资源；
  • 磁盘目录映射：addResourceHandler 的 URL 前缀与 addLocations 的磁盘目录一一对应；
  • 权限分离：静态资源路径通常不经过 JWT 拦截器（在第 94 章配置中排除），受保护附件下载改走后端受控接口（95.5）。

95.5 文件下载与 OSS 简介

一句话定位：受控下载不能直接暴露磁盘路径，由接口读取文件流写入 ResponseEntity，设置 Content-Disposition 决定浏览器内联预览还是附件下载；生产环境大文件优先走对象存储 CDN。

@GetMapping("/download/{filename}")
public ResponseEntity<Resource> download(@PathVariable String filename) throws IOException {
    Path file = rootDir.resolve(filename).normalize();
    if (!file.startsWith(rootDir) || !Files.exists(file)) {
        throw new BizException(ErrorCode.USER_NOT_FOUND, "文件不存在");
    }
    Resource resource = new UrlResource(file.toUri());

    String encoded = java.net.URLEncoder.encode(filename, StandardCharsets.UTF_8)
            .replace("+", "%20");
    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename=\"" + encoded + "\"; filename*=UTF-8''" + encoded)
            .contentLength(resource.contentLength())
            .body(resource);
}

95.6 常见坑排查

坑：临时目录清理大文件先写系统临时目录，进程异常退出可能残留碎片；长时间运行需关注临时目录空间，或显式配置 spring.servlet.multipart.location 并纳入磁盘清理策略。

坑：中文文件名乱码下载响应头直接写中文文件名，不同浏览器解析结果不一致；必须按 RFC 5987 同时提供 filename 与 filename*=UTF-8'' 编码形式（95.5 代码已落地）。

坑：大小超限返回 500未处理 MaxUploadSizeExceededException，前端收到 500 与系统错误文案；应在全局处理器中映射为 400 并返回"文件大小超出限制"。

坑：原始文件名直接落盘同名覆盖、特殊字符、路径穿越、文件名乱码全部由此引发；落盘名使用 UUID 或雪花 id，原始名单独存数据库供展示。

要点一句话

✎ 本章习题

A 基础复述：MultipartFile 五个常用方法；max-file-size 与 max-request-size 区别；为什么落盘必须重命名？路径穿越防护的两个步骤是什么？
B 进阶实现头像上传接口：白名单 png/jpg/jpeg，限制 5MB，UUID 重命名后存入本地目录并配置静态映射；补充下载接口，处理中文文件名编码；把大小超限异常接入全局异常处理器返回 400。
C 挑战接入 MinIO 或某云 OSS SDK：后端校验身份后返回预签名上传 URL，前端直传；再写一个预签名下载 URL 生成接口。对比本地存储方案在多实例部署时的共享磁盘需求，写出迁移 OSS 后上传、下载两条链路的时序说明。
