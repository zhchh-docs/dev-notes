92.1 starter 引入与数据源配置

一句话定位：mybatis-spring-boot-starter 把 DataSource、SqlSessionFactory、Mapper 扫描的自动配置打包引入；你只需提供数据库连接参数，Spring 侧的 JdbcTemplate、事务管理器由 Boot 自动装配。

<dependencies>
    <dependency>
        <groupId>org.mybatis.spring.boot</groupId>
        <artifactId>mybatis-spring-boot-starter</artifactId>
        <version>3.0.3</version>
    </dependency>
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-jdbc</artifactId>
    </dependency>
</dependencies>
# application.yml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
    username: root
    password: ${DB_PASSWORD:123456}
    hikari:
      maximum-pool-size: 10
      minimum-idle: 2

mybatis:
  mapper-locations: classpath*:mapper/**/*.xml      # XML 映射文件位置
  type-aliases-package: com.example.demo.entity     # 实体类别名包
  configuration:
    map-underscore-to-camel-case: true               # 下划线转驼峰
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl   # 开发期打印 SQL

数据源、HikariCP 连接池、DataSourceTransactionManager 由 spring-boot-starter-jdbc 自动配置；MyBatis 自动配置类在容器中创建 SqlSessionFactory 与 SqlSessionTemplate，业务代码只接触 Mapper 接口。

92.2 Mapper 扫描与接口定义

一句话定位：Mapper 是普通 Java 接口，不加实现类；启动时由 MyBatis-Spring 为每个接口生成代理 Bean 注册进容器，Service 通过类型注入即可使用。

package com.example.demo.mapper;

import com.example.demo.entity.User;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import java.util.List;

@Mapper                                   // 方式一：接口上标注，逐个被扫描
public interface UserMapper {

    User selectById(@Param("id") Long id);

    List<User> selectByCondition(@Param("keyword") String keyword,
                                  @Param("status") Integer status);

    int insert(User user);

    int update(User user);

    int deleteById(@Param("id") Long id);

    List<User> selectByIds(@Param("ids") List<Long> ids);
}
// 方式二：启动类或配置类上统一扫描，接口上无需 @Mapper
@SpringBootApplication
@MapperScan("com.example.demo.mapper")
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
扫描方式说明
@Mapper（接口级）每个 Mapper 接口标注；包内接口较少时直观清晰
@MapperScan（类级）启动类/配置类声明扫描包，批量注册；接口上不再重复注解，适合中型工程
两种不要混用冲突同一接口被两次扫描会报重复 Bean 或注册异常，团队统一选一种
 
// Service 通过构造器注入 Mapper，无实现类也能被容器装配
@Service
public class UserService {

    private final UserMapper userMapper;

    public UserService(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    public UserVO getById(Long id) {
        User user = userMapper.selectById(id);
        if (user == null) throw new BizException(ErrorCode.USER_NOT_FOUND);
        return UserVO.from(user);
    }
}

92.3 XML 映射与动态 SQL

一句话定位：XML 把 SQL 与 Java 接口解耦：namespace 绑定接口全限定名，id 绑定方法名；动态标签根据参数是否为空拼接 SQL 片段，条件查询、批量 in 全靠它。

<!-- src/main/resources/mapper/UserMapper.xml -->
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
    PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
    "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.demo.mapper.UserMapper">

    <resultMap id="userMap" type="com.example.demo.entity.User">
        <id     column="id"        property="id"/>
        <result column="user_name" property="userName"/>
        <result column="email"     property="email"/>
        <result column="status"    property="status"/>
        <result column="created_at" property="createdAt"/>
    </resultMap>

    <select id="selectById" resultMap="userMap">
        SELECT id, user_name, email, status, created_at
        FROM sys_user
        WHERE id = #{id}
    </select>

    <!-- 动态条件：keyword、status 非空才拼接对应 where 片段 -->
    <select id="selectByCondition" resultMap="userMap">
        SELECT id, user_name, email, status, created_at
        FROM sys_user
        <where>
            <if test="keyword != null and keyword != ''">
                AND user_name LIKE CONCAT('%', #{keyword}, '%')
            </if>
            <if test="status != null">
                AND status = #{status}
            </if>
        </where>
        ORDER BY created_at DESC
    </select>

    <!-- 批量 in：foreach 遍历集合拼接逗号分隔的占位符 -->
    <select id="selectByIds" resultMap="userMap">
        SELECT id, user_name, email, status, created_at
        FROM sys_user
        WHERE id IN
        <foreach collection="ids" item="id" open="(" close=")" separator=",">
            #{id}
        </foreach>
    </select>

    <insert id="insert" parameterType="com.example.demo.entity.User"
            useGeneratedKeys="true" keyProperty="id">
        INSERT INTO sys_user (user_name, email, status)
        VALUES (#{userName}, #{email}, #{status})
    </insert>

    <update id="update" parameterType="com.example.demo.entity.User">
        UPDATE sys_user
        <set>
            <if test="userName != null">user_name = #{userName},</if>
            <if test="email != null">email = #{email},</if>
            <if test="status != null">status = #{status},</if>
        </set>
        WHERE id = #{id}
    </update>

    <delete id="deleteById">
        DELETE FROM sys_user WHERE id = #{id}
    </delete>
</mapper>
动态标签作用
<if test="...">条件成立时拼接标签内 SQL；test 是 OGNL 表达式，访问参数属性
<where>包裹多个 if，自动去除开头多余的 AND/OR，无任何条件时不生成 WHERE
<set>更新语句中自动去除末尾多余逗号，只拼接非空字段
<foreach>遍历集合/数组生成 in 列表或批量 VALUES，collection 对应 @Param 名
<sql> + <include>抽出公共列片段，多处复用，避免重复书写列名
<choose/when/otherwise>类似 if-else if-else，多分支择一拼接

92.4 注解式 SQL

一句话定位：简单 SQL 直接写在 @Select/@Insert/@Update/@Delete 注解里，省去 XML 文件；条件较复杂、结果映射较多时回到 XML，两者可在同一工程共存。

package com.example.demo.mapper;

import com.example.demo.entity.User;
import org.apache.ibatis.annotations.*;
import java.util.List;

@Mapper
public interface UserMapper {

    @Select("SELECT id, user_name AS userName, email, status, created_at AS createdAt " +
            "FROM sys_user WHERE id = #{id}")
    User selectById(@Param("id") Long id);

    @Select("SELECT id, user_name AS userName, email, status, created_at AS createdAt " +
            "FROM sys_user WHERE status = #{status}")
    List<User> selectByStatus(@Param("status") Integer status);

    @Insert("INSERT INTO sys_user (user_name, email, status) " +
            "VALUES (#{userName}, #{email}, #{status})")
    @Options(useGeneratedKeys = true, keyProperty = "id")
    int insert(User user);

    @Update("UPDATE sys_user SET status = #{status} WHERE id = #{id}")
    int updateStatus(@Param("id") Long id, @Param("status") Integer status);

    @Delete("DELETE FROM sys_user WHERE id = #{id}")
    int deleteById(@Param("id") Long id);
}
选型建议单表 CRUD、固定条件查询用注解式；多表关联、动态条件、复杂 resultMap 与批量语句用 XML。注解内多行 SQL 用字符串拼接，可读性下降后即应迁移到 XML。

92.5 #{} 与 ${} 的安全边界

一句话定位：#{} 生成 JDBC 预编译占位符 ?，参数由驱动安全绑定，防 SQL 注入；${} 把参数值原样拼进 SQL 文本，只用于表名、列名、排序方向等不能用占位符的位置。

对比项#{}（占位符）${}（字符串拼接）
SQL 形态WHERE id = ?WHERE id = 123（值直接写入文本）
防注入是；参数被当作值处理，引号与特殊字符转义否；用户输入可闭合引号注入额外 SQL
适用位置所有参数值、查询条件、插入值表名、列名、ORDER BY 字段、排序方向等 SQL 结构片段
参数校验要求无需额外过滤必须白名单校验，禁止直接使用前端原始输入
 
<!-- 安全：排序字段与方向来自后端白名单映射，不能直接接前端字符串 -->
<select id="selectPage" resultMap="userMap">
    SELECT id, user_name, email, status, created_at
    FROM sys_user
    ORDER BY ${sortColumn} ${sortDirection}
    LIMIT #{offset}, #{size}
</select>
// Service 层做白名单映射，再把合法列名传给 Mapper
private String resolveSortColumn(String raw) {
    return switch (raw == null ? "created_at" : raw) {
        case "name"    -> "user_name";
        case "status"  -> "status";
        case "created" -> "created_at";
        default        -> "created_at";
    };
}
private String resolveSortDirection(String raw) {
    return "desc".equalsIgnoreCase(raw) ? "desc" : "asc";
}
红线登录名、查询关键字、手机号等用户可控值一律 #{}；出现 ${keyword}、${order} 直接接前端输入，就是 SQL 注入漏洞。动态表名、排序字段必须先过白名单。

92.6 动态代理原理与常见坑

一句话定位：Mapper 接口没有实现类，MyBatis-Spring 在容器启动时为每个接口生成 JDK 动态代理；方法被调用时，代理根据"接口全限定名 + 方法名"找到对应 MappedStatement，由 SqlSession 执行 SQL 并把结果映射为返回类型。

图 92-1 Mapper 动态代理执行链路

坑：resultType 映射不对列名与属性名不一致又没写 resultMap，字段为 null；开启 map-underscore-to-camel-case 后 user_name 自动映射 userName，但多表列名冲突、嵌套对象仍需 resultMap 显式映射。

坑：XML 绑定失败namespace 与接口全限定名不一致、id 与方法名不一致、mapper-locations 路径写错，启动期或调用期报 "Invalid bound statement"。排查顺序：包扫描 → XML 位置 → namespace → id → 参数名匹配。

坑：多参数无 @Param接口方法有多个参数却未标注 @Param，XML 中取不到参数名（编译未保留参数名时按 param1/param2 索引访问）；多参数一律显式 @Param。

✓ 本章小结

要点一句话
starter 配置mybatis-spring-boot-starter 自动装配 SqlSessionFactory，数据源由 jdbc starter 提供
Mapper 扫描@Mapper 接口级标注或 @MapperScan 包级批量扫描，二选一不混用
XML 映射namespace 绑接口、id 绑方法，if/where/set/foreach 完成动态 SQL
注解式 SQL简单 CRUD 用 @Select 等注解，复杂查询回 XML，两者可共存
安全边界#{} 预编译防注入；${} 仅用于表名列名等结构片段且必须白名单
代理原理JDK 代理按 namespace+方法名定位 MappedStatement，SqlSession 执行并映射结果

✎ 本章习题

A 基础复述：@Mapper 与 @MapperScan 区别；#{} 与 ${} 的安全差异与各自适用位置；动态 SQL 的 where/set/foreach 各解决什么问题？
B 进阶为 sys_order 表编写 Mapper 接口与 XML：条件查询（订单号模糊、状态、时间区间可选拼接）、批量按 id 查询、局部更新；开启驼峰映射并写 resultMap 对照验证。
C 挑战实现一个安全的通用排序参数：前端只传字段 key 与方向，Service 层白名单映射后再调用 ${} 排序；故意用注入字符串测试被拦截；再阅读 MyBatis-Spring 源码说明 MapperFactoryBean 如何生成代理并注册进容器。
