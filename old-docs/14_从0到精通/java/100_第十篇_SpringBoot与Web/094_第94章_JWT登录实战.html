94.1 会话与无状态认证对比

一句话定位：Session 模式在服务端存储登录态，Cookie 携带 sessionId；JWT 把身份信息编码进令牌本身，每次请求携带令牌，服务端验签后信任内容，不查存储。

维度Session-CookieJWT 无状态令牌
登录态存储服务端内存 / Redis / 数据库不存登录态，信息在令牌内自包含
凭证载体Cookie 中的 sessionIdAuthorization: Bearer <token> 请求头
水平扩展多实例需共享 Session（Redis 集中存储）天然支持多实例，任意节点验签即可
主动登出直接删除服务端 Session，立即可效令牌未过期前依然有效，需黑名单或短有效期 + 刷新令牌
性能每次校验读存储；可缓存验签为本地计算，无存储往返；令牌越大 header 越重
适用传统单体、强管控会话前后端分离、开放接口、跨域多端、微服务鉴权
前端视角前端登录后把令牌保存在内存或 localStorage，后续请求统一在 axios 拦截器里附加 Authorization 头；401 时清除令牌并跳转登录页——这套约定与第 89 章接口体系直接对接。

94.2 JWT 结构与签名算法

一句话定位：JWT 形如 xxxxx.yyyyy.zzzzz，三段均为 Base64URL 编码，点号分隔；前两段是可读编码（不是加密），第三段签名保证前两段未被篡改。

图 94-1 JWT 结构与签名输入

签名算法密钥机制适用场景
HS256（HMAC）对称共享密钥：签发与验签用同一密钥，速度快单服务或内部体系，密钥由签发方独占保管
RS256（RSA）非对称密钥对：私钥签发，公钥验签，多服务可只持公钥开放平台、多服务共享鉴权、第三方验证
标准声明含义
sub主体，通常存用户 id
iss签发方标识
iat签发时间（issued at，Unix 秒）
exp过期时间（expiration），过期后验签仍通过但应判失效
自定义 claim角色、昵称等业务字段；不要放入密码、密钥等敏感信息

一句话定位：使用 jjwt 0.12.x（Jakarta 兼容版本）封装工具类：密钥由配置注入，签发时写 sub 与过期时间，解析时验签、校验 exp，失败抛出自定义认证异常。

package com.example.demo.security;

import io.jsonwebtoken.*;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;

@Component
public class JwtUtil {

    private final SecretKey key;
    private final long expireMillis;

    public JwtUtil(@Value("${jwt.secret}") String secret,
                    @Value("${jwt.expire-minutes}") long expireMinutes) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expireMillis = expireMinutes * 60_000L;
    }

    /** 签发令牌：subject 存用户 id，附带角色 claim */
    public String issue(Long userId, String role) {
        Date now = new Date();
        Date exp = new Date(now.getTime() + expireMillis);
        return Jwts.builder()
                .subject(String.valueOf(userId))
                .claim("role", role)
                .issuedAt(now)
                .expiration(exp)
                .signWith(key)
                .compact();
    }

    /** 解析并验签；返回用户 id，失败抛异常由全局处理器映射 401 */
    public Long parseUserId(String token) {
        Claims claims = Jwts.parser()
                .verifyWith(key)
                .build()
                .parseSignedClaims(token)
                .getPayload();
        return Long.valueOf(claims.getSubject());
    }

    public String parseRole(String token) {
        Claims claims = Jwts.parser()
                .verifyWith(key)
                .build()
                .parseSignedClaims(token)
                .getPayload();
        return claims.get("role", String.class);
    }
}

94.4 登录接口完整流程

一句话定位：登录接口按"按账号查用户 → 校验密码哈希 → 签发 JWT → 返回令牌"推进；密码用 BCrypt 哈希存储与比对，不明文落库；错误信息统一为"账号或密码错误"，避免枚举用户。

// 登录请求 DTO（第 90 章校验注解）
public record LoginRequest(
        @NotBlank(message = "用户名不能为空") String username,
        @NotBlank(message = "密码不能为空") String password) { }

public record LoginResponse(String token, Long userId, String role) { }
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    private final UserService userService;
    private final JwtUtil jwtUtil;
    private final PasswordEncoder passwordEncoder;

    public AuthController(UserService userService, JwtUtil jwtUtil,
                          PasswordEncoder passwordEncoder) {
        this.userService = userService;
        this.jwtUtil = jwtUtil;
        this.passwordEncoder = passwordEncoder;
    }

    @PostMapping("/login")
    public Result<LoginResponse> login(@Valid @RequestBody LoginRequest req) {
        User user = userService.findByUsername(req.username());
        if (user == null ||
                !passwordEncoder.matches(req.password(), user.getPasswordHash())) {
            throw new BizException(ErrorCode.UNAUTHORIZED, "账号或密码错误");
        }
        String token = jwtUtil.issue(user.getId(), user.getRole());
        return Result.ok(new LoginResponse(token, user.getId(), user.getRole()));
    }
}
// BCrypt 编码器 Bean（内置盐值，比对时从哈希串中提取）
@Configuration
public class SecurityBeans {
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder();
    }
}

94.5 拦截器校验与用户上下文

一句话定位：受保护接口前注册 HandlerInterceptor，从请求头解析 Bearer 令牌、验签并取出用户 id 存入线程上下文；控制器方法直接读取当前用户；请求结束清理上下文，防止线程复用串号。

// 用户上下文：基于 ThreadLocal 持有当前登录用户
public final class UserContext {
    private static final ThreadLocal<CurrentUser> HOLDER = new ThreadLocal<>();

    public static void set(CurrentUser user) { HOLDER.set(user); }
    public static CurrentUser get() { return HOLDER.get(); }
    public static void clear() { HOLDER.remove(); }

    public record CurrentUser(Long userId, String role) { }
}
@Component
public class AuthInterceptor implements HandlerInterceptor {

    private final JwtUtil jwtUtil;

    public AuthInterceptor(JwtUtil jwtUtil) { this.jwtUtil = jwtUtil; }

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) throws Exception {
        String header = request.getHeader("Authorization");
        if (header == null || !header.startsWith("Bearer ")) {
            throw new BizException(ErrorCode.UNAUTHORIZED, "缺少登录凭证");
        }
        String token = header.substring(7);
        try {
            Long userId = jwtUtil.parseUserId(token);
            String role = jwtUtil.parseRole(token);
            UserContext.set(new UserContext.CurrentUser(userId, role));
        } catch (JwtException ex) {
            throw new BizException(ErrorCode.UNAUTHORIZED, "登录已过期，请重新登录");
        }
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request,
                                HttpServletResponse response,
                                Object handler, Exception ex) {
        UserContext.clear();          // 必须清理，避免线程池复用串号
    }
}
@Configuration
public class WebConfig implements WebMvcConfigurer {

    private final AuthInterceptor authInterceptor;

    public WebConfig(AuthInterceptor authInterceptor) {
        this.authInterceptor = authInterceptor;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(authInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/auth/login", "/api/auth/register");
    }
}
分层提醒拦截器内抛出的 BizException 仍由第 91 章 @RestControllerAdvice 接管，返回统一 Result；401 状态码在处理器中按错误码映射（可配合 ResponseEntity）。

94.6 登出过期与攻击面

  • 过期机制：签发时设置 exp；解析阶段 jjwt 校验过期时间，过期令牌解析抛 ExpiredJwtException，映射为 401；
  • 主动登出：无状态令牌服务端不记录，常见方案是维护 Redis 黑名单（登出后把 token 加入直到 exp），或签发短期 access token + 长期 refresh token 刷新；
  • 续期策略：access token 有效期短（如 2 小时），刷新令牌单独接口换取新令牌，降低泄露窗口。
红线一：密钥泄露HS256 对称密钥一旦泄露，任何人可伪造任意用户令牌；密钥走环境变量/配置中心，长度不低于 32 字节，不写进仓库，多人环境下定期轮换。
红线二：alg=none 攻击攻击者把头部算法改为 none、去掉签名尝试绕过校验；验签时必须使用框架默认的算法校验（jjwt 解析器按签名密钥类型限定算法），不要手工接受无签名令牌。
红线三：payload 明文Payload 只是 Base64 编码，任何人可解码阅读；禁止写入密码、身份证、手机号全文等敏感信息；令牌传输必须走 HTTPS，防止中间人截获。

✓ 本章小结

要点一句话
模型选择Session 服务端存储、易管控；JWT 无状态、利于分布式扩展，主动登出需额外方案
JWT 结构Header.Payload.Signature，前两段可解码阅读，签名保证完整性
算法HS256 对称共享密钥，RS256 非对称私钥签/公钥验

拦截校验Interceptor 解析 Bearer 令牌，写入 UserContext，afterCompletion 清理
安全纪律密钥保密轮换、拒绝 alg=none、payload 不放敏感信息、全程 HTTPS
