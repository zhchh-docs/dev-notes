第 19 章 record：不可变数据载体

◆本章目标

  • 理解传统数据类（POJO）的样板代码痛点；
  • 掌握 record 的声明与自动生成物；
  • 知道 record 的不可变特性；
  • 了解何时应/不应使用 record。

19.1 传统 POJO 的样板

只想"装一组数据"（姓名、年龄），传统写法却要手写字段、构造器、getter、equals、hashCode、toString——几十行纯样板：

class User {
    private final String name;
    private final int age;
    User(String name, int age) { this.name = name; this.age = age; }
    String getName() { return name; }
    int getAge() { return age; }
    // 还得写 equals / hashCode / toString ...
}

这些代码无业务价值、却极易写错（尤其 equals/hashCode），是 bug 温床。

19.2 record 一行搞定

Java 16 正式化的 record，把上面一切浓缩成一行：

record User(String name, int age) { }
User u = new User("小明", 18);
u.name();   // 访问器是小写方法名，不是 getXxx

括号里的 name、age 叫组件（component），编译器据此自动生成一切。

19.3 自动获得什么

  • 私有 final 字段 + 全参构造器；
  • 每个组件的访问器（name() 而非 getName()）；
  • 基于所有组件的 equals / hashCode / toString；
  • 天然不可变：字段 final，没有 setter。
record 是"数据的官方答案"——尤其适合 DTO、返回值、临时元组。Spring Boot 3 已大量使用。

19.4 定制与边界

record 仍能定制：加构造器做校验、加普通方法、实现接口；但不能继承（final），不能有非 final 字段，也不能加额外实例字段。

record User(String name, int age) {
    User {                              // 紧凑构造器，参数已就位
        if (age < 0) throw new IllegalArgumentException("age");
    }
    String greeting() { return "Hi " + name; }
}
常见坑需要可变性、需要额外字段、或要被继承时，record 都不合适——回归普通类。record 不是万能数据类。

✓ 本章小结

要点一句话
痛点POJO 样板多、equals/hashCode 易错
record一行声明，自动生成字段/构造器/访问器/等值方法
特性不可变、final、访问器为 name() 形式
边界无继承、无额外字段；需要可变或继承时退回普通类
