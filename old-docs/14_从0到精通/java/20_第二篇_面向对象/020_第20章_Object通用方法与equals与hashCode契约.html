20.1 Object：所有类的祖先

每个类都直接或间接继承 Object，所以它定义的方法"全民可用"：toString()、equals()、hashCode()、clone()、finalize()、getClass()、notify/notifyAll/wait。

  • toString()：打印对象时默认调，默认是"类名@哈希"，建议重写；
  • equals/hashCode：判断相等与哈希，本章重点；
  • getClass()：运行时类型，反射基础。

20.2 == 与 equals 的区别

String a = new String("hi");
String b = new String("hi");
a == b;          // false：比的是"是不是同一个对象"（地址）
a.equals(b);     // true：比的是"内容是否相等"（Object 默认也用 ==，String 重写了）
  • ==：基本类型比"值"，引用类型比"地址"；
  • equals：默认实现就是 ==，想比内容必须重写。
常见坑Integer 等有缓存（-128~127 复用对象），== 在该区间"恰好 true"是陷阱；比较值永远用 equals。

20.3 正确重写 equals

规范步骤（来自《Effective Java》）：① 自反/对称/传递/一致/非空；② 先 == 判同引用，再 instanceof 判类型，最后比关键字段。

@Override public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof User u)) return false;
    return age == u.age && name.equals(u.name);
}

20.4 equals 与 hashCode 的契约

契约：若 a.equals(b) 为 true，则 a.hashCode() == b.hashCode() 必须成立。反之不要求（哈希冲突允许）。

为什么必须一起重写？因为 HashMap/HashSet 先用 hashCode 定位桶，再用 equals 比对。若只重写 equals 不重写 hashCode，两个"相等"的对象会被算成不同哈希，存进 Set 变两份、Map 取不出——契约被破坏。

@Override public int hashCode() {
    return Objects.hash(name, age);   // 用同样的字段
}
黄金法则：只要重写 equals，就必须用相同字段重写 hashCode。用 Objects.hash(...) 最省心（record 已自动帮你做对）。
