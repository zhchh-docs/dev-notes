15.1 抽象类与抽象方法

有些父类本身"说不清具体怎么做"，只定下"必须有什么行为"，把实现留给子类——这就是抽象类。用 abstract 修饰：

abstract class Shape {        // 抽象类
    abstract double area();    // 抽象方法：只有声明，没有方法体
    void print() {             // 普通方法：抽象类也能有具体实现
        System.out.println("面积=" + area());
    }
}
  • abstract 方法没有方法体（直接 ; 结尾）；
  • 含抽象方法的类必须声明为 abstract；
  • 抽象类里可以有普通字段和具体方法。

15.2 不能 new，必须被继承

抽象类是"写了半本的说明书"，所以不能直接 new。new Shape() 会编译报错。它必须由子类补全所有抽象方法后才能 new 子类。

class Circle extends Shape {
    double r;
    @Override double area() { return Math.PI * r * r; }  // 补全抽象方法
}
// Shape s = new Shape();   // 报错
Shape s = new Circle();       // OK：多态，指向补全了的子类

如果子类没补全所有抽象方法，那子类也得是 abstract，继续往下传。

15.3 模板方法模式雏形

抽象类最经典的用法：把"算法的骨架"写在具体方法里，把"会变的一步"留成抽象方法让子类填。这叫模板方法模式。

abstract class Game {
    void play() {                 // 模板：固定流程
        start();
        while (!isOver()) round(); // round 由子类决定
        end();
    }
    abstract void start();
    abstract void round();
    abstract boolean isOver();
    abstract void end();
}

子类只要实现 start/round/isOver/end，就能复用整条 play() 流程。这就是"好莱坞原则：别调用我，我会调用你"。

15.4 抽象类 vs 接口（初判）

  • 抽象类：偏"is-a + 共享代码"，单继承，适合一组紧密相关的类共用状态与逻辑；
  • 接口（下章）：偏"能做什么"的能力契约，可多实现，适合跨继承树的通用能力。
经验：要复用代码、表达"是一种"用抽象类；要定义能力、解耦行为规范用接口。

要点一句话
abstract方法无体、类不能 new；含抽象方法的类必须 abstract
