12.1 什么是封装

封装就是把对象的内部数据藏起来，只留几个受控的"门"（方法）让外界安全地读写。就像自动售货机：你不用知道里面怎么运转，只要按按钮（方法）就能买到饮料。

封装 = 隐藏实现细节 + 暴露稳定接口。它的价值是：内部怎么改都行，只要门不变，用你代码的人就不必跟着改。

12.2 四种访问权限

Java 用关键字控制"谁能看见这个成员"，从松到严：

修饰符可见范围
public谁都能访问（最松）
protected同包 + 子类可见
（默认/包私有）同包内可见
private只有本类自己可见（最严）

经验法则：字段一律 private，需要对外暴露时再用 public 的方法（getter/setter）。类本身通常用 public。

12.3 为什么字段不该 public

直接 public int age; 看似省事，但会带来三个真实麻烦：

  • 无法校验：别人能写 s.age = -5;，你的对象瞬间处于非法状态；
  • 无法拦截：年龄变化时你想同步"是否成年"标记，public 字段拦不住；
  • 难以演进：哪天把 age 改成"出生年份推算"，所有直接访问 .age 的代码都得改。
常见坑很多初学者把"public 字段写起来快"当成优点。一旦项目变大、多人协作，public 字段会让状态随处可变、Bug 极难定位。JavaBean 规范与主流框架（Spring、MyBatis）都要求属性通过 getter/setter 访问。

12.4 getter 与 setter：受控的门

把字段私有化，再提供一对方法作为读写门：

public class Student {
    private String name;
    private int age;

    public String getName() { return name; }     // getter：读
    public void setName(String name) { this.name = name; }  // setter：写
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }
}

IDE（IDEA/Eclipse）可以一键生成（右键 → Generate → Getter and Setter）。这套写法的好处：门在你手里，要不要加逻辑你说了算。

12.5 在 setter 里做校验

setter 最实用的瞬间——把"合法性检查"关在门内，保证对象永远是合法状态：

public void setAge(int age) {
    if (age < 0 || age > 150) {
        throw new IllegalArgumentException("年龄必须在 0~150 之间");
    }
    this.age = age;
}

这样任何地方 s.setAge(-5) 都会立刻报错，而不是让一个非法值悄悄混进系统。这就是封装带来的"自我保护"能力。
