14.1 什么是多态

同一行代码，在不同对象上表现出不同行为——这就是多态。它是 OOP 最强大的特性：让你写"面向父类"的通用代码，却能自动适配所有子类。

多态三要素：① 继承（is-a）；② 子类重写父类方法；③ 父类引用指向子类对象。

14.2 向上转型与统一处理

子类对象可以"悄悄"赋给父类类型的引用，这叫向上转型（自动、安全）：

Animal a1 = new Cat();   // 向上转型：Cat 是 Animal
Animal a2 = new Dog();   // Dog 也是 Animal
a1.sound();              // 喵
a2.sound();              // 汪

好处：把一堆子类收进 Animal[] 或 List<Animal>，用一段循环统一处理，新增子类也不用改这段循环——这就是"开闭原则"的体现。

14.3 动态绑定：看左边编译、看右边运行

为什么 a1.sound() 调的是 Cat 的版本而不是 Animal 的？因为 Java 用动态绑定（运行时绑定）：

  • 编译看左边：编译器只认 a1 的声明类型 Animal，所以只能调用 Animal 里存在的方法；
  • 运行看右边：真正执行时，JVM 看对象的实际类型（Cat），调用它重写过的方法。
常见坑只有"实例方法"走动态绑定；static 方法、private 方法、字段不走动态绑定（字段没有重写，只有隐藏）。所以"多态"只对可重写的方法有效。

14.4 instanceof 与向下转型

当你确实需要调用子类特有的方法时，得先把父类引用"向下转型"回子类。但转错类型会抛 ClassCastException，所以先 instanceof 判断：

if (a1 instanceof Cat) {
    Cat c = (Cat) a1;     // 安全向下转型
    c.meow();             // 调用 Cat 特有方法
}

Java 16+ 还支持"模式匹配"一步到位：if (a1 instanceof Cat c) { c.meow(); }。

14.5 多态的工程价值

框架大量使用多态：Spring 的 BeanPostProcessor、JDBC 的 Driver 接口、日志门面 SLF4J……你写的业务代码依赖"接口/父类"，运行时再注入具体实现。这样换实现（换数据库、换日志框架）无需改业务代码。

✓ 本章小结

要点一句话
多态同一代码对不同对象表现不同行为；三要素：继承+重写+父类引用指向子类
向上转型子类→父类，自动安全，便于统一处理
动态绑定编译看左边（声明类型），运行看右边（实际类型）
向下转型需 instanceof 先判断，否则可能 ClassCastException
