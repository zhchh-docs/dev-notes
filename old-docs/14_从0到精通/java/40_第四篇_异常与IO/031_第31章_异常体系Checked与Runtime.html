31.1 Throwable 家谱

所有异常/错误的顶层是 Throwable，分两支：Error（如 OutOfMemoryError、StackOverflowError，通常指 JVM 无法恢复的严重问题，不应捕获）和 Exception（程序可处理的异常）。

Throwable
 ├─ Error          // 不该捕获，如 OOM
 └─ Exception
     ├─ RuntimeException        // 非受检
     └─ 其它（IOException 等）   // 受检

31.2 受检与非受检异常

受检异常（checked）：编译期强制你处理（try-catch 或 throws 声明），如 IOException、SQLException——代表“可预见的外部失败”。非受检异常（RuntimeException 及其子类）：编译不强制，多由程序逻辑错误引起，如 NullPointerException、IllegalArgumentException、ArrayIndexOutOfBoundsException。捕获顺序必须先子类后父类。

try {
  int x = Integer.parseInt("abc"); // 可能抛 NumberFormatException(Runtime)
} catch (NumberFormatException e) {  // 先子类
  e.printStackTrace();
}

31.3 throws 与 throw

throws 在方法签名上声明“我可能抛出这些受检异常，由调用方处理”；throw 是主动抛出一个异常实例。自定义业务异常通常继承 RuntimeException，避免污染所有调用链。

void read(String path) throws IOException { ... }
throw new IllegalArgumentException("id 不能为空");

31.4 捕获顺序与最佳实践

常见坑① catch (Exception e) 一把抓，吞掉 RuntimeException 反而难排查；② 空 catch 块吞异常；③ 用异常做正常流程控制（性能差）。建议：只捕获能处理的异常，保留堆栈，业务异常带错误码。
异常是“意外”，不是“流程分支”；能恢复才捕获，否则让它冒泡。
