38.1 NIO 换了个思路

BIO（Blocking IO）的困境：一个连接一个线程，in.read() 读不到数据就一直阻塞——一万个长连接就要一万个线程，内存和调度都吃不消。

// BIO：线程被 read 卡死，直到对端发来数据
Socket s = server.accept();          // 阻塞等连接
InputStream in = s.getInputStream();
int b = in.read();                   // 阻塞等数据，线程挂起

NIO（Java 1.4 引入，注意不是后来的 NIO.2）的三板斧：

  • Buffer（缓冲区）：数据不直接读写，先搬进缓冲区再加工——IO 变成"内存到内存"的批处理；
  • Channel（通道）：双向的，既能读又能写（流是单向的），且可以配合 Buffer 批量搬运；
  • Selector（选择器）：一个线程轮询多个 Channel 的"就绪事件"（可读/可写/连接到达），谁就绪处理谁——一线程多连接的根基，Netty、Redis、Kafka 都站在这块基石上。
BIO 是"人等数据"，NIO 是"数据等人来取"：把阻塞点从线程挪到缓冲区，线程效率暴涨。

38.2 Buffer 的三个变量

Buffer 是块带位置指针的内存（HeapByteBuffer 或 DirectByteBuffer）：

ByteBuffer buf = ByteBuffer.allocate(1024);   // 堆内缓冲区
// 三个核心变量
int capacity = buf.capacity();   // 容量：1024，固定不变
int position = buf.position();   // 下一个要读写的位置
int limit = buf.limit();         // 读/写边界

// 写模式：往缓冲区塞数据
buf.put("hello".getBytes());     // position 前进 5，limit 仍是 capacity

// 翻转：写 → 读
buf.flip();                      // limit = position(5)，position 归零

// 读模式：从缓冲区取数据
while (buf.hasRemaining()) {
    byte b = buf.get();          // position 前进
}

// 倒带重读 / 清空重写
buf.rewind();                    // position 归零，limit 不变（再读一遍）
buf.clear();                      // position 归零，limit = capacity（准备重写）
  • flip 是灵魂：写完翻转成"可读模式"，经典易错点是忘了 flip 直接 get，读到 limit=capacity 一大片空数据；
  • clear() 只是重置指针，不清数据——旧字节还在，靠 position 覆盖；
  • 直接缓冲区（allocateDirect）用堆外内存，少一次拷贝，适合大文件长连接，但分配释放成本高。

38.3 Channel 与 Selector 一瞥

// 文件 Channel：双向，配合 Buffer
try (FileChannel ch = new RandomAccessFile("data.txt", "rw").getChannel()) {
    ByteBuffer buf = ByteBuffer.allocate(48);
    int n = ch.read(buf);            // 文件 → 缓冲区
    buf.flip();
    while (buf.hasRemaining()) {
        ch.write(buf);               // 缓冲区 → 文件（同一 channel 双向！）
    }
}

网络编程里，SocketChannel 可以切成非阻塞模式：

// Selector：单线程管理多个 Channel 的骨架
Selector sel = Selector.open();
SocketChannel ch = SocketChannel.open();
ch.configureBlocking(false);              // 关键：非阻塞
ch.register(sel, SelectionKey.OP_READ);   // 登记"我可读了通知我"

while (true) {
    sel.select();                          // 阻塞直到有事件
    for (SelectionKey key : sel.selectedKeys()) {
        if (key.isReadable()) {
            ByteBuffer buf = ByteBuffer.allocate(256);
            ch.read(buf);                  // 有数据才读，不会干等
            // ... 处理、写回
        }
    }
    sel.selectedKeys().clear();
}
  • 这条代码骨架就是 Reactor 模式的雏形：事件到达 → 分发 → 处理；Netty 把它封装成了工业级框架；
  • Java 7 的 NIO.2（java.nio.file：Path/Files/watchService、AIO 的 AsynchronousFileChannel）解决的是"文件 API 难用"，和这里的 NIO 是两代东西，别混淆。

✓ 本章小结

要点一句话
NIO 三件套Buffer 搬数据、Channel 双向通道、Selector 事件分发
BIO vs NIO一连接一线程阻塞等 vs 一线程多连接事件驱动
Buffer 指针capacity 定容量；写完 flip；读完 clear；rewind 重读
非阻塞前提configureBlocking(false) + register 到 Selector
应用Netty/Redis/Kafka 的地基；NIO.2 是另一代文件 API
