35.1 字节流家族与 read 的返回值

图片、视频、压缩包、class 文件……磁盘上的一切都是字节序列。Java 用字节流读写它们：输入流管"读进来"，输出流管"写出去"。

// 字节输入流家族（从抽象到具体）
InputStream
 ├─ FileInputStream        文件
 ├─ BufferedInputStream    缓冲（套在别的流外面）
 ├─ ByteArrayInputStream   内存字节数组
 └─ DataInputStream        读写基本类型

// 字节输出流家族
OutputStream
 ├─ FileOutputStream       文件
 ├─ BufferedOutputStream   缓冲
 ├─ ByteArrayOutputStream  内存字节数组
 └─ PrintOutputStream / ObjectOutputStream  打印 / 对象序列化

read() 为什么返回 int？

// int read()：读一个字节，返回 0~255；读到文件末尾返回 -1
try (InputStream in = new FileInputStream("a.jpg")) {
    int b;
    while ((b = in.read()) != -1) {   // 必须是 int 比较，不能是 byte
        // b 里是 0~255 的一个字节
    }
}
  • byte 取值范围是 -128~127，装不下 0~255 全部字节值，更腾不出一个值表示"结束"；
  • int 用 -1 表示 EOF（End Of File），0~255 表示真实字节——这是所有 read 循环的通用约定；
  • 批量读用 read(byte[] buf)：返回本次实际读到的字节数（也可能 -1），一次搬一块，比逐字节快几个数量级。
看到 while ((b = in.read()) != -1) 要条件反射：这是 Java IO 的"Hello World"循环。

35.2 缓冲流：为什么快、快多少

FileInputStream 每次 read 都是一次系统调用——用户态切内核态、磁盘寻道，一次几十微秒起。逐字节读 1MB 文件就是一百万次系统调用。

// 缓冲流：套娃模式，给流加一个 8KB 默认的内存缓冲区
InputStream in = new BufferedInputStream(
                     new FileInputStream("a.jpg"));

// 读的时候：一次性从磁盘搬 8KB 进缓冲区，后续 read 直接从内存拿
// 缓冲区空了，再触发下一次磁盘读取
  • BufferedInputStream 默认缓冲区 8192 字节，可用构造参数自定义；
  • 效果：把"百万次系统调用"压成"128 次"，大文件拷贝常见 10 倍以上提速；
  • 输出同理：BufferedOutputStream 攒够一批再 flush 落盘，减少写放大；
  • 关闭流会自动 flush，但想中途确保数据落地（如日志），要手动 flush()。
常见坑忘记关闭最外层的包装流没关系，但 close 的是最外层时才会连锁关闭内层；只 close 内层不会 flush 外层的缓冲区。用 try-with-resources 包住最外层即可。

35.3 try-with-resources 标准拷贝模板

所有实现 AutoCloseable 的流都可以放进 try 的括号里，Java 保证无论正常结束还是抛异常都会自动 close，且 close 抛的异常不会覆盖 try 里的主异常。

public static void copyFile(String src, String dst) throws IOException {
    try (InputStream in = new BufferedInputStream(new FileInputStream(src));
         OutputStream out = new BufferedOutputStream(new FileOutputStream(dst))) {
        byte[] buf = new byte[8192];
        int n;
        while ((n = in.read(buf)) != -1) {   // 一次最多读 8KB
            out.write(buf, 0, n);            // 只写实际读到的 n 个字节！
        }
    }   // 自动 close + flush
}
  • write(buf, 0, n) 的 n 不能省：最后一次 read 通常填不满 buf，省了 n 会把上一次的残留字节也写进去，造成文件尾部污染；
  • try 里可以声明多个资源，用分号隔开，按声明逆序关闭；
  • 拷贝大文件还有更快的路：Files.copy(Path, Path)（NIO.2，第 38 章展开）——但手写循环是理解 IO 的地基。
模板背下来：Buffered 双套管 + byte[8192] + (n = read(buf)) != -1 + write(buf, 0, n)。

✓ 本章小结

要点一句话
字节流InputStream/OutputStream 两大抽象，一切文件皆字节
read 返回值int：0~255 是数据，-1 是 EOF；byte 装不下 255 更没有 EOF
缓冲流内存缓冲区把系统调用次数打下来，读写都提速
关闭与 flushclose 自动 flush；想中途落地手动 flush
拷贝模板try-with-resources + read(buf) 循环 + write(buf, 0, n)
