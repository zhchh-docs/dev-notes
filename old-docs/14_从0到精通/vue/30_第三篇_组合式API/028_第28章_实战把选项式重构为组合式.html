28.2 选项式原码：用户中心页

下面是一个典型的 Vue2 时代选项式组件：用户列表 + 筛选 + 搜索。先看原码，再逐段重构。

<script>
export default {
  props: { role: String },
  emits: ['view'],
  data() {
    return {
      list: [],
      keyword: '',
      page: 1,
      loading: false
    }
  },
  computed: {
    filteredList() {
      return this.list.filter(u => u.name.includes(this.keyword))
    },
    totalPages() {
      return Math.max(1, Math.ceil(this.list.length / 10))
    }
  },
  watch: {
    keyword() { this.page = 1 }
  },
  created() {
    this.fetchList()
  },
  methods: {
    async fetchList() {
      this.loading = true
      this.list = await fetch('/api/users').then(r => r.json())
      this.loading = false
    },
    viewUser(user) {
      this.$emit('view', user)
    }
  }
}
</script>

28.3 逐段对照重构

对照上面的映射表，一段一段翻：

<script setup>
import { ref, computed, watch } from 'vue'

// props / emits：写法不变
const props = defineProps({ role: String })
const emit = defineEmits(['view'])

// data → ref（每个数据一个 ref）
const list = ref([])
const keyword = ref('')
const page = ref(1)
const loading = ref(false)

// computed → computed(() => ...)
const filteredList = computed(() =>
  list.value.filter(u => u.name.includes(keyword.value))
)
const totalPages = computed(() =>
  Math.max(1, Math.ceil(list.value.length / 10))
)

// watch → watch(源, 回调)
watch(keyword, () => { page.value = 1 })

// created → setup 顶层直接执行（或 onMounted，见 27 章）
fetchList()

// methods → 普通函数
async function fetchList() {
  loading.value = true
  list.value = await fetch('/api/users').then(r => r.json())
  loading.value = false
}
function viewUser(user) {
  emit('view', user)
}
</script>

关键差别再点一遍：

  • 没有 this：所有变量直接按名引用；
  • JS 里要 .value：list.value、keyword.value；模板里自动解包；
  • created 没了：setup 顶层执行就相当于 created；需要 DOM 时再用 onMounted。

28.4 mixins → 组合式函数

假设原项目里有一个 paginationMixin，被多个组件混入。它的痛点是：你在组件里看到 page，不知道它来自 mixin 还是自己的 data。重构成组合式函数：

// composables/usePagination.js（替代 paginationMixin）
import { ref } from 'vue'

export function usePagination(initialPage = 1, pageSize = 10) {
  const page = ref(initialPage)
  const pageSize = ref(pageSize)

  function next() { page.value++ }
  function prev() { page.value-- }
  function reset() { page.value = initialPage }

  return { page, pageSize, next, prev, reset }
}
<!-- 组件里：命名由你，冲突显式解决 -->
<script setup>
import { usePagination } from '@/composables/usePagination'

// 原来 mixin 里的 page 会和组件自己的 page 冲突；
// 现在解构出来想叫什么叫什么：userPage
const { page: userPage, next, prev } = usePagination()
</script>

mixins 的命名冲突在组合式函数里消失了：返回值你自己命名，谁和谁冲突一目了然。

28.5 渐进迁移策略

老项目不可能一天重写完。Vue 允许同一组件内选项式与 setup 混用，可以渐进迁移：

  1. 阶段一：新增逻辑全部写进 <script setup>，旧 export default 保留；
  2. 阶段二：逐段把 data/methods/computed 搬进 setup，一次搬一块、跑一次测试；
  3. 阶段三：生命周期与 watch 迁移；最后删掉选项式壳。
提醒混用时有个坑：setup 顶层变量与选项式 data 同名会冲突。迁移时先把要搬进 setup 的字段改名（如 list → userList），确认无冲突再搬。

常见迁移路径与边界：

场景做法注意
新增小功能直接写 <script setup>与旧选项式并存
整组件重写一次性迁完，跑全量测试换分支、可回滚
mixins 多组件共享先抽成 useXxx，再逐组件替换每个组件单独改，互不影响
字段同名冲突setup 里改名后再引用别让两个状态同名

28.6 迁移自检清单与常见坑

每次重构完，对照这份清单过一遍：

  • □ data 全部变 ref/reactive，没有遗留 this.xxx；
  • □ JS 里访问 ref 都写了 .value，模板里没多写 .value；
  • □ computed 是函数，不是对象属性；
  • □ watch 源正确：监听 reactive 字段用 getter；
  • □ 生命周期钩子：created 的逻辑进了 setup 或 onMounted；
  • □ mixins 已抽成 useXxx，命名冲突显式解决；
  • □ 混用字段无同名：setup 变量与旧 data 不撞名；
  • □ 行为验证：重构前后渲染同一组数据，结果一致。
  • 坑 1迁移后 this 没清干净：setup 里写 this.list 直接报错。所有 this.xxx 换成变量名。
  • 坑 2computed 写成普通方法：失去缓存，每次模板访问都重算。派生值必须 computed。
  • 坑 3watch 漏 deep：监听 ref 装对象不更新。需要时加 { deep: true }。
  • 坑 4把 created 的异步请求放进 setup 顶层却没等：常规就放 onMounted，别阻塞首屏。
  • 坑 5一次性全量重写不跑测试：一次改太多，出问题难定位。一次迁一块、跑一次测试。
