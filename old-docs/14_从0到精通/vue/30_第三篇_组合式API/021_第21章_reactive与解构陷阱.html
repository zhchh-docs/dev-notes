第 21 章 reactive 与解构陷阱

教科书 第 21 章 / 共 76 章 · 预计 30 分钟 · 示例可直接运行

reactive 是 Vue3 响应式的另一半：它接管整个对象，但也带来了最经典的陷阱——解构就失效。本章讲透解构为什么丢响应、toRefs/toRef 怎么救、什么时候别用 reactive。

21.1 reactive：接管整个对象

reactive(obj) 返回原对象的响应式代理：之后对这个代理的任何属性读写，都会被 Vue 拦截并追踪。它适合"一个对象装着一组相关状态"的场景——最典型就是表单：

<script setup>
import { reactive } from 'vue'

const form = reactive({
  username: '',
  email: '',
  age: 18
})

// 直接改属性，页面自动更新——不需要 .value
function submit() {
  console.log(form.username, form.email)
}
</script>

<template>
  <input v-model="form.username" placeholder="用户名" />
  <input v-model="form.email" placeholder="邮箱" />
  <button @click="submit">提交</button>
</template>

与 ref 对比，它有两个"爽点"和一个"坑"：

  • 爽点 1：没有 .value，form.username 就是直观的属性访问；
  • 爽点 2：直接 form.xxx = yyy 即可，和写普通对象一模一样；
  • 坑：这个代理有严格的"保命边界"，跨过边界就失效——下两节就是边界现场。
输入是否响应式说明
reactive({ a: 1 })是普通对象代理
reactive([1, 2])是数组也代理，按下标读写被追踪
reactive(new Map())是Map / Set 的 get/set/has/forEach 都被支持
reactive(123)否（运行告警）原始类型不能用 reactive，只能 ref
同一对象二次 reactive返回同一代理幂等，不会重复包装

21.2 解构陷阱：一行代码失去响应

这是组合式 API 新手遇到的第一个"玄学 bug"：

import { reactive } from 'vue'

const form = reactive({ username: '张三', age: 18 })

// 看起来很爽：解构出来直接用
const { username, age } = form

age = 20            // 页面里 age 还是 18？！
console.log(form.age)   // 20 了
console.log(age)        // 20 了——但页面没更新

为什么？看图。form 是代理对象，username 和 age 是通过代理读出来的普通值（这里是原始类型）。解构那一刻，你拿到的是值的快照，而不是"通往代理的引用"：

图 21-1 解构把响应式值复印成普通值（示意）

本质：响应性挂在"代理对象的属性访问"这条通道上，不挂在值本身。一旦你把值从通道里取出来单独放着，它就是个孤儿普通变量。

记住这个直觉：reactive 对象本身别拆，拆出来就不是响应式的了。

21.3 toRefs 与 toRef：把解构救回来

Vue 提供了救援工具。toRefs(reactiveObj) 会把代理对象的每个字段转成一个 ref——这个 ref 和原属性是双向绑定的：

import { reactive, toRefs, ref } from 'vue'

const form = reactive({ username: '张三', age: 18 })

// toRefs：每个字段变成 ref，且与 form 双向同步
const { username, age } = toRefs(form)

age.value = 20            // 改 ref
console.log(form.age)      // 20 ✅ 同步回 reactive
form.age = 25             // 改 reactive
console.log(age.value)     // 25 ✅ 反向也同步

// 解构出来的 username 是个 ref，模板里照样自动解包
// <p>{{ username }}</p>  → 正常显示、正常更新
// toRef：给 reactive 对象的某一个字段单独做一个 ref
const ageRef = toRef(form, 'age')
ageRef.value = 30          // 与 form.age 双向同步

// toRef 也能给普通值做一个"常量 ref"（用于组合式函数返回值统一）
const staticRef = toRef(100)
staticRef.value            // 100，不可变常量容器
工具做什么典型场景
toRefs(obj)把 reactive 对象所有字段批量转 ref组合式函数 return 一个 reactive，组件解构使用时
toRef(obj, key)把单个字段转 ref只需要其中一两个字段
toRef(value)把普通值包成常量 ref统一返回值形态（ref 与 reactive 混用处）

提醒用 toRefs 是为了解构安全，不是为了解构好看。如果你直接 form.username 用，就别 toRefs——多一层 ref 包装徒增心智负担。

21.4 整体替换：reactive 对象被重新赋值

第二个经典事故：

import { reactive } from 'vue'

let state = reactive({ list: [1, 2, 3] })

async function loadData() {
  const res = await fetch('/api/list').then(r => r.json())
  state = reactive({ list: res })   // ❌ 组件里原来持有的还是旧代理！
}

问题出在：你重新赋值的是 state 这个变量本身，模板和渲染函数在 setup 阶段已经绑定了"旧代理对象"那个引用，你换变量指向新代理，旧引用纹丝不动。

正确姿势有两种：

// 姿势一：改属性，不换对象
state.list = res

// 姿势二：展开替换
Object.assign(state, { list: res })

// 姿势三：用 ref 装整个对象，直接换 .value
const state = ref({ list: [] })
state.value = { list: res }   // ✅ ref 替换不丢响应

这正是第 20 章"ref 适合整体替换"的理由：reactive 是代理原对象，换不动；ref 是容器，.value 里爱装啥装啥。要整体替换的状态，天生该用 ref。

21.5 readonly 与 reactive 的边界

第 18 章用过 readonly：祖先 provide 出去的数据，包一层 readonly 防止后代直接改。这里把它和 reactive 放一起看：

import { reactive, readonly } from 'vue'

const state = reactive({ count: 0 })
const copy = readonly(state)

copy.count = 1      // ❌ 开发环境下告警，不生效
state.count = 1     // ✅ 正常改，copy 自动同步更新

边界一句话：readonly 是"同一个响应式对象的只读视图"，它本身也是响应式的（会随原对象更新），但写操作被拒绝。

  • reactive：能改，追踪所有读写；
  • readonly：能读（追踪读），不能写；
  • reactive 的局限再强调：原始类型不行（reactive(0) 会告警）、深层对象自动代理（嵌套对象访问时也是响应式的）、Map/Set 全支持但 WeakMap/WeakSet 不支持。

21.6 常见坑

  • 坑 1解构 reactive 直接用：const { a, b } = state 之后改 a 页面不更新。要么不解构（直接 state.a），要么 toRefs(state) 之后解构。
  • 坑 2整体替换 reactive 对象：state = reactive(newData) 绑不住。用 Object.assign 或改用 ref。
  • 坑 3把 reactive 当 props 直接解构：props 是 shallow 响应式对象，解构 props 也会丢响应，要 toRefs(props)（第 11 章 props 已讲过）。
  • 坑 4解构后给变量重新赋值想触发更新：age = 20 只是普通赋值，页面无反应。改 form.age = 20 或 ageRef.value = 20。
  • 坑 5以为 readonly 是深拷贝：它是"视图"，原对象改了它照样变。想隔离就复制，不是 readonly。
  • 坑 6用 reactive 装数组后做整体重置：list = [] 无效；list.length = 0 或 list.splice(0) 才正确。

✓ 本章小结

要点一句话
reactive代理整个对象/数组/Map；属性读写被拦截追踪，无需 .value
解构陷阱解构取出的是值快照，与代理断开，改它不触发更新
toRefs把 reactive 各字段转双向绑定的 ref，解构也不丢响应
整体替换换对象本身无效；改属性/Object.assign，或直接用 ref
readonly同一响应式对象的只读视图；写拒绝、读同步
边界原始类型不能 reactive；Map/Set 支持；嵌套对象自动代理

A 基础复现解构 bug：写一个 reactive({ count: 0 })，解构出 count，在按钮事件里 count++ 并在模板显示；观察页面是否更新。然后用 toRefs 修复，再验证。
B 进阶写一个 useUser() 组合式函数：内部 reactive({ name, age, email })，return 出去。组件里用解构拿到三个字段并渲染，要求改任意字段页面同步更新（提示：return 时用 toRefs）。
