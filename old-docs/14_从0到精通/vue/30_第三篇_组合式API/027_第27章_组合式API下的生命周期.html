27.1 onXxx：组合式生命周期钩子清单

组合式 API 里，每个选项式生命周期钩子对应一个 onXxx 函数，在 setup 中调用：

<script setup>
import { onBeforeMount, onMounted, onBeforeUpdate, onUpdated,
         onBeforeUnmount, onUnmounted } from 'vue'

onBeforeMount(() => console.log('挂载前'))
onMounted(() => console.log('挂载后：DOM 可用'))
onBeforeUpdate(() => console.log('更新前：DOM 即将变化'))
onUpdated(() => console.log('更新后：DOM 已变化'))
onBeforeUnmount(() => console.log('卸载前：清理资源'))
onUnmounted(() => console.log('卸载后'))
</script>

组合式生命周期没有 created / beforeCreate——因为 setup() 本身就在这两个阶段执行，setup 顶层代码就是 created。

27.2 与选项式钩子的映射表

选项式组合式触发时机
beforeCreate（无对应，setup 本身）实例初始化后
created（无对应，setup 顶层）数据已响应式化
beforeMountonBeforeMount挂载 DOM 前
mountedonMountedDOM 挂载后，可操作 DOM
beforeUpdateonBeforeUpdate响应式变化、重新渲染前
updatedonUpdated重新渲染与 DOM 更新后
beforeUnmountonBeforeUnmount实例卸载前（Vue3 改名）
unmountedonUnmounted卸载后（Vue2 叫 destroyed）

27.3 keep-alive 与错误捕获钩子

还有两个特殊钩子，呼应第 19 章的 keep-alive：

<script setup>
import { onActivated, onDeactivated, onErrorCaptured } from 'vue'

// 组件被 <keep-alive> 缓存：切走时休眠，切回时唤醒
onActivated(() => console.log('被唤醒（keep-alive 切回）'))
onDeactivated(() => console.log('被休眠（keep-alive 切走）'))

// 捕获后代组件的错误（自己组件的错误不捕获）
onErrorCaptured((err, instance, info) => {
  console.error('捕获到子组件错误', err, info)
  return true   // 返回 true 阻止错误继续向上冒泡
})
</script>

27.4 在组合式函数里用生命周期

第 23 章 useMouse 已经用过。核心规则再强调一次：

  • 组合式函数在 setup 同步段被调用，里面的 onXxx 自动绑定到当前组件；
  • 资源在函数内申请，就在函数内 onUnmounted 清理——调用方零负担；
  • 不能在 await / setTimeout 之后调 onXxx，否则 Vue 不知道绑给谁。
// composables/useDocumentTitle.js
import { ref, onMounted, onUnmounted } from 'vue'

export function useDocumentTitle(initial) {
  const title = ref(initial)
  function update() { document.title = title.value }

  onMounted(() => {
    update()
    window.addEventListener('focus', update)
  })
  onUnmounted(() => window.removeEventListener('focus', update))

  return { title }
}

27.5 setup 阶段与 mounted 阶段的区别

新手最容易犯的错：把"只在挂载后才该做的事"写进 setup 顶层。两者区别：

阶段能做什么不能做什么
setup 阶段声明响应式状态、定义函数、调组合式函数、注册 onXxx访问模板 ref（null）、操作 DOM、调第三方 DOM 库
onMounted访问真实 DOM、模板 ref 已有值、初始化图表/编辑器修改响应式状态（会触发额外渲染）

与 watch 的关系：watchPostEffect 相当于"DOM 更新后立刻跑"，行为接近 onUpdated；watchSyncEffect 是同步执行。它们不是生命周期钩子，但常用于"DOM 更新后做副作用"，与 onUpdated 同类。

27.6 常见坑

  • 坑 1await 之后调 onMounted：报错 "no active component instance"。组合式函数与生命周期都要在 setup 同步段调用。
  • 坑 2把数据请求写进 onMounted 之外：setup 顶层发请求会阻塞首次渲染（除非 Suspense）。常规做法就是 onMounted 里请求。
  • 坑 3onUnmounted 忘记清理：addEventListener、setInterval、WebSocket 不清理会内存泄漏。资源谁申请谁清理。
  • 坑 4以为 onActivated 在首次挂载也触发：首次挂载走 onMounted；onActivated 只在 keep-alive 切回时触发。
  • 坑 5onUpdated 里改状态造成死循环：onUpdated 改响应式 → 触发 onUpdated → 死循环。派生值用 computed。

✓ 本章小结

要点一句话
钩子函数名onBeforeMount/onMounted/onBeforeUpdate/onUpdated/onBeforeUnmount/onUnmounted
created/beforeCreate无对应——setup 本身就是这两个阶段
keep-alive 钩子onActivated 唤醒、onDeactivated 休眠（呼应 19/64 章）
错误捕获onErrorCaptured 捕后代错误，return true 阻止冒泡
组合式函数内setup 同步段调用即可绑定组件；资源谁申请谁清理

✎ 本章习题

A 基础写一个组件，把六个 onXxx 钩子都打 console.log，验证执行顺序：setup → onBeforeMount → onMounted →（改状态）→ onBeforeUpdate → onUpdated。
B 进阶写 useDocumentTitle(initial)：返回一个 ref，改它时同步更新 document.title；组件卸载时恢复原标题。验证：① 组件卸载后监听器被移除；② 在两个组件分别调用互不干扰。
C 挑战结合第 19 章 keep-alive：写一个带计数器的组件，包在 keep-alive 里，用 onActivated/onDeactivated 打印休眠与唤醒。验证：① 首次挂载只走 onMounted；② 切走再切回走 onDeactivated → onActivated；③ 计数状态是否保留。
