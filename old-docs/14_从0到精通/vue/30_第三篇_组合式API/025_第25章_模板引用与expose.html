25.1 模板引用：抓住 DOM 元素

响应式系统之外，Vue 也允许你"伸手抓住真实 DOM"：模板里写 ref="xxx"，组件里用同名 ref 接住：

<script setup>
import { ref, onMounted } from 'vue'

const inputRef = ref(null)   // 同名 ref接住模板里 ref="inputRef"

onMounted(() => {
  inputRef.value.focus()      // 挂载后拿到真实 <input> DOM，调原生方法
})
</script>

<template>
  <input ref="inputRef" placeholder="自动聚焦" />
</template>

几个关键点：

  • ref 的初始值是 null，挂载后才有值——所以操作 DOM 要在 onMounted 里；
  • 拿到的就是原生 DOM 元素，可以调 .focus() / .scrollIntoView() / .getBoundingClientRect()；
  • Vue 3.5+ 还提供了 useTemplateRef('inputRef')，不用再声明一个同名 ref 变量：
// Vue 3.5+ 新写法
import { useTemplateRef, onMounted } from 'vue'

const inputRef = useTemplateRef('inputRef')   // 字符串对应模板里的 ref 名
onMounted(() => inputRef.value.focus())

25.2 引用组件实例

把 ref 放在组件标签上，拿到的是子组件实例。默认（没有 defineExpose 时）你能访问子组件的公共实例属性，但工程上推荐显式 defineExpose 暴露：

<!-- 子组件：MyForm.vue -->
<script setup>
function validate() { console.log('校验通过') }
function reset() { console.log('重置') }

// 只暴露这两个方法，父组件只能调这两个
defineExpose({ validate, reset })
</script>

<!-- 父组件 -->
<script setup>
import { ref } from 'vue'
import MyForm from './MyForm.vue'

const formRef = ref(null)
function submit() {
  formRef.value.validate()    // 命令式调子组件方法
}
</script>

<template>
  <MyForm ref="formRef" />
  <button @click="submit">提交</button>
</template>

defineExpose 是子组件对外的唯一门：你显式列出什么，父组件才能用什么；不 expose，父组件拿到的是一个空壳。

25.3 v-for 中的 ref 与函数 ref

循环里的 ref 不是单个元素，而是数组：

<script setup>
import { ref, onMounted } from 'vue'

const itemRefs = ref([])

onMounted(() => {
  console.log(itemRefs.value.length)   // DOM 元素数组
  itemRefs.value[0].focus()
})
</script>

<template>
  <input
    v-for="(item, i) in list"
    :key="i"
    :ref="el => itemRefs[i] = el"   <!-- 函数 ref：逐个登记 -->
  />
</template>

函数 ref 的通用形态：:ref="(el) => 把 el 存进某个结构"。它比字符串 ref 更灵活——可以放进数组、Map、或直接关联到数据项。

提醒v-for 的 ref 数组顺序与列表顺序对应，但不要依赖下标做长期缓存——列表增删时元素会重排，下标映射会乱。用函数 ref 按 key 登记更稳。

25.4 defineExpose：控制暴露面

为什么需要 defineExpose？两个工程理由：

  • 封装性：子组件内部有一堆 ref 和方法，父组件不该全部摸到。defineExpose 就是"最小公开 API"；
  • 类型安全：TS 下 InstanceType<typeof MyForm> 只推导出 expose 出来的成员，父组件写错方法名会报错。
<script setup>
import { ref } from 'vue'

const dialogVisible = ref(false)
const list = ref([])

function open() { dialogVisible.value = true }
function close() { dialogVisible.value = false }
function refresh() { /* 重新拉数据 */ }

// 对外只暴露这三个；list、dialogVisible 内部用，不暴露
defineExpose({ open, close, refresh })
</script>

注意：<script setup> 的组件默认是"封闭的"——即使你不写 defineExpose，父组件通过模板 ref 也拿不到组件内部的 ref（只有 defineExpose 列出的才行）。这与选项式 API 时代"实例上什么都能摸"完全不同。

25.5 与 props / 事件的分工

父子通信有三条通道，各自职责不同：

通道方向与用途典型例子
props父 → 子，数据输入（声明式）<MyList :data="list" />
事件 emit子 → 父，通知发生了什么（声明式）emit('select', item)
模板 ref + expose父 → 子，命令式调用方法formRef.value.validate()

判断标准很简单：

  • 父组件只是给数据 → props；
  • 子组件告诉父组件发生了什么 → emit；
  • 父组件主动发起一个子组件动作（校验、打开弹窗、滚动到底）→ ref + expose。

能用 props/事件解决的，就别用模板 ref；ref 是"命令式逃生舱"，只在真的需要主动调子组件方法时才用。

25.6 常见坑

  • 坑 1在 setup 阶段就访问 ref.value：此时 DOM 还没挂载，是 null。要在 onMounted 里。
  • 坑 2以为父组件能直接调子组件内部方法：没 defineExpose 就调不到。需要对外暴露就显式 expose。
  • 坑 3v-for 里 ref 当成单个元素用：它是数组。遍历或用函数 ref 按 key 登记。
  • 坑 4过度使用模板 ref：能用 props/事件的场景却用 ref 调方法，会让数据流变成隐式的、难追踪。优先声明式。
  • 坑 5在 v-if 切换后忘记 ref 变 null：元素被 v-if 移除后，对应 ref 会重置为 null；再访问要判空。
  • 坑 6useTemplateRef 拼错字符串：3.5+ 的新写法，字符串要与模板里 ref 名完全一致，拼错会得到 null。
