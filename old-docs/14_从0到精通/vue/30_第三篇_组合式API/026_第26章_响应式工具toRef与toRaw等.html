26.1 toRef / toRefs：解构响应性

第 21 章讲过：解构 reactive 会丢响应。toRefs 把整个 reactive 对象的字段转成 ref，toRef 转单个字段。复习一下它们的关键性质——与原属性双向同步：

import { reactive, toRefs, toRef } from 'vue'

const state = reactive({ name: '张三', age: 18 })

// toRefs：批量转 ref
const { name, age } = toRefs(state)
name.value = '李四'      // state.name 同步变
state.age = 20           // age.value 同步变

// toRef：单个字段
const ageRef = toRef(state, 'age')

它最常见的工程用途是组合式函数 return reactive 对象：调用方解构后仍是响应式的。第 23 章的 useUser 就是这个模式。

26.2 判定与解包：isRef / unref

写组合式函数时，经常要判断"传进来的到底是不是 ref"：

import { isRef, isReactive, isProxy, unref, ref } from 'vue'

const count = ref(0)
isRef(count)         // true
isReactive(count)    // false
isProxy(count)       // true（ref 内部也是代理包装）

// unref：如果是 ref 就取 .value，不是就原样返回——写工具函数极常用
unref(count)         // 0
unref(123)           // 123

// 等价于：val = isRef(x) ? x.value : x
API判断什么典型用途
isRef(x)x 是不是 ref 对象工具函数参数归一化
isReactive(x)x 是不是 reactive 代理区分普通对象与响应式对象
isProxy(x)x 是不是任何一种 Vue 代理（reactive/readonly）边界判断
unref(x)ref 取 .value，否则原样统一取值

26.3 toRaw / markRaw：绕过代理

Vue 的响应式是有成本的：每个对象都要被 Proxy 代理，深层属性都是响应式的。某些场景你就是不希望它被代理：

import { reactive, toRaw, markRaw } from 'vue'

const state = reactive({ user: { name: '张三' } })

// toRaw：拿到代理背后的原始对象（只读、不追踪）
const rawUser = toRaw(state.user)

// markRaw：标记一个对象"永远不要被代理"
import { markRaw, ref } from 'vue'
class BigData { /* 大型表格数据实例，带方法 */ }
const big = ref(markRaw(new BigData()))
// big.value 不是响应式代理——它不会被 Vue 追踪读写
// 适合：第三方类实例、大型数据结构、只渲染一次不更新的对象

markRaw 的典型场景：表格行数据、第三方类实例、canvas/WebGL 对象——你不需要它们的属性变化触发更新，代理纯属浪费。

26.4 shallow 系列与 triggerRef

shallowRef 只追踪 .value 整体替换，不深入内部；shallowReactive 只代理第一层属性：

import { shallowRef, triggerRef } from 'vue'

// shallowRef：大对象整体替换才更新
const list = shallowRef([])

// 直接改 list.value.push(x) —— shallowRef 不会触发更新！
list.value.push({ name: 'A' })

// 必须手动 triggerRef 通知，或整体替换
list.value = [...list.value, { name: 'B' }]   // ✅ 触发更新
triggerRef(list)                              // ✅ 手动触发
API代理深度用途
shallowRef(x)只追踪 .value 整体大型列表数据：整体替换才更新
shallowReactive(obj)只代理第一层属性顶层字段响应、嵌套对象不追踪
shallowReadonly(obj)只读 + 只浅层只读视图、避免深层冻结
triggerRef(ref)手动触发 shallowRef 更新不得不改 .value 内部时

26.5 customRef：手写防抖 ref

customRef 让你自己控制 ref 的 track/trigger 时机。最经典的用途是防抖 ref：

import { customRef } from 'vue'

// 防抖 ref：赋值后延迟 delay ms 才真正更新视图
function useDebouncedRef(initial, delay = 300) {
  let timer = null
  return customRef((track, trigger) => ({
    get() {
      track()               // 读：收集依赖
      return initial
    },
    set(newVal) {
      clearTimeout(timer)
      timer = setTimeout(() => {
        initial = newVal
        trigger()           // 写：延迟后才触发更新
      }, delay)
    }
  }))
}

// 组件里
const keyword = useDebouncedRef('', 300)
// 输入框 v-model 它：输入后 300ms 才触发搜索

这个例子把 ref 的本质又讲了一遍：track = "记录谁在用我"，trigger = "通知他们我变了"。customRef 就是让你插在这两步之间做手脚（防抖、节流、日志、校验）。

26.6 工具选用一览与常见坑

需求用什么别用什么
解构 reactive 不丢响应toRefs / toRef直接解构
判断参数是否 refisRef / unref手动 typeof
大对象不需要响应式markRaw普通 ref（白白代理）
大列表整体替换才更新shallowRef深 ref（深层追踪浪费）
防抖输入customRef 或 VueUse useDebounce自己写 setTimeout 队列
  • 坑 1toRaw 拿到的对象改了不更新视图：它是原始对象，不被追踪。改完要手动重新赋值或用 reactive。
  • 坑 2markRaw 之后又放进 reactive：markRaw 是永久标记，之后放进 reactive 也不会被代理。
  • 坑 3shallowRef 改 .value 内部却不 trigger：视图不更新。要么整体替换，要么 triggerRef。
  • 坑 4过度使用 shallow：日常业务数据普通 ref 即可，shallow 是性能优化手段，不是默认选择。
