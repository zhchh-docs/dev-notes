22.1 computed：缓存与可写形式

第 5 章讲过：computed 是"从已有状态派生新值"，并且带缓存——依赖没变就不会重算。组合式写法就是一个函数：

<script setup>
import { ref, computed } from 'vue'

const firstName = ref('三')
const lastName = ref('张')

// 只读 computed：传入 getter 函数
const fullName = computed(() => lastName.value + firstName.value)

// 可写 computed：传入 { get, set }
const fullNameWritable = computed({
  get: () => lastName.value + firstName.value,
  set: (newVal) => {
    lastName.value = newVal[0]
    firstName.value = newVal.slice(1)
  }
})

fullNameWritable.value = '李四'    // 触发 set → lastName='李', firstName='四'
</script>

什么时候用可写 computed？两个典型场景：

  • 双向绑定到"派生值"：比如弹窗的 visible 实际是父组件传的 prop，你想 v-model 它，就用可写 computed 在 set 里 emit 事件；
  • 表单字段的中间形态：输入框绑定"格式化后再显示"的值，set 里拆回原始字段。

computed 的价值不是"少写代码"，而是缓存 + 声明式派生：依赖不变就不重算，模板里用多少次都只算一次。

22.2 watch：多源、immediate 与深度

组合式 API 里 watch(数据源, 回调, 选项)。它比选项式 watch 强大的地方在于：数据源可以是 ref、getter 函数、或它们的数组。

<script setup>
import { ref, reactive, watch } from 'vue'

const keyword = ref('')
const page = ref(1)
const form = reactive({ age: 18 })

// ① 监听单个 ref
watch(keyword, (newVal, oldVal) => {
  console.log('关键词变了', newVal, oldVal)
})

// ② 多源数组：任一变化都触发，回调拿到新旧数组
watch([keyword, page], ([newK, newP], [oldK, oldP]) => {
  console.log('关键词或页码变了')
})

// ③ 监听 reactive 对象里某个字段：用 getter 函数
watch(
  () => form.age,
  (newAge) => console.log('年龄变了', newAge)
)

// ④ immediate：立即执行一次（不等变化）
watch(keyword, (val) => fetchList(val), { immediate: true })

// ⑤ deep：深度监听对象内部变化
const user = reactive({ profile: { name: '' } })
watch(user, (val) => console.log('深层变化'), { deep: true })

// ⑥ once（Vue 3.4+）：只触发一次后自动停止
watch(keyword, (val) => console.log('首次变化'), { once: true })
</script>
选项作用注意
immediate组件挂载时立即跑一次回调适合"初始化就要做一次 + 变化也要做"
deep深入对象内部追踪嵌套变化监听 reactive 对象本身默认深层；监听 ref 装对象需要 deep
once只跑一次后自动停止（Vue 3.4+ 稳定）替代手动第一次后 stop
多源数组[a, b]，任一变化触发回调参数是新旧值数组

22.3 watch 的进阶选项与手动停止

watch 返回一个停止函数，需要"提前结束监听"时调用它：

const stop = watch(keyword, (val) => fetchList(val))

// 某个时机不再监听了
stop()    // 之后 keyword 再变也不会触发回调

// flush 选项：控制回调执行时机
watch(
  keyword,
  (val) => { console.log('DOM 更新后再看', document.querySelector('#result').textContent) },
  { flush: 'post' }   // 'pre'（默认）DOM 更新前；'post' 更新后；'sync' 同步
)

flush 三个值的区别：

flush回调执行时机用途
'pre'（默认）组件 DOM 更新之前大多数业务逻辑，赶在渲染前准备好新状态
'post'组件 DOM 更新之后需要读更新后的 DOM（如测滚动位置、调第三方组件）
'sync'每次变化同步立刻执行慎用：高频更新会拖慢性能
提醒组合式 API 里 watch 是在 setup 内声明即自动随组件卸载停止的，不需要像 Vue2 那样在 beforeDestroy 里手动解绑。只有你想"提前停"时才调返回的 stop()。

22.4 watchEffect：自动追踪依赖

watch 要你显式声明监听谁；watchEffect 自动收集回调里用到的响应式数据，谁变了就重跑回调：

<script setup>
import { ref, watchEffect } from 'vue'

const keyword = ref('')
const page = ref(1)

watchEffect(() => {
  // 回调里读到了 keyword 和 page → 自动依赖这两个
  fetchList({ keyword: keyword.value, page: page.value })
})
// 挂载时立即执行一次；之后 keyword / page 任一变化自动重跑
</script>

它还能通过 onCleanup 清理上一次的副作用——最典型的是请求竞态：

watchEffect(async (onCleanup) => {
  const controller = new AbortController()
  const res = await fetch(`/api/search?q=${keyword.value}`, {
    signal: controller.signal
  })
  // 下一次重跑前会执行这个清理：取消上一次未完成的请求
  onCleanup(() => controller.abort())
})

两个变体：

  • watchPostEffect：相当于 watchEffect + flush: 'post'；
  • watchSyncEffect：相当于 watchEffect + flush: 'sync'。

22.5 watch 与 watchEffect 怎么选

维度watchwatchEffect
依赖声明显式列出监听源回调内自动收集
拿到旧值能拿 newVal / oldVal拿不到旧值
默认执行时机惰性（变化才跑）；可 immediate挂载即立即跑一次
适合场景需要"旧值 vs 新值"判断、多源精确控制副作用与数据强绑定、不关心旧值
可读性一眼看出依赖谁要读回调才知道依赖谁

经验法则：要拿旧值、或想一眼看清"谁触发我"，用 watch；只是"数据变了就去做一件事"，用 watchEffect 更简洁。

22.6 常见坑

  • 坑 1监听 reactive 数组的 length 或整体替换不触发：监听 list.value.length 用 getter；整体替换 list.value = newList 才会触发（ref 装数组场景）。
  • 坑 2忘了 deep 导致对象深层变化不触发：ref 装对象时必须 { deep: true }；监听整个 reactive 对象默认就是深层。
  • 坑 3回调里改了正在被监听的变量：会造成循环触发。要么在回调里做幂等判断，要么用 computed 派生替代。
  • 坑 4watchEffect 里用了异步赋值导致依赖漏收：把依赖读取放在 await 之前；await 之后才读的数据不会被追踪。
  • 坑 5用 watch 代替 computed：派生值就该用 computed，watch 里改另一个 ref 是反模式（多一次渲染、多一层心智）。
  • 坑 6请求竞态：连续输入触发多次请求，旧响应可能后回来覆盖新结果。用 onCleanup + AbortController，或加请求序号。

✓ 本章小结

要点一句话
computed带缓存的派生值；{ get, set } 变可写，用于双向绑定派生状态
watch数据源 ref/getter/数组；选项 immediate / deep / once(3.4+) / flush
stop()返回的停止函数；组件卸载自动停，提前停才手动调
watchEffect自动收集回调内依赖；onCleanup 清理上次副作用（AbortController）
选型要旧值/显式依赖用 watch；纯副作用用 watchEffect
