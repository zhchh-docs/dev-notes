23.1 从 mixins 到组合式函数

Vue2 时代复用逻辑靠 mixins：把一组 data/methods 抽进一个对象，多个组件混入。它有三个致命问题：

痛点mixins 的表现组合式函数怎么解决
命名冲突两个 mixins 都有 count，互相覆盖，报错无声函数返回的对象自己命名：const { count: c1 } = useA()，冲突显式解决
来源不清模板里的 xxx 不知道来自哪个 mixin函数调用就在眼前：const mouse = useMouse()，出处一目了然
不能传参mixins 是静态合并，无法"按需求定制"函数可传参：useMouse({ touch: true })

组合式函数的本质：把"与组件相关的一小段逻辑"抽成普通 JS 函数，状态在函数内、闭包隔离，组件按需调用并命名返回值。

23.2 useXxx：命名约定与基本形态

约定俗成：以 use 开头、驼峰命名（useMouse、useDebounce、useRequest），放在 src/composables/ 目录。它接收参数、返回一个"状态 + 方法"的集合：

// composables/useMouse.js
import { ref, onMounted, onUnmounted } from 'vue'

export function useMouse() {
  const x = ref(0)
  const y = ref(0)

  function update(e) {
    x.value = e.pageX
    y.value = e.pageY
  }

  // 生命周期钩子在组合式函数内调用：随调用它的组件生效
  onMounted(() => window.addEventListener('mousemove', update))
  onUnmounted(() => window.removeEventListener('mousemove', update))

  // 返回响应式状态 + 方法；组件解构后自由命名
  return { x, y }
}
<script setup>
import { useMouse } from '@/composables/useMouse'

// 组件里：一行调用就拥有了鼠标坐标
const { x, y } = useMouse()
</script>

<template>
  <p>鼠标位置：{{ x }}, {{ y }}</p>
</template>

这个模式里，状态的归属非常清晰：x、y 是 useMouse 内部创建的 ref，组件只是引用它们。多个组件各自调用 useMouse() 会得到各自独立的状态——因为每次调用都是一次全新的函数执行，闭包独立。

23.3 接收响应式参数：props 怎么传

组合式函数经常要"跟着组件的某个 prop 走"。直接传 props.key 会丢响应性（读出来就是值），正确做法是传 ref 或 getter 函数：

// composables/useFetchUser.js
import { watch, ref, toValue } from 'vue'

// 接收一个 "ref 或 getter"，内部用 toValue 统一取值
export function useFetchUser(userId) {
  const user = ref(null)
  const loading = ref(false)

  async function fetch() {
    loading.value = true
    user.value = await fetch(`/api/users/${toValue(userId)}`).then(r => r.json())
    loading.value = false
  }

  // 无论 userId 是 ref、getter 还是普通值，watch 都能正确追踪
  watch(userId, fetch, { immediate: true })

  return { user, loading }
}
<script setup>
import { toRef } from 'vue'
import { useFetchUser } from '@/composables/useFetchUser'

const props = defineProps({ id: String })

// 方式一：toRef(props, 'id') 把 prop 转成 ref 传进去
const { user } = useFetchUser(toRef(props, 'id'))

// 方式二：传 getter 函数（推荐，最简单）
// const { user } = useFetchUser(() => props.id)
</script>

提醒别把 props.id 这个值直接传进去——它是 props 当前快照，之后 props 变了你的函数毫无感知。传 toRef(props,'id') 或 () => props.id，把"取值通道"交出去。

23.4 组合式函数里的生命周期

上面 useMouse 已经用了 onMounted / onUnmounted。规则很简单：只要组合式函数是在组件 setup 阶段被同步调用的，里面的生命周期钩子就自动绑定到那个组件。

// composables/useInterval.js
import { ref, onUnmounted } from 'vue'

export function useInterval(fn, interval = 1000) {
  const count = ref(0)
  const timer = setInterval(() => {
    count.value++
    fn()
  }, interval)

  // 组件卸载时自动清理定时器——调用方什么都不用管
  onUnmounted(() => clearInterval(timer))

  return { count }
}

这就是组合式函数最舒服的地方："申请了什么资源，就在函数里负责清理"，调用方只管用。生命周期钩子的完整映射与细节（onActivated/onErrorCaptured 等）见第 27 章。

注意一个前提：组合式函数必须在 setup 同步执行期间被调用。在 setTimeout、事件回调、await 之后才调 onMounted，Vue 会报警告——因为它不知道该绑到哪个组件上。

23.5 VueUse 生态与组织方式

写组合式函数是有门槛的通用能力，社区已经把最常用的几百个做好了——VueUse：

npm i @vueuse/core
<script setup>
import { useMouse, useDebounceFn, useStorage } from '@vueuse/core'

const { x, y } = useMouse()                    // 鼠标位置，开箱即用
const saveSearch = useDebounceFn((q) => fetchList(q), 300)  // 防抖
const token = useStorage('token', '')            // 同步 localStorage 的 ref
</script>
场景VueUse 提供替代了你手撸的什么
鼠标/键盘/设备useMouse / useMagicKeys / useDeviceMotion一堆 addEventListener + 清理
异步请求useFetch / useAsyncStateloading/error/数据三态管理
存储useStoragelocalStorage 序列化 + 响应式同步
防抖节流useDebounceFn / useThrottleFn手写 setTimeout 队列
元素尺寸/可见性useElementSize / useIntersectionObserverResizeObserver / IntersectionObserver 样板

项目里的组织建议：

  • 通用业务逻辑（与后端接口绑定的除外）抽进 src/composables/；
  • 每个文件一个导出函数，文件名即函数名；
  • 跨业务复用率低的逻辑，先留在组件里，第二次复用时再抽——别为了抽而抽。

23.6 常见坑

  • 坑 1在组合式函数里直接改 props：props 只读，要改就 emit 事件或传回调。
  • 坑 2把 props 的值（不是 ref）传进函数：之后 props 变了函数无感知。用 toRef(props,'x') 或 getter。
  • 坑 3在 await 之后调生命周期钩子：报错 "onMounted is called when there is no active component instance"。组合式函数必须在 setup 同步段调用。
  • 坑 4组合式函数返回的对象忘记展开/解构：const mouse = useMouse() 后模板写 {{ x }}——没解构，x 不存在。要 const { x, y } = useMouse()。
  • 坑 5把单例状态放进组合式函数模块顶层：const global = ref(0) 写在函数外面会被所有实例共享。状态要写在函数内部。
  • 坑 6过度抽象：只在一个地方用、却抽成 useXxx，反而多一层跳转。第二次复用时再抽。

✎ 本章习题

A 基础实现 useMouse()：返回 { x, y } 两个 ref，组件挂载时监听 mousemove，卸载时移除；在两个不同组件里分别调用，验证状态互不干扰。
B 进阶写 useFetch(url)：接收一个 getter（() => \`/api/users/${id}\`），内部返回 { data, loading, error }，id 变化时自动重新请求（用 watch + immediate）；要求组件卸载时取消未完成请求（AbortController）。
C 挑战用 VueUse 的 useStorage + useDebounceFn 实现"搜索框：输入 300ms 后自动把关键词存到 localStorage，下次打开页面自动回填"。要求：① 不自己写防抖和 localStorage 逻辑；② 说明每一步对应 VueUse 的哪个函数；③ 自己手写一版等价实现，对比代码行数。
