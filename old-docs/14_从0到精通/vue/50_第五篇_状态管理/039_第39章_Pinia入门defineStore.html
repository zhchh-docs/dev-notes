39.1 安装与接入

npm install pinia
// main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const app = createApp(App)
app.use(createPinia())     // 把 pinia 实例装到应用上
app.mount('#app')

就这么简单。createPinia() 返回一个插件实例，app.use 之后，所有组件里都能通过 useXxxStore() 拿到 store。

39.2 defineStore 选项式写法

defineStore 接受两个参数：store 的唯一 id + 选项对象（state / getters / actions）。

// stores/counter.js
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  // state：必须是函数（返回初始对象），类似组件 data
  state: () => ({
    count: 0,
    history: []
  }),

  // getters：类似 computed，基于 state 派生
  getters: {
    double: (state) => state.count * 2,
    // 访问其他 getter 用 this
    doublePlusOne() {
      return this.double + 1
    }
  },

  // actions：类似 methods，可以同步也可以异步
  actions: {
    increment() {
      this.count++
      this.history.push('+1')
    },
    incrementBy(n) {
      this.count += n
    },
    async fetchAndSet(id) {
      const res = await fetch(`/api/item/${id}`)
      this.count = await res.json()
    }
  }
})

三个概念

概念对应组件里的说明
statedata()响应式状态，必须是函数返回初始对象
getterscomputed基于 state 派生，有缓存
actionsmethods改 state 的方法，可同步可异步

Pinia 没有 Vuex 的 mutations——改 state 的唯一入口就是 actions（但你也可以直接改 state，Pinia 不强制）。

39.3 在组件中使用：storeToRefs

<script setup>
import { useCounterStore } from '@/stores/counter'
import { storeToRefs } from 'pinia'

const counter = useCounterStore()

// ❌ 直接解构：丢失响应式
// const { count, double } = counter

// ✅ 用 storeToRefs：保持响应式
const { count, double } = storeToRefs(counter)

// ✅ action 可以直接解构（函数本身不丢响应式）
const { increment } = counter
</script>

<template>
  <p>count = {{ count }}</p>
  <p>double = {{ double }}</p>
  <button @click="increment">+1</button>
  <button @click="counter.incrementBy(5)">+5</button>
</template>

为什么不能直接解构

Pinia 的 store 是一个 reactive 对象，但它的 state 字段是通过 getters 暴露的（不是普通属性）。你直接解构 const { count } = store，拿到的是当时那个值（一个普通 number），不是响应式引用——之后 store.count 变了，你的 count 不会变。

storeToRefs 做的事情就是：把 state 和 getters 字段包装成 ref，这样解构出来的还是响应式。

写法响应式说明
store.count是完整保留
const { count } = store否解构出普通值
const { count } = storeToRefs(store)是保持 ref 响应式
const { increment } = store—action 是函数，直接解构 OK
提醒记住这条规则：state 和 getters 用 storeToRefs 解构；actions 直接解构。这是 Pinia 最容易踩的坑。

39.4 setup store 写法（预告）

除了选项式，defineStore 还支持"组合式"写法：

export const useCounterStore = defineStore('counter', () => {
  const count = ref(0)
  const history = ref([])

  const double = computed(() => count.value * 2)

  function increment() {
    count.value++
    history.value.push('+1')
  }

  return { count, history, double, increment }
})

这种写法和 <script setup> 的思路完全一致：ref 是 state、computed 是 getters、function 是 actions。第 42 章会专门讲什么时候用它。

39.5 Pinia vs Vuex

Vuex 是上一代官方状态管理库（Vue 2 时代）。如果你接手老项目，对比一下：

维度Vuex 3/4Pinia 2+
mutations必须：改 state 只能走 mutation没有：直接改或走 actions
模块化需要 modules 嵌套每个 store 天然独立，无嵌套
TypeScript需要额外类型声明原生 TS 推导，自动推断
devtools支持支持（Vue DevTools 内置）
组合式 API支持但别扭一等公民（setup store）
体积~ 15KB~ 10KB
SSR支持支持

迁移建议：新项目一律用 Pinia。老 Vuex 项目不要一次性重写，按模块逐步迁移（Pinia 支持和 Vuex 共存）。

39.6 本章常见坑

  • 坑 1直接解构 store 的 state：丢失响应式。用 storeToRefs。
  • 坑 2state 写成对象而不是函数：state: { count: 0 }——这样所有 store 实例共享同一份对象（SSR 串用户）。必须 state: () => ({ count: 0 })。
  • 坑 3在组件外调用 useXxxStore()：必须在 pinia 装好之后调用（app.use(pinia) 之后），否则报错。
  • 坑 4不同 store 用同一个 id：defineStore 第一个参数 id 必须全局唯一，否则后注册的覆盖前一个。
  • 坑 5把 store 存到 reactive() 里：store 本身已经是 reactive 的，再包一层会出问题。
