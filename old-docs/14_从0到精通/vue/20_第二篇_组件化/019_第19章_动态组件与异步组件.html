19.1 component :is：运行时切换组件

前面写组件都是"模板里写死哪个就是哪个"。但 UI 里大量场景是同一个位置、按状态渲染不同组件：Tabs 标签页、后台管理的左侧菜单切换、向导步骤。<component :is="..."> 就是 Vue 提供的"占位符插槽"。

<!-- Tabs 容器：同一个位置，按 activeTab 渲染不同组件 -->
<template>
  <div class="tabs">
    <button
      v-for="tab in tabs"
      :key="tab.key"
      :class="{ active: activeTab === tab.key }"
      @click="activeTab = tab.key"
    >{{ tab.label }}</button>
  </div>

  <!-- 动态组件：is 指向谁，就渲染谁 -->
  <component :is="currentComponent" />
</template>

<script setup>
import { ref, computed } from 'vue'
import UserList from './UserList.vue'
import RoleList from './RoleList.vue'
import DeptTree from './DeptTree.vue'

const tabs = [
  { key: 'user', label: '用户', comp: UserList },
  { key: 'role', label: '角色', comp: RoleList },
  { key: 'dept', label: '部门', comp: DeptTree }
]
const activeTab = ref('user')
const currentComponent = computed(() =>
  tabs.find(t => t.key === activeTab.value).comp
)
</script>

is 的值可以是三种东西：

is 的值写法说明
组件对象（推荐）:is="MyComp"直接传 import 进来的组件，类型安全、可 tree-shaking
注册名（字符串）:is="'MyComp'"对应局部/全局注册的名字；TS 无推导
原生 HTML 标签:is="'button'"渲染原生元素，常用于包裹层抽象

动态组件的本质：模板里的一个占位符，具体渲染什么由 JS 状态决定。它把"视图结构"和"视图选择"解耦了。

19.2 切换即销毁：状态丢失从哪来

把上面的 Tab 用一下你会立刻踩到坑：在"用户"页翻了第 3 页、填了半行筛选条件，切到"角色"再切回来——页码和筛选条件全没了。

原因看这张图：

图 19-1 动态组件在无缓存时的销毁与重建（示意）

这正是第 16 章生命周期的用武之地：组件切走时 onBeforeUnmount / onUnmounted 会执行，组件内部的 ref 状态、未保存的表单、已发出去但未响应的请求，都随实例一起被回收。

工程上这是特性不是 bug：卸载即清理，无需手动解绑事件、取消定时器。但你要记住这个行为，否则"切个 Tab 数据就没了"会变成反复出现的线上 bug。

19.3 与 v-if / v-show 的取舍

同一个"按条件渲染组件"的需求，有三种写法。它们的差异不在视觉，而在实例生命周期：

写法切换时做了什么状态是否保留适用场景
<component :is>销毁旧实例、挂载新实例不保留分支 ≥3 个、组件各不相同
v-if / v-else销毁/创建整个分支不保留分支少且固定（2 个）
v-show只切 CSS display保留两个组件频繁互切、都要保状态
:is + <keep-alive>切走时把实例缓存进内存保留Tab 多、切换频繁（后台系统）
提醒三个及以上分支时，别写 v-if / v-else-if / v-else-if ...——那会变成噩梦般的层级嵌套。分支数 ≥3 就上动态组件，分支数 =2 且要保状态就用 v-show。

19.4 keep-alive：把实例缓存起来

给动态组件包一层 <keep-alive>，切走的实例不再被销毁，而是挂在内存里休眠；切回来时原地唤醒，状态原样恢复。

<script setup>
import { ref } from 'vue'
import UserList from './UserList.vue'
import RoleList from './RoleList.vue'

const activeTab = ref('user')
</script>

<template>
  <!-- 缓存所有动态切换的组件实例 -->
  <keep-alive>
    <component :is="activeTab === 'user' ? UserList : RoleList" />
  </keep-alive>
</template>
<!-- 更常见的精确控制：只缓存 UserList，RoleList 不缓存 -->
<!-- include/exclude 匹配组件的 name（defineOptions 里定义） -->
<keep-alive include="UserList" :max="5">
  <component :is="currentComponent" />
</keep-alive>
选项作用注意
include只缓存 name 命中的组件（字符串/正则/数组）配合 defineOptions({ name: 'X' })
excludename 命中的不缓存优先级低于 include
max最多缓存多少个实例（LRU 淘汰）后台系统建议设上限，防止内存膨胀

被缓存的组件多了两个生命周期钩子：onActivated（唤醒时）与 onDeactivated（休眠时）——第 27 章会给出完整的组合式写法。注意它们只在 keep-alive 包裹下触发，首次挂载仍然走 onMounted。

本章只讲 keep-alive 的用法。它内部如何维护 LRU 缓存、include 的匹配算法、与异步组件的配合，放到第 64 章深挖。

19.5 defineAsyncComponent：按需加载

动态组件的另一个痛点是：一进页面就把 Tabs 里三个组件全打包、全下载。RoleList 里可能有个超大的图表组件，用户根本不点。defineAsyncComponent 把组件变成"用到时才发请求加载"。

<script setup>
import { defineAsyncComponent } from 'vue'

// 箭头函数返回 Promise：打包时会单独拆成一个 chunk
// 只有组件被首次渲染时才会去下载这个 chunk
const UserList = defineAsyncComponent(() => import('./UserList.vue'))
const RoleList = defineAsyncComponent(() => import('./RoleList.vue'))
</script>

<template>
  <!-- 用法与普通组件完全一样 -->
  <component :is="activeTab === 'user' ? UserList : RoleList" />
</template>

异步组件不只是"懒加载"，它还能控制加载中、失败、超时三种异常路径。完整选项：

<script setup>
import { defineAsyncComponent } from 'vue'
import LoadingSpinner from './LoadingSpinner.vue'
import LoadError from './LoadError.vue'

const RoleList = defineAsyncComponent({
  // 必填：加载器，返回 Promise（Vite 的动态 import）
  loader: () => import('./RoleList.vue'),

  // 加载中显示的占位组件；delay 避免快速加载时闪屏
  loadingComponent: LoadingSpinner,
  delay: 200,

  // 失败显示的组件；onError 提供重试机会
  errorComponent: LoadError,
  timeout: 10000,   // 10 秒没加载出来算失败

  // 发生错误时的回调：retry() 重试，fail() 放弃
  onError(error, retry, fail, attempts) {
    if (attempts <= 3) retry()
    else fail(error)
  }
})
</script>
选项作用典型值
loader返回 Promise 的加载函数（动态 import）() => import('./X.vue')
loadingComponent加载中的占位 UI骨架屏 / Spinner
delay延迟多少 ms 才显示 loading，避免闪屏200
errorComponent加载失败的错误 UI带"重试"按钮的组件
timeout超时即判失败（ms）10000
onError失败回调，可 retry() 重试最多重试 3 次

工程上：路由级页面全部异步化（Vue Router 原生支持），首屏不展开的 Tabs/弹窗/重图表组件也用异步组件——这是 Vite 项目最立竿见影的分包手段。

19.6 与 Suspense 的关系（预告）

异步组件解决了"组件代码按需加载"，但还有一个更细的问题：组件内部 setup 里就要发请求拿数据，加载期间整棵子树显示什么？

Vue 提供了内置的 <Suspense> 组件（实验性特性）：它会等异步组件加载完毕、async setup() 完成后，再一起渲染；期间渲染 #fallback 插槽。它和 defineAsyncComponent 经常配合使用。

<!-- 概念示例：具体语法在第 63 章精讲 -->
<Suspense>
  <template #default>
    <UserProfile />   <!-- async setup 会先请求用户数据 -->
  </template>
  <template #fallback>
    <LoadingSpinner />
  </template>
</Suspense>
本章只建立概念：defineAsyncComponent 管"组件代码加载"，Suspense 管"组件内部异步依赖的等待 UI"。完整 API、与 SSR 的配合、边界行为见第 63 章。

19.7 常见坑

  • 坑 1切 Tab 后状态丢失却不知道为什么：默认动态组件不缓存。要么包 <keep-alive>，要么把状态提升到父级（第 24 章 provide / 第五篇 Pinia）。
  • 坑 2v-if / v-else 写四五个分支：分支数 ≥3 就改用 :is + 组件映射表。
  • 坑 3keep-alive include 匹配不上：<script setup> 里组件名要通过 defineOptions({ name: 'X' }) 显式声明，include 按这个 name 匹配，不匹配文件名。
  • 坑 4把 import() 写成静态 import：只有 () => import('./X.vue') 这种动态形式才会被 Vite/Rollup 拆包；写成 import X from './X.vue' 就回退成同步加载。
  • 坑 5loading 组件一闪而过：网络快时 loading 只显示几十毫秒就消失，视觉上像闪烁。设置 delay: 200，加载超过 200ms 才显示 loading。
  • 坑 6异步组件没有超时与错误兜底：弱网环境下用户永远看到一个转圈。timeout + errorComponent + retry 是标准三件套。
  • 坑 7以为 keep-alive 缓存的是数据：缓存的是组件实例（含其 setup 里的 ref 状态）。如果状态在外部 store，那本来就不会丢，和 keep-alive 无关。

✓ 本章小结

要点一句话
:is 动态组件模板占位符，运行时按状态渲染不同组件；is 可传组件对象/注册名/HTML 标签
切换即销毁无缓存时切走 = onUnmounted，内部状态随之回收
选型≥3 分支用 :is；2 个分支要保状态用 v-show；Tab 多且频繁切用 :is + keep-alive
keep-alive休眠实例而非销毁；include/exclude 按组件 name；max 防内存膨胀
defineAsyncComponent动态 import 拆包；配套 loadingComponent / errorComponent / delay / timeout / retry
Suspense管组件内部异步依赖的等待 UI，第 63 章精讲

✎ 本章习题

A 基础用 <component :is> 实现一个三标签 Tabs（"列表 / 卡片 / 设置"三个简单组件），点击按钮切换。验证：不包 keep-alive 时，在"列表"组件里放一个 ref(0) 计数器，点几次后切到别的 Tab 再切回来，计数是否归零？
B 进阶给上面的 Tabs 包上 <keep-alive>，并用 defineOptions 给组件命名；再用 include 只缓存其中一个 Tab，验证：被缓存的 Tab 切回来计数保留，未被缓存的 Tab 计数仍归零。
C 挑战把"设置"组件用 defineAsyncComponent 包装，配置 loadingComponent、errorComponent、timeout: 3000 与 onError 最多重试 2 次。用 Chrome DevTools 的 Network 节流到 "Fast 3G"，观察：① loading 是否在 delay 后才出现；② 弱网下超时后是否出现错误组件并可重试。
