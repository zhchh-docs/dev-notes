11.1 声明 props 的三种方式

① 数组形式（最简，不校验）

<script setup>
const props = defineProps(['title', 'count'])
</script>

② 对象形式（推荐，可校验）

<script setup>
const props = defineProps({
  title: { type: String, required: true },
  count: { type: Number, default: 0 },
  list: { type: Array, default: () => [] },   // 注意：对象/数组用工厂函数
  status: {
    type: String,
    default: 'pending',
    validator: (v) => ['pending', 'done', 'failed'].includes(v)
  }
})
</script>

③ TypeScript 泛型（类型即文档）

<script setup lang="ts">
interface User { id: number; name: string; avatar?: string }

// 方式 A：运行时类型推导（Vue 3.3+ 支持复杂类型）
const props = defineProps<{
  user: User
  size?: 'small' | 'large'
  disabled?: boolean
}>()

// 方式 B：带默认值（withDefaults）
const props = withDefaults(defineProps<{
  user: User
  size?: 'small' | 'large'
  count?: number
}>(), {
  size: 'small',
  count: 0
})
</script>
方式优点适用
数组最快原型、内部小组件
对象运行时校验 + 默认值JS 项目主力写法
TS 泛型编译期类型 + IDE 提示TS 项目首选
注意：defineProps 是编译宏，不需要 import；只能在 <script setup> 顶层调用；它的返回值要赋给变量（模板里也能直接用 props 名）。

11.2 校验：type / required / default / validator

<script setup>
const props = defineProps({
  // 基础类型
  name: String,
  age: Number,
  active: Boolean,
  tags: Array,
  meta: Object,
  onChange: Function,

  // 多类型
  id: [String, Number],

  // 必填
  title: { type: String, required: true },

  // 默认值（基础类型直接给）
  size: { type: Number, default: 24 },

  // 默认值（对象/数组必须用工厂函数返回新对象）
  options: { type: Array, default: () => [] },
  config: { type: Object, default: () => ({ theme: 'light' }) },

  // 自定义校验：返回 false 会在控制台告警
  status: {
    type: String,
    default: 'pending',
    validator(value) {
      return ['pending', 'running', 'done', 'failed'].includes(value)
    }
  },

  // 构造函数作为类型（自定义类）
  author: { type: Person }   // Person 是一个 class
})
</script>
对象/数组默认值必须写成工厂函数：default: () => []。若写成 default: []，所有组件实例会共享同一个数组（引用复用），一个实例改了它，别的实例跟着变——这是极其隐蔽的 bug。
校验时机props 校验只在开发模式下进行（生产构建会被剥离以减小体积），且只告警不阻断：校验失败不会阻止渲染，只在控制台输出警告。

11.3 单向数据流：为什么不能改 props

Vue 的 props 是单向的：父组件的数据向下流向子组件，子组件不应反向修改它。

图 11-1 单向数据流：向下传 props，向上发事件

为什么必须单向：

  1. 可追踪：数据只有一个"所有者"，改动的来源永远只有一个地方；
  2. 可预测：子组件是"纯展示"的，同样的 props 一定渲染同样的结果；
  3. 避免循环：双向随意改会让父子互相触发更新，最终演变成"谁改的？"的调试噩梦。
<script setup>
const props = defineProps({ count: Number })

// ❌ 反例：直接改 props
props.count++        // 控制台告警：Set operation on key "count" failed: target is readonly

// ❌ 反例：对象类型的属性也不能"改内部"（若父传的是响应式对象，会影响父状态）
props.user.name = 'x'  // 不告警但违反约定，父组件状态被偷偷改了
</script>

11.4 想改 props 时的三种正确做法

做法一：作为本地初始值的副本（最常用）

<script setup>
const props = defineProps({ initialName: String })
// props 只作为初值，之后改本地副本
const name = ref(props.initialName)
</script>

做法二：可写计算属性（与父状态保持同步）

<script setup>
const props = defineProps({ modelValue: String })
const emit = defineEmits(['update:modelValue'])

// 读走 props，写走 emit —— 这就是 v-model 的本质（第 13 章）
const value = computed({
  get: () => props.modelValue,
  set: v => emit('update:modelValue', v)
})
</script>

<template>
  <input v-model="value">
</template>

做法三：发事件让父组件改（最规范）

<!-- 子组件 -->
<script setup>
const props = defineProps({ user: Object })
const emit = defineEmits(['update-name'])
</script>
<template>
  <input :value="user.name" @input="emit('update-name', $event.target.value)">
</template>

<!-- 父组件 -->
<UserCard :user="user" @update-name="user.name = $event" />
做法父子是否同步适用
本地副本❌ 之后不同步表单初始值、配置快照
可写计算属性✅ 完全同步受控组件、v-model 实现
emit 通知父改✅ 完全同步通用首选

11.5 传参细节与 $attrs

命名转换

<!-- 定义用 camelCase，模板里推荐 kebab-case -->
<script setup>
defineProps({ userId: Number, userName: String })
</script>

<!-- 父组件两种写法都行，推荐后者（与 HTML 属性风格一致） -->
<UserCard :user-id="1" :user-name="'小明'" />

静态 vs 动态

<!-- 静态：传字符串 -->
<UserCard title="标题" />

<!-- 动态：传表达式（数字、布尔、变量、对象） -->
<UserCard :count="42" :disabled="true" :user="currentUser" />

<!-- 布尔简写：写属性名即 true -->
<UserCard disabled />      <!-- 等价 :disabled="true" -->

<!-- 整体传入一个对象：用 v-bind 展开 -->
<UserCard v-bind="userProps" />
<!-- 等价：<UserCard :id="userProps.id" :name="userProps.name" /> -->

$attrs：未被 props 声明的属性

<!-- 父组件 -->
<MyInput class="w-full" placeholder="请输入" data-test="input" />

<!-- MyInput.vue -->
<script setup>
defineProps({ modelValue: String })   // 只声明了 modelValue
// 其余 class / placeholder / data-test 都会进 $attrs
</script>
<template>
  <!-- 默认会自动透传到根元素；想指定位置就显式绑定 -->
  <div class="wrap">
    <input v-bind="$attrs" :value="modelValue">
  </div>
</template>
<script setup>
defineOptions({ inheritAttrs: false })   // 关掉默认透传，避免挂到 .wrap 上
</script>

$attrs 是"属性分发的下水道"：封装第三方组件时，把没声明的属性全部透传进去，使用者就能像用原生组件一样传任意属性（第 61 章二次封装会大量使用）。

11.6 只读与响应式：别解构 props

<script setup>
import { toRefs, toRef, computed } from 'vue'
const props = defineProps({ count: Number, user: Object })

// ❌ 解构会丢失响应性：count 只是一个数字快照
const { count } = props

// ✅ 方式一：用 toRefs 保持响应
const { count: countRef } = toRefs(props)
console.log(countRef.value)

// ✅ 方式二：用 toRef 取单个字段
const count2 = toRef(props, 'count')

// ✅ 方式三：在计算属性/模板里直接读 props.xxx（最省事）
const double = computed(() => props.count * 2)
</script>
Vue 3.5+ 引入响应式 props 解构：const { count = 0 } = defineProps(...) 在开启相应编译选项后可保持响应性。未确认项目是否启用时，仍用 toRefs 更稳妥。

另外，props 对象本身是浅层只读的：改 props.count 会告警；但 props.user.name = 'x'（改对象内部）不会告警——因为它修改的是父组件创建的那个对象。不告警 ≠ 正确，这依然违反单向数据流。

11.7 本章常见坑

  • 坑 1对象默认值写成字面量：default: [] → 所有实例共享同一数组。必须 default: () => []。
  • 坑 2直接改 props：告警且违反单向流。用 emit 或可写计算属性。
  • 坑 3解构 props 丢响应：用 toRefs / toRef 或直接读 props.x。
  • 坑 4传参漏冒号：count="42" 传的是字符串 "42"，:count="42" 才是数字。
  • 坑 5Boolean 类型的坑：布尔 prop 的 default 若为 false 可以省略；但注意空字符串也是 false 之外的真值判断——写了 disabled="" 表示 true。
  • 坑 6validator 里写异步：校验函数必须同步返回布尔值，异步校验无意义（且不会被 await）。
