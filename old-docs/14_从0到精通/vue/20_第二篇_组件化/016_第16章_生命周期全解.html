<script setup>
import {
  onBeforeMount, onMounted,
  onBeforeUpdate, onUpdated,
  onBeforeUnmount, onUnmounted
} from 'vue'

onBeforeMount(() => console.log('① DOM 还没创建'))
onMounted(() => console.log('② DOM 已插入页面'))
onBeforeUpdate(() => console.log('③ 数据变了，DOM 还没更新'))
onUpdated(() => console.log('④ DOM 已更新'))
onBeforeUnmount(() => console.log('⑤ 组件即将卸载，实例仍可用'))
onUnmounted(() => console.log('⑥ 已卸载，清理在这里做'))
</script>
为什么没有 onCreated：组合式 API 中，setup 顶层代码的执行时机就在 beforeCreate 与 created 之间，所以"需要 created 做的事"直接写在顶层即可。这也是 <script setup> 里代码看起来"没有生命周期"的原因。

16.3 创建阶段：setup

setup（或 <script setup>）是组件逻辑的入口，此时组件实例刚创建、DOM 还不存在。

<script setup>
import { ref } from 'vue'

const list = ref([])
const loading = ref(false)

// ✅ 可以：定义状态、计算属性、侦听器、发请求（不需要 DOM）
async function load() {
  loading.value = true
  list.value = await fetch('/api/list').then(r => r.json())
  loading.value = false
}
load()   // 直接在 setup 里调用，等价于 created 时发请求

// ❌ 不可以：此时 DOM 不存在
// document.querySelector('.box').style.color = 'red'
</script>

"发请求放 setup 还是 onMounted？"——都可以，语义有别：setup 里发=组件创建即发（不等 DOM）；onMounted 里发=等首屏渲染完再发（适合请求结果依赖 DOM 尺寸，或想让首屏更快出现）。实践中常放 setup（更快）。

16.4 挂载阶段：onMounted

此时组件的 DOM已插入文档，可以安全地：

  • 操作 DOM / 获取元素尺寸（offsetHeight、getBoundingClientRect）；
  • 初始化需要 DOM 的第三方库（ECharts、地图、富文本编辑器）；
  • 注册全局事件监听（window / document）；
  • 发起依赖 DOM 的请求。
<template>
  <div ref="chartEl" style="height: 300px"></div>
</template>

<script setup>
import { ref, onMounted, onUnmounted } from 'vue'
import * as echarts from 'echarts'

const chartEl = ref(null)
let chart = null
let timer = null

onMounted(() => {
  // 初始化图表（必须有真实 DOM）
  chart = echarts.init(chartEl.value)
  chart.setOption({ /* ... */ })

  // 注册全局监听
  window.addEventListener('resize', onResize)
  timer = setInterval(tick, 1000)
})

function onResize() { chart && chart.resize() }
function tick() { /* 轮询 */ }

onUnmounted(() => {
  // 一一对应地清理！
  window.removeEventListener('resize', onResize)
  clearInterval(timer)
  chart && chart.dispose()
})
</script>
坑onMounted 里拿到的 DOM 尺寸，可能还不是最终布局（图片未加载完、字体未就绪、CSS 动画中）。需要精确尺寸时用 nextTick 或监听 load 事件。

16.5 更新阶段：onUpdated

响应式数据变化 → 重新渲染 → DOM 更新完成后触发。

<script setup>
import { ref, onUpdated, onBeforeUpdate } from 'vue'
const count = ref(0)

onBeforeUpdate(() => {
  // DOM 还是旧的，可以记录更新前的状态（如滚动位置）
  console.log('更新前 DOM 内容：', el.textContent)
})

onUpdated(() => {
  // DOM 已是新的；适合做依赖 DOM 的后续处理
  console.log('更新后')
})
</script>
不要在 onUpdated 里修改响应式状态：改了又会触发更新 → 再次调用 onUpdated → 无限循环。确实需要时加终止条件或用 watch 精确监听。

更常用的替代方案是 nextTick（在一次更新后立即执行）：

import { nextTick } from 'vue'

async function addItem() {
  list.value.push(newItem)
  await nextTick()             // 等 DOM 更新完成
  container.value.scrollTop = container.value.scrollHeight  // 滚到底部
}

16.6 卸载阶段：onUnmounted

这是内存泄漏的头号防线：组件销毁时，所有"组件之外"的东西都要在这里收回。

需要清理的东西清理方式
setTimeout / setIntervalclearTimeout / clearInterval
window / document 事件监听removeEventListener（必须传同一个函数引用）
第三方库实例（图表、编辑器、地图）调用其 destroy() / dispose()
未完成的请求AbortController.abort() 或标记 cancelled
WebSocket / EventSourceclose()
手动创建的侦听器（异步创建的 watch）调用 stop()
 
<script setup>
import { onUnmounted, onMounted } from 'vue'

const controller = new AbortController()

async function load() {
  const res = await fetch('/api/data', { signal: controller.signal })
  // ...
}

onUnmounted(() => {
  controller.abort()   // 组件销毁时取消未完成的请求
})
</script>
Vue 自动清理的部分：模板里的事件监听、在 setup 中同步创建的 watch / watchEffect、组件自身的响应式副作用——这些都会随组件卸载自动停止，无需手动处理。

16.7 特殊钩子：KeepAlive 与错误捕获

<script setup>
import { onActivated, onDeactivated, onErrorCaptured } from 'vue'

// 被 <KeepAlive> 缓存的组件：显示/隐藏时触发
onActivated(() => {
  // 重新显示：适合恢复轮询、刷新数据
  startPolling()
})
onDeactivated(() => {
  // 被隐藏（但没销毁）：暂停轮询、保存滚动位置
  stopPolling()
})

// 错误边界：捕获子孙组件抛出的错误
onErrorCaptured((err, instance, info) => {
  console.error('捕获到子组件错误：', err, info)
  reportToSentry(err)
  return false   // 返回 false 阻止错误继续向上传播
})
</script>

调试专用钩子（仅开发模式有意义）：

import { onRenderTracked, onRenderTriggered } from 'vue'

onRenderTracked((e) => console.log('依赖被追踪：', e))
onRenderTriggered((e) => console.log('哪个依赖触发了更新：', e))

排查"为什么这个组件反复重渲染"时，onRenderTriggered 是最直接的工具——它会告诉你是哪个响应式字段引起的（第 71 章性能排查会用到）。

16.9 本章常见坑

  • 坑 1在 setup 里操作 DOM：此时 DOM 还没创建，拿到 null。用 onMounted 或 nextTick。
  • 坑 2在 onUpdated 里改状态：造成无限更新循环。
  • 坑 3忘记清理定时器/监听：组件销毁后回调仍在执行，访问已销毁的状态 → 报错或内存泄漏。
  • 坑 4onMounted 里以为子组件一定渲染完：若子组件是异步组件或 v-if 为假，它此时并不存在（第 19、63 章）。
  • 坑 5用 setTimeout(…, 0) 代替 nextTick：不保证顺序正确。请用 await nextTick()。
  • 坑 6KeepAlive 组件里用 onMounted 刷新数据：缓存后只有第一次触发。应改用 onActivated。
  • 坑 7在 onUnmounted 里访问已被销毁的 ref：el.value 可能已是 null，做空值判断。

✓ 本章小结

要点一句话
四阶段创建（setup）→ 挂载（onMounted）→ 更新（onUpdated）→ 卸载（onUnmounted）
组合式对照无 onCreated（写在 setup 顶层）；destroy 改叫 unmount
setup定义状态、发请求；不能碰 DOM
onMountedDOM 就绪：操作 DOM、初始化库、注册全局监听
onUpdatedDOM 已更新；禁止在其中改状态
onUnmounted清理定时器、监听、请求、第三方实例
顺序子 mounted 先于父 mounted
特殊KeepAlive 用 onActivated；错误边界用 onErrorCaptured
