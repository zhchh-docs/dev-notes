10.1 为什么需要单文件组件

组件本质是"可复用的界面单元"。不用 SFC 也能写，但体验差别很大：

写法形式问题
字符串模板template: '<div>...</div>'没有语法高亮、没有补全、换行要拼字符串
JSX / render 函数return h('div', ...)灵活但模板可读性差，样式仍需单独文件
SFC（推荐）.vue 文件三段式需要编译（Vite 已处理）

SFC 把结构（template）、逻辑（script）、样式（style）放进同一个文件，同时保留各自的语法高亮——这是 Vue 在工程体验上的核心优势。

一个重要认知：SFC 不是浏览器原生支持的，它由 @vitejs/plugin-vue 在构建时编译成 JS 渲染函数。所以".vue 文件"只存在于源码阶段。

10.2 三个区块的职责

<template>
  <!-- 结构：必须有（也可以只有一个根节点，Vue3 支持多根） -->
  <div class="user-card">
    <img :src="user.avatar" :alt="user.name">
    <h3>{{ user.name }}</h3>
    <slot name="extra" />
  </div>
</template>

<script setup>
// 逻辑：组合式 API，顶层变量自动暴露给模板
import { ref, computed } from 'vue'
import UserBadge from './UserBadge.vue'   // import 后模板可直接用

const props = defineProps({ user: { type: Object, required: true } })
const emit = defineEmits(['follow'])

const following = ref(false)
const label = computed(() => following.value ? '已关注' : '关注')

function toggle() {
  following.value = !following.value
  emit('follow', props.user.id, following.value)
}
</script>

<style scoped>
/* 样式：scoped 表示只作用于本组件 */
.user-card { display: flex; gap: 12px; padding: 12px; }
.user-card h3 { margin: 0; font-size: 16px; }
</style>
区块必填要点
<template>是（也可用 render 函数替代）Vue3 支持多根节点；不能有 v-if 之外的顶层逻辑
<script setup>否（纯展示组件可省）顶层绑定自动暴露；每组件实例独立执行
<style>否可写多个 style 块；scoped / module / 预处理器
多根组件（Fragment）：Vue3 允许 <template> 下有多个根元素。代价是属性透传失效（class/style 不知道挂到哪），需要显式 v-bind="$attrs"（第 7 章已提）。

10.3 script setup：编译器的魔法

<script setup> 不是新语法，而是编译期语法糖：编译器把你在顶层写的代码"搬进" setup() 函数，并把变量自动 return 给模板。

<!-- 你写的 -->
<script setup>
import { ref } from 'vue'
import MyComp from './MyComp.vue'
const count = ref(0)
function inc() { count.value++ }
</script>

<template>
  <MyComp :n="count" @click="inc" />
</template>

<!-- 编译器大致生成（简化示意） -->
<script>
import { ref } from 'vue'
import MyComp from './MyComp.vue'
export default {
  components: { MyComp },          // 自动注册
  setup() {
    const count = ref(0)
    function inc() { count.value++ }
    return { count, inc }           // 自动暴露给模板
  }
}
</script>

由此得到的四条规则：

  1. 顶层变量自动可用：import 的组件、函数、常量、ref 都能直接在模板里用，不用注册也不用 return；
  2. 组件名自动推导：MyComp.vue 直接以 <MyComp> 使用（推荐 PascalCase）；
  3. 只在 setup 阶段执行：不要在里面写"只在挂载后才该跑"的代码，那是 onMounted 的事；
  4. 不能写 export default：需要额外选项时用 defineOptions（如 defineOptions({ name: 'UserCard' })）。
<script setup>
// 定义组件名（用于 devtools、递归组件、keep-alive include）
defineOptions({ name: 'UserCard', inheritAttrs: false })

// 定义 props / emits / 暴露给父组件的接口
const props = defineProps({ title: String })
const emit = defineEmits(['close'])
defineExpose({ reset })      // 父组件通过 ref 能调用的方法

function reset() { /* ... */ }
</script>

10.4 样式区块：scoped、module 与 :deep

scoped 的原理

<template>
  <div class="card"><p>文字</p></div>
</template>

<style scoped>
.card { padding: 12px; }
</style>
<!-- 编译后：元素被加上 data-v-xxx 属性，选择器也带上属性限定 -->
<div class="card" data-v-7ba5bd90><p data-v-7ba5bd90>文字</p></div>

<style>
.card[data-v-7ba5bd90] { padding: 12px; }
</style>

因此：

  • 本组件根元素也会带上父组件的 scopeId（方便父组件控制子组件根元素样式）；
  • 子组件内部的元素不带父组件的 data 属性，所以父组件 scoped 样式默认改不到子组件内部——需要 :deep()。
<style scoped>
/* 穿透到子组件内部：修改 Element Plus 等第三方组件的内部类名 */
:deep(.el-input__inner) { height: 32px; }

/* 插槽内容属于父组件作用域，也要用 deep */
:deep(.slot-content) { color: red; }

/* 声明一段全局样式（不推荐滥用） */
:global(.global-tip) { font-size: 12px; }

/* 多个 style 块：一个 scoped，一个全局 */
</style>

<style>
html body .force-global { z-index: 9999; }
</style>

CSS Modules

<template>
  <div :class="$style.card">内容</div>
</template>

<style module>
.card { padding: 12px; }   /* 类名会被哈希成唯一值，通过 $style 访问 */
</style>

选择建议：业务组件用 scoped（简单直观）；基础组件库或需要绝对隔离时用 module。

10.5 组件注册：局部、全局、自动导入

// ① 局部注册（推荐）：script setup 里 import 即用
import UserCard from './UserCard.vue'

// ② 全局注册：适合极高频的基础组件
// main.js
import BaseButton from '@/components/BaseButton.vue'
app.component('BaseButton', BaseButton)

// ③ 自动导入（需插件 unplugin-vue-components）
// vite.config.js
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    vue(),
    Components({
      dts: 'src/components.d.ts',
      resolvers: [ElementPlusResolver()]   // 按需自动引入 Element Plus
    })
  ]
})
方式优点缺点
局部 import依赖清晰、tree-shaking 好每个文件都要写 import
全局注册到处能直接用依赖关系隐藏；无法被 tree-shaking，体积增大
自动导入二者兼得（推荐大型项目）需配置，新人可能困惑"这组件哪来的"

10.6 命名与文件组织约定

项目规范示例
文件名PascalCase（大驼峰）UserCard.vue、BaseButton.vue
基础组件Base / App 前缀BaseInput.vue
单例组件The 前缀（每页只用一次）TheHeader.vue
紧密耦合的子组件父名前缀TodoList.vue + TodoListItem.vue
模板中使用PascalCase 优先（可自闭合）<UserCard />（DOM 内模板除外）
props 定义camelCase，模板用 kebab-case定义 userId，用 :user-id="1"
 
src/
├── components/          # 通用组件（跨页面复用）
│   ├── BaseButton.vue
│   └── UserCard.vue
├── views/               # 页面级组件（路由直接对应）
│   └── user/
│       ├── UserList.vue
│       └── components/  # 只属于该页面的子组件
│           └── UserFilter.vue
└── composables/         # 组合式函数（第三篇）
提醒在 DOM 内模板（直接写在 HTML 文件里、没有构建步骤）中，浏览器会把标签名统一小写，因此必须用 kebab-case：<user-card></user-card>。SFC 场景不受此限制。

10.7 常见坑

  • 坑 1在 <script setup> 里写 export default：不允许，用 defineOptions 代替。
  • 坑 2以为 scoped 能改子组件内部样式：需要 :deep()；第三方组件库尤其常见。
  • 坑 3多根组件导致 class 透传失效：需要 v-bind="$attrs"。
  • 坑 4组件名与 HTML 原生标签冲突：如命名 <Button> 会与原生 button 冲突，加前缀（BaseButton）。
  • 坑 5循环引用组件：A 引 B、B 引 A。用异步导入或在 defineOptions 里显式命名后按名引用（Vite 通常能处理，但要注意 name）。
  • 坑 6在模板里访问未暴露的变量：<script setup> 里写在 if/function 内部的变量不会暴露（只有顶层绑定才会）。
