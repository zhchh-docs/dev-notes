◆本章目标

  • 会用 defineEmits 声明并触发自定义事件；
  • 能传递任意数量与类型的事件参数；
  • 会为事件写参数校验（开发期保障）；
  • 理解声明 emits 带来的三个实际好处（不只是"规范"）；
  • 分清 原生 DOM 事件与自定义事件的边界（Vue3 取消了 .native）；
  • 独立完成一个分页组件的父子通信。

12.1 defineEmits：声明并触发

<!-- 子组件 Child.vue -->
<script setup>
// 声明：数组形式
const emit = defineEmits(['save', 'cancel'])

// 触发
function onSave() {
  emit('save')            // 无参数
}
function onCancel(reason) {
  emit('cancel', reason)  // 带参数
}
</script>

<template>
  <button @click="onSave">保存</button>
  <button @click="onCancel('用户放弃')">取消</button>
</template>
<!-- 父组件 -->
<template>
  <Child @save="handleSave" @cancel="handleCancel" />
</template>

<script setup>
function handleSave() { console.log('保存') }
function handleCancel(reason) { console.log('取消：', reason) }
</script>

在模板里也可以直接内联触发（用 $emit）：

<template>
  <!-- 不使用 script setup 时用 $emit；setup 里推荐用 emit 变量更清晰 -->
  <button @click="$emit('save', formData)">保存</button>
</template>
defineEmits 是编译宏：无需 import，只能在 <script setup> 顶层调用，返回值就是触发函数。

12.2 传参与多事件

<!-- 子组件 -->
<script setup>
const props = defineProps({ row: Object, index: Number })
const emit = defineEmits(['edit', 'delete', 'change'])

function onEdit() {
  emit('edit', props.row)                      // 一个参数
}
function onDelete() {
  emit('delete', props.row.id, props.index)    // 多个参数
}
</script>

<template>
  <button @click="onEdit">编辑</button>
  <button @click="onDelete">删除</button>
  <!-- 模板内联：直接 emit 并传参 -->
  <button @click="emit('change', { id: row.id, v: $event })">改</button>
</template>
<!-- 父组件：按顺序接收多个参数 -->
<Row
  :row="item"
  :index="i"
  @edit="onEdit"
  @delete="(id, index) => remove(id, index)"
/>

emit 的参数是位置参数（没有名字）。参数超过两个时，建议改为传一个对象：emit('delete', { id, index, row })——可读性更好，也不会因顺序变动出错。

TS 类型写法

<script setup lang="ts">
const emit = defineEmits<{
  // 具名元组语法（Vue 3.3+）
  change: [value: string]
  delete: [id: number, index: number]
  // 旧写法
  // (e: 'change', value: string): void
}>()

emit('change', 'abc')      // ✅
emit('delete', 1, 2)       // ✅
// emit('delete', '1')     // ❌ 类型报错
</script>

12.3 事件校验

<script setup>
const emit = defineEmits({
  // 无校验：给 null
  click: null,

  // 有校验：函数返回 true 表示通过
  submit: (payload) => {
    if (!payload || typeof payload.email !== 'string') {
      console.warn('submit 事件缺少 email 字段')
      return false
    }
    return true
  },

  // 校验参数个数与类型
  delete: (id, index) => typeof id === 'number' && typeof index === 'number'
})
</script>

校验失败只会在开发模式下打印警告，不会阻止事件继续传播。它适合作为"组件库对外契约的自检"。

12.4 声明 emits 的三个好处

  1. 避免"事件被当成普通属性透传"：未声明的 @click 会作为 onClick 落到子组件根元素上变成原生监听；声明后 Vue 知道这是自定义事件，不会重复触发（否则你点一次可能触发两次）。
  2. 更好的 IDE 与类型支持：TS 项目里父组件写错事件名/参数类型会直接报错。
  3. 自文档化：看一眼 defineEmits([...]) 就知道这个组件会对外发什么消息（组件库必备）。
<!-- 反面案例：子组件没声明 click -->
<!-- Child.vue -->
<template><div class="box" @click="$emit('click')"></div></template>
<script setup>
// 没写 defineEmits(['click'])
</script>

<!-- 父组件 -->
<Child @click="handler" />
<!-- 结果：点击时 handler 执行两次 —— 一次是自定义事件，一次是透传到根元素的原生 click -->
坑这个"触发两次"的问题非常常见。只要组件会 emit 某个事件名，就一定要在 defineEmits 里声明它。

判断口诀：声明了 → 自定义事件；没声明 → 透传到根元素当原生事件用。

12.6 事件命名约定

  • kebab-case 优先：模板里 @update-name；camelCase（@updateName）也能用，但 HTML 属性不区分大小写，易踩坑；
  • v-model 专用命名：update:modelValue、update:title（第 13 章）；
  • 语义化动词：submit、cancel、change、delete、select；避免用 click 这类已被原生占用的名字（除非你确实想声明它）；
  • 组件库规范：统一前缀（如 Element Plus 全用 @change/@update:modelValue）。

12.7 实战：分页组件

<!-- Pagination.vue -->
<template>
  <div class="pager">
    <button :disabled="page <= 1" @click="go(page - 1)">上一页</button>
    <button
      v-for="p in pages"
      :key="p"
      :class="{ active: p === page }"
      @click="go(p)"
    >{{ p }}</button>
    <button :disabled="page >= totalPage" @click="go(page + 1)">下一页</button>
    <span>共 {{ total }} 条 / {{ totalPage }} 页</span>
  </div>
</template>

<script setup>
import { computed } from 'vue'

const props = defineProps({
  page: { type: Number, required: true },      // 当前页（受控）
  total: { type: Number, required: true },     // 总条数
  pageSize: { type: Number, default: 10 }
})

const emit = defineEmits({
  'update:page': (p) => Number.isInteger(p) && p >= 1,
  change: (p) => Number.isInteger(p)
})

const totalPage = computed(() => Math.ceil(props.total / props.pageSize) || 1)

const pages = computed(() => {
  // 最多显示 7 个页码按钮（简化版：从头开始展示）
  const n = Math.min(7, totalPage.value)
  return Array.from({ length: n }, (_, i) => i + 1)
})

function go(p) {
  if (p < 1 || p > totalPage.value || p === props.page) return
  emit('update:page', p)
  emit('change', p)
}
</script>
<!-- 父组件使用 -->
<template>
  <ul>
    <li v-for="i in list" :key="i.id">{{ i.name }}</li>
  </ul>
  <!-- 用 v-model:page 双向绑定（第 13 章）；这里先展示完整写法 -->
  <Pagination
    :page="page"
    :total="total"
    @update:page="page = $event"
    @change="fetchList"
  />
</template>

<script setup>
import { ref, watch } from 'vue'
import Pagination from './Pagination.vue'

const page = ref(1)
const total = ref(0)
const list = ref([])

async function fetchList() {
  const res = await fetch(`/api/list?page=${page.value}`).then(r => r.json())
  list.value = res.items
  total.value = res.total
}
fetchList()
</script>

这个分页组件体现了组件化的核心：数据由父组件持有（受控），子组件只负责"展示 + 报告用户意图"。它自己不知道数据从哪来，因此可以在任何页面复用。

12.8 本章常见坑

  • 坑 1没声明 emits 导致事件触发两次（自定义 + 原生透传）。
  • 坑 2事件名大小写：DOM 模板里 @updateName 会被小写化为 @updatename 而匹配不上。统一用 kebab-case。
  • 坑 3在 emit 后立刻读 props 期望已更新：父组件状态更新与 DOM 更新都是异步的，紧接着读 props.page 仍是旧值（用 nextTick 或 watch）。
  • 坑 4emit 与 props 同名冲突：不要 emit 一个与 props 同名的事件，会引起理解混乱。
  • 坑 5多根组件监听器丢失：需 v-bind="$attrs"。
  • 坑 6在子组件里监听自己的 emit：emit 是"向上广播"，不会触发自己。
