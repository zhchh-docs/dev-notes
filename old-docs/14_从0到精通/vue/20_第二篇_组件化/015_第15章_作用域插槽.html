◆本章目标

  • 理解为什么需要作用域插槽（插槽内容在父作用域，但数据来自子）；
  • 掌握 <slot :item="x"> + v-slot="{ item }" 的配对写法；
  • 掌握具名作用域插槽与解构重命名；

15.1 问题：父要渲染子的数据

上一章留下一个矛盾：插槽内容在父作用域编译，因此访问不到子组件的数据。但真实需求恰恰是：

  • 表格组件知道每一行的数据，但"这一行怎么显示"应由使用者决定（日期格式、按钮、标签）；
  • 列表组件知道加载状态、是否有更多，但"加载中显示什么"应由使用者决定。
<!-- 需求：父组件想这样写 -->
<DataTable :data="users">
  <template #row="{ item }">
    <!-- 这个 item 来自子组件（每一行的数据） -->
    <td>{{ item.name }}</td>
    <td>{{ formatDate(item.createdAt) }}</td>
    <td><button @click="remove(item.id)">删除</button></td>
  </template>
</DataTable>

作用域插槽的机制：子组件在 <slot> 上"传参"，父组件在 v-slot 上"接参"——就像调用一个函数把数据交出去。

15.2 基本用法：slot props

<!-- UserList.vue（子组件） -->
<template>
  <ul>
    <li v-for="user in users" :key="user.id">
      <!-- 把数据绑到 slot 上，称为"插槽 props" -->
      <slot :user="user" :index="index" :is-last="index === users.length - 1">
        <!-- 后备内容：没传插槽时用默认渲染 -->
        {{ user.name }}
      </slot>
    </li>
  </ul>
</template>

<script setup>
defineProps({ users: { type: Array, required: true } })
</script>
<!-- 父组件 -->
<UserList :users="users">
  <!-- v-slot 的值就是子组件传出的那个对象 -->
  <template v-slot:default="slotProps">
    <span>{{ slotProps.index + 1 }}. {{ slotProps.user.name }}</span>
    <em v-if="slotProps.isLast">（最后一位）</em>
  </template>
</UserList>

<!-- 简写：#default="slotProps"（推荐直接解构） -->
<UserList :users="users">
  <template #default="{ user, index, isLast }">
    <span>{{ index + 1 }}. {{ user.name }}</span>
    <em v-if="isLast">（最后一位）</em>
  </template>
</UserList>

记忆方式：<slot :user="user"> 相当于"函数调用时传参"，v-slot="{ user }" 相当于"函数定义时接参"。

15.3 具名作用域插槽

具名 + 作用域组合，写法是 #名字="参数"：

<!-- DataTable.vue -->
<template>
  <table>
    <thead>
      <tr>
        <slot name="head" :columns="columns">
          <th v-for="c in columns" :key="c.key">{{ c.title }}</th>
        </slot>
      </tr>
    </thead>
    <tbody>
      <tr v-for="(row, i) in data" :key="row.id">
        <slot name="row" :row="row" :index="i">
          <td v-for="c in columns" :key="c.key">{{ row[c.key] }}</td>
        </slot>
      </tr>
    </tbody>
    <tfoot>
      <slot name="empty" :is-empty="data.length === 0">
        <tr v-if="!data.length"><td colspan="99">暂无数据</td></tr>
      </slot>
    </tfoot>
  </table>
</template>

<script setup>
defineProps({ data: Array, columns: Array })
</script>
<!-- 使用 -->
<DataTable :data="users" :columns="cols">
  <template #head="{ columns }">
    <th v-for="c in columns" :key="c.key">{{ c.title.toUpperCase() }}</th>
  </template>

  <template #row="{ row, index }">
    <td>{{ index + 1 }}</td>
    <td>{{ row.name }}</td>
    <td><StatusTag :status="row.status" /></td>
  </template>

  <template #empty="{ isEmpty }">
    <tr v-if="isEmpty"><td colspan="99">没有找到用户~</td></tr>
  </template>
</DataTable>
默认插槽的两种写法：#default="{ x }" 显式写法；或省略 template 直接把内容写在组件标签内（此时无法接参数）。要接参数就必须写 template。

15.4 解构与重命名

<template>
  <!-- 解构 -->
  <template #row="{ row }">{{ row.name }}</template>

  <!-- 重命名（a: b 的形式） -->
  <template #row="{ row: user }">{{ user.name }}</template>

  <!-- 默认值（子组件没传该项时兜底） -->
  <template #row="{ row = {}, index = 0 }">{{ index }} {{ row.name }}</template>

  <!-- 直接拿到整个对象 -->
  <template #row="props">{{ props.row.name }}</template>
</template>

解构特别适合嵌套组件：避免变量名冲突（例如外层也叫 row）。

15.5 无渲染组件（Renderless）

把"逻辑"和"渲染"彻底分离：组件不渲染任何 DOM，只通过作用域插槽把状态与方法交出去。

<!-- MouseTracker.vue：只负责追踪鼠标位置，不渲染任何东西 -->
<template>
  <slot :x="x" :y="y"></slot>
</template>

<script setup>
import { ref, onMounted, onUnmounted } from 'vue'
const x = ref(0)
const y = ref(0)

function update(e) { x.value = e.clientX; y.value = e.clientY }

onMounted(() => window.addEventListener('mousemove', update))
onUnmounted(() => window.removeEventListener('mousemove', update))
</script>
<!-- 用法一：渲染成文字 -->
<MouseTracker v-slot="{ x, y }">鼠标位置：{{ x }}, {{ y }}</MouseTracker>

<!-- 用法二：渲染成方块（同一份逻辑，完全不同的 UI） -->
<MouseTracker v-slot="{ x, y }">
  <div class="dot" :style="{ left: x + 'px', top: y + 'px' }"></div>
</MouseTracker>

价值：逻辑复用率最高、UI 完全自由。它的现代替代方案是组合式函数（第 23 章 useMouse()）——后者没有额外组件层级，性能更好。二者取舍：

方案优点缺点
无渲染组件模板里一目了然；可在纯模板场景使用多一层组件实例（有开销）
组合式函数无额外层级、可组合、易测试只能在 script setup 里用

Vue3 的主流选择是组合式函数优先；无渲染组件仍适合"需要把逻辑做成可视化配置"或团队以模板为主的场景。

15.6 实战：可配置表格

这是企业级项目最常见的组件之一：列配置 + 自定义单元格。

<!-- ConfigTable.vue -->
<template>
  <table class="ct">
    <thead>
      <tr>
        <th v-for="col in columns" :key="col.key" :style="{ width: col.width }">
          {{ col.title }}
        </th>
      </tr>
    </thead>
    <tbody>
      <tr v-for="(row, i) in data" :key="rowKey ? row[rowKey] : i">
        <td v-for="col in columns" :key="col.key">
          <!-- 每列都可以有具名插槽：#cell-字段名 -->
          <slot :name="`cell-${col.key}`" :row="row" :value="row[col.key]" :index="i">
            <!-- 默认：直接显示值，支持格式化函数 -->
            {{ col.formatter ? col.formatter(row) : row[col.key] }}
          </slot>
        </td>
      </tr>
      <tr v-if="!data.length">
        <td :colspan="columns.length" class="empty">
          <slot name="empty">暂无数据</slot>
        </td>
      </tr>
    </tbody>
  </table>
</template>

<script setup>
defineProps({
  data: { type: Array, default: () => [] },
  columns: { type: Array, required: true },   // [{ key, title, width, formatter }]
  rowKey: { type: String, default: 'id' }
})
</script>
<!-- 使用 -->
<ConfigTable :data="users" :columns="cols">
  <!-- 自定义"状态"列 -->
  <template #cell-status="{ value }">
    <StatusTag :status="value" />
  </template>

  <!-- 自定义"操作"列：能拿到整行 -->
  <template #cell-actions="{ row }">
    <button @click="edit(row)">编辑</button>
    <button @click="remove(row.id)">删除</button>
  </template>

  <template #empty><Empty description="还没有用户" /></template>
</ConfigTable>

<script setup>
const cols = [
  { key: 'name', title: '姓名', width: '120px' },
  { key: 'status', title: '状态' },
  { key: 'createdAt', title: '创建时间', formatter: r => formatDate(r.createdAt) },
  { key: 'actions', title: '操作', width: '160px' }
]
</script>

这个模式是 Element Plus 的 el-table-column、Ant Design Vue 的表格的核心思路：列用配置描述，单元格用插槽定制。第 59 章会再深入表格组件设计。

15.7 与作用域样式的关系

再强调一次作用域规则的实践影响：

  • 插槽内容在父组件作用域编译 → 父组件的 scoped 样式直接生效；
  • 子组件 scoped 样式不会作用于插槽内容（因为内容不带子的 data-v 属性）；
  • 子组件若想给插槽内容加样式，需要 :deep() 或在父组件写。
<!-- 子组件内：改不到插槽内容 -->
<style scoped>
.slot-text { color: red; }      /* ❌ 无效（内容由父渲染） */
:deep(.slot-text) { color: red; } /* ✅ 可以 */
</style>

15.8 本章常见坑

  • 坑 1忘了在 slot 上绑定数据：写了 <slot> 却没写 :item，父组件解构出来是 undefined。
  • 坑 2在组件标签上直接写 v-slot 接参：<Comp #default="{x}"> 只能用于只有默认插槽的组件；有具名插槽时必须用 template。
  • 坑 3同名变量冲突：内外层都叫 row 时看不出是谁的。用重命名解决。
  • 坑 4插槽 props 不是响应式的误解：它本身就是每次渲染重新计算的，父组件拿到的就是最新值；但别把它存进普通变量再用于模板（存进 ref 或直接用）。
  • 坑 5性能：插槽内容会在父组件更新时重新渲染。把插槽内容抽成子组件 + v-memo 可优化（第 71 章）。
