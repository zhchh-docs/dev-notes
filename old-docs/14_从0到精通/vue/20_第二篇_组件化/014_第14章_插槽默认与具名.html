14.1 为什么需要插槽

props 能把数据传进子组件，但传不了结构。看一个真实需求：卡片组件。

<!-- ❌ 用 props 传结构？做不到（或只能用危险的 v-html） -->
<Card :title="标题" :html="'<button>操作</button>'" />

<!-- ✅ 插槽：把"结构"当参数传进去 -->
<Card>
  <template #header>
    <h3>标题</h3>
  </template>

  <p>这里是卡片正文，可以是任意结构</p>

  <template #footer>
    <button>确定</button>
    <button>取消</button>
  </template>
</Card>

一句话区分：props 传"数据"，插槽传"内容"；事件传"动作"。三者构成组件的完整对外接口。

插槽的价值在于：组件负责结构与行为，使用者负责内容——这是弹窗、表格、布局类组件能被复用的根本原因。

14.2 默认插槽

<!-- Card.vue -->
<template>
  <div class="card">
    <slot></slot>          <!-- 出口：父组件传的内容会渲染到这里 -->
  </div>
</template>

<!-- 使用 -->
<Card>
  <p>任意内容</p>
  <button>按钮</button>
</Card>

渲染结果：

<div class="card">
  <p>任意内容</p>
  <button>按钮</button>
</div>

默认插槽的名字是 default，完整写法是 <template #default>，通常省略。

14.3 后备内容（默认值）

在 <slot> 标签里写的内容是后备内容：父组件没传时显示它。

<!-- SubmitButton.vue -->
<template>
  <button type="submit">
    <slot>提交</slot>      <!-- 没传内容时显示"提交" -->
  </button>
</template>

<!-- 用法一：用默认值 -->
<SubmitButton />          <!-- 按钮文字：提交 -->

<!-- 用法二：覆盖默认值 -->
<SubmitButton>保存草稿</SubmitButton>

后备内容是组件设计友好度的体现：常用场景零配置可用，特殊场景可完全定制（Element Plus 的按钮、空状态组件都大量使用）。

14.4 具名插槽

一个组件可能需要多个"出口"，比如布局组件的 header / main / footer。

<!-- PageLayout.vue -->
<template>
  <div class="layout">
    <header>
      <slot name="header"></slot>
    </header>

    <main>
      <slot></slot>                 <!-- 未命名的就是 default -->
    </main>

    <aside>
      <slot name="sidebar"></slot>
    </aside>

    <footer>
      <slot name="footer"></slot>
    </footer>
  </div>
</template>
<!-- 完整写法：v-slot:name -->
<PageLayout>
  <template v-slot:header>
    <h1>页面标题</h1>
  </template>

  <!-- 简写：#name（强烈推荐） -->
  <template #sidebar>
    <nav>侧边导航</nav>
  </template>

  <!-- 默认插槽：可省略 template，也可显式写 #default -->
  <p>正文内容</p>

  <template #footer>
    <small>© 2026</small>
  </template>
</PageLayout>
写法说明推荐度
v-slot:header完整写法一般
#header简写，与前者完全等价✅ 推荐
#default默认插槽显式写法需要时
元素上直接 slot="header"Vue2 遗留写法❌ 已废弃
注意v-slot 只能写在组件标签或 <template> 上，不能写在普通元素上（如 <div #header> 是错误的）。

14.5 动态插槽名

插槽名可以来自变量，用于"可配置布局"这类高级场景：

<template>
  <PageLayout>
    <template #[currentSection]>
      <p>这段内容会进入名为 {{ currentSection }} 的区域</p>
    </template>
  </PageLayout>

  <button @click="currentSection = 'sidebar'">移到侧边</button>
</template>

<script setup>
import { ref } from 'vue'
const currentSection = ref('header')
</script>

动态插槽名用得少，但它是"配置驱动页面"（低代码/表单生成器）的关键技术之一：后端下发 { slot: 'header', component: 'Xxx' }，前端用 <component :is> + 动态插槽拼装页面（第 19 章会组合使用）。

14.6 插槽内容的作用域

这是插槽最重要、也最容易理解错的一条规则：插槽内容在父组件的作用域中编译。

<!-- Child.vue -->
<template>
  <div>
    <slot></slot>
  </div>
</template>
<script setup>
import { ref } from 'vue'
const innerMsg = ref('子组件的数据')     // 只在子组件可见
</script>

<!-- 父组件 -->
<Child>
  <!-- ✅ 可以访问父组件的数据 -->
  <p>{{ parentMsg }}</p>

  <!-- ❌ 访问不到子组件的 innerMsg：插槽内容不是在这里编译的 -->
  <p>{{ innerMsg }}</p>
</Child>

图 14-1 插槽内容的作用域归属

两个实际影响：

  • 样式：插槽内容属于父组件，所以父组件的 scoped 样式能作用到它（不需要 :deep）；而子组件的 scoped 样式作用不到插槽内容。
  • 数据访问：想让插槽里用子组件的数据，必须用作用域插槽（下一章）。

14.7 实战：可配置布局卡片

<!-- BaseCard.vue -->
<template>
  <section class="card">
    <header v-if="$slots.header" class="card__head">
      <slot name="header">
        <h3>{{ title }}</h3>          <!-- 后备内容也能用 props -->
      </slot>
    </header>

    <div class="card__body">
      <slot></slot>
    </div>

    <footer v-if="$slots.footer" class="card__foot">
      <slot name="footer"></slot>
    </footer>

    <div v-if="$slots.extra" class="card__extra">
      <slot name="extra"></slot>
    </div>
  </section>
</template>

<script setup>
defineProps({ title: { type: String, default: '' } })
</script>

<style scoped>
.card { border: 1px solid #d8e2cc; border-radius: 12px; background: #fff; }
.card__head { padding: 12px 16px; border-bottom: 1px solid #eee; }
.card__body { padding: 16px; }
.card__foot { padding: 12px 16px; border-top: 1px solid #eee; text-align: right; }
</style>
<!-- 使用 -->
<BaseCard title="用户统计">
  <template #header>
    <div class="row">
      <h3>用户统计</h3>
      <el-tag>实时</el-tag>
    </div>
  </template>

  <p>本月新增 1,284 人，环比 +12%</p>

  <template #footer>
    <button>导出报表</button>
  </template>
</BaseCard>

关键技巧：用 $slots.xxx 判断插槽是否被传入，从而决定外层容器是否渲染（避免出现空的 header 边框）。

<!-- $slots 是插槽对象，常用于条件渲染 -->
<header v-if="$slots.header">...</header>
<div v-if="$slots.default">...</div>

<!-- 在 JS 里访问（script setup 中用 useSlots） -->
<script setup>
import { useSlots } from 'vue'
const slots = useSlots()
console.log(!!slots.header)   // 父组件是否传了 header 插槽
</script>

14.8 本章常见坑

  • 坑 1在插槽里访问子组件数据：默认不行，需要作用域插槽（第 15 章）。
  • 坑 2v-slot 写在普通元素上：只能用于组件标签或 <template>。
  • 坑 3混用新旧写法：slot="header"（Vue2）与 v-slot 不能在同一组件内混用。
  • 坑 4以为子组件的 scoped 样式能改插槽内容：不能，插槽内容属父作用域，样式应在父组件写或用 :deep 反向处理。
  • 坑 5多个同名插槽：后写的会覆盖先写的（只有最后一个生效）。
  • 坑 6插槽内容里的事件冒泡路径：事件按渲染后的 DOM 结构冒泡，不是按模板嵌套关系——子组件内部元素上的事件会冒泡到子组件根元素。
