18.1 基本用法：provide 与 inject

<!-- 祖先组件 Ancestor.vue -->
<script setup>
import { provide, ref } from 'vue'

// ① 提供静态值
provide('theme', 'dark')

// ② 提供对象（可包含方法）
provide('config', { size: 'large', onChange: (v) => console.log(v) })
</script>

<!-- 任意后代组件（不管隔多少层） -->
<script setup>
import { inject } from 'vue'
const theme = inject('theme')          // 'dark'
const config = inject('config')
</script>

<template>
  <div :class="`theme-${theme}`">内容</div>
</template>

关键点：

  • provide 必须在组件的 setup 阶段同步调用（不能在 setTimeout 里调）；
  • inject 会沿着父组件链向上查找，找到最近的 provide；
  • 祖先与后代不需要知道彼此的存在，只要 key 一致。
它不是"全局"：provide 的作用域是该组件的子树。两个平级的父组件各自 provide 同名 key，互不影响——这比全局变量安全得多。

18.2 传递响应式数据

静态值意义有限。真实场景中要传的是会变化的数据——直接把 ref / reactive 对象传下去即可。

<!-- 祖先 -->
<script setup>
import { provide, ref, reactive, readonly, computed } from 'vue'

const count = ref(0)
const user = reactive({ name: '小明', level: 1 })
const double = computed(() => count.value * 2)

// ✅ 传 ref / reactive 对象本身（保持响应性）
provide('count', count)
provide('user', user)

// ✅ 传 readonly 版本：禁止后代直接改（推荐做法！）
provide('readonly-count', readonly(count))

function inc() { count.value++ }
provide('inc', inc)     // 提供修改方法
</script>

<!-- 后代 -->
<script setup>
import { inject } from 'vue'
const count = inject('count')
const user = inject('user')
const inc = inject('inc')

// 模板里直接用：{{ count }}（ref 自动解包）
// JS 里：count.value
</script>
不要传 count.value：provide('count', count.value) 传的是快照数字，之后变化不会同步。必须传 ref 对象本身。

响应式传递口诀：传对象（ref/reactive），不传值。

18.3 默认值与安全注入

<script setup>
import { inject } from 'vue'

// ① 默认值（祖先没提供时使用）
const theme = inject('theme', 'light')

// ② 默认值是工厂函数（开销大或需要新对象时用）
const config = inject('config', () => ({ size: 'small' }), true)
// 第三个参数 true 表示"把第二个参数当工厂函数调用"

// ③ 安全写法：判空 + 抛出明确错误
const ctx = inject('form-context', null)
if (!ctx) {
  throw new Error('FormItem 必须放在 Form 组件内部使用')
}
</script>

组件库里推荐第 ③ 种：与其让使用者拿到 undefined 后在某处莫名其妙报错，不如在组件初始化时抛出一条明确的错误信息。

18.4 用 Symbol 作为 key

字符串 key 有冲突风险（尤其是大型项目或多组件库混用）。用 Symbol 可彻底避免：

// keys.js —— 集中管理注入 key
export const THEME_KEY = Symbol('theme')
export const FORM_CONTEXT = Symbol('form-context')
export const TABLE_CONTEXT = Symbol('table-context')
<!-- 提供 -->
<script setup>
import { provide } from 'vue'
import { FORM_CONTEXT } from './keys'
provide(FORM_CONTEXT, { model, rules, validate })
</script>

<!-- 注入 -->
<script setup>
import { inject } from 'vue'
import { FORM_CONTEXT } from './keys'
const ctx = inject(FORM_CONTEXT, null)
</script>

TypeScript 项目还能配合 InjectionKey<T> 获得完整类型推导：

// keys.ts
import type { InjectionKey, Ref } from 'vue'
export interface FormContext {
  model: Record<string, any>
  validate: () => Promise<boolean>
}
export const FORM_CONTEXT: InjectionKey<FormContext> = Symbol('form-context')

// 注入时自动推导出 FormContext 类型
const ctx = inject(FORM_CONTEXT)   // ctx: FormContext | undefined

18.5 应用级 provide

在应用实例上 provide，相当于给整个应用提供全局依赖（插件常用）：

// main.js
import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)

// 全局注入：任意组件都能 inject
app.provide('appVersion', '1.2.0')
app.provide('httpClient', axios.create({ baseURL: '/api' }))

app.mount('#app')
<!-- 任意组件 -->
<script setup>
import { inject } from 'vue'
const http = inject('httpClient')
</script>
方式作用域适用
app.provide整个应用插件、全局配置（i18n、http client）
组件内 provide该组件子树组件族内部上下文

18.6 谁负责修改？只读约定

这是 provide/inject 最重要的设计约定：谁 provide，谁负责修改；后代只读取和调用提供的方法。

<!-- ✅ 推荐：提供状态 + 修改方法，后代调用方法 -->
<script setup>
import { provide, ref, readonly } from 'vue'

const count = ref(0)
function inc() { count.value++ }

provide('count', readonly(count))   // 只读，后代改不了
provide('inc', inc)                 // 想改？调我提供的方法
</script>

<!-- 后代 -->
<script setup>
const count = inject('count')
const inc = inject('inc')
// count.value++  → 告警（readonly）
// inc()          → ✅ 正确
</script>

为什么这么约定：

  • 可追踪：所有修改都发生在同一个文件里，调试只需看一处；
  • 可维护：后代组件不依赖"上游内部实现"，只依赖约定好的方法；
  • 与 Pinia 的对比：Pinia 的 action 也是同样思路——状态集中修改。

一句话：inject 拿到的是"能力"，不是"可以随便改的数据"。

18.7 实战：Form / FormItem 组件族

这是 provide/inject 最经典的用例：表单容器提供上下文，表单项注入并使用。

<!-- MyForm.vue -->
<template>
  <form @submit.prevent="onSubmit">
    <slot></slot>
  </form>
</template>

<script setup>
import { provide, ref } from 'vue'
import { FORM_CONTEXT } from './keys'

const props = defineProps({ model: { type: Object, required: true } })

// 收集所有 FormItem 的校验函数
const validators = ref([])
const errors = ref({})

function register(prop, validateFn) {
  validators.value.push({ prop, validateFn })
}
function unregister(prop) {
  validators.value = validators.value.filter(v => v.prop !== prop)
}
async function validate() {
  const results = await Promise.all(validators.value.map(v => v.validateFn()))
  return results.every(Boolean)
}

// 提供上下文：数据 + 注册/校验能力
provide(FORM_CONTEXT, { model: props.model, errors, register, unregister })

async function onSubmit() {
  if (!(await validate())) return
  console.log('提交', props.model)
}
defineExpose({ validate })
</script>
<!-- MyFormItem.vue -->
<template>
  <div class="form-item">
    <label>{{ label }}</label>
    <slot></slot>
    <p v-if="error" class="err">{{ error }}</p>
  </div>
</template>

<script setup>
import { inject, ref, computed, onUnmounted } from 'vue'
import { FORM_CONTEXT } from './keys'

const props = defineProps({
  label: String,
  prop: { type: String, required: true },
  required: Boolean
})

const ctx = inject(FORM_CONTEXT)
if (!ctx) throw new Error('MyFormItem 必须在 MyForm 内使用')

const error = ref('')

async function validateFn() {
  const value = ctx.model[props.prop]
  if (props.required && (value === '' || value == null)) {
    error.value = `${props.label}不能为空`
    return false
  }
  error.value = ''
  return true
}

// 向表单注册自己，卸载时注销
ctx.register(props.prop, validateFn)
onUnmounted(() => ctx.unregister(props.prop))
</script>
<!-- 使用 -->
<MyForm :model="form" ref="formRef">
  <MyFormItem label="用户名" prop="name" required>
    <input v-model="form.name">
  </MyFormItem>
  <MyFormItem label="邮箱" prop="email" required>
    <input v-model="form.email">
  </MyFormItem>
  <button type="submit">提交</button>
</MyForm>

这个模式正是 Element Plus 的 el-form / el-form-item 的实现原理（第 58 章会完整实现一版）：容器收集子项的校验器，子项注入容器上下文。

18.8 本章常见坑

  • 坑 1传值不传对象：provide('c', count.value) 失去响应性。传 count。
  • 坑 2解构注入的响应式对象：const { count } = inject('ctx') 若 count 是 ref 没问题，若已被展开成普通值则失去响应。谨慎解构，用 toRefs。
  • 坑 3key 冲突或写错：用 Symbol + 集中管理 keys 文件。
  • 坑 4后代直接修改注入的数据：破坏可追踪性。用 readonly + 提供方法。
  • 坑 5异步 provide：provide 必须在 setup 同步阶段调用，写在 await 之后不生效。
  • 坑 6注册未注销：FormItem 类组件要在 onUnmounted 中注销，否则表单里残留已销毁项的校验器。
  • 坑 7把 provide 当全局状态：跨业务模块共享请用 Pinia，provide 只用于组件族内部。

✓ 本章小结

要点一句话
作用跨任意层级向后代注入依赖，避免 props 透传地狱
用法祖先 provide(key, value)；后代 inject(key, default)
响应式传 ref/reactive 对象本身，不传 .value
默认值第二个参数；工厂函数需第三参 true
key用 Symbol（+ TS 的 InjectionKey）避免冲突与获得类型
应用级app.provide 注入全局依赖（插件、http client）
约定谁 provide 谁修改：传 readonly + 方法
经典用例Form / FormItem：子项注册校验器，容器统一校验
