57.1 先拆需求：一个弹窗到底要做对多少件事

新手写弹窗只写一个居中 div，老手写弹窗要同时对付六件事。在写第一行代码前，先把清单列全：

需求点要解决的问题
遮罩层半透明背景，挡住底层交互，点击遮罩是否关闭要可配
层级 z-index弹窗永远浮在最上面；多个弹窗时后开的在上（见第 62 章）
锁定滚动打开弹窗时禁止背后页面滚动，否则滚滚轮背景跟着跑
Esc 关闭按 Esc 触发关闭，符合键盘用户习惯
进出动画淡入缩放，关闭时先播离场动画再卸载 DOM
关闭时机关到一半用户又打开：动画状态不能错乱；关闭后是否销毁内容

通用组件的工作量，80% 在"边界情况"，20% 在主体 UI。弹窗如此，表格、表单同样如此。

57.2 v-model 受控弹窗骨架

<!-- BaseDialog.vue -->
<script setup>
import { watch, onBeforeUnmount } from 'vue'
const props = defineProps({
  title: { type: String, default: '' },
  closeOnClickModal: { type: Boolean, default: true },
  destroyOnClose: { type: Boolean, default: false }
})
const visible = defineModel({ type: Boolean, default: false })
const render = ref(true)          // destroyOnClose 时控制内容是否挂载

function close() { visible.value = false }

// 锁定 body 滚动
watch(visible, (v) => {
  document.body.style.overflow = v ? 'hidden' : ''
  if (!v && props.destroyOnClose) {
    setTimeout(() => { render.value = false }, 300)  // 等离场动画播完
  }
  if (v) render.value = true
})

function onKey(e) { if (e.key === 'Escape') close() }
onMounted(() => window.addEventListener('keydown', onKey))
onBeforeUnmount(() => {
  window.removeEventListener('keydown', onKey)
  document.body.style.overflow = ''
})
</script>

<template>
  <Teleport to="body">
    <transition name="dialog">
      <div v-if="visible" class="mask" @click.self="closeOnClickModal && close()">
        <div class="dialog" role="dialog">
          <header class="dialog__header">{{ title }}</header>
          <div class="dialog__body" v-if="render"><slot /></div>
          <footer class="dialog__footer"><slot name="footer" /></footer>
        </div>
      </div>
    </transition>
  </Teleport>
</template>
.dialog-enter-active,.dialog-leave-active{transition:opacity .25s}
.dialog-enter-active .dialog,.dialog-leave-active .dialog{transition:transform .25s;transform:scale(.96)}
.dialog-enter-from,.dialog-leave-to{opacity:0}

57.3 为什么要 Teleport 到 body

如果弹窗直接写在组件的 DOM 树里，它会受祖先元素 transform / overflow / z-index 的影响：一个祖先设了 overflow:hidden 或 transform，弹窗的居中定位和层叠上下文就全乱了。<Teleport to="body"> 把弹窗节点渲染到 body 直接子节点下，绕开这些限制。

57.4 插槽与两种调用方式

声明式调用（推荐，可追踪）

<BaseDialog v-model="show" title="编辑用户">
  <UserForm :user="current" />
  <template #footer>
    <button @click="show = false">取消</button>
    <button @click="onSave">保存</button>
  </template>
</BaseDialog>

命令式调用（适合"弹一下就走"的提示）

// confirm.js：用 createApp 临时挂载一个确认框，不污染页面模板
import { createApp } from 'vue'
import ConfirmDialog from './ConfirmDialog.vue'

export function confirm(message) {
  const node = document.createElement('div')
  document.body.appendChild(node)
  const app = createApp(ConfirmDialog, {
    message,
    onConfirm: () => { app.unmount(); node.remove() }
  })
  app.mount(node)
}
维度声明式命令式
状态可见性模板里看得见，易调试藏在 JS 里，调用即忘
内容复杂度适合带表单的复杂弹窗适合 alert/confirm 类简单提示
生命周期跟随父组件需手动 unmount，否则内存泄漏

57.5 destroy-on-close 与内存注意

弹窗里如果放了一个大表单，关闭后内容其实还在 DOM 里（只是 v-if 隐藏）。两种策略：

  • 默认保留：重复打开不用重建，表单输入不丢——适合需要"暂存"的场景；
  • destroy-on-close：关闭即销毁，下次全新渲染——适合每次数据都不同、且弹窗内有定时器/订阅的场景。
别忘了弹窗内若 setInterval、addEventListener、订阅了全局事件，关闭不等于卸载。要么在关闭回调里清理，要么用 destroy-on-close 让组件走 unmount。

57.6 常见坑

  • 坑 1忘记恢复 body 滚动：关弹窗后页面滚不动了。
  • 坑 2动画与 v-if 同时切换导致离场动画看不到——要先播动画再卸载。
  • 坑 3命令式弹窗忘记 unmount，反复 confirm 内存持续增长。
  • 坑 4遮罩点击穿透到背后按钮：遮罩层要 @click.self 且独占最前。
  • 坑 5Esc 监听在多个弹窗重复注册，要在 unmount 时 remove。

工程上弹窗不只是「显示/隐藏」，还要管「焦点归位」和「层级队列」。打开时焦点应进入弹窗第一个可交互元素，关闭时焦点还给触发按钮，否则键盘用户会丢失位置。多个弹窗叠加时，用一个自增 z-index 计数器分配层级，Esc 只关最上层——这就是为什么不要写死 9999。

// 焦点归位 + z-index 自增队列（工程骨架）
let zTop = 2000
function openDialog(dlg) {
  dlg.style.zIndex = ++zTop          // 后开的永远在上
  dlg.addEventListener('keydown', e => {
    if (e.key === 'Escape' && +dlg.style.zIndex === zTop) dlg.close()
  })
  dlg.$refs.first?.focus()           // 焦点移入弹窗
}
// 关闭时：trigger.focus() 把焦点还回去
可访问性弹窗未管焦点会让键盘用户掉进遮罩后——打开 focus 弹窗、关闭 focus 触发按钮，是无障碍基线。

✓ 本章小结

要点一句话
需求清单遮罩/层级/锁滚动/Esc/动画/关闭时机，六件事缺一不可
受控弹窗defineModel 控 visible，关与开都通过父级状态
Teleport渲染到 body 绕开祖先 overflow/transform/层叠限制
插槽默认插槽放主体，#footer 放按钮区，允许父级替换
两种调用声明式管复杂表单，命令式管简单提示
内存关闭≠卸载；定时器/事件要在关闭或 unmount 时清理
