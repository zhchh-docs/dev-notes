60.1 列表页的标准三段式

后台系统 80% 的页面都是同一个模子：上面搜索条件、中间表格、下面分页。把它定型后，新页面就是"填空"。

<template>
  <PageSearch v-model="filters" @search="onSearch" @reset="onReset" />
  <BaseTable :columns="columns" :data="list" :loading="loading" />
  <BasePagination v-model:page="query.page" v-model:page-size="query.pageSize"
                   :total="total" @change="fetchList" />
</template>

60.2 查询参数对象与 URL 同步

所有查询条件放进一个 reactive 对象，请求时整体带去。更进一步：把条件同步到 URL query，刷新页面或分享链接时筛选条件不丢。

import { reactive, watch } from 'vue'
import { useRoute, useRouter } from 'vue-router'
const route = useRoute(), router = useRouter()

const filters = reactive({ keyword: '', status: '', page: 1, pageSize: 20 })

// 初始化：从 URL 读回条件
Object.assign(filters, route.query)

// 变化：写回 URL（replace 避免污染浏览器历史）
watch(filters, (q) => router.replace({ query: { ...q } }), { deep: true })

60.3 防抖搜索与重置

import { ref, watch } from 'vue'
// 简单防抖：输入后 300ms 才请求，避免每敲一个字打一次接口
let timer = null
watch(() => filters.keyword, () => {
  clearTimeout(timer)
  timer = setTimeout(() => { filters.page = 1; fetchList() }, 300)
})

function onReset() {
  Object.keys(filters).forEach(k => { filters[k] = k === 'pageSize' ? 20 : '' })
  filters.page = 1
  fetchList()
}

搜索类输入必须防抖，否则一次输入触发十次请求，既浪费后端算力又让列表闪烁。

60.4 三种 loading 的差别

场景体验目标loading 表现
首次加载告诉用户"正在取数"整表骨架屏
切换筛选条件旧数据还能看，新数据在来表格上轻遮罩，不清空旧列表
翻页仅换数据行仅表格行 loading，分页器禁用
常见错误切条件时直接清空 list，导致中间闪一块空白。更好的做法是保留旧数据 + 遮罩，新数据到了再替换。

60.5 封装 useListPage 组合式函数

// composables/useListPage.js
import { reactive, ref } from 'vue'
export function useListPage(api, initial = {}) {
  const list = ref([]), total = ref(0), loading = ref(false)
  const query = reactive({ page: 1, pageSize: 20, ...initial })

  async function fetchList() {
    loading.value = true
    try {
      const { list: rows, total: count } = await api({ ...query })
      list.value = rows; total.value = count
    } finally { loading.value = false }
  }
  async function refresh() { query.page = 1; await fetchList() }

  return { list, total, loading, query, fetchList, refresh }
}
// 任何列表页：三行接入
const { list, total, loading, query, fetchList } = useListPage(api.getUsers)
onMounted(fetchList)

60.6 常见坑

  • 坑 1翻页后修改筛选条件没把 page 重置回 1，导致停在第 5 页且无数据。
  • 坑 2快速输入时旧请求后返回覆盖新数据：加请求序号或取消机制，只认最后一次。
  • 坑 3URL 同步与 watch 死循环：query 变化→写 URL→路由变化→又改 query。用 replace + 判断相等。
  • 坑 4重置不彻底：只清 keyword，忘了清 status / page。

列表页最隐蔽的 bug 是「请求竞态」：输入快时先发的请求可能后返回，把旧数据盖在新数据上。用一个自增序号做令牌，只有最后一次的结果允许写入。同时 filters 要完整同步到 URL，刷新后筛选条件、页码、每页条数都能还原。

// 竞态防护：自增令牌（工程骨架）
let seq = 0
async function fetchList() {
  const cur = ++seq               // 本次请求的令牌
  const data = await api.list(query)
  if (cur !== seq) return          // 已有更新的请求，丢弃本次
  rows.value = data.list
}
watch(filters, () => { page.value = 1; fetchList() }, { deep: true })
URL 同步把 filters/page/pageSize 写进 route.query，刷新与浏览器后退都能还原现场。

列表页的「重置」不只是清空输入：要把 page 回 1、filters 回初始、重新拉取，同时清掉 URL 上残留的 query。否则用户点重置后，URL 还挂着旧条件，刷新又回到老筛选。

// 重置：清空 filters + 回页码 + 同步 URL
const initial = { kw:'', city:'' }
function reset(){
  Object.assign(filters, initial)
  page.value = 1
  router.replace({ query: { ...filters } })  // 清掉旧 query
  fetchList()
}
要点说明
重置范围filters/page/URL 三处一起清
防抖输入停顿 300ms 才请求
竞态自增令牌丢弃过期响应

列表页的三种 loading 要分清：首次进页用骨架屏（整屏占位）、切查询条件用表格遮罩（保留旧数据）、翻页用行内 loading（不阻塞阅读）。混为一谈会让用户在无反馈时重复点查询。

// 三种 loading（工程骨架）
const firstLoading = ref(false)   // 首次：骨架屏
const filtering = ref(false)      // 切条件：表格遮罩
const paging = ref(false)         // 翻页：行内
// 模板：骨架 / v-loading 遮罩 / 行 loading 各管各的
要点首次骨架、切条件遮罩、翻页行 loading，三者别混用。

useListPage 把取数、分页、loading、竞态防护收敛成一个组合式函数，业务页只传 query 与请求函数。这样每个列表页不再重复写 try/catch 与 page 回 1。

// useListPage（工程骨架）
function useListPage(request){
  const rows=ref([]), page=ref(1), size=ref(10), loading=ref(false)
  async function load(){ loading.value=true; rows.value=(await request({page:page.value,size:size.value})).list; loading.value=false }
  return { rows, page, size, loading, load }
}
要点收敛取数逻辑，业务页零胶水。

URL 同步让列表页可分享：把 filters 与 page 写进 query，进页先从 query 还原状态，再请求。刷新后筛选不丢，这也是 44/47 章路由 query 的工程化用法。

// URL 还原（工程骨架）
const route = useRoute()
filters.kw.value = route.query.kw ?? ''
page.value = Number(route.query.page ?? 1)
要点说明
URL 同步筛选可分享可刷新
竞态自增令牌丢过期响应
