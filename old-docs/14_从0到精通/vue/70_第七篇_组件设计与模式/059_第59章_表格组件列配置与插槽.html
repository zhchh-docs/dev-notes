59.1 列配置数组驱动渲染

业务表格的列常常要动态增删（不同角色看不同列）。把列描述抽成数组，模板只负责"按数组渲染"，这是 ProTable 的核心思路。

<!-- BaseTable.vue 核心 -->
<script setup>
defineProps({
  columns: { type: Array, required: true },
  data: { type: Array, default: () => [] },
  loading: Boolean
})
// columns: [{ prop:'name', label:'姓名', width:120, fixed:true, sortable:true }]
</script>

<template>
  <table class="base-table">
    <thead>
      <tr>
        <th v-for="c in columns" :key="c.prop" :style="{ width: c.width + 'px' }">
          {{ c.label }}
          <span v-if="c.sortable" @click="$emit('sort-change', c.prop)">⇅</span>
        </th>
      </tr>
    </thead>
    <tbody>
      <tr v-for="(row, i) in data" :key="row.id ?? i">
        <td v-for="c in columns" :key="c.prop">{{ row[c.prop] }}</td>
      </tr>
    </tbody>
  </table>
</template>
列配置字段含义
prop对应行数据的字段名
label表头文字
width列宽（px）
fixed冻结列（横向滚动时固定在左/右）
sortable是否可排序，点击触发 sort-change
slot指定用哪个具名插槽渲染该列（见 59.2）

59.2 列插槽与表头插槽

纯文本列够用，但状态列要渲染标签、操作列要渲染按钮——这时用作用域插槽把单元格渲染权交给父级。

<!-- 子组件：给每列留一个 #cell 作用域插槽 -->
<td v-for="c in columns" :key="c.prop">
  <slot :name="'cell-' + c.prop" :row="row" :value="row[c.prop]">
    {{ row[c.prop] }}<!-- 默认兜底：纯文本 -->
  </slot>
</td>
<!-- 使用方 -->
<BaseTable :columns="columns" :data="list">
  <!-- 状态列渲染成标签 -->
  <template #cell-status="{ row }">
    <span class="tag" :class="row.status">{{ statusMap[row.status] }}</span>
  </template>
  <!-- 操作列渲染按钮 -->
  <template #cell-actions="{ row }">
    <button @click="edit(row)">编辑</button>
    <button @click="remove(row)">删除</button>
  </template>
</BaseTable>

列配置数组决定"有哪些列"，作用域插槽决定"某列怎么画"——两者组合，表格才能既配置化又不失灵活。

59.3 排序与筛选接口

// 父组件监听表格抛出的 sort-change，把排序参数交给后端或本地排序
<script setup>
const sort = reactive({ prop: '', order: 'asc' })
function onSortChange(prop) {
  sort.order = sort.prop === prop && sort.order === 'asc' ? 'desc' : 'asc'
  sort.prop = prop
  fetchList()   // 重新请求：{ sortProp, sortOrder, page, pageSize }
}
</script>
<BaseTable :columns="columns" :data="list" @sort-change="onSortChange" />
本地排序 vs 服务端排序：数据量小（<200 条）前端直接 Array.sort；数据量大必须把排序条件发给后端，由数据库排序后返回，否则前端翻页+排序对不上。

async function fetchList() {
  loading.value = true

59.5 空态、加载态与多选

  • 加载态：loading 为真时显示骨架或"加载中"，避免白屏；
  • 空态：data.length === 0 且非 loading 时，显示空插画与"暂无数据"，而不是一张空表头；
  • 多选：表头一列 checkbox 控制全选，行内 checkbox 维护 selectedIds，注意翻页后选中态是否保留。
性能预告当单页数据上千、或要一次渲染几万行时，DOM 节点过多会卡顿——那不是表格组件的问题，需要虚拟滚动，见第 72 章。

59.6 常见坑

  • 坑 1行 key 用下标 index：配合排序/删行时行渲染错乱（第 70 章专讲）。
  • 坑 2排序在前端、分页在后端，导致排序只对当前页生效，数据看起来"假排序"。
  • 坑 3列配置里塞渲染函数 JSX，模板可读性变差；优先用插槽。
  • 坑 4空态判断漏了 loading，加载中也显示"暂无数据"。

表格列配置的真正威力在于「配置驱动渲染」：columns 数组既描述列，也驱动排序、筛选、显隐。业务侧不改模板，只改配置对象——这就是为什么 ProTable 把列定义抽成数据。排序状态由组件持有，变化时 emit 给父级去请求后端排序。

// 列配置 + 排序状态（工程骨架）
const columns = [
  { prop: 'name', label: '姓名', sortable: true },
  { prop: 'age',  label: '年龄', width: 80 },
  { prop: 'city', label: '城市', slots: { default: 'cityTag' } }
]
function onSortChange({ prop, order }) {
  query.sort = order ? `${prop}:${order}` : ''
  fetchList()
}
大数据列配置驱动后，超过 500 行请交虚拟列表（第 72 章），不要一次性渲染全部行。

列配置驱动还能做「列显隐」：用户勾选哪些列就渲染哪些列，偏好存 localStorage。这比手写一堆 v-if 干净——配置变，渲染就变。

// 列显隐 + 偏好持久化
const hidden = ref(new Set(JSON.parse(localStorage.getItem('cols')||'[]')))
function toggle(col){
  hidden.value.has(col.prop) ? hidden.value.delete(col.prop) : hidden.value.add(col.prop)
  localStorage.setItem('cols', JSON.stringify([...hidden.value]))
}
const visibleCols = computed(()=> columns.filter(c=>!hidden.value.has(c.prop)))
要点说明
配置驱动columns 数组即渲染契约，业务不改模板
显隐hidden Set 过滤，偏好持久化
排序sort-change 事件交后端
