58.1 两级结构：Form 管全局，Item 管单项

表单不是一个大组件，而是两层协作：Form 持有 model 数据和规则总表，每个 FormItem 负责自己那一个字段的校验与错误显示。两者靠 provide/inject 通信。

<!-- BaseForm.vue -->
<script setup>
import { provide, reactive } from 'vue'
const props = defineProps({
  model: { type: Object, required: true },     // 表单数据对象
  rules: { type: Object, default: () => ({}) }  // { name: [规则...] }
})
const items = ref([])
provide('form', { model: props, rules: props.rules, register })
function register(item) { items.value.push(item) }

async function validate() {
  const results = await Promise.all(items.value.map(i => i.validate()))
  return results.every(Boolean)
}
function resetFields() {
  Object.keys(props.model).forEach(k => (props.model[k] = ''))
  items.value.forEach(i => i.clearError())
}
defineExpose({ validate, resetFields, validateField: (f) => {} })
</script>
<template><form class="base-form"><slot /></form></template>
<!-- BaseFormItem.vue -->
<script setup>
const props = defineProps({ prop: { type: String, required: true }, label: String })
const form = inject('form')
const error = ref('')
async function validate() {
  const value = form.model[props.prop]
  const rules = form.rules[props.prop] || []
  for (const rule of rules) {
    if (rule.required && !value) { error.value = rule.message; return false }
    if (rule.pattern && !rule.pattern.test(value)) { error.value = rule.message; return false }
    if (rule.validator) { const ok = await rule.validator(value); if (!ok) { error.value = rule.message; return false } }
  }
  error.value = ''; return true
}
function clearError() { error.value = '' }
defineExpose({ validate, clearError })
</script>
<template>
  <div class="form-item" :class="{ 'is-error': error }">
    <label>{{ label }}</label>
    <div class="control"><slot /></div>
    <p v-if="error" class="err">{{ error }}</p>
  </div>
</template>

58.2 校验规则体系

const rules = {
  name: [
    { required: true, message: '姓名必填' },
    { min: 2, max: 10, message: '2-10 个字符' }
  ],
  phone: [
    { required: true, message: '手机号必填' },
    { pattern: /^1\d{10}$/, message: '手机号格式不正确' }
  ],
  username: [
    // 自定义异步校验：去后端查重
    { required: true, message: '用户名必填' },
    { asyncValidator: async (value) => {
        const taken = await api.checkUsername(value)
        return !taken   // false => 不通过
      }, message: '用户名已被占用' }
  ]
}
规则类型写法用途
required{ required:true, message }必填
pattern{ pattern:/正则/, message }格式校验（手机/邮箱）
自定义 validator{ validator:(v)=>布尔 }业务规则（两次密码一致）
异步校验{ asyncValidator: async v=>布尔 }后端查重，需 loading 态防并发

58.3 校验时机与错误显示

什么时候触发校验，直接决定用户体验。常见三种时机：

  • blur：输入框失焦才校验——不打扰，适合注册；
  • change：值一变就校验——实时反馈，但要防抖；
  • submit：点提交时一次性全量校验——错误汇总，适合表单较少的场景。
<!-- 用法：和第 18 章的基础 Form 一致，但现在是工程级 -->
<script setup>
import { reactive, ref } from 'vue'
const formRef = ref()
const model = reactive({ name: '', phone: '' })
const rules = { /* 见 58.2 */ }
async function onSubmit() {
  const ok = await formRef.value.validate()
  if (!ok) return                       // 任一字段失败，不提交
  await api.save(model)
}
</script>
<template>
  <BaseForm ref="formRef" :model="model" :rules="rules">
    <BaseFormItem prop="name" label="姓名">
      <input v-model="model.name" />
    </BaseFormItem>
    <BaseFormItem prop="phone" label="手机号">
      <input v-model="model.phone" />
    </BaseFormItem>
    <button @click="onSubmit">提交</button>
  </BaseForm>
</template>

表单的核心是"校验状态归 FormItem，数据归 model，规则归 Form"，三者各司其职，才能支持动态增删字段。

58.4 defineExpose：父组件能调哪些方法

暴露方法行为
validate()校验所有字段，全部通过 resolve(true)，否则 reject/resolve(false)
validateField(prop)只校验某一个字段（用于字段联动后局部重校）
resetFields()把 model 各字段还原为初始值，并清空所有错误
clearValidate()只清错误信息，不动数据
注意子组件通过模板 ref 拿到的是 组件公开实例，只有 defineExpose 暴露出来的方法才能调用；内部 ref 默认拿不到。

58.5 常见坑

  • 坑 1动态增删字段后没重新注册 Item——新增的 FormItem 没被 Form 的 items 收集到，validate 漏掉它。
  • 坑 2异步校验并发：用户快速输入，两次查重请求返回顺序颠倒，错误提示闪错。要做取消或只认最后一次。
  • 坑 3resetFields 只清错误不清数据，或只清数据不重置校验态。
  • 坑 4model 用了会被整体替换的对象（reactive 被重新赋值），Form 持有的是旧引用。
  • 坑 5错误提示同时出现多个——一个字段只显示第一条未通过规则即可。

真实表单的校验常是异步的：手机号要查是否已注册、密码要查强度。把异步校验写成 validator 返回 Promise，Form 在校验期间进入 loading，避免用户重复提交。错误信息统一由 FormItem 渲染，业务组件只管抛错。

// 异步校验：手机号查重（工程骨架）
const rules = {
  phone: [
    { required: true, message: '手机号必填' },
    { asyncValidator(rule, value) {
        return fetch(`/api/check-phone?n=${value}`)
          .then(r => r.ok ? Promise.resolve() : Promise.reject('已注册'))
    } }
  ]
}
// submit 时 await formRef.validate() 通过后再提交
时机异步校验放在 change（失焦后）触发，避免每次按键都打接口；submit 时再兜底全量校验。

✓ 本章小结

要点一句话
两级结构BaseForm 持 model+rules，BaseFormItem 管单项，provide/inject 串联
规则体系required/pattern/validator/asyncValidator，可链式校验
