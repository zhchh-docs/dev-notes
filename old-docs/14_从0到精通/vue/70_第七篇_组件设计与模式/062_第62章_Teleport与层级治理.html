62.1 Teleport 基本用法

<!-- to 可以是 body、选择器或元素 -->
<Teleport to="body">
  <div class="popup">我被渲染到了 body 下</div>
</Teleport>

<!-- disabled=true 时不传送，留在原位（动态切换有用） -->
<Teleport to="body" :disabled="isMobile">
  <div class="popup">移动端就就地渲染</div>
</Teleport>

传送只是改变 DOM 位置，不改变组件逻辑关系：props、事件、插槽依然按原组件树工作，卸载时也会跟着移除。

62.2 多个 Teleport 到同一目标

多个弹窗都 to="body"，它们会按挂载顺序依次成为 body 的子节点，后挂载的在 DOM 中更靠后，默认渲染在上面。但仅靠 DOM 顺序不够——还要靠 z-index。

图 62-1 层叠层级与 z-index（示意）

Element Plus 内部用自增 z-index（每个弹窗打开 +1）避免手写冲突。自己造轮子时，建议维护一个全局计数器，而不是写死 9999。

62.3 Teleport 与 scoped 样式

常见疑问：节点被传到 body 了，组件的 scoped 样式还生效吗？生效。因为 scoped 的原理是给元素加 data-v-xxx 属性、选择器也带属性限定（第 10 章）。Teleport 出去的节点仍然带着它所属组件的 data-v 属性，所以样式照常命中。

<!-- 传送后真实 DOM：class 与 data-v 都在 -->
<div class="popup" data-v-7ba5bd90>我被传送了</div>
<style scoped>.popup[data-v-7ba5bd90]{...}</style>  <!-- 依然命中 -->
例外如果弹窗里嵌套了另一个组件，那个组件内部的元素属于它自己的 scopeId，父组件 scoped 仍改不到——依旧要 :deep()。
<!-- disabled 动态切换：移动端就地渲染，桌面端传送 -->
<Teleport to="body" :disabled="isMobile">
  <div class="popup">自适应渲染位置</div>
</Teleport>

62.4 SSR 注意与常见坑

  • SSR：服务端没有真实 body，Teleport 内容在 SSR 输出中默认不会渲染到传送目标；Nuxt 等框架对 Teleport 有专门处理（如 <ClientOnly> 配合），以官方文档为准。
  • 坑 1to 选择器在挂载时不存在——比如传送目标是某个异步组件里的 div，挂载顺序错了会报警告。
  • 坑 2写死 z-index:9999，通知组件晚于弹窗打开时反被压在下面。
  • 坑 3以为 Teleport 出去样式就丢了，又写了一遍全局样式，造成重复。

62.5 Teleport 与 transition 动画配合

弹窗要淡入淡出，就离不开 transition。Teleport 把节点送到 body 后，transition 的进出场钩子依然生效——但包裹顺序有讲究：transition 必须包在"会被 v-if 切换的那一层"上，而不是包在 Teleport 外层。

<!-- 正确：transition 包 v-if，Teleport 在外层 -->
<Teleport to="body">
  <Transition name="dialog">
    <div v-if="visible" class="dialog">...</div>
  </Transition>
</Teleport>

常见错误是把 <Transition> 套在 <Teleport> 外面——这样 transition 观察的是 Teleport 这个"传送容器"的挂载/卸载，而 Teleport 本身不会随 visible 切换卸载，进出场动画就不会触发。把 transition 放在 Teleport 内部、紧贴 v-if 的元素，动画才正常。

图 62-2 transition 包裹顺序（示意）

Teleport 解决的是「祖先样式/层叠限制」，不是组件通信。传送后组件间的 provide/inject、事件链照常工作。真正要治理的是 z-index：用全局自增计数器分配层级，多个弹窗叠加时后开在上；SSR 下没有真实 body，要配合 ClientOnly，否则注水会 mismatch。

// z-index 自增计数器 + SSR ClientOnly（工程骨架）
let zTop = 2000
function openPopup(el) { el.style.zIndex = ++zTop }
// 模板里：
// <ClientOnly>
//   <Teleport to="body"><div class="popup">...</div></Teleport>
// </ClientOnly>
坑scoped 样式仍生效——传送节点带着原组件 data-v 属性，选择器照常命中，别重复写全局样式。

Teleport 出去的节点仍受原组件 scoped 样式命中——因为它带着 data-v 属性。但如果弹窗里再嵌一个子组件，那个子组件内部的元素属于它自己的 scopeId，父组件 scoped 仍改不到，得用 :deep()。

// scoped 命中边界（工程骨架）
// 弹窗根节点带 data-v-xxx → 父 scoped 命中
// 弹窗内嵌套子组件 → 子组件元素带它自己的 data-v
// 父级要改子组件内部样式：:deep(.inner){...}
要点说明
scoped 命中传送节点带原 data-v，样式照常
嵌套子组件子组件元素属它自己 scopeId
改内部样式:deep() 穿透

多个 Teleport 到同一 body 时，DOM 顺序等于挂载顺序，最终靠 z-index 决胜。自己造层级就维护一个自增计数器，别写死 9999——否则通知晚于弹窗打开会反被压在下面。

// z-index 自增计数器（工程骨架）
let zTop = 2000
function open(el){ el.style.zIndex = ++zTop }
// 关闭后不回收，保证后开的永远在上
要点全局自增 z-index，别写死；Esc 只关最上层。

Teleport 出去的节点仍受 scoped 命中——因为它带着 data-v 属性。但弹窗里再嵌子组件时，子组件内部元素属它自己的 scopeId，父级 scoped 改不到，要 :deep()。

// scoped 边界（工程骨架）
// 弹窗根节点带 data-v → 父 scoped 命中
// 内嵌子组件 → 子元素带它自己 data-v
// 父级改子内部：:deep(.inner){...}
要点传送节点样式不丢，嵌套子组件要穿透。

z-index 治理别写死 9999：维护全局自增计数器，后开的永远在上。Esc 只关最上层遮罩，关闭时回退计数器。SSR 时挂载目标不存在，要等 onMounted。

// z-index 自增（工程骨架）
let zTop = 2000
function open(el){ el.style.zIndex = ++zTop }
要点说明
自增计数后开永远在上
Esc只关最上层
SSR等 onMounted 再传送

Teleport 的 disabled 可动态切回原位：在弹窗内调试时把它设 false，节点留在组件作用域里，CSS 选择器与浏览器元素检查都顺。正式环境再打开传送。

// disabled 调试（工程骨架）
要点说明
to目标 body 或 selector
disabled调试时切回原位
scoped传送节点仍带 data-v

层级治理小结：Teleport 解决挂载位置，z-index 自增解决叠放顺序，scoped 仍命中解决样式丢失。三件事分清，弹窗/通知/抽屉才不互相压。

// 治理清单（工程骨架）
// 1. Teleport to=body
// 2. z-index 自增
// 3. scoped 仍命中；嵌套子组件用 :deep

记住三件事的分工：Teleport 管挂到哪，z-index 自增管谁压谁，scoped 仍命中管样式不丢。混用才是层级混乱的根。

// 分工（工程骨架）
// 挂位置 → Teleport
// 叠顺序 → z-index 自增
// 样式 → data-v 仍命中

层级治理的常见误区是「到处加 z-index」：其实只要统一自增计数器，谁后开谁在上，就不需要为单个弹窗改数字。Esc 监听在最上层关闭时移除，避免内存泄漏。

// 收尾（工程骨架）
// 关闭弹窗 → 移除 Esc 监听
// z-index 计数器不回收

记住：Teleport 解决挂位置，z-index 自增解决叠顺序，scoped 仍命中解决样式不丢。

✓ 本章小结

要点一句话
Teleport改变 DOM 位置，不改变组件逻辑关系；支持 disabled 动态切换
多实例顺序后挂载者 DOM 靠后，但最终靠 z-index 决胜
层级治理用全局自增 z-index，别写死 9999
scoped传送节点仍带 data-v 属性，scoped 样式照常生效
动画配合Transition 紧贴 v-if，别包在 Teleport 外层
