64.1 KeepAlive 基本用法与 max 的 LRU

默认切换组件时旧组件被卸载、再切回要重建。<KeepAlive> 会把切走的组件缓存下来，保留其状态与 DOM。

<!-- 缓存所有直接子组件 -->
<KeepAlive>
  <component :is="currentTab" />
</KeepAlive>

<!-- 只缓存 / 按名字排除 -->
<KeepAlive :include="['UserList']" :max="10">
  <component :is="currentTab" />
</KeepAlive>
选项含义
include只缓存名字匹配的组件（字符串/正则/数组）
exclude排除某些组件不缓存
max最多缓存实例数，超过按 LRU（最近最少使用）淘汰最久未访问的

max 是内存保险丝：不设上限，缓存页面越攒越多，单页应用久开内存持续上涨。

64.2 onActivated / onDeactivated

被缓存的组件再切换时，不会再触发 mounted/unmounted，而是触发一对新钩子：

<script setup>
import { onActivated, onDeactivated } from 'vue'
onActivated(() => {
  // 每次切回这个组件都执行：如刷新列表、恢复滚动位置
})
onDeactivated(() => {
  // 切走时执行：暂停轮询、停掉昂贵动画
})
</script>

<!-- App.vue：router-view 外套 KeepAlive -->
<router-view v-slot="{ Component }">
  <KeepAlive :include="cachedViews" :max="10">
    <component :is="Component" />
  </KeepAlive>
</router-view>
// 约定：在路由 meta 上声明需要缓存的页面
const routes = [
  { path: '/users', component: UserList, meta: { keepAlive: true, name: 'UserList' } }
]
// cachedViews 根据当前路由 meta.keepAlive 动态收集组件名

64.4 缓存策略与内存注意

  • 该缓存：列表页（用户翻页后点详情、返回要留在原页）、多标签切换的固定页；
  • 不该缓存：详情编辑页（每次进入要拿最新数据）、一次性表单；
  • 回退刷新：列表页在 onActivated 里按需静默刷新，而不是整页重建；
  • 内存缓存组件里若 setInterval 轮询，切走时不会自动停！要在 onDeactivated 暂停、onActivated 恢复，否则后台空转耗电。

64.5 缓存命中与失活的内部机制

KeepAlive 为什么能"记住"页面？本质是一个按 key 存取的虚拟 DOM 缓存表：组件失活时把它的 vnode 摘出渲染树、塞进缓存；再次进入时先查表，命中就复用这棵被缓存的树、只触发 onActivated，而不是重新挂载。

用户离开 A 页（<router-view> 切换）
  ├─ A 的 vnode 不再渲染 → 移入 cache(key = A)
  └─ 触发 onDeactivated（DOM 保留在内存，从页面"隐藏"）

用户再回到 A 页
  ├─ 查 cache.has(A) → 命中
  ├─ 复用缓存的 vnode 树（不重新创建组件实例）
  └─ 触发 onActivated（等价"重新可见"）

缓存命中 = 复用旧 vnode 实例 + 触发 onActivated；缓存未命中 = 正常新建组件实例。

理解这套机制后，两个行为就有了根：一是组件实例不会随切走销毁，所以 data、表单输入、滚动位置都保留；二是 max 淘汰时，超出容量的旧实例会被真正卸载（触发 onUnmounted），缓存的状态随之丢失——这正是"内存保险丝"的含义。

图 64-1 缓存命中与 LRU 淘汰流程（示意）

缓存策略的核心是「哪些页该留」：列表页翻页后点详情、返回要留在原页，所以缓存；详情编辑页每次进入要拿最新数据，所以不缓存。路由级缓存用 meta.keepAlive 标记，组件内 onActivated 里做静默刷新，而不是整页重建。

// 路由级缓存白名单（工程骨架）
const router = createRouter({
  routes: [
    { path: '/list', component: List, meta: { keepAlive: true } },
    { path: '/detail', component: Detail, meta: { keepAlive: false } }
  ]
})
// App.vue: <router-view v-slot="{ Component}">
//   <KeepAlive :include="cachedViews"><component :is="Component"/></KeepAlive>
// </router-view>
内存被缓存组件里 setInterval 切走不会自动停——onDeactivated 暂停、onActivated 恢复。

缓存组件里最隐蔽的坑是「定时器空转」：切走页面后 setInterval 不会自动停，后台一直跑耗电。要在 onDeactivated 暂停、onActivated 恢复，把轮询挂在可见性上。

// 缓存组件定时器治理（工程骨架）
let timer
onActivated(()=>{ timer = setInterval(poll, 5000) })
onDeactivated(()=>{ clearInterval(timer) })  // 切走即停
要点说明
该缓存列表页翻页后返回留原页
不缓存详情编辑页每次拿最新
定时器deactivated 暂停、activated 恢复

缓存命中率取决于「白名单」：列表页该留、详情页不该留。用 meta.keepAlive 标记，组件内 onActivated 里静默刷新，而不是整页重建——否则缓存形同虚设。

// 路由白名单（工程骨架）
routes: [
  { path:'/list', meta:{ keepAlive:true } },
  { path:'/detail', meta:{ keepAlive:false } }
]
// KeepAlive :include='cachedViews'
要点列表缓存留现场，详情不缓存拿最新。

onActivated/onDeactivated 替代 mounted/unmounted 管缓存组件的可见性。轮询在 deactivated 暂停、activated 恢复，否则切走后后台空转耗电。

// 定时器治理（工程骨架）
let timer
onActivated(()=>{ timer=setInterval(poll,5000) })
onDeactivated(()=>{ clearInterval(timer) })
要点切走即停，回来再启。

include/exclude 按组件 name 匹配，max 用 LRU 淘汰最久未用。缓存别贪多——每页组件实例常驻内存，多了反而吃内存。
