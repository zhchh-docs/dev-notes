49.1 全局前置守卫 beforeEach

这是最常用的守卫：每次任何跳转都先过它。适合做登录拦截、全局鉴权。

// src/router/index.js
router.beforeEach((to, from) => {
  // to：即将前往的路由；from：当前离开的路由
  const isLogin = !!localStorage.getItem('token')

  // 需要登录但没登录 → 重定向到登录页，并记下要去哪，登录后好跳回
  if (to.meta.requiresAuth && !isLogin) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  // 返回 true / undefined 表示放行；返回 false 取消本次导航
  return true
})

vue-router 4 推荐用返回值替代 next：return false 取消、return '/login' 重定向、return true 放行。少一个参数，少一种"忘了调用 next"的 bug。

提醒如果你在老代码里看到 beforeEach((to, from, next) => { next() })，那是 v3 风格。v4 仍兼容，但同一守卫里不要混用返回值和 next，否则可能导航不结束。

49.2 beforeResolve 与 afterEach

// 全局解析守卫：所有组件内守卫、异步组件都解析完之后、确认导航前触发
router.beforeResolve(async to => {
  // 适合在这里确保"进入页面前数据一定就绪"
})

// 全局后置钩子：导航已经完成，不能取消
router.afterEach((to, from) => {
  // 最典型：设置页面标题（下一章详讲）、埋点上报
  document.title = to.meta.title || '默认标题'
})
守卫能否取消导航典型用途
beforeEach能登录拦截、全局鉴权
beforeResolve能导航最终确认前的最后校验（如权限弹窗已结束）
afterEach不能标题、埋点、滚动、关闭 loading

49.3 路由独享 beforeEnter

只在进入某一条路由时触发，写在路由记录上：

const routes = [
  {
    path: '/admin',
    component: Admin,
    beforeEnter: (to, from) => {
      // 只对 /admin 这一条生效，不必堆在全局 beforeEach 里
      if (!isAdmin()) return { name: 'forbidden' }
    }
  }
]
beforeEnter 只在进入路由时触发，不会在 params/query 变化（如 /user/1→/user/2）时再次触发——那种场景用 onBeforeRouteUpdate。

49.4 组件内守卫

组件自己也能"说话"：离开前问一句"表单还没保存，确定走吗？"。组合式 API 用两个钩子：

<script setup>
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router'

// 离开当前组件前
onBeforeRouteLeave((to, from) => {
  if (formDirty.value) {
    const ok = window.confirm('有未保存的修改，确定离开？')
    if (!ok) return false   // 取消离开
  }
})

// 同组件复用时（参数变了）
onBeforeRouteUpdate((to, from) => {
  // 等价于 watch(() => route.params.id)，但语义更明确
})
</script>

49.6 守卫里的异步、重定向与错误

router.beforeEach(async (to) => {
  const store = useUserStore()
  // 异步守卫：返回一个 Promise，路由会等它 resolve 后再继续
  if (to.meta.requiresAuth && !store.isLogin) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  // 刷新后若 token 还在但 store 空了，先拉用户信息
  if (store.token && !store.user) {
    try {
      await store.fetchUser()
    } catch (e) {
      store.logout()
      return { name: 'login' }
    }
  }
})
  • 取消：return false，URL 回退到 from；
  • 重定向：return '/login' 或一个路由对象，导航会中断并转向新目标；
  • 异步：守卫是 async 时路由自动等待，期间可用全局 loading；
  • 报错：守卫里抛错会让导航失败，记得 try/catch 并给出兜底跳转。
在 beforeEach 里死循环重定向是经典事故：守卫把 /login 也判成需要登录，于是又跳 login、又判、又跳……务必用 to.meta.public 或 to.name === 'login' 把登录页本身排除。

49.7 本章常见坑

  • 坑 1守卫里漏调 next 或漏 return：导航卡住不动，页面空白。v4 用返回值可减少此类问题。
  • 坑 2登录页自身也被 requiresAuth 拦截：死循环，登录页要放行。
  • 坑 3在 afterEach 里尝试取消导航：它已经晚了，只能做副作用。
  • 坑 4beforeEnter 指望在参数变化时触发：它只在初次进入路由时跑。
  • 坑 5async 守卫里没 catch：接口失败导致整个导航挂起。

✓ 本章小结

要点一句话
beforeEach全局前置、可取消，做登录鉴权
beforeResolve导航确认前最后一道，确保数据就绪
afterEach导航完成后，不可取消，做标题/埋点
beforeEnter路由独享，只对单条路由生效
组件守卫onBeforeRouteLeave 离开确认、onBeforeRouteUpdate 参数变化
返回值语义true 放行 / false 取消 / 新地址重定向

✎ 本章习题

A 基础写一个 beforeEach：目标路由 meta.requiresAuth 为真且本地无 token 时，重定向到登录页并带上 redirect 查询参数。
B 进阶在表单页加 onBeforeRouteLeave：表单有未保存修改时弹窗确认，取消则留在原页。
C 挑战实现"刷新后守卫里先拉用户信息"：无 store 但有 token 时 await fetchUser()，失败则登出并跳登录；要求登录页本身不被拦截、不产生重定向死循环。

参考答案见附录 C。下一章讲路由元信息：用 meta 统一管理页面标题、权限标记。
