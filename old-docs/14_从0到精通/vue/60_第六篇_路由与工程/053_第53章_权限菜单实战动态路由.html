53.1 登录态与鉴权流程

图 53-1 登录与动态路由加载的整体流程（示意）

// 登录成功后
async function onLogin(form) {
  const { token } = await api.login(form)
  localStorage.setItem('token', token)
  await userStore.fetchUser()          // 拉用户信息与权限码
  await permissionStore.generateRoutes() // 根据权限过滤出可访问路由
  router.replace('/')                   // 跳转，此时动态路由已注册
}

53.2 动态路由：addRoute

静态路由只放登录页、404 等公共部分；登录后根据权限把业务路由动态加进去：

// permission store
import router from '@/router'
import { asyncRoutes } from '@/router/async-routes'  // 所有业务路由（待过滤）

const addedRoutes = ref([])

function generateRoutes() {
  // 根据当前用户角色过滤出他能看的路由
  const accessible = filterAsyncRoutes(asyncRoutes, userStore.roles)
  accessible.forEach(r => router.addRoute(r))
  addedRoutes.value = accessible
}

function resetRoutes() {
  // 登出时移除动态加的路由
  addedRoutes.value.forEach(r => router.removeRoute(r.name))
  addedRoutes.value = []
}
API作用
router.addRoute(route)运行时动态注册一条路由
router.removeRoute(name)按名移除之前动态加的路由（登出时清理）
router.hasRoute(name)判断某路由是否已注册
提醒addRoute 是即时生效但不触发导航。加完后要 router.replace(currentPath) 重新进一次目标页，否则当前地址可能匹配不到新加的路由而落到 404。

53.3 菜单与路由表映射

侧边菜单不必单独维护一份，直接从路由表（meta）渲染：

<!-- Sidebar.vue -->
<template>
  <router-link
    v-for="r in menus" :key="r.path"
    :to="r.path"
  >
    {{ r.meta.title }}
  </router-link>
</template>

<script setup>
import { computed } from 'vue'
import { usePermissionStore } from '@/stores/permission'
const permissionStore = usePermissionStore()
// 只显示 meta.visible !== false 的路由
const menus = computed(() =>
  permissionStore.addedRoutes.filter(r => r.meta && r.meta.visible !== false)
)
</script>

菜单即路由表：路由的 meta.title / icon / visible 就是菜单的数据源。不要再维护第二份菜单配置，否则两处必然不同步。

53.4 角色 → 权限码 → 路由过滤

// 每条业务路由在 meta 里声明所需角色或权限码
{
  path: '/admin',
  component: AdminLayout,
  meta: { roles: ['admin'] },     // 仅管理员
  children: [
    { path: 'finance', component: Finance, meta: { title: '财务', roles: ['admin', 'finance'] } }
  ]
}

// 过滤：路由声明的角色与用户角色有交集才保留
function filterAsyncRoutes(routes, userRoles) {
  return routes.filter(route => {
    if (route.meta && route.meta.roles) {
      const ok = route.meta.roles.some(role => userRoles.includes(role))
      if (!ok) return false
    }
    if (route.children) {
      route.children = filterAsyncRoutes(route.children, userRoles)
    }
    return true
  })
}

53.5 刷新后路由恢复

动态路由存在内存里，一刷新就没了。刷新后守卫要检测"有 token 但路由是空的"，重新拉权限并 addRoute：

router.beforeEach(async (to) => {
  const hasToken = !!localStorage.getItem('token')
  if (!hasToken && to.meta.requiresAuth) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  // 已登录但动态路由还没加（刷新场景）
  if (hasToken && permissionStore.addedRoutes.length === 0) {
    await userStore.fetchUser()
    await permissionStore.generateRoutes()
    // addRoute 后重新导向目标，确保命中新路由
    return to.fullPath
  }
})
刷新丢路由是动态路由最容易漏的一环。只在登录时加路由、不在守卫里补，结果就是登录后正常、一刷新就 404。

53.6 按钮级权限

路由权限管"能不能进页面"，页面内按钮还要再细控。自定义指令 v-permission：

// directives/permission.js
export const permission = {
  mounted(el, binding) {
    const userPermissions = userStore.value.perms  // 如 ['user:add','user:delete']
    const need = binding.value                       // 如 'user:delete'
    if (!userPermissions.includes(need)) {
      el.parentNode && el.parentNode.removeChild(el)  // 无权限直接移除按钮
    }
  }
}
<!-- 使用 -->
<el-button v-permission="'user:delete'">删除用户</el-button>

<!-- 或简单用 v-if（不移除 DOM，只是隐藏） -->
<el-button v-if="hasPerm('user:delete')">删除用户</el-button>
前端权限只是体验层：隐藏按钮能减少误操作，但真正的安全必须由后端接口校验。前端绕过权限照样能调接口，别把它当安全边界。

53.7 本章常见坑

  • 坑 1addRoute 后不重新导航：当前页落到 404，要 replace 一次。
  • 坑 2刷新后动态路由丢失：守卫里要补一次 generateRoutes。
  • 坑 3菜单与路由两份配置：改一处忘改另一处，必然不同步。
  • 坑 4登出不移除动态路由：换账号登录，上一个人的路由还在。
  • 坑 5把前端按钮权限当安全：后端必须二次校验。

✎ 本章习题

A 基础把业务路由分成"静态（登录/404）"与"动态（需权限）"两组，写一个 generateRoutes() 用 addRoute 把动态组加进路由。
B 进阶在 beforeEach 里实现刷新恢复：有 token 但动态路由为空时，重新拉用户权限并 addRoute，再 return to.fullPath。
