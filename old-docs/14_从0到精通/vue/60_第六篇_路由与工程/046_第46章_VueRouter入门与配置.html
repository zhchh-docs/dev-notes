46.1 为什么需要路由

单页应用（SPA）只有一个 index.html。没有路由时，"页面切换"只能靠自己写 v-if 切组件——浏览器地址栏不变、不能前进后退、不能直接分享某个页面链接。Vue Router 就是把 URL 映射到组件的官方路由器。

它替你做的事：

  • 根据当前 URL 决定渲染哪个组件（<router-view> 出口）；
  • 拦截链接点击，不刷新页面地切换视图；
  • 同步浏览器历史栈，让前进/后退按钮可用；
  • 在切换前后执行钩子（导航守卫，第 49 章）。

路由的本质是"URL 即状态"：把当前页面的位置编码进地址栏，可前进、可后退、可收藏、可分享。

安装与接入

npm install vue-router@4
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  { path: '/', component: () => import('../views/Home.vue') },
  { path: '/about', component: () => import('../views/About.vue') }
]

const router = createRouter({
  history: createWebHistory(),   // HTML5 history 模式
  routes
})

export default router
// src/main.js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

const app = createApp(App)
app.use(router)     // 必须在 mount 之前 use
app.mount('#app')
提醒app.use(router) 必须在 app.mount('#app') 之前调用。否则首次渲染时 <router-view> 还没拿到路由实例，会渲染空白或报错。

46.2 两个核心组件：router-view 与 router-link

<!-- App.vue -->
<template>
  <nav>
    <router-link to="/">首页</router-link>
    <router-link to="/about">关于</router-link>
  </nav>

  <!-- 当前路由匹配到的组件渲染在这里 -->
  <router-view />
</template>

<router-link> 编译后是一个 <a>，但它阻止默认跳转，改为交给路由器在前端切换。匹配当前地址的链接会自动带上 router-link-active 与 router-link-exact-active 两个类，可据此高亮：

.router-link-active { color: #2d6a3f; font-weight: 600; }
.router-link-exact-active { border-bottom: 2px solid #2d6a3f; }
类名含义
router-link-active链接路径是当前地址的前缀（如 /about 命中 /about/detail）
router-link-exact-active链接路径与当前地址完全相等，用于精确高亮
自定义激活类：可在 createRouter 里设 linkActiveClass / linkExactActiveClass，或用 <router-link active-class="..."> 单独指定。

46.3 命名路由、redirect、alias 与 404

const routes = [
  // 命名路由：以后改路径不用改到处的 to
  { path: '/home', name: 'home', component: Home },

  // redirect：访问 / 时重定向到 /home
  { path: '/', redirect: '/home' },

  // alias：/about 与 /about-us 渲染同一个组件（区别于 redirect，地址不变）
  { path: '/about', component: About, alias: '/about-us' },

  // 404：通配所有未匹配路径（Vue Router 4 用自定义正则参数）
  { path: '/:pathMatch(.*)*', name: 'not-found', component: NotFound }
]

用命名路由跳转时写法更稳：

<router-link :to="{ name: 'home' }">首页</router-link>
能力行为典型用途
name给路由起逻辑名，跳转按名引用路径可能调整、需传参时
redirect地址栏真的跳转到新路径旧地址迁移、默认页
alias多入口共用同一组件，URL 保持用户输入短链、SEO 多入口
:pathMatch(.*)*匹配任意未命中路径404 页面
Vue Router 3 时代的 path: '*' 通配在 v4 已被移除，必须写 /:pathMatch(.*)*。网上老教程的 path: '*' 现在会报错。

46.4 三种路由模式对比

图 46-1 三种路由模式的地址栏与适用场景（示意）

import { createRouter, createWebHistory, createWebHashHistory, createMemoryHistory } from 'vue-router'

// history：地址栏 /about，生产需 Nginx 配 try_files $uri /index.html
createRouter({ history: createWebHistory(), routes })
// hash：地址栏 /#/about，天然无需服务端配置
createRouter({ history: createWebHashHistory(), routes })
// memory：不碰地址栏，SSR 与单元测试用
createRouter({ history: createMemoryHistory(), routes })
模式地址栏服务端要求典型场景
createWebHistory干净路径需 SPA 回退到 index.html绝大多数正式 Web 项目
createWebHashHistory带 #无静态托管、老服务器无 rewrite 权限
createMemoryHistory不变无SSR、测试、嵌入式容器

46.5 main.js 里 router 与 pinia 的接入次序

// main.js —— 推荐次序
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import router from './router'

const app = createApp(App)
app.use(createPinia())   // ① 先装 pinia
app.use(router)          // ② 再装 router
app.mount('#app')        // ③ 最后挂载

次序的原因：导航守卫里常常要读 store（如登录态、用户权限，第 49、53 章会写）。如果 router 先 use、而守卫触发时 pinia 还没装好，守卫里 useUserStore() 会拿不到实例而报错。先 pinia 后 router，守卫执行时两个插件都已就绪。

插件次序口诀：被别人依赖的先装。pinia 被 router 的守卫依赖，所以 pinia 在 router 之前。

46.6 本章常见坑

  • 坑 1用 path: '*' 配 404：v4 已移除，改 /:pathMatch(.*)*。
  • 坑 2history 模式刷新 404：线上 Nginx/静态服务器没配回退，刷新 /about 就 404——这是服务端配置问题，不是路由 bug。
  • 坑 3把 app.use(router) 写在 mount 之后：首屏 router-view 渲染异常。
  • 坑 4redirect 与 alias 混用：redirect 会改地址栏，alias 不改；分享链接行为不同。
  • 坑 5以为 router-link-active 是精确匹配：它是前缀匹配，高亮父菜单时对，但高亮同级菜单时要用 exact-active。

✓ 本章小结

要点一句话
路由作用URL 与组件映射，SPA 内无刷新切换并维护历史栈
接入createRouter + createWebHistory，app.use(router) 先于 mount
两个组件router-view 出口、router-link 导航（active/exact-active 高亮）
路由表能力name / redirect / alias / :pathMatch(.*)* 兜底
三种模式history（干净需回退）/ hash（无需配置）/ memory（SSR 测试）
插件次序pinia 先于 router，守卫里才能安全读 store
