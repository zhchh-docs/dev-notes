48.1 children：路由也能嵌套

后台系统里，所有页面都套在"侧边栏 + 顶栏"的壳里。把壳抽成布局组件，子路由在它内部渲染：

const routes = [
  {
    path: '/admin',
    component: AdminLayout,          // 布局：含侧边栏 + 顶栏
    children: [
      // /admin  默认重定向到 /admin/dashboard
      { path: '', redirect: '/admin/dashboard' },
      { path: 'dashboard', component: Dashboard },   // 实际是 /admin/dashboard
      { path: 'users', component: UserList },
      { path: 'users/:id', component: UserDetail }
    ]
  }
]
<!-- AdminLayout.vue -->
<template>
  <div class="layout">
    <aside>侧边栏菜单</aside>
    <main>
      <!-- 子路由组件渲染在这里：又一个 router-view -->
      <router-view />
    </main>
  </div>
</template>

嵌套路由 = 组件树的嵌套与 URL 的嵌套一一对应。URL 有几层，就有几层 <router-view> 出口。

48.2 布局组件模式：Outlet 类比

图 48-1 嵌套路由的组件树：每一层 router-view 负责一层（示意）

这套"布局壳 + 内容出口"的模式，在 React Router 里叫 <Outlet/>，概念完全一致。布局组件本身只在父路由匹配时渲染一次，切换子路由不会重渲染整个布局，侧边栏状态得以保留。

写法行为
子路由 path: 'users'（无前导斜杠）拼在父路径后：/admin/users，推荐写法
子路由 path: '/users'（带斜杠）变成根路径 /users，脱离父布局，慎用
父路由有 children 但无 component合法，仅作路径分组（不渲染布局壳）

48.3 命名视图：同一层渲染多个组件

有些布局同一层要并排几个独立区块（如主内容 + 右侧边栏）。默认 <router-view> 只能渲染一个，命名视图解决：

const routes = [
  {
    path: '/settings',
    components: {
      default: SettingsMain,   // 默认出口
      aside: SettingsAside     // 名为 aside 的出口
    }
  }
]
<template>
  <router-view />                 <!-- 渲染 default: SettingsMain -->
  <router-view name="aside" />     <!-- 渲染 aside: SettingsAside -->
</template>
注意区别：普通路由用 component（单数），命名视图路由用 components（复数对象）。

48.4 面包屑与空路径重定向

面包屑通常由当前匹配的路由记录链推出来。route.matched 是一个数组，按嵌套顺序装着每一层匹配到的路由记录：

<!-- Breadcrumb.vue：/admin/users/7 -> /admin /admin/users /admin/users/7 -->
<template>
  <nav>
    <span v-for="(record, i) in matched" :key="i">
      {{ record.meta.title }} <template v-if="i < matched.length - 1"> / </template>
    </span>
  </nav>
</template>

<script setup>
import { useRoute } from 'vue-router'
const route = useRoute()
const matched = route.matched.filter(r => r.meta && r.meta.title)
</script>

空路径重定向让"进父路径就落进第一个子页"：

children: [
  { path: '', component: Dashboard },          // /admin 直接渲染仪表盘，不重定向
  // 或
  { path: '', redirect: '/admin/dashboard' }  // /admin 跳到 /admin/dashboard
]

写嵌套时最常漏的一件事：忘了给空路径配默认子路由。结果访问 /admin 时布局壳出来了，内容区却是空白——因为没有任何子路由匹配空路径。

48.5 嵌套路由的完整例子

把前面的点串成一个可对照的完整路由表，注意每一层出口：

const routes = [
  { path: '/login', component: Login },          // 无布局，直接顶层渲染
  {
    path: '/',
    component: SiteLayout,                        // 第一层：整站布局（导航栏）
    children: [
      { path: '', component: Home },              // /
      {
        path: 'docs',
        component: DocsLayout,                    // 第二层：文档布局（侧目录）
        children: [
          { path: '', redirect: '/docs/intro' },
          { path: 'intro', component: DocIntro },
          { path: 'guide', component: DocGuide }
        ]
      }
    ]
  },
  { path: '/:pathMatch(.*)*', component: NotFound }
]

此时访问 /docs/guide，组件树是 App → SiteLayout → DocsLayout → DocGuide，三层 router-view 依次填充。SiteLayout 在所有页面都常驻，切 docs 子页时只有最内层出口变化。

什么时候不该嵌套：两个页面没有公共外壳、只是路径形似，就别硬塞 children。嵌套的前提是"父子页面共享布局/上下文"，否则平铺路由更清晰。

48.6 本章常见坑

  • 坑 1子路由 path 误加前导 /：路径脱离父级，布局壳不生效。
  • 坑 2父路由忘了放 <router-view />：子组件根本没出口可渲染。
  • 坑 3空路径无默认子路由：进父路径内容区空白。
  • 坑 4把 components 写成 component：命名视图不生效，控制台报找不到出口。
  • 坑 5嵌套层级与 router-view 层数对不上：URL 三层却只放了两层出口，最深层组件渲染不出来。

✓ 本章小结

要点一句话
children子路由嵌套在父路由内，路径不带前导斜杠
布局模式父路由=布局壳，每下钻一层就多一个 router-view
命名视图components:{default, aside} 同层多出口
面包屑由 route.matched 按层级推出
空路径父路径必须给默认子路由或重定向，否则内容空白

B 进阶给上面的布局加一个面包屑组件，从 route.matched 读取各层 meta.title 渲染，访问 /dashboard 时应显示两层路径。
