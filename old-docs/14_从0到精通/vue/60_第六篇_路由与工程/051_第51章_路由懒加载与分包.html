51.1 () => import：路由级代码分割

如果路由表直接 import Home from '../views/Home.vue'，所有页面都会被打进首屏 bundle，用户一进门就下载全站代码。改成动态 import：

const routes = [
  // 静态导入：进首屏 bundle
  // { path: '/', component: Home },

  // 动态导入：该组件单独打成一个 chunk，访问 / 时才下载
  { path: '/', component: () => import('../views/Home.vue') },
  { path: '/about', component: () => import('../views/About.vue') },
  { path: '/admin', component: () => import('../views/Admin.vue') }
]

() => import() 不只是"异步加载组件"，它同时是一个构建信号：打包器看到它就会把该模块切到独立 chunk。

51.2 命名 chunk：webpack 与 Vite 的差异

默认 chunk 名是哈希数字，不好定位。webpack 时代用魔法注释命名：

// webpack：通过魔法注释命名 chunk（打包后文件名带这个名字）
component: () => import(/* webpackChunkName: "about" */ '../views/About.vue')
// Vite（Rollup）：不识别 webpackChunkName。
// Vite 用 /* @vite-ignore */ 之类注解，但命名 chunk 主要靠下面的 manualChunks
// 或依赖文件路径自动分包；魔法注释在 Vite 里无效
能力webpackVite（Rollup）
动态 import 分包支持支持（自动）
命名 chunkwebpackChunkName 注释该注释无效，靠 manualChunks/路径约定
公共依赖提取SplitChunksbuild.rollupOptions.output.manualChunks
提醒网上大量教程教你写 webpackChunkName。如果你用的是 Vite（本书基线），那个注释不生效，别误以为它在起作用。

51.3 Vite manualChunks：手动拆分依赖

把 Vue、路由、UI 库这些不常变的第三方依赖单独打成 vendor chunk，利用浏览器长期缓存：

// vite.config.js
import { defineConfig } from 'vite'

export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'vue-vendor': ['vue', 'vue-router', 'pinia'],
          'element-plus': ['element-plus']
        }
      }
    }
  }
})
优先级与权衡：manualChunks 是手动覆盖自动分包。拆太细会产生过多小请求，拆太粗又失去缓存意义。一般只把"体积大、更新频率低"的库单独拆，业务代码仍交给自动分包。

51.4 加载状态与错误处理

懒加载组件在弱网下要花时间下载，期间 router-view 是空的。可以用 <Suspense> 包一层显示 loading（第 63 章详讲 Suspense）：

<router-view v-slot="{ Component }">
  <Suspense>
    <component :is="Component" />
    <template #fallback>
      <div class="loading">页面加载中…</div>
    </template>
  </Suspense>
</router-view>

下载失败（如发版后旧 chunk 被删）要兜底。动态 import 可加 catch：

const lazyLoad = (loader) =>
  loader().catch((err) => {
    // 线上发版后旧 hash chunk 已不存在 → 提示刷新
    window.location.reload()
    throw err
  })

// 路由里：component: () => lazyLoad(() => import('../views/Report.vue'))

51.5 预取与 keep-alive 的配合

  • 预取（prefetch）：Vite 在构建时会为入口动态 import 生成 <link rel="modulepreload">，浏览器空闲时提前下载可能要去的页面。可按需关闭，不必手动写。
  • 与 keep-alive：懒加载组件被 <keep-alive> 缓存后，切走再回来不会重新下载/执行，但首次进入仍需加载。
  • 与动态组件：<component :is="() => import(...)"> 同理分包，但要配合 Suspense，否则切换瞬间空白。
别把所有路由都懒加载。首屏首页（如登录页、仪表盘）用静态 import 更快——它本来就要立刻用，懒加载反而多一次异步往返。

51.6 如何分析打包产物体积

光凭感觉调分包不可靠，要用工具看清楚每个 chunk 里到底装了什么：

# 构建时生成分析报告（rollup-plugin-visualizer）
npm install -D rollup-plugin-visualizer

# vite.config.js 里加入后再 build，会产出 stats.html 可视化各模块占比
# import { visualizer } from 'rollup-plugin-visualizer'
# plugins: [vue(), visualizer({ open: true, gzipSize: true })]

npm run build

看报告时关注三件事：①首屏主包是否还含没用到的大依赖；②路由 chunk 是否拆得均匀；③有没有某个第三方库意外被打了两份。

现象可能原因与对策
主包异常大首屏直接 import 了重组件；改动态 import
单个 chunk 过大某页面依赖了巨大库；manualChunks 把库拆出
重复模块出现两次版本不一致或双向依赖；对齐依赖版本

51.7 本章常见坑

  • 坑 1在 Vite 里迷信 webpackChunkName：该注释无效，chunk 名由构建决定。
  • 坑 2所有路由都懒加载：首屏页面也被异步化，反而更慢。
  • 坑 3发版后用户停在旧页面，点进去报 chunk 404：旧 hash 文件已删。需 catch 后自动 reload。
  • 坑 4manualChunks 拆得过碎：请求数暴涨，首屏更慢。
  • 坑 5懒加载路由不包 Suspense：弱网下页面空白、无任何反馈。
