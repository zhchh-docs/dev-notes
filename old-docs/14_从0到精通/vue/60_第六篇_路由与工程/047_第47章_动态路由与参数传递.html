47.1 动态段：一条路由匹配一族 URL

详情页不可能为每个 id 写一条路由。用动态段 :xxx 占位：

const routes = [
  // /user/1、/user/42 都命中这条
  { path: '/user/:id', component: UserDetail },
  // 多段参数：/order/2026/main/88
  { path: '/order/:year/main/:mainId', component: OrderDetail }
]

组件内用 useRoute() 读取（组合式 API 没有 this，不能用 this.$route）：

<script setup>
import { useRoute } from 'vue-router'
const route = useRoute()
// route.params.id 即 URL 里的 :id；多段则都在 route.params 里
console.log(route.params.id, route.params.year)
</script>
提醒动态段取出来的永远是字符串。/user/99 里 route.params.id 是 "99" 不是数字，需要时自己 Number(...)。

47.2 params 与 query：参数放哪

两者都能传参，但语义不同：

// /user/12?tab=post&page=2
//        └─params─┘  └───────query───────┘
route.params.id   // "12"   —— 路由结构的一部分
route.query.tab   // "post" —— 可选筛选/分页
route.query.page   // "2"
维度params（动态段）query（?a=b）
URL 形态/user/12/user/12?tab=post
语义资源的身份（必选）视图状态（可选）
路由表路径里必须声明 :id无需声明，任意带
典型内容id、slug分页、tab、搜索词、回跳地址
刷新保留保留（在路径里）保留（在路径里）

经验法则："定位一个资源"用 params，"描述怎么看这个资源"用 query。

47.3 参数变化不刷新组件：watch 它

经典坑：从 /user/1 跳到 /user/2，它们复用同一个 UserDetail 组件实例。Vue 为了性能会复用组件，不会重新 setup，于是 route.params.id 变了但页面数据没更新。

<script setup>
import { useRoute } from 'vue-router'
import { watch } from 'vue'
const route = useRoute()

// 错：只在 setup 跑一次，/user/1 -> /user/2 不会重新请求
// const userId = route.params.id

// 对：监听参数变化，变化时重新拉数据
watch(
  () => route.params.id,
  (newId, oldId) => {
    fetchUser(newId)
  },
  { immediate: true }   // 首次进入也执行一次
)
</script>
另一种解法：在 <router-view :key="$route.fullPath"> 上按完整路径强制重建组件。简单但会丢弃组件内状态（滚动位置、表单输入），能用 watch 就别靠 key。

47.4 props: true：把参数变成 props

组件里直接读 route.params 会让组件和路由耦合，换个地方复用就要改代码。路由提供 props: true，把动态段作为 props 传进组件：

// 路由表
{ path: '/user/:id', component: UserDetail, props: true }
// 也可传函数，把 query 一起映射成 props
{
  path: '/user/:id',
  component: UserDetail,
  props: route => ({ id: route.params.id, tab: route.query.tab })
}
<!-- UserDetail.vue：不再依赖 useRoute，组件更纯、更好测 -->
<script setup>
defineProps({ id: [String, Number], tab: { type: String, default: 'post' } })
</script>

<template>
  <h3>用户 {{ id }} · 标签页 {{ tab }}</h3>
</template>

props: true 让页面组件"只关心拿到什么参数"，而不关心"参数从 URL 哪一段来"——这是组件可复用性的关键一步。

47.5 编程式导航

除了 <router-link>，代码里也要跳转（登录成功后、提交表单后）。用 useRouter()：

<script setup>
import { useRouter } from 'vue-router'
const router = useRouter()

function goHome() {
  router.push('/')                       // 字符串
  router.push({ path: '/about' })        // 对象
  router.push({ name: 'user', params: { id: 7 } })   // 命名路由 + params
  router.push({ path: '/search', query: { q: 'vue' } }) // 带 query

  router.replace('/login')   // 不留历史记录（登录后别让用户回退到登录页）
  router.back()              // 等同浏览器后退
  router.forward()
</script>
方法历史栈典型用途
router.push新增一条历史正常的菜单/链接跳转
router.replace替换当前历史登录成功、表单提交成功后
router.back / forward栈内移动"返回上一页"按钮
提醒命名路由配 params 时不能同时用 path：router.push({ path:'/user', params:{id:7} }) 里 params 会被忽略。要么 path + query，要么 name + params。

47.6 重复导航报错：NavigationFailure

vue-router@4 里，重复导航到同一个地址（比如连点两次）会返回一个被拒绝的 Promise。这不是真正的错误，但未捕获时控制台会冒 Uncaught (in promise)。

const router = useRouter()

// 推荐：catch 掉重复导航，其他导航失败才真正处理
router.push('/home').catch(err => {
  // vue-router 4 提供 isNavigationFailure 区分失败类型
})

// 或全局统一：push 都包一层
function safePush(to) {
  return router.push(to).catch(() => {})
}
版本差异：vue-router 3 里重复导航是静默无操作；v4 改为返回 Promise rejection。所有升级到 v4 的老项目，控制台突然一片红，多半就是它。

47.7 本章常见坑

  • 坑 1同组件切 id 页面不刷新：没 watch route.params.id，数据停在旧 id。
  • 坑 2params 拿到字符串还拿去做数字比较：Number() 一下。
  • 坑 3path 和 params 混用：params 被静默丢弃，id 变成 undefined。
  • 坑 4登录后用 push 而非 replace：用户点后退又回到登录页。
  • 坑 5把 route 当普通对象解构：const { id } = route.params 会丢失响应性，要解构也应在 watch/computed 里做。
