50.1 meta：路由记录上的自定义字段

路由记录除了 path/component，还能挂任意 meta 对象。它不影响 URL，只给你的代码读：

const routes = [
  {
    path: '/user',
    component: User,
    meta: {
      title: '用户管理',
      requiresAuth: true,
      icon: 'user',
      keepAlive: true
    }
  }
]
<script setup>
import { useRoute } from 'vue-router'
const route = useRoute()
console.log(route.meta.title)   // '用户管理'
</script>

嵌套时 meta 的继承：用 matched 合并

嵌套路由里，route.meta 默认合并了所有层级路由记录的 meta（子覆盖父的同名字段）。如果你只想取当前这一层，用 route.matched[i].meta：

const routes = [
  {
    path: '/admin',
    component: AdminLayout,
    meta: { requiresAuth: true },          // 父级：需要登录
    children: [
      { path: 'users', component: UserList, meta: { title: '用户管理' } }
      // 进入 /admin/users 时：
      // route.meta === { requiresAuth: true, title: '用户管理' }（已合并）
    ]
  }
]

route.meta 是整条匹配链的合并结果：父路由声明的 requiresAuth，子路由天然继承——这正是"登录区里所有页面都要登录"的优雅实现。

50.2 统一页面标题方案

每个页面标签页的标题不该各组件自己改。在全局后置守卫里统一设：

const appName = '后台管理系统'

router.afterEach((to) => {
  // meta.title 可缺省；拼上站点名
  document.title = to.meta.title
    ? `${to.meta.title} · ${appName}`
    : appName
})

更灵活的做法是把标题做成模板/函数，处理"详情页标题带用户名"这类动态需求：

router.afterEach((to) => {
  const base = to.meta.title
  // 若 meta.title 是函数，调用它（可结合 store 里的当前数据）
  document.title = (typeof base === 'function' ? base(to) : base) || appName
})
为什么放 afterEach 而不是 beforeEach：标题要在导航确认成功后再改。如果放前置守卫里跳来跳去，标题会跟着失败的导航乱跳。

50.3 meta 约定字段表

团队应在路由表上方定一份 meta 约定文档。常见约定：

字段含义谁来消费
title页面标题afterEach、面包屑、菜单
requiresAuth是否需要登录全局 beforeEach（第 49 章）
roles允许访问的角色权限过滤（第 53 章）
icon菜单图标名侧边菜单渲染
visible是否在菜单显示菜单过滤
keepAlive是否缓存该页<keep-alive> include
transition页面切换动画名<transition> 组件

50.4 TypeScript：给 RouteMeta 加类型

默认 route.meta 是宽松类型，自己约定的字段没有提示。用模块扩充（module augmentation）补类型：

// src/types/route-meta.d.ts
import 'vue-router'

declare module 'vue-router' {
  interface RouteMeta {
    title?: string
    requiresAuth?: boolean
    roles?: string[]
    icon?: string
    visible?: boolean
    keepAlive?: boolean
  }
}

export {}   // 确保这是模块
// 之后在任何组件/守卫里，route.meta.title 都有类型提示与校验
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isLogin) { /* 类型安全 */ }
})
提醒这个 .d.ts 必须被 tsconfig 包含（通常放 src/ 下即可自动收录）。写在 declare module 'vue-router' 之外、或漏了 export {}，类型扩充不生效。

50.5 在守卫里读 meta（衔接 49/53 章）

把第 49 章的鉴权与本章 meta 串起来，就是后台鉴权的骨架：

router.beforeEach((to) => {
  // to.matched 含整条链；任一父级标了 requiresAuth 即视为需要登录
  if (to.matched.some(r => r.meta.requiresAuth)) {
    if (!localStorage.getItem('token')) {
      return { name: 'login', query: { redirect: to.fullPath } }
    }
  }
})

meta 是路由与业务逻辑之间的契约：路由表只声明"这个页面叫什么、要不要登录"，真正的拦截、菜单、标题逻辑集中在守卫与布局里——改页面不用动业务代码。

50.6 本章常见坑

  • 坑 1以为 route.meta 只有当前层：它是整条 matched 链合并后的结果，想取单层用 matched[i].meta。
  • 坑 2标题设在 beforeEach：导航被取消时标题已经改了，应放 afterEach。
  • 坑 3TS 项目里 meta 字段无提示：忘了做 RouteMeta 模块扩充。
  • 坑 4meta 里放大对象/函数导致路由表难读：meta 只放声明式标记，数据交给 store/接口。
  • 坑 5子路由同名 meta 覆盖父级却不知情：合并是浅合并、子覆盖父，关键字段（requiresAuth）别在子级误写 false。
