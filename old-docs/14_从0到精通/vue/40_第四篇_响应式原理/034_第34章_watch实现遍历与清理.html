34.1 把 source 转成 getter

watch 的第一个参数 source 可以是三种形态，它内部要先统一转成"一个能返回当前值的 getter 函数"。

function watch(source, cb, options = {}) {
  // ① 把 source 规范化为 getter
  let getter
  if (isRef(source)) {
    getter = () => source.value           // ref：读 .value
  } else if (isReactive(source)) {
    getter = () => source                   // reactive：返回整个对象
    options.deep = true                    // reactive 默认深层
  } else if (isFunction(source)) {
    getter = source                        // 用户直接给了函数，就是它
  } else if (Array.isArray(source)) {
    getter = () => source.map(s => ...)    // 多源：挨个转 getter
  }

  // ② 包一个 effect：run 时执行 getter（读响应式 → 被 track）
  // ③ 数据变了，调 cb(newVal, oldVal)
}

三种 source 的差别

source 形态getter 等价于说明
watch(ref, cb)() => ref.value最常见
watch(() => state.x, cb)用户给的函数灵活：可以读多个、可以过滤
watch(reactiveObj, cb)() => reactiveObj自动 deep
watch([a, b], cb)组合 gettercb 收到新旧值数组

watch 的本质就是：跑一遍 getter 收集依赖 → 依赖变了 → 调 cb(newVal, oldVal)。和普通 effect 的差别只在于"cb 拿到了新旧值"。

34.2 traverse：深层遍历依赖

一个关键问题：watch(state, cb) 里 state 是 reactive 对象。如果只执行 getter（返回 state 本身），track 只会收集"读 state 这一步"——也就是 state 对象本身的 'value' 或顶层 key。state.user.name 变了，cb 不会触发，因为 getter 没读 user.name。

解决办法：traverse

function traverse(value, seen = new Set()) {
  // 只遍历响应式对象/数组；原始值、ref、标记过的就直接返回
  if (!isObject(value) || seen.has(value)) return value
  seen.add(value)

  if (isArray(value)) {
    value.forEach(item => traverse(item, seen))
  } else if (value instanceof Map) {
    value.forEach((v, k) => { traverse(k, seen); traverse(v, seen) })
  } else {
    // 普通对象：递归读每个 key
    Object.keys(value).forEach(key => traverse(value[key], seen))
  }
  return value
}

// 在 watch 里：
effect = new ReactiveEffect(() => {
  const value = getter()
  if (options.deep) traverse(value)   // ← 把整个对象读一遍，所有嵌套 key 都被 track
  return value
})

什么时候需要 deep

  • watch(reactiveObj, cb)：Vue 自动 deep（因为返回的是整个对象，不 deep 收集不到嵌套字段）；
  • watch(() => state.obj, cb)：如果 obj 本身是对象，但只是替换引用（obj = newObj），不需要 deep；如果你希望"obj 内部任意字段变"也触发，加 { deep: true }。
提醒deep 会递归遍历整个对象树——大对象（上千字段）每次重跑都遍历一遍，有真实开销。只在必要时开 deep。

34.3 flush：pre / post / sync

flush 决定 cb 什么时候跑：

值时机典型场景
'pre'（默认）组件更新前跑 cb大多数业务场景；cb 里改 state，下次 render 能一起更新
'post'组件更新后跑 cb需要操作 DOM（cb 里读新 DOM、调第三方库）
'sync'同步立即跑极少数必须同步的场景，性能差，慎用
 
watch(
  searchKeyword,
  async (kw) => {
    // flush: 'post' 时，DOM 已经更新，能读到新渲染的列表容器
    const listEl = document.querySelector('#result-list')
    await fetchList(kw)
  },
  { flush: 'post' }
)

pre/post 的差别本质是 scheduler 不同：

  • pre：cb 进入组件更新队列，在组件 render 之前跑（和组件更新合并批处理）；
  • post：cb 进入 post 队列，在组件更新完成之后跑（等同 await nextTick 之后）。

34.4 onCleanup：处理竞态

经典场景：搜索框输入，每次变化发请求。如果用户连续输入"a"、"ab"、"abc"，三次请求并发返回——最后谁返回谁赢，可能"ab"的结果后到覆盖了"abc"。这就是竞态。

// ❌ 没有清理：请求乱序返回会写错数据
watch(searchKeyword, async (kw) => {
  const result = await fetch(`/api/search?q=${kw}`)
  resultBox.value = await result.json()
})

// ✅ 用 onCleanup：上一次回调还没结束就被新回调取代时，先跑清理函数
watch(searchKeyword, async (kw, prevKw, onCleanup) => {
  let cancelled = false
  onCleanup(() => { cancelled = true })

  const result = await fetch(`/api/search?q=${kw}`)
  if (cancelled) return              // 已经被新回调取代，丢弃结果
  resultBox.value = await result.json()
})

onCleanup 的触发时机

  • 下一次 cb 被调用之前（即新值触发时，旧回调还没结束，先调清理）；
  • watch 被 stop 时（清理最后一次未完成的工作）。

34.5 watchEffect 与 stop

watchEffect

// watch：显式声明 source，cb 拿到新旧值
watch(keyword, (kw, prev) => fetch(kw))

// watchEffect：立即执行一次函数，函数内部读到的响应式数据自动成为依赖
watchEffect(async () => {
  const result = await fetch(`/api/search?q=${keyword.value}`)
  box.value = await result.json()
})

差别：

  • watch 显式 source：依赖由你指定；watchEffect 隐式：函数内读到什么就收集什么；
  • watchEffect 立即执行一次（默认），watch 不立即（除非 immediate: true）；
  • watchEffect 拿不到"旧值"，因为它不像 watch 那样比较新旧。

stop 手动停止监听

const stop = watchEffect(() => { /* ... */ })

// 不再需要时：
stop()    // 把这个 effect 从所有 dep 里删掉，再也不跑了

组件 setup 里的 watch 一般不需要手动 stop——组件卸载时 Vue 自动停止。但如果你在组件外（路由切换后）创建的 watch，或在一个长时间运行的页面里"临时监听"，就要记得 stop，否则内存泄漏。

"组件卸载自动停"只对 setup 同步创建的 watch 有效。如果你在 setTimeout、异步回调里才创建 watch，Vue 不知道它属于哪个组件，要自己 stop。

34.6 本章常见坑

  • 坑 1watch 一个 reactive 对象但没 deep：嵌套字段变不触发。要么直接 watch(reactiveObj)（自动 deep），要么显式 { deep: true }。
  • 坑 2watch 一个 getter 但 getter 只返回某个字段：那只有那个字段变才触发——这是 feature，不是 bug。想监听整个对象要 deep。
  • 坑 3cb 是异步函数但忘了 onCleanup：连续触发时旧请求覆盖新结果。
  • 坑 4在 cb 里改刚被 watch 的那个 ref：会立刻再触发一次（同步改 → 同步触发），小心无限循环。
  • 坑 5在 setTimeout / Promise.then 里创建 watch：组件卸载时 Vue 不会自动停它，内存泄漏。

✓ 本章小结

要点一句话
source 规范化ref / getter / reactive / 多源数组统一转成 getter
traversedeep 时递归遍历整个对象，把所有嵌套字段都 track
flushpre 默认（更新前）、post 更新后（操作 DOM）、sync 同步
onCleanup新回调触发前 / stop 时跑清理，解决异步竞态
watchEffect立即执行 + 自动收集依赖，拿不到新旧值
stop手动停止；组件外创建的 watch 必须自己 stop

✎ 本章习题

A 基础什么时候需要给 watch 加 { deep: true }？用 watch(() => state.user, cb) 举一个"不加 deep 不触发、加了才触发"的例子。
B 进阶实现一个搜索输入框：输入变化时发请求（用 onCleanup），模拟 200ms / 500ms / 800ms 三种不同延迟，验证：连续输入"a"、"ab"、"abc"，最终渲染的是"abc"的结果而不是"a"的。
