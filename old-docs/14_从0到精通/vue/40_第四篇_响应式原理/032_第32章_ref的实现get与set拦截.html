32.1 为什么 ref 不用 Proxy

Proxy 只能代理对象。当你写 ref(0) 或 ref('vue')，原始值（string/number/boolean）根本不是对象——你没法 new Proxy(0, ...)，会直接抛错。

所以 Vue 换了一个思路：造一个对象把原始值包起来，在这个对象的 value 属性上用 getter/setter 拦截。

const count = ref(0)

// ref(0) 内部大致长这样：
{
  _value: 0,                       // 真实值存在 _value 上
  get value() {                    // 读 .value 时进这里
    track(this, 'value')
    return this._value
  },
  set value(newVal) {              // 写 .value 时进这里
    if (newVal !== this._value) {
      this._value = newVal
      trigger(this, 'value')
    }
  }
}

count.value     // 0 —— 走 get value
count.value = 1 //  —— 走 set value

也就是说：ref 是一个"对象属性级"的拦截，不是"整个对象级"的 Proxy。它和 Vue2 的 defineProperty 思路同源——只是把它用在一个自己造的包装对象上。

维度refreactive
拦截手段对象自身的 getter/setter（value 属性）new Proxy 整个目标对象
能包什么任何值，包括原始值只能对象
依赖 key固定 'value'每个属性一个 key
赋值方式r.value = xobj.key = x

ref 和 reactive 不是两套响应式，是同一套 track/trigger 引擎的两种入口：一个拦在 value 属性上，一个拦在 Proxy 的 get/set 上。

32.2 RefImpl 的内部结构

真实源码里 ref 是一个类（简化版）：

class RefImpl {
  constructor(rawValue) {
    // 注意：__v_isRef 是个标识位，供 isRef 判断
    this.__v_isRef = true
    // 存一份原始值 + 一份响应式化后的值（对象才会响应式化）
    this._rawValue = rawValue
    this._value = toReactive(rawValue)
    this.dep = undefined    // 这个 ref 的依赖集合，第一次 track 时才建
  }

  get value() {
    track(this, 'value')        // ← 读 .value 时收集当前 effect
    return this._value
  }

  set value(newVal) {
    // 比较用 _rawValue（没响应式化的原始值），避免代理对象误判
    if (hasChanged(newVal, this._rawValue)) {
      this._rawValue = newVal
      this._value = toReactive(newVal)
      trigger(this, 'value')     // ← 写 .value 时通知
    }
  }
}

function ref(value) {
  return new RefImpl(value)
}

三个细节

  1. track 的 target 就是这个 ref 实例本身，key 固定是 'value'。和 reactive 的 targetMap 是同一个全局表——所以 ref 和 reactive 的 effect 收集是统一的；
  2. dep 懒建：第一次 track(this, 'value') 时才在 targetMap 里建这一项，没被读过的 ref 不占依赖表空间；
  3. 比较用 _rawValue 而不是 _value：set 时新旧值比较，必须用"没响应式化"的原始值，否则两个不同的对象只要内容长得像，代理层比较可能出错（对象引用比较本来就该用原始引用）。

32.3 toReactive：对象值自动转 reactive

有一个常被问的问题：const user = ref({ name: 'vue' })，那 user.value.name 的修改能不能触发更新？

const user = ref({ name: 'vue' })

user.value.name = 'new'     // 能触发吗？

答案是能。原因在 toReactive：

function toReactive(value) {
  // 对象才走 reactive；原始值原样返回
  return isObject(value) ? reactive(value) : value
}

// 所以：
ref(0)._value            // 0 —— 原始值，不代理
ref({ name: 'vue' })._value  // Proxy —— 对象，套一层 reactive

链路是：

  1. 读 user.value → 进 get value → track(this, 'value') → 返回 reactive({name:'vue'}) 这个代理；
  2. 再读代理的 .name → 进 Proxy get 陷阱 → track 到代理上（而不是 ref 上）；
  3. 写 user.value.name = 'new' → 触发的是这个 Proxy 上 name 的 dep，而不是 ref.value 的 dep。
操作触发哪个 dep谁会被通知
user.value = newObjref 的 'value'读 .value 的 effect
user.value.name = 'x'内层 Proxy 的 'name'读 .value.name 的 effect
watch(user, cb)ref 的 'value'cb（拿到整个新对象）
watch(() => user.value.name, cb)内层 Proxy 的 'name'cb
提醒正因为对象值会自动转 reactive，ref 和 reactive 在对象场景下行为几乎一致。选择哪种主要看"是否需要整体替换"——ref 可以直接 .value = newObj，reactive 不行。

32.4 isRef / unref / toRaw 的实现

// isRef：看 __v_isRef 标识位
function isRef(r) {
  return !!(r && r.__v_isRef === true)
}

// unref：是 ref 就 .value，否则原样返回
function unref(r) {
  return isRef(r) ? r.value : r
}

// toRaw：ref 也要能拆到原始值
function toRaw(observed) {
  // ref：先 .value 拆包，再递归 toRaw；reactive：直接反查原始对象
  const real = observed.__v_raw ?? observed
  return real.__v_raw ?? real
}

这三个函数都是为了写工具库 / 组合式函数时判断"这东西到底是不是 ref"。典型场景：

// 写一个接受"可能是 ref 也可能是普通值"的参数
function useX(maybeRef) {
  // unref 之后拿到的永远是"解开的"值
  const value = unref(maybeRef)
  // 如果要在 effect 里用，最好用 toValue 兼容 getter
  console.log(value)
}

扩展：Vue 3.3 起还有 toValue(source)，能统一处理"普通值 / ref / getter 函数"三种入参，是写组合式函数时最稳的解包工具。

32.5 模板里的 ref 自动解包

你写的模板：

<template>
  <p>{{ count }}</p>   <!-- 注意：不是 count.value -->
</template>

<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

为什么模板里写 {{ count }} 而不是 {{ count.value }}？两个原因：

  1. 编译器层面的自动解包：<script setup> 编译时，模板里的顶层 ref 引用会被自动加 .value。{{ count }} 编译后约等于 {{ count.value }}——这是编译期做的语法糖，不是运行时魔法；
  2. 组件实例代理：选项式 API 里 setup() 返回的对象，在模板里访问时经过一层代理，自动解包顶层 ref（setupState proxy）。

什么时候不会自动解包

  • 嵌套在响应式对象里的 ref：const state = reactive({ count: ref(0) })，模板里 {{ state.count }} 会自动解包（这是 reactive 的代理做的）；但在 JS 里访问 state.count 也是自动解包的（reactive 内部对 ref 做了 unwrap）；
  • ref 作为数组元素：const list = [ref(1), ref(2)]，模板里 {{ list[0] }} 不会自动解包，要写 list[0].value。
写法是否自动解包说明
模板里顶层 ref（count）是编译器加 .value
reactive 对象的 ref 字段（state.count）是reactive 代理 unwrap
数组里的 ref（list[0]）否必须写 .value
JS 代码里的 ref否必须 .value

"模板里能省 .value，JS 里不能省"——这是最容易记混的一条。JS 里永远要写 .value。

32.6 本章常见坑

  • 坑 1JS 代码里漏写 .value：拿到的是 ref 对象本身，不是值。模板里能省，script 里不能省。
  • 坑 2把 ref 解构出来：const { count } = state（state 是 reactive）——解构出来的 count 还是 ref（reactive 字段解包只在属性访问时发生），要 storeToRefs 或自己 .value。
  • 坑 3以为 ref({}) 和 reactive({}) 完全等价：行为接近，但 ref 可以整体 .value = newObj 替换，reactive 不能整体替换。
  • 坑 4用 Object.keys 或 JSON.stringify 序列化 ref：得到的是 { _value: 0, dep: ... } 这些内部字段，不是干净的 0。要先 .value 或用 toRaw。
  • 坑 5给 ref 赋一个新对象以为内层 Proxy 会复用：set value 时会重新 toReactive(newVal)，旧代理废弃、新代理建立——读旧代理的 effect 可能没被通知到（设计如此，业务里注意）。
