30.1 为什么需要依赖收集

设想一个最简单的场景：

const state = reactive({ name: 'vue', age: 3 })

effect(() => {
  console.log(state.name)    // 只关心 name
})

state.age = 4                // 这一步要不要触发上面的 effect？

答案是不要——上面那个 effect 从来没读过 state.age，age 变了它不该重跑。如果没有"依赖收集"，set 能做的只有"通知所有人"：

  • 方案 A：set 时遍历所有 effect 全跑一遍——白白浪费，而且会跑根本不关心这个字段的副作用；
  • 方案 B：set 时按"对象 + key"找到一份专门关心它的 effect 列表，只跑这些——这就是 track + trigger 的分工。

track 解决的问题只有一个：在读属性的时候，把"当前正在跑的副作用"登记到这个属性名下。等到 set 时，按名单通知。

30.2 三层结构 targetMap / depsMap / dep

依赖名单的存储结构是三层 Map：

// 全局唯一的依赖表
const targetMap = new WeakMap()
//   key:  原始对象 rawTarget
//   val:  depsMap

// depsMap: Map<key, dep>
//   key:  属性名（字符串 / Symbol）
//   val:  dep —— 一个 Set，装着所有依赖这个 key 的 effect

// dep: Set<ReactiveEffect>
//   一个 effect 集合，即"谁关心这个 key"

图 30-1 三层依赖表：从对象一路查到关心它的 effect 集合（示意）

三种容器的选型理由

容器放在哪一层为什么是它
WeakMap最外层 targetMap键是原始对象。WeakMap 持弱引用：当原始对象没有任何地方再引用时，它的依赖名单能被 GC 自动回收，不会内存泄漏
Map中间层 depsMap键是属性名（字符串/Symbol/数字），普通 Map 即可；数字 key 也能存（数组下标）
Set最内层 dep键是 effect 实例。Set 自动去重：同一个 effect 多次读同一 key，只登记一次

WeakMap 的"弱引用"不是玄学：如果你用普通 Map 当 targetMap，那些已经在组件卸载后没人引用的对象，会因为依赖表还拿着它，永远无法被垃圾回收——大型应用跑久了内存只涨不跌。

30.3 activeEffect 与 track 代码骨架

track 要回答的核心问题是："现在正在跑的副作用是谁？"。get 陷阱只是一个拦截点，它本身不知道调用栈上层是谁在读属性。Vue 的办法是一个模块级全局变量：

let activeEffect = null   // 当前正在执行的副作用实例

class ReactiveEffect {
  constructor(fn) { this.fn = fn }
  run() {
    activeEffect = this       // 1. 把自己设为"当前副作用"
    this.fn()                // 2. 执行用户的函数 —— 函数内部一旦读响应式属性
    activeEffect = null      // 3. 执行完立刻清掉
  }
}

function effect(fn) {
  const runner = () => {
    const ef = new ReactiveEffect(fn)
    ef.run()
    return ef
  }
  return runner()
}

track 本身

function track(target, key) {
  // 关键：如果当前没有正在跑的 effect，直接什么都不做
  // （比如你在浏览器控制台直接 state.name，没有 effect 在跑）
  if (activeEffect === null) return

  // ① 查 / 建 depsMap
  let depsMap = targetMap.get(target)
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()))
  }

  // ② 查 / 建 dep
  let dep = depsMap.get(key)
  if (!dep) {
    depsMap.set(key, (dep = new Set()))
  }

  // ③ 把当前 effect 登记进 dep（Set 自动去重）
  dep.add(activeEffect)
}

和 get 陷阱串起来

const proxy = new Proxy(raw, {
  get(target, key, receiver) {
    track(target, key)                        // ← 读属性时收集
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    Reflect.set(target, key, value, receiver)
    trigger(target, key)                     // ← 下一章讲
    return true
  }
})

把上面两段连起来，完整流程就是：

  1. effect(() => console.log(state.name)) 被调用 → 构造 ReactiveEffect → activeEffect = 自己 → 执行函数；
  2. 函数体内读到 state.name → 进 get 陷阱 → track(raw, 'name')；
  3. track 查表：targetMap[raw]['name'] 这个 Set 里加上"自己"；
  4. 函数跑完 → activeEffect = null；
  5. 以后谁 state.name = 'x' → set 陷阱 → trigger 按表通知这个 Set 里的所有 effect。

activeEffect 是一个"线程局部"式的全局游标：它只在 effect.fn() 执行的那一瞬非空——track 能不能收集，全靠这一瞬。

30.4 访问才收集：effect 闭包是什么

回到 30.1 的例子：为什么 state.age = 4 不会触发那个 effect？因为 activeEffect 在跑这个函数期间，从来没经过过 age 的 get 陷阱，所以 depsMap['age'] 里根本没有它的名字。

"收集了什么"——不是值，是 effect 闭包

Set 里装的是 ReactiveEffect 实例，实例身上有一个 fn 字段——就是你传给 effect() / watchEffect() 那个函数的闭包。闭包里捕获了渲染需要的所有东西：组件实例、DOM 引用、computed 引用、其他响应式变量。

effect(() => {
  // 这个闭包捕获了 document.body、user、format 等外部变量
  document.body.innerText = `${user.name} 的年龄是 ${user.age}`
})
// 上面这个函数一旦被登记进 dep，trigger 时直接 ef.run() 就能完整重跑这段逻辑
// —— Vue 不需要知道函数内部干了什么，只要"原样执行一遍"就够了

访问才收集带来的两个推论

  • 动态属性访问也会被收集：state[someKey] 这种动态读，key 是运行时确定的，track 会用那个具体的 key 登记——没问题；
  • 没读到的字段变化不会触发：这是 feature 不是 bug。它解释了为什么"条件分支里的字段不读就不触发"、为什么"console.log(state) 之后改 state.xxx 可能不更新"（console.log 不一定读具体 key）。

trackShouldTrack 的边界

真实源码里 track 不是无脑收集，会判断几件事：

  • activeEffect 是否存在；
  • 这个 effect 是否正在被"清理依赖"中（避免自循环）；
  • 属性是不是 markRaw 过的（跳过代理的不收集）。

为什么要"重新收集"而不是累计：effect 每次重跑前，会先把自己从所有 dep 里删掉（cleanup），再重新执行函数、重新 track 一遍。这样上一次跑时读过、这一次跑时没读的字段，就不会再通知这个 effect——否则条件分支切换会漏更新或多更新。

30.5 渲染 effect 与组件的关系

Vue 的组件实例在挂载时，本质上就是把它的渲染函数包成一个 effect：

// 简化示意（不是真实源码）
class ComponentInstance {
  mount() {
    this.effect = new ReactiveEffect(() => {
      this.render()    // 把虚拟 DOM diff、patch 到真实 DOM
    })
    this.effect.run()  // 首次执行：render 过程中读到的 props/state 全部被 track
  }
}
  • 组件的整个 render 函数就是一个 effect：模板里用到的每个响应式字段，都在 render 执行时被收集到对应 dep；
  • 以后这些字段任何一个变化，trigger 通知这个渲染 effect，组件重渲染；
  • 组件卸载时，把这个 effect 从所有 dep 里删掉（stop），否则组件销毁了还在被通知——内存泄漏。
effect 类型来源典型职责
渲染 effect组件挂载时自动创建把模板渲染到 DOM，组件卸载时 stop
watchEffect用户手动调用自定义副作用（请求、日志、订阅）
watch 的回调用户指定 source + cb拿到新旧值做副作用
computed 的求值器 computed 内部惰性求值（第 33 章）

Vue 的所有"响应式"现象，追到底都是同一件事：某个 effect 在跑的时候读了属性，被记进 dep；属性变了，trigger 把这些 effect 再跑一遍。

30.6 本章常见坑

  • 坑 1在 console 里直接 state.xxx 没被收集：因为 activeEffect = null，track 直接 return。不要以为"我打印过它，它就该响应"。
  • 坑 2组件卸载后还在跑请求：effect 没被 stop，组件销毁了 dep 里还有它的引用，state 一变就重跑旧组件的 render——内存泄漏 + 报错。
  • 坑 3在 setTimeout / Promise.then 里读响应式属性：回调执行时 activeEffect 已经是 null（effect 已经跑完），读了也白读。要收集，必须在 effect 同步执行期间读。
  • 坑 4对普通对象（未 reactive）做依赖收集：没有 get 陷阱，track 永远不会被调用。
  • 坑 5把依赖表存在普通 Map 上做大型应用：组件卸载后无法 GC，内存只涨不跌。
