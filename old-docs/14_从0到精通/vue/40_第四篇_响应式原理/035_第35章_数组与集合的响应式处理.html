35.1 数组的特殊性：下标与 length

JS 数组本质上是"特殊对象"：arr[0] 就是 arr['0']，arr.length 也是它的一个属性。但它有两个普通对象没有的行为：

① 越界赋值会自动改 length

const arr = [1, 2, 3]        // length = 3
arr[5] = 99                  // 越界赋值
console.log(arr.length)       // 6 —— length 被自动改成 6，中间是 empty

所以 set 陷阱里写 arr[5] = 99 时，不仅要通知 key '5' 的依赖，还要通知 'length' 的依赖（比如 v-for）。

② 直接改 length 会影响下标

arr.length = 1               // 直接截断
// 此时 arr[1]、arr[2] 这些 key 都"消失"了

set 陷阱里当 key === 'length' 且新 length 小于旧 length 时，要通知被删掉的那些下标 key 的依赖。

Vue3 的处理（简化版）

set(target, key, value, receiver) {
  const isArray = Array.isArray(target)
  const hadKey = Object.prototype.hasOwnProperty.call(target, key)
  const oldLength = isArray ? target.length : undefined

  const result = Reflect.set(target, key, value, receiver)

  // 情况 A：数组新增下标（key 不是整数、或整数 >= oldLength）
  if (isArray && !isNaN(Number(key))) {
    const index = Number(key)
    if (index >= oldLength) {
      trigger(target, 'length', 'SET')   // 下标新增 → 通知 length
    }
    trigger(target, index, hadKey ? 'SET' : 'ADD')
  }
  // 情况 B：直接改 length
  else if (key === 'length') {
    if (value < oldLength) {
      trigger(target, 'length', 'SET')   // 截断 → 通知 length
    }
  }
  // 情况 C：普通对象
  else {
    trigger(target, key, hadKey ? 'SET' : 'ADD')
  }
  return result
}
操作触发哪些 dep备注
arr[i] = x（i < length）key='i'普通修改
arr[i] = x（i ≥ length）key='i' + key='length'越界新增
arr.length = n（n < length）key='length' + 被删的下标截断
Object.keys(arr) 收集ITERATE_KEY枚举变化时通知

35.2 变异方法的包装

数组有 7 个会隐式改 length 的方法：push / pop / shift / unshift / splice / sort / reverse。

为什么要包装

比如 arr.push(4)：

  • JS 引擎内部等价于：先读 arr.length（拿到 3），再 arr[3] = 4（新增下标），再 arr.length = 4；
  • 问题：如果你的 effect 里只 console.log(arr.length)，它会被 read length 触发 track——这是好事；但 push 本身是一个方法调用，不是"属性 set"。

Vue 的做法：把这 7 个方法在拦截层替换成"instrumented version"，在调用原生方法前后手动 trigger。

const arrayInstrumentations = {
  push(...args) {
    // 1. 先暂停依赖收集（避免内部读 length 又触发 track，造成递归）
    pauseTracking()
    const result = Array.prototype.push.apply(this, args)
    resumeTracking()
    // 2. 手动 trigger：新增了下标、改了 length
    trigger(this, 'length', 'ADD')
    return result
  },
  pop() { /* 类似：删了 length-1 下标 + 改 length */ },
  splice(...) { /* 类似 */ }
  // ...其余 4 个
}

// 在 get 拦截里：如果读的是这些方法，返回 instrumented 版本
get(target, key, receiver) {
  if (Array.isArray(target) && hasOwn(arrayInstrumentations, key)) {
    return arrayInstrumentations[key]
  }
  // ...正常 track + Reflect.get
}

为什么要 pauseTracking

push 内部会读 length（为了知道新下标在哪）。如果不暂停收集，那一次内部读 length 会把"正在跑的 effect"登记进 length 的 dep——但这不是用户主动读的，是 push 内部隐式读的。把它登记进去，会造成"push 一次就把当前 effect 和 length 绑死"，之后任何 length 变化都触发这个 effect——可能不是用户想要的。

Vue2 重写数组方法是为了"在 defineProperty 时代补上拦截"；Vue3 的拦截已经够强，包装这些方法只是为了精准控制 trigger 时机，避免隐式读造成误收集。

35.3 Map / Set 的响应式

Map/Set 不能用普通对象的 Proxy 套路，因为它们的"读"和"写"都是方法调用（map.get(k) / map.set(k,v)），不是属性访问。

三个根本差异

  • get/set 是方法，不是属性：map.set('a', 1) 不走 Proxy 的 set 陷阱；
  • 判断存在用 map.has(k)，不是 k in map；
  • 迭代用 map.keys() / map.values() / map.forEach，不是 Object.keys。

Vue 的做法：在 get 拦截里重写这些方法

const mutableInstrumentations = {
  get(key) {
    const target = this.__v_raw       // 拿到原始 Map（通过 receiver 反查）
    track(target, key)                // 读 key → 收集
    return toReactive(target.get(key))  // 值也包响应式
  },
  set(key, value) {
    const target = this.__v_raw
    const had = target.has(key)
    const oldValue = target.get(key)
    target.set(key, toRaw(value))     // 写原始 Map
    if (!had) {
      trigger(target, key, 'ADD')
    } else if (hasChanged(value, oldValue)) {
      trigger(target, key, 'SET')
    }
    return this                       // 返回代理（链式调用）
  },
  has(key) {
    track(this.__v_raw, key)
    return this.__v_raw.has(key)
  },
  delete(key) {
    const had = this.__v_raw.has(key)
    const result = this.__v_raw.delete(key)
    if (had) trigger(this.__v_raw, key, 'DELETE')
    return result
  },
  clear() {
    const hadItems = this.__v_raw.size !== 0
    const result = this.__v_raw.clear()
    if (hadItems) trigger(this.__v_raw, CLEAR, 'CLEAR')
    return result
  },
  forEach(cb, thisArg) {
    track(this.__v_raw, ITERATE_KEY)   // 遍历依赖：迭代集合变化
    // ...正常 forEach，但把每个值 toReactive 后回调
  }
  // keys / values / entries / size 类似
}

// 在 get 陷阱：如果读的是这些方法名（get/set/has/...），返回 instrumented 版本
get(target, key, receiver) {
  if (key === '__v_raw') return target
  if (hasOwn(mutableInstrumentations, key)) {
    // 注意绑定 receiver：让这些方法里的 this 指向代理（能拿到 __v_raw）
    return mutableInstrumentations[key].bind(receiver)
  }
  // ...
}

WeakMap / WeakSet

Vue 也能让 WeakMap/WeakSet 响应式（同样方法重写），但它们的 key 必须是对象。WeakMap 本身弱引用，适合做"对象附属元数据"缓存——和响应式无关。

集合类型响应式处理注意
普通对象Proxy get/set 陷阱key 是字符串/Symbol
数组Proxy + 7 个变异方法包装下标与 length 联动
Map / Set方法重写（get/set/has/...）key 可以是任意类型
WeakMap / WeakSet同上，但 key 必须是对象弱引用，适合元数据缓存

35.4 集合方法的 this 绑定

最后一个细节：mutableInstrumentations.get 这些方法里写 this.__v_raw——this 必须是代理（这样才能 __v_raw 反查原始 Map）。所以 get 陷阱返回它们时必须 .bind(receiver)。

为什么不能直接用原 Map 方法

const rawMap = new Map()
const proxyMap = reactive(rawMap)

// 如果不 bind，proxyMap.get('a') 内部 this 指向：
//   - 指向 rawMap？那 this.__v_raw 是 undefined，拿不到原始对象
//   - 指向 proxyMap？能拿到 __v_raw，正确

// 所以 get 陷阱返回 instrumented.get 时：
//   return instrumentations.get.bind(receiver)
// 调用时：instrumented.get 内部 this === proxyMap，this.__v_raw === rawMap ✓

普通 Proxy 靠 receiver 把 this 修正到代理；集合类靠 __v_raw 反查 + .bind(receiver) 把方法 this 绑到代理——最终目的都是"能拿到原始对象"。

35.5 本章常见坑

  • 坑 1以为 Map 的 key 改了能自动更新：Map 的 key 是引用类型时，改 key 对象本身不会触发——因为 key 是按引用存的，key 对象变了 Map 不知道。要么换 key，要么用普通 reactive 对象。
  • 坑 2用 map.keys() 收集但忘了它依赖迭代：map.add/delete/clear 都会通知 ITERATE_KEY，所以 .keys() 的迭代依赖能正确触发。
  • 坑 3数组直接赋值替换（arr = newArr）丢响应式：arr 是 reactive 代理，重新赋值会断开——要么改代理内部（arr.splice(0)），要么用 ref 包数组。
  • 坑 4在 v-for 里用 Set 但没展开：Set 是可迭代的，v-for="item in set" 能工作，但 Set 没有索引，key 绑定要用 item 本身。
  • 坑 5把 Map/Set 直接 JSON.stringify：得到 {}——Map/Set 不是普通对象，序列化要先 Array.from(map.entries())。
