2第一篇 入门（第 1-9 章）

第 1 章 认识 Vue：声明式与渐进式

A 基础用不超过三句话向同事解释：为什么用了 Vue 之后，就不该再写 document.querySelector('#x').textContent = ... 这种代码？

答案：Vue 是声明式框架：你只描述"状态 → 视图"的映射，状态一变，框架自动 diff 并更新对应 DOM。再手动操作 DOM 等于绕过框架、回到命令式，既重复劳动，又与框架的更新体系不同步，还会丢掉批量更新与虚拟 DOM 优化。一句话：Vue 接管了"怎么改 DOM"，手动改就是两套体系打架。

B 进阶把上面"点击计数"的命令式原生代码补全并运行，然后改造成 Vue 版本（可先用 CDN 方式），对比两者代码行数与维护点数量的差异。

答案：命令式原生版约 15–20 行：取 DOM、绑 click、改 textContent，每加一处交互都要手动找节点；Vue CDN 版核心约 5 行：createApp({ setup(){ const count = ref(0); return { count } } }).mount('#app')，模板 {{ count }} <button @click="count++">+1</button>。维护点：原生版每处更新都要手动改节点；Vue 版只管状态，视图自动跟随。

C 挑战打开 Vue 官网的"渐进式"介绍页，找出任意一个"核心之外"的能力（如 Transition、Teleport），思考：如果核心不提供它，你会怎么用原生方式实现？

答案：以 Teleport 为例：原生要自己写"把弹窗 DOM 从组件容器搬到 body"的搬运逻辑、卸载时手动移除、再自管 z-index 层级；Transition 则要手写 rAF 对比前后 class、监听 transitionend 再删元素。这些正是"能写但不该人人重写"的能力，Vue 把它做成内置组件。

第 2 章 环境搭建：create-vue 与工程结构

A 基础创建项目后，把浏览器地址栏的端口改成别的（在 vite.config.js 配 server.port），确认修改生效，并说出为什么改配置后要重启服务。

答案：vite.config.js 写 server: { port: 5174 }，重启 dev server 后地址栏变为新端口。配置文件只在启动时读取一次，dev server 本身就是配置的产物，所以配置改动不走 HMR，必须重启。

B 进阶在 vite.config.js 里配置 @ 别名，然后把 App.vue 里对组件的相对路径引用全部改成 @/components/... 形式，跑通 dev 与 build 两种模式。

答案：resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } }。dev 与 build 共用同一份 vite.config，所以两种模式都能解析 @/。

C 挑战执行 npm run build 后用 npm run preview 打开产物，打开浏览器 Network 面板，记录产物文件名里的 hash 值；再改一行代码重新构建，观察 hash 的变化并解释它解决了什么问题。

答案：产物形如 assets/index-B8k2xQ.js；改一行代码再 build，hash 变化、文件名也变。hash 的作用：内容变 → 文件名变，浏览器/CDN 缓存自动失效，避免"HTML 更新了用户还在用旧 JS"的经典缓存问题；长期不变的 vendor 包 hash 稳定，可被长期缓存。

第 3 章 模板插值与表达式

A 基础写出下面三种写法的渲染结果并说明原因：{{ 'a' + 1 }}、{{ { a: 1 } }}、{{ [1, 2, 3] }}。

答案：{{ 'a' + 1 }} → "a1"（字符串拼接）；{{ { a: 1 } }} → "[object Object]"（插值对对象调用 toString，要展示对象得 JSON.stringify 或取字段）；{{ [1,2,3] }} → "1,2,3"（数组 toString 用逗号连接）。

B 进阶写一个用户信息卡片：昵称（可能为空，兜底"未设置"）、标签数组（用"、"连接）、注册时间（格式化为"2026-10-01 12:30"）。要求模板里不出现超过一行的表达式。

答案：把展示逻辑放进 computed：displayName = user.nickname || '未设置'、tagText = tags.join('、')、timeText = format(regTime)（格式化为 yyyy-MM-dd HH:mm）。模板里全是 {{ displayName }} 这类单点插值。

C 挑战模拟一次 XSS：用 v-html 渲染 <img src=x onerror="alert(1)">，观察攻击如何发生；然后改用 v-text 并说明两种做法在浏览器里的差异。进一步思考：如果业务必须展示富文本，你的处理流程应该是什么？

答案：v-html 把字符串当 HTML 解析，img 的 onerror 真的执行脚本——XSS；v-text 等价 textContent，标签原样显示、脚本不执行。业务必须展示富文本时：先经白名单 sanitize（如 DOMPurify 清洗标签与属性）再 v-html，绝不直接渲染用户输入。

第 4 章 指令体系：v-bind / v-on / v-if / v-for / v-model

A 基础写出 <input v-model="msg"> 的等价展开写法，并说明 .lazy 修饰符改变了其中的哪一部分。

答案：等价展开：:value="msg" @input="msg = $event.target.value"。.lazy 把 input 事件换成 change 事件——输入过程中不同步，失焦或回车才同步。

B 进阶实现一个"待办清单"：输入框回车添加、点击删除、底部显示"共 N 条 / 已完成 M 条"。要求 v-for 使用 id 作为 key，删除中间项时验证输入框内容不会串位。

答案：<input v-model="text" @keyup.enter="add">；<li v-for="t in list" :key="t.id">{{ t.text }}<button @click="del(t.id)">×</button></li>；件数用 computed：doneCount = list.filter(t => t.done).length。用 id 作 key，删中间项时按身份复用节点，输入框内容不串位。

C 挑战把 v-for 的 key 分别换成 item.id、index、Math.random()，在列表项里放一个 <input> 让用户先输入内容，再删除第一项，观察三种 key 下输入内容的表现差异并解释原因。

答案：item.id：按身份复用，输入留在对应项上；index：按下标对齐，删首项后整体上移，输入内容"挪"到新第一项，看起来错位；Math.random()：每次渲染都是新 key，Vue 认为全是新节点，每次销毁重建，输入每次都丢、性能最差。结论：key 必须稳定且唯一。

第 5 章 计算属性 vs 方法

A 基础用一段可运行代码证明"计算属性有缓存、方法没有"：分别在两者里 console.log，然后修改一个与其无关的数据触发渲染，记录打印次数。

答案：computed getter 里 log 一次，模板方法调用里也 log。修改一个与二者都无关的数据触发重渲染：方法每次渲染都重新打印（N 次），computed 只在依赖变化时打印一次，之后读缓存。

B 进阶实现一个"购物车结算"：商品列表（含单价、数量、选中状态），用计算属性派生出「已选商品件数」「商品总价」「满 200 减 30 后的应付金额」「是否可用优惠券」。要求模板中没有任何复杂表达式。

答案：四个 computed：selectedCount = list.filter(i=>i.checked).reduce((s,i)=>s+i.count,0)；totalPrice = list.filter(i=>i.checked).reduce((s,i)=>s+i.price*i.count,0)；payable = totalPrice>=200 ? totalPrice-30 : totalPrice；canUseCoupon = totalPrice>=200。模板只写 {{ payable }} 等。

C 挑战写一个可写计算属性完成「金额（元）↔ 金额（分）」双向转换：输入框以元为单位编辑，底层存储以分为单位（避免浮点误差）。思考：为什么金融场景要用分而不是元？

答案：底层 cents = ref(100)；可写 computed yuan = { get: ()=> (cents.value/100).toFixed(2), set: v=> cents.value = Math.round(parseFloat(v)*100) }，输入框 v-model="yuan"。金融用分：二进制浮点无法精确表示 0.1 这类十进制小数，用最小货币单位（整数分）存储可避免 0.1+0.2=0.3000000004 一类误差。

第 6 章 侦听器 watch 与 watchEffect

A 基础分别用 watch 与 watchEffect 实现"监听 a、b 两个 ref，任一变化就打印它们的和"，体会两者在"首次是否执行"上的差别。

答案：watch：watch([a, b], ([na, nb]) => console.log(na + nb))，首次不执行；watchEffect：watchEffect(() => console.log(a.value + b.value))，挂载后立即执行一次，之后任一变化再执行。差别就在"首次是否立即跑"与"是否需要显式声明依赖"。

B 进阶在 6.6 的搜索防抖基础上增加：① 请求竞态处理（只接受最后一次响应）；② 关键字清空时立刻清空结果且不发请求；③ 组件卸载时取消定时器。

答案：① 过期标记：回调开头 if (cancelled) return，onCleanup 里置 cancelled=true；② 先判断 if (!keyword) { result = []; return } 再发请求；③ watch 清理函数或 onUnmounted 里 clearTimeout(timer)。

C 挑战实现一个 useTitle(titleRef) 组合式函数：内部用 watchEffect 把标题同步到 document.title，并要求组件卸载后停止同步。再思考：为什么用 watchEffect 比 watch 更省事？

答案：function useTitle(r){ watchEffect(() => { document.title = r.value }) }；组件卸载时 watchEffect 随作用域自动停止。watchEffect 自动收集回调内用到的响应式源，不用手写源列表，且挂载即跑一次正好符合"标题立即同步"。

第 7 章 class 与 style 绑定

A 基础写出 <div class="a" :class="['b', { c: true, d: false }]"> 的最终 class 结果，并说明静态与动态 class 的合并顺序。

答案：最终 class="a b"（c 为 true 保留、d 为 false 跳过）。静态 class 与 :class 合并而不互相覆盖；对象/数组中值为假的类名被跳过；两类来源并存。

B 进阶封装一个 <StatusTag status="pending|running|done|failed"> 组件：内部用计算属性返回 class 对象，外部可再用 class 追加边距类（验证透传是否生效）。

答案：const cls = computed(() => ({ pending:'text-gray', running:'text-blue', done:'text-green', failed:'text-red' }))，模板 <span class="tag" :class="cls[status]">；外部 <StatusTag class="ml-2"> 的边距类自动合并到组件根节点（class 透传）。

C 挑战实现一个"可配置主题"的卡片组件：通过 props 传入 theme（light/dark）与 accentColor，用 CSS 变量 + class 实现切换；要求 accentColor 用内联 style 绑定变量（:style="{ '--accent': accentColor }"）而不是直接改背景色，并说明这样做的好处。

答案：根元素 :style="{ '--accent': accentColor }"，CSS 里 .card{ color: var(--accent) }。好处：组件只注入一个变量，主题色与样式结构解耦；多组件共用同一变量时只需改一处；避免为每个颜色写一套 class。

第 8 章 条件渲染与列表渲染细节

A 基础说出 v-if 与 v-show 在"首次渲染""切换""组件生命周期"三个维度上的差异，并各举一个适用场景。

答案：首次渲染：v-if 条件为假时不渲染真实 DOM；v-show 始终渲染，只切 display。切换频率：频繁切换用 v-show（免销毁重建），很少切换用 v-if（初始更省）。生命周期：v-if 切换会触发组件挂载/卸载，v-show 不涉及。

B 进阶做一个"可编辑列表"：每行含一个输入框，支持删除任意行、在中间插入行。分别用 item.id 与 index 作为 key，输入内容后删除首行，记录并解释两者差异。

答案：item.id：删首行后输入内容留在原行上，符合预期；index：按下标对齐复用，删首行后第二行复用了第一行的 DOM 与输入状态，内容"串位"。原因：key 决定复用身份，index 随删除漂移。

C 挑战给一个 1000 条的列表加"关键字搜索 + 状态筛选 + 排序"，全部逻辑用计算属性完成；然后尝试把过滤逻辑移到模板里（v-for="i in list.filter(...)"），用 console.count 对比两种方式在数据变化时的执行次数。

答案：过滤/筛选/排序全部交给 computed：filtered = computed(() => list.filter(matchKw).filter(matchStatus).sort(bySort))，模板 v-for="i in filtered"。移到模板后 list.filter(...) 每次渲染都重算，console.count 次数明显多于 computed（computed 有缓存，依赖不变不重算）。

第 9 章 事件处理与修饰符

A 基础写出下列写法的等价原生代码：@click.stop、@submit.prevent、@keyup.enter、@click.self。

答案：@click.stop → e.stopPropagation()；@submit.prevent → e.preventDefault()；@keyup.enter → if (e.key === 'Enter') handler；@click.self → if (e.target === e.currentTarget) handler。

B 进阶实现一个弹窗：点遮罩层关闭（但不能因点击内容区误关）、按 Esc 关闭、点关闭按钮关闭且事件不冒泡到遮罩层。全部要求使用修饰符完成，处理函数里不出现一行 DOM 事件代码。

答案：遮罩 @click.self="close"（点遮罩空白处才关，点内容区不触发）；内容区 @keydown.esc="close"；关闭按钮 @click.stop="close"（.stop 阻止冒泡，避免双触发）。处理函数里零 DOM 代码。

C 挑战写一个"全局快捷键"功能：在组件挂载时给 window 绑定 keydown 监听（Ctrl+S 保存、Esc 取消），组件卸载时移除监听；并说明为什么这里必须用 onUnmounted 清理，以及用 VueUse 的 useEventListener 能省掉哪些代码。

答案：onMounted 里 window.addEventListener('keydown', onKey)，onUnmounted 里 window.removeEventListener('keydown', onKey)。必须清理：组件卸载后监听仍挂在 window 上会继续执行，闭包引用组件变量造成内存泄漏。useEventListener('keydown', onKey) 一行搞定，自动在卸载时解绑。

C 挑战在项目中接入 unplugin-vue-components + Element Plus resolver，删除所有手写 import，确认：① 模板里直接用 <ElButton> 是否生效；② 打包体积是否只含用到的组件；③ 生成的 components.d.ts 有什么作用。

第 11 章 props 声明校验与单向流

A 基础写一个 BaseTag 组件：props 含 text（必填字符串）、type（枚举校验：info/success/warn/error，默认 info）、size（数字，默认 12）。故意传一个非法 type，观察控制台告警。

答案：defineProps({ text:{ type:String, required:true }, type:{ type:String, default:'info', validator: v=>['info','success','warn','error'].includes(v) }, size:{ type:Number, default:12 } })；传非法 type 时控制台出现 [Vue warn] 校验失败提示。

B 进阶实现一个"受控输入组件"：父组件持有值，子组件通过可写计算属性实现读写同步；再实现一个"非受控版本"（本地副本 + watch 同步 props 变化），比较两者的差异与适用场景。

答案：受控版：const model = defineModel()，内部直接读写 model.value，一切以父级为准；非受控版：const inner = ref(props.modelValue); watch(() => props.modelValue, v => inner.value = v)，本地副本为初始值、props 变化时同步。受控适合父级要掌控值；非受控适合组件自治、父级只给初始值。

C 挑战封装 BaseInput：内部包一层 <div class="wrap">，要求父组件写的 class、placeholder、data-* 都落到内部 <input> 上（用 $attrs + inheritAttrs: false），并验证多根模板下不这样做会怎样。

答案：defineOptions({ inheritAttrs: false })，把 v-bind="$attrs" 显式绑到内部 input 上。多根模板下 attrs 本就无处自动落，不显式绑定的话 class/事件会直接丢失。

第 12 章 自定义事件 emit

A 基础写一个 Counter 组件：内部有 +1/-1 按钮，每次变化 emit change 事件并把新值传出，父组件显示"当前值 N"。

答案：const emit = defineEmits(['change'])，按钮 @click="n++; emit('change', n)"；父组件 <Counter @change="v => count = v">，显示 当前值 {{ count }}。

B 进阶把 12.5 的"触发两次"问题复现出来，再用 defineEmits 修复它，并在 $attrs 中观察声明前后 onClick 是否存在。

答案：未声明时父组件 @click 被当成原生事件透传到根元素，根节点同时绑了一次原生 click，导致触发两次；defineEmits(['click']) 声明后 onClick 进入 emits 范畴不再透传，$attrs 里不再出现 onClick。

第 20 章 setup 与 ref 为什么包一层

A 基础写一个 ref(0) 计数器：模板里放 {{ count }} 和 {{ count.value }} 两种写法的输出，对比结果；再把事件处理函数里的 count.value++ 改成 count++，观察控制台与页面的差异。

答案：模板里 {{ count }} 自动解包显示值；{{ count.value }} 在模板里也能渲染出值（因为渲染上下文里 count 是 ref，模板编译时对顶层 ref 做解包，但显式写 .value 也能访问到值）。事件里 count++ 等价于 count = count + 1，是把整个 ref 对象重新赋值为数字——之后 count 不再是 ref，模板再读 count 显示的就是数字本身，且后续修改不触发更新；正确做法始终是 count.value++。

B 进阶写一个函数 useDouble(ref入参)：接收一个 ref，返回它的 2 倍（要求用 computed 实现）。在组件里传入不同的 ref，验证：改原始 ref 的 .value，组件里的显示是否同步更新。

答案：function useDouble(r) { return computed(() => r.value * 2) }。组件里 const a = ref(2); const d = useDouble(a)，模板 {{ d }}；改 a.value = 5，d 自动变 10。因为传入的是同一个 ref 容器引用，computed 追踪 r.value 的变化。

C 挑战用纯 JS（不引入 Vue）手写一个极简 myRef(init) 对象：包含 .value 的 getter/setter，set 时打印 "触发更新"。再写一个 effect(fn)：第一次执行 fn，之后每次 .value 变化自动重新执行 fn。用它验证"读收集依赖、写触发更新"这个最小模型。

答案：

  let currentEffect = null
  function myRef(init) {
    let _v = init
    const deps = new Set()
    return {
      get value() { if (currentEffect) deps.add(currentEffect); return _v },
      set value(n) { _v = n; deps.forEach(fn => fn()) }
    }
  }
  function effect(fn) { currentEffect = fn; fn(); currentEffect = null }
  const r = myRef(0)
  effect(() => console.log('render:', r.value))  // 立即打印 render: 0
  r.value = 5   // 打印 render: 5

这就是 Vue ref 的最小模型：get 收集依赖（deps），set 触发更新（重跑 deps 里的 effect）。

A 基础复现解构 bug：写一个 reactive({ count: 0 })，解构出 count，在按钮事件里 count++ 并在模板显示；观察页面是否更新。然后用 toRefs 修复，再验证。

    onUnmounted(() => window.removeEventListener('mousemove', fn))

答案：

  export function useFetch(getUrl) {
    const data = ref(null), loading = ref(false), error = ref(null)
    let ctrl = null
    async function run() {
      ctrl?.abort()
      loading.value = true
      try { data.value = await fetch(getUrl(), { signal: ctrl?.signal }).then(r => r.json()) }

    onUnmounted(() => ctrl?.abort())
    return { data, loading, error }
  }

第 24 章 provide 与 inject 的组合式用法

A 基础把第 18 章的主题 provide/inject 重构成 useThemeProvider / useTheme 两个组合式函数：祖先调 provider 提供 theme（readonly）与 toggle，后代调 consumer 消费；验证后代无法直接 theme.value = 'dark'。

第 29 章 Proxy 基础与拦截时机

A 基础用自己的话说：Vue2 里的 this.$set(obj, 'newKey', 1) 在 Vue3 里为什么不需要了？从 Proxy 的 set 陷阱角度解释。

第 33 章 computed 实现脏检查

答案：Vue Devtools→组件树→看渲染耗时；常见原因：大对象 props、高频 watch、无 key 列表。

C 挑战给项目加事件监听/定时器的统一清理约定，检查现有页面是否有泄漏。

答案：约定 onMounted 加监听必须 onBeforeUnmount 移除；排查现有页面未移除的 addEventListener/setInterval。

第 72 章 大列表与大数据渲染

A 基础实现 72.2 的固定高虚拟列表，渲染 5000 行并对比直接渲染的流畅度。

答案：可视行数=height/rowHeight，start=scrollTop/rowHeight，渲染 [start-buffer,start+visible+buffer]，用 translateY 平移；只渲染几十行。

B 进阶给虚拟列表加"滚动到某行"的方法（scrollToIndex）。

答案：function scrollToIndex(i){ container.scrollTop = i*rowHeight }，触发热度更新。

C 挑战用 shallowRef 改造一个大表格，对比改造前后组件的更新开销。

答案：const rows=shallowRef([]) 后，Vue 跳过深度响应式转换，大列表更新时 diff 只比较浅层，开销显著下降。

第 73 章 面试知识体系梳理与延伸路线

A 基础用一张图给同事讲清 Vue3 响应式从 track 到 trigger 的完整链路。

答案：读取时 track（收集 effect）→ 修改时 trigger（重新执行 effect）→ effect 触发 render → diff → patch。

B 进阶把你做过的一个项目亮点，按"背景—方案—取舍—结果"写成 200 字介绍。

答案：背景（列表卡顿）→方案（虚拟列表+shallowRef）→取舍（不选全量分页因为要一次看全）→结果（长任务 180ms→40ms）。

C 挑战在 reactive/ref/computed/虚拟滚动 里挑一个，手写最小实现并讲出设计理由。

答案：reactive 用 Proxy，get 时 track、set 时 trigger；理由：Proxy 能感知新增属性、数组下标，比 defineProperty 更适合对象响应式。
