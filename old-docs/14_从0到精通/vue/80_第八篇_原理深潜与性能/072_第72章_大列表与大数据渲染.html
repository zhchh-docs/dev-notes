72.1 为什么需要虚拟列表

一次渲染 10000 行，意味着 10000 个 DOM 节点。浏览器渲染节点数是有上限的，再多就会卡顿、掉帧。虚拟列表的思路：只渲染可视区内的几十行，其余用占位高度撑起滚动条。

72.2 手写固定高度虚拟列表

<script setup>
import { ref, computed } from 'vue'
const props = defineProps({
  data: { type: Array, required: true },
  rowHeight: { type: Number, default: 40 },
  height: { type: Number, default: 400 }     // 容器可视高
})
const scrollTop = ref(0)
// 可视区能放几行
const visibleCount = computed(() => Math.ceil(props.height / props.rowHeight))
// 起始行索引
const start = computed(() => Math.floor(scrollTop.value / props.rowHeight))
// 渲染 [start-缓冲, start+visible+缓冲] 的窗口
const buffer = 3
const visibleData = computed(() => {
  const s = Math.max(0, start.value - buffer)
  const e = Math.min(props.data.length, start.value + visibleCount.value + buffer)
  return props.data.slice(s, e).map((item, i) => ({ item, index: s + i }))
})
// 总高度撑起滚动条，内容用 transform 平移
const totalHeight = computed(() => props.data.length * props.rowHeight)
const offsetY = computed(() => (start.value - buffer) * props.rowHeight)
</script>

<template>
  <div :style="{ height: height + 'px' }" @scroll="scrollTop = $event.target.scrollTop">
    <div :style="{ height: totalHeight + 'px' }">
      <div :style="{ transform: `translateY(${offsetY}px)` }">
        <div v-for="{item, index} in visibleData" :key="index"
             :style="{ height: rowHeight + 'px' }">
          {{ item.name }}
        </div>
      </div>
    </div>
  </div>
</template>

要点：总高度撑滚动条，真正渲染的那几十行用 translateY 移到对应位置，视觉上像整列都在。

72.3 第三方库与降响应式开销

  • vue-virtual-scroller：处理不定高行、自动测量，复杂场景直接用库；
  • 分页/懒加载：数据本身不要一次拉全，后端分页是更治本的方案；
  • 时间分片：必须处理大批数据时，用 requestIdleCallback 分批，别阻塞主线程；
  • 降响应式开销：大列表数据不需要深度响应式时，用 shallowRef、markRaw 或 Object.freeze，跳过 Proxy 转换。
import { shallowRef, markRaw } from 'vue'
// 只读展示的大列表：shallowRef 省去深度响应式
const list = shallowRef(rawData)
// 或在取数后冻结，Vue 不再给它包 Proxy
const rows = ref(data.map(markRaw))
权衡Object.freeze 后数据不能改。凡是要就地更新行数据的场景，别 freeze，改用 shallowRef 按需替换整个数组。
// 时间分片：必须一次处理大批数据时，让主线程喘口气
function processBatch(items, i = 0) {
  const end = Math.min(i + 100, items.length)
  for (; i < end; i++) handle(items[i])
  if (i < items.length) requestIdleCallback(() => processBatch(items, i))
}

72.4 动态高度的虚拟列表处理

行高不固定时，无法用"可视行数 = 容器高 / 行高"直接算窗口。做法是：先给每行一个估计高度，渲染后实测真实高度并缓存，滚动位置按"已渲染行的累计高度"推算。

// 不定高虚拟列表：估计高度 + 渲染后实测缓存
const EST = 40                 // 初始估计行高
const heights = new Map()      // 实测高度缓存：index -> px
function offsetOf(index) {     // 前 index 行累计高度
  let sum = 0
  for (let i = 0; i < index; i++) sum += heights.get(i) ?? EST
  return sum
}
// 行渲染后回填真实高度
function measure(index, el) { heights.set(index, el.offsetHeight) }
行高情形做法复杂度
固定高可视行=容器高/行高，translateY 平移低，手写即可
近似等高用平均高度估算，误差可接受中
真·不定高实测回填+累计偏移，或直接用 vue-virtual-scroller高，建议用库
坑不定高列表若不实测回填，滚动条总长与可视位置会漂移——要么渲染后测，要么用现成库。

72.5 大数据量下的内存与 GC 注意

一次渲染几万行不只卡渲染，还会常驻一大块内存。数据本身、组件实例、事件监听都要在切走时释放。

  • 数据别全量驻留：后端分页/滚动加载，只保留当前屏附近数据；用 shallowRef/markRaw 去掉无谓的 Proxy 包裹。
  • 组件实例随虚拟列表回收：滚出可视区的行被卸载，其 watcher、事件监听随之销毁——这正是虚拟列表省内存的根源。
  • 避免闭包引用整批数据：回调里若闭包持有大数组，即使 UI 卸载，GC 也回收不掉。
