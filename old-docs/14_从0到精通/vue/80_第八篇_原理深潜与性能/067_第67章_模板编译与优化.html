67.1 编译三阶段

你写的 <div>{{ msg }}</div>，浏览器并不认识。@vue/compiler-sfc 在构建时把它编译成 render 函数，分三步：

阶段做什么产物
parse把模板字符串解析成语法树AST（抽象语法树）
transform遍历 AST，做静态提升、打 patchFlag 等优化标记带优化信息的 AST
generate把 AST 生成 JS 渲染函数字符串render() 代码

67.2 编译产物长什么样

// 源码：<div class="box">你好 {{ msg }}</div>
// 编译后的 render（简化）：
import { createElementVNode as _createElementVNode, toDisplayString as _toDisplayString, openBlock as _openBlock, createElementBlock as _createElementBlock } from "vue"

export function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock("div", { class: "box" },
    "你好 " + _toDisplayString(_ctx.msg)   // 动态部分带 patchFlag
  ))
}

注意：模板里的静态部分被原样保留，动态内容用 _toDisplayString 包裹，并附带优化标记——这就是下一章要讲的 patchFlag。

# 用 @vue/compiler-sfc 查看编译产物（构建时自动完成，这里仅观察）
npx vite build        # 模板已在构建期编译成 render 函数

67.3 编译时 vs 运行时

职责编译时（构建期）运行时（浏览器）
做什么模板→render、静态提升、打 patchFlag执行 render、做 diff、操作 DOM
时机npm run build 时一次完成用户打开页面后每次更新
谁受益把工作前移，运行时更省渲染路径更短

Vue 的很多"性能魔法"其实是在编译时多做一点，让运行时少做很多。

// 运行时拿到的是编译产物，不再解析字符串模板
// render(_ctx, _cache) { return _createElementBlock("div", ...) }
// 运行时只负责：执行 render → diff → patch，不做模板解析
SFC 版 vs 浏览器版：用 @vue/compiler-sfc 构建时，模板在构建期就编译好，运行时体积更小；直接用 CDN 全量版时，编译发生在浏览器里（运行时编译），功能全但略大。

67.4 AST 与 transform 打标的细节

transform 阶段遍历 AST，给每个节点贴上"它是否动态、动态在哪"的标记。看一段具体模板编译后的 AST（简化树）就清楚了：静态节点原样保留，带插值/指令的节点会被记上动态类型。

<div class="box">
  <p>静态文字</p>
  <span>{{ msg }}</span>
</div>

编译后的 AST（节点类型简化）：
Element div(class="box")
├─ Element p            → static（无插值，可提升）
└─ Element span
   └─ Interpolation msg → dynamic: TEXT（patchFlag = 1）

transform 的核心动作：遍历到 {{ msg }} 这种插值时，把所在 span 标上 patchFlag: TEXT；遍历到 v-bind:class 时标 CLASS；遍历到静态节点时交给 hoistStatic 提升。这些标记最终在 generate 阶段写进 render 函数的参数里。

模板写法transform 判定运行时后果
纯静态文本 <p>静态</p>static，可提升只创建一次，diff 跳过
{{ msg }} 插值dynamic: TEXT只比对文本内容
:class="x"dynamic: CLASS只比对 class
@click="fn"cacheHandler 缓存事件只绑定一次，不重复卸载

67.5 编译相关常见问题

  • 浏览器端运行时编译：用 CDN 全量版（vue.global.js）时，模板在浏览器里现编译——功能完整但多付一份编译器体积，且首屏多一步编译。生产项目应走 SFC 构建期编译。
  • 坑 1运行时去改模板字符串再让 Vue 编译，既慢又拿不到编译期优化；正确做法是把"可变部分"写成响应式数据，而不是改模板。
  • 坑 2以为写了 v-once/静态标签就自动提升——hoistStatic 只提升"无任何动态绑定"的节点；只要混了插值，整块都不会被提升。
  • 坑 3把数据塞进 v-html，那部分内容不参与编译，既无 patchFlag 也无事件绑定，富文本里要交互时只能手动处理。

编译期多做一点，运行时少做很多。模板在 build 时变成 render 函数，静态节点被提升、动态节点打 patchFlag。要观察优化是否真生效，构建后在产物里搜 _hoisted_（静态提升）与 patchFlag 数字（动态标记）。

// 观察编译产物（工程骨架）
npm run build
grep -o '_hoisted_[0-9]*' dist/assets/*.js | head   # 静态提升数量
grep -o 'TEXT\|CLASS\|STYLE' dist/assets/*.js | head # patchFlag 标记
// 该提升没提升 = 节点里混了插值/事件，拆静态子树即可
