66.1 为什么需要虚拟 DOM

直接操作 DOM 很慢：每一次 element.style.xxx 都可能触发浏览器重排重绘。虚拟 DOM 的思路是——先在 JS 里描述界面，算好最小改动，再一次性写进真实 DOM。

  • 跨平台：VNode 是 JS 对象，不只渲染到浏览器 DOM，也能渲染到原生/App/WebGL；
  • 批量与最小化：把多次状态变化合并成一次"比对后更新"，避免反复触碰 DOM；
  • 可推导：声明式描述界面，框架负责 diff，开发者不用手动找要改的节点。

虚拟 DOM 不是"比直接操作 DOM 更快"，而是在可维护性与性能之间取平衡：手写最优 DOM 操作更快，但成本是无法维护。

66.2 h() 与 VNode 结构

import { h } from 'vue'
// 一个 VNode 就是描述"界面上一个节点"的普通 JS 对象
const vnode = h(
  'div',                       // type：标签/组件
  { class: 'box', onClick: onOpen },  // props：属性/事件
  [h('span', 'hello')]         // children：子节点
)
// 关键长这样：
// { type:'div', props:{...}, children:[...], key:null, el:真实DOM引用 }
字段含义
type节点类型：标签名字符串、组件对象、Fragment、文本
props属性、事件、指令等
children子 VNode 数组或文本
keydiff 时的身份标识（第 70 章专讲）
el该 VNode 对应的真实 DOM 元素（挂载后才填）

66.3 渲染总链路

图 66-1 渲染链路（示意）

当响应式数据变化，组件的 render 函数重新执行，生成新 VNode 树；框架把它与旧 VNode 树做 diff，只把差异 patch 到真实 DOM。

66.4 diff 策略：同层比较 + 两端对比

两棵树全量递归比较是 O(n³)，不可接受。Vue 采用两个关键假设把成本降到 O(n)：

  • 同层比较：只比较同一层级的节点，不跨层移动节点（跨层移动视为"删旧建新"）；
  • 同类型才复用：type 变了（div→p 或组件 A→组件 B）直接销毁重建；type 相同才深入比较 props/children。
// diff 的核心伪代码（简化）
function patch(n1, n2) {
  if (!n1) mount(n2)                 // 旧节点没有 → 新建
  else if (n1.type !== n2.type) destroy(n1); mount(n2)  // 类型不同 → 重建
  else patchElement(n1, n2)         // 类型相同 → 复用 DOM，比对 props/children
}

对一组带 key 的子节点，Vue 用双端指针（旧头尾、新头尾四个指针）依次比对，尽量复用已有 DOM，减少移动与重建。key 的作用就是告诉框架"哪个新节点对应哪个旧节点"。

// 新旧子节点：旧 [a,b,c] 新 [a,c,b,d]
// 头头：a==a 复用；尾尾：d 是新增挂载
// 中间 b/c 乱序，靠 key 映射找到旧位置，最小化移动
const oldChildren = [a, b, c]
const newChildren = [a, c, b, d]

66.5 常见误区

  • 坑 1以为虚拟 DOM 一定比手写 DOM 快——它是工程平衡，不是银弹。
  • 坑 2以为 diff 会跨层移动节点——不会，跨层变更直接删建。
  • 坑 3把 key 当"排序标记"——key 是身份，不是顺序号（第 70 章）。

虚拟 DOM 不是更快，而是可维护 + 批量最小更新。直接操作 DOM 性能更好但难维护，VDOM 用一层 JS 抽象把 diff 成本降到 O(n)：只同层比较、同类型才复用，跨层移动视为删除+新建。

// 用 h() 手写一个三行列表（工程骨架）
import { h } from 'vue'
export default {
  render() {
    return h('ul', ['A','B','C'].map(t => h('li', t)))
  }
}
// VNode 结构：{ type, props, children, key, el }
O(n) 前提同层比较 + 同类型复用 + key 身份识别，三者缺一，diff 都会退化为全量树比较。

VDOM 不是「更快」，而是「可维护 + 批量最小更新」。它把 diff 压到 O(n)：只同层比较、同类型才复用，跨层移动视为删除+新建。直接操作 DOM 更快但难维护，VDOM 用一层抽象换可维护性。

// h() 手写列表（工程骨架）
import { h } from 'vue'
export default { render(){ return h('ul', ['A','B','C'].map(t=>h('li',t))) } }
要点说明
同层比较只比对同一层级
同类型复用type 相同才复用 DOM
key 身份用 key 识别节点身份

VDOM 的 O(n) 不是白来的：靠同层比较、同类型复用、key 身份识别三条前提。跨层移动被当删除+新建，所以列表重排才要 key——它让 diff 按身份而非位置比对。

// VNode 结构（工程骨架）
// { type, props, children, key, el }
// h('ul', ['A','B','C'].map(t=>h('li',t)))
要点同层+同类型+key 三前提，缺一 diff 退化。

VDOM 把 diff 压到 O(n)：同层比较、同类型复用、key 身份识别。跨层移动当删除+新建，所以列表重排才需要 key——它让 diff 按身份比对，而非按位置。

要点三前提缺一，diff 退化为全量。

VDOM 的价值在跨平台：render 返回的是 VNode 对象，渲染器可以把它渲染成 DOM、Native 或 Canvas。diff 是渲染器内部算法，与视图层解耦。
