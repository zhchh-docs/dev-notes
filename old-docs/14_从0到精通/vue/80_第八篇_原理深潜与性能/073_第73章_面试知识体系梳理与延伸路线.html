73.3 手写题清单与项目亮点

高频手写：reactive / ref / computed / watch / 虚拟滚动 / 简单 diff。手写的关键不是背代码，而是讲清为什么这样设计。

项目亮点组织：用 背景—方案—取舍—结果四段式讲——你遇到什么问题、选了什么方案、为什么不选另一个、最终量化收益。例如"列表页性能"：从一次渲染卡顿，到引入虚拟列表 + shallowRef，长任务从 180ms 降到 40ms。

function track(target, key) { /* 收集当前 effect */ }
function trigger(target, key) { /* 重新执行依赖它的 effect */ }
function reactive(obj) {
  return new Proxy(obj, {
    get(t, k) { track(t, k); return t[k] },
    set(t, k, v) { t[k] = v; trigger(t, k); return true }
  })
}

73.5 模拟面试问答示例

把高频题按"问—答要点"演练一遍。回答时先给结论、再给机制、最后给取舍。

面试官提问你的回答骨架（结论→机制→取舍）
Vue3 响应式怎么实现的？结论：Proxy 包裹对象，访问时 track、修改时 trigger。机制：get 收集依赖 effect，set 派发更新。取舍：Proxy 替代 defineProperty，支持数组/嵌套/ Map，但需深层访问才代理。
computed 和 watch 区别？结论：computed 是派生值、有缓存；watch 是副作用、监听变化做事。机制：computed 惰性重算，watch 回调在值变后异步触发。取舍：派生用 computed，副作用用 watch。
v-for 为什么要 key？结论：key 标识节点身份，diff 据此复用还是重建。机制：无 key 按下标复用，头部插入会错位；有 key 按身份移动 DOM。取舍：用业务 id，别用 index。
Pinia 比 Vuex 好在哪？结论：更轻、TS 友好、无 mutation。机制：store 是函数，state/getters/actions 直接定义。取舍：中小型项目够用，模块化自然。
技巧回答原理题时，用"一句话结论 + 一段机制 + 一个实际例子"三段式，比堆术语更得分。
