70.1 key 是节点身份，不是顺序号

diff 要判断"新列表里的某一项，对应旧列表里的哪一项"，靠的就是 key。key 相同 = 同一个节点，复用 DOM 与组件状态；key 对不上 = 新节点，要重建。

key 的唯一作用是身份标识，让 Vue 在列表变化时正确复用对应节点，而不是按位置瞎猜。

70.2 用 index 作 key 的坑

假设列表 [A, B, C]，每项带一个输入框。我们在头部插入一项，变成 [X, A, B, C]。如果 key 是下标：

// key=index 的后果
// 旧: 0:A(输入"a")  1:B  2:C
// 新: 0:X          1:A  2:B  3:C
// diff 按下标复用：
//   下标0 旧A → 新X：直接把 A 的 DOM 改写成 X 的内容
//   下标1 旧B → 新A：把 B 的 DOM 改写成 A
// 结果：A 输入框里的内容"跑错位置"，状态与节点错位！
为什么错用 index 作 key 时，头部插入会让所有项的下标都平移，Vue 以为"这是不同内容"，把 DOM 挨个改写，连同组件内部状态（输入框、勾选）一起错乱。

70.3 稳定唯一 key 与不写 key

做法后果
用业务 id / 码作 key正确：增删排序都能精准复用对应节点
用 index 作 key有增删/排序时状态错位
完全不写 keyVue 按下标就地复用（无 key 模式），列表会报警告
 
<!-- 正确：用稳定业务 id 作 key -->
<div v-for="user in list" :key="user.id">{{ user.name }}</div>

70.4 key 变化触发重建

反过来，key 变了 Vue 就认为是"另一个节点"，会销毁旧组件、挂载新组件——组件内部状态随之丢失。这既是坑，也是工具：

<!-- 想强制重置一个表单组件：换 key 即可让它全新挂载 -->
<UserForm :key="formVersion" />
<button @click="formVersion++">重置表单</button>

另外，列表配合 <transition-group> 做增删动画时，稳定 key 也是动画正确播放的前提。

70.5 key 与组件复用的边界（SSR / 动画）

key 决定"复用还是重建"，但在两类场景下它的边界要特别留意：SSR 注水（hydration）与列表动画。

场景key 的影响正确做法
SSR 注水前后端渲染出的列表 key 顺序要一致，否则注水 mismatch用稳定业务 id，别用 index
transition-group 动画key 不稳定会导致离场/入场动画错位、重播每行绑业务 id
强制重置组件改 key 让组件销毁重建，内部状态清空:key="version"
同位置切换组件不同组件类型天然不复用；同类型不同 key 才重建区分"类型变"与"key 变"
 
<!-- transition-group：每行绑业务 id，增删动画才正确 -->
<transition-group name="list" tag="ul">
  <li v-for="u in users" :key="u.id">{{ u.name }}</li>
</transition-group>
<!-- SSR 注水要求前后端 key 顺序一致，index 会错位 -->

key 决定「复用还是重建」。index 作 key 在头部插入时会让下标平移，DOM 与状态错位；用业务 id 作 key，diff 才能按身份识别节点、正确移动 DOM。SSR 注水时前后端 key 顺序必须一致，否则 mismatch。

key 是节点的身份证：diff 靠它认出「这是同一个」，从而正确移动 DOM、保留状态。用 index 等于每换一个人就重发身份证，状态自然错乱。

// 身份证（工程骨架）
// 稳定 id → 正确移动
// index → 下标平移，状态错位

稳定 key 用业务 id，别用 index。SSR 注水前后端 key 顺序须一致，否则 mismatch。key 变化也会触发组件重建、状态丢失。

// 稳定 key（工程骨架）
// :key='user.id'
// 勿用 :key='index'

列表动画配合 key：transition-group 靠 key 识别哪些节点进入/离开/移动，才能播 FLIP 动画。没有稳定 key，动画位置全错。

// transition-group（工程骨架）
//

    // 反例：:key='index'
// 正例：:key='row.id'

    小结：key 决定复用还是重建。用业务稳定 id，别用 index；SSR 与列表动画都依赖稳定 key。

    再强调：index 作 key 在头部插入时整列下标平移，diff 按下标复用会把 A 的 DOM 改写成 X，输入框内容随之错位。这是列表最隐蔽的 bug。

    <!-- 反例 -->
<li v-for="(item,i) in list" :key="i">{{ item.name }}</li>
<!-- 正例 -->
<li v-for="item in list" :key="item.id">{{ item.name }}</li>

    本章要点：稳定 id、勿用 index、SSR 顺序一致、key 变即重建。
