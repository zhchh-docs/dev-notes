69.1 patch 入口：按 type 分发

diff 出差异后，patch 负责把它落到真实 DOM。第一步是看新 VNode 的类型，分发到不同处理函数。

function patch(n1, n2, container) {
  if (n1 == null) {
    mount(n2, container)              // 旧节点没有 → 挂载
  } else {
    const type = n2.type
    if (type === Text)        updateText(n1, n2)      // 文本节点
    else if (type === Fragment) patchChildren(n1, n2) // 片段
    else if (typeof type === 'string') patchElement(n1, n2) // 普通元素
    else                          processComponent(n1, n2) // 组件
  }
}

patch 的第一原则：类型不同直接销毁重建，类型相同才深入比对。

69.2 patchElement 与 patchProps

同类型元素复用上同一个真实 DOM，只更新变化的属性。配合 patchFlag，运行时知道只需比对被标记的那几个 props：

function patchElement(n1, n2) {
  const el = n2.el = n1.el          // 复用同一个 DOM 元素
  patchProps(n1.props, n2.props, n2.patchFlag)
  patchChildren(n1, n2)            // 再递归比对子节点
}

事件更新也在这一步：新事件与旧事件不同就替换，相同则跳过。

69.3 patchChildren 的三种模式

新旧 children 形态处理方式
新节点是文本旧 children 卸载，设 textContent
新节点是数组、旧是文本清空文本，挂载数组节点
新旧都是数组（keyed）走 keyed diff 算法（69.4）
新旧都是数组（无 key）按下标顺序就地复用，不做移动

69.4 keyed diff 的实际步骤

Vue 3 的 keyed diff 用四个指针，先做头头、尾尾的快速对比，再处理中间不确定的部分：

  1. 从头比：新旧开头节点 key 相同就复用，指针后移；
  2. 从尾比：新旧结尾 key 相同就复用，指针前移；
  3. 经过两步后，若一边已耗尽，就把另一边剩余节点挂载或卸载；
  4. 剩下乱序的中间部分：建立新节点的 key→索引映射，遍历旧剩余，按最长递增子序列减少 DOM 移动次数。

69.5 常见误区

  • 坑 1以为 patch 会重建整个 DOM——它复用元素，只改变化的 props/子树。
  • 坑 2无 key 时以为会智能排序——无 key 按下标就地复用，乱序列表会出错。
  • 坑 3忽略 transition 钩子：进出场动画正是在挂载/卸载节点的时机被插入的。
// patch 最小流程回顾：同类型 → 复用 el → 只改 props/children
function patchElement(n1, n2) {
  n2.el = n1.el               // 不新建 DOM
  patchProps(n1.props, n2.props, n2.patchFlag)
  patchChildren(n1, n2)
}

patch 的核心是「复用优先」：同类型节点复用同一 DOM，patchProps 只改变化的属性；事件更新走专门路径，不会整 props 扫描。keyed diff 先做头头、尾尾复用，中间乱序用映射表最小移动 DOM。

// patchProps：只更新变化的属性（工程骨架）
function patchProps(el, oldProps, newProps) {
  for (const k in newProps) {
    if (oldProps[k] !== newProps[k]) el.setAttribute(k, newProps[k])
  }
  for (const k in oldProps) {
    if (!(k in newProps)) el.removeAttribute(k)
  }
}
事件事件更新走缓存路径（cacheHandlers），不会每次 render 新建函数触发 props 无谓更新。
