1.1 Vue 是什么

一句话定义：Vue 是一套用于构建用户界面的渐进式 JavaScript 框架。它把"数据"和"页面"连起来，你只管改数据，页面自己更新。

把这句话拆成三个关键词：

  • 构建用户界面：Vue 的核心职责只有一件事——把数据渲染成界面，并在数据变化时更新界面。路由、请求、状态管理都不属于"核心"，它们是生态。
  • 框架：与库（library）不同，框架规定了代码该怎么写、往哪放（组件、模板、生命周期），你按它的约定来，它替你干活。
  • 渐进式：可以只用一小块，也可以全套都用。下一节详说。

Vue 替你承担的最累的一件事是：数据变了以后，手动去找 DOM、改 DOM 的那一整套脏活。

在原生开发里，"数据 → 界面"这一步是你自己写的；在 Vue 里，你声明"界面长什么样、绑定哪些数据"，剩下的同步工作交给框架。这中间的差别，就是下一节的主题。

1.2 声明式 vs 命令式

这是整本书最核心的一组概念。命令式：你一步步告诉程序"先做什么再做什么"；声明式：你只描述"结果是什么"，过程由框架决定。

同一个需求：点击按钮，计数加一并显示在页面上

命令式写法（原生 JavaScript）

<button id="btn">点了 0 次</button>

<script>
  // 1. 自己维护数据
  let count = 0
  // 2. 自己找 DOM
  const btn = document.querySelector('#btn')
  // 3. 自己写"数据变了以后做什么"
  function render() {
    btn.textContent = `点了 ${count} 次`
  }
  // 4. 自己绑定事件
  btn.addEventListener('click', () => {
    count++
    render()   // 忘了这一行，页面就不更新 —— 新手最常见的 bug
  })
</script>

这段代码的每一个步骤都得你写：数据放在哪、DOM 怎么找、什么时候更新、更新哪些节点。规模一大，"同步"逻辑会散落各处，改一个字段要改五六处 DOM 操作。

声明式写法（Vue 3）

<template>
  <button @click="count++">点了 {{ count }} 次</button>
</template>

<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

对比一下你"没写"的东西：

  • 没有 querySelector——不需要自己找 DOM；
  • 没有 textContent = ...——不需要手动改 DOM；
  • 没有 render()——不需要记得"改完数据要刷新"；
  • 没有 addEventListener——@click 就是绑定。

命令式关心"怎么做（How）"，声明式关心"是什么（What）"。Vue 的响应式系统负责把 What 翻译成 How。

代价是什么

声明式不是免费的：框架需要在内存里维护一份虚拟 DOM 描述界面，数据变化时做比对（diff），再决定最小更新范围。这就是为什么"框架有开销"，也是第八篇性能优化的由来。

维度命令式声明式
心智负担随规模指数上升（要自己维护同步）平缓（只描述结果）
性能上限理论上可手写最优解多一层 diff 开销，但 Vue3 编译优化已极小
可维护性数据与视图耦合在一处数据独立、视图可测试
适合场景极致性能动画、局部微交互绝大多数业务界面

1.3 渐进式的三层含义

"渐进式"是 Vue 官方对自己的定位，实际体现在三个层面：

第一层：接入成本可渐进

你可以只引一个 CDN 脚本，在一个老页面里增强一小块交互——不需要构建工具、不需要重写整个站点：

<!-- 一个传统服务端渲染页面里，只让这一块"活"起来 -->
<div id="app">{{ message }}</div>

<script type="module">
  import { createApp, ref } from 'https://unpkg.com/vue@3/dist/vue.esm-browser.js'
  createApp({
    setup() {
      const message = ref('这段内容由 Vue 渲染')
      return { message }
    }
  }).mount('#app')
</script>

第二层：功能可渐进

核心库只管渲染。需要路由就加 Vue Router，需要全局状态就加 Pinia，需要工程化就上 Vite——按需引入，不强买强卖。

第三层：写法可渐进

同一个组件里，你可以用选项式 API（data/methods/computed）也可以用组合式 API（ref/computed/setup），甚至可以混用。这让庞大老项目能够逐模块迁移，而不是一次性重写。

1.4 Vue3 相比 Vue2 变了什么

如果你接触过 Vue2，下面这张表能帮你把旧知识重新对齐到 Vue3：

维度Vue 2Vue 3
响应式实现Object.defineProperty 逐个劫持属性Proxy 代理整个对象，能感知新增属性、数组下标
主力写法选项式 API（data/methods）组合式 API（ref/reactive/setup）+ <script setup>
逻辑复用mixins（命名冲突、来源不清）组合式函数（显式输入输出，可传参）
组件根节点必须有且只有一个根元素支持多根节点（Fragment）
v-model一个组件只能一个 v-model支持 v-model:title 多个，组件内用 defineModel
TypeScript支持有限源码用 TS 重写，类型推导完善
性能—编译期优化（静态提升、patch flag）、体积更小、diff 更快
为什么要提这些：你在网上搜到的很多教程/答案还是 Vue2 写法。看到 this.xxx、data() { return {} }、Vue.use() 时，要知道那是上一代写法——本书主线是 Vue3。

1.6 本章常见误区

  • 坑 1把 Vue 当 jQuery 用：在 mounted 里写一堆 document.querySelector 手动改 DOM。结果两套更新逻辑打架，数据变了页面却"时灵时不灵"。——正确做法：所有界面变化都回到模板和数据。
  • 坑 2以为"改了变量页面就该变"：只有响应式数据的变化才会触发更新。普通变量（let x = 1）不会。这就是第 20 章要讲"为什么要用 ref 包一层"的原因。
  • 坑 3直接替换整个响应式对象导致失效：reactive 创建的代理被重新赋值后，旧引用失去响应性（第 21 章详解）。
  • 坑 4一上来就 npm 装全家桶：还没搞懂组件通信就上 Pinia，会把所有状态塞进全局 store，后期难以拆分。第 38 章会给判断标准。
