2.1 前置：Node 与包管理器

Vue 的构建工具跑在 Node.js 上，所以第一步是装 Node（它自带 npm）。

软件要求说明
Node.js建议 18 LTS 及以上Vite 5+ 要求 Node 18+；太低会在安装或启动时报奇怪的错
npm随 Node 安装官方包管理器，npm -v 查看版本
pnpm（可选）推荐团队项目用磁盘占用小、安装快，命令与 npm 基本一致
VS Code + Volar编辑器Vue 官方推荐插件（禁用 Vetur，它与 Vue3 冲突）
 
# 检查环境
node -v     # 例：v18.19.0
npm -v      # 例：10.2.3

# 设置国内镜像（网络不畅时强烈建议先做这一步）
npm config set registry https://registry.npmmirror.com
坑项目路径不要包含中文或空格。诸如 D:\我的 项目\vue app 会导致某些依赖在解析路径时出错，报错信息往往与真实原因毫无关联，排查成本极高。

2.2 用 create-vue 创建项目

官方脚手架叫 create-vue（不是老的 vue-cli）。执行后会进入交互式问卷：

npm create vue@latest my-vue-app
# 或 pnpm create vue my-vue-app

# 交互式选项（本书示例一律按下表选择）
# ✔ Add TypeScript?                …… No（前四篇先不用，第 34 章后引入）
# ✔ Add JSX Support?               …… No
# ✔ Add Vue Router for SPA?        …… Yes（第六篇要用；现在也可 No）
# ✔ Add Pinia for state management?…… Yes（第五篇要用）
# ✔ Add Vitest for Unit Testing?   …… No
# ✔ Add an End-to-End Testing?     …… No
# ✔ Add ESLint for code quality?   …… Yes

cd my-vue-app
npm install
npm run dev

看到终端打印 VITE v5.x ready in xxx ms 与 http://localhost:5173/，浏览器打开就是你的第一个 Vue 应用。

为什么不用 vue-cli：vue-cli 是 Webpack 时代的脚手架，已停止新增特性。Vue3 生态的构建工具统一到 Vite，官方脚手架也随之换成 create-vue。

如果只想快速试一个组件

不想建工程时，可以用官方在线演练场（Vue SFC Playground）或第 1 章的 CDN 方式。本书所有"小例子"都能在演练场里跑。

2.3 目录结构逐个认识

my-vue-app
├── index.html              # 页面模板入口（注意：不是 public 里的）
├── package.json            # 依赖清单 + 脚本命令
├── vite.config.js          # Vite 配置（别名、代理、插件）
├── public/                 # 静态资源，原样拷贝到产物根目录
│   └── favicon.ico
└── src/
    ├── main.js             # 应用入口：创建 Vue 实例并挂载
    ├── App.vue             # 根组件
    ├── components/         # 通用组件
    ├── views/              # 页面级组件（配了 Router 时）
    ├── router/             # 路由配置（第六篇）
    ├── stores/             # Pinia store（第五篇）
    └── assets/             # 会被打包处理的资源（图片、样式）
文件作用与注意点
index.htmlVite 的入口 HTML，里面只有 <div id="app"></div> 和一个 <script type="module" src="/src/main.js">。开发时直接以此为页面，与 Webpack 的"模板注入"思路不同
src/main.js创建应用实例、注册插件（Router/Pinia）、挂载到 #app
src/App.vue根组件，通常放布局与 <RouterView>
vite.config.js配置 @ 别名、开发代理 server.proxy、构建产物目录等
public/ vs assets/public 里的文件不参与打包、用绝对路径 /xxx.png 引用；assets 里的会被处理（压缩、加 hash），用相对路径 import

2.4 入口文件与挂载过程

这是全书最需要背下来的一段代码：Vue 应用是怎么从 JS 变成页面的。

// src/main.js
import { createApp } from 'vue'
import App from './App.vue'
import { createPinia } from 'pinia'
import router from './router'

import './assets/main.css'

const app = createApp(App)   // ① 用根组件创建"应用实例"

app.use(createPinia())       // ② 装插件（顺序无关，但要在 mount 之前）
app.use(router)

app.mount('#app')            // ③ 挂载：把渲染结果放进 #app 这个 DOM 里
  1. createApp(App)：以 App.vue 为根组件创建一个应用实例。Vue3 用应用实例代替了 Vue2 的全局 Vue 对象——这样多个应用实例之间不会互相污染全局配置。
  2. app.use(...)：安装插件（Router、Pinia、自定义组件库）。必须在 mount 之前调用。
  3. app.mount('#app')：真正开始渲染。它会清空 #app 里原有的内容，把组件树渲染成真实 DOM 插进去。

Vue 只接管 #app 这一块 DOM。页面里 #app 之外的 HTML（比如服务端渲染的头部）Vue 不会碰——这也是 Vue 能"渐进式嵌入老页面"的原因。

2.5 三条命令：dev / build / preview

命令做什么什么时候用
npm run dev启动开发服务器（默认 5173），带热更新 HMR日常开发
npm run build打包到 dist/：压缩、tree-shaking、hash 文件名发布前
npm run preview本地起一个静态服务器预览 dist/发布前自检（务必做）
 
npm run build
# vite v5.x building for production...
# ✓ 42 modules transformed.
# dist/index.html                  0.62 kB │ gzip:  0.39 kB
# dist/assets/index-Cx8fD2k1.js   88.41 kB │ gzip: 34.12 kB
坑preview 不等于 dev：很多问题（路由 history 模式 404、环境变量、资源路径）只在构建产物里出现。上线前一定要跑一次 build + preview，而不是只测 dev。

2.6 Vite 到底做了什么

理解两点就够了：

  1. 开发态：不打包。浏览器原生支持 ES Module，Vite 只在浏览器请求某个文件时才即时编译它，所以启动是"秒开"、改文件是"局部热更新"，与项目大小几乎无关。
  2. 生产态：用 Rollup 打包。因为线上不能让浏览器发几百个模块请求，所以要合并压缩。

最常用的两项配置

// vite.config.js
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))  // @ 指向 src
    }
  },
  server: {
    port: 5173,
    proxy: {                       // 开发代理：解决跨域
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
        // rewrite: p => p.replace(/^\/api/, '')
      }
    }
  }
})

配了别名后，组件里就能写 import UserCard from '@/components/UserCard.vue'，不用再数 ../../..。

2.7 本章常见坑

  • 坑 1Node 版本过低：报 You are using Node.js xx, which is not supported 或各种 crypto.hash is not a function。升级 Node 到 18+ 即可。
  • 坑 2装了 Vetur 插件：与 Vue3 的 <script setup> 冲突，出现满屏报错。禁用 Vetur，改用 Vue - Official（Volar）。
  • 坑 3依赖装不上 / 卡住：先换镜像源（npm config set registry）；仍失败删掉 node_modules 与 package-lock.json 重装。
  • 坑 4把资源放错目录：需要被处理（压缩/加 hash）的放 src/assets；必须保持原文件名（如 robots.txt）的放 public。
  • 坑 5改了 vite.config.js 不生效：配置文件变更后需要重启 dev server，它不像业务代码那样会自动热更新。

要点一句话

✎ 本章习题

A 基础创建项目后，把浏览器地址栏的端口改成别的（在 vite.config.js 配 server.port），确认修改生效，并说出为什么改配置后要重启服务。
B 进阶在 vite.config.js 里配置 @ 别名，然后把 App.vue 里对组件的相对路径引用全部改成 @/components/... 形式，跑通 dev 与 build 两种模式。
C 挑战执行 npm run build 后用 npm run preview 打开产物，打开浏览器 Network 面板，记录产物文件名里的 hash 值；再改一行代码重新构建，观察 hash 的变化并解释它解决了什么问题。
