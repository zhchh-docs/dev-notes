9.1 事件绑定与事件对象

<template>
  <!-- ① 方法处理器：默认拿到原生事件对象 -->
  <button @click="onClick">点击</button>

  <!-- ② 内联调用：可传业务参数，但拿不到 event -->
  <button @click="remove(item.id)">删除</button>

  <!-- ③ 业务参数 + 事件对象：用 $event 占位 -->
  <button @click="remove(item.id, $event)">删除</button>

  <!-- ④ 内联语句 -->
  <button @click="count++">{{ count }}</button>

  <!-- ⑤ 绑定多个处理函数（Vue 3 支持数组） -->
  <button @click="[save, log]">保存并记录</button>
</template>

<script setup>
import { ref } from 'vue'
const count = ref(0)

function onClick(e) {
  console.log(e.target)        // 触发事件的 DOM 元素
  console.log(e.currentTarget) // 绑定事件的元素（冒泡时两者不同）
}
function remove(id, e) {
  e.stopPropagation()          // 阻止冒泡（但更推荐用 .stop 修饰符，见 9.2）
  console.log('删除', id)
}
function save() { console.log('保存') }
function log() { console.log('记录日志') }
</script>

记住这个对照：@click="fn" → fn(event)；@click="fn(1)" → fn(1)；@click="fn(1, $event)" → fn(1, event)。

9.2 五大事件修饰符

修饰符是 Vue 提供的声明式语法糖，让"阻止冒泡""阻止默认行为"这类 DOM 细节不污染业务方法。

修饰符等价代码典型场景
.stope.stopPropagation()子元素点击不触发父容器事件（卡片里的按钮）
.prevente.preventDefault()阻止表单默认提交、阻止链接跳转
.capture使用捕获阶段监听（从外向内）需要先于子元素处理时
.self只有 e.target === e.currentTarget 才触发点击遮罩层关闭弹窗，但点内容区不关
.once只触发一次引导提示、一次性上报
 
<template>
  <!-- 阻止冒泡 -->
  <div class="card" @click="openDetail">
    <button @click.stop="deleteItem">删除</button>
  </div>

  <!-- 阻止表单默认提交 -->
  <form @submit.prevent="onSubmit">
    <input v-model="name">
    <button type="submit">提交</button>
  </form>

  <!-- 点遮罩关闭弹窗，点内容不关 -->
  <div class="mask" @click.self="close">
    <div class="dialog">内容区</div>
  </div>

  <!-- 链式：先阻止冒泡再阻止默认 -->
  <a href="/detail" @click.stop.prevent="onLinkClick">链接</a>

  <!-- 只触发一次 -->
  <button @click.once="firstClick">首次点击奖励</button>
</template>
为什么推荐修饰符：① 方法里只剩业务逻辑，纯粹可测；② 模板上一眼能看出事件行为；③ 顺序语义明确（.stop.prevent 与 .prevent.stop 产生相同的调用顺序，但 Vue 会按固定顺序生成代码，避免手写时的顺序错误）。

9.3 按键修饰符

<template>
  <!-- 回车提交：最常见 -->
  <input v-model="keyword" @keyup.enter="search">

  <!-- Esc 关闭 -->
  <input @keyup.esc="clear">

  <!-- 组合键：Ctrl + S 保存 -->
  <div tabindex="0" @keydown.ctrl.s.prevent="save">编辑区</div>

  <!-- 直接用 KeyboardEvent.key 的短横线写法 -->
  <input @keyup.page-down="nextPage">
  <input @keyup.arrow-up="prev">
</template>

常用按键别名：

类别别名
按键.enter .tab .delete（Delete/Backspace） .esc .space .up .down .left .right
系统修饰键.ctrl .alt .shift .meta（Mac 的 Command / Win 键）
 
<template>
  <!-- 精确控制：只有 Ctrl+A 才触发，多按了 Shift 就不触发 -->
  <input @keydown.ctrl.a.exact="selectAll">

  <!-- 不加 exact：Ctrl+Shift+A 也会触发 -->
  <input @keydown.ctrl.a="selectAll">

  <!-- 只按 Ctrl（不配合其他键） -->
  <div @click.ctrl.exact="onCtrlClick"></div>
</template>
坑组合键必须一起按下才触发：写 @keydown.ctrl.s 时，若先按 Ctrl 再松开再按 S，不会触发。另外注意浏览器自身快捷键（如 Ctrl+S 保存网页）需要 .prevent 才能拦住。

9.4 鼠标与 exact 修饰符

<template>
  <!-- 左键 / 右键 / 中键 -->
  <div @click.left="onLeft">左键</div>
  <div @click.right.prevent="showContextMenu">右键（阻止浏览器菜单）</div>
  <div @click.middle="onMiddle">中键</div>

  <!-- exact：只按住指定键，不多不少 -->
  <button @click.ctrl.exact="onCtrlOnly">仅 Ctrl+点击</button>
</template>
写法含义区别
@click.ctrl按住 Ctrl 时点击同时按了 Shift 也会触发
@click.ctrl.exact只按住 Ctrl 时点击多按其他键就不触发
@click.exact没按任何修饰键时点击—

9.5 passive 与滚动性能

.passive 告诉浏览器：我的处理函数不会调用 preventDefault()，浏览器可以放心地立即滚动，不必等待 JS 执行完。

<template>
  <!-- 移动端滚动卡顿的经典优化：passive 让滚动不被 JS 阻塞 -->
  <div class="scroll-area" @scroll.passive="onScroll"></div>

  <!-- touchstart 同理 -->
  <div @touchstart.passive="onTouchStart"></div>
</template>
不要同时用 .passive 和 .prevent：语义矛盾（一个承诺不阻止默认行为，一个要阻止），.prevent 会被忽略，浏览器控制台会给出警告。

对比一下三者的使用场景：

修饰符目的场景
.once只执行一次首屏引导、一次性埋点
.passive承诺不阻止默认行为scroll / touch 的流畅度优化
.capture捕获阶段触发需要在子组件之前拦截事件

9.6 自定义事件与原生事件的区分

在原生元素上，@click 是 DOM 事件；在组件上，@click 默认被当作组件自定义事件（由子组件 emit('click') 触发）。

<template>
  <!-- 原生元素：DOM 事件 -->
  <button @click="onNativeClick">原生按钮</button>

  <!-- 组件：默认是自定义事件（需要子组件 emit('submit')） -->
  <MyForm @submit="onSubmit" />

  <!-- 想在组件的根元素上监听原生事件：加 .native 的替代写法 -->
  <!-- Vue3 移除了 .native！组件上写 @click 若子组件未 emit，会落到根元素（透传） -->
  <MyButton @click="onBtnClick" />
</template>
Vue3 变化Vue2 的 .native 修饰符已被移除。Vue3 中组件未声明为 emits 的事件监听器，会作为透传属性落到根元素上，表现为"监听了原生事件"。若子组件用 defineEmits 声明了该事件，则优先作为自定义事件处理。详见第 12、18 章。

自定义事件的完整机制（defineEmits、事件校验）在第 12 章讲。

9.7 本章常见坑

  • 坑 1传参后拿不到 event：@click="fn(1)" 里没有 event，需要 fn(1, $event)。
  • 坑 2.self 与 .stop 混淆：.self 只跳过"子元素冒泡上来"的事件，但不阻止继续向外冒泡；要阻止冒泡必须加 .stop。
  • 坑 3组合键失效：需同时按下；且浏览器保留快捷键要配合 .prevent。
  • 坑 4.passive 与 .prevent 同用：语义冲突，prevent 被忽略。
  • 坑 5在组件上监听原生 click 却没生效：子组件可能没渲染根元素（多根）或未透传 attrs；也可能子组件声明了 emits 却没 emit（第 18 章）。
  • 坑 6忘记在组件卸载时移除全局监听：window.addEventListener 不会随组件自动移除，需 onUnmounted 清理（第 27 章）。

✓ 本章小结

要点一句话
参数传递fn 拿 event；fn(a) 只拿参数；$event 补事件对象
事件修饰符.stop 阻止冒泡、.prevent 阻止默认、.self 仅自身、.once 一次、.capture 捕获
按键修饰符.enter/.esc/.ctrl 等；组合键需同时按；.exact 精确匹配
鼠标修饰符.left/.right/.middle；右键常配 .prevent
passive承诺不 preventDefault，提升滚动流畅度；不可与 prevent 同用
Vue3 变化移除 .native，未声明的监听器透传到根元素
