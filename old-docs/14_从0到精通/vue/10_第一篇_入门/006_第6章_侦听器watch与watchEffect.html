6.1 watch：监听指定数据源

import { ref, reactive, watch } from 'vue'

const count = ref(0)
const user = reactive({ name: '小明', age: 18 })

// ① 监听一个 ref（最常见）
watch(count, (newVal, oldVal) => {
  console.log(`count: ${oldVal} → ${newVal}`)
})

// ② 监听一个 getter（想只关心对象的某个字段时用）
watch(
  () => user.age,
  (newVal, oldVal) => { console.log('年龄变了', newVal) }
)

// ③ 监听多个源：任一个变化都触发
watch(
  [count, () => user.name],
  ([newCount, newName], [oldCount, oldName]) => {
    console.log(newCount, newName)
  }
)
监听目标说明
ref直接传；回调拿到 (新值, 旧值)
reactive 对象直接传会隐式开启 deep（见 6.2）；建议改用 getter 精确定位字段
getter 函数() => obj.a.b；精确监听某条路径，性能最好
数组多源监听，回调参数是两个数组

监听 reactive 对象的某个属性时，必须写成 getter（() => state.count），不能直接写 state.count——后者传进去的是一个数字常量，没有响应性。

6.2 immediate 与 deep

immediate：创建时立刻执行一次

// 需求：页面进来就拉一次数据，之后筛选条件变了再拉
watch(
  () => filters.value,
  fetchList,
  { immediate: true }   // 否则要手动再调一次 fetchList()
)

典型场景：立即拉取数据、初始化第三方库。

deep：深度监听

const form = reactive({ user: { name: '小明', tags: ['a'] } })

// 浅层：只关心 form 被整体替换
watch(form, cb)

// 深层：任意层级的字段变化都触发
watch(form, cb, { deep: true })

// 更推荐：精确定位，避免整树遍历
watch(() => form.user.name, cb)

deep: true 会递归遍历对象所有属性，在大对象上代价明显。能用 getter 精确定位就别用 deep。

选项默认何时开
immediatefalse需要"首次也执行"时
deepfalse（监听 reactive 对象时隐式 true）确实无法预知哪个层级会变时
flush'pre'需要 DOM 更新后再执行时设为 'post'
 
// flush: 'post' —— 想在 DOM 更新后操作 DOM / 拿最新布局
watch(count, () => {
  console.log(el.value.offsetHeight)  // DOM 已更新
}, { flush: 'post' })

6.3 watchEffect：自动收集依赖

watch 需要你显式指出监听谁；watchEffect 不指定源，它执行一遍函数，用到谁就监听谁。

import { ref, watchEffect } from 'vue'

const keyword = ref('')
const page = ref(1)

// 不需要声明依赖：函数里读了 keyword 和 page，它们就自动成为依赖
watchEffect(() => {
  console.log('查询条件：', keyword.value, page.value)
  fetchList({ keyword: keyword.value, page: page.value })
})

// watch 的等价写法要显式列出依赖，重复且易漏
watch([keyword, page], () => {
  fetchList({ keyword: keyword.value, page: page.value })
}, { immediate: true })

三个特点：

  1. 立即执行：创建时就跑一次（相当于自带 immediate: true）；
  2. 自动收集：函数体里读到的响应式数据都被追踪；
  3. 拿不到旧值：回调只接收一个 onCleanup 参数。
// watchEffect 的回调参数是"清理函数注册器"
watchEffect((onCleanup) => {
  const timer = setTimeout(() => { /* ... */ }, 500)
  onCleanup(() => clearTimeout(timer))   // 下次执行前 / 停止时清理
})
坑watchEffect 只追踪同步执行期间读到的依赖。写在 await 之后的代码里读的响应式数据不会被追踪——这是最常见的"为什么它不更新"的原因。

6.4 watch vs watchEffect 如何选择

维度watchwatchEffect
依赖声明显式指定自动收集（函数里读了谁就是谁）
首次执行默认不执行（需 immediate）立即执行
旧值能拿到 (new, old)拿不到
精确控制强（只监听某个字段）弱（可能多监听了分支里的值）
适合需要旧值 / 精确监听 / 懒执行依赖多且分散、逻辑"就这一段"

选择口诀：要旧值、要精确 → watch；要省事、要立即执行 → watchEffect。

还有一个常见的替代思路——根本不用侦听器：

// ❌ 用侦听器"同步"两个状态
const total = ref(0)
watch([price, count], () => { total.value = price.value * count.value })

// ✅ 用计算属性
const total = computed(() => price.value * count.value)

6.5 停止侦听与清理副作用

自动停止

在 <script setup> 或组件的 setup() 里同步创建的侦听器，会随组件卸载自动停止，一般不用管。

手动停止

const stop = watch(count, cb)

// 条件满足后主动停掉
if (someCondition) stop()

// 异步创建的侦听器必须手动停（组件已卸载的话，自动清理不会生效）
let stopAsync
setTimeout(() => {
  stopAsync = watch(count, cb)
}, 1000)
onUnmounted(() => stopAsync && stopAsync())

清理过期副作用（onCleanup）

这是写出"正确异步"的关键：侦听器回调被再次触发或侦听器停止时，先执行上一次注册的清理函数。

watch(id, (newId, oldId, onCleanup) => {
  let cancelled = false
  onCleanup(() => { cancelled = true })   // 下一次触发前把上次的请求作废

  fetchDetail(newId).then(res => {
    if (cancelled) return                  // 过期响应直接丢弃
    detail.value = res
  })
})

没有这段清理，快速切换 id 时会出现响应竞态：先发的请求后返回，把新数据覆盖成旧数据。

6.6 实战一：搜索防抖

<template>
  <input v-model="keyword" placeholder="输入关键字搜索">
  <p v-if="loading">搜索中…</p>
  <ul>
    <li v-for="item in results" :key="item.id">{{ item.title }}</li>
  </ul>
</template>

<script setup>
import { ref, watch } from 'vue'

const keyword = ref('')
const results = ref([])
const loading = ref(false)

watch(keyword, (kw, _, onCleanup) => {
  if (!kw.trim()) { results.value = []; return }

  loading.value = true
  const timer = setTimeout(async () => {
    try {
      const res = await fetch(`/api/search?q=${encodeURIComponent(kw)}`)
      results.value = await res.json()
    } finally {
      loading.value = false
    }
  }, 300)                       // 300ms 防抖

  onCleanup(() => clearTimeout(timer))   // 关键字再变：取消上一次定时器
})
</script>

要点：onCleanup 让"上一次还没发出的请求"被取消，用户连续输入时只会发最后一次请求。

这个逻辑在真实项目里通常抽成组合式函数（第 23 章）或直接复用 VueUse 的 useDebounceFn / refDebounced。

6.7 实战二：监听路由参数拉数据

<script setup>
import { ref, watch } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const detail = ref(null)

// 路由参数变化（/user/1 → /user/2）时重新拉取
watch(
  () => route.params.id,
  (id) => { loadDetail(id) },
  { immediate: true }        // 首次进入也要拉
)

async function loadDetail(id) {
  detail.value = null
  const res = await fetch(`/api/users/${id}`)
  detail.value = await res.json()
}
</script>

这里有个高频陷阱：组件没被销毁时（例如 /user/1 跳到 /user/2 复用同一个组件），onMounted 不会再次执行，只有侦听路由参数才能拿到新数据。

6.8 本章常见坑

  • 坑 1监听 props.xxx 写成常量：watch(props.count, ...) 传的是数字。正确：watch(() => props.count, ...)。
  • 坑 2新旧值相同：监听 reactive 对象时（隐式 deep），回调里的 newVal 与 oldVal 是同一个对象引用，比较无意义。请监听具体字段。
  • 坑 3在 await 之后读依赖：watchEffect 收集不到异步后的依赖。
  • 坑 4忘了清理：定时器、请求、事件监听未清理 → 内存泄漏 + 竞态覆盖。
  • 坑 5滥用 deep：大表单上开 deep，每次输入都全树遍历。改用具体字段或多个 getter。
  • 坑 6用 watch 派生值：见 6.4，那是 computed 的活。

✓ 本章小结

要点一句话
watch显式指定源，拿得到新旧值，默认懒执行
watchEffect自动收集依赖、立即执行、拿不到旧值
immediate创建时立刻跑一次（首次拉数据必备）
deep递归监听，代价高；优先用 getter 精确定位
flushpre（默认，更新前）/ post（DOM 更新后）/ sync
清理onCleanup 取消过期异步；手动 stop() 停止侦听
纪律能用 computed 就别用 watch
