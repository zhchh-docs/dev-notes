8.1 v-if 的分组与复用控制

用 template 包一组元素

<template>
  <!-- ❌ 每个元素都写一遍 v-if，难维护且容易漏 -->
  <h3 v-if="isLogin">{{ user.name }}</h3>
  <p v-if="isLogin">余额 {{ user.balance }}</p>
  <button v-if="isLogin">退出</button>

  <!-- ✅ 用 template 包起来，它本身不渲染成 DOM -->
  <template v-if="isLogin">
    <h3>{{ user.name }}</h3>
    <p>余额 {{ user.balance }}</p>
    <button @click="logout">退出</button>
  </template>
  <template v-else>
    <button @click="login">登录</button>
  </template>
</template>
<template> 是一个不可见的包裹容器，最终不会出现在 DOM 里；v-else 必须紧跟在 v-if/v-else-if 之后，中间插别的元素会失效。

用 key 强制重建元素

Vue 会尽可能复用相同类型的元素以提升性能。但有时你恰恰不想复用：

<template>
  <!-- 切换登录方式时，希望输入框被清空（而不是复用同一个 input） -->
  <template v-if="loginType === 'phone'">
    <input key="phone" placeholder="手机号">
  </template>
  <template v-else>
    <input key="email" placeholder="邮箱">
  </template>

  <!-- 重置一个子组件的完整内部状态 -->
  <UserForm :key="formKey" />
  <button @click="formKey++">重置表单</button>
</template>

<script setup>
import { ref } from 'vue'
const loginType = ref('phone')
const formKey = ref(0)
</script>

:key 是 Vue 给的"强制重建开关"：key 变了 → 旧节点销毁、新节点创建，内部状态（输入内容、子组件 data）全部重置。

8.2 v-show 的真实代价

维度v-ifv-show
DOM假时不存在始终存在，display:none
组件假时卸载（触发 unmount 生命周期）始终挂载（生命周期只走一次）
首次渲染假时几乎零成本无论真假都完整渲染
切换重建子树，成本较高只改 CSS，极快
可用元素任意（含 template）只能是单个元素（template 上无效）

判断标准：

  • 切换频率高（Tab、hover 菜单、折叠面板）→ v-show；
  • 条件很少变化，或假时子树很重（含大表格、地图、图表）→ v-if；
  • 子树里有副作用（定时器、订阅）：v-if 卸载时记得清理，v-show 不会卸载所以不会自动清理。
<template>
  <!-- 频繁切换的 Tab：用 v-show，三个面板都渲染，切换只是改样式 -->
  <div v-show="tab === 'a'">面板 A（含表单输入，切换后内容保留）</div>
  <div v-show="tab === 'b'">面板 B</div>

  <!-- 很少出现、但一出现就很重的弹窗：用 v-if -->
  <HeavyChart v-if="showChart" :data="chartData" />
</template>

8.3 v-for 的完整形态

<template>
  <!-- ① 数组：(item, index) -->
  <li v-for="(item, index) in items" :key="item.id">{{ index }} - {{ item.name }}</li>

  <!-- ② 数组解构（直接用字段） -->
  <li v-for="({ id, name }, i) in items" :key="id">{{ i }} - {{ name }}</li>

  <!-- ③ 对象：(value, key, index) —— 顺序固定 -->
  <li v-for="(value, key, index) in user" :key="key">{{ index }}. {{ key }} = {{ value }}</li>

  <!-- ④ 数字范围：1 到 n -->
  <option v-for="n in 10" :key="n" :value="n">第 {{ n }} 页</option>

  <!-- ⑤ of 代替 in（更接近 JS 的 for...of） -->
  <li v-for="item of items" :key="item.id">{{ item.name }}</li>

  <!-- ⑥ template 上循环：一次渲染多个元素 -->
  <template v-for="item in items" :key="item.id">
    <dt>{{ item.name }}</dt>
    <dd>{{ item.desc }}</dd>
  </template>
</template>
注意在 <template v-for> 上，key 要写在 template 上（不能写到子元素上）；用 v-if 过滤时也要写成 <template v-for><div v-if> 的嵌套结构。

8.4 key：节点的身份证

key 的作用是告诉 Vue：新旧两次渲染中，哪个节点是"同一个"。Vue 据此决定是"就地复用更新"还是"销毁重建"。

图 8-1 key 用 id 与用 index 的差别

key 取值结果评价
后端 id / 唯一字段身份稳定，节点正确复用✅ 推荐
index位置即身份，增删时错位❌ 除非列表只追加、不删改
Math.random()每次都是新身份，全部重建❌ 性能差、状态全丢
不写 keyVue3 会告警并按"就地复用"处理❌ 不推荐

第 70 章会从 diff 源码层面解释 key 的复用算法（双端对比 + 最长递增子序列），本章只需记住：key = 稳定且唯一的业务 id。

8.5 数组更新检测：哪些写法会触发渲染

Vue3 用 Proxy 实现响应式，理论上能拦截所有操作。但仍要分清两类写法：

分类方法是否触发更新
变更方法（原地改数组）push/pop/shift/unshift/splice/sort/reverse✅ 触发
替换方法（返回新数组）filter/concat/slice/map✅ 需重新赋值：list.value = list.value.filter(...)
按下标赋值arr[0] = xVue3 ✅ 触发（Vue2 ❌ 不触发）
改 lengtharr.length = 0Vue3 ✅ 触发
新增对象属性obj.newKey = 1Vue3 ✅ 触发（Vue2 需 $set）
 
const list = ref([1, 2, 3])

// ✅ 变更方法
list.value.push(4)

// ✅ 替换方法要重新赋值（忘了赋值是最常见错误）
list.value = list.value.filter(n => n > 1)

// ✅ Vue3 支持下标赋值，但语义上更推荐用 splice
list.value[0] = 99

// ❌ 这样写常量数组被丢掉了 —— 没有赋回给 list
list.value.filter(n => n > 1)
坑filter/map 不改原数组，它们返回新数组。写了却没赋值，页面纹丝不动——这是新手排名第一的"为什么不更新"。

8.6 过滤与排序：别在模板里做

<template>
  <!-- ❌ 反例：v-for 与 v-if 同元素（Vue3 中 v-if 优先级更高，取不到 item） -->
  <li v-for="item in list" v-if="item.done" :key="item.id">{{ item.name }}</li>

  <!-- ⚠️ 可行但不推荐：每次渲染都要跑一遍 filter，且逻辑藏在模板里 -->
  <li v-for="item in list.filter(i => i.done)" :key="item.id">{{ item.name }}</li>

  <!-- ✅ 推荐：计算属性过滤，有缓存、可复用、可测试 -->
  <li v-for="item in doneList" :key="item.id">{{ item.name }}</li>
</template>

<script setup>
import { ref, computed } from 'vue'
const list = ref([
  { id: 1, name: '写文档', done: true },
  { id: 2, name: '改 bug', done: false }
])
const doneList = computed(() => list.value.filter(i => i.done))
</script>

要在循环内部做条件判断时，把两者分层：

<template>
  <!-- 外层循环、内层判断 -->
  <template v-for="item in list" :key="item.id">
    <li v-if="item.visible">{{ item.name }}</li>
  </template>

  <!-- 或者：整个列表都不显示时用外层的 v-if（短路，性能更好） -->
  <ul v-if="list.length">
    <li v-for="item in list" :key="item.id">{{ item.name }}</li>
  </ul>
  <p v-else>暂无数据</p>
</template>

8.7 性能相关：v-for 与 v-if 的组合

  • 先过滤再循环：用计算属性把列表缩短，比在循环里判断更快（少渲染节点）；
  • 循环体外判断：v-if="list.length" 放在 v-for 外层，空列表时直接不进循环；
  • 大数据量：几千条以上考虑分页或虚拟列表（第 72 章），别指望 v-for + key 能扛住；
  • 避免循环里创建复杂对象：:item="{ ...item, extra: computed() }" 每次渲染都产生新对象，让子组件无谓重渲染（第 71 章性能排查会再提）。
<template>
  <!-- ❌ 每次渲染都生成新对象，子组件必然重渲染 -->
  <Item v-for="i in list" :key="i.id" :data="{ id: i.id, name: i.name.toUpperCase() }" />

  <!-- ✅ 传原对象，格式化逻辑放子组件内部或用计算属性 -->
  <Item v-for="i in list" :key="i.id" :data="i" />
</template>

8.8 本章常见坑

  • 坑 1v-if 与 v-for 同元素：Vue3 中 v-if 先执行，取不到循环变量。改成嵌套或用计算属性。
  • 坑 2用 index 当 key：删除中间项后状态错位。
  • 坑 3filter/map 不赋值：写了 list.filter() 却没赋回 list.value。
  • 坑 4v-else 前面插了别的元素：v-else 必须紧跟 v-if，否则报错。
  • 坑 5v-show 用在 template 上：无效，v-show 只能作用于单个元素。
  • 坑 6期望"切换时清空输入"却没加 key：Vue 默认复用同类型元素，需要 key 强制重建。

✓ 本章小结

要点一句话
分组渲染<template v-if> / <template v-for> 不产生 DOM
强制重建给元素或组件加 :key，key 变则销毁重建
v-if vs v-show切换频繁用 v-show，子树重或很少显示用 v-if
key 原则稳定唯一业务 id；不用 index，不用随机数
数组更新变更方法直接改；filter/map 必须重新赋值
过滤排序放计算属性：有缓存、可复用、模板干净

✎ 本章习题

A 基础说出 v-if 与 v-show 在"首次渲染""切换""组件生命周期"三个维度上的差异，并各举一个适用场景。
B 进阶做一个"可编辑列表"：每行含一个输入框，支持删除任意行、在中间插入行。分别用 item.id 与 index 作为 key，输入内容后删除首行，记录并解释两者差异。
C 挑战给一个 1000 条的列表加"关键字搜索 + 状态筛选 + 排序"，全部逻辑用计算属性完成；然后尝试把过滤逻辑移到模板里（v-for="i in list.filter(...)"），用 console.count 对比两种方式在数据变化时的执行次数。
