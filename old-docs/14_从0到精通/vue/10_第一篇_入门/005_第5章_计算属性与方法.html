第 5 章 计算属性 vs 方法

教科书 第 5 章 / 共 76 章 · 预计 35 分钟 · 示例可直接运行

模板里放不下复杂逻辑时该怎么办？计算属性是最常用的答案。这一章讲清它的缓存机制、与方法/侦听器的区别、可写计算属性的写法，以及"什么时候不该用计算属性"。

◆本章目标

  • 理解计算属性存在的理由：让模板保持"声明式"，逻辑可复用、可缓存；
  • 掌握 computed 的缓存语义——依赖不变就不重算；

  • 会写可写计算属性（get/set）处理"组合字段"与"反解字段"；
  • 面对一个需求能判断：用计算属性、方法还是侦听器。

5.1 问题：模板里的逻辑越写越长

看一段真实会出现的模板：

<template>
  <p>{{ user.firstName + ' ' + user.lastName }}</p>
  <p>{{ list.filter(i => i.done).length }} / {{ list.length }} 已完成</p>
  <p>{{ (price * (vip ? 0.8 : 1) * (coupon ? 0.95 : 1)).toFixed(2) }} 元</p>
  <p>{{ orders.filter(o => o.status === 1).map(o => o.amount).reduce((a, b) => a + b, 0) }}</p>
</template>

问题不在于"能不能跑"，而在于：

  • 读不懂：模板本该描述结构，现在塞满了业务计算；
  • 不能复用：同一个"已完成数量"要在三处显示，就得复制三遍；
  • 每次渲染都重算：filter/map/reduce 在每次组件更新时都会执行一遍；
  • 无法测试：逻辑粘在模板里，单测无从下手。

计算属性就是为了解决这四点。

5.2 computed 基本用法

<template>
  <p>{{ fullName }}</p>
  <p>{{ doneCount }} / {{ list.length }} 已完成</p>
  <p>{{ finalPrice }} 元</p>
</template>

<script setup>
import { ref, reactive, computed } from 'vue'

const user = reactive({ firstName: '张', lastName: '三' })
const list = ref([
  { id: 1, title: '写文档', done: true },
  { id: 2, title: '改 bug', done: false }
])
const price = ref(199)
const vip = ref(true)
const coupon = ref(false)

// 只读计算属性：传一个 getter 函数
const fullName = computed(() => user.firstName + ' ' + user.lastName)

const doneCount = computed(() => list.value.filter(i => i.done).length)

const finalPrice = computed(() => {
  const rate = (vip.value ? 0.8 : 1) * (coupon.value ? 0.95 : 1)
  return (price.value * rate).toFixed(2)
})
</script>

要点：

  1. computed() 的参数是一个 getter 函数，返回值就是计算属性的值；
  2. 模板里不需要 .value（与 ref 一样自动解包），JS 里要写 fullName.value；
  3. 计算属性是只读的，直接赋值会告警（需要可写版本见 5.4）；
  4. 它会自动追踪函数内用到的响应式数据（user.firstName 等），这就是"依赖"。

5.3 缓存机制：与方法的核心差别

一句话：计算属性基于依赖缓存，方法每次渲染都重新执行。

<template>
  <!-- 方法：每次渲染都调用 -->
  <p>{{ calcSum() }}</p>
  <p>{{ calcSum() }}</p>
  <p>{{ calcSum() }}</p>

  <!-- 计算属性：依赖不变时只算一次 -->
  <p>{{ sum }}</p>
  <p>{{ sum }}</p>
  <p>{{ sum }}</p>

  <button @click="other++">改一个无关数据（触发重新渲染）：{{ other }}</button>
</template>

<script setup>
import { ref, computed } from 'vue'
const list = ref([1, 2, 3, 4, 5])
const other = ref(0)

function calcSum() {
  console.log('方法执行了')
  return list.value.reduce((a, b) => a + b, 0)
}

const sum = computed(() => {
  console.log('计算属性执行了')
  return list.value.reduce((a, b) => a + b, 0)
})
</script>

打开控制台观察：

  • 首次渲染：方法打印 3 次（模板里出现 3 次就执行 3 次），计算属性只打印 1 次；
  • 点击按钮（other 变化触发重新渲染，但 list 没变）：方法又打印 3 次，计算属性一次都不打印；
  • 只有 list 真正变化时，计算属性才会重新计算。

图 5-1 计算属性的缓存与惰性求值

缓存带来的不只是性能：它保证了同一个值在一轮渲染中绝对一致，不会因为多次调用算出不同结果。

5.4 可写计算属性（get / set）

只读计算属性赋值会失败。想让它可写，传一个对象形式的 get / set：

<template>
  <input v-model="fullName">
  <p>姓：{{ user.firstName }}｜名：{{ user.lastName }}</p>
</template>

<script setup>
import { reactive, computed } from 'vue'
const user = reactive({ firstName: '张', lastName: '三' })

const fullName = computed({
  // 读：组合
  get() {
    return user.firstName + ' ' + user.lastName
  },
  // 写：反解回依赖
  set(val) {
    const parts = val.split(' ')
    user.firstName = parts[0] || ''
    user.lastName = parts[1] || ''
  }
})
</script>

典型使用场景：

  • 组合字段：姓 + 名 ↔ 全名、省 + 市 + 区 ↔ 完整地址；
  • 单位换算：元 ↔ 分、摄氏度 ↔ 华氏度；
  • 与组件 v-model 配合：把 props 值包装成本地可写的计算属性（第 13 章会用到）。
坑setter 里不要去改计算属性自己（fullName = x），要改的是它的依赖源（user.firstName）。否则就是自己写自己，造成死循环。

5.5 computed vs 方法 vs 侦听器

维度computedmethodswatch
目的派生出一个值执行一段逻辑值变了做点什么
缓存有（依赖不变不重算）无（每次调用都跑）—
模板用法{{ fullName }}{{ fn() }}不在模板用
副作用不应有（纯函数）可以有专门做副作用
异步不合适可以可以（常见）

决策流程：

  1. 你需要一个"由别的数据算出来的值" → computed；
  2. 你需要"用户点一下就做某事"或"每次渲染都要重新执行（如取当前时间）" → methods；
  3. 你需要"数据变化后发请求 / 写日志 / 操作 DOM / 做防抖" → watch（第 6 章）。
// ❌ 错误示范：用 watch 去"派生"一个值
const fullName = ref('')
watch(() => user.firstName + user.lastName, v => { fullName.value = v })

// ✅ 正确：这就是计算属性的活
const fullName = computed(() => user.firstName + ' ' + user.lastName)

判断口诀：能用 computed 表达的需求，就不要用 watch。watch 是"逃生舱"，不是首选。

5.6 计算属性的调试与性能

  • 别在计算属性里做重活：它会在依赖变化时同步执行，排序上万条数据会卡住渲染。大数据列表请用分页/虚拟列表（第 72 章）。
  • 依赖要"被读取"才算依赖：写在 if 分支里、本次没走到的响应式数据，不会被追踪。
  • Vue 3.4+ 支持调试选项（了解即可）：
const sum = computed(() => list.value.length, {
  onTrack(e) { console.log('被追踪的依赖：', e) },
  onTrigger(e) { console.log('触发重算的原因：', e) }
})
在生产构建中这些调试回调会被移除，不会影响体积。

5.7 本章常见坑

  • 坑 1给只读计算属性赋值：报 Write operation failed: computed value is readonly。需要改就写 setter，或改依赖源。
  • 坑 2在计算属性里做副作用：如发请求、改别的 state、操作 DOM。计算属性应当是纯函数（同样的输入永远同样的输出）。
  • 坑 3在 getter 里用异步：async computed 返回的是 Promise，模板里会渲染成 [object Promise]。异步数据请用 watch + ref，或第 63 章的 Suspense。
  • 坑 4以为计算属性"一定会实时更新"：它惰性地在下次读取时才重算，不是依赖一变就立刻算（第 33 章详解）。
  • 坑 5把 Date.now() 放进计算属性：它不是响应式依赖，永远不会更新。需要"当前时间"请用方法或在定时器里改 ref。

✓ 本章小结

要点一句话
为什么用让模板保持声明式；逻辑可复用、可缓存、可测试
缓存语义依赖不变不重算；惰性求值（读取时才算）
vs 方法方法每次渲染都执行；计算属性按依赖缓存
可写版本computed({ get, set })，setter 里改依赖源
vs 侦听器派生值用 computed，副作用用 watch
纪律计算属性保持纯函数：不同步、无异步、无副作用

A 基础用一段可运行代码证明"计算属性有缓存、方法没有"：分别在两者里 console.log，然后修改一个与其无关的数据触发渲染，记录打印次数。
B 进阶实现一个"购物车结算"：商品列表（含单价、数量、选中状态），用计算属性派生出「已选商品件数」「商品总价」「满 200 减 30 后的应付金额」「是否可用优惠券」。要求模板中没有任何复杂表达式。
