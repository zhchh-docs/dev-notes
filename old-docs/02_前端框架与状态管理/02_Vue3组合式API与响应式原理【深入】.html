Vue3 组合式 API 与响应式原理

深入 定位：Vue3 的两大升级——组合式逻辑复用 + Proxy 响应式源码级机制

Vue3 带来两件大事：用 Proxy 重写响应式（替代 Vue2 的 Object.defineProperty），以及组合式 API（Composition API）让逻辑按关注点聚合、可抽成 composable 复用。本页从源码级讲透 track/trigger 依赖收集、ref/reactive/computed 的关系、为什么组件更新是异步的，再落到 业务系统 表单设计器/渲染器的 composable 实战。这是 Vue 面试的深水区。

1简介与阅读指引

1.1 定位

Vue3 两大核心升级：①组合式 API——不再 data/methods/computed 分块，而是在 <script setup> 里按"逻辑关注点"组织代码，可复用逻辑抽成 composables 函数；②Proxy 响应式——new Proxy(target, handler) 劫持整个对象，替代 Vue2 逐属性 defineProperty。附带：原生 TS 支持、虚拟 DOM 重写更小更快、Fragments 多根节点。它解决的是选项式的两大痛点：同一逻辑被拆散在 data/methods/watch 各处（组件一大上下滚动找齐），以及 Vue2 响应式的增删盲区。

1.2 横向对比：选项式 vs 组合式

  • 逻辑组织：选项式按"选项类型"分块、同一功能拆散；组合式按"功能"聚合——组件越大组合式越好维护（图 2）；
  • 复用方式：mixins（命名冲突、来源不清）→ composable 函数（显式导入、类型清晰）——业务系统把表单逻辑抽成公共 composable 的原因；
  • 响应式底层：defineProperty 逐属性劫持、检测不到增删 → Proxy 整对象代理、增删自动追踪——理解这个差异，才知道 Vue.set 在 Vue3 为什么消失了。

1.3 学习目标与阅读指引

  1. 讲清 ref/reactive 的选择与解构陷阱；
  2. 口述 Proxy + track/trigger + 三层映射的响应式闭环；
  3. 会手写一个最小 reactive（面试题）；
  4. 抽一个可复用 composable（useRequest/useFormSchema）；
  5. 避开六条高频坑（解构丢响应/.value/computed 副作用/nextTick/deep/增删误区）。

前置知识：01 篇选项式基础、01 模块 06 篇 TS。难度：★★★★☆（响应式原理是前端面试深水区）。务必动手：第 6 章 Demo——手写 reactive 并用之驱动视图。本篇不涉及：插槽与组件模式（03 篇）、Pinia（04 篇）。

2核心模型

六个核心模型：组合式组织→ ref 与 reactive→ computed 与 watch/watchEffect→ Proxy+Reflect→ track/trigger 闭环→ composables。

2.1 组合式 API 与 script setup

状态/计算/方法都在 <script setup> 一个作用域里，同一逻辑关注点写在一起；普通变量/函数取代 this.xxx——类型推导更友好、利于 Tree-shaking、可抽函数复用，模板直接用声明的变量。

2.2 ref 与 reactive：统一用 ref 最稳

ref(x)：包装任意值，带 .value（模板自动解包、JS 要 .value）；reactive(obj)：对象转 Proxy，直接访问属性。坑：reactive 解构会失去响应性（解构出普通值脱离 Proxy）；ref 解构后仍是引用。经验法则：基础类型用 ref，对象两者皆可但 ref 更统一（图 3）。

2.3 computed 与 watch/watchEffect

computed：内部建 effect，依赖变才重算、带缓存。watch(source, cb)：默认惰性（首次不跑）、能拿 oldValue/newValue、可监听多源、可配 deep/immediate。watchEffect(fn)：自动收集 fn 里用到的依赖、变了重跑——挂载时立即执行一次、拿不到 oldValue。选择：要 oldValue/惰性用 watch，要"立即跑+自动收集"用 watchEffect。

2.4 Proxy 与 Reflect 的配合

Proxy 包装目标对象拦截 get/set/has/deleteProperty；Reflect 提供同名默认操作（Reflect.get(target,key)）。组合：get 时先 track、再 Reflect.get 返回真值；set 时先 Reflect.set 写值、再 trigger——在默认行为前后插一脚。

2.5 track/trigger 闭环

track（依赖收集）：三层映射——targetMap（WeakMap，键=原始对象）→ depsMap（Map，键=属性名）→ dep（Set，装依赖该属性的所有 effect）；读属性时若当前有 effect 在跑就登记进 dep。trigger（触发更新）：写属性时取出 dep，重跑里面所有 effect；effect 重跑时重新读依赖、自动更新依赖关系（旧的不再用就自然解除）。闭环："读时收集、写时触发"就是 Vue3 响应式的核心。

2.6 effect 调度与 composables

异步批量：渲染 effect 不立即执行，进更新队列、下一微任务统一 flush——同一次同步代码改三次状态只渲染一次；更新后操作 DOM 必须 await nextTick()。composables：把一组响应式状态与逻辑封装成函数返回（返回响应式引用保持响应性），多组件 import 复用——Vue3 逻辑复用的标准答案，比 mixin 清晰、比 renderless 组件直接。

3核心用法（按场景）

3.1 场景一：script setup 基本写法

<script setup>
import { ref, computed, watch } from 'vue';

const count = ref(0);                       // 基础类型用 ref
const double = computed(() => count.value * 2);

watch(count, (nv, ov) => console.log(ov, '→', nv));

function inc() { count.value++; }           // JS 里用 .value
</script>

<template>
  <button @click="inc">{{ count }} ×2 = {{ double }}</button>  <!-- 模板自动解包 -->
</template>

3.2 场景二：composable——useRequest

// useRequest.ts：封装"加载-数据-错误"状态
export function useRequest(fetcher) {
  const data = ref(null);
  const loading = ref(false);
  async function run() {
    loading.value = true;
    try { data.value = await fetcher(); }
    finally { loading.value = false; }
  }
  return { data, loading, run };   // 返回响应式引用，调用方保持响应性
}

3.3 场景三：手写一个最小 reactive（面试题）

let activeEffect = null;
const targetMap = new WeakMap();

function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, (dep = new Set()));
  dep.add(activeEffect);                 // 登记依赖
}
function trigger(target, key) {
  const depsMap = targetMap.get(target);
  const dep = depsMap?.get(key);
  dep?.forEach(e => e());                // 重跑所有依赖该属性的 effect
}
function reactive(target) {
  return new Proxy(target, {
    get(t, k) { track(t, k); return Reflect.get(t, k); },
    set(t, k, v) { const r = Reflect.set(t, k, v); trigger(t, k); return r; }
  });
}

三件套记忆：activeEffect（当前在跑的副作用）、track（读时登记）、trigger（写时重跑）——30 行讲清响应式。

4进阶知识点【进阶】

首次学习可整章跳过。前置：track/trigger 闭环已能口述。

4.1 shallowRef 与 triggerRef

shallowRef 只对 .value 本身响应（内部对象变化不追踪）——大表格/大列表替换整体时性能更好；配合 triggerRef 手动触发。大数据场景"整替优于深改"。

4.2 toRefs 与解构安全

toRefs(obj) 把 reactive 对象的每个属性转成 ref——解构后仍是响应式引用；store 解构用 storeToRefs（Pinia 专用，跳过函数）。解构安全的两个工具：toRefs（reactive）与 storeToRefs（store）。

4.3 effect 的清理与 stop

watch/watchEffect 返回 stop 函数——组件卸载时自动调用；手动场景（异步回调里创建的 effect）要自己管理。onInvalidate：watch 回调里注册清理逻辑（如防抖取消），下次触发前先执行。

4.4 defineProps/defineEmits 的编译期魔法

script setup 里 defineProps/defineEmits/defineExpose 无需 import（编译器宏）；TS 泛型写法 defineProps<{ title: string }>()——类型即 props 声明，与 01 模块 TS 篇的结构化类型一脉相承。

4.5 响应式性能：大对象的策略

超大列表/树的三板斧：①shallowRef + 整体替换；②分页/虚拟滚动（06 工程化篇）；③真正离线的计算挪 Worker。原则：响应式追踪有成本，追踪"需要 reactive 的最小范围"。

闭环四步：①读属性——Proxy.get 拦截，沿 targetMap→depsMap 找到 dep；②登记——当前正在执行的 effect 加进 dep；③写属性——Proxy.set 拦截，取出 dep 重跑所有 effect；④重跑——effect 重新读依赖自动更新关系。为什么更新是异步的：渲染 effect 进 jobQueue，用 Promise.then（微任务）flush——同一次同步代码改三次状态只渲染一次（衔接 01 模块 03 篇事件循环）。

6最小可运行 Demo

性质：业务系统（Vue3+TS+Pinia）表单设计器/渲染器实战——两端共享同一套字段元数据逻辑。

6.1 完整实现：useFormSchema composable

// useFormSchema.ts
export function useFormSchema(initial: FieldMeta[] = []) {
  const fields = ref<FieldMeta[]>(initial);
  const selected = ref<FieldMeta | null>(null);
  function addField(f: FieldMeta) { fields.value.push(f); }
  function removeField(key: string) {
    fields.value = fields.value.filter(f => f.key !== key);
  }
  return { fields, selected, addField, removeField };
}
// 设计器与渲染器各自 import，逻辑单一来源、不漂移
// stores/user.ts（Pinia setup 风格——store 即响应式）
export const useUserStore = defineStore('user', () => {
  const token = ref('');
  const profile = ref<Profile | null>(null);
  const isLogin = computed(() => !!token.value);
  function setToken(t: string) { token.value = t; }
  return { token, profile, isLogin, setToken };
});

6.2 踩坑记录（真实问题与解法）

  • 解构后仍是 ref：const { fields } = useFormSchema() 后 fields 还是 ref 要 .value——曾误当普通数组 push 报错；
  • reactive 解构丢响应：reactive schema 解构丢响应性——统一用 ref 返回；
  • 深层 watch 漏 deep：校验在 watch 里做，深层嵌套没加 { deep: true } 不触发；
  • 直接解构 store 丢响应：const { token } = useUserStore() token 变了视图不更新——用 storeToRefs 保持引用。

6.3 逐段解析

  • 返回 ref 而非 reactive：解构后仍是响应式引用——composable 的返回契约；
  • Pinia setup 风格：store 就是 ref+computed+函数——组合式的自然延伸，概念零新增；
  • FieldMeta 泛型：与公共包类型一致（01 模块 06 篇 OpenAPI codegen 同源）。

6.4 复盘与可复用经验

  1. 逻辑同源靠 composable：多入口共享逻辑就抽成函数返回响应式状态；
  2. ref 返回优于 reactive 解构：避免响应性丢失；
  3. 解构 store 必用 storeToRefs：Pinia 最常见的"视图不更新"坑。

7常见坑 & Debug

六条高频坑。

7.1 reactive 解构丢响应性

现象：const { name } = reactive(obj) 后改 name 视图不更新。根因：解构出普通值脱离 Proxy。正解：用 ref、或 toRefs/storeToRefs 保持引用。

7.2 ref 在 JS 里忘写 .value

现象：count === 0 永远 false。根因：模板自动解包、JS 不解包。正解：逻辑里一律 count.value，ESLint 规则兜底。

7.3 computed 里写副作用

现象：computed 里发请求/改 DOM。根因：computed 可能被延迟求值，副作用不可控。正解：副作用用 watch/watchEffect——computed 是纯派生。

7.4 改状态后立刻读 DOM

根因：更新异步批量（jobQueue 微任务 flush）。正解：await nextTick()。

7.5 watch 深层对象漏 deep

现象：改嵌套属性 watch 不触发。正解：watch(obj, cb, { deep: true })，或直接 watch 一个 getter（(() => obj.a.b)——更精确还省 deep）。

7.6 "Proxy 不能监听新增删除"？——误解

口径：Proxy 能拦截 delete/add，新增/删除对象属性天然响应，Vue3 不需要 Vue.set——别把 Vue2 的限制带进 Vue3。

8重点讲解

Q1：Vue3 的 Proxy 响应式是怎么工作的？相比 Vue2 解决了什么？

参考答案：工作原理——reactive 返回 new Proxy(target, handler)：get 拦截时先 track（把当前正在执行的 effect 登记进三层映射 targetMap→depsMap→dep），再 Reflect.get 返回真值；set 拦截时先 Reflect.set 写值、再 trigger（取出 dep 重跑所有 effect）。effect 重跑重新读依赖，依赖关系自动更新。解决三件事：①新增/删除属性天然响应（Proxy 拦截整个对象的所有操作，Vue.set 消失）；②数组下标赋值/length 可追踪；③惰性代理（访问到才深层代理，初始化不用递归全量劫持）。

加分点：能写出 30 行最小 reactive（track/trigger/activeEffect 三件套）。

Q2：ref 和 reactive 怎么选？解构为什么会丢响应性？

参考答案：ref 包装任意值（内部也用 reactive 实现对象包装），JS 里 .value、模板自动解包，解构后仍是引用；reactive 只包装对象返回 Proxy，解构出的是普通值——脱离了 Proxy 拦截，改成什么样 Vue 都不知道，所以丢响应。工程约定：统一用 ref（composable 返回 ref、store 用 storeToRefs 解构），需要按属性解构 reactive 时用 toRefs。口诀：解构出来的东西必须还是 ref。

Q3：组合式 API 为什么比 mixins 好？怎么抽一个 composable？

参考答案：mixins 三宗罪——来源不透明（this.foo 不知道来自哪个 mixin）、命名冲突、多 mixin 叠加难追踪；composable 是显式 import 的普通函数——来源清晰、可 TS 类型化、可组合嵌套。抽取方法：把"一组相关响应式状态 + 操作函数"装进函数并 返回 ref 引用（不是 reactive 解构值），如 useRequest（data/loading/run）、useFormSchema（fields/selected/addField/removeField）。实战收益：设计器与渲染器逻辑从两份拷贝合并为单一来源，改一处两端同步。
