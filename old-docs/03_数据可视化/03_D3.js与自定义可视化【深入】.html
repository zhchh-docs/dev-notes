1简介与阅读指引

1.1 定位：不是图表库，是"数据 → DOM"的工具集

D3（Data-Driven Documents）的定位常被误解——它不提供"折线图/柱状图"这种成品图型，提供的是四类独立积木：

  • 选择集（selection）：select/selectAll + 数据绑定与 enter/update/exit 生命周期；
  • 比例尺（scale）：数据域 → 像素域的映射函数，是"数据变坐标"的唯一正解；
  • 坐标轴/形状（axis/shape）：按你的比例尺生成轴与路径（线/弧/面积）；
  • 布局（layout）：d3.force/d3.hierarchy 等纯数据计算器，只算位置不画图。

与 ECharts 的关系是互补而非替代：ECharts 把"图表工程"收进引擎（02 篇），D3 把底层给你自己拼——图型自由度 100%，工程成本也 100%。01 篇选型铁律重申：常规统计图表优先 ECharts，只有非标准图形或深度定制交互才上 D3。

1.2 横向对比

方案抽象层级图型自由度工程成本适用
ECharts配置式（option）内置几十种低（开箱即用）常规图表/大屏
D3命令式（工具集）完全自由高（全自己拼）非标准图形/深度定制
原生 SVG/Canvas无抽象自由极高极简一次性需求

1.3 学习目标与阅读指引（诚实声明）

  1. 掌握 data-join 与 enter/update/exit——D3 的灵魂；
  2. 会用比例尺与坐标轴搭建一张图；
  3. 理解通用更新模式（数据变了图怎么跟）；
  4. 知道 D3 与 Vue 的所有权冲突及分治方案。

诚实声明：本套技术栈实战中 ECharts 是绝对主力，D3 属于学习储备与个别定制场景备用——本篇代码为自学练习性质，未承担生产大屏主体。正因为亲手用 D3 拼过一张图，才真正理解 ECharts 帮你省掉了什么（这本身是重要认知）。

前置知识：01 模块 SVG 基础、01 篇渲染后端。难度：★★★★☆。

2核心模型

五个核心模型：选择集与数据绑定（总纲）→ enter/update/exit→ 比例尺→ 坐标轴与形状→ 布局。

2.1 选择集与数据绑定：data-join

d3.selectAll('rect').data(data) 把数据数组按序绑到元素集合上——绑定产生三个分组：update（数据有对应元素）、enter（数据多出、元素不够）、exit（元素多出、数据不足）。后续所有操作都作用在分组上，这是 D3 与 jQuery 最大的差别：操作的是"数据与元素的对应关系"，不是元素本身。

2.2 enter/update/exit 生命周期

  • enter：新数据的"占位"——先 append 元素再设属性；
  • update：已有元素直接更新属性（配合 transition 做平滑过渡）；
  • exit：被删数据的元素——.exit().remove() 清理，不清理就泄漏。

核心：数据驱动视图的"手动机器"——D3 的通用更新模式（5.3）全部建立在这三分组上。

2.3 比例尺：数据域 → 像素域的映射函数

  • 线性：d3.scaleLinear().domain([0, max]).range([height, 0])——连续数值；
  • 序数/分段：d3.scaleBand()——类目轴（柱状图一格一个 band，含内边距）；
  • 时间/对数/颜色：scaleTime/scaleLog/scaleSequential（连续色带配插值器）。

禁止手算坐标：y = height - value/max*height 这类硬编码在数据范围变化时全崩——一切位置都过比例尺。

2.4 坐标轴与形状生成器

  • axis：把比例尺"渲染成"刻度组——g.call(d3.axisBottom(xScale))；轴的刻度数/格式均可配；
  • shape：d3.line/d3.area/d3.arc/d3.symbol——纯计算器，输入数据输出 path 的 d 字符串，不碰 DOM（可测、可复用）。

2.5 布局：只算位置不画图

d3.forceSimulation（力导向）、d3.hierarchy + d3.tree/d3.pack（层级）、d3.pie（角度）——输入数据、输出带坐标的派生数据。布局是纯函数：你可以拿它的输出喂给 ECharts/D3/Canvas 任何渲染端。

3核心用法（按场景）

3.1 场景一：柱状图骨架（比例尺 + join）

const svg = d3.select('#chart').append('svg')
  .attr('width', 600).attr('height', 300);

const x = d3.scaleBand().domain(data.map(d => d.name))
  .range([40, 580]).padding(0.2);
const y = d3.scaleLinear().domain([0, d3.max(data, d => d.value)])
  .range([260, 20]);

svg.selectAll('rect').data(data).join('rect')
  .attr('x', d => x(d.name))
  .attr('y', d => y(d.value))
  .attr('width', x.bandwidth())
  .attr('height', d => 260 - y(d.value))
  .attr('fill', '#3d7a4f');

3.2 场景二：显式 enter/update/exit（通用更新模式雏形）

const sel = svg.selectAll('rect').data(data, d => d.name); // key 函数保对应关系

sel.enter().append('rect')              // 新数据：先建元素
  .attr('y', 260).attr('height', 0)     // 从 0 长出来的入场动画起点
  .merge(sel)                            // 与 update 合流
  .transition().duration(500)
  .attr('x', d => x(d.name)).attr('y', d => y(d.value))
  .attr('width', x.bandwidth()).attr('height', d => 260 - y(d.value));

sel.exit().transition().duration(300)
  .attr('height', 0).remove();           // 退场：缩到 0 再删

3.3 场景三：坐标轴与刻度格式化

svg.append('g')
  .attr('transform', 'translate(0,260)')
  .call(d3.axisBottom(x));                       // X 轴挂类目比例尺

svg.append('g').attr('transform', 'translate(40,0)')
  .call(d3.axisLeft(y).ticks(5).tickFormat(d => d + ' MW'));

3.4 场景四：折线 + 面积（shape 生成器）

const line = d3.line()
  .x(d => x(d.time)).y(d => y(d.value))
  .curve(d3.curveMonotoneX);          // 单调插值，避免假峰谷

svg.append('path')
  .datum(data)
  .attr('d', line)
  .attr('fill', 'none').attr('stroke', '#047857').attr('stroke-width', 2);

3.5 场景五：tooltip（全手工的代价）

const tip = d3.select('body').append('div')
  .style('position', 'fixed').style('display', 'none')
  .style('background', '#fff').style('padding', '6px 10px');

svg.selectAll('rect')
  .on('mouseenter', (e, d) => tip.style('display', 'block').text(`${d.name}: ${d.value}`))
  .on('mousemove', e => tip.style('left', e.clientX + 12 + 'px').style('top', e.clientY + 12 + 'px'))
  .on('mouseleave', () => tip.style('display', 'none'));
// 对比 ECharts：tooltip 一个配置项的事——这就是"自己拼"的成本体感

4进阶知识点【进阶】

首次学习可整章跳过。前置：join 与比例尺已会用。

4.1 通用更新模式（General Update Pattern）

把"数据变了图跟着变"固化成流程：绑定（带 key 函数）→ merge enter+update 统一过渡 → exit 清理 → 重算比例尺与轴。比例尺 domain 要随新数据动态扩展（d3.max 重算），轴要重新 call——漏掉任一步就是"图更新了轴没更新"的经典 bug。

4.2 d3.force 力导向图

节点/边数据 → forceSimulation 迭代收敛：d3.forceManyBody（斥力）、d3.forceLink（边弹力）、d3.forceCenter（居中）。tick 事件里把节点坐标写回元素——布局是异步模拟，首次收敛可能数百帧，性能敏感要预收敛（simulation.tick() 手动跑完再上屏）。

4.3 d3.zoom 与画布交互

d3.zoom() 统一管理缩放平移：把 transform 应用到一个 g 上，图内所有元素一起变换；配合 scaleExtent 限制倍率。坐标反解：d3.pointer(event, svg) 拿画布内坐标，缩放后的坐标换算用 transform.invert——手写缩放图表必然用到。

4.4 D3 与 Vue 的所有权分治

Vue 管模板、D3 管 SVG 子树——两边都操作同一棵树必然互踩（02 模块 Layui/Vue 抢节点同款问题）。两种成熟分法：①D3 全托管：Vue 组件只留一个空容器，onMounted 里 D3 接管、onUnmounted 清理（数据变更通过 watch 调 D3 更新函数）；②Vue 托管、D3 只算：只用 D3 的比例尺/布局/shape 算坐标与 path 字符串，渲染交给 Vue 模板响应式——推荐后者，与框架心智一致。

4.5 按需引入与体积

整包 d3 是 30+ 模块的聚合——只 import 用到的模块（d3-scale/d3-selection/d3-shape），体积从 ~250KB 降到几十 KB；用 ESM tree-shaking 天然生效。

6最小可运行 Demo

性质（诚实声明）：自学练习——用 D3 拼一张"带入场动画 + tooltip + 动态更新"的柱状图，目标不是替代 ECharts，而是亲手体会引擎帮你省掉的工程量（tooltip 手工挂/轴手工 call/更新模式手写）。

6.1 完整可运行代码

<div id="chart"></div>
<script type="module">
import * as d3 from 'https://cdn.jsdelivr.net/npm/d3@7/+esm';

const data = [{name:'一',value:80},{name:'二',value:120},{name:'三',value:65}];
const svg = d3.select('#chart').append('svg').attr('width',600).attr('height',300);
const x = d3.scaleBand().domain(data.map(d=>d.name)).range([40,580]).padding(0.2);
const y = d3.scaleLinear().domain([0,100]).range([260,20]);

svg.append('g').attr('transform','translate(0,260)').call(d3.axisBottom(x));
svg.append('g').attr('transform','translate(40,0)').call(d3.axisLeft(y));

svg.selectAll('rect').data(data).join('rect')
  .attr('x',d=>x(d.name)).attr('width',x.bandwidth())
  .attr('y',260).attr('height',0)
  .transition().duration(600)
  .attr('y',d=>y(d.value)).attr('height',d=>260-y(d.value))
  .attr('fill','#3d7a4f');
</script>

6.2 练习扩展（验证清单）

  1. 加 tooltip（3.5 手工三事件），体会与 ECharts 一个配置项的差距；
  2. 按钮切换新数据，跑 3.2 的 enter/update/exit——验证 key 函数保留已有元素（浏览器 devtools 看元素不重建）；
  3. 改数据最大值，观察不重算 scale domain 时的"出图"事故；
  4. 换 d3.curveStep 或 curveCatmullRom，理解 curve 参数对视觉的影响。

6.3 复盘经验

  • 认知收益：拼完这张图，ECharts 的 option 里每个配置项对应 D3 的哪段手工代码就全对上了——这是读 02 篇渲染管线的最好注脚；
  • 工程结论：常规需求不要用 D3（成本 3-5 倍）；非标准图形（自定义网络拓扑/特殊 glyphs）才是它的主场。

7常见坑 & Debug

五条高频坑。

7.1 忘记 exit().remove()，幽灵元素堆积

现象：数据缩减后旧柱子还在图上。根因：data-join 只覆盖 update/enter，exit 的元素没人管。正解：.exit().remove()（或先退场动画再删）。

7.2 手算坐标，数据范围一变全崩

现象：新数据超出旧 max，柱子冲出画布或压成一条线。正解：一切位置过比例尺，domain 随数据动态重算（d3.max/extent）。

7.3 data 绑定不带 key 函数，对应关系错乱

现象：更新数据后柱子颜色/tooltip 串位。根因：默认按数组下标绑定，排序/过滤后元素与数据错配。正解：.data(data, d => d.name)——key 函数锁定元素与数据的身份对应。

7.4 axis 更新后刻度不变

现象：数据更新图变了、轴刻度还是旧的。根因：axis 是"把比例尺渲染一次"的命令，比例尺 domain 变了要重新 call。正解：更新流程里对轴的 g 重新执行 .call(d3.axisBottom(x))（可配 transition 平滑）。

7.5 D3 与 Vue 抢同一棵 DOM 树

现象：Vue 响应式重渲染把 D3 画的元素清掉，或 D3 改的属性被 Vue 覆盖。正解：所有权分治——推荐"Vue 托管渲染、D3 只算坐标"（4.4），D3 全托管则容器必须对 Vue 透明。

8重点讲解

Q1：D3 和 ECharts 的本质区别是什么？什么时候选 D3？

参考答案：抽象层级不同——ECharts 是配置式引擎，一份 option 声明结果，布局/编码/绘制/交互全由引擎完成；D3 是命令式工具集，把"数据→像素"的每一步（比例尺、布局、shape、事件）交给你自己拼。选型：常规统计图表/大屏一律 ECharts（成本 1/3-1/5、交互完整）；非标准图形或深度定制（自定义网络拓扑、特殊 glyphs、需要完全掌控动画与交互语义）才上 D3。两者共享同一渲染管线概念——D3 的自由就是把引擎内部步骤开放出来。

Q2：解释 data-join 与 enter/update/exit。

参考答案：selectAll().data(data, keyFn) 按绑定产生三分组——enter（数据多出）：append 占位元素后设属性；update（一一对应）：直接更新属性+transition；exit（元素多出）：退场动画后 remove。key 函数是重点：不带 key 默认按下标绑定，排序/过滤后元素与数据身份错配（颜色串位）；带 key 则已有元素被保留复用（devtools 可验证不重建）。通用更新模式 = merge(enter,update) 统一过渡 + exit 清理 + 重算 scale domain + 重新 call axis。

Q3：D3 怎么和 Vue/React 协作？

参考答案：核心是DOM 所有权划清（同一棵树两边操作必互踩）。两种分法：①D3 全托管——框架只留空容器，onMounted 接管、onUnmounted 清理，数据变更经 watch 调 D3 更新函数；②框架托管渲染、D3 只算——只用 D3 的 scale/layout/shape 生成坐标与 path 字符串，渲染走框架响应式模板。推荐②：与框架心智一致、无泄漏风险，D3 退化为纯计算库。这与 02 模块"Layui/Vue 抢节点划清管辖"是同一原则。
