1简介与阅读指引

1.1 定位：Python 生态的事实标准数据访问层

SQLAlchemy 不是一个"只能用对象"的 ORM，而是"ORM（对象视角）+ Core（SQL 表达式视角）"双层结构：日常 CRUD 用 ORM 省事，复杂统计/批量操作用 Core 或直接 SQL 更可控。它不替你设计表结构，而是把你的模型与 SQL 精确对应起来。

1.2 数据访问方式怎么选

方式写法适合代价
ORM（2.0 风格）类 + session.execute(select(...))业务 CRUD、模型关系复杂 SQL 表达力受限
Core（SQL 表达式）table.select().where(...)报表、批量、动态条件要懂 SQL 与表结构
原生 SQL 文本text("select ...")DBA 给的调优 SQL、数据库特性无编译期检查，注意注入
Django ORMActive Record 风格Django 项目内与框架强绑定
选型口诀：业务 CRUD 用 ORM，复杂查询用 Core，极端场景用原生 SQL——SQLAlchemy 允许三者在同一事务里混用。

1.3 与已有经验的对照

  • 对照 MyBatis/JPA：SQLAlchemy 的 Session 类似 JPA 的 EntityManager + 一级缓存 + Unit of Work；select() 构造式查询更像 Criteria API / jOOQ，而非字符串拼 SQL。
  • 对照 Prisma/TypeORM：模型类 ≈ entity，relationship() ≈ 关联字段，区别在于加载策略要显式指定（否则触发 N+1）。
  • 心智差Python 里"查出来的是对象，但对象只在 Session 内有效"——Session 一关再访问属性会报错（detached），这和很多 ORM 的直觉不同。

1.4 学习目标

  1. 理解 Engine / Connection / Session 三层，知道事务边界在哪；
  2. 用 2.0 风格定义模型、建表、完成 CRUD 与条件查询；
  3. 配置 relationship 并用预加载消除 N+1；
  4. 会配连接池参数、会用 Alembic 做迁移。

难度：★★★☆☆。前置：SQL 基础（JOIN/GROUP BY）、Python 类与装饰器。版本：SQLAlchemy 2.x。

2核心模型

五个核心模型：Engine→ Connection/Session→ Unit of Work→ 对象状态→ 加载策略。

2.1 Engine：连接池与方言的持有者

create_engine(url) 创建的是全局唯一、线程安全的资源：管理连接池 + 数据库方言（MySQL/PostgreSQL/SQLite 差异的翻译层）。要点Engine 不是连接，不要在请求里反复创建——应用启动时建一次即可。

from sqlalchemy import create_engine
engine = create_engine(
    "sqlite:///./app.db",            # 其他：postgresql+psycopg://user:pwd@host/db
    echo=False,                      # True 会打印所有 SQL，调试利器
    pool_size=10, max_overflow=20, pool_pre_ping=True,
)

2.2 Session：ORM 的工作单元（Unit of Work）

Session 是一次业务操作的会话：它维护对象身份映射（同一行只对应一个对象）、累积变更，commit() 时一次性 flush 成 SQL。作用域Web 应用里一个请求一个 Session，请求结束即关闭（FastAPI 里用 Depends + yield 实现，见 05 篇）。

2.3 Connection vs Session

维度Connection（Core 层）Session（ORM 层）
操作对象表（Table）与行（Row）模型类与实例
事务显式 begin()/commit()自动 begin，commit() 触发 flush
身份映射/缓存无有（同一主键同一对象）
典型用途批量、报表、ETL业务 CRUD

2.4 对象的四种状态

Transient（新建未加入 Session）→ Pending（add 后待 flush）→ Persistent（在 Session 中且有数据库行）→ Detached（Session 关闭后对象仍在，但已与数据库断开）。坑源Detached 状态下访问未加载的属性会抛 DetachedInstanceError。

2.5 加载策略：lazy / selectin / joined

关系字段默认惰性加载（lazy）——访问时才发 SQL，这既是便利也是 N+1 的根源。selectinload()（额外一条 IN 查询批量加载）与 joinedload()（LEFT JOIN 一次取回）是两种常用预加载手段。

3核心用法（按场景）

3.1 场景一：定义模型与建表（2.0 风格）

from typing import Optional, List
from datetime import datetime
from sqlalchemy import String, Integer, DateTime, ForeignKey, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(50), index=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
    posts: Mapped[List["Post"]] = relationship(back_populates="author",
                                               cascade="all, delete-orphan")

class Post(Base):
    __tablename__ = "posts"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(120))
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
    author: Mapped["User"] = relationship(back_populates="posts")

Base.metadata.create_all(engine)      # 建表（生产请用 Alembic，见 4.4）

2.0 风格要点Mapped[T] + mapped_column() 让类型注解真正参与映射（IDE 与 mypy 可检查），取代 1.x 的 Column()。

3.2 场景二：Session 与增删改

from sqlalchemy.orm import Session

with Session(engine) as session:                 # 退出自动 close
    u = User(name="张三")
    session.add(u)                               # Pending
    session.commit()                             # flush → INSERT → 提交事务
    print(u.id)                                  # 主键已回填

    u.name = "李四"                               # 改属性即标记脏
    session.commit()                             # UPDATE

    session.delete(u)
    session.commit()                             # DELETE
必须 commit：不 commit 就退出，事务自动回滚，改动全部丢失——这是新手最常见的"我明明改了却没生效"。

3.3 场景三：查询（select + where + 排序分页）

from sqlalchemy import select, or_, desc

with Session(engine) as session:
    stmt = (select(User)
            .where(User.name.like("张%"), User.id > 10)
            .order_by(desc(User.created_at))
            .limit(20).offset(0))
    users = session.scalars(stmt).all()          # 模型对象列表

    one = session.scalars(select(User).where(User.id == 1)).first()
    cnt = session.scalar(select(func.count()).select_from(User))   # 聚合标量
    rows = session.execute(                       # 只要部分列 → Row
        select(User.id, User.name).where(or_(User.id == 1, User.id == 2))
    ).all()

API 区分：session.execute() 返回 Row；session.scalars() 返回第一列（常用来取 ORM 对象）；session.scalar() 取单个值。

3.4 场景四：关系与预加载（消除 N+1）

from sqlalchemy.orm import selectinload

# 反例：N+1 —— 1 条查用户 + N 条查各自的文章
users = session.scalars(select(User)).all()
for u in users:
    print(u.posts)          # 每次访问触发一条 SELECT

# 正解：预加载，总共 2 条 SQL
users = session.scalars(
    select(User).options(selectinload(User.posts))
).all()

3.5 场景五：联表与聚合统计

stmt = (select(User.name, func.count(Post.id).label("post_cnt"))
        .join(Post, Post.user_id == User.id)     # 内连接
        .group_by(User.id, User.name)
        .having(func.count(Post.id) >= 2))
for name, cnt in session.execute(stmt):
    print(name, cnt)

# 左连接：没有文章的用户也要出现
select(User.name, func.count(Post.id)).outerjoin(Post, Post.user_id == User.id).group_by(User.id)

3.6 场景六：事务与批量

try:
    with Session(engine) as session:
        session.add_all([User(name=f"u{i}") for i in range(100)])
        session.commit()                # 一次性批量 INSERT
except Exception:
    session.rollback()                  # 异常必须回滚
    raise

# Core 批量：更快，绕过 ORM 开销
from sqlalchemy import insert
with engine.begin() as conn:            # begin() 自带事务提交/回滚
    conn.execute(insert(User.__table__), [{"name": f"u{i}"} for i in range(1000)])

4进阶知识点【进阶】

4.1 N+1 问题的系统解法

  • 识别：开 echo=True 或接入慢查询日志，看到"1 条 + 大量同构 SQL"即 N+1；
  • 手段：selectinload（一对多/多对多，推荐，走 IN 查询）、joinedload（多对一，走 JOIN）、contains_eager（配合手写 JOIN）；
  • 兜底：模型上声明 lazy="selectin" 让关系默认预加载；
  • 注意预加载不是越多越好——一次性 join 过多表会让结果集膨胀，按需加载。

4.2 连接池参数怎么配

参数含义建议
pool_size常驻连接数≈ 并发峰值 / worker 数，别盲目调大
max_overflow峰值可临时超出的连接数pool_size 的 1~2 倍
pool_pre_ping取连接前先探活建议 True，自动丢弃被数据库断开的连接
pool_recycle连接最大存活秒数小于数据库 wait_timeout（MySQL 常配 3600）
计算常识：总连接数 = (pool_size + max_overflow) × worker 进程数。多进程部署时必须一起算，否则会打爆数据库的 max_connections。

4.3 Session 作用域与 Web 集成

from contextlib import contextmanager

@contextmanager
def session_scope():                    # 通用模板
    s = Session(engine)
    try:
        yield s
        s.commit()
    except Exception:
        s.rollback()
        raise
    finally:
        s.close()

Web 规则：一个请求一个 Session；Session 不是线程安全的，禁止跨线程/跨请求共享；异步场景用 AsyncSession + async 驱动。

4.4 Alembic 数据库迁移

pip install alembic
alembic init migrations                       # 生成 alembic.ini + migrations/
# 在 env.py 里设置 target_metadata = Base.metadata 与数据库连接
alembic revision --autogenerate -m "add posts table"   # 自动生成迁移脚本
alembic upgrade head                          # 应用到数据库
alembic downgrade -1                          # 回滚一步

工程建议迁移脚本必须进版本库并 review：autogenerate 识别不出所有变更（如字段重命名会被识别成"删列 + 加列"，可能丢数据）。

4.5 异步 ORM（AsyncSession）

from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession

engine = create_async_engine("postgresql+asyncpg://user:pwd@host/db")
async with AsyncSession(engine) as s:
    r = await s.scalars(select(User).options(selectinload(User.posts)))
    users = r.all()          # 注意：异步下惰性加载会报错，关系必须预加载
异步铁律：AsyncSession 中禁止惰性加载（隐式 IO 不被允许），所有关系必须用 selectinload 等显式预加载，否则抛 MissingGreenlet。

6最小可运行 Demo

性质（诚实声明）：本篇为可运行的教学 demo（SQLite 单机脚本），非生产履历；生产请换 PostgreSQL/MySQL 并用 Alembic 管理结构。

6.1 Demo 设计：学生成绩管理脚本

  • 目标：建表 → 插入学生与成绩 → 查询统计（每人平均分、按班级排名）→ 更新与删除；
  • 验证：开 echo=True 数一数每条业务触发了几条 SQL，体会预加载的作用。
# demo_orm.py  ——  pip install sqlalchemy
from sqlalchemy import create_engine, select, func, String, ForeignKey
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship, Session, selectinload

class Base(DeclarativeBase):
    pass

class Student(Base):
    __tablename__ = "students"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(20))
    clazz: Mapped[str] = mapped_column(String(20), default="1班")
    scores: Mapped[list["Score"]] = relationship(back_populates="student",
                                                 cascade="all, delete-orphan")

class Score(Base):
    __tablename__ = "scores"
    id: Mapped[int] = mapped_column(primary_key=True)
    subject: Mapped[str] = mapped_column(String(20))
    value: Mapped[int] = mapped_column()
    student_id: Mapped[int] = mapped_column(ForeignKey("students.id"))
    student: Mapped["Student"] = relationship(back_populates="scores")

engine = create_engine("sqlite:///./school.db", echo=False)
Base.metadata.create_all(engine)

with Session(engine) as s:
    if not s.scalar(select(func.count()).select_from(Student)):
        zs = Student(name="张三", clazz="1班")
        zs.scores = [Score(subject="数学", value=92), Score(subject="英语", value=88)]
        s.add_all([zs, Student(name="李四", clazz="1班")])
        s.commit()

    # 统计：每人平均分（JOIN + GROUP BY）
    rows = s.execute(
        select(Student.name, func.avg(Score.value).label("avg"))
        .join(Score, Score.student_id == Student.id)
        .group_by(Student.id)
        .order_by(func.avg(Score.value).desc())
    ).all()
    for name, avg in rows:
        print(f"{name} 平均 {avg:.1f}")

    # 预加载：一次性取出学生及其成绩（避免 N+1）
    for st in s.scalars(select(Student).options(selectinload(Student.scores))):
        print(st.name, [(x.subject, x.value) for x in st.scores])

6.2 踩坑记录

  • 坑提交后立刻访问对象属性触发了额外 SELECT（expire_on_commit），在返回响应前访问会多查一次——要么一次性读够，要么配置关闭过期；
  • 坑把 Session 存成全局变量复用，第二次请求读到上一次的脏数据；
  • 坑循环里访问 st.scores 导致几十条 SQL，加 selectinload 后降到 2 条。

6.3 成果与复盘

  1. 能力：模型定义、CRUD、条件查询、联表聚合、预加载、事务模板都能落地；
  2. 一句话抓手："用 SQLAlchemy 2.0 写过数据层：Mapped 注解定义模型，Session 每请求一份，select + selectinload 预加载解决 N+1，连接池按 worker 数核算上限，结构变更走 Alembic 迁移。"

7常见坑 & Debug

7.1 N+1 查询

现象：列表页 100 条数据发了 101 条 SQL，接口随数据量线性变慢。Debug：echo=True 或慢 SQL 日志；正解：selectinload/joinedload 预加载，或只查需要的列。

7.2 忘 commit（或异常未 rollback）

现象："代码没报错但数据没变"。正解：写操作后必 commit()；异常分支必 rollback()；用 4.3 的 session_scope() 模板把流程固定下来。

7.3 DetachedInstanceError

现象：Session 关闭后访问对象属性报错。正解：在 Session 内把需要的字段读出来（转成 dict/Pydantic 模型），或 session.refresh(obj)、expire_on_commit=False；Web 接口推荐先序列化再关闭会话。

7.4 Session 跨线程/跨请求复用

现象：偶发数据错乱、连接泄漏。正解：Session 非线程安全，严格"一请求一 Session"；Engine 才是全局共享的。

7.5 原生 SQL 拼接导致注入

现象：用 f-string 拼 text(f"select * from t where name='{name}'")。正解：用绑定参数 text("select * from t where name=:name") + {"name": name}；ORM/Core 的构造式查询天然参数化。

7.6 连接池打爆 / 连接失效

现象：QueuePool limit overflow 或 MySQL server has gone away。正解：按 (pool_size+max_overflow)×worker数 反推上限；开 pool_pre_ping=True、设置 pool_recycle 小于数据库 wait_timeout。

8重点讲解

Q1：Engine、Connection、Session 三者是什么关系？

参考答案：Engine 是全局唯一的连接池 + 方言（Dialect）持有者，负责把 SQLAlchemy 的通用表达式翻译成具体数据库能执行的 SQL，并管理物理连接的创建/复用/回收——它不含事务概念，应用启动时创建一次即可。Connection 是从池中取出的一条物理连接的代理，代表一个数据库事务（engine.begin() 自动提交/回滚），Core 层用它执行 SQL。Session 是 ORM 层的工作单元：内部持有一条 Connection，额外提供身份映射（同一主键只对应一个对象）、变更追踪（dirty tracking）与 flush 机制——commit() 时把累积的对象变更翻译成 INSERT/UPDATE/DELETE 一次性发出。实践：Engine 全局唯一、Connection 随用随取、Session 每请求一份且用完即关。

Q2：什么是 N+1 查询？怎么发现和解决？

参考答案：查询出 N 条主记录后，逐条访问其惰性加载的关系字段，于是额外发出 N 条 SQL——总计 1+N 条。发现：开 engine.echo=True 打印 SQL、接入慢查询日志、或用 assert 统计测试中的语句条数；解决：①预加载——selectinload()（关系集合，走 IN 查询，共 2 条）或 joinedload()（多对一，走 LEFT JOIN 一次取回）；②只查需要的列——select(User.id, User.name) 避免加载整对象；③模型上声明 lazy="selectin" 改变默认行为；④异步场景必须预加载，因为 AsyncSession 不允许隐式 IO。权衡：预加载会一次性取回更多数据，join 过多会膨胀结果集，应按页面实际用到的字段决定加载哪些关系。

Q3：commit 之后为什么还会再发一条 SELECT？

参考答案：因为 Session 默认 expire_on_commit=True——提交后所有持久对象的属性被标记为过期，下次访问时会重新发一条 SELECT 刷新，目的是保证读到的是数据库中（可能被触发器/其他事务修改过）的最新值。副作用是"提交后访问属性会多一条 SQL"，在 Web 接口里表现为先 commit 再序列化时莫名其妙多出 N 条查询。三种解法：①在 Session 关闭/提交前把需要的字段读出来（转成 DTO/Pydantic 模型）；②Session(engine, expire_on_commit=False) 保留快照（注意：读到的是提交时刻的值，不再是最新值）；③提交后 session.refresh(obj) 显式刷新一次。Detached 同理：Session 关闭后对象脱离管理，访问未加载属性会抛 DetachedInstanceError。
