1简介与阅读指引

1.1 定位：现代 Python Web API 的默认选择之一

FastAPI = Starlette（ASGI 异步内核）+ Pydantic（类型驱动校验）+ 依赖注入系统 + 自动 OpenAPI 文档。它面向的是REST/JSON API与AI 服务接口（FastAPI 已成为很多 LLM 服务暴露 HTTP 接口的首选）。

1.2 横向对比：该选哪个框架

框架类型强项适合代价
FastAPIASGI 异步校验/文档/异步/类型提示JSON API、AI 服务、微服务生态比 Django 薄，需自选 ORM
FlaskWSGI 同步极简、插件多、心智轻小服务、原型、内部工具无内置校验/异步较弱
DjangoWSGI 全栈ORM/后台/权限/全家桶内容型站点、后台系统重、约定多、异步支持后补
Express(Node)异步JS 全栈同语言BFF、前端团队自持校验/类型靠生态自建
选择口诀：纯 API + 要文档 + 要异步 → FastAPI；要后台/ORM 全家桶 → Django；小脚本服务 → Flask。

1.3 心智差异（面向 JS/Java 开发者）

  • 参数不是从 request 对象里手抠：函数签名即接口契约——路径参数、查询参数、Body 模型、依赖全部声明在参数里，框架自动注入与校验（对照 Express 的 req.query/req.body、Java 的 @RequestParam/@RequestBody）。
  • 文档自动生成：写完就有 /docs（Swagger UI）与 /openapi.json——前端可直接生成 TS 类型与请求客户端。
  • 易错类型注解在 FastAPI 里不只是提示，它参与运行时校验：注解写错，请求就会被 422 拒绝。

1.4 学习目标

  1. 写清"路径参数 / 查询参数 / 请求体模型 / 响应模型"四类契约；
  2. 用 Depends 做依赖注入（数据库会话、当前用户、配置）；
  3. 理解 async def 与 def 路由的线程池差异并正确选择；
  4. 掌握 APIRouter 拆分、lifespan 生命周期、异常与中间件。

难度：★★★☆☆。前置：Python 类型注解、HTTP 基础、装饰器；建议同时阅读本模块 04 篇（asyncio）。

2核心模型

四个核心模型：声明式参数→ Pydantic 模型→ 依赖注入→ ASGI 异步。

2.1 声明式参数：函数签名即契约

框架按参数名 + 类型注解 + 默认值判断来源：与路径模板同名 → 路径参数；标量类型且不在路径 → 查询参数；Pydantic 模型 → 请求体；Depends(...) → 依赖。好处IDE 自动补全 + 运行时校验 + 自动文档三合一。

2.2 Pydantic 模型：一份定义三处复用

from pydantic import BaseModel, Field, EmailStr

class UserIn(BaseModel):                 # 入参：请求体校验
    name: str = Field(min_length=1, max_length=20)
    age: int = Field(ge=0, le=150, default=18)
    email: EmailStr | None = None        # 格式校验开箱即用

class UserOut(BaseModel):                # 出参：响应序列化（可裁剪敏感字段）
    id: int
    name: str
    age: int

入参/出参分离是 FastAPI 的最佳实践：response_model=UserOut 保证密码哈希等内部字段永远不会外泄。

2.3 依赖注入（Depends）：可复用、可覆盖、可测试

Depends(fn) 声明"这个参数由 fn 提供"，框架在调用路由前先解析依赖树。典型用途：数据库会话、鉴权取当前用户、分页参数、限流器。测试价值用 app.dependency_overrides[get_db] = fake_db 一行替换依赖，无需 mock 框架。

2.4 ASGI 与异步路由

FastAPI 跑在 ASGI 服务器（uvicorn）上，天然支持异步与 WebSocket。关键规则：async def 路由在事件循环里执行；def（普通）路由会被丢到外部线程池执行——这条差异决定了阻塞代码放哪儿（见 4.1）。

3核心用法（按场景）

3.1 场景一：最小应用与启动

pip install "fastapi[standard]"      # 含 uvicorn 与常用可选依赖
from fastapi import FastAPI

app = FastAPI(title="demo", version="1.0")

@app.get("/")
def root():
    return {"msg": "hello"}

@app.get("/users/{user_id}")
def get_user(user_id: int, q: str | None = None):   # 路径参数 + 可选查询参数
    return {"user_id": user_id, "q": q}
uvicorn main:app --reload --port 8000     # 开发：热重载
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4   # 生产：多进程

自动文档：启动后访问 http://127.0.0.1:8000/docs（Swagger UI）与 /redoc，还能 /openapi.json 导出给前端生成客户端。

3.2 场景二：POST 校验与响应模型

from fastapi import FastAPI, HTTPException, status

app = FastAPI()
db: dict[int, UserOut] = {}
seq = 0

@app.post("/users", response_model=UserOut, status_code=status.HTTP_201_CREATED)
def create_user(payload: UserIn):
    global seq
    seq += 1
    user = UserOut(id=seq, name=payload.name, age=payload.age)
    db[seq] = user
    return user                      # 只返回 UserOut 声明的字段

@app.get("/users/{uid}", response_model=UserOut)
def read_user(uid: int):
    if uid not in db:
        raise HTTPException(status_code=404, detail="user not found")
    return db[uid]
校验失败的表现：参数不合法时框架自动返回 422 Unprocessable Entity，响应体里精确指出哪个字段、什么原因——前端可以直接把这段信息渲染成表单错误。

3.3 场景三：依赖注入（会话 / 当前用户）

from fastapi import Depends, Header

def get_db():                        # 依赖：每次请求一个会话，退出即关闭
    db = SessionLocal()
    try:
        yield db                     # yield 之后的代码在响应返回后执行
    finally:
        db.close()

def current_user(token: str = Header(alias="Authorization"), db=Depends(get_db)):
    user = db.query(User).filter_by(token=token).first()
    if not user:
        raise HTTPException(401, "invalid token")
    return user

@app.get("/me")
def me(user=Depends(current_user)):  # 依赖可嵌套依赖
    return {"id": user.id, "name": user.name}

要点带 yield 的依赖 = 上下文管理器式依赖：yield 之前初始化，之后清理（提交/关闭连接/释放锁）；Depends 的依赖本身还能再 Depends，形成依赖树。

3.4 场景四：路由拆分与标签分组

# routers/users.py
from fastapi import APIRouter
router = APIRouter(prefix="/users", tags=["users"])

@router.get("")
def list_users(skip: int = 0, limit: int = 20):
    return {"skip": skip, "limit": limit}

# main.py
app.include_router(users.router)     # 文档里按 tags 分组展示

3.5 场景五：中间件与 CORS

from fastapi.middleware.cors import CORSMiddleware
import time

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],   # 前端地址，别写 "*" 带凭证
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.middleware("http")
async def timing(request, call_next):           # 自定义中间件：统计耗时
    t0 = time.perf_counter()
    response = await call_next(request)
    response.headers["X-Process-Time"] = f"{time.perf_counter()-t0:.3f}"
    return response

3.6 场景六：统一异常处理

from fastapi.responses import JSONResponse

class BizError(Exception):
    def __init__(self, code: int, msg: str):
        self.code, self.msg = code, msg

@app.exception_handler(BizError)
def biz_handler(request, exc: BizError):
    return JSONResponse(status_code=200, content={"code": exc.code, "msg": exc.msg})

4进阶知识点【深入】

4.1 async def 还是 def？（最容易踩的坑）

写法执行位置内部调阻塞 IO 会怎样建议
async def主事件循环堵死整个进程的所有请求全程异步库（httpx/asyncpg）时用
def外部线程池（默认 40 线程）只占一个线程，不阻塞循环用同步库（requests/psycopg2）时用
铁律：async def 里绝不能出现同步阻塞调用（time.sleep、requests.get、同步 ORM）；反之同步库也不要在 async 路由里用——要么全异步，要么明确用 def 走线程池。

4.2 lifespan：启动/关闭生命周期

from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动时：建连接池、预热模型、拉配置
    app.state.pool = await create_pool()
    yield
    # 关闭时：优雅释放资源
    await app.state.pool.close()

app = FastAPI(lifespan=lifespan)

用途加载一次性的重资源（ML 模型、连接池、定时任务），替代已废弃的 @app.on_event("startup")。

4.3 BackgroundTasks：响应后继续干活

from fastapi import BackgroundTasks

def send_email(email: str, content: str):
    ...   # 耗时任务

@app.post("/notify")
def notify(email: str, bg: BackgroundTasks):
    bg.add_task(send_email, email, "welcome")    # 先返回响应，再后台执行
    return {"queued": True}

边界BackgroundTasks 适合轻量、短时任务（发邮件、写审计日志）；任务重、要重试、要跨进程 → 用 Celery/RQ + 消息队列。

4.4 Pydantic v2 要点

  • 校验用 Field(gt=0, max_length=20)，自定义校验器用 @field_validator（v1 的 @validator 已废弃）；
  • 序列化用 model_dump() / model_dump_json()（v1 的 .dict() 已废弃）；
  • 性能核心由 Rust 重写，比 v1 快数倍；嵌套模型与 Optional 语义更严格。

4.5 异步数据库与并发

异步栈组合：SQLAlchemy 2.0 async_session + asyncpg 或 SQLModel。提醒异步不会让单条 SQL 变快，好处是高并发下不被连接/等待占满线程；同时要给连接池设合理上限（见本模块 06 篇）。

6最小可运行 Demo

性质（诚实声明）：本篇为可运行的教学 demo（内存存储的 REST CRUD），非生产履历；生产请接数据库（见 06 篇）。

6.1 Demo 设计：任务管理 CRUD 服务

  • 目标：一个文件跑通 增删改查 + 校验 + 状态码 + 404 + 自动文档；
  • 验证：uvicorn main:app --reload 后在 /docs 里直接点着调，或用 curl 验证 422/404。
# main.py  ——  pip install "fastapi[standard]"  &&  uvicorn main:app --reload
from typing import Optional
from fastapi import FastAPI, HTTPException, Query, status
from pydantic import BaseModel, Field

app = FastAPI(title="Task API", version="1.0.0")

class TaskIn(BaseModel):
    title: str = Field(min_length=1, max_length=50)
    done: bool = False
    priority: int = Field(default=1, ge=1, le=5)

class TaskOut(TaskIn):
    id: int

tasks: dict[int, TaskOut] = {}
seq = 0

@app.get("/tasks", response_model=list[TaskOut], summary="任务列表")
def list_tasks(done: Optional[bool] = None,
               limit: int = Query(default=20, ge=1, le=100)):
    items = [t for t in tasks.values() if done is None or t.done == done]
    return items[:limit]

@app.post("/tasks", response_model=TaskOut, status_code=status.HTTP_201_CREATED)
def create_task(payload: TaskIn):
    global seq
    seq += 1
    task = TaskOut(id=seq, **payload.model_dump())
    tasks[seq] = task
    return task

@app.patch("/tasks/{tid}", response_model=TaskOut)
def update_task(tid: int, payload: TaskIn):
    if tid not in tasks:
        raise HTTPException(status_code=404, detail="task not found")
    tasks[tid] = TaskOut(id=tid, **payload.model_dump())
    return tasks[tid]

@app.delete("/tasks/{tid}", status_code=status.HTTP_204_NO_CONTENT)
def delete_task(tid: int):
    if tasks.pop(tid, None) is None:
        raise HTTPException(status_code=404, detail="task not found")
curl -X POST localhost:8000/tasks -H "Content-Type: application/json" \
     -d '{"title":"写文档","priority":3}'
curl "localhost:8000/tasks?done=false&limit=10"
curl -X POST localhost:8000/tasks -H "Content-Type: application/json" -d '{"title":""}'
# → 422，body 里精确指出 title 字段 min_length 不满足

6.2 踩坑记录

  • 坑用全局 dict 当存储：多 worker 部署时每个进程一份数据，请求打到不同进程结果不一致——状态必须放数据库/Redis；
  • 坑路由写成 async def 却调用同步 ORM，压测时 QPS 塌方——改成 def 走线程池或全异步栈；
  • 坑响应直接 return orm_obj 却没声明 response_model，把 password_hash 一起返回了。

6.3 成果与复盘

  1. 能力：能独立搭一个带校验、文档、错误码、依赖注入的 REST 服务；
  2. 一句话抓手："用 FastAPI 写过任务管理 REST 服务：Pydantic 做入参/出参分离校验、Depends 注入会话与鉴权、async 与线程池路由按库的类型选择，接口文档由 OpenAPI 自动生成给前端。"

7常见坑 & Debug

7.1 async 路由里调同步阻塞库

现象：压测并发一上去 QPS 反而暴跌，请求互相排队。正解：换异步库（httpx/asyncpg/aiofiles），或把路由改回 def 让框架丢线程池。

7.2 422 校验失败不知从哪查

现象：请求被 422 拒了但看不出原因。Debug：看响应体 detail[].loc（字段位置）+ msg + type；或在模型里加 Field(description=...)、用 examples 让文档示例更清晰。

7.3 Pydantic v1/v2 API 混用

现象：.dict()/@validator 报废弃警告或行为异常。正解：统一到 v2——model_dump()、@field_validator、Optional[X] = None 显式可空；升级前跑一遍回归测试。

7.4 依赖对象被跨请求共享

现象：Depends 里用了不带 yield 的单例（如全局 Session），导致事务串味、数据脏读。正解：会话类资源一律用 yield 依赖，每请求一份、用完即关。

7.5 多 worker 下的全局状态

现象：uvicorn --workers 4 后内存计数器、互斥标志失效。正解：进程外状态入库/入 Redis；进程内只读资源（模型）放 lifespan 加载一次。

7.6 CORS 配错导致前端报跨域

现象：浏览器控制台 CORS error，但 curl 正常。正解：allow_origins 写前端精确源（含协议与端口）；带 Cookie 时不能 allow_origins=["*"] 且需 allow_credentials=True。

8重点讲解

Q1：FastAPI 为什么能做到"自动校验 + 自动文档"？

参考答案：核心是类型注解在运行时可读。定义路由时，FastAPI 通过 inspect.signature 与 typing.get_type_hints 拿到每个参数的注解类型，把 int/str、Optional、Pydantic 模型分别翻译成参数来源（path/query/body）与校验规则；Pydantic 负责把原始 JSON 转成强类型对象（失败则汇总成 422 的 detail 列表）。同一份类型信息还能生成 JSON Schema，进而产出 OpenAPI 描述文件——所以 /docs 是"类型信息的副产品"而非额外维护。实践含义：注解写错 = 接口契约写错，因此模型要入参/出参分离并用 response_model 控制外泄字段。

Q2：async def 路由和 def 路由到底差在哪？怎么选？

参考答案：async def 的路由函数会被 await 在事件循环里执行，全程不切换线程，因此能支撑大量并发等待——但一旦里面出现同步阻塞调用（requests、time.sleep、同步 ORM、CPU 密集计算），就会把事件循环堵死，所有请求一起卡住。def 路由框架会把它丢进外部线程池（默认约 40 线程）执行，阻塞只占一个线程、不影响循环；代价是线程数有限、高并发下会排队，且不能 await。选型：整条调用链都是异步库 → async def；只能用同步库（老 SDK、部分数据库驱动）→ def；CPU 密集 → 两者都不合适，应丢进程池或独立任务队列。

Q3：Depends 解决了什么问题？为什么利于测试？

参考答案：Depends 是 FastAPI 内置的依赖注入：把"获取当前用户""拿数据库会话""解析分页参数"这类横切逻辑抽成可复用单元，路由只声明"我需要什么"，框架负责按依赖树解析并注入（依赖还能嵌套依赖）。带 yield 的依赖等价于上下文管理器：yield 前初始化、响应返回后执行清理（提交/关闭/释放锁），保证每请求一份资源且必定释放。测试价值：app.dependency_overrides[get_db] = lambda: FakeSession() 就能把真实数据库换成假实现，不需要 monkeypatch 或 mock 框架——这让集成测试写起来非常轻。
