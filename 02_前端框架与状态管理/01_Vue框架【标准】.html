Vue 框架

标准 定位：渐进式前端框架——数据驱动视图、组件化、响应式绑定

Vue 用"数据驱动视图"取代手写 DOM：你只改数据，框架负责更新界面。本页讲清响应式数据绑定、组件化系统、生命周期，以及 Vue2 选项式 API 的核心心智。案例来自本技术栈最真实的项目系列：数据编排平台与低代码平台（Vue2+ElementUI）、智能监控大屏（Vue2 与 jQuery 渐进式混用）。Vue3 的 Proxy 响应式原理与组合式 API 单独成深入页。

1简介与阅读指引

1.1 定位

Vue 是渐进式 JavaScript 框架，核心是响应式数据绑定 + 组件化：你维护一份状态（data）、声明它在界面上长什么样（模板），状态一变，框架自动更新受影响的 DOM——这就是 MVVM（Model-View-ViewModel）：视图与模型绑定，ViewModel 负责同步。Vue2 用 Object.defineProperty 做响应式，Vue3 换成 Proxy（02 篇深入）。它终结的是 jQuery 时代"状态变了→自己改 DOM"的漏改噩梦——开发者只关心数据。

1.2 痛点

  • 手改 DOM 极易漏改、难维护——状态到视图的同步是体力活；
  • 界面无法拆分复用；
  • 老项目要上 Vue 却不敢推翻重写。

1.3 学习目标与阅读指引

  1. 理解响应式数据流（状态→依赖收集→批量更新→patch DOM）；
  2. 掌握选项式组件五要素（props/data/computed/watch/生命周期）；
  3. 分清 v-if/v-show、computed/methods 等易混对；
  4. 学会渐进引入（局部挂载与 jQuery 共存）；
  5. 避开五条高频坑（Vue.set/key/nextTick/清理/computed）。

前置知识：01 模块 JS 核心。难度：★★☆☆☆。务必动手：第 6 章 Demo。本篇不涉及：组合式 API 深入与响应式原理（02 篇专讲）、路由/状态管理（03/04 篇）。

2核心模型

五个核心模型：响应式绑定（灵魂）→ 组件化（复用单元）→ 指令（模板语法）→ computed 与 watch（派生与副作用）→ 生命周期（初始化与清理的锚点）。

2.1 响应式绑定：谁用到就记谁

data 字段被劫持：Vue2 用 Object.defineProperty 把属性转 getter/setter——访问时收集依赖、修改时触发更新；模板渲染/computed/watch 都是依赖方。坑：新增/删除属性检测不到（需 Vue.set）；数组按下标赋值 arr[i]=x、改 length 也不触发——但 push/pop/shift/unshift/splice/sort/reverse 这 7 个数组方法已被 Vue 重写，可正常触发。Vue3 用 Proxy 解决全部盲区。

2.2 组件化：单向数据流

应用是一棵组件树：数据靠 props 向下、事件靠 emit 向上单向流动；每个组件自带模板、状态、逻辑。组件是复用与拆分的基本单位——表格面板、流程图容器、低代码物料都做成组件。

2.3 模板指令与 v-if/v-show

常用指令：插值 {{ }}、v-bind(:) 绑属性、v-on(@) 绑事件、v-if/v-show 控显隐、v-for 列表。v-if vs v-show：v-show 始终渲染只切 display（切换开销小）；v-if 惰性销毁/重建（切换开销大但初始不渲染）——频繁切换用 v-show，很少切换用 v-if。坑：v-for 必须给稳定的 :key（唯一 id，别用 index）。

2.4 computed 与 watch：派生值 vs 副作用

computed：派生状态，依赖变才重算、带缓存——模板组合逻辑首选；watch：观察变化后做副作用（发请求/操作 DOM）。经验法则：能 computed 就别在 methods 里重复算；methods 只用于事件处理。

2.5 生命周期：在哪初始化、在哪清理

  • created：实例建好、data 可用——常在这发请求；
  • mounted：DOM 已挂载——操作 DOM、初始化图表；
  • beforeDestroy/destroyed：清理定时器、解绑监听、dispose 图表——防内存泄漏（衔接 01 模块 04 篇泄漏三来源）。

3核心用法（按场景）

3.1 场景一：选项式组件基本结构

export default {
  props: { title: String },
  data() { return { count: 0, list: [] }; },
  computed: {
    double() { return this.count * 2; }      // 派生状态，带缓存
  },
  watch: {
    count(nv, ov) { console.log('变了', ov, '→', nv); }
  },
  mounted() { this.fetchList(); },
  beforeDestroy() { clearInterval(this.timer); },
  methods: {
    inc() { this.count++; },
    async fetchList() { this.list = await api.getList(); }
  }
};

3.2 场景二：模板绑定与列表

<template>
  <h3>{{ title }}</h3>
  <button @click="inc" :disabled="count >= 10">加 {{ double }}</button>
  <ul>
    <li v-for="item in list" :key="item.id">{{ item.name }}</li>
  </ul>
</template>

// 智能监控大屏：局部挂载 Vue，与 jQuery 页面共存
new Vue({
  el: '#alarm-panel',
  data: { alarms: [] },
  mounted() {
    // WebSocket 推来的数据，jQuery 负责别处，这里只管告警面板

  }

关键纪律：划清"谁管哪块 DOM"——两边改同一节点会互相覆盖。

4进阶知识点【进阶】

首次学习可整章跳过。前置：选项式五要素已用熟。

4.1 nextTick 与更新时序

DOM 更新是异步批量的：同一 tick 内多次改状态合并成一次重渲染。改完立刻读 DOM 是旧值——要 this.$nextTick(() => ...)。原理见 03 篇微任务（nextTick 在微任务阶段批量 flush）。

4.2 v-for 里的 key 与 diff

key 是虚拟 DOM diff 的"身份"：稳定 id 让节点跨渲染可追踪（移动复用），index 作 key 在排序/增删时身份错位——就地复用导致输入框内容串行等经典 bug。原则：列表项有唯一 id 就绝不用 index。

4.3 mixins 的复用困境与替代

mixins 的问题：来源不透明（模板里 this.data 看不出来自哪个 mixin）、命名冲突、多 mixin 叠加难追踪。Vue3 的 composables（组合式函数）按"逻辑功能"聚合、显式导入——复用方式的演进是 Vue3 的核心动机之一（02 篇展开）。

4.4 组件通信谱系

props/emit 是主干；跨层级：provide/inject（祖先→后代，主题/配置类场景）；全局状态：Vuex/Pinia（04 篇）；事件总线在 Vue3 已移除（$on 依赖实例方法）——跨组件非父子通信收敛到状态管理。通信方式按"层级距离"选，别一步到位上全局 store。

4.5 keep-alive 与组件缓存

<keep-alive> 包裹的组件切换时不销毁（activated/deactivated 钩子），保留状态——列表页→详情页→返回列表不丢滚动与筛选。代价：内存驻留，配合 include/exclude 控制缓存范围。

7常见坑 & Debug

五条高频坑。

7.1 Vue2 新增属性不响应

根因：defineProperty 只劫持已有属性，新增的没有 setter。正解：Vue.set(obj, key, val) 或整体替换对象；Vue3 无此问题。

7.2 v-for 缺 key 或用 index

现象：列表排序/增删后渲染错乱。根因：index 作 key 身份错位、就地复用。正解：稳定的唯一 id 作 key（4.2）。

7.3 改数据后立刻读 DOM

现象：this.list.push(x) 后马上查 li 还是旧值。根因：DOM 更新异步批量。正解：this.$nextTick(() => {...})。

7.4 定时器/监听未清理

现象：切走页面后定时器还在跑、报"操作已销毁组件"。正解：beforeDestroy 里 clearInterval、off 事件、dispose 图表（对应泄漏三来源）。

7.5 computed 与 methods 混用

误区：把模板组合逻辑写进 methods。正解：派生值用 computed（依赖不变不重算、有缓存），methods 只用于事件处理。

8重点讲解

Q1：Vue 的响应式原理（Vue2 版）？有什么局限？

参考答案：Vue2 用 Object.defineProperty 把 data 的每个属性转成 getter/setter——访问时收集依赖（谁在渲染/computed/watch 里读了这个字段，就把它记为依赖），修改时触发更新（通知依赖方入队，nextTick 批量刷新后虚拟 DOM diff、patch DOM）。局限三处：①新增/删除属性劫持不到（defineProperty 只能处理"声明时存在的属性"）——需 Vue.set；②数组下标赋值与 length 修改不触发——7 个重写方法除外；③初始化要递归遍历全部属性，深层对象开销大。Vue3 用 Proxy 代理整个对象，三处局限全解（02 篇深入）。

Q2：v-if 和 v-show 怎么选？computed 和 watch 怎么选？

参考答案：v-show 始终渲染、只切 display——切换开销小、初始开销大（即使隐藏也要渲染），适合频繁切换；v-if 惰性渲染、销毁/重建——初始不渲染省成本、切换开销大，适合很少切换或权限类一次判断。computed 是带缓存的派生值（依赖不变直接返回缓存），适合模板组合逻辑；watch 是观察变化执行副作用（发请求/操作 DOM/深度监听），适合"变化后要做事"。口诀：要一个值用 computed，要做一件事用 watch。

Q3：老项目怎么渐进引入 Vue？

参考答案：Vue 的"渐进式"就为此设计——局部挂载：在老页面某个区域 new Vue({ el: '#panel' })，该区域享受数据驱动，其余仍 jQuery。关键纪律是 DOM 所有权：划清 Vue 管哪块、jQuery 管哪块，两边改同一节点会互相覆盖。路径：局部试点（告警面板）→ 跑通后推广 → 新模块全面组件化（SFC）。渐进引入优于推翻重写：风险可控、随时可停。
