ElementUI 与 ElementPlus

标准 定位：桌面端后台组件库——ElementUI(Vue2) 与 ElementPlus(Vue3)

ElementUI 与 ElementPlus 是中后台最常用的 Vue 组件库：表格、表单、弹窗、菜单开箱即用，保证整个产品 UI 一致。ElementUI 服务 Vue2，ElementPlus 服务 Vue3。本页讲清按需引入、二次封装、主题定制，以及两者差异。案例来自数据编排平台（ElementUI 封装与按需引入）与 业务系统（ElementPlus 表单设计器组件封装、主题定制）。

1简介与阅读指引

1.1 定位

ElementUI / ElementPlus 是饿了么团队出品的 Vue 桌面端组件库（表单/表格/弹窗/导航/消息提示等几十个组件）：ElementUI 对应 Vue2、ElementPlus 对应 Vue3。本技术栈后台系统几乎都基于它——数据编排平台（Vue2+ElementUI）、业务系统（Vue3+ElementPlus）。它让后台开发从"写控件"变成"拼控件"、交互视觉统一；工程上还要解决两件事：按需引入（体积）与二次封装（业务口径）。

1.2 痛点

  • 全量引入首屏包过大；
  • 每个列表页重复写分页/序号列/loading/空态；
  • 跨版本迁移（UI→Plus）API 差异逐页踩；
  • 只改主色——hover/active 派生色仍旧蓝。

1.3 学习目标与阅读指引

  1. 落地按需引入（Vue2 插件方案 vs Plus+Vite 自动摇树）；
  2. 封装 CommonTable/SearchForm 统一业务口径；
  3. 用 CSS 变量派生体系做主题定制（含派生色）；
  4. 掌握 UI→Plus 的迁移差异清单（icon/插槽/message）；
  5. 用 schema 驱动渲染表单（设计器核心）。

前置知识：03 篇插槽（二次封装重度依赖作用域插槽与 $attrs）。难度：★★☆☆☆。本篇不涉及：各组件逐一用法（查官方文档，本篇讲工程化模式）。

2核心模型

四个核心模型：分层架构（基础组件→二次封装→业务页）→ 按需引入→ 主题定制→ UI vs Plus 差异。

2.1 后台组件分层：三层金字塔

Element 基础组件（按需引入）→ 二次封装业务组件（CommonTable/SearchForm：加分页/序号列/loading/空态/校验等业务默认值，插槽透传）→ 业务页面（只拼业务组件、传配置）。分层的意义：交互口径改一处全站生效；Element 升级时业务页零改动。

2.2 按需引入：只打包用到的

全量引入把整个组件库打进包；按需只打包用到的组件。版本差异：Vue2 用 babel-plugin-component 类插件；ElementPlus 本身 ESM、配合 Vite 自动 tree-shaking 开箱即用。

2.3 主题定制：变量派生体系

Element 的颜色/圆角/字号基于变量：ElementPlus 覆盖 --el-color-primary 等 CSS 变量；ElementUI 改 SCSS 变量。坑：只改主色不够——hover/active/disabled 派生色要随派生体系一起覆盖，否则按钮 hover 还是旧蓝。

2.4 ElementUI vs ElementPlus：迁移差异清单

  • icon：属性写法 icon="edit" → 组件插槽写法（图标独立为 @element-plus/icons-vue 包，单独安装以组件注册）；
  • message：this.$message() 全局挂载 → import { ElMessage } 显式导入；
  • 插槽：具名插槽写法、弹窗组件参数均有变化——迁移要清单化逐页核对。

3核心用法（按场景）

3.1 场景一：按需注册（Vue2）

import Vue from 'vue';
import { Button, Table, TableColumn, Pagination, Dialog, Form, FormItem } from 'element-ui';
Vue.use(Button); Vue.use(Table); Vue.use(Pagination); // 只注册用到的
import 'element-ui/lib/theme-chalk/index.css';         // 样式按需另配

3.2 场景二：二次封装通用表格

<!-- CommonTable.vue：封装分页/loading/列 -->
<el-table :data="data" v-loading="loading">
  <el-table-column type="index" label="#" />
  <el-table-column v-for="c in columns" :key="c.prop" :label="c.label" :prop="c.prop" />
</el-table>
<el-pagination layout="prev, pager, next" :total="total" @current-change="onPage" />

封装要点：业务页只传 columns 和接口；插槽透传（$attrs，见 4.2）保证特殊列可定制。

3.3 场景三：ElementPlus 主题定制

/* 覆盖全局 CSS 变量即可换主色（派生色随体系联动） */
:root {
  --el-color-primary: #2d6a3f;
  --el-border-radius-base: 6px;
}

3.4 场景四：schema 驱动表单渲染（设计器核心）

<!-- 表单渲染器：按字段类型渲染对应控件 -->
<el-form-item v-for="f in fields" :key="f.key" :label="f.label">
  <el-input v-if="f.type==='input'" v-model="form[f.key]" />
  <el-select v-else-if="f.type==='select'" v-model="form[f.key]">
    <el-option v-for="o in f.options" :key="o.value" :label="o.label" :value="o.value" />
  </el-select>
  <el-date-picker v-else-if="f.type==='date'" v-model="form[f.key]" />
</el-form-item>

契约先行：与产品定字段类型枚举（input/select/date…），渲染器按类型分发控件；校验规则抽公共函数按类型自动带出。

4进阶知识点【进阶】

首次学习可整章跳过。前置：CommonTable 封装已落地。

4.1 二次封装的透传三件套

包装 Element 组件时保留原生能力：$attrs 透传未声明属性与事件（inheritAttrs:false + v-bind="$attrs"）、作用域插槽全量转发（v-for 遍历 $slots/#动态插槽名）、expose 方法代理（把 el-table 的方法暴露出去）。缺一不可——否则封装组件"能干 80% 的活，剩下 20% 干不了"。

4.2 校验规则体系

表单校验散在各页是维护灾难：抽成公共函数库（required/length/format/手机号/身份证），schema 字段按 type 自动带出规则，特殊页可覆盖。校验口径与后端对齐（正则同一份），前后端规则漂移是"前端能过后端拒"的根源。

4.3 异步 options 的加载策略

下拉数据来自接口时：①未到就渲染下拉为空——等数据到再渲染或组件内 loading；②大字典用远程搜索（filterable + remote）；③多页复用的字典进 store 缓存（04 篇边界判断）。

4.4 表格性能

大数据量表格：分页是首选；必须长列表时用 vxe-table（05 模块专讲）虚拟滚动；Element 表格千行以上渲染明显变慢——选型时按数据量定，不硬扛。

4.5 暗黑模式与设计令牌

ElementPlus 内置 dark 主题：html.dark 类切换（配 darkMode:'class' 类似机制）；品牌令牌与 01 模块 CSS 变量换肤同一思想——组件库变量、业务令牌、页面样式三层统一规划，避免两套换肤机制打架。

6最小可运行 Demo

性质：真实项目落地——数据编排平台（Vue2+ElementUI）列表封装、业务系统（Vue3+ElementPlus）表单设计器与品牌主题。

6.1 落地设计

  • 按需引入：减小首屏包体积；
  • 通用封装：CommonTable/SearchForm 统一业务口径；
  • schema 渲染：按字段类型渲染对应控件；CSS 变量覆盖主色与派生色（3.3/3.4 代码）。

6.2 踩坑记录（真实问题与解法）

  • 全量引入包大：早期全量引入首屏包大——改按需引入后明显改善；
  • API 迁移差异：Plus 迁移时 icon 属性变插槽、$message 变 ElMessage 导入——逐页清单化修改；
  • select options 异步：options 未到就渲染下拉为空——等数据到再渲染或加 loading；
  • 派生色没同步：只改主色 hover 仍旧蓝——用 CSS 变量派生体系一起覆盖。

6.3 验证与经验

  1. 按需引入后首屏包体积明显下降（bundle 分析对照）；
  2. 设计器/渲染器共用一套 schema，改字段类型枚举两端同步；
  3. 经验：列表页抽象成通用组件一次封装处处复用；主题要覆盖派生色；跨大版本迁移清单化推进。

7常见坑 & Debug

五条高频坑。

7.1 全量引入导致包过大

正解：按需引入；ElementPlus 配合 Vite 自动 tree-shaking 开箱即用。

7.2 ElementUI 与 ElementPlus API 混淆

误区：以为两者 API 一致。正解：按对应版本文档查；icon 属性变插槽、$message 变 ElMessage 导入——迁移清单化。

7.3 二次封装缺失导致重复代码

正解：通用模式（表格+分页+查询）抽业务组件；封装时透传三件套（4.1）保住原生能力。

7.4 主题只改主色漏派生色

现象：按钮 hover 还是旧蓝。正解：用 Element 的 CSS 变量派生体系一起覆盖（--el-color-primary-light-3 等）。

7.5 表单校验规则不统一

正解：校验规则抽公共函数库，设计器按字段类型自动带出；正则与后端对齐同一份。

8重点讲解

Q1：组件库工程化的两个核心问题是什么？怎么解决？

参考答案：体积——全量引入把几十个组件全打进包，按需引入（tree-shaking）只打包用到的：Vue2 用 babel 插件转换，ElementPlus 是 ESM 配合 Vite 开箱即用。口径——原生组件直接用会让每个页面重复写分页/序号列/loading，且交互不统一：二次封装业务组件层（CommonTable/SearchForm），业务默认值收敛在一处、Element 升级业务页零改动。分层架构：基础组件（按需）→ 业务组件（封装）→ 业务页面（拼装）。

Q2：ElementUI 迁 ElementPlus 要注意什么？

参考答案：三类高频差异——①icon：字符串属性 icon="edit" 变组件写法（@element-plus/icons-vue 独立包、组件注册）；②全局方法：this.$message 挂载式变 import { ElMessage } 显式导入（组合式下无 this，方向一致）；③插槽与弹窗参数：具名插槽写法、dialog 参数有变。迁移方法：差异清单化、逐页核对、先基础组件后业务页面；与 Vue2→Vue3 迁移合并规划。

Q3：二次封装 Element 表格组件，怎么不丢原生能力？

参考答案：透传三件套——①$attrs：inheritAttrs:false + v-bind="$attrs"，把未声明的属性与事件透给内部 el-table（调用方仍可传 border/height 等）；②插槽转发：遍历 $slots 用动态插槽名 #[name] 转发，自定义列模板照常用；③方法代理：通过 ref 把 el-table 的方法（clearSort 等）暴露出去。原则：封装加"默认值与默认行为"，不封死"定制口子"——否则封装组件能干 80% 的活、剩下 20% 逼人绕开它。
