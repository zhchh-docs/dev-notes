jQuery 与 Bootstrap

深入 定位：现代框架的前史——命令式 DOM 操作时代的工程遗产

jQuery 与 Bootstrap 是 Vue/React 之前的前端标配：jQuery 用"选择器+方法+链式调用"统一了 DOM 操作，Bootstrap 用栅格系统和现成组件快速搭后台。本技术栈从 智能监控大屏（jQuery 时代自研 Grid/Tree/Dialog 插件）到大屏（Layui+Vue 混合改造）一路走来。本页讲透 jQuery 的链式调用、事件委托、插件机制，Bootstrap 栅格原理，以及它们与现代框架的承接关系——这是理解"为什么需要现代框架"的最好对照。

1技术点概览

是什么

jQuery 是一个 DOM 操作库：用 $(selector) 选中元素，链式调用方法操作它们，抹平浏览器差异。Bootstrap 是 CSS+JS 框架：栅格布局、按钮/表格/弹窗等现成组件，快速搭出一致的后台。在 Vue/React 出现前，它们是前端开发的事实标准。

解决什么问题

原生 DOM 操作冗长、各浏览器 API 不一致、要自己拼样式。jQuery 一行代码选中并操作元素；Bootstrap 一套类名搭出布局与组件。代价是：命令式——你要一步步告诉浏览器"做什么"（选中、改文本、绑事件），状态和 DOM 的同步全靠自己维护。这正是现代声明式框架要解决的痛点。

图 1 命令式 jQuery 与声明式框架的范式对比（示意）

横向对比：jQuery 时代与现代框架的承接

  • DOM 操作：jQuery 手写 $('#x').text(v)；现代框架只改状态，框架改 DOM。
  • 事件绑定：jQuery .on('click')；现代框架模板里 @click。
  • 组件复用：jQuery 靠插件（$.fn.grid）；现代框架靠组件/SFC。
  • 布局：Bootstrap 栅格类；现代框架用 Flex/Grid + 组件库（Element 等）。
  • 渐进承接：新项目用现代框架，老项目可局部引入 jQuery，或逐步重写——智能监控大屏 就是 Vue2+jQuery 共存的过渡态。

2核心概念

2.1 选择器与 DOM 操作核心

一句话定位：$(selector) 返回包裹 DOM 集合的 jQuery 对象，后续方法都作用在集合上。

  • 核心动作：用 CSS 选择器选中，再链式操作 text/html/attr/css/append。

2.2 链式调用（Chaining）

一句话定位：几乎所有 jQuery 方法都返回 this，所以能一路 find().addClass().on() 串下去。

  • 关键：方法返回当前 jQuery 对象——一次选中、连续操作。

2.3 事件委托（Event Delegation）

一句话定位：把子元素事件绑在父元素上，靠冒泡统一处理动态新增的子元素。

  • 写法：$('#list').on('click','li',fn)。
  • 好处：动态新增的 li 不用重新绑定；绑一个 vs 绑 N 个更省内存。

要点动态列表的点击处理必须委托到不变的父容器，否则翻页/新增后监听丢失。

2.4 jQuery 插件机制

一句话定位：插件 = 往 $.fn 上加方法，之后 $(...).插件名() 就能用。

  • 写法：$.fn.grid = function(opts){ ... }，之后 $('#x').grid()。

智能监控大屏 的 Grid/Tree/Dialog 都是这么做的；插件末尾要 return this.each(...) 保持可链式。

2.5 Ajax 封装

一句话定位：$.ajax/$.get/$.post 把 XHR 封装成回调/Promise，是 fetch/axios 之前的标准请求方式。

  • 价值：比手写 XMLHttpRequest 简洁、抹平浏览器差异。

2.6 Bootstrap 栅格系统

一句话定位：把容器分 12 列，row 包 col-md-* 指定占几列，自动响应式。

  • 本质：Bootstrap 3 栅格基于 float + 百分比宽度 + 媒体查询；Bootstrap 4/5 已改为 Flexbox（display:flex）。
  • 规则：一行内 col-* 加起来 ≤12，多了会换行。

2.7 Bootstrap 组件

一句话定位：按钮/表格/表单/弹窗/下拉等现成组件，配类名即用。

  • 交互：JS 交互靠 data 属性或 API 触发。

后台系统的快速搭建靠它。

2.8 与现代框架的承接

一句话定位：理解 jQuery 的痛点，就理解 Vue/React 为什么出现。

  • jQuery 痛点：状态与 DOM 手动同步、选择器散落、插件难以组合。
  • 现代框架的解法：命令式变声明式、DOM 同步自动化、复用从插件升级为组件。

样本智能监控大屏 的 Vue2+jQuery 混用、大屏 Layui→Vue2 改造，正是这一承接的真实样本。

4核心语法与 API 要点

4.1 链式调用与 DOM 操作

$('#list')
  .find('li.active')      // 选中子元素
  .addClass('highlight')   // 加类
  .text('已选中')          // 改文本
  .on('click', function(){ /* ... */ });

4.2 事件委托

// 动态新增的 li 不用重新绑定
$('#list').on('click', 'li', function () {
  console.log($(this).text());
});

4.3 写一个 jQuery 插件（$.fn）

$.fn.grid = function (options) {
  return this.each(function () {       // 返回 this 保持链式
    const $el = $(this);
    const cfg = $.extend({}, $.fn.grid.defaults, options);
    // 渲染表格、绑事件……
  });
};
$.fn.grid.defaults = { pageSize: 20 };
// 使用：$('#table').grid({ url: '/list' });

注意$.extend({}, defaults, options) 是浅拷贝，嵌套对象会被各实例共享；要深拷贝须写 $.extend(true, target, src)——defaults 含嵌套配置时，浅合并会导致多实例互相污染。

4.4 Bootstrap 栅格类

<div class="container">
  <div class="row">
    <div class="col-md-4">左侧</div>
    <div class="col-md-8">右侧</div>
  </div>
</div>

5实战项目经验（实战落地）

5.1 项目背景

一句话定位：jQuery 时代的两处实战——智能监控大屏 自研 Grid/Tree/Dialog 插件，以及数据可视化大屏项目 Layui+Vue 混合改造。

  • 智能监控大屏（2016-2018）：监控场景要高度定制的表格/树/弹窗，无合适现成库，自研 jQuery 插件。
  • 数据可视化大屏项目：早期基于 Layui（带 jQuery 的 UI 框架），后局部引入 Vue2。

5.2 我的角色与职责

  • 角色：前端开发，负责自研 jQuery 插件库与 Layui→Vue 渐进改造。
  • 团队与分工：前端若干（估算）；我写插件与改造方案。

5.3 技术栈

  • jQuery + $.fn 插件机制 + 事件委托 + Layui；后期局部 Vue2。

5.4 落地设计

  • 插件化：Grid/Tree/Dialog 往 $.fn 挂方法，配置驱动渲染 DOM。
  • 事件委托：行/分页事件绑容器，动态重建的行也能响应。
  • 渐进改造：Layui 负责静态结构，Vue 局部挂动态数据面板。

5.5 关键实现要点

// 自研表格插件：配置驱动渲染
$.fn.grid = function (opts) {
  return this.each(function () {
    const $wrap = $(this).empty();
    opts.columns.forEach(c => { /* 渲染表头 */ });
    opts.data.forEach(row => { /* 渲染行 */ });
    $wrap.on('click', 'tr', () => opts.onRowClick?.(row)); // 事件委托
  });
};
// 业务：$('#alarmGrid').grid({ columns, data, onRowClick })

5.6 真实问题与解法

  • 没 return this：插件忘 return this.each，链式断、页面复用报错。
  • 动态行绑事件丢失：事件绑动态生成的行，翻页重建后监听丢失；改事件委托绑容器。
  • 插件无销毁方法：面板切走事件还挂着内存泄漏；补 destroy()。
  • 抢同一 DOM 节点：Layui 与 Vue 都改同一节点互相覆盖；划清管辖区域。
  • 切屏没清理：图表/定时器切屏未清，内存只涨不降。

5.7 量化成果

  • 一套 Grid/Tree/Dialog 插件复用到多个监控面板，渐进改造不推翻重写。

5.8 协作与排期过程

  • 排期：先做 Grid 插件跑通，再抽 Tree/Dialog；改造从高频面板试点。
  • 协作：与维护老 Layui 页面的同事约定 DOM 边界。

5.9 复盘与可复用经验

  • 插件三件套：return this、事件委托、提供 destroy。
  • 命令式 DOM 管理的痛点：正是这些催生了后来全面转向 Vue 数据驱动。

教训这些都是"命令式手工管理 DOM"时代的典型痛点，也正是后来全面转向 Vue 数据驱动的原因。

5.10 面试讲法

实战要点在 jQuery 时代用 $.fn 插件机制自研了可复用的 Grid/Tree/Dialog，并亲历了 Layui→Vue 的渐进改造，因此深刻理解命令式 DOM 管理的痛点与数据驱动的价值。

6易错点与面试重点

6.1 插件不 return this 破坏链式

一句话定位：插件末尾不 return this，链式调用就断了。

  • 正解：插件末尾 return this.each(...)，保持可链式调用。

6.2 动态元素直接绑事件丢失

一句话定位：动态 DOM 重建后监听丢失，要委托到不变的父容器。

  • 现象：翻页/新增 DOM 后点击无反应。
  • 正解：用事件委托绑在不变的父容器上。

6.3 事件与 DOM 不清理导致泄漏

一句话定位：面板切走后事件还挂着、DOM 没清，内存泄漏。

  • 正解：组件销毁/面板切走时 .off()、清空容器、移除插件实例。

6.4 jQuery 与 Vue 直接改同一节点

一句话定位：两边都改同一节点会互相覆盖、状态不一致。

  • 正解：划清"谁管哪块"，不交叉操作。

6.5 过度用 jQuery 操作该用状态的场景

一句话定位：命令式 DOM 同步极易漏改，新功能优先声明式。

  • 教训：新功能优先声明式（Vue），jQuery 只用于过渡/特殊 DOM。

6.6 Bootstrap 栅格数学错误

一句话定位：一行内 col-* 加起来超过 12 就会换行错位。

  • 现象：列换行错位。
  • 正解：一行内 col-* 加起来 ≤12，多了会换行。
