组件设计模式与插槽机制

标准 定位：组件通信四件套——props / emit / slot / provide-inject 的取舍

组件化的核心问题是"组件之间怎么配合"：父子传数据用 props、向父级发事件用 emit、留内容口子用 slot、跨层级共享用 provide/inject。选对方式，组件才既复用又灵活。本页讲清四种通信方式的适用场景与取舍，落到数据编排平台 通用物料插槽 通用动态组件渲染容器——用 slot 与 render 函数实现配置驱动渲染，这是低代码平台的底层能力。

1简介与阅读指引

1.1 定位

组件设计模式是"组件之间如何传数据、传内容、传事件"。Vue 四件套：props（父→子传数据，单向）、emit（子→父发事件）、slot（父把内容插进子组件的占位）、provide/inject（祖先→后代跨层级注入）；再配 <component :is> 动态组件，就能做到配置驱动渲染。它解决的是"通用组件的灵活性"：弹窗/表格/容器要适应不同业务，不能把内容写死——留 slot 口子、props 配行为。数据编排平台的通用物料插槽（渲染哪个组件/传什么属性/绑什么事件全部配置化）就是这套机制的低代码应用。

1.2 痛点

  • 通用组件内容写死——换业务就要改组件；
  • 深层 props 层层透传（prop drilling）；
  • 动态渲染时组件没注册/事件名不对——渲染空白。

1.3 学习目标与阅读指引

  1. 讲清四件套各自的职责与取舍（按层级距离选）；
  2. 分清默认/具名/作用域插槽三级（作用域插槽是核心）；
  3. 落地配置驱动渲染容器（component :is + v-bind/v-on + 动态插槽）；
  4. 避开五条高频坑（改 props/slot 不分发/未注册/滥用 inject/v-model 约定）。

前置知识：01 篇组件基础、02 篇组合式。难度：★★★☆☆。务必动手：第 6 章 Demo。本篇不涉及：跨页面全局状态（04 篇 Pinia）。

2核心模型

五个核心模型：props 单向数据流→ emit 与 v-model 本质→ slot 三级→ provide/inject→ 动态组件与配置驱动。

2.1 props：父→子单向数据流

子组件声明 props 接收父级数据，props 是组件的对外接口（配 type/required/default 校验）。单向：子组件不改 props——破坏单向流会导致父子状态不一致；要改就 emit 让父级改，或子组件内部复制一份。

2.2 emit 与 v-model 的本质

子 $emit('event', payload)、父 @event="handler"。v-model 的本质：Vue2 是 :value + @input 的语法糖；Vue3 改为 :modelValue + @update:modelValue，并支持 v-model:title 多个具名 v-model——自定义组件要按新约定收 modelValue、发 update 事件。

2.3 slot 三级：内容分发出口

  • 默认插槽：组件模板留 <slot></slot>，父标签内容渲染到这里；
  • 具名插槽：<slot name="head"> 留多个口子，父级 #head 对应；
  • 作用域插槽：子组件把内部数据回传给父级决定怎么渲染（如 el-table 列模板）——从"塞内容"升级到"塞渲染逻辑"。

2.4 provide/inject：跨层级但要克制

祖先 provide、任意后代 inject，免去层层 props——适用真正跨层级的全局配置（主题、登录态、字典）。坑：过度使用会让数据来源不清晰难追踪——普通父子通信仍用 props/emit（通信谱系见 01 篇 4.4）。

2.5 动态组件：配置驱动的钥匙

<component :is="compName"> 按变量选组件渲染；render 函数用 JS 描述渲染结果更灵活。核心：一份配置描述"用哪个组件、什么 props、绑什么事件"，运行时动态渲染——通用物料插槽容器，低代码"拖拽出页面"的底层机制。

3核心用法（按场景）

3.1 场景一：props / emit 基本用法

<!-- 子组件 -->
<button @click="$emit('select', item)">{{ title }}</button>
<script>
export default { props: { title: String, item: Object } }
</script>
<!-- 父组件 -->
<Child :title="'标题'" :item="row" @select="onSelect" />

3.2 场景二：作用域插槽（子把数据回传）

<!-- 子组件：把 row 通过插槽暴露给父级 -->
<slot :row="row"></slot>
<!-- 父组件：决定这行长什么样 -->
<MyList>
  <template #default="{ row }">{{ row.name }} <b>{{ row.status }}</b></template>
</MyList>

3.3 场景三：动态组件配置驱动

<!-- 通用物料插槽：根据配置动态渲染 -->
<component
  :is="resolveComp(config.comp)"
  v-bind="config.props"
  v-on="config.on">
</component>

3.4 场景四：四种通信方式取舍

方式适用注意
props父→子传数据单向，子不应改 props
emit子→父发事件配 v-model 可双向
slot父给子塞内容作用域插槽回传数据
provide/inject跨层级共享别滥用，来源要清晰

4进阶知识点【进阶】

首次学习可整章跳过。前置：配置驱动容器已跑通。

4.1 递归组件与树形渲染

组件在自身模板里引用自己（<TreeNode> 套 <TreeNode>），配合配置树的 children 字段递归渲染——菜单/分类树/低代码画布的标准实现。两个条件：递归终止条件 + 稳定 key（唯一 id，index 会错乱，实战坑 7.4）。

4.2 attrs 与透传

$attrs 收集父传的未声明 props 与事件，inheritAttrs: false + v-bind="$attrs" 实现"包装组件透传"——封装 el-table 加默认配置又允许调用方覆盖，是二次封装组件库的关键技巧。

4.3 依赖注入的响应性与设计

provide 传 ref/computed 保持响应性；用 InjectionKey（Symbol）+ TS 泛型给 inject 标类型、防 key 冲突。设计约定：provide 只提供"读多写少"的上下文，可变业务状态走 store（04 篇）——inject 是"配置通道"不是"数据总线"。

4.4 渲染策略：h 函数与函数式组件

h 函数（createVNode）比模板更底层：动态属性名、条件复杂、性能敏感时用；函数式组件（无状态、无实例）适合纯展示包装件。配置驱动容器在插槽分发逻辑复杂时，render 比 template 更好写。

4.5 组件设计的分层判断

给一个新需求选组件形态：展示复用→props+slot；行为复用→composable（02 篇）；跨层级配置→provide；跨页面状态→store。多数"想抽组件"的需求其实是"想抽逻辑"——先问复用的是结构还是行为。

6最小可运行 Demo

性质：数据编排平台/低代码平台真实落地——通用物料插槽配置驱动渲染容器。

6.1 完整实现（registry + 动态渲染 + 插槽分发）

配置结构约定：{ comp, props, on, slots }；动态渲染按 comp 取真实组件、v-bind 绑属性、v-on 绑事件；具名插槽分发 slots 内容、作用域插槽回传行数据。

// 容器渲染逻辑
const registry = { 'el-button': ElButton, 'search-panel': SearchPanel };
// config = { comp:'el-button', props:{ type:'primary' }, on:{ click: onOk } }
// 模板：<component :is="registry[config.comp]" v-bind="config.props" v-on="config.on">
//   <template v-for="(slot,name) in config.slots" #[name]>{{ slot }}</template>
// </component>

6.2 踩坑记录（真实问题与解法）

  • 组件未注册：:is 写字符串名时组件未注册渲染空白——维护 registry 并确保注册；
  • 事件名用 Vue 名：v-on="config.on" 事件名要用 click 而非 onClick，否则绑不上；
  • 作用域插槽没暴露：回传数据时子组件忘 <slot :row> 暴露，父级拿不到；
  • 递归 key 用 index：深层嵌套递归渲染更新错乱——改配置项唯一 id。

6.3 逐段解析

  • registry 而非字符串直填：显式注册表 = 白名单 + 类型安全，杜绝"渲染空白"这类静默失败；
  • v-on 的事件名口径：配置里存原生事件名（click），容器不做转换——契约写进文档；
  • 动态插槽 #[name]：插槽名也是配置的一部分——comp/props/on/slots 四维齐备才是完整的物料描述。

6.4 复盘与可复用经验

  1. 配置驱动 = 组件 + props + events + slots 的抽象：四个维度都要覆盖；
  2. 动态组件要先注册：registry 是安全做法；
  3. 递归列表用稳定 key：别用 index。

7常见坑 & Debug

五条高频坑。

7.1 子组件修改 props

危害：破坏单向数据流，父子状态不一致。正解：emit 通知父级改，子组件内部需要可变副本就用 data/ref 复制一份。

7.2 slot 内容没正确分发

正解：多口子用具名插槽，子组件 <slot name="x">、父级 #x 严格对应；动态插槽名用 #[name]。

7.3 动态组件没注册或 key 错误

现象：:is 渲染空白或更新错乱。正解：组件已注册（registry）+ 给稳定 key。

7.4 滥用 provide/inject

危害：数据来源不清晰、难追踪。正解：只用于真正跨层级的全局配置（主题/字典/登录态）；普通父子用 props/emit；可变业务状态走 store。

7.5 v-model 约定搞混

要点：自定义组件支持 v-model 要自己收 value、emit 事件；Vue3 是 modelValue/update:modelValue（不再是 value/input），且支持 v-model:title 具名多个——写自定义组件按新约定。

8重点讲解

Q1：Vue 组件间有哪些通信方式？各自适用什么场景？

参考答案：按"层级距离"选——props/emit（父子主干，单向数据流）；slot（父向子分发内容，作用域插槽可回传子组件数据）；provide/inject（祖先→任意后代的跨层级配置注入，别当数据总线）；store（跨页面全局状态，04 篇）；v-model 是 props+emit 的语法糖（Vue3 为 modelValue 约定）。原则：通信方式随层级递增而升级，别一步到位上全局 store。

Q2：作用域插槽解决什么问题？和普通插槽的区别？

参考答案：普通插槽是"父传内容给子"——内容由父级数据决定；作用域插槽是"子的数据、父的渲染"——子组件通过 <slot :row="row"> 把内部数据回传，父级用 #default="{ row }" 决定这行长什么样。典型场景：el-table 列模板（表格组件拥有数据与排序逻辑，但每列的展示形态由使用者定制）。本质：把"渲染决策权"从子组件转移到父级，同时保留数据所有权在子组件——通用组件灵活性的关键。

Q3：低代码"配置驱动渲染"的底层机制是什么？

参考答案：一份 JSON 配置描述物料的四个维度——comp（哪个组件）+ props（什么属性）+ on（绑什么事件）+ slots（插什么内容）；容器用 <component :is="registry[config.comp]" v-bind="config.props" v-on="config.on"> 加 #[name] 动态插槽分发渲染。配置变→渲染结果变，这就是"拖拽出页面"的底层。工程要点：registry 显式注册（白名单防静默失败）、事件名用原生口径、递归渲染用稳定 key。
