技术栈详解 · 03_数据可视化

数据可视化 · 模块导览

精讲 本模块 9+1 篇 · 建议学习时长 2~3 周

可视化的本质是"把数据映射成视觉编码"。本模块先建立选型地图与渲染底座认知（01），再按场景学工具：声明式图表（ECharts）、自绘（D3）、关系图（G6/GoJS）、3D（Three.js）、地图（GIS），最后是大屏适配与大数据量渲染两大工程专题。

1这个模块解决什么问题

读完本模块，你应该能：为业务场景选对可视化方案与库，独立完成图表/大屏/图分析开发，并让它在十万级数据量下不卡。

  • 给大屏业务的你：01 → 02 → 08 → 09 四篇就是一条大屏生产线（选型、图表、适配、性能）。
  • 给面试的你：Canvas/SVG/WebGL 选型依据、ECharts 配置体系、大数据渲染优化是高频考点。
  • 给深度定制的你：D3 的"数据到 DOM 的映射思想"是所有可视化库的底层语言。

本模块 9 篇按学习曲线排列，编号即建议阅读顺序。每篇标注了前置依赖，跳读前请确认前置已过。

4模块边界：这里不讲什么

  • 绘图 API 的语言基础（Canvas/SVG 语法）在 01 模块第 10 篇；
  • UI 设计规范与配色审美不在本库范围；
  • GIS 的后端瓦片服务只讲概念，实现需后端模块配合；
  • WebGL 原生（shader）只作原理介绍，深入属图形学方向。

5进入下一篇前的自测

能答出以下任意 4 条，就可以放心进入 可视化技术选型与原理；答不出就先回到对应篇：

  1. Canvas 与 SVG 的选型依据是什么？各适合什么场景？
  2. ECharts 里 dataZoom 与大数据量下的 dataSampling 各解决什么？
  3. 十万级散点渲染卡顿，你的优化清单有哪些？
  4. G6 与 GoJS 的定位差异？关系图布局算法举两例。
  5. 大屏适配的等比缩放方案有什么副作用，怎么补救？
