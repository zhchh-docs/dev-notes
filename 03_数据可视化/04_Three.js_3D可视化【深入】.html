Three.js 3D 可视化

深入 定位：WebGL 上层的 3D 渲染引擎——场景图 + 相机 + 材质光照 + 渲染循环

Three.js 对 WebGL 做了一层易用封装，让开发者不必手写 shader 与缓冲管理即可搭建 3D 场景：场景图组织物体、相机定义视角、几何+材质描述外观、渲染循环驱动帧。数据可视化大屏项目用它把万级监测点渲染成稳定 3D 点云。本页讲透场景图、相机投影、材质光照、渲染循环与万点性能（InstancedMesh/视锥剔除/LOD/帧预算）。

1技术点概览

是什么

一句话定位：Three.js 是 WebGL 的高级封装——用场景/相机/网格/渲染器的对象模型组织 3D。

  • 场景 Scene：物体的树形容器。
  • 相机 Camera：决定从哪看、用什么投影（透视/正交）。
  • 网格 Mesh = 几何体 Geometry + 材质 Material：前者定形状，后者定外观。
  • 渲染器 Renderer：每帧把场景从相机视角光栅化到 Canvas。

解决什么问题

一句话定位：把实时 3D 引擎骨架做好，业务只管摆物体、打光、动相机。

  • 原生 WebGL 门槛高：要手写顶点/片元 shader、管顶点缓冲矩阵、自己实现矩阵栈与渲染循环。
  • 项目落地：大屏用它做 3D 站点布局、点云态势可视化。

  • 选 Three.js：足够轻、API 直观、生态示例丰富。
  • Cesium：仅明确要"地球级地理可视化"时考虑。
  • Babylon：要"完整游戏循环 + 物理"才上。

2核心概念

2.1 场景图（Scene Graph）

一句话定位：场景是 Object3D 节点树，父节点动则子节点跟着动。

  • 节点：Mesh、Light、Group、Camera 都是 Object3D，各有 position/rotation/scale，变换按父子层级累乘。
  • Group：把一组物体当整体移动/旋转。

心智模型父节点动子节点跟着动——这是组织层级 3D 物体（如一个变电站含多台设备）的基础。

2.2 相机（Camera）

一句话定位：透视相机用于常规 3D，正交相机用于精确对齐的 2.5D 面板。

  • PerspectiveCamera：近大远小，符合人眼。
  • OrthographicCamera：无透视、工程图纸感，用于需精确对齐的面板。
  • 坑必设 aspect（否则画面拉伸）与 near/far 裁剪面，落在裁剪面外的物体会被剔除。

2.3 几何体（Geometry）与缓冲

一句话定位：几何体是顶点数据，万点就写进一个 BufferGeometry。

  • 内置基本体：BoxGeometry/SphereGeometry/PlaneGeometry。
  • 点云：BufferGeometry 自定义一组顶点，万级坐标写进 position 属性。
  • 性能：BufferGeometry（按属性缓冲）优于旧 Geometry。

2.4 材质与着色（Material）

一句话定位：材质与几何体解耦，按真实度与开销取舍。

  • MeshBasicMaterial：不受光照、纯色，最省。
  • MeshLambertMaterial：漫反射，便宜；MeshStandardMaterial：PBR 最真实但贵。
  • PointsMaterial：点云专用。
  • 取舍：大屏静态展示用 Lambert/Basic 省开销。

2.5 光照（Light）

一句话定位：大屏常"环境光 + 一盏平行光"，或干脆不打光。

  • AmbientLight：环境光整体提亮；DirectionalLight：平行光像太阳。
  • PointLight：点光源；SpotLight：聚光。

2.6 网格（Mesh）与 draw call

一句话定位：性能核心是 draw call，万级相同物体用 InstancedMesh 合并。

  • draw call：每画一组同材质同几何体的物体，GPU 一次绘制调用；几千个独立 Mesh 会把 GPU 调度打满。
  • 要点InstancedMesh：一次 draw call 画多个实例——万点稳定渲染的关键。

2.7 渲染循环与帧（Render Loop）

3D 是逐帧重绘：requestAnimationFrame 里每帧调 renderer.render(scene, camera)。动画/旋转在每帧回调里更新物体变换。帧率 60fps 意味着每帧预算约 16.6ms——包含 JS 更新、矩阵计算、GPU 绘制三部分。

2.8 视锥剔除与 LOD（Culling & LOD）

视锥剔除（Frustum Culling）：相机看不到的物体自动不提交绘制，Three.js 默认开启。LOD（Level of Detail）：远处物体用低模、近处用高模，省顶点。配合空间划分（八叉树/四叉树）可快速剔除整块不可见区域——万点大场景的必备。

4核心语法与 API 要点

4.1 最小 3D 场景

import * as THREE from 'three';
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(60, innerWidth / innerHeight, 0.1, 1000);
camera.position.z = 10;
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);
// 一个方块 = 几何体 + 材质
const cube = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  new THREE.MeshStandardMaterial({ color: '#3d7a4f' })
);
scene.add(cube);
scene.add(new THREE.AmbientLight(0xffffff, 0.6));
// 渲染循环
(function animate() {
  requestAnimationFrame(animate);
  cube.rotation.x += 0.01; cube.rotation.y += 0.01;
  renderer.render(scene, camera);
})();

4.2 写法对比：逐点 Mesh vs InstancedMesh

// 写法 A（卡）：每个点一个独立 Mesh → 上万 draw call
// for (let i = 0; i < 10000; i++) {
//   const m = new THREE.Mesh(geo, mat);
//   m.position.set(x[i], y[i], z[i]);
//   scene.add(m);
// }

// 写法 B（稳）：InstancedMesh，一次 draw call 画 1 万实例
const inst = new THREE.InstancedMesh(geo, mat, 10000);
const dummy = new THREE.Object3D();
for (let i = 0; i < 10000; i++) {
  dummy.position.set(x[i], y[i], z[i]);
  dummy.updateMatrix();
  inst.setMatrixAt(i, dummy.matrix);    // 每个实例的变换塞进同一缓冲
}
inst.instanceMatrix.needsUpdate = true;
scene.add(inst);
取舍：大量"同形状、同材质"物体（万点、重复设备模型）用 InstancedMesh；少数不同物体才用独立 Mesh。这是 3D 性能优化的第一原则。

4.3 点云：BufferGeometry 自定义顶点

const positions = new Float32Array(N * 3);   // 万级坐标
// ... 填充 positions ...
const geo = new THREE.BufferGeometry();
geo.setAttribute('position', new THREE.BufferAttribute(positions, 3));
const points = new THREE.Points(geo, new THREE.PointsMaterial({ size: 0.05, color: '#4f8a63' }));
scene.add(points);
// 高频刷新只更新 position 缓冲的一段
geo.attributes.position.needsUpdate = true;

4.4 自适应窗口

window.addEventListener('resize', () => {
  camera.aspect = innerWidth / innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(innerWidth, innerHeight);   // 大屏多分辨率必加
});

5实战项目经验（实战落地）

5.1 项目背景（业务量级/场景）

一句话定位：电力大屏在 3D 站点布局上叠加万级实时监测点，旋转视角不能掉帧。

  • 场景：3D 厂区/站点布局上叠加万级监测点（温度、负荷越限），需旋转视角交互且高频刷新。
  • 量级：监测点上万、运行在低配大屏主机上。

5.2 我的角色与职责

一句话定位：3D 可视化渲染层前端，负责性能预算与渲染循环。

  • 分工：负责场景图、相机、材质光照与渲染循环调优；后端提供点位坐标与遥测值。

5.3 技术栈

  • 前端：Three.js（WebGL），与 ECharts 2D 面板同屏叠加。
  • 部署：大屏主机，GPU 配置偏弱，需做降级。

5.4 落地设计（关键选型理由）

一句话定位：用 InstancedMesh 压 draw call、BufferGeometry 缓冲只更新脏位、视锥剔除+LOD。

  • 实例化：万点从逐点 Mesh 改 InstancedMesh，一次 draw call 画全部。
  • 缓冲：高频刷新只更新脏位并置 position.needsUpdate=true，不重建几何体；只改一段时用 attribute.addUpdateRange(start,count)（r159 起弃用旧的 updateRange）。
  • 降级：静态层 Lambert/Basic 省 PBR，远端点配 LOD。

5.5 关键实现要点

const inst = new THREE.InstancedMesh(
  new THREE.SphereGeometry(0.05, 8, 8),
  new THREE.MeshLambertMaterial({ color: 0x4f8a63 }),
  10000
);
const dummy = new THREE.Object3D();
function layoutPoints(samples) {
  samples.forEach((s, i) => {
    dummy.position.set(s.x, s.y, s.z);
    dummy.updateMatrix();
    inst.setMatrixAt(i, dummy.matrix);
  });
  inst.instanceMatrix.needsUpdate = true;   // 只标记缓冲脏，不重建
}
scene.add(inst);
(function animate() {
  requestAnimationFrame(animate);
  renderer.render(scene, camera);
})();

5.6 真实问题与解法

  • 坑draw call 上万：逐点独立 Mesh 是 GPU 调度瓶颈——换 InstancedMesh 后 draw call 骤降。
  • 坑每帧重建 BufferGeometry：高频刷新顶点反复上传——改只更新 position.needsUpdate。
  • 坑低配 GPU 扛不住 PBR：大屏 GPU 弱，静态层改 Lambert/Basic，仅特写保留 PBR。
  • 要点前后对比：从个位数 fps 提到接近 60fps（估算）。

5.7 量化成果

  • 帧率：旋转视角稳定在可交互范围，约从个位数 fps 提到接近 60fps（估算）。
  • draw call：从万级压到个位数。

5.8 协作与排期过程

  • 契约先行：与后端约定点位坐标与遥测值数组格式。
  • 联调协商：按现场主机 GPU 档位分材质降级策略，低配机关抗锯齿。

5.9 复盘与可复用经验

  • 要点先压 draw call：万级同类对象首选 InstancedMesh/Points，别逐对象建 Mesh。
  • 要点缓冲只更新脏位：高频数据刷新绝不重建几何体。
  • 要点按 GPU 降级：大屏弱机静态层用低成本材质。

5.10 面试讲法

实战要点「万级监测点 3D 渲染，实践中常采用 InstancedMesh 把 draw call 从万级压到个位数、BufferGeometry 只更新脏位、视锥剔除+LOD，帧率从个位数拉到接近 60。」

6易错点与面试重点

6.1 逐点独立 Mesh 打爆 draw call

  • 现象：物体过千就转不动、帧率暴跌。
  • 原因：每个独立 Mesh 一次 draw call，GPU 调度开销随物体数线性增长。

坑正解：大量同形物体用 InstancedMesh，点云用 BufferGeometry+Points。面试常考"draw call 是什么、怎么降"。

6.2 高频重建几何体

  • 现象：数据一刷新就卡顿、内存上涨。
  • 原因：每次都 new BufferGeometry 重建，GPU 反复重新上传顶点缓冲。

坑正解：复用几何体，只更新属性缓冲并设 needsUpdate = true。

6.3 相机 aspect 不随窗口更新

  • 现象：窗口拉大后画面拉伸变形。
  • 原因：aspect 固定为初始宽高比。

坑正解：resize 时更新 camera.aspect 并 updateProjectionMatrix()，再 renderer.setSize。

6.4 过度使用 PBR 与抗锯齿

  • 现象：低端大屏 GPU 上帧率低。
  • 原因：MeshStandardMaterial 逐像素 PBR 计算 + MSAA 抗锯齿开销大。

坑正解：静态/远层用 Lambert/Basic，抗锯齿按机器能力取舍，特写才用 PBR。

6.5 不利用视锥剔除与 LOD

  • 现象：大场景里很多看不见的物体也在耗算力。
  • 原因：未做剔除/LOD，所有物体每帧都参与计算与提交。

坑正解：保证视锥剔除开启（默认），大场景加空间划分，远处用 LOD 低模。

6.6 渲染循环里做重活

  • 现象：动画卡顿、帧率不稳。
  • 原因：在 animate 回调里做数据处理/布局计算，挤占 16.6ms 预算。

坑正解：数据准备在循环外/Worker，渲染循环只做必要的变换更新与 render。
