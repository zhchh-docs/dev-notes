GIS 地图可视化

标准 定位：地理空间可视化——坐标系、瓦片与地图库的选型地图

GIS 可视化的第一课不是地图库，而是坐标系：WGS84/GCJ-02/BD-09 三套坐标不纠偏就"点位漂移数百米"；第二课是瓦片原理：地图不是一张大图，而是按层级预切的 XYZ 瓦片网格。选型按需求分层——简单标点用 ECharts geo，交互地图用 Leaflet，海量点/矢量瓦片用 MapLibre，地球级用 Cesium。

1简介与阅读指引

1.1 定位：先坐标系，再瓦片，最后才是库

GIS 可视化的知识分三层：①坐标系——业务数据是经纬度（WGS84）、国内地图服务是 GCJ-02（火星坐标）、百度是 BD-09，三套不纠偏点位漂移数百米；②瓦片与渲染——地图不是一张大图，而是按缩放层级预切的 XYZ 瓦片网格，矢量瓦片（MVT）则把"数据下发、客户端渲染"倒过来；③地图库选型——按需求复杂度分层，别为标几个点引入重型 GIS 引擎。

1.2 横向对比：按需求分层选库

方案定位优势适用
ECharts geo/map图表内嵌地图与图表体系一致、visualMap 直接可用省/市级统计着色、简单标点
Leaflet轻量交互地图库极轻（~40KB）、插件丰富、上手最快点位标注/弹窗/简单交互
MapLibre GL矢量瓦片渲染引擎客户端渲染、样式灵活、海量点流畅大数据量地图/自定义样式
高德/百度 JS API国内服务商全家桶国内底图+POI+路网+逆地理编码一体依赖国内地图服务的业务
Cesium3D 地球引擎地球级 3D、地形、影像图层地理空间分析、3D 地球

  1. 讲清三套坐标系与纠偏——国内 GIS 的第一坑；
  2. 理解瓦片金字塔与 LOD 的同源思想；
  3. 掌握 GeoJSON 数据格式与 ECharts geo 的衔接；
  4. 建立按需求分层的选型框架。

诚实声明：本套技术栈的地图场景以 ECharts geo 组件（01/02 篇热力图与分布图）为主，Leaflet/MapLibre 属学习储备与评估视角——本篇把 GIS 概念地基打牢，供选型时直接调用。

2核心模型

五个核心模型：坐标系（总纲）→ 瓦片金字塔→ GeoJSON 数据→ 图层模型→ 投影。

2.1 坐标系：WGS84 / GCJ-02 / BD-09

  • WGS84：GPS 原始坐标，国际标准，GeoJSON/PostGIS 默认；
  • GCJ-02：国测局加密（"火星坐标"）——高德/腾讯地图用它；
  • BD-09：百度在 GCJ-02 上再加密。

核心：WGS84 的点直接丢到高德底图上，漂移数百米——底图与业务数据必须同坐标系，否则先纠偏（WGS84→GCJ-02 有公开算法，非线性不可简单减偏移）。

2.2 瓦片金字塔：地图 = 层级瓦片网格

缩放级别 z（0-18+）下，全球切成 2^z × 2^z 张 256px 瓦片：级别越深瓦片越多、越精细；客户端按视口只请求可见瓦片（URL 模板 /{z}/{x}/{y}.png）。栅格瓦片是预渲染图片（快、样式固定）；矢量瓦片（MVT）下发几何数据、客户端按样式渲染（体积小、样式随时换、可交互）。

2.3 GeoJSON：GIS 的 JSON

Point/LineString/Polygon 及 Multi 系列 + properties 业务字段 + FeatureCollection 容器——前端 GIS 事实上的数据交换标准；ECharts 的 map/geo 组件、Leaflet 的 L.geoJSON、PostGIS 导出全走它。行政区边界就是一份 Polygon GeoJSON（阿里 DataV 提供全国省市边界下载）。

2.4 图层模型：底图 + 业务层叠加

地图库的心智都是"图层栈"：底图层（瓦片）→ 矢量业务层（标记/线/面/热力）→ 交互浮层（popup/tooltip）。业务数据只改业务层，底图按视口懒加载——与 09 篇大屏分层渲染同构。

2.5 投影：球面 → 平面

Web 端主流 Web Mercator（EPSG:3857）：等角（形状正）但高纬度面积失真——Google/高德/Leaflet 默认；经纬度直投（EPSG:4326）用于数据存储。换算关系：业务存 4326 经纬度，渲染时库内部转 3857——除非自建投影，一般无感。

3核心用法（按场景）

3.1 场景一：ECharts geo 行政区着色（本套技术栈主用法）

// 注册行政区 GeoJSON（DataV 边界数据）
fetch('https://geo.datav.aliyun.com/areas_v3/bound/440000_full.json')
  .then(r => r.json())
  .then(geoJson => {
    echarts.registerMap('guangdong', geoJson);
    chart.setOption({
      visualMap: { min: 0, max: 100, inRange: { color: ['#dcfce7', '#dc2626'] } },
      series: [{
        type: 'map', map: 'guangdong',
        data: [{ name: '深圳市', value: 92 }, { name: '广州市', value: 78 }]
      }]
    });
  });

3.2 场景二：Leaflet 标点 + 弹窗

import L from 'leaflet';
const map = L.map('map').setView([22.54, 114.06], 12);        // 纬度在前！
L.tileLayer('https://tile.openstreetmap.org/{z}/{x}/{y}.png', {
  attribution: '© OpenStreetMap'
}).addTo(map);

stations.forEach(s => {
  L.marker([s.lat, s.lng])
    .bindPopup(`<b>${s.name}</b><br>负荷：${s.load}%`)
    .addTo(map);
});

3.3 场景三：点位聚合（海量点）

// 数千 marker 直接 add 会卡——聚合插件按缩放级别合并邻近点
const cluster = L.markerClusterGroup();
stations.forEach(s => cluster.addLayer(L.marker([s.lat, s.lng])));
map.addLayer(cluster);   // 缩放时自动聚合/展开

3.4 场景四：GeoJSON 面数据渲染

fetch('/api/areas.geojson')
  .then(r => r.json())
  .then(gj => {
    L.geoJSON(gj, {
      style: f => ({ color: '#3d7a4f', fillOpacity: f.properties.risk > 0.7 ? 0.5 : 0.15 }),
      onEachFeature: (f, layer) => layer.bindPopup(f.properties.name)
    }).addTo(map);
  });

3.5 场景五：坐标纠偏（GCJ-02 转换）

// GPS 采集(WGS84) → 高德底图(GCJ-02)：引入 gcoord 等纠偏库
import gcoord from 'gcoord';
const [lng, lat] = gcoord.transform(
  [rawLng, rawLat],
  gcoord.WGS84,        // 源坐标系
  gcoord.GCJ02         // 目标坐标系
);

4进阶知识点【进阶】

首次学习可整章跳过。前置：坐标系与瓦片原理已清楚。

4.1 瓦片加载优化

瓦片请求优化四招：①maxZoom/minZoom 限制（超范围瓦片不存在，别白请求）；②keepBuffer（预加载视口外一圈，拖动不闪白）；③多子域并发（tile 子域名突破浏览器同域并发限制）；④离线瓦片（内网大屏用 mbtiles 本地化，不出外网——与 09_DevOps 内网部署场景衔接）。

4.2 海量点位分层策略

千级以内直接 marker；数千到数万用聚合（markercluster）或 canvas 渲染层（Leaflet.CanvasLayer/MapLibre circle 层）；十万级上 MapLibre + 矢量瓦片或 GL 点层——01 篇渲染后端阈值在 GIS 同样成立。

4.3 实时轨迹与动画

车辆轨迹：LineString 按时间排序 + 平滑插值动画（两点间 lerp，配合 rAF 移动 marker）；大量轨迹回放用 canvas 层统一重绘。坑：轨迹点时间戳乱序要先排序，否则线段来回折返。

4.4 逆地理编码与搜索

坐标 ↔ 地址互换依赖服务商 API（高德 Web 服务 key），注意配额与并发限制；内网环境不可用——离线方案要自建 POI 库或只做行政区级归属（point-in-polygon，turf.js 判断点在哪个区）。

4.5 内网部署与合规

电力等内网场景：底图本地化（mbtiles/pyramid 瓦片包内网分发）、数据不出域（与 09 模块内网声明一致）；对外网业务注意地图服务合规（境内_public 数据使用条款、key 保密——泄露在 referer 白名单外被盗刷）。

性质（诚实声明）：本套技术栈地图场景以 ECharts geo 为主（01 篇热力分布图已覆盖），本 demo 为 Leaflet 学习储备——目标是用 20 行代码跑通"底图+标点+弹窗+GeoJSON 面"四件事，建立 GIS 库的体感。

  1. npm i leaflet gcoord，容器设固定高度（地图库容器无高度不显示——高频坑）；

  1. 缩放地图：network 面板可见按 z/x/y 增量请求瓦片（图 1 行为验证）；

  • 选型复盘：行政区统计着色 ECharts geo 一把梭最省；需要逐点交互/底图切换才上 Leaflet；十万级点才考虑 MapLibre——不按需分层就会"为标 5 个点引入 3D 地球引擎"；

7常见坑 & Debug

五条高频坑。

7.1 坐标系错配漂移（国内第一坑）

现象：点位整体偏移数百米、设备"跑马路对面"。排查：先问底图坐标系（高德 GCJ-02/百度 BD-09/OSM WGS84）与数据坐标系是否一致。正解：gcoord 等纠偏库转换，注意非线性算法不能手写近似。

7.2 地图容器无高度不显示

现象：init 后一片空白。原因：地图容器高度为 0（flex 布局/百分比高度链断裂）。正解：给容器显式高度或 100% 链路打通（01 模块百分比高度坑同源）。

7.3 经纬度顺序写反

现象：点位飞到别的大洲。原因：GeoJSON/turf 是 [lng, lat]（经度在前），Leaflet 是 [lat, lng]（纬度在前）——两套约定并存。正解：封装统一入口，入库按 [lng,lat]、Leaflet 层再翻转。

7.4 海量 marker 直接 add 卡死

现象：数千点位后缩放/拖动卡顿。正解：聚合（markercluster）或 canvas 渲染层；十万级上 MapLibre GL 点层——渲染后端阈值与 01 篇一致。

7.5 底图请求出外网被拦

现象：内网大屏底图全灰。原因：瓦片 URL 指向外网服务商。正解：瓦片本地化（mbtiles 自建服务），选型阶段就把"内网可达"列为硬约束。

8重点讲解

Q1：国内地图为什么有三套坐标系？怎么处理？

参考答案：WGS84 是 GPS 原始与国际标准；GCJ-02 是国测局对境内数据做的非线性加密（"火星坐标"），高德/腾讯底图使用；BD-09 是百度在 GCJ-02 上的二次加密。处理原则：底图与业务数据必须同坐标系——GPS 采集的 WGS84 点直接铺高德底图会整体漂移数百米；转换用 gcoord 等库（非线性加密算法，手写"减固定偏移"精度不够）。排查口诀：点位漂移先问"底图什么系、数据什么系"，而不是查渲染代码。

Q2：瓦片地图的原理？栅格瓦片与矢量瓦片的取舍？

参考答案：瓦片金字塔——每个缩放级别 z 把全球切成 2^z×2^z 张 256px 瓦片，客户端按视口与当前 z 只请求可见瓦片（URL 模板 /{z}/{x}/{y}）；"放大地图"本质是换一套更精细的层级。栅格瓦片：预渲染图片，加载快、样式固定；矢量瓦片（MVT）：下发几何数据客户端渲染——体积小、样式运行时可换、要素可交互，但渲染算力在客户端。选型：常规底图栅格够用；海量要素/自定义样式/暗色主题切换选矢量。

Q3：地图库怎么按需求分层选型？

参考答案：四层——①行政区统计着色/简单分布：ECharts geo（与图表体系一致、visualMap 直接可用，本套技术栈主用法）；②逐点交互/弹窗/轻量底图：Leaflet（~40KB、插件生态全）；③海量点位/矢量瓦片/自定义样式：MapLibre GL；④3D 地球/地形/空间分析：Cesium；国内业务依赖 POI/路网/逆地理再叠加高德百度 JS API。内网约束：电力等内网场景底图必须本地化，在线服务商方案直接出局——可达性是比功能更硬的约束。
