Canvas 与 SVG

深入 定位：浏览器两大绘图体系——位图逐帧绘制 vs 矢量 DOM 描述

Canvas 是一块"位图画布"，靠 JS 逐帧往像素里画；SVG 是"矢量 XML"，每个图形都是一个 DOM 节点。本页讲透两者的渲染模型、高清屏适配（devicePixelRatio）、绘制状态栈，以及最关键的工程问题：什么场景选 Canvas、什么场景选 SVG。案例取自 WebRTC 播放器的 Canvas 画面绘制、低代码开发平台的 Diff 高亮版本对比——这两个项目恰好踩在两种技术的边界上。

1简介与阅读指引

1.1 定位

Canvas 是一块位图绘图画布：拿 2D/3D 上下文，用命令式 API（fillRect/drawImage/beginPath）逐帧往像素缓冲区画——画完即位图，不保留对象信息。SVG 是 XML 描述的矢量图形：circle/path 都是真实 DOM 节点，浏览器按数学公式实时绘制、放大不失真。Web 画图形三条路里，切图不可缩放、CSS 只适合 UI 元素——真正可编程绘图只有这两条：Canvas 管"高帧率/海量元素/像素级控制"，SVG 管"少量矢量/要交互/缩放不失真"。选型错了要么卡顿（SVG 画万点），要么交互难做（Canvas 命中要自己算坐标）。

1.2 选型决策：最硬的分界线是元素数量

  • 元素数量：几十个 → SVG（省事能交互）；上万个 → Canvas（DOM 撑不住）；
  • 帧率：视频流/实时刷新 → Canvas；静态或低频 → SVG；
  • 交互与可访问性：点击命中/CSS 改样式/读屏 → SVG（它就是 DOM）；
  • 工程现实：图表类（ECharts）默认 Canvas、关系图（G6 默认 Canvas 也支持 SVG）——库已替你选好，本篇是让你理解为什么。

1.4 学习目标与阅读指引

  1. 讲清 立即模式 vs 保留模式（位图 vs 矢量 DOM）的本质差异；
  2. 落地 DPR 高清适配（Canvas 发虚的根解）；
  3. 掌握 save/restore 状态栈与逐帧绘制流程；
  4. 理解 viewBox 等比映射（本系列示意图的原理）；
  5. 避开六条高频坑（发虚/状态污染/万点卡顿/命中自算/变形/beginPath）。

前置知识：04 篇渲染流水线（合成线程与图层）。难度：★★★☆☆。务必动手：第 6 章 Demo。本篇不涉及：ECharts/G6/Three.js 用法（03 模块专讲）。

2核心模型

六个核心模型：立即模式（Canvas 的本质）→ 坐标系与变换→ DPR→ 状态栈→ 保留模式与 viewBox（SVG 的本质）→ 事件与上层库。

2.1 Canvas 立即模式：画完即忘

调用一次 fillRect，像素立刻画上去，之后不再记得"那个矩形"。动起来的代价：每帧清空整个画布、重画全部内容。要点：Canvas 性能取决于"每帧画了多少东西"——想流畅就要控制每帧绘制指令数（对比 SVG 保留模式：操作对象语义，浏览器负责栅格化）。

2.2 坐标系与变换：改的是坐标系不是图形

默认坐标原点在左上角、x 向右 y 向下。translate/rotate/scale 改的是后续所有绘制依托的坐标系——画旋转物体：先 translate 到物体中心、再 rotate、画完逆变换回去。变换叠加在当前矩阵上，配合 save/restore 隔离每段绘制。

2.3 DPR：Canvas 发虚的唯一根因

物理像素与 CSS 像素的比值是 window.devicePixelRatio（Retina 屏 2 或 3）。发虚根因：绘制缓冲按 CSS 尺寸建，高分屏上被放大显示而模糊。根解法：canvas 实际宽高 = css尺寸 × dpr，再 ctx.scale(dpr, dpr)——绘制仍按 CSS 坐标写，输出却是物理像素。

2.4 状态栈：全局状态的隔离

填充色/线宽/变换矩阵都是全局状态：save() 压栈、restore() 弹出恢复。多层变换、不同样式绘制，每段前后成对 save/restore。坑："上一段设的红色污染后面所有图形"是 Canvas 颜色错乱头号原因——忘了 save/restore 而已。

2.5 SVG 保留模式与 viewBox

节点即 DOM：每个 circle/path 参与事件冒泡、被 CSS 命中、可 getBBox 量尺寸；天然支持无障碍（title）与文本选择；代价是每节点 DOM 开销——海量节点必卡。viewBox：CSS 尺寸是视口，viewBox 是内部坐标系，浏览器等比映射（preserveAspectRatio="xMidYMid meet" 居中等比）——本系列所有示意图在不同宽度下等比不变形的原理。

2.6 SVG 事件与上层库

SVG 节点直接 addEventListener，命中测试浏览器按矢量形状自动完成。命中细节：默认 pointer-events:visiblePainted 下 fill="none" 的区域不算命中；fill="transparent"（非 none）仍命中——连线交互的常见困惑点。上层库（ECharts/G6/Three.js）在 Canvas/WebGL 上封装了"场景图"——理解 Canvas/SVG 才懂库为何"万点用 Canvas、少量节点可切 SVG 渲染"。

3核心用法（按场景）

3.1 场景一：Canvas 基础绘制 + DPR 适配

const canvas = document.querySelector('#c');
const dpr = window.devicePixelRatio || 1;
const cssW = 800, cssH = 400;
canvas.width = cssW * dpr;          // 缓冲按物理像素建
canvas.height = cssH * dpr;
canvas.style.width = cssW + 'px';   // 显示按 CSS 尺寸
canvas.style.height = cssH + 'px';
const ctx = canvas.getContext('2d');
ctx.scale(dpr, dpr);                // 之后按 CSS 坐标画即可

ctx.clearRect(0, 0, cssW, cssH);    // 清屏
ctx.fillStyle = '#2d6a3f';
ctx.fillRect(10, 10, 120, 60);     // 画块
ctx.beginPath();                    // 路径：必须 beginPath 开新路径
ctx.arc(400, 200, 50, 0, Math.PI * 2);
ctx.fill();

3.2 场景二：Canvas 绘制视频帧（cover 缩放）

// 把 video 当前帧画到 canvas（WebRTC 播放器的做法）
function drawFrame(video, ctx, canvas) {
  const vw = video.videoWidth, vh = video.videoHeight;
  const scale = Math.max(canvas.width / vw, canvas.height / vh);
  const dw = vw * scale, dh = vh * scale;
  ctx.drawImage(video, (canvas.width - dw) / 2, (canvas.height - dh) / 2, dw, dh);
}

3.3 场景三：SVG 基础——元素即 DOM

<svg viewBox="0 0 200 100" width="100%">
  <circle cx="50" cy="50" r="30" fill="#2d6a3f"/>
  <rect x="100" y="20" width="80" height="60" rx="6" fill="#4f8a63"/>
  <text x="50" y="95" text-anchor="middle" font-size="12">标签</text>
</svg>

3.4 场景四：同一红点两种实现——交互成本对比

// SVG：声明一个可点选的圆点（它就是 DOM，事件自动绑）
document.querySelector('#p').addEventListener('click', onPointClick);

// Canvas：同样的红点要自己算命中（鼠标坐标落在半径内才算点中）
canvas.addEventListener('click', (e) => {
  const rect = canvas.getBoundingClientRect();
  const x = (e.clientX - rect.left), y = (e.clientY - rect.top);
  if (Math.hypot(x - 100, y - 100) <= 8) onPointClick();   // 手写命中测试
});
// 结论：少量可交互图形 SVG 省事；海量图形 Canvas 要自维护"元素列表"做命中。

4进阶知识点【进阶】

首次学习可整章跳过。前置：逐帧流程与 DPR 适配已跑通。

4.1 离屏缓存与分层渲染

静态背景（网格/底图）预渲染到一个 offscreen canvas，每帧只 drawImage 贴图 + 重绘动态层——把"每帧指令数"压到最低（第 6 章 diff 高亮的分层方案）。OffscreenCanvas 进一步把离屏渲染挪到 Worker 线程，主线程零占用。

4.2 双缓冲与脏区域

高频可视化两个降耗手段：双缓冲——在离屏画完再一次性上屏，避免闪烁；脏区域——只 clearRect + 重绘变化的矩形区域，不全屏重画。ECharts 等库内部都做了这两件事（"库替你选好"的深层原因）。

4.3 isPointInPath 与命中加速

Canvas 命中测试除手写几何碰撞（rect 包含/圆距离），复杂 path 可用 ctx.isPointInPath(path, x, y) 让引擎代算。海量元素时先包围盒粗筛再做精确碰撞——空间换时间的经典分层。

4.4 SVG 交互增强

  • pointer-events 精细控制：stroke 只命中描边（连线场景）、bounding-box 按包围盒命中；
  • CSS 能力：transition/animation 直接作用于 SVG 属性，hover 高亮零 JS；
  • 无障碍：给关键图形配 title/desc，读屏器可读——Canvas 做不到（位图无语义）。

4.5 WebGL 与 Canvas 2D 的边界

2D 上下文 CPU 绘制，万点已是舒适区上限；WebGL 走 GPU，十万级点/粒子才需要（Three.js 底座）。判断依据与 Canvas/SVG 同构：数量级再上一层、且不依赖 DOM 语义。

6最小可运行 Demo

性质：两处真实实战——WebRTC 播放器视频帧叠加、低代码平台版本 diff 高亮。

6.1 场景一：WebRTC 视频上 Canvas（rAF 渲染循环）

function startRenderLoop(video, canvas, ctx) {
  function tick() {
    if (video.readyState >= 2) {          // 已有可画的帧
      ctx.drawImage(video, 0, 0, canvas.width, canvas.height);
      drawWatermark(ctx);                  // 同帧叠加层
    }
    requestAnimationFrame(tick);           // 与显示节奏对齐，多路同屏也不抢帧
  }
  requestAnimationFrame(tick);
}

设计：流接隐藏 video 解码，rAF 把当前帧 drawImage 到可见 Canvas 叠水印；Canvas 尺寸 = 容器 CSS × DPR（高清不糊）。

6.2 场景二：版本 diff 高亮（分层 + offscreen）

// diff：按 id 对齐两版节点
function diffNodes(oldNodes, newNodes) {
  const oldMap = new Map(oldNodes.map(n => [n.id, n]));
  const result = { added: [], removed: [], changed: [] };
  for (const n of newNodes) {
    const o = oldMap.get(n.id);
    if (!o) result.added.push(n);
    else if (JSON.stringify(o.data) !== JSON.stringify(n.data)) result.changed.push({ old: o, now: n });
    oldMap.delete(n.id);
  }
  result.removed.push(...oldMap.values());
  return result;
}
// 高亮层：新增=绿，删除=红，修改=黄
function paintDiffOverlay(ctx, diff) {
  diff.added.forEach(n => paintBox(ctx, n, '#047857'));
  diff.removed.forEach(n => paintBox(ctx, n, '#b91c1c'));
  diff.changed.forEach(({ now }) => paintBox(ctx, now, '#d97706'));
}

6.3 踩坑记录（真实问题与解法）

  • 不处理 DPR 发虚：4K 大屏视频发虚——补 canvas.width = cssW × dpr 后清晰；
  • 未按 cover 缩放：drawImage 用原始尺寸拉伸变形——按宽高比算 cover；
  • readyState 判断缺失：视频未到就 drawImage 抛错黑屏——加 readyState>=2；
  • JSON 比较假阳性：stringify 因字段顺序不稳误报"修改"——逐字段/排序后比；
  • 高亮层没清：切版本旧高亮残留——每次重绘前 clearRect 高亮层；
  • 上千节点掉帧：静态底图缓存 offscreen、差异层单独叠加——帧率恢复。

6.4 复盘与可复用经验

  1. DPR 是 Canvas 清晰的前提：任何 Canvas 上屏都按 DPR 放大画布再 CSS 缩回；
  2. 分层 + offscreen 缓存：高频可视化把静态层缓存、动态层叠加，是性能关键；
  3. 对象比较要稳定：别用 JSON.stringify 直接判等。

7常见坑 & Debug

六条高频坑。

7.1 Canvas 高分屏发虚

根因：缓冲按 CSS 尺寸建、被 DPR>1 的屏拉伸。正解：缓冲按 css尺寸×dpr 建、再 ctx.scale(dpr,dpr)（2.3）。

7.2 状态污染：颜色/变换错乱

现象：这段设了红色，后面全变红。根因：样式/变换是全局状态。正解：每段绘制前后成对 save/restore。

7.3 SVG 画万点卡顿

现象：几千个 SVG 节点页面卡、滚动掉帧。根因：每节点都是 DOM。正解：海量数据切 Canvas/WebGL；SVG 只留少量节点场景。

7.4 Canvas 点击命中没反应

根因：位图不做命中测试。正解：维护元素几何列表，坐标换算后碰撞检测（rect 包含/圆距离/path 用 isPointInPath，4.3）。

7.5 viewBox 与 CSS 尺寸不一致导致变形

现象：SVG 被拉伸。正解：容器 width:100% + height:auto，让浏览器按 viewBox 比例等比缩放。

7.6 beginPath 漏调导致连线

现象：每次画圆都和上个形状连上线。根因：路径是累加的。正解：每个独立形状前 beginPath()。

8重点讲解

Q1：Canvas 和 SVG 的本质区别？怎么选？

参考答案：Canvas 立即模式——命令式 API 逐帧画进像素缓冲，画完即位图不保留对象；性能取决于每帧指令数，海量元素流畅但命中要自己算。SVG 保留模式——矢量图形是真实 DOM，事件/CSS/无障碍天然可用、放大不失真，但节点多必卡。选型最硬的分界线是元素数量：几十个选 SVG，上万选 Canvas；再叠加帧率（视频/实时→Canvas）与交互需求（点击/CSS→SVG）。工程上 ECharts/G6 默认 Canvas 就是这条逻辑。

Q2：Canvas 在 Retina 屏发虚的原因与解法？

参考答案：根因——绘制缓冲按 CSS 尺寸建立，DPR>1 的屏把缓冲拉伸到物理像素显示，一 CSS 像素对应多物理像素就模糊。解法三件套：canvas.width = cssW × dpr（缓冲按物理像素建）、canvas.style.width = cssW + 'px'（显示按 CSS 尺寸）、ctx.scale(dpr, dpr)（绘制代码仍按 CSS 坐标写）。记忆点：缓冲放大、显示缩回、坐标不变。

Q3：Canvas 上怎么实现图形点击？SVG 呢？

参考答案：SVG——图形就是 DOM，直接 addEventListener，浏览器按矢量形状做命中（注意 fill="none" 不命中、transparent 仍命中，可用 pointer-events 调规则）。Canvas——位图无对象信息，要维护"元素几何列表"：click 事件坐标换算到画布坐标系（减去 getBoundingClientRect），再碰撞检测——rect 包含判断、圆用距离（Math.hypot）、复杂 path 用 isPointInPath；海量元素先包围盒粗筛再精确判定。这正是"少量交互选 SVG、海量渲染选 Canvas"在交互维度的体现。
