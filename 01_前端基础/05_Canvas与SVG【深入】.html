Canvas 与 SVG

深入 定位：浏览器两大绘图体系——位图逐帧绘制 vs 矢量 DOM 描述

Canvas 是一块"位图画布"，靠 JS 逐帧往像素里画；SVG 是"矢量 XML"，每个图形都是一个 DOM 节点。本页讲透两者的渲染模型、高清屏适配（devicePixelRatio）、绘制状态栈，以及最关键的工程问题：什么场景选 Canvas、什么场景选 SVG。案例取自 WebRTC 播放器的 Canvas 画面绘制、低代码开发平台的 Diff 高亮版本对比——这两个项目恰好踩在两种技术的边界上。

1技术点概览

是什么

Canvas 是 HTML5 提供的一块位图绘图画布：你拿到 <canvas> 元素的 2D/3D 上下文，用命令式 API（fillRect/drawImage/beginPath）逐帧往像素缓冲区画。画完就是一张位图，不再保留"这是个圆"的对象信息。SVG（Scalable Vector Graphics，可缩放矢量图）是用 XML 描述的矢量图形：<circle>、<path> 都是真实 DOM 节点，浏览器按数学公式实时绘制，放大不失真。

解决什么问题

Web 要画图形，有三条路：切图（不可缩放、不动态）、CSS（只适合 UI 元素）、Canvas/SVG（真正的可编程绘图）。Canvas 解决"高帧率、海量元素、像素级控制"（视频帧、游戏、万点 3D、实时热力图）；SVG 解决"少量矢量图形、要交互、要缩放不失真"（图标、流程图、可点击的图形元素）。选型错了，要么卡顿（SVG 画万点），要么难做交互（Canvas 上点击命中要自己算坐标）。

横向对比：选型决策

图 2 Canvas vs SVG 选型决策（示意）

  • 元素数量：几十个图形 → SVG（省事、能交互）；上万个点/帧 → Canvas（DOM 节点撑不住）。这是最硬的分界线。
  • 是否需要逐帧高帧率：视频流、动画、实时刷新 → Canvas（重绘成本可控）；静态或低频图形 → SVG。
  • 交互与可访问性：要点击命中、要 CSS 改样式、要屏幕阅读器读图形 → SVG（它就是 DOM）；Canvas 的命中要手写坐标换算。
  • 工程现实：图表类（ECharts/Chart）默认 Canvas，关系图（G6 默认 Canvas，也支持 SVG 渲染）——库已经替你选好，本页是让你理解为什么。

2核心概念

2.1 Canvas 的位图绘制模型（Immediate Mode）

一句话定位：Canvas 是立即模式——画完即忘，想动起来就得每帧清空重画全部内容。

  • 立即模式：调用一次 fillRect，像素立刻画上去，之后不再记得"那个矩形"。
  • 动起来的代价：每一帧都要清空整个画布、重新画全部内容——与 SVG 的保留模式根本不同。

要点Canvas 性能取决于"每帧画了多少东西"，想流畅就要控制每帧的绘制指令数。

2.2 坐标系与变换（Coordinate System & Transform）

一句话定位：translate/rotate/scale 改的不是某个图形，而是后续所有绘制所依托的坐标系。

  • 默认坐标：原点在左上角，x 向右、y 向下。
  • 变换坐标系：画旋转物体，先 translate(x,y) 把原点移到物体中心，再 rotate(角) 画，最后逆变换回去。
  • 叠加与隔离：变换叠加在当前矩阵上，配合 save/restore 隔离每段绘制。

2.3 devicePixelRatio 与高清屏（DPR）

一句话定位：Canvas 发虚，几乎都是绘制缓冲没按 DPR 放大。

  • DPR 是什么：物理像素与 CSS 像素的比值即 window.devicePixelRatio，Retina 屏为 2 或 3。
  • 发虚根因：绘制缓冲按 CSS 尺寸建，在高分屏上被放大显示而模糊。

根解法canvas 实际宽高属性设为 css尺寸 × dpr，再 ctx.scale(dpr, dpr)，绘制仍按 CSS 坐标写。

2.4 绘制状态栈（save / restore）

一句话定位：填充色、线宽、变换矩阵都是全局状态，不 save/restore 就会跨图形污染。

  • 状态栈：2D 上下文维护一个栈；save() 压当前状态，restore() 弹出恢复。
  • 用法：多层变换、不同样式的绘制，每段前后成对 save/restore。

坑"上一段设的红色"污染后面所有图形，是 Canvas 颜色错乱的头号原因——忘了 save/restore 而已。

2.5 SVG 的矢量 DOM 模型（Retained Mode）

一句话定位：SVG 图形是真实 DOM 节点，你操作对象语义，浏览器负责栅格化。

  • 节点即 DOM：每个 <circle>/<path> 参与事件冒泡、能被 CSS 选择器命中、能 getBBox() 量尺寸。
  • 天然优势：支持无障碍（带 <title>）和文本选择。
  • 代价：每个节点都有 DOM 开销——海量节点时会卡。

2.6 viewport 与 viewBox（视口与视图框）

一句话定位：CSS 尺寸是视口，viewBox 是内部坐标系，浏览器负责把后者等比映射进前者。

  • viewBox 的含义：viewBox="0 0 800 600" = 内容画在 800×600 的坐标系里，浏览器自动缩放进视口。
  • 对齐控制：配合 preserveAspectRatio 控制缩放对齐方式。

要点这正是本系列所有示意图在不同宽度下等比不变形的原理。

2.7 SVG 事件与交互

一句话定位：SVG 节点和 HTML 节点一样绑事件，命中测试由浏览器按矢量形状自动完成。

  • 绑定：节点可直接 addEventListener('click')，无需自己算坐标。
  • 命中细节：默认 pointer-events:visiblePainted 下，fill="none"（或 stroke="none"）的区域不算命中；注意 fill="transparent"（非 none）仍会命中。可设 pointer-events:stroke 改命中规则。

这就是流程图、节点连线用 SVG 写交互省事的原因。

2.8 与上层库的关系

一句话定位：ECharts/G6/Three.js 都在 Canvas/WebGL 上封装了一层"场景图"，你声明数据，库决定每帧画什么。

  • 场景图封装：库在内部做脏重绘、决定渲染策略。
  • 选型呼应：理解 Canvas/SVG，才懂这些库为何"万点用 Canvas、少量节点可切 SVG 渲染模式"。

3工作原理与流程

3.1 Canvas 每帧在做什么

图 2 Canvas 逐帧绘制与 DPR 适配（示意）

  1. 清空：立即模式下上一帧内容还在，必须先 clearRect 清掉。
  2. save/变换：把坐标系移到该画的位置、设好颜色线宽。
  3. 绘制：逐个画元素；性能敏感场景用离屏 canvas 缓存静态背景，每帧只 blit（贴图）动态层。需要进一步卸载主线程时可用 OffscreenCanvas，把离屏渲染挪到 Worker 里跑。
  4. restore：还原状态，避免污染下一帧。

3.2 SVG 的坐标映射

SVG 视口（CSS 尺寸）与 viewBox（内部坐标系）之间是一层仿射映射：preserveAspectRatio="xMidYMid meet" 表示"等比缩放并居中"。本系列示意图用 viewBox="0 0 800 H"，外层 CSS width:100%，于是容器多宽、SVG 内部 800 坐标就等比缩放到多宽——文字和图形永远成比例、不变形。这就是"矢量可缩放"在工程上的落地方式。

4核心语法与 API 要点

4.1 Canvas 基础绘制与 DPR 适配

const canvas = document.querySelector('#c');
const dpr = window.devicePixelRatio || 1;
const cssW = 800, cssH = 400;
canvas.width = cssW * dpr;          // 缓冲按物理像素建
canvas.height = cssH * dpr;
canvas.style.width = cssW + 'px';   // 显示按 CSS 尺寸
canvas.style.height = cssH + 'px';
const ctx = canvas.getContext('2d');
ctx.scale(dpr, dpr);                // 之后按 CSS 坐标画即可

ctx.clearRect(0, 0, cssW, cssH);    // 清屏
ctx.fillStyle = '#2d6a3f';
ctx.fillRect(10, 10, 120, 60);     // 画块
ctx.beginPath();                    // 路径：必须 beginPath 开新路径
ctx.arc(400, 200, 50, 0, Math.PI * 2);
ctx.fill();

4.2 用 Canvas 绘制视频帧

// 把 video 当前帧画到 canvas（WebRTC 播放器的做法）
function drawFrame(video, ctx, canvas) {
  // 保持宽比：视频帧按 cover 方式裁进画布
  const vw = video.videoWidth, vh = video.videoHeight;
  const scale = Math.max(canvas.width / vw, canvas.height / vh);
  const dw = vw * scale, dh = vh * scale;
  ctx.drawImage(video, (canvas.width - dw) / 2, (canvas.height - dh) / 2, dw, dh);
}

4.3 SVG 基础：元素即 DOM

<svg viewBox="0 0 200 100" width="100%">
  <circle cx="50" cy="50" r="30" fill="#2d6a3f"/>
  <rect x="100" y="20" width="80" height="60" rx="6" fill="#4f8a63"/>
  <text x="50" y="95" text-anchor="middle" font-size="12">标签</text>
</svg>

4.4 同一图形两种实现对比

// SVG：声明一个可点选的圆点（它就是 DOM，事件自动绑）
// <circle id="p" cx="100" cy="100" r="8" fill="red"/>
document.querySelector('#p').addEventListener('click', onPointClick);

// Canvas：同样的红点要自己算命中（鼠标坐标落在半径内才算点中）
canvas.addEventListener('click', (e) => {
  const rect = canvas.getBoundingClientRect();
  const x = (e.clientX - rect.left), y = (e.clientY - rect.top);
  if (Math.hypot(x - 100, y - 100) <= 8) onPointClick();   // 手写命中测试
});
// 结论：少量可交互图形 SVG 省事；海量图形 Canvas 要自己维护一个"元素列表"做命中。

5实战项目经验（实战落地）

5.1 项目背景

一句话定位：两处 Canvas 实战——WebRTC 播放器把视频帧画到 Canvas 做叠加，低代码平台用 diff + Canvas 高亮版本对比。

  • 场景一：WebRTC 无插件播放器（Vue2+Janus+Canvas，2020-2022）去 ActiveX 化，多路同屏需在视频上叠水印/时间戳。
  • 场景二：低代码开发平台（Vue3+G6+ElementUI，2022-）流程/配置的版本对比，并排高亮新增/删除/修改节点。

5.2 我的角色与职责

  • 角色：前端开发，负责 Canvas 视频渲染管线与版本对比差异高亮。
  • 团队与分工：前端若干（估算）；我负责画布渲染层，与后端对版本快照数据结构。

5.3 技术栈

  • 播放器：Vue2 + Janus + WebRTC + Canvas + rAF。
  • 低代码平台：Vue3 + G6（图可视化）+ ElementUI + diff 算法。

5.4 落地设计

  • 视频帧上屏：流接隐藏 <video> 解码，rAF 把当前帧 drawImage 到可见 Canvas 并叠水印。
  • DPR 适配：Canvas 尺寸 = 容器 CSS 尺寸 × DPR，高清屏不糊。
  • 差异分层：静态底图缓存到 offscreen canvas，差异高亮作为 overlay 单独重绘。

5.5 关键实现要点

function startRenderLoop(video, canvas, ctx) {
  function tick() {
    if (video.readyState >= 2) {          // 已有可画的帧
      ctx.drawImage(video, 0, 0, canvas.width, canvas.height);
      drawWatermark(ctx);                  // 同帧叠加层
    }
    requestAnimationFrame(tick);           // 与显示节奏对齐，多路同屏也不抢帧
  }
  requestAnimationFrame(tick);
}
// diff：按 id 对齐两版节点
function diffNodes(oldNodes, newNodes) {
  const oldMap = new Map(oldNodes.map(n => [n.id, n]));
  const result = { added: [], removed: [], changed: [] };
  for (const n of newNodes) {
    const o = oldMap.get(n.id);
    if (!o) result.added.push(n);
    else if (JSON.stringify(o.data) !== JSON.stringify(n.data)) result.changed.push({ old: o, now: n });
    oldMap.delete(n.id);
  }
  result.removed.push(...oldMap.values());
  return result;
}
// 高亮层绘制：新增=绿，删除=红，修改=黄
function paintDiffOverlay(ctx, diff) {
  diff.added.forEach(n => paintBox(ctx, n, '#047857'));
  diff.removed.forEach(n => paintBox(ctx, n, '#b91c1c'));
  diff.changed.forEach(({ now }) => paintBox(ctx, now, '#d97706'));
}

5.6 真实问题与解法

  • 不处理 DPR 发虚：4K 大屏视频发虚；补 canvas.width = cssW × dpr 后清晰。
  • 未按 cover 缩放：drawImage 用原始尺寸致拉伸变形，按宽高比算 cover 后正常。
  • readyState 判断缺失：视频未到就 drawImage 抛错黑屏，加 readyState>=2 判断后稳定。
  • JSON 比较假阳性：JSON.stringify 比 data 因字段顺序不稳误报"修改"，改逐字段/排序后比。
  • 高亮层没清：切版本旧高亮残留，每次重绘前 clearRect 高亮层。
  • 上千节点掉帧：静态底图缓存到 offscreen canvas、差异层单独叠加，帧率恢复。

5.7 量化成果

  • 多路同屏视频 CPU 占用可控，遮罩/水印叠加比原生 video 方案更灵活（估算）。
  • 版本对比一眼可见改动范围，上千节点重绘经 offscreen 缓存后帧率恢复。

5.8 协作与排期过程

  • 契约先行：与后端定版本快照节点数据结构（id + data），diff 才能按 id 对齐。
  • 联调协商：diff 假阳性问题，与产品确认"哪些字段算真改动"，收敛比较口径。
  • 排期：先做播放器 Canvas 上屏，再做低代码平台版本对比。

5.9 复盘与可复用经验

  • DPR 是 Canvas 清晰的前提：任何 Canvas 上屏都要按 DPR 放大画布再 CSS 缩回。
  • 分层 + offscreen 缓存：高频可视化把静态层缓存、动态层叠加，是性能关键。
  • 对象比较要稳定：别用 JSON.stringify 直接判等，字段顺序会制造假阳性。

5.10 面试讲法

实战要点用"隐藏 video 解码 + rAF drawImage + DPR 适配"做 WebRTC 视频上 Canvas，并用 offscreen 分层缓存把上千节点的版本 diff 高亮做到不卡。

6易错点与面试重点

6.1 Canvas 在高分屏发虚

一句话定位：缓冲按 CSS 尺寸建、被 DPR>1 的屏拉伸，所以发虚。

  • 现象：画出来的图形边缘模糊。
  • 正解：缓冲按 css尺寸×dpr 建、再 ctx.scale(dpr,dpr)。

6.2 状态污染：颜色/变换错乱

一句话定位：2D 上下文样式/变换是全局状态，不 save/restore 就泄漏。

  • 现象：这一段设了红色，后面所有图形都变红。
  • 正解：每段独立绘制前后成对 save/restore。

6.3 SVG 画万点卡顿

一句话定位：每个 SVG 节点都是 DOM，万点时浏览器布局/合成扛不住。

  • 现象：生成几千个 SVG 节点后页面卡顿、滚动掉帧。
  • 正解：海量数据切 Canvas/WebGL；SVG 只保留给少量节点场景。

6.4 Canvas 点击命中要自己算

一句话定位：位图不做命中测试，点击检测得自己写碰撞。

  • 现象：Canvas 上点击元素没反应。
  • 正解：维护元素几何列表，鼠标坐标换算到画布坐标后做碰撞检测（rect 包含、圆距离、path 用 isPointInPath）。

6.5 viewBox 与 CSS 尺寸不一致导致变形

一句话定位：未设 preserveAspectRatio 或 CSS 比例与 viewBox 不一致就变形。

  • 现象：SVG 被拉伸变形。
  • 正解：容器用 width:100%+height:auto，让浏览器按 viewBox 比例等比缩放。

6.6 beginPath 漏调导致连线

一句话定位：路径是累加的，不开新路径之前的子路径会一起重绘。

  • 现象：每次画圆都和上一个形状连上线。
  • 正解：每个独立形状前 beginPath()。
