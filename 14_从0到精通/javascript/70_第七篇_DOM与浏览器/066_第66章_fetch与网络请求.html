66.1 fetch 基本用法：一句 GET 拿数据

// fetch(url) 返回 Promise，resolve 的是 Response 对象（不是数据本身！）
const res = await fetch("https://jsonplaceholder.typicode.com/users/1")
console.log(res.ok)        // true —— 状态码 2xx
console.log(res.status)    // 200

const user = await res.json()   // 第二步：把响应体解析成 JS 对象
console.log(user.name)     // 'Leanne Graham'

fetch 一定要"两步走"：第一步拿到 Response（信封），第二步用 .json() 拆信拿内容。新手最常见的误区就是以为 fetch 直接返回数据，然后对着 Response 对象找字段找不到。

66.2 Response 方法族：json / text / blob

方法把响应体解析成适用场景
res.json()JS 对象/数组（走 JSON.parse）接口返回 JSON（绝大多数 API）
res.text()纯字符串HTML 片段、CSV、日志
res.blob()二进制 Blob图片、文件下载
 
// 三个方法都返回 Promise（解析体是异步的，响应没下完就要等）
// 注意：响应体只能读一次，二次读取会 TypeError
const res = await fetch("https://example.com/data")
const first = await res.text()
// const again = await res.json()   // 报错！体已被消费

// 拿一张图片并显示：
const blobRes = await fetch("https://example.com/cat.png")
const blob = await blobRes.blob()
img.src = URL.createObjectURL(blob)
响应体是一次性的（流）：json / text / blob 选一个调用，读完即没。不确定内容类型时，先 res.headers.get("content-type") 看一眼再选方法。

66.3 经典坑：404/500 不 reject

这是 fetch 全网最著名的坑：fetch 只在"网络层失败"（断网、DNS 解析失败）时 reject；服务器回了 404、500 也是"成功收到响应"，Promise 照样 resolve——错误被静默吞掉，后续 .json() 解析出错更让你一头雾水。

// 反例：404 了代码却走进 try 成功分支
try {
  const res = await fetch("https://example.com/api/999")  // 服务器返回 404
  const data = await res.json()      // JSON 解析失败才抛错，报错信息误导人
} catch (e) {
  console.log("请求失败")             // 归因错误！其实是 404
}

// 正解：每次 fetch 后手动判 res.ok
async function getJSON(url) {
  const res = await fetch(url)
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}: ${res.statusText}`)   // 转成真正的异常
  }
  return res.json()
}

记住因果：fetch 的 reject = "没收到响应"；res.ok 为 false = "收到了，但服务器说不行"。把"判 ok + 抛错"封装进 getJSON，一劳永逸——上面的封装直接抄走用。

66.4 POST + JSON + headers 全套

// 发送 JSON 的标准四件套：method / headers / body
const newUser = { name: "张三", job: "front-end" }

const res = await fetch("https://jsonplaceholder.typicode.com/users", {
  method: "POST",                                   // 默认 GET，必须声明
  headers: {
    "Content-Type": "application/json",             // 告诉服务器：我发的是 JSON
  },
  body: JSON.stringify(newUser),                    // 25 章兑现：对象转字符串
})

if (res.ok) {
  const created = await res.json()
  console.log(created.id)   // 11 —— 服务器分配的新 id
}

// 63 章 FormData 版 POST：不用写 Content-Type，浏览器自动配
const fd = new FormData(form)
await fetch("/upload", { method: "POST", body: fd })

JSON POST 三连必须成套出现：method: "POST" + Content-Type 头 + JSON.stringify(body)——漏掉 stringify 会把对象序列化成 [object Object]，漏掉头会让服务器拿不到可解析的 JSON。63 章的 FormData 则反过来：直接当 body，头都不用写。

66.5 AbortController：取消请求

// 56 章伏笔兑现：AbortController 是取消 fetch 的官方工具
const controller = new AbortController()

fetch("https://example.com/big-data", { signal: controller.signal })
  .then(res => res.json())
  .catch(err => {
    if (err.name === "AbortError") {
      console.log("请求被取消，不算错误")     // 主动取消走 catch，但可识别
    } else {
      console.error("真错误", err)
    }
  })

controller.abort()        // 随时调用 → fetch 立刻以 AbortError 拒绝

// 杀手级应用：搜索框输入防抖 + 取消旧请求
let controller
input.addEventListener("input", async e => {
  controller?.abort()                       // 上一单还没回来？退单！
  controller = new AbortController()
  const res = await fetch(`/api/search?q=${e.target.value}`,
                          { signal: controller.signal })
  show(await res.json())                    // 永远只显示最新一单的结果
})

没有取消机制的搜索联想会"后发先至"：慢的旧响应盖掉快的新响应。AbortController + 每次输入 abort 上一单，是多请求竞态的标准解法——这就是 56 章"可取消异步"在真实世界的用法。

66.6 错误三分类与统一兜底

类别怎么发生怎么识别 / 处理
网络层断网、DNS 失败、CORS 拦截fetch reject（TypeError）；提示"请检查网络"
HTTP 层服务器回 4xx / 5xxres.ok 为 false；读 res.status 区分（401 登录态失效 / 404 无资源 / 500 服务器崩）
解析层res.json() 解析失败（返回了 HTML 错误页等）json() reject；先看 content-type 再解
（附加）取消abort() 主动取消err.name === "AbortError"，静默处理
 
// 终极封装：三分类一网打尽
async function request(url, options = {}) {
  let res
  try {
    res = await fetch(url, options)
  } catch (err) {
    if (err.name === "AbortError") throw err          // 取消：原样上抛
    throw new Error("网络错误，请检查连接")            // 网络层
  }
  if (!res.ok) {
    throw new Error(`服务器错误 ${res.status}`)        // HTTP 层
  }
  try {
    return await res.json()                           // 解析层
  } catch {
    throw new Error("响应不是合法 JSON")
  }
}

调用方只需 catch 一种错误：request() 把三类网络问题翻译成带语义的 Error——这是把 55 章"错误传播"用到实战的完整范本，也是后面项目课所有接口层的雏形。
