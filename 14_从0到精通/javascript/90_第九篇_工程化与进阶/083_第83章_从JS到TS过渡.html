83.1 JS 的痛：错误总在运行时爆发

动态类型让 JS 上手飞快，但代价是类型错误全部推迟到运行时——炸在用户面前，而不是炸在你的编辑器里。

// 痛点一：实参错型，运行才炸
function applyDiscount(price, rate) {
  return price * (1 - rate)
}
applyDiscount(100, 0.2)     // 80      —— 正常
applyDiscount(100, "0.2")   // 80      —— 貌似正常？100*(1-"0.2") 强转成功
applyDiscount(100, null)    // 100     —— 静默给出错误结果，更危险
applyDiscount("一百", 0.2)  // NaN     —— 直到用户下单才暴露

// 痛点二：重构靠全局搜索
// 把 config.timeout 改名 config.timeoutMs：
//   搜索 "timeout" 搜出 40 处（含注释、字符串、别的对象的 timeout）
//   漏改的那一处，要等用户点到那个页面才报 undefined

// 痛点三：补全靠猜
// getuser() 返回什么结构？点不出属性，只能翻源码或 console.log 撞
  • 这三痛同根：关于"数据长什么样"的知识只存在于作者脑子里，语言层面无处记录；
  • 测试（82 章）能兜一部分，但测试只盖"被测路径"——没测到的组合依旧裸奔；
  • 项目越大、协作人越多、存活越久，这些痛按平方级放大——所以 TS 出现在"工程化"这一篇：它不是语法糖，是团队协作的基础设施。

JS 的问题不是"写得出来"，而是"错的写法也要等运行才知道"——把发现时机从运行时提到编译期，就是 TS 的全部动机。

83.2 TS = JS + 静态类型

把上一节的例子加上类型注解，同样的错误在写代码的那一刻就被划了红线：

// TS 版本：冒号后面是类型注解
function applyDiscount(price: number, rate: number): number {
  return price * (1 - rate)
}

applyDiscount(100, 0.2)     // ✓
applyDiscount(100, "0.2")   // ✗ 编辑器立刻标红：
// Argument of type 'string' is not assignable to parameter of type 'number'
applyDiscount("一百", 0.2)  // ✗ 同上——还没运行，错误已被拦截
  • TS 是 JS 的超集：所有合法 JS 都是合法 TS（先把 .js 改名 .ts 也能过），你已会的全部照用；
  • 编译后类型消失：tsc（TS 编译器）输出的还是纯 JS，运行时没有类型检查、没有类型开销——它只存在于开发阶段；
  • 两大产出：①编译期报错（本节）；②精确的编辑器补全与跳转（getuser 的返回结构一点就出——83.1 的痛点三自动消失）。

TS 不改变你的代码"怎么跑"，只改变你"什么时候知道写错了"——从上线后的报错单，提前到敲键盘的下一秒。

83.3 注解速览：基本类型 / interface / 泛型

过渡期只需要认识三样东西，就能读懂 90% 的 TS 代码：

// ① 基本类型注解
let title: string = "hello"
let count: number = 0
let ok: boolean = true
let ids: number[] = [1, 2, 3]
let pair: [string, number] = ["age", 18]        // 元组：定长定型

// 函数：参数与返回值
const add = (a: number, b: number): number => a + b

// ② interface：描述"对象长什么样"
interface User {
  id: number
  name: string
  email?: string            // ? 表示可选
  readonly createdAt: Date  // readonly 创建后不可改
}
function greet(u: User): string { return `你好, ${u.name}` }
greet({ id: 1, name: "张三" })       // ✓ 缺 email 没关系（可选）
greet({ id: "1", name: "张三" })     // ✗ id 该是 number

// ③ 泛型：类型层面的"参数"，一句话理解——"类型待定，用时确定"
function first<T>(arr: T[]): T | undefined {
  return arr[0]
}
first([1, 2, 3])          // T 被推断为 number，返回 number | undefined
first(["a", "b"])         // T 被推断为 string
// 好处：不用为每种类型写一遍 firstNumber / firstString
注解解决什么JS 时代的对应物
基本类型实参错型（83.1 痛点一）只靠注释和自觉
interface对象结构契约 + 重构改名一键全改（痛点二）JSDoc 注释（无人校验）
泛型 T"逻辑相同、类型不同"的复用复制粘贴多个版本

读 TS 代码的心法：冒号后的都是"说明书"，不影响运行逻辑——先把说明书跳过，读剩下的 JS；写的时候再反过来，给 JS 补说明书。

83.4 渐进迁移：allowJs 起步，逐文件 .ts

"全仓库一夜换成 TS"是新手最大的误区。正确路线是渐进式：让 JS 和 TS 共存，从新文件开始收紧。

// tsconfig.json —— 过渡期配置（允许 JS 与 TS 共存）
{
  "compilerOptions": {
    "allowJs": true,          // 允许 .js 文件参与编译（共存的前提）
    "checkJs": false,         // true 则连 .js 也做类型检查（可选的收紧档位）
    "noEmit": true,           // 只做检查不产出文件（构建交给 Vite/Webpack）
    "strict": true            // 严格模式：新 .ts 文件一律最严检查
  },
  "include": ["src"]
}
# 渐进路线图：
# 1. 装 TS：npm install -D typescript ；npx tsc --init 生成 tsconfig
# 2. allowJs:true —— 旧 JS 原样放行，项目立即可构建
# 3. 新文件一律写 .ts（增量：新代码不再欠债）
# 4. 每次改动某个旧文件时，顺手把它改成 .ts（改动哪块修哪块）
# 5. 收紧可选项：checkJs:true 让旧 JS 也享受检查（JSDoc 提供类型）
# 6. 改不动的大文件可临时加一行注释豁免：// @ts-nocheck （逐个消灭它）
  • 优先迁移顺序：公共工具函数 > API 响应定义（数据边界）> 频繁改动的模块——类型的价值 = 该处出错的概率 × 波及范围；
  • Vite 项目：再加 vue-tsc / tsc --noEmit 挂进 CI（81 章），类型检查成为合并闸门；
  • any 是逃生门不是家：卡住时可以 any 先通过，但要记 TODO 还债——满屏 any 的 TS 项目比纯 JS 还糟（类型撒谎）。

迁移的节奏感：不追求一次到位，追求"债务不再增长"——新文件全 TS、旧文件随改随迁，三个月后自然完成大半。

83.5 心智定位：TS 是防弹衣，不是新语言

很多人被 TS 吓退，是因为把它当成了"另一门语言"。换一个比喻：TS 是 JS 的防弹衣——衣服不会替你打仗，但流弹（错型、拼错属性、null 炸弹）打不到你身上。

  • 内核不变：你 82 章之前学的所有 JS——原型链、闭包、this、异步——在 TS 里原样成立；TS 加的只是"开发期的名字标签"；
  • 类型是文档更是杠杆：interface 一改，所有不匹配处自动标红——重构从"全局搜索赌运气"变成"跟着红线走"；
  • 边界最值钱：API 响应、公共函数签名、配置文件——这些"多人交接面"优先上类型；函数体内部的小变量，让 TS 自动推断即可（不必处处手写）；
  • 与 82 章互补：测试抓"行为对不对"，类型抓"数据形不对"——两张网一起，才敢大胆重构。

定位口诀："写的是 JS，穿的是 TS"——语言是你的，防弹衣是工具；它管住弹药，不管住你施展拳脚。

要点一句话
JS 的痛错型运行才炸、重构靠全局搜索、补全靠猜——知识没落在代码上

✎ 本章习题

A 基础把 83.1 的 applyDiscount 改成 TS 版并复现三个报错（"0.2"、null、"一百"）；再用联合类型 rate: number | null 让 null 合法化，体会"显式声明可能性"与"静默强转"的差别。
B 进阶为一个 API 响应写 interface（含可选字段与嵌套数组），写一个处理函数消费它；然后把接口里某字段改名，观察编辑器红线的传播路径——记录"跟红线重构"与"全局搜索重构"的步骤差异。
C 挑战给 82 章的 memoize 写 TS 版本：function memoize<T extends (...args: any[]) => any>(fn: T): T，保证返回值类型与原函数一致；解释 extends 约束在这里挡住了哪类误用（如对非函数调用 memoize）。
