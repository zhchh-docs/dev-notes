2核心模型

五个核心模型：一切皆对象→ 缩进即语法→ 可变/不可变→ 引用模型→ 鸭子类型。

2.1 一切皆对象与动态类型

数字、字符串、函数、类都是对象——变量只是贴在对象上的名字，类型属于对象而不属于变量：x = 1 后 x = "a" 完全合法。心智转换：从"盒子装值"换成"标签贴对象"，赋值是让名字指向另一个对象。

2.2 缩进即语法

没有花括号，缩进就是代码块边界（惯例 4 空格）；冒号开块。Tab 与空格混用直接报错——编辑器统一配置。

2.3 可变 vs 不可变

可变：list、dict、set——原地修改，对象不变；不可变：int、float、str、tuple——"修改"实际是创建新对象。这是函数传参行为、字典 key 要求、并发安全的共同根源：不可变对象可哈希可共享，可变对象做字典 key 会出事。

2.4 引用模型：赋值不复制

b = a 只是多贴一个标签——两者指同一对象；改 b.append() 时 a 也在变（同一对象）。要独立副本得显式 copy()（浅）或 copy.deepcopy()（深）。浅拷贝只复制第一层，嵌套结构仍共享内层引用。

2.5 鸭子类型

"走起来像鸭子就叫鸭子"——不看继承关系看有没有这个方法：任何实现了 __iter__ 的对象都能 for 循环，实现了 __len__ 的都能 len()。这是 Python"约定优于声明"的哲学基础（对照 Java 接口、JS 的 duck typing 同源）。

3核心用法（按场景）

3.1 场景一：变量、字符串与 f-string

name = "全栈"
version = 3.12
# f-string：格式化首选（对照 JS 模板字符串）
print(f"{name} 学习 Python {version:.1f}")
# 字符串不可变：所有"修改"都返回新串
s = " hello ".strip().upper()   # "HELLO"

3.2 场景二：四大容器与选型

lst = [3, 1, 2]              # list：有序可变 → 顺序集合
tup = ("a", "b")             # tuple：有序不可变 → 固定结构/字典 key
dct = {"id": 1, "ok": True}  # dict：键值映射 → 查表/JSON 天然对应
st  = {1, 2, 3}              # set：去重/成员判断 → in 是 O(1)

dct["extra"] = 1
print(2 in st, list(set([1, 1, 2])))   # True [1, 2]
选型心智：有序列表用 list、字段结构用 dict（对应 JS 对象）、去重与快速判断用 set、固定坐标/多返回值用 tuple。

3.3 场景三：控制流与函数

def top_n(items, n=3, reverse=True):
    """取前 N 大：默认参数 + 切片 + 排序"""
    return sorted(items, reverse=reverse)[:n]

scores = [88, 92, 75, 60, 99]
for i, s in enumerate(scores):        # 对照 JS 的 entries()
    if s < 60:
        continue
    print(i, s)
print(top_n(scores))                  # [99, 92, 88]

3.4 场景四：推导式（Pythonic 核心）

squares = [x * x for x in range(10) if x % 2 == 0]
by_id   = {u["id"]: u["name"] for u in users}
words   = [w for line in lines for w in line.split()]
gen     = (x * x for x in range(10**8))   # 生成器：惰性，不占内存
经验：推导式替掉大部分"新建空列表+append+if"三段式；超过两层嵌套改回普通循环——可读性优先。

4进阶知识点【进阶】

首次学习可整章跳过。前置：四大容器与函数已会。

4.1 解包与 *args/**kwargs

a, *rest = [1, 2, 3] 就地解包；函数签名 def f(*args, **kwargs) 收任意位置/关键字参数（对照 JS 的 ...rest 与对象展开）；调用侧 f(*list, **dict) 反向拆开传参——封装转发型函数（装饰器/代理）的标准姿势。

4.2 异常处理与 EAFP 风格

Python 社区推崇 EAFP（Easier to Ask Forgiveness than Permission）：直接试、捕获异常，而不是先判断存在——与 JS 的 try/catch 习惯一致，与 Go 的 if err 风格相反。

try:
    val = cfg["db"]["port"]
except (KeyError, TypeError):
    val = 3306        # 缺省兜底
finally:
    log("done")

4.3 with 上下文管理器

with open(path) as f: 退出自动关文件——实现 __enter__/__exit__ 协议的对象都可用 with（文件、锁、连接池）；资源清理的标准答案，对照 Java try-with-resources。

4.4 排序的 key 函数与 stable sort

sorted(rows, key=lambda r: (r["day"], -r["cnt"]))——元组 key 实现多级排序（负号降序）；sorted 是稳定排序，多级可连续两次排序叠加；list.sort() 原地、sorted() 返回新列表。

6最小可运行 Demo

性质（诚实声明）：日常主力是 JS/Java——本篇为 Python 自学 demo（脚本自动化与数据处理方向），非生产履历。

6.1 Demo 设计：词频统计脚本

  • 目标：读一个日志/文章文本，统计词频输出 TopN——串起容器、推导式、函数、文件 IO；
  • 验证：对照手写 Java/JS 同逻辑，体会代码量差异。
import collections

def word_top(path, n=10):
    with open(path, encoding="utf-8") as f:
        text = f.read()
    words = [w.lower() for w in text.split() if w.isalpha()]
    counter = collections.Counter(words)      # dict 的计数封装
    return counter.most_common(n)

if __name__ == "__main__":
    for w, c in word_top("demo.txt", 5):
        print(f"{w:<12} {c}")

7常见坑 & Debug

五条新手高频坑。

7.1 可变默认参数

现象：def f(x, acc=[]) 多次调用共享同一个列表——默认值在函数定义时求值一次。 正解：acc=None + 函数体内 acc = acc or []。

7.2 is 与 == 混用

原因：is 比对象身份（同一内存），== 比值。正解：值比较用 ==；is 仅用于 is None/单例判断。

7.3 浅拷贝陷阱

现象：b = a.copy() 后改 b[0][1]，a 跟着变——内层仍是共享引用。正解：嵌套结构用 copy.deepcopy。

7.4 切片越界不报错

现象：lst[5:10] 越界切片静默返回空/截断，索引取值 lst[10] 才报 IndexError。Debug：切片当"夹取范围"理解，不确定先 len() 检查。

7.5 Tab 与空格混用

现象：TabError/IndentationError 且肉眼难辨。正解：编辑器统一"Tab 转 4 空格"，.editorconfig 团队统一。

8重点讲解

Q1：Python 变量赋值的本质？和 Java 有什么不同？

参考答案：Python 变量是名字到对象的引用——赋值 b = a 只是把名字 b 绑到 a 所指的同一对象，不发生复制。类型属于对象：同一名字可先后指向不同类型对象（动态类型）。后果：①改可变对象内容（append）对所有引用可见；②给名字重新绑定（= 新对象）不影响其他名字；③要独立状态必须显式 copy/deepcopy。Java 的"基本类型传值、对象传引用值"在 Python 里统一成"一切传对象引用"——"传值/传引用"之争落地为"改对象 vs 换绑定"两个动作。

Q2：可变默认参数为什么是坑？怎么正确写？

参考答案：默认值表达式在函数定义（def 执行）时求值一次并存在函数对象的 __defaults__ 里——每次调用不带该参数时都复用同一个列表/字典对象，跨调用累积状态。正确写法：def f(x, acc=None): acc = [] if acc is None else acc——每次调用新建。同理适用于 cache={} 这类写法。反向知识：这个机制也可当"函数级持久缓存"用（配合不可变约束），但生产代码不建议依赖。

Q3：四大容器怎么选？推导式和普通循环怎么取舍？

参考答案：list 有序可变——顺序集合/栈；dict 键值映射——查表、JSON、计数（collections.Counter）；set 去重+O(1) 成员判断——已见判断/交集并；tuple 不可变——固定结构、多返回值、字典 key。推导式取舍：单层条件映射用推导式（简洁且解释器优化，略快于循环 append）；超过两层嵌套/有复杂副作用改回普通循环——可读性优先于炫技；数据量大且只需遍历一次时用生成器表达式 (...) 惰性省内存（深入篇展开）。
